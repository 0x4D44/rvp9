### Root cause #1 — KEYFRAME under-allocation (dominant single-frame loss)
foreman cpu7 @250k per-frame: KF rvp9 41.81 dB vs vpx 52.54 dB = 10.73 dB gap on frame 0.
KF bytes: rvp9 13760 (20% of stream) vs vpx 38349 (42%). libvpx front-loads 2.8x more KF bits.
Not an intra-coder deficiency (e9 matched-Q shows KF intra path competent) — it's RC bit allocation.
C1 fixed the Q-floor; libvpx still spends far more on the KF at constrained bitrate.

### Root cause #2 — PARTITION RIGIDITY (structural, content-independent)
e1 oracle foreman_cif cpu7, inter-frame area%: rvp9 stuck 96%+ 16x16 at EVERY bitrate.
libvpx adapts: @25k 79.5% 16x16 + 13% 32x32 + 4.8% 64x64; @250k 35.5% 8x8 + 50.7% 16x16.
rvp9 uses 0% 8x8 (cannot - floored) and 0% 64x64. Code: variance_hint_bounds floors min+max
at Block16x16 (nonrd_partition.rs:537); RD descent caps recursion at 16x16, square NONE/SPLIT
only, no rect (lib.rs:2648-2659). So partition space = {16x16,32x32,64x64} squares, collapses to 16x16.

### Root cause #3 — INTER-RD coding inefficiency at matched Q (e9, cpu7 foreman_cif)
At SAME Q, rvp9 spends MORE bits AND gets LOWER PSNR (Q80: rvp9 33262 b/f @39.96dB vs vpx 30595 b/f
@41.78dB; +1.83 dB / -2667 b). Pure coding-efficiency loss, no RC confound.
- tx-size: rvp9 ~76% TX_4X4 [87632,23020,4564,83] - over-splits transforms on smooth residual.
- skip frac: rvp9 6-40% vs libvpx 81-97% (e1) - still codes residual far more often post-S2.
- mode mix post-S2: ZEROMV down (good), NEWMV ~matches libvpx, but NEARESTMV 4-22% vs libvpx 60-86%.
- coef entropy ~3.0-3.2 bits/coef (coef coding itself OK).
- Domain mismatch (coef-domain coef_rate vs pixel-SSE dist) still live (inter.rs:2760-2794);
  Lever-3b proven NOT universalizable by global constant (journal).

### Root cause #4 — ALTREF / GOP topology
rvp9 ref ALTREF = 0% everywhere; libvpx 11-14%. No alt-ref frame synthesis in this config.

## 1. Summary

Stage 4a is close enough that the remainder should be narrow and evidence-driven.
HEAD `ffc4e7e` already promoted the coupled realtime VBR RD/rate calibration:

- `InterRdCalibration::stage4a_vbr()` enables coefficient-domain RD, `skip_shift=2`, and skip-modecost retention for one-pass VBR + realtime + speed >= 7.
- One-pass VBR's default `bits_per_mb_multiplier` is now 4.0.
- Latest no-env journaled Foreman result: BD-rate `-3.99%`, matched PSNR delta mean `+0.99 dB`, realtime median `25.02 ms`, `vpxdec` byte-exact, `ffmpeg` missing, with only two rvp9 points inside the libvpx bitrate range.

That result is encouraging but not a product sign-off. The remaining design has two parts:

1. Harden the Stage 4a gates so sign-off cannot pass on skipped tools, report-only `DEFERRED`/`PARTIAL` output, or tests that do not exercise the realtime VBR/P8 path.
2. If current-HEAD diagnostics prove the candidate cohort exists, add one compiled `Block16x16 -> 4x Block8x8` split-admission policy in the A4 non-RD partition descent.

The implementation should stop rather than stack heuristics if either part fails. This HLD deliberately does not reopen rate-control-only spend, RECT disable, AQ, denoising, ALTREF/TPL, or broad encoder architecture.

## 4. Design

### 4.1 Strict Product Gates First

The implementation begins by hardening the gates. A product gate must fail the test process, not merely print `DEFERRED`, `PARTIAL`, or `[SKIPPED]`.

Add a shared strict mode or test-local helper for Stage 4a product runs with this configuration:

- Source: `tests/corpus/foreman_cif.y4m`, 256x256 center crop, 64 frames.
- Encoder: `AqMode::Off`, one-pass `RcMode::Vbr`, realtime deadline, speed 7, `lag_in_frames=0`, no alt-ref, min q 4, max q 255.
- Targets: `[25_000, 50_000, 75_000, 100_000, 150_000, 250_000, 400_000]` bps.
- Tools: live libvpx `vpxenc`, sibling `vpxdec`, and `ffmpeg` on PATH for strict sign-off.
- Environment: no behavior-affecting `RVP9_*` env vars. The only allowed `RVP9_*` in product-gate variants is `RVP9_A4_SPLIT_STATS=1` for instrumentation, and only after a focused byte-identity test proves that stats-on/stats-off produce identical IVFs when the split-admission policy is `Strict`.

The existing advisory ignored tests may remain for local measurement, but Stage 4a sign-off uses strict product variants.

### 4.2 No-Behavior Split Preflight

Before enabling behavior, extend `NonRdSplitStats` so `RVP9_A4_SPLIT_STATS=1` can report what Slack1Over8 would have done while final selection remains strict.

Add counters for `Block16x16 -> 8x8` only:

- `block16_partial_early_out_after_child[4]`: which child index triggered strict early-out.
- `block16_slack_would_continue`: strict early-out would stop, but the Slack1Over8 cap would allow continuing.
- `block16_slack_completed`: all four children completed under the Slack1Over8 cap in diagnostic mode.
- `block16_slack_split_eligible`: completed split was within the Slack1Over8 admission band.
- `block16_slack_split_committed`: final winner at the node was SPLIT via Slack1Over8.
- `block16_slack_rect_override`: RECT beat a slack-eligible SPLIT within the same parent-NONE band.
- `block16_slack_rejected`: completed split exceeded the Slack1Over8 admission band.

Diagnostic completion must not feed synthetic child results into strict selection, rect-prune inputs, final leaves, final cells, final mode caches, or emitted packets. If the implementation uses scratch state to finish skipped children, it must discard that state before the real selection path continues. The focused byte-identity test in §6.1 is mandatory.

Preflight materiality must be measured on current HEAD before behavior is promoted. Run the strict product source and targets with policy `Strict` and stats enabled. Promotion to behavior is allowed only if all of these are true:

- `block16_attempts > 0`.
- `block16_child_infeasible <= 5% of block16_attempts`.
- `block16_slack_would_continue >= max(200, 2% of block16_partial_rd_early_out)`.
- `block16_slack_split_eligible >= max(50, 0.5% of block16_attempts)`.
- `block16_slack_split_eligible > 0` at two or more target bitrates.

If these thresholds fail, stop the implementation and record that split admission is not the current Stage 4a remainder. Do not respond by sweeping ratios, adding env knobs, or forcing split.

### 4.3 Split-Admission Policy

Add a typed policy:

```rust
pub enum Block16SplitAdmission {
    Strict,
    Slack1Over8,
}
```

Add it to `NonRdDescentParams`, defaulting to `Strict`. Do not expose `{ num, den }`, a CLI flag, or an env-controlled ratio. `Slack1Over8` is a single compiled policy for the diagnosed Stage 4a slice.

The encoder selects `Slack1Over8` only when all are true:

- `RcMode::Vbr`,
- `Deadline::Realtime`,
- `speed >= 7`,
- P8 is enabled for the frame,
- `rt_large_recovery` is false.

All other modes keep `Strict`.

The 1/8 band is a small-shape prior, not a magic quality knob. It says that at this exact block size, for this exact Stage 4a path, a completed 8x8 split may beat parent NONE if it is inside a narrow parent-NONE band and no non-NONE candidate strictly beats NONE. If product gates fail, the next design should return to RD/picker/TX ownership, not add `Slack1Over16`, `Slack1Over4`, or a runtime sweep.

### 4.4 Early-Out And Selection Semantics

These semantics apply only to `Block16x16 -> 4x Block8x8` when `Slack1Over8` is active and parent `PARTITION_NONE` is feasible. If parent NONE is not feasible, there is no parent-NONE cap and behavior remains strict.

Define:

```text
none_rd = RD(parent PARTITION_NONE with NONE partition cost)
slack_cap = none_rd + floor(none_rd / 8)
strict_best = best candidate by actual RD under today's strict rules
```

During SPLIT child evaluation:

```text
strict early-out: partial_split_rd >= strict_best_rd
Slack1Over8 early-out: partial_split_rd > slack_cap
```

The equality case may continue; anything above the cap stops. If all four children complete:

```text
split_actual_rd = RD(sum child rate + SPLIT cost, sum child dist)
split_slack_eligible = split_actual_rd <= slack_cap
```

Candidate arbitration is explicit:

1. Strict non-NONE wins are unchanged. If SPLIT, HORZ, or VERT has `actual_rd < none_rd`, choose the best strict candidate.
2. If no non-NONE candidate strictly beats NONE and `split_slack_eligible` is true, SPLIT may override NONE.
3. RECT remains enabled. A RECT arm that strictly beats NONE wins normally. If no RECT arm strictly beats NONE but SPLIT is only slack-admitted, RECT may override that slack SPLIT only when:

```text
rect_actual_rd < split_actual_rd
rect_actual_rd <= slack_cap
```

4. Ties keep the existing ordering unless the current code already specifies otherwise. Slack never changes tie behavior outside the parent-NONE band.

Rect-prune inputs must stay well-defined:

- `RectPruneRdContext.best_rd_cost` is the strict actual-RD best after NONE and any strict SPLIT, not the slack cap and not a discounted SPLIT RD.
- `RectPruneRdContext.partitioning_is_none` means the strict current winner is NONE.
- `split_none_rd_cost` may include child NONE costs from a SPLIT that genuinely completed under the active child loop, but the pruner must not receive diagnostic-only child data from no-behavior preflight.

Parent propagation always uses real accounting:

- Return the selected candidate's actual `rate`, actual `dist`, and actual `rd_cost`.
- Do not discount rate, distortion, or parent RD when a candidate was admitted by slack.
- A parent SPLIT therefore sees the true cost of a slack-admitted child.

### 4.5 Causal Emit Boundary

Do not make the dry-run descent own final mode, residual, skip, or neighbor state.

The current final per-leaf pass remains the source of emitted reconstruction and `mi_grid` updates. The descent may choose shape and may continue to seed/reuse existing safe picker data, but final emit stays raster/causal. This preserves the invariant that the decoder sees the same neighbor state the encoder committed.

### 4.7 Stop Conditions

Stop the build and report rather than stacking more heuristics if any of these are true:

- Preflight stats show no material Slack1Over8 cohort by §4.2.
- Stats instrumentation cannot be proven byte-identical when behavior is strict.
- Slack-admitted behavior improves BD-rate only by making curves noncomparable.
- Product quality is worse than HEAD after a fair live-libvpx run.
- Product cross-decoder validity fails.
- Product VBR/P8 path is not exercised by the strict gates.
- Realtime fails.
- The implementation needs a broad descent refactor to make the policy correct.

## 7. Residual Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Slack1Over8 is the wrong prior. | Quality or block stats regress. | Single compiled constant; stop if gates fail, no ratio sweep. |
| Preflight instrumentation accidentally changes behavior. | False evidence. | Mandatory byte-identity stats-on/stats-off test under strict policy. |
| BD-rate looks good due to poor curve overlap. | False sign-off. | Expanded targets, finite BD-rate, monotonic curves, and >=3 overlap points. |
| Product gates still miss the changed path. | False confidence. | Strict VBR/Foreman/speed-7/P8 variants assert Slack1Over8 counters after behavior is enabled. |
| Extra 8x8 evaluation hurts realtime. | Stage 4a fails performance. | Limit to Block16/P8/VBR/non-large-recovery slice; realtime gates are blocking. |
| RECT inherits unintended slack. | Partition shape drifts unpredictably. | Strict rect-prune inputs and explicit slack override band. |
| Descent/final emit mismatch. | Invalid or poor bitstream. | Preserve causal final emit and run product cross-decoder gate. |
| Foreman overfit. | Product does not generalize. | Do not claim broad content parity from this HLD; add broader corpus only under a separate requirement. |
| Preflight refutes split admission. | This HLD's behavior path cannot finish Stage 4a. | Stop and reopen RD/picker/TX ownership design; do not stack scalar tweaks. |

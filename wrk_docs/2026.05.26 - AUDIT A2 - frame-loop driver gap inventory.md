## Section-by-Section Narrative

### 1. Main Encode Entry Point & Recode Loop

libvpx's `vp9_get_compressed_data` (encoder.c:6362-6875) is the public API entry point. It handles lookahead queue management, ALTREF construction decision and temporal filtering, one-pass vs two-pass dispatch, ALTREF AQ setup, SVC layer indexing, frame-level flags and context setup.

rvp9's `frame_loop.rs::encode_frame` (line 530) replaces this with a simplified single-frame entry: rate control integration is PORTED, lookahead infrastructure is NOT PORTED, ALTREF construction is NOT PORTED, temporal filtering is NOT PORTED.

The recode path (libvpx: `encode_with_recode_loop`, encoder.c:4458-4660) iteratively encodes at increasing Q when the frame overshoots its rate target. rvp9 currently runs a single encode pass — recode loop NOT PORTED.

### 2. Per-Frame Setup (setup_frame, set_frame_size, speed features)

`setup_frame` (encoder.c:809-859) sets the entropy context bank index and refresh flags. rvp9 emits `refresh_frame_context = false` (frame_loop.rs:1503) and always uses default contexts.

`set_frame_size` (encoder.c:3820-3930) handles dynamic resize logic, reference frame buffer reallocation, and motion-estimation parameter initialization. rvp9 has static 64-multiple sizing — dynamic resize NOT PORTED.

`set_size_independent_vars` and `set_size_dependent_vars` wire speed-features defaults. Speed-feature setup and rate-control Q pick are PORTED.

### 3. Tile Dispatch & Encode

`encode_frame_internal` (encodeframe.c:6069-6207) initialises quantizer, RD constants, ME constants, sets up the MB context/MI grid, handles tile-MT synchronisation setup, dispatches to `encode_tiles` or tile-MT variants.

rvp9's `pick_and_simulate_inter_encode_partitions` (lib.rs) and the frame-loop integration cover the single-threaded dispatch — PORTED. Multi-threaded variants (`encode_tiles_mt`, `vp9_encode_tiles_row_mt`) NOT PORTED.

### 4. Reference Frame Rotation

`vp9_update_reference_frames` (encoder.c:3382-3390) and `vp9_swap_mi_and_prev_mi` (encoder.c:908-927) rotate the decoded frame into the reference buffer and swap the mode-info grid.

rvp9 maintains `last_recon_y`, `last_recon_u`, `last_recon_v` buffers (frame_loop.rs:291-297) and updates them on keyframes. Prev-MV salvage path (F.4-4) is PORTED.

### 5. Loop Filter Level Pick & Apply

`loopfilter_frame` (encoder.c:3392-3452) calls `vp9_pick_filter_level` and applies the loop filter to the reconstructed frame. rvp9 has a skeleton (`loopfilter.rs::pick_filter_level`) but loop-filter application is NOT PORTED (filter_level stays 0).

### 6. Recode Loop (VBR)

`encode_with_recode_loop` (encoder.c:4458-4660) iteratively re-encodes at increasing Q when overshooting the rate target. rvp9 does NOT have recode logic. NOT PORTED.

### 7. Post-Encode Bookkeeping

Rate-control post-encode update, frame index increment, ref-frame buffer housekeeping. rvp9 integrates `rate_control.postencode_update(actual_bits, frame_kind)` (frame_loop.rs:684-686) — PORTED.

### 8. Config / Reconfig Paths

`vp9_change_config` (encoder init path) and per-frame overrides. Dynamic-resize path (`set_frame_size` handling `resize_pending`) NOT PORTED.

### 9. Cross-Cutting: Frame Context Adaptation & show_existing_frame

**Frame context adaptation:** libvpx sets `refresh_frame_context = true` so the decoder advances the context bank. rvp9 always emits `false` — cost tables frozen at defaults across the GOP.

**show_existing_frame:** ALTREF frames are displayed via `show_existing_frame = true`. rvp9 does not construct ALTREF, so this path is N/A until ALTREF (A16) lands.

## Cross-Cutting Gaps

### CC-1. Frame Context Adaptation (refresh_frame_context)

libvpx sets `refresh_frame_context: true` (encoder.c:6402) and calls `vp9_adapt_{mode,mv,coef}_probs` after every frame (encoder.c:5833-5836). rvp9 hard-codes `refresh_frame_context: false` (frame_loop.rs:1503) and builds cost tables from defaults every frame.

Effect: MV-cost table never learns sequence motion distribution; inter-mode costs frozen (NEARESTMV always charged symmetric rate); skip probs static. Encoder and decoder disagree on cost tables (encoder frozen, decoder adapting), creating systematic RD mismatch.

~60 LOC to wire; HIGH impact.

### CC-2. Dynamic Resize (set_frame_size with resize_pending)

CBR RT and VBR 2-pass both support dynamic resolution adjustment when buffer occupancy exceeds high-water-mark or falls below target. libvpx calls `vp9_set_size_literal` (encoder.c:3834, 3849).

rvp9 has no resize support. ~100 LOC; MEDIUM impact (rare in steady-state encode, prerequisite for adaptive-bitrate scenarios).

### CC-3. Recode Loop (VBR)

`encode_with_recode_loop` (encoder.c:4458-4660) re-encodes at higher Q when overshooting rate target. Used by VBR 2-pass and 1-pass VBR with `recode_loop_allowed`. rvp9 does NOT recode.

~200 LOC; HIGH impact on VBR paths (in scope per goal doc).

### CC-4. Lookahead Pipeline

libvpx's lookahead queue (`cpi->lookahead`) holds N frames in advance. Used for ALTREF frame selection (`get_arf_src_index`), two-pass lookahead for rate control, temporal denoising pre-pass, lag-in-frames computation.

rvp9 has no lookahead. ~500 LOC for infrastructure; HIGH impact on VBR + ALTREF + denoiser (all in scope).

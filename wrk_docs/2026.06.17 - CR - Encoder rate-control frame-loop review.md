### Findings

1. **High - Strided lookahead input can panic instead of returning an input-size error**  
   Confidence: High. Effort: Small. Bug: `RVP9-BUG-KILN-00001`.  
   Evidence: `crates/rvp9-encoder/src/frame_loop.rs:1571`, `crates/rvp9-encoder/src/lookahead.rs:215`, `crates/rvp9-encoder/src/lookahead.rs:230`.  
   `encode_frame_delayed` multiplies user-supplied strides by rows without checked arithmetic, while direct `LookaheadCtx::push` validates tight plane length but copies with row stride. Padded-stride short buffers can panic instead of producing `InvalidPlaneSize` / `InvalidConfig`.  
   Concrete fix: centralize checked plane-extent validation for Y/U/V and use it in both stream and lookahead paths; add a padded-stride regression test that expects an error, not panic.

2. **High - Accepted encoder and rate-control configs overflow derived arithmetic**  
   Confidence: High. Effort: Medium. Bug: `RVP9-BUG-KILN-00002`.  
   Evidence: `crates/rvp9-encoder/src/frame_loop.rs:1214`, `crates/rvp9-encoder/src/frame_loop.rs:1307`, `crates/rvp9-encoder/src/frame_loop.rs:1345`, `crates/rvp9-encoder/src/rate_control/config.rs:162`, `crates/rvp9-encoder/src/rate_control/state.rs:491`.  
   Public validation accepts extreme dimensions and bitrate/buffer values that later overflow `u32` macroblock multiplication, overflow `i64` buffer-bit conversion, narrow SVC bitrate to negative `i32`, or attempt unbounded frame-area allocation.  
   Concrete fix: define supported maxima, validate them at the public boundary, and compute derived sizes with checked `usize`/`u64`/`u128` before allocation or RC state construction.

3. **High - ARF FC bank adapts from the post-header bank instead of the pre-header snapshot**  
   Confidence: High. Effort: Small. Bug: `RVP9-BUG-KILN-00004`.  
   Evidence: `crates/rvp9-encoder/src/frame_loop.rs:2923`, `crates/rvp9-encoder/src/frame_loop.rs:3022`, `crates/rvp9-encoder/src/frame_loop.rs:3371`, `crates/rvp9-encoder/src/frame_loop.rs:3406`, `crates/rvp9-encoder/src/frame_loop.rs:3433`.  
   The show-frame inter path explicitly snapshots pre-header FC and adapts from it; the ARF path says it mirrors the show path but adapts bank 1 from the mutable `decoder_fc` after `build_inter_packet_with_residuals` has applied compressed-header updates.  
   Concrete fix: clone `pre_header_decoder_fc_arf` before the ARF packet builder call and use that snapshot for mode, coefficient, and MV adaptation.

4. **Medium - Flush leaves queued lookahead frames after an encode error**  
   Confidence: High. Effort: Medium. Bug: `RVP9-BUG-KILN-00003`.  
   Evidence: `crates/rvp9-encoder/src/frame_loop.rs:1609`, `crates/rvp9-encoder/src/frame_loop.rs:1619`, `crates/rvp9-encoder/src/frame_loop.rs:1643`.  
   `flush()` documents that the lookahead is empty afterward, but on the first encode error it breaks after consuming the current popped frame, leaving later delayed frames queued.  
   Concrete fix: either make encode errors poison the encoder and document that contract, or drain/discard remaining queued frames and clear pending state before returning the error.

5. **Medium - SVC refresh override can reset GOLDEN age without refreshing GOLDEN**  
   Confidence: High. Effort: Small. Bug: `RVP9-BUG-KILN-00005`.  
   Evidence: `crates/rvp9-encoder/src/frame_loop.rs:2427`, `crates/rvp9-encoder/src/frame_loop.rs:2763`, `crates/rvp9-encoder/src/frame_loop.rs:2900`, `crates/rvp9-encoder/src/frame_loop.rs:3129`.  
   SVC replaces scheduled refresh flags with `0x01` / `0x00`, but the GOLDEN-age counter resets from the original GOP schedule, not the emitted mask. Picker inputs can then treat a stale GOLDEN as fresh.  
   Concrete fix: reset only when the final `refresh_flags` includes GOLDEN (`0x02`), or make the picker ignore GOLDEN age when SVC owns the reference structure.

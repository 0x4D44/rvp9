## 0. Pre-flight context

Extends the temporal-SVC integration that landed at `dc53eec` / journal
`2026.05.27 - JRN - SVC temporal landed.md` and addresses the four blockers
documented in `2026.05.27 - JRN - spatial SVC feasibility.md`. Constrained by:

- The cross-decoder gate (`crates/rvp9-encoder/tests/cross_decoder_gate.rs`) —
  must stay 4/4 byte-exact (rvp9enc → rvp9-decoder + vpxdec + ffmpeg) at every
  commit.
- `drift_diag` (`crates/rvp9-encoder/tests/drift_diag.rs`) — must stay SSE = 0
  at every commit.
- The temporal-SVC scaffold (`crates/rvp9-encoder/src/svc.rs`, 1341 LOC,
  complete data structures + 4 temporal setters) is reused as the spine.
- The decoder reference-scaling path is already byte-exact validated on
  `vp90-2-05-resize.ivf` (10/10) — the decode side is not touched.

The feasibility journal's verdict — "no smallest-verifiable-increment exists;
all four subsystems must land before any byte-exact spatial-SVC stream can
emit" — frames the strategy: build the four subsystems independently behind
off-by-default gates so each commit keeps the single-layer path byte-identical,
then in a final slice flip the master switch.

The faithful 3-tier temporal piece is the same engineering work as one of the
spatial-SVC blockers (per-layer ref-slot routing through the 8-slot pool), so
it lands as part of the spatial pipeline rather than as a separate refactor.

## 2. rvp9-2 surface audit (what's reusable)

### Already present (don't refactor)

- **`crates/rvp9-encoder/src/svc.rs` (1341 LOC).** Full `LAYER_CONTEXT` / `SVC`
  shape, `MAX_SPATIAL_LAYERS = 5`, `MAX_VPX_LAYERS = 12`, `REF_FRAMES = 8`
  constants, `layer_ids_to_idx`, `Svc::alloc_layers`, save/restore stubs, four
  temporal-mode setters, `apply_temporal_layering` dispatcher. **All spatial
  data fields exist already** (`lst_fb_idx[VPX_MAX_LAYERS]`, `gld_fb_idx`,
  `alt_fb_idx`, `reference_last`/`golden`/`altref`, `ref_frame_flags`,
  `current_{lst,gld,alt}_fb_idx`, `current_superframe`,
  `number_spatial_layers`). The setters populate them; rvp9 currently ignores
  them.
- **`crates/rvp9-encoder/src/buffer_pool.rs` (861 LOC).** A10's `BufferPool` +
  `RefFrameManager` + 8-slot `RefFramePool` with `ref_frame_map[8]`,
  `new_fb_idx`, `update_reference_frames(refresh_frame_flags)`. The pool owns
  physical pixel storage at one fixed resolution — this is the per-spatial-layer
  object that has to multiply.
- **`crates/rvp9-core/src/bitstream/superframe.rs::SuperframeBuilder`
  (`:145`).** `push_frame(Vec<u8>) -> Result<(), …>` + `finish() -> Vec<u8>` with
  `MAX_SUPERFRAME_FRAMES`. Wire format identical to libvpx
  `vp9_pack_bitstream:5093-5142`. Reusable as-is for packing spatial-layer
  slices.
- **`crates/rvp9-core/src/inter/scale.rs` (929 LOC).** `ScaleFactors::new`,
  `is_scaled`, `is_valid`, `scaled_x_q4`, `scaled_y_q4`, `inter_predictor`
  dispatcher (`:242`) routing to `convolve8_scaled` / `convolve8_scaled_avg`.
  Already used byte-exact by the decoder on the resize corpus.
- **`crates/rvp9-encoder/src/frame_loop.rs`** — `EncoderConfig::temporal_layers`,
  `StreamEncoder::svc: Option<Svc>`, `SvcFrameDecision`, `svc_assign_layer`,
  `refresh_flags` override at `:2674-2677`, `EncodedFrame::temporal_layer_id`.
- **CLI**: `--temporal-layers` flag at `crates/rvp9-cli/src/bin/rvp9enc.rs`.

### Conspicuously missing (the four blockers)

- **No source downscaler.** `grep downscale|resize|downsample|bilinear` under
  `crates/rvp9-encoder/src/` returns only doc comments.
- **No per-layer resolution.** `EncoderConfig::width`/`height`
  (`frame_loop.rs:142-144`) are fixed at construction. `encode_frame_delayed`
  validates planes against the single configured size
  (`frame_loop.rs:1395-1411`).
- **Encoder MC hardcodes identity scale.** `build_inter_pred_plane_unscaled`
  (`lib.rs:5565`) constructs `ScaleFactors::new(ref_w, ref_h, ref_w, ref_h)`
  and `debug_assert!(!sf.is_scaled, "F10.1c v1 encoder assumes identity ref
  scale")` (`lib.rs:5598`). Called from `lib.rs:5063`, `:5116`.
- **No multi-slot read routing.** `RefFramePool::frame_refs()` returns
  `[ref_frame_map[0], ref_frame_map[1], ref_frame_map[2]]` (identity selector).
  The other 5 slots in `ref_frame_map[]` are write-only via
  `update_reference_frames`. `current_{lst,gld,alt}_fb_idx` is completely
  ignored.

### Stale tag the temporal SVC journal flagged for follow-up

- "3-layer (0-2-1-2) ref hierarchy simplified": tags are correct
  (`svc.rs:794-799`), but tl1 layer projects to `0x00` instead of refreshing a
  distinct slot. Same multi-slot routing fix spatial SVC needs
  (`vp9_svc_layercontext.c:591-616`). Lands "for free" in Slice 3.

## 5. Risk + decision points (full)

### 5.1 Downsample filter selection (Slice 2 / Slice 5)
libvpx defaults `BILINEAR` + `phase_scaler = 8`
(`vp9_svc_layercontext.c:73-74`), with two overrides at
`vp9_one_pass_svc_start_layer:929-934`: w*h ≤ 320*240 ⇒ `EIGHTTAP_SMOOTH`;
ratio > 0.75 ⇒ `phase = 0`. Decision: copy libvpx defaults verbatim;
`--downsample-filter` / `--downsample-phase` for parity verification only.

### 5.2 Reference-frame slot allocation (Slice 3)
libvpx `set_flags_and_fb_idx_for_temporal_mode{2,3}` writes
`current_{lst,gld,alt}_fb_idx`. With nsl=2,ntl=2: slots {0,1,2,3}. With
nsl=3,ntl=3: {0..5}. 8-slot pool never overflowed in scope.

### 5.3 Rate-control coupling (Slice 11)
Per-layer save/restore + `vp9_svc_adjust_avg_frame_qindex` cross-temporal-slot
sync. Per-layer buffer model from `vp9_svc_layercontext.c:131, :150-152`. Test
tolerance ±30% across 8 frames.

### 5.4 Superframe trailer byte (Slice 10)
Already implemented byte-exact at `superframe.rs:194-219`. Single-frame
`finish()` returns frame unwrapped → byte-identity for spatial_layers=1.

### 5.5 Encoder scaled MC vs decoder scaled MC (Slices 6, 7) — HIGH-RISK
Mitigations: (1) reuse decoder's already-byte-exact arithmetic at
`reconstruct_inter.rs:376-402`; (2) two-arm PROOF in Slice 6
(single-layer byte-equal + differential vs decoder); (3) Slice 7 honours
`force_zero_mode_spatial_ref` → picker never runs ME against scaled refs in
real-time mode (libvpx parity).

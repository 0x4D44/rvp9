## 1. Noise estimator (`vp9_noise_estimate.c`)

libvpx runs a per-frame, periodic (every 8th frame) histogram-based estimator. It samples 16x16 blocks at ¼-sample density, restricted to "steady background" (`consec_zero_mv > thresh_consec_zeromv = 6` for non-denoised, =2 for ≥VGA denoised), excluding skin and high-source-SAD frames. For each sampled block it accumulates `variance(src - last_source)` into a 20-bin histogram (bin width 100), smooths the histogram (with a dark-scene flattening at L247-256), finds the dominant bin, and feeds it into an EMA on `ne->value` (`(3·old + 40·max_bin) >> 2`, L280). Level transitions are gated by `ne->count == ne->num_frames_estimate` (15 initially, 30 thereafter, L289). The output `NOISE_LEVEL ∈ {kLowLow, kLow, kMedium, kHigh}` feeds:
- `set_vbp_thresholds` (encodeframe.c:589-598) — scales the 64x64 variance partition threshold by 7/8 / 1× / 2× / 3× depending on level (640×480+ only).
- `vp9_NEWMV_diff_bias` consumers in the picker (pickmode.c:1352-1355) — the `lowvar_highsumdiff` clause is suppressed at high noise.
- `cyclic_refresh` weighting (aq_cyclicrefresh.c).
- `vp9_denoiser_set_noise_level` when denoising is enabled.

**rvp9 status:** the consumer-side struct `NoiseEstimate { enabled, level: NoiseLevel }` exists at `crates/rvp9-core/src/mode_decision/inter.rs:3214` and the picker reads it (`inter.rs:1553`), but every call site in `crates/rvp9-encoder/src/lib.rs` (3037, 3640) constructs `NoiseEstimate::default()` (enabled=false, level=Low), which is libvpx's pre-init state. No producer module, no histogram, no sampling loop, no EMA, no dispatch from the frame loop. Search confirms: `noise_estimate_init`, `vp9_update_noise_estimate`, `MAX_VAR_HIST_BINS` — zero hits in `crates/`.

Rows 1-8 are all NOT PORTED except row 8 (the enum), which exists at `inter.rs:3196-3201`.

## 2. Skin detector (`vp9_skin_detection.c` + `vpx_dsp/skin_detection.c`)

Two layers:
1. **Pixel-level model** (`vpx_dsp/skin_detection.c`) — Mahalanobis distance against 5 Cb/Cr cluster means with a q16 inverse-covariance, gated by luma window `[40, 220]`, with grey-pixel and strong-Cb early exits and a per-cluster threshold table. Returns `is_skin ∈ {0, 1}`.
2. **Block / SB API** (`vp9_skin_detection.c`):
   - `vp9_compute_skin_block`: samples the centre pixel of a `BLOCK_*` and calls `vpx_skin_pixel`, with a `consec_zeromv > 60` static-pixel fast-reject and a `consec_zeromv > 25 + curr_motion_magn == 0` "no motion" branch.
   - `vp9_compute_skin_sb`: fills `cpi->skin_map[]` (per-8x8 byte map) over a 64x64 SB at 8x8 or 16x16 granularity, then runs a neighbour-count smoothing pass that removes isolated skin blocks and fills isolated non-skin holes.

Consumers: `vp9_update_noise_estimate` (excludes skin from variance samples), `aq_cyclicrefresh.c:179` (lowers refresh frequency on skin), `vp9_denoiser.c:367` (boosts denoising on skin), and `x->sb_is_skin` propagation into the picker via `pickmode.c:994, 2031` (gates `vp9_NEWMV_diff_bias` and the `lowvar_highsumdiff` sub-clause).

**rvp9 status:** the picker has a boolean input `is_skin` (`inter.rs:676`, `1555`), the encoder passes `false` (`lib.rs:3039, 3642`). No pixel model, no `skin_map`, no per-SB pass. `vpx_skin_pixel` / `vp9_compute_skin_block` / `vp9_compute_skin_sb` / `skin_inv_cov` / `MODEL_MODE` — zero hits in `crates/`.

## 4. Scene-change (`vp9_ratectrl.c::vp9_scene_detection_onepass` + `adjust_gf_boost_lag_one_pass_vbr`)

Two paths:
1. **One-pass realtime / CBR** (L3034-3260): on every show-frame, sample 64x64 luma SADs against `Last_Source` in a checker-board pattern, compute `avg_sad`, and set `rc->high_source_sad = (avg_sad > max(min_thresh, prev·thresh))` where `thresh = 8.0` (CBR / screen) or `2.1` (VBR). Hard-cut threshold (`thresh_key = 140000` / 240000 at speed ≤ 5) forces a key frame. CBR-non-screen has a "rate-controller reset" branch at L3190-3203 (re-init `rate_correction_factors`, `buffer_level`, `bits_off_target`). Output drives `cpi->compute_source_sad_onepass`, `cpi->ref_frame_flags` golden refresh, AQ mode toggles, dropframe veto (L4118-4127), and the picker's `scene_change_detected` gate (pickmode.c:1771-1773, 1631).
2. **VBR lag-in-frames** (L2883-3027): rolls over the `rc->avg_source_sad[lag]` ring, detects upcoming scene change (`high_source_sad_lagindex`) and steady regions, sets `gfu_boost`, `baseline_gf_interval`, `af_ratio_onepass_vbr`, and `source_alt_ref_pending` accordingly. This is the producer that makes "future frame is a scene cut → shorten this GF group → don't put ALTREF across the cut" work.

**rvp9 status:** picker has `scene_change_detected: bool` field (`inter.rs:779`), encoder passes `false` (`lib.rs:3058, 3688`). Rate control module mentions it in a doc comment (`rate_control/mod.rs:52`) but does not implement it. No `vp9_scene_detection_onepass`, no `avg_source_sad[]` ring, no `high_source_sad`, no `prev_avg_source_sad_lag`, no `scene_cut_force_key_frame`, no `adjust_gf_boost_lag_one_pass_vbr`. The full scene-detection pre-analysis (rows 33-37) is absent.

## 5. `content_state_sb` machinery (`vp9_encodeframe.c::avg_source_sad`)

`avg_source_sad` (L1209-1257) is the per-SB pre-analysis that runs *once per 64x64 block in the encode loop*, before any mode picking. Inputs are `cpi->Source` and `cpi->Last_Source` at the SB offset. It computes:
- `tmp_sad = sdf(src, last)` (64x64 SAD)
- `tmp_variance, tmp_sse = variance64x64(src, last)`
- Classifies the SB into one of `{kLowSadLowSumdiff, kLowSadHighSumdiff, kHighSadLowSumdiff, kHighSadHighSumdiff, kLowVarHighSumdiff, kVeryHighSad}` based on `tmp_sad < 10000`, `tmp_sse - tmp_variance < 25`, and the lighting-change detector at L1239-1242 (`tmp_variance < tmp_sse >> 3 && (tmp_sse - tmp_variance) > 10000` ⇒ `kLowVarHighSumdiff`).
- Updates `cpi->content_state_sb_fd[sb_offset]` (per-SB consecutive-low-sad counter, capped at 255).
- Sets `x->zero_temp_sad_source = (tmp_sad == 0)`.

Consumers downstream (encodeframe.c:1343-1606, pickmode.c:1964, 2030, 2127-2138, 2177, 2521, 2572): partition force-split decisions, `skip_low_source_sad`, `lowvar_highsumdiff`, `last_sb_high_content`, GF-ref disable, screen-content gates, intra-in-inter gates.

**rvp9 status:** picker-side enum `ContentStateSb` exists (`inter.rs:3100-…`) and is plumbed through (`inter.rs:750, 1108, 1308, 1583, 1631, 1820, 3105`), but every call site passes `ContentStateSb::Normal` (`lib.rs:3054, 3685, 3761`). The producer (rows 25, 27-32) is NOT PORTED. There is no `avg_source_sad` call, no `content_state_sb_fd` allocation, no `consec_zero_mv` update, no `color_sensitivity` derivation, no `zero_temp_sad_source` populator. The picker's pre-init defaults are functionally equivalent to libvpx with `compute_source_sad_onepass = 0`, but the goal here is parity with `compute_source_sad_onepass = 1` (realtime mode, the rvp9 op point).

## 6. Source-variance pre-pass (`source_var_based_partition_search_method`)

A frame-level partition-mode dispatcher used by `cpu-used 0..=3` (good / best) when `sf.partition_search_type = SOURCE_VAR_BASED_PARTITION`. It runs the 16x16-variance histogram of `Source` vs `Last_Source` once, picks `cpi->source_var_thresh` such that the cumulative low-variance count crosses a percentage cutoff (45 % / 75 % depending on resolution), and then per-SB chooses between 16/32/64 partitioning by comparing the per-16x16 variance against `source_var_thresh` (with threshold doubling at each merge step). Output is a partition map fed into `nonrd_use_partition`.

State: `cpi->source_diff_var` (per-MB `Diff{sse, sum, var}`), `cpi->source_var_thresh` (u32), `cpi->frames_till_next_var_check` (frame skipping at speed-feature `search_type_check_frequency`).

**rvp9 status:** NOT PORTED (rows 38-41). rvp9's partition module (`crates/rvp9-core/src/mode_decision/partition.rs`) implements `choose_partitioning` (variance-tree from raw pixels) but does not implement the SVBP path; it has no `source_var_thresh`, no `source_diff_var`, no 16x16 histogram and no frame-level mode selector. (Note: `partition.rs:40` references `noise_level`/`content_state` only in a doc comment about the consumer threshold-scaling that A4 already flagged.) `VAR_HIST_BINS`, `VAR_HIST_FACTOR`, `source_var_thresh`, `frames_till_next_var_check`, `set_var_thresh_from_histogram`, `set_source_var_based_partition` — zero hits in `crates/`.

## 7. Pre-analysis orchestration (frame-loop glue in `vp9_encoder.c`)

libvpx's `encode_frame_to_data_rate` (L3984-4163) orchestrates the pipeline:
1. `compute_source_sad_onepass = (mode == REALTIME)` (L3984).
2. Allocate / scale `Last_Source` whenever any analysis below needs it (L4056-4065).
3. Reset `consec_zero_mv` on KF / resize (L4072-4075).
4. Call `vp9_scene_detection_onepass` (L4093) under `(show_frame && REALTIME && (VBR || screen || speed 5–7))`.
5. Propagate `high_source_sad` to SVC superframe state (L4096-4110).
6. Call `vp9_update_noise_estimate` (L4113).
7. Toggle `cpi->use_skin_detection = 1` under CBR + CYCLIC_REFRESH + speed ≥ 5 + non-screen + 8-bit (L4159-4163).

This is the producer side that wires the helpers together each frame. Row 43 captures it. **rvp9 status:** the encoder frame loop in `crates/rvp9-encoder/src/lib.rs` calls none of these. Searches for `update_noise_estimate`, `scene_detection_onepass`, `compute_source_sad_onepass` from a call-site context return zero hits in `crates/` (only the doc-comment hits above).

## Cross-Cutting Gaps

### CC-1 — Pre-analysis is producer-free
The picker / partition / AQ / RC modules in rvp9 all expose consumer-side fields (`NoiseEstimate`, `ContentStateSb`, `is_skin`, `lowvar_highsumdiff`, `zero_temp_sad_source`, `scene_change_detected`, `source_variance`, `force_skip_low_temp_var`) for the libvpx pre-analysis outputs. The producers — **all of A5** — are absent. Every consumer site is fed libvpx's pre-init / disabled default. This is faithful-port-compatible only in the regime where libvpx itself runs with the corresponding `cpi->compute_source_sad_onepass = 0`, `cpi->use_skin_detection = 0`, `cpi->noise_estimate.enabled = 0`, `cpi->rc.high_source_sad = 0`. Our op-point (`cpu-used 6/7`, CBR or VBR realtime) is the opposite regime — libvpx enables all of these at L4159-4163 and L4088-4092. Result: the picker, partition, and AQ paths under-utilise content-aware decisions across the board.

### CC-2 — `consec_zero_mv` state has no producer
Multiple downstream gates (noise sampling, skin detection, AQ cyclic-refresh) read `cpi->consec_zero_mv[bl_index]` to identify steady-background blocks. The state is reset on KF / resize (`vp9_encoder.c:4072-4075`) and incremented inside the encode loop whenever a block's final MV is zero (search `consec_zero_mv` in encodeframe / pickmode for ~30 update sites). rvp9 has no `consec_zero_mv` array, no reset, no increment hook. Even if rows 4 / 12 / 14 are ported, they will read garbage without this state.

### CC-3 — `Last_Source` scaling and ownership
libvpx's pre-analysis runs against a scaled `cpi->Last_Source` that the frame loop allocates on demand at L4056-4065 (under any of: screen content, VBR realtime speed≥5, SVBP, noise estimation enabled, `compute_source_sad_onepass`). rvp9's frame loop holds the previous reconstruction but does not maintain a scaled `Last_Source` view of the previous *source*. Any port of rows 4, 25, 33, 39 needs this view first.

### CC-4 — Picker's `force_skip_low_temp_var` is fed `false` always
Picker field `force_skip_low_temp_var` (`inter.rs`, consumer in the `variance_low[]` clause documented in the picker inventory P38) is downstream of the same `content_state_sb` + `consec_zero_mv` producers. Even though the consumer-side logic is wired, it is dead code until the producers exist. Same applies to `skip_low_source_sad`, `lowvar_highsumdiff`, `last_sb_high_content`, `zero_temp_sad_source` — all of them are consumer wiring with stub producers.

### CC-5 — No `color_sensitivity` populator (cross-cuts UV-RD)
A4 (partition) and A1 (picker UV gate) consume `x->color_sensitivity[1..3]` (U / V chroma-vs-luma SAD ratio) which is set by an inner loop inside `choose_partitioning` (encodeframe.c:1170-1206). rvp9 has neither the populator nor the consumer field. Cross-zone: A5 owns the producer, A1 / A4 own the consumer slots that need to be added.

### CC-6 — Scene-change forced key-frame
`scene_cut_force_key_frame` (row 37) crosses into A3 (rate control) and A10 (reference-frame management) — when libvpx detects a hard cut it forces `cm->frame_type = KEY_FRAME` regardless of the GOP planner. rvp9's frame-type decision in `frame_loop.rs` does not have a scene-cut override input. Without it, every scene cut burns ~10× the bitrate predicting against a stale reference.

### CC-7 — VBR lag-in-frames pre-analysis (row 34) crosses into A3 / A16
`adjust_gf_boost_lag_one_pass_vbr` reaches into the rate-controller (gf_interval, gfu_boost, af_ratio) and the ALTREF planner (`source_alt_ref_pending`, `alt_ref_gf_group`). These hooks need to exist in A3 / A16 before this can be wired.

## Conclusion / Sequencing notes

- **Gap counts:** PORTED 2 · PARTIAL 4 · NOT PORTED 37 · OUT-OF-SCOPE 2 (44 total in-scope; row 44 is the SVC carve-out and is in-scope only for A18).
- **Cross-zone dependencies surfaced:**
  - A1 (picker) is currently consuming pre-init defaults for every A5 producer (CC-1, CC-4) — closing A5 P0-P2 will move picker quality without touching A1 code.
  - A4 (partition) consumes `content_state_sb`, `noise_level`, `source_var_thresh`, `color_sensitivity` (CC-5) — closing A5 unlocks the consumer-side logic A4 audited.
  - A3 (rate control) and A10 (ref management) are the consumers of `high_source_sad` / `scene_cut_force_key_frame` (CC-6) and of VBR-lag pre-analysis (P6, CC-7).
  - A11 (AQ) consumes `noise_level`, `skin_map`, `consec_zero_mv` — those are A5 outputs.
  - A17 (denoiser, out of A5) consumes `noise_level` and `skin_map`; A5 producers are prerequisites for A17.
- **Recommended Phase 2 sequencing for this zone:** land P0 (scaffold) first as a no-op refactor; then P1 (avg_source_sad) — this single item unlocks the largest cluster of dead consumer wiring; then P2 (scene detection) for the bitrate-on-cuts win; then P3-P4 (noise + skin) as a paired wave to retire all of CC-1; defer P5 (SVBP) until the cpu-used 0..=3 wave starts; defer P6 (VBR lag analysis) until A3 is materially complete.
- **AUDIT-UNCERTAIN rows:** none — every row was either confirmed present (PORTED rows verified by reading the cited rvp9 file) or absent (every NOT PORTED row was grep-confirmed across `crates/rvp9-core/` and `crates/rvp9-encoder/` for both the function name and a body-token; only consumer-side stub references surfaced).

**Major**
- Unsupported AQ3 rejection is underspecified. The HLD allows “construction or CLI parsing” to reject unsupported profiles, but `EncoderConfig` is public and `StreamEncoder::new` currently allocates CR for any `AqMode::CyclicRefresh`. See [HLD](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\wrk_docs\2026.06.25 - HLD - Stage 4b cyclic-refresh AQ - V4.md:76>) and [frame_loop.rs](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\crates\rvp9-encoder\src\frame_loop.rs:1298>). Make `StreamEncoder::new` the hard validation point, with CLI rejection as UX only. Add table tests for each constructible unsupported field.

- The transactional CR-map staging is not concrete enough. The HLD requires side-effect-free trials, but the existing per-block CR update mutates `self.map` and `segmentation_map` directly. See [HLD](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\wrk_docs\2026.06.25 - HLD - Stage 4b cyclic-refresh AQ - V4.md:99>) and [aq_cyclic_refresh.rs](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\crates\rvp9-encoder\src\aq_cyclic_refresh.rs:648>). Split this into pure decision plus one final commit, or introduce an explicit staged `CrMapDelta`. Extend the forced flip test to assert CR map/cursor/counts are committed once.

- The CR-state oracle may be overconstrained. Exact matching for actual BOOST counts and segmentation-map counts depends on rvp9 matching libvpx’s block decisions, not just CR policy. See [HLD](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\wrk_docs\2026.06.25 - HLD - Stage 4b cyclic-refresh AQ - V4.md:264>) and CR update inputs in [aq_cyclic_refresh.rs](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\crates\rvp9-encoder\src\aq_cyclic_refresh.rs:621>). Make exact fields limited to q-independent CR setup/golden state, or explicitly document that the oracle run must match libvpx’s block decisions.

- Golden demotion timing needs a named phase. The HLD says postencode demotion must affect refresh flags before reference rotation, but current code computes refresh flags, builds the packet, rotates refs, then updates CR. See [HLD](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\wrk_docs\2026.06.25 - HLD - Stage 4b cyclic-refresh AQ - V4.md:135>) and [frame_loop.rs](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\crates\rvp9-encoder\src\frame_loop.rs:2932>). Define this as `post_leaf_pre_packet` demotion and add a header-level test proving the emitted refresh mask changes correctly.

**Minor**
- Env sanitization is directionally right but too open-ended. The HLD says sanitize behavior-changing `RVP9_*` vars, while the code has many such flags. See [HLD](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\wrk_docs\2026.06.25 - HLD - Stage 4b cyclic-refresh AQ - V4.md:233>) and examples in [lib.rs](<D:\worktrees\rvp9-2\20260625-TSK-HUM-stage4b-aq-hld\crates\rvp9-encoder\src\lib.rs:2663>). Add a shared sign-off helper that clears or rejects all known `RVP9_*` behavior flags, with an explicit allowlist.

## 1. Problem statement

Track F is about to land **four multi-day picker changes** (F.1
`block_yrd` port, F.2 `find_mv_refs` propagation, F.3 motion-aware
partition, F.4 tuning). Each one changes the picker's decision on a
per-block basis — but the only signal currently available is the
end-to-end PSNR-delta gate on foreman, which has a noise floor of
hours-of-encode and integrates over every block in the sequence. If a
milestone moves 5% of blocks from NEAREST→NEW correctly **and** moves
3% from 64x64→16x16 incorrectly, the PSNR-delta might cancel and we
would think the change did nothing. We would fly blind for a week per
milestone.

**This sub-track delivers a per-(frame, block) diagnostic harness**
that captures, for every block on foreman, libvpx's chosen
partition / mode / MV / coef-bit estimate / SSE alongside rvp9's
same fields, and produces a structured diff. Track F milestones can
then report concrete "fraction of blocks now matching libvpx"
numbers per change, decoupled from the end-to-end metric.

## 2. Prior art — E1 `e1_block_stats`

The closest existing tool is `crates/rvp9-harness/src/bin/e1_block_stats.rs`
(committed during the Track E1 gap analysis, produced
`wrk_docs/E1_encoder_gap_analysis.md`). E1's design:

- **Pipeline:** drive vpxenc over foreman → IVF; encode the same
  source through rvp9 → IVF; decode **both** IVFs through the **same
  rvp9 decoder** (the "shared oracle parser"); read
  `Decoder::last_frame_mi_grid()` after each parsed frame.
- **Per-frame stats captured:** bit allocation
  (`FrameStats::bits`, `is_key`, `base_qindex`); partition-leaf count
  + area histogram (`block_count[BLOCK_SIZES]`,
  `block_area8[BLOCK_SIZES]`); mode tallies (`intra_area8`,
  `inter_mode_area8[4]`); skip fraction (`skip_area8`); reference-frame
  usage (`ref_last_area8`, `ref_golden_area8`, `ref_altref_area8`).
- **Granularity:** per-frame aggregates, not per-block tuples.
- **Output:** a single markdown report aggregated across the run.

**What broke on the libvpx leg:** the E1 report (`§"What the data
does NOT support"`, lines 67–82) flags that the libvpx
**mode / skip / ref-frame columns are not trustworthy**. The decoder
reported 80–100% intra on libvpx inter frames whose total cost was
<100 bytes — physically impossible. Cross-decode itself succeeded
(0 decode errors across 64 frames); loop-filter-driving fields like
`block_size` are trustworthy because they cross-validate against
byte-exact reconstruction. But `mode`, `skip`, and `ref_frame` in
`last_frame_mi_grid` appear to be mislabelled for libvpx-coded
inter-skip / ZEROMV blocks. **This is a decoder mi-grid population
bug on the mode column.** It is outside Track F's scope (decoder
team's code; multi-agent rules forbid us fixing it here) and it
**rules out any oracle design that depends on reading libvpx-coded
mi-grids through the rvp9 decoder.**

The E1 tool is still useful for partition-and-bits questions, but
**any new oracle that needs mode/skip/ref-frame ground truth for
libvpx must obtain those fields from libvpx itself, not from
decoding-then-reading-mi-grid.**

## 3. Proposed harness

### 3.1 Design overview

A new standalone binary `f02-block-oracle` in
`crates/rvp9-harness/src/bin/f02_block_oracle.rs` that:

1. Runs **two encoders** over the same `foreman_cif.y4m` source
   (256×256 centre-crop, 64 frames, matched config):
   - **rvp9 leg:** `StreamEncoder` configured to match the Track F
     baseline (`--rt`, `--cpu-used=7`, `aq=0`, the same target
     bitrates as `quality_gate_stage4a_realcontent`). Per-block
     decisions are siphoned via a new **env-gated tracer**
     (`RVP9_F02_ORACLE=1`) inside the picker — see §3.2.
   - **libvpx leg:** a **patched** `vpxenc` from
     `third_party/libvpx` that emits one structured line per coded
     block to a sidecar file when `VPX_F02_ORACLE_OUT=<path>` is
     set — see §3.3.
2. Parses both sidecar streams into a common in-memory
   `BlockDecision` schema (§3.4).
3. Aligns blocks by `(frame_idx, mi_row, mi_col)` and emits a diff
   report (§3.5).

### 3.2 rvp9 side — env-gated thread-local sink

Track F's constraint forbids changing the picker's public API. The
existing crate already has the exact pattern for this: every Track E
diagnostic (`predstat`, `e12stat`, `skipstat`, `e1_block_stats`)
uses an env-gated thread-local accumulator. F.0.2 reuses that
pattern.

**New module:** `crates/rvp9-encoder/src/f02_oracle.rs`. Mirrors
`predstat.rs` exactly:

- `static F02_ON: AtomicBool` — set by `init_from_env()` from
  `RVP9_F02_ORACLE`; one relaxed atomic load when disabled.
- `thread_local! { static SINK: RefCell<Vec<BlockDecision>> }` —
  the accumulator.
- A single `pub fn record_decision(d: BlockDecision)` entry point.
- A `pub fn drain_frame() -> Vec<BlockDecision>` for the harness to
  pull at end-of-frame.

**Hook sites (all in the picker, no behaviour change):**

- `mode_decision::inter::pick_inter_mode_luma` — after the argmin,
  push one `BlockDecision` with the winner's mode, MV,
  `best_distortion`, `best_rate`. (The function already returns this
  data; the hook just snapshots it into the sink.)
- `mode_decision::intra::pick_intra_mode_luma` — same pattern for
  intra blocks.
- `mode_decision::partition::choose_partitioning` — push one
  partition decision per chosen leaf.
- Skip / coef-bit estimate: read from the existing
  `skipstat::record_leaf` and the bit accountant
  (`rvp9_core::entropy::bitacct`) so we don't double-instrument.

**Realtime impact when off:** one relaxed atomic load per hook.
Identical to the existing `predstat`/`e12stat` pattern, which the
realtime gate (`5.34 ms median`) was measured with present-but-off.

### 3.3 libvpx side — patched vpxenc (option **b**)

**Decision: option (b) — patch libvpx itself.** Justification:

- **Option (a)** (decode libvpx IVF through rvp9 decoder, read
  mi-grid) is **directly blocked by the decoder mi-grid mode-column
  bug** documented in §2. Even if we worked around mode, the
  populated MV is what the decoder stores after potential clamping;
  it is not necessarily the MV libvpx's picker chose. (a) cannot
  give ground truth for the picker's decision, only for the parsed
  bitstream.
- **Option (c)** (third-party tool, e.g. an existing analyzer) is
  the least preferred: we would have to validate a tool we don't
  control, and most VP9 analyzers also work on the decoded bitstream
  (same problem as (a)).
- **Option (b)** instruments libvpx's picker output **directly at
  the source**: `vp9_pick_inter_mode` / `vp9_choose_partitioning` in
  `vp9/encoder/vp9_pickmode.c` and `vp9_encodeframe.c`. The
  instrumentation is a single `fprintf` per chosen block, gated by an
  environment variable so the unpatched code path is unchanged
  when not running F.0.2. **No behaviour change** — only an extra
  write to a sidecar file when `VPX_F02_ORACLE_OUT` is set.

**Patch shape:** a small textual diff applied to
`third_party/libvpx/vp9/encoder/vp9_pickmode.c` and
`vp9_encodeframe.c`. Maintained as
`third_party/libvpx-patches/f02_oracle.patch` (a single file under
20 lines of change). The patched binary is only used
when running F.0.2; production benchmarking continues to use the
stock `D:\language\libvpx-stock\vpxenc.exe` referenced by E1.

**Version pin.** The patch is authored against the libvpx commit currently checked out at `D:\language\libvpx-stock` (libvpx v1.14.1; `git rev-parse HEAD` at the top of the patch file as a comment). The patch file's first line must be a comment of the form `# libvpx commit: <hash> (v1.14.1)`. If `third_party/libvpx` is ever bumped, the patch may need re-rebasing; the build script must abort loudly if `git rev-parse HEAD` of `third_party/libvpx` doesn't match the patch's pin header.

**Build approach.** A separate developer-invoked PowerShell script `scripts/build_f02_libvpx.ps1` applies the patch and runs the libvpx build steps. The script aborts loudly if (a) `third_party/libvpx` is unset, (b) the libvpx commit doesn't match the patch's version pin, (c) the patch fails to apply, or (d) the build produces no `vpxenc.exe`. The harness binary (`f02-block-oracle`) checks for the patched binary at `third_party/libvpx/build_f02/vpxenc.exe` and errors loudly with the exact PowerShell command to run if missing. **No `build.rs` invocation of external build systems.**

**Format of the libvpx sidecar:** one JSON object per line (JSONL),
each line is one `BlockDecision` in the schema below. JSONL is
chosen so we can stream-parse without loading the whole file and
because Track E's existing dumpers (e.g.
`decode_coefs_oracle_diff.rs`) use the same convention.

**Output buffering.** Multiple `fprintf` calls per block without explicit line-buffering can interleave or partially-flush on Windows when the patched vpxenc is invoked from a harness. The patch MUST set `setvbuf(oracle_fp, NULL, _IOLBF, 0)` immediately after opening the sidecar file, or call `fflush(oracle_fp)` after each block-decision write. Either is acceptable; the patch comment should justify the choice. The smoke test in §6 must reload the sidecar and confirm one valid JSONL object per line (no truncation, no interleaving).

### 3.4 Data schema

One `BlockDecision` per coded block, on **both** legs:

```text
frame_idx        : u32              # 0-based; matches IVF presentation order
mi_row           : u16              # 8x8-cell row (0..frame_h/8)
mi_col           : u16              # 8x8-cell col (0..frame_w/8)
bsize            : enum BlockSize   # 4x4, 4x8, 8x4, 8x8, 8x16, 16x8, ..., 64x64
mode             : enum BlockMode   # DC/V/H/D45/.../TM | NEAREST/NEAR/ZERO/NEW
ref_frame        : enum RefFrame    # NONE (intra) | LAST | GOLDEN | ALTREF
mv_row           : i16              # 1/8-pel; 0 for intra and ZEROMV
mv_col           : i16              # 1/8-pel; 0 for intra and ZEROMV
mode_bits_est    : u32              # picker's mode-rate estimate (inter_mode_probs or intra_mode_probs cost)
mv_bits_est      : u32              # picker's MV-rate estimate (0 for non-NEW modes)
coef_bits_est    : u32              # picker's coefficient-bit estimate (0 in rvp9 pre-F.1 — forward-looking)
sse_after_pred   : u64              # SSE(source - prediction) over Y, pre-quant
skip_flag        : bool             # picker's final skip decision (the one written to the bitstream)
```

**Minimality justification.** This is the smallest tuple that
covers Track F's three primary levers, and the three split
rate-component fields each map directly to one Track F lever
(`mode_bits_est` to F.3 partition/mode mix; `mv_bits_est` to F.2
candidate-list quality; `coef_bits_est` to F.1 RD model). Splitting
now costs almost nothing and pays off across three milestones.
- F.1 `block_yrd` lands a coefficient-bit-aware RD model
  → measured by `coef_bits_est` delta vs libvpx and by the rate of
  mode flips from NEAREST to NEW;
- F.2 `find_mv_refs` propagation lands a richer MV-candidate list
  → measured by `mv_row` / `mv_col` distribution shifts and by
  `mv_bits_est` convergence to libvpx;
- F.3 motion-aware partition lands a coarser partition tree
  → measured by `bsize` distribution converging to libvpx's and by
  `mode_bits_est` shifts as the mode mix changes.
Anything beyond these thirteen fields (e.g. per-coefficient dumps,
filter choice, segmentation) is out of scope until a Track F
milestone asks for it.

#### 3.4.1 Field liveness at F.0.2 milestone

Not every field has a measurable value in *both* legs at the F.0.2 commit landing. The harness must emit and report all fields, but the diff report's markdown header should explicitly state which fields are "live" (both legs produce meaningful values) vs "forward-looking" (one or both legs emit a placeholder until later milestones):

| Field             | rvp9 leg at F.0.2 | libvpx leg at F.0.2 | When live on rvp9 |
|---|---|---|---|
| `bsize`           | live              | live                | already live |
| `mode`            | live              | live                | already live |
| `ref_frame`       | live              | live                | already live |
| `mv_row`, `mv_col`| live              | live                | already live |
| `sse_after_pred`  | live              | live                | already live |
| `skip_flag`       | live              | live                | already live |
| `mode_bits_est`   | live              | live                | already live (mode-rate is in the picker today) |
| `mv_bits_est`     | live              | live                | already live (mv-rate is in the picker today) |
| `coef_bits_est`   | live (since F.1)        | live                | live (F.1 landed: `coef_rate >> 9` in `lib.rs`) |

The diff report's markdown header **must** emit a "schema liveness at this milestone" footer line stating which fields are forward-looking, so a reader cannot accidentally compare a `Δ coef_bits` column against rvp9=0 and conclude "rvp9 wins on coef_bits".

**Schema location.** Defined in the new `rvp9-harness` module
`crates/rvp9-harness/src/f02_schema.rs`. Both legs serialise to the
same JSONL format via `serde`. Inside the rvp9 picker, the sink
holds a `Vec<BlockDecision>` typed against the same Rust struct,
so the harness's parser code path is shared.

### 3.5 Diff / report

**Per-frame summary table** (one row per frame, emitted as
markdown):

| frame_idx | n_blocks | partition_match% | mode_match% | mean Δ mode_bits | mean Δ mv_bits | mean Δ coef_bits | mean Δ sse |

- `partition_match%` = fraction of (mi_row, mi_col) where libvpx's
  `bsize` equals rvp9's `bsize` at the **top-left mi cell** of the
  containing leaf. (This is the same area-weighting E1 uses, see
  `e1_block_stats.rs:158-170`.)
- `mode_match%` = of the blocks where partition matched, fraction
  where `(mode, ref_frame)` also matches.
- `Δ mode_bits` / `Δ mv_bits` / `Δ coef_bits` = rvp9 minus libvpx;
  positive means rvp9 estimates more bits than libvpx for that
  rate component.
- `Δ sse` = same sign convention.

**Aggregate summary** (one row per encode target bitrate):

| target_kbps | partition_match% | mode_match% | mean Δ mode_bits | mean Δ mv_bits | mean Δ coef_bits | mean Δ sse | RMS Δ mv |

**Per-(frame, block) raw dump** (JSONL, paired-tuple format) so
deep dives can grep for specific divergences:

```text
target/track_f_oracle/foreman_100kbps_raw.jsonl
  { "frame_idx": 7, "mi_row": 4, "mi_col": 12,
    "rvp9":   { "bsize": "8x8",   "mode": "NEAREST", "ref": "LAST", ... },
    "libvpx": { "bsize": "32x32", "mode": "ZERO",    "ref": "LAST", ... } }
```

This is the file Track F milestone owners grep when the summary
table shows a regression and they need to know which blocks moved.

**Frame-index alignment.** Both legs use IVF presentation-order frame indexing. Foreman is a simple IDR + inter sequence (no show-existing-frame, no superframes, no altref synthetics), so frame_idx is unambiguous. If Track F later extends to clips with altref / showframe=0, this assumption must be revisited — explicitly flagged here for downstream awareness.

## 4. Build / run interface

**Decision: standalone binary in `crates/rvp9-harness/src/bin/`,
not a `cargo test --ignored`.**

Justification:
- The harness produces *artifacts* (markdown report + JSONL dumps)
  for offline analysis, not pass/fail signal for CI. Putting it in
  the integration-test tree would conflate "did the build break" with
  "did Track F's diff move", and would force every test runner to
  produce gigabytes of JSONL.
- It needs to invoke an **external** patched `vpxenc.exe`. Cargo
  integration tests have a brittle relationship with the working
  directory and PATH; a regular binary makes the invocation
  explicit.
- Track E's prior diagnostic binaries (`e1_block_stats`,
  `e12_oracle`, `decode_coefs_oracle_diff`) follow this same
  convention — F.0.2 fits the established shape.

**Invocation:**

```text
cargo run -p rvp9-harness --release --bin f02-block-oracle -- \
    --foreman tests/corpus/foreman_cif.y4m \
    --vpxenc third_party/libvpx/build_f02/vpxenc \
    --frames 64 \
    --kbps 25,50,100,250 \
    --out target/track_f_oracle/
```

`Cargo.toml` gets one new `[[bin]]` stanza pointing at
`src/bin/f02_block_oracle.rs`.

## 5. Storage

**Decision: `target/track_f_oracle/` — gitignored, regenerable.**

- All JSONL dumps and markdown reports land in
  `target/track_f_oracle/<run-id>/`. `target/` is already
  gitignored, so nothing leaks into the commit tree.
- Per-target-bitrate JSONL files are ~5–20 MB each (~50k blocks per
  64-frame foreman run × ~80 bytes per JSONL line × 4 bitrates).
  Acceptable as an ephemeral artefact, **not** acceptable to
  commit. The HLD explicitly **forbids** committing oracle dumps.
- For *signal* persistence, each F.x milestone copies its summary
  markdown table (only — not the raw dumps) into
  `wrk_docs/Track_F/Fx_oracle_summary.md` so the next milestone has
  a "where we were" reference. These are small (<100 KB each) and
  do belong in git.

## 6. Test plan

**Smoke test (`f02_oracle_smoke.rs`, an integration test inside
`crates/rvp9-harness/tests/`):**

1. Generate a **single-frame, single-SB** synthetic input (an
   already-existing helper in
   `rvp9-encoder::encode_synthetic_two_frame_kf_inter_non_skip`
   produces exactly this shape — re-used from S4.16m).
2. Drive both legs of the harness with that input.
3. Assert:
   - **Schema round-trip:** rvp9 leg's `BlockDecision` for the
     single coded block deserialises back from its JSONL line and
     equals the in-memory struct (catches schema drift).
   - **Diff structure:** the harness produces a per-frame summary
     row with `n_blocks = 16` (a 256×256 frame has 16 SBs;
     single-frame, single-SB stream gives 1 SB).
   - **Identity-of-decisions at trivial input:** for a flat-grey single-frame inter source, both legs are expected to pick `ZEROMV + skip` for every coded block (regardless of partition tiling). Assert: for **every** `BlockDecision` in both legs, `(mode == ZEROMV || mode == SKIP) && mv_row == 0 && mv_col == 0 && skip_flag == true`. **Do not assert `partition_match% == 100`** — partition tilings can differ for flat input due to different RD ties / different default thresholds.
   - **Off-by-default:** when `RVP9_F02_ORACLE` is unset, the
     encoder's recorded sink is empty (no measurement leakage).

**Manual smoke (not gated):** run the full foreman invocation from
§4 and confirm:
- The patched libvpx binary produces a non-empty JSONL sidecar.
- The diff report's `partition_match%` agrees with E1's existing
  partition-distribution table (both legs see ~85% rvp9 8×8 vs
  ~80% libvpx 64×64 at the 100 kbps point — i.e. the new oracle
  reproduces E1's known-good finding).

**Acceptance criterion for F.0.2:** smoke test green; manual
run produces a markdown report whose 100 kbps partition_match% is
within ±2% of E1's pre-existing measurement.

## 7. Realtime-budget impact

**Off by default.** The encoder hooks are gated on
`F02_ON: AtomicBool` set from `RVP9_F02_ORACLE`. When unset:
- One relaxed atomic load per picker call site.
- No allocation.
- No string formatting.
- No I/O.

This is the same pattern measured under the realtime gate for
`predstat`/`e12stat`/`skipstat` — that gate is currently 5.34 ms
median (6× headroom against 33 ms). F.0.2 adds no more cost than
those three combined.

When **enabled**, the hook is **not** realtime-safe — it allocates
into a `Vec<BlockDecision>` and at end-of-frame writes JSONL to
disk. That is acceptable: F.0.2 is a *diagnostic* harness, not a
production path. The `realtime_gate_720p30` test continues to run
with `RVP9_F02_ORACLE` unset; no regression should appear.

| R2 | **Decoder mi-grid mode column bug** (known, §2). | Out of scope; option (b) sidesteps it entirely by reading libvpx's picker directly, not via decode. Flagged here so the team-lead knows we are not solving the underlying decoder bug. |
| R3 | **Alignment of mi_row / mi_col across the two encoders.** Both encoders use the same 8×8 mi grid by VP9 spec, but `bsize` of a leaf covers multiple mi cells. ## 9. Out of scope (explicit)

- **Fixing the decoder mi-grid mode-column bug.** That is the
  decoder team's code. Per CLAUDE.md multi-agent rules we leave it
  alone; option (b) sidesteps it.
- **Changing the rvp9 picker's public API.** Per the constraints,
  the picker's `pick_inter_mode_luma` / `pick_intra_mode_luma`
  signatures stay exactly as they are today. Instrumentation lives
  in a thread-local sink behind an env var, identical to the
  existing diagnostic pattern.
- **Behaviour changes in libvpx.** The patch is instrumentation
  only — one `fprintf` per coded block, gated on an environment
  variable. No picker logic, no RD model, no entropy.
- **Per-coefficient dumps, filter choices, segmentation IDs.**
  These can be added to the schema in a follow-up if a Track F
  milestone needs them, but the YAGNI principle (CLAUDE.md
  "Don't predict the future") says we don't pre-build for it.
- **Bit-exact agreement between legs.** The oracle measures
  *picker decisions*, not bitstream equivalence. F.4 is where
  byte-exact cross-decode is re-established as the exit gate.

## 1. Problem statement

`find_mv_refs` builds the `(nearest, near)` MV-reference list that every
inter mode (`ZEROMV`, `NEARESTMV`, `NEARMV`, `NEWMV`) reads as its
seed/anchor. On rvp9 today that list is sourced **only** from spatial
neighbours in the in-progress mi-grid. After a keyframe every neighbour
in the first inter frame carries the default `(ZEROMV, LASTFRAME)` —
nothing has been picked yet — so `find_mv_refs` returns `(0, 0)` for
every candidate. NEAREST/NEAR/NEW therefore evaluate against the same
all-zero anchor, the strict-`<` RD argmin defaults to NEARESTMV (the
cheapest), and the picker emits `LASTFRAME + ZEROMV` everywhere. The
*second* inter frame inherits the same degeneracy because the
in-progress mi-grid for frame N still starts from `Default::default()`
at the top of `pick_and_simulate_inter_encode_partitions`, so frame N's
top-left leaf sees the same chicken-and-egg as frame 1. The libvpx
escape hatch from this is the **previous frame's coded MV grid**
(`cm->prev_frame->mvs`, `vp9_mvref_common.c:25-28`) — `find_mv_refs`
salvages the co-located cell's MV when no spatial neighbour matches the
target ref. `wrk_docs/E9_quality_gap_decomposition.md` §4 calls this
out by name: *"MV-ref seeding is degenerate: `find_mv_refs` returns
(0,0) nearest everywhere, so NEARESTMV codes a zero-motion prediction
even where the scene moves → large residual → 26 dB"*. F.2's
`find_mv_refs` port cannot lift the curve without the prev-grid being
populated and available — that is what F.0.3 finishes.

### 2.4 Net diagnosis

- **Writer-side capture: works.** `out_mv_grid` is populated correctly
  on every inter frame; `self.prev_mv_grid` holds a well-formed grid
  for the *next* frame.
- **Reader-side wiring: works.** Picker + writer both accept and
  thread `Option<&[PrevFrameMvRef]>` to `find_mv_refs`; the per-leaf
  lookup math is correct.
- **Gate logic: works.** `gate_open` correctly mirrors libvpx's
  `use_prev_frame_mvs` predicate (size-match + `!last_frame_was_key`,
  with `!error_resilient`, `!last_intra_only`, `last_show_frame`
  collapsing to `true` by Stage 4a' scope).
- **Activation: defeated.** The unconditional `env::var_os(
  "RVP9_A18_ACTIVATE").is_some()` clause forces the slice to `None`
  every frame.

The "no-op" is therefore precisely the one boolean. The work F.0.3
needs to do is **not "wire it up"** (it is wired) — it is **"unblock
activation without regressing testsrc"**. The next two sections
explain why activation regressed testsrc, and what minimal change
fixes that without modifying `find_mv_refs`.

### 2.5 Why activation regressed testsrc (regression that gated A18 off)

From `notes\divergence-ledger.md:676-697`:

> With activation ON: **testsrc**: BD-rate +630.68 % → +870.01 %
> (regression -240 pp). **foreman**: unchanged (the prev_mv_grid
> is all-zero because no NEWMV picks happen on the previous frame,
> so the salvage adds zero candidates that dedup against the
> already-zero spatial list).
>
> Root cause: with non-zero prev-frame MVs propagating into
> `mvc.near`, the picker's RD math favours NEARMV (rate-free; no
> MV-delta bits) even when its prediction error is worse than
> refined-NEWMV's after diamond + sub-pel. The picker's strict-`<`
> argmin then keeps NEARMV. Cross-decoder remains byte-exact (the
> encoder and decoder agree on the wrong picks).

So activating A18 makes the **picker** pick NEARMV on testsrc when
NEWMV would have won. That is a picker-side RD-ranking bug, not a
prev_frame_mvs plumbing bug. It is exactly what F.1 (block_yrd) and
F.2 (find_mv_refs proper) are scoped to fix — block_yrd makes NEWMV's
residual savings visible to the RD score so NEWMV beats rate-free
NEARMV when the prediction is actually better. **Until F.1/F.2 land,
activating A18 today is a net regression. After F.1/F.2 land,
activating A18 unlocks the temporal salvage path the gap analysis
requires.**

## 4. Proposed completion path

The plumbing is in place. The remaining work is to **flip the
activation gate** in a way that **doesn't regress testsrc until F.1
and F.2 land**, and to **prove the path now fires** in tests that
F.2 can trust.

### 4.1 Writer integration point — already correct, leave alone

`pick_and_simulate_inter_encode_partitions` writes `out_mv_grid` at
`lib.rs:3500-3535` unconditionally on every inter frame. The keyframe
path at `frame_loop.rs:690-706` rebuilds the grid as all-`(IntraFrame,
ZERO)`. **No change required.** A18 already captures correctly.

### 4.2 Reader integration point — the one mechanical change

Replace the env-gated activation in `frame_loop.rs:859-867` with a
**boolean field on `EncoderConfig`** (default `false`, single source
of truth, name suggestion `use_prev_frame_mvs: bool`).

```rust
let prev_grid_slice: Option<&[PrevFrameMvRef]> = if gate_open
    && self.config.use_prev_frame_mvs   // was: env::var_os("RVP9_A18_ACTIVATE")
{
    self.prev_mv_grid.as_deref()
} else {
    None
};
```

Why the change: an env var is invisible to tests, harnesses, and the
F.2 implementer. Moving it to `EncoderConfig` means F.2's tests can
flip it on explicitly per-test, the BD-rate harness can sweep it as
part of "with A18" vs "without A18" diagnostic runs, and the default
stays `false` so byte-exact output and BD-rate baselines are
preserved on the gate-passing CI build.

**Default `use_prev_frame_mvs = false`** for the moment — F.2's HLD
will flip the default to `true` once the picker's NEARMV/NEWMV
RD-ranking is fixed.

### 4.3 Data shape — already correct

`Vec<PrevFrameMvRef>` of length `mi_rows * mi_cols`, row-major at
stride `mi_cols`. Each cell is `{ mvs: [Mv; 2], ref_frames:
[RefFrame; 2] }` (`crates\rvp9-core\src\inter\mv_ref.rs:648-668`).
The decoder uses an `Arc<Vec<…>>` for cheap sharing across the
per-tile workers (`crates\rvp9-decoder\src\lib.rs:428,2776`); the
encoder is single-tile so a plain `Vec` is sufficient and **no
change is needed**.

### 4.4 Invalidation rules — already correct

| Event | Action | Site |
|---|---|---|
| Keyframe | Rebuild grid as all-`(IntraFrame, ZERO)`, `last_frame_was_key = true`. | `frame_loop.rs:690-706` |
| Frame resize (A19 surface) | Gate fails on `prev_mv_grid_dims != (mi_rows, mi_cols)`, so `prev_grid_slice = None`. The grid is then overwritten by the next frame's picker write-back at the new size. | `frame_loop.rs:859-860` |
| `show_existing_frame` | Not emitted by Stage 4a' encoder. Equivalent of "don't update prev_frame" handled by the keyframe / inter dichotomy. | n/a |
| First inter after KF | Gate fails on `last_frame_was_key == true`, so `prev_grid_slice = None`. Picker behaves as today. | `frame_loop.rs:859` |

### 4.5 A19 interaction

A19 (frame-resize) is the night-7 surface that handled mid-stream
resize. The grid dims check in `gate_open` (`frame_loop.rs:860`)
already collapses resize into "gate closed", which is the libvpx
behaviour (`vp9_encodeframe.c:6109` — `cm->width == cm->last_width &&
cm->height == cm->last_height`). **A19 needs nothing further** —
the resize codepath drops `prev_mv_grid` on the next frame's picker
write-back at the new dims, the grid stays sized to whatever the
last *encoded* frame was, and the next inter frame after the resize
runs with `prev_grid_slice = None`. Self-correcting.

### 4.6 No public picker / API breakage

`pick_and_simulate_inter_encode_partitions` and
`build_inter_packet_with_residuals` already accept the grid. The
public encoder API (`StreamEncoder::encode_frame`) is unchanged. The
single new surface is `EncoderConfig.use_prev_frame_mvs: bool`
(default `false`).

**Implementer note (serde):** verify the trait derivations on
`EncoderConfig` before adding any `#[serde(default)]`. If
`EncoderConfig` derives `Deserialize`, add `#[serde(default)]` so
existing JSON/TOML configs still parse without the new field. If it
doesn't, no annotation needed.

## 7. Realtime-budget impact

Negligible. Per-frame cost added:

- **Write-back loop in picker** (`lib.rs:3500-3535`): already runs.
  No change.
- **Per-leaf prev-grid lookup** (`lib.rs:2767-2770`): one `Vec::get`
  + one `Copy` of a 16-byte struct (`PrevFrameMvRef`: 2× `Mv` = 8B,
  2× `RefFrame` = 2B, padding to 16B). Per leaf. At foreman_cif
  256×256 with the F8.2 partitioner descending to ~1024 leaves per
  inter frame, that's ~1024 lookups × ~20 ns ≈ **20 µs per frame**.
- **Writer-side per-block lookup** (`modes_writer.rs:1472`'s inner
  loop): one lookup per leaf, same cost. Another ~20 µs.

Total: ~40 µs / 5340 µs current foreman median = **0.75 %** of the
existing realtime budget. Against the 33 ms hard gate that is
**0.12 %**.

The picker pipeline is already gated off for `w * h > 307_200`
(`lib.rs:2330,2340,2359` — A4.rt-recovery from night-7), so 720p+
inter leaves never even reach the lookup site. **A18 cannot regress
the 33 ms RT gate.**

# HLD — `pick_inter_mode` port completion

**Date:** 2026-05-24
**Author:** Arthur + Claude
**Input:** `wrk_docs/2026.05.24 - pick_inter_mode gap inventory.md`
**Goal:** Close the +9 dB foreman PSNR-delta gap by completing the port of libvpx's `vp9_pick_inter_mode` realtime path.

---

## 1. Problem statement

The gap inventory identifies 24 NOT PORTED and 13 PARTIAL helpers in
the `vp9_pick_inter_mode` call tree. The current rvp9 picker
(`pick_inter_mode_luma`, 67 lines) is a stub: it evaluates 4
candidates against 1 ref frame, uses a full DCT round-trip as its
cost model (10× more expensive than libvpx's variance-domain
`model_rd_for_sb_y`), and lacks intra-in-inter fallback, adaptive TX
selection, skip-txfm early-exit, encode-breakout, UV RD, and most
speed-feature pruning.

The stub is also too expensive for 720p+, so the entire picker is
gated off above 640×480 (`inter_picker_enabled = w * h <= 307_200`).
At 720p the encoder emits ZEROMV-skip on every inter leaf.

Additionally, the codebase has accumulated env-var gates on partial
ports: `RVP9_F1_SKIP_TIE_BREAK_ENABLE`, `RVP9_F3_NONRD_PARTITION_ENABLE`,
`RVP9_F5_FILTER_SEARCH`, `RVP9_FIXED_Q`, and various `RVP9_DIAG_*` /
`RVP9_E*` instrumentation flags. Several of these guard code that
should be unconditionally active; others guard dead experiments.

Two cross-cutting issues compound the problem:

1. **`inter_mode_ctx` hardcoded to 0** (`lib.rs:3217`). The picker
   always uses mode-context 0 ("both neighbours have zero MV"), which
   over-charges NEWMV by ~1 bit per block vs the true per-block context.
   This directly contributes to Track G's "picker rejects NEWMV" finding.

2. **Frame context adaptation disabled.** The encoder always emits
   `refresh_frame_context: false` and builds all cost tables from
   `FrameContext::new_default()`. libvpx adapts probs per-frame and
   sets `refresh_frame_context: true`. Our cost model systematically
   diverges from the true bitstream cost across multi-frame sequences.

## 2. Design principles

1. **Port, don't invent.** Match libvpx's realtime `vp9_pick_inter_mode`
   line-for-line where practical. Don't try to improve on libvpx's
   design — the goal is compression parity, not superiority.

2. **Always on.** No new environment variables or feature flags. Each
   phase compiles, passes all tests, and is unconditionally active.
   Remove existing env-var gates as we absorb their functionality.

3. **Smallest diff per phase.** Each phase is one logical unit that
   compiles and passes gates. Commit after each.

4. **Measure after each phase.** Run the F.0.1 PSNR-delta gate
   (foreman_cif at 25/50/100/250 kbps) and the 720p30 RT gate. Record
   the number in the commit message.

## 3. Architecture

### 3.1 New top-level function: `pick_inter_mode`

Replace the current `pick_inter_mode_luma` (67 lines, luma-only,
single-ref, full-DCT-round-trip) with a new `pick_inter_mode` that
mirrors libvpx's `vp9_pick_inter_mode` (1134 lines) structurally:

```
pick_inter_mode(params: &PickInterModeParams) -> PickInterModeResult
  ├── for each ref_frame in [LAST, GOLDEN]:
  │     └── find_predictors(ref_frame)     // mv_refs + mv_pred
  ├── for each (ref_frame, mode) in RT_INTER_MODES:
  │     ├── build_inter_prediction(...)    // sub-pel convolution
  │     ├── model_rd_for_sb_y(...)         // cheap variance RD + TX size
  │     ├── if !early_term:
  │     │     ├── block_yrd(...)           // refine RD with coef estimate
  │     │     └── skip_flag_tie_break(...) // encode vs skip comparison
  │     ├── UV RD (model_rd_for_sb_uv)    // chroma rate+dist
  │     ├── accumulate rate (mode + ref + mv) + rdcost
  │     ├── encode_breakout_test(...)      // post-RD: skip block entirely
  │     ├── update best_rdc
  │     └── if x->skip or best_early_term: break
  ├── intra_in_inter_search(...)           // DC/V/H/TM fallback
  └── return best
```

**Note on ordering:** `encode_breakout_test` runs AFTER the full RD
cost is computed (libvpx pickmode.c:2415-2425), not between model_rd
and block_yrd. It tests whether the prediction alone (no residual) is
good enough using `var_y` and `sse_y` from model_rd. When it fires,
it sets `skip = true` which breaks the entire mode loop (line
2468-2470). This is a late-stage short-circuit.

**Note on prediction build:** every candidate builds the inter
prediction (sub-pel convolution) BEFORE model_rd can run, because
model_rd needs `variance(src, pred)`. model_rd saves the DCT+quant+
dequant+IDCT round-trip (~60% of per-candidate cost), but the
prediction build is not eliminated.

The new function lives in `crates/rvp9-core/src/mode_decision/inter.rs`,
replacing the existing `pick_inter_mode_luma`. The old function and its
`InterModeSearchParams` / `InterModeSearchResult` types are superseded —
the new types carry the additional fields.

The caller in `lib.rs:pick_and_simulate_inter_encode_partitions`
simplifies: instead of calling `pick_inter_mode_luma` twice (once per
ref) and taking the argmin, it calls `pick_inter_mode` once. The
dual-ref loop, the `ref_frame_cost_last` / `ref_frame_cost_golden`
computation, and the GOLDEN argmin logic all move into the picker.

Port each libvpx helper as a standalone function in the appropriate

### 3.3 Env-var cleanup

Remove these gates as we absorb their functionality into the
unconditional picker:

| Gate | Disposition |
|---|---|
| `RVP9_F1_SKIP_TIE_BREAK_ENABLE` | Absorbed into `pick_inter_mode`; always on |
| `RVP9_F3_NONRD_PARTITION_ENABLE` | Stays for now (partition is out of scope for this HLD) |
| `RVP9_F5_FILTER_SEARCH` | Absorbed; filter search always on once switchable-rate is correct |
| `RVP9_FIXED_Q` | Keep (diagnostic tool, not a feature flag) |
| `RVP9_DIAG_*`, `RVP9_E*` | Keep (diagnostics, not feature flags) |

### 3.4 Removing the 720p gate

The three area gates in `lib.rs` (`inter_picker_enabled`,
`block8x8_picker_enabled`, `int_pro_enabled`) exist because the
full-DCT-round-trip picker is too expensive at 720p. With
`model_rd_for_sb_y` as the primary cost model — variance is ~10×
cheaper than DCT+quant+dequant+IDCT — the picker becomes affordable
at 720p. The gates are removed in Phase 3 after `model_rd_for_sb_y`
is proven to meet the RT budget.

## 4. Phased delivery

### Phase 0 — `inter_mode_ctx` threading + frame context adaptation (~70 LOC)

Two independent fixes, each its own commit. Neither touches the
picker's structure — they fix the inputs.

**0a. `inter_mode_ctx` threading (~10 LOC)**

`find_mv_refs` already returns `mode_context` via `RefMvList`. The
encoder ignores it and passes `inter_mode_ctx: 0` to the picker.
Thread the returned value into `InterModeSearchParams::inter_mode_ctx`.

This is the cheapest single fix likely to move the NEWMV needle.
Context 0 over-charges NEWMV by ~1 bit/block; correct context charges
~1.9 bits — a 35% rate reduction on NEWMV candidates. On foreman at
100 kbps (~2,500 NEWMV-eligible blocks) this directly addresses the
Track G diagnosis.

**0b. Frame context adaptation (~60 LOC)**

Wire `vp9_adapt_mode_probs`, `vp9_adapt_mv_probs`,
`vp9_adapt_coef_probs` into the encoder's frame loop (the backward-
adapt functions already exist in `rvp9-core` for the decoder). Flip
`refresh_frame_context: true` in the bitstream header. Build per-frame
cost tables from the adapted `FrameContext` instead of
`FrameContext::new_default()`.

This fixes the systematic cost-model drift: MV costs, mode costs,
skip probs, and coef probs now track the actual content statistics
across the sequence. Orthogonal to the picker structure.

**Tests for both:**
- Existing encoder lib tests (100/100).
- Cross-decoder gate (vpxdec + ffmpeg + rvp9dec).
- F.0.1 PSNR-delta measurement.

### Phase 1 — Variance-domain RD model (~160 LOC)

**Port:** `vp9_model_rd_from_var_lapndz`, `model_rd_for_sb_y`,
`calculate_tx_size`.

**New file:** `crates/rvp9-core/src/mode_decision/model_rd.rs`

**What changes in the picker:** `evaluate_candidate` gains a fast
path: call `model_rd_for_sb_y` first. If `skip_txfm == AC_DC` (the
prediction is so good the residual quantises to zero), return
immediately with `(rate=0, dist=sse<<4)` — no DCT round-trip needed.
Otherwise, proceed to the existing `reconstruct_via_round_trip` +
`block_yrd` path.

The sub-pel convolution to build the prediction still runs for every
candidate (model_rd needs `variance(src, pred)`). The saving is the
DCT+quant+dequant+IDCT round-trip (~60% of per-candidate cost), not
the prediction build. The transform round-trip still runs for the
winning candidate to produce the actual reconstruction and
coefficients.

**TX size:** `calculate_tx_size` selects the transform size per-block
based on the var/sse ratio from `model_rd_for_sb_y`. The selected TX
size flows into `reconstruct_via_round_trip`. This replaces the
current `max_txsize(block_size)` hard-coding.

**Tests:**
- Unit tests for `vp9_model_rd_from_var_lapndz` against the libvpx LUT
  (known-value tests at representative q/var points).
- Unit test for `calculate_tx_size` (known var/sse inputs → expected TX).
- Existing encoder lib tests (100/100 must stay green).
- Cross-decoder gate (vpxdec + ffmpeg + rvp9dec).
- F.0.1 PSNR-delta measurement (expect improvement from TX-size selection).
- 720p30 RT gate (expect speedup from skip_txfm early-exit).

**Deliverable:** Compiling, unconditionally active, measured.

### Phase 2a — Restructured picker loop (~200 LOC)

**Port:** The top-level `vp9_pick_inter_mode` loop structure,
`find_predictors` (partial — just the `vp9_find_best_ref_mvs` piece).

A new `pick_inter_mode` function replaces `pick_inter_mode_luma`. It:

1. Iterates `(ref, mode)` in libvpx's `RT_INTER_MODES` order:
   `[(LAST, ZERO), (LAST, NEAREST), (GOLDEN, ZERO), (LAST, NEAR),
   (LAST, NEW), (GOLDEN, NEAREST), (GOLDEN, NEAR), (GOLDEN, NEW)]`.

2. Uses `model_rd_for_sb_y` (Phase 1) as the primary cost estimate for
   each candidate. Calls `block_yrd` only when `!early_term`.

3. Skip-flag tie-break is unconditionally active (absorbs
   `RVP9_F1_SKIP_TIE_BREAK_ENABLE`). Lambda is calibrated from
   Phase 1's `model_rd_for_sb_y` scale.

4. `encode_breakout_test` runs after the full rdcost is computed
   (matching libvpx pickmode.c:2415 position). When it fires,
   sets `skip = true` → breaks entire mode loop.

**New params type:** `PickInterModeParams` replaces
`InterModeSearchParams`. Carries both ref planes, both MvCandidates
(LAST + GOLDEN). The old type is removed.

**Caller simplification:** `pick_and_simulate_inter_encode_partitions`
in `lib.rs` drops the dual-ref loop, the `ref_frame_cost_*` computation,
and the GOLDEN argmin logic. The new picker handles all of this internally.

**Tests:**
- Existing encoder lib tests (100/100).
- Cross-decoder gate.
- F.0.1 PSNR-delta.
- 720p30 RT gate (expect improvement from model_rd fast path + breakout).

### Phase 2b — Intra-in-inter fallback (~120 LOC)

**Port:** Intra-in-inter fallback body (pickmode.c:2517-2646),
`vp9_get_intra_cost_penalty` (~20 LOC).

After the inter loop from Phase 2a, evaluate DC/V/H intra modes gated
by `best_rdc.rdcost > inter_mode_thresh` (libvpx's gate). Uses the
existing `pick_intra_mode_luma` infrastructure but adds
`intra_cost_penalty` to the rate. Replaces best if intra wins.

**Impact note:** On foreman specifically, the F.0.2 oracle measured
rvp9 at 1.7% intra in inter frames vs libvpx's 1.6% — nearly
identical, so this may contribute only ~0.3-0.5 dB on foreman. Impact
will be larger on scene-change-heavy content. Measure on both.

**Tests:**
- Existing encoder lib tests.
- Cross-decoder gate.
- F.0.1 PSNR-delta.

### Phase 2c — Absorb env-var gates (~30 LOC net reduction)

Remove `RVP9_F1_SKIP_TIE_BREAK_ENABLE` and `RVP9_F5_FILTER_SEARCH`
env-var checks. The functionality these gates protected is now
unconditionally active within the restructured picker (skip tie-break
from 2a, filter search with per-context switchable rate from the
existing `switchable_interp_costs` table).

### Decision gate — partition convergence check

After Phase 2c, measure the partition distribution on foreman_cif
(8×8 / 16×16 / 32×32 fraction) and compare to libvpx's (41% / 56% /
3%). If it hasn't converged from the pre-Phase-0 baseline (64% / 36%
/ 0.3%), the picker improvements aren't self-correcting the partition
and the partition decision needs explicit attention before Phase 3.

### Phase 3 — Remove 720p gate (~50 LOC net reduction)

**What changes:** Delete the three area gates:
```rust
let block8x8_picker_enabled = w * h <= 307_200;
let int_pro_enabled = w * h <= 307_200;
let inter_picker_enabled = w * h <= 307_200;
```

The Phase 0-2 picker is cheaper than the old full-DCT-round-trip
picker (model_rd + breakout save ~60% of per-candidate cost). If the
first measurement shows it still doesn't meet the 33 ms 720p30
budget, add `model_rd_for_sb_y_large` (the extended variant with
8x8-granularity skip for ≥32×32 blocks, ~200 LOC) as Phase 3b.

**Tests:**
- 720p30 RT gate is the critical gate. Must stay ≤ 33 ms p50.
- F.0.1 PSNR-delta on 720p content (first time we can measure this).
- Cross-decoder gate at 720p.

### Phase 4 — Polish (~200 LOC total)

Independent items, each its own commit:

**4a. `vp9_mv_pred` seeding (~50 LOC)**
Port `vp9_mv_pred` to `mv_search/mv_pred.rs`. It evaluates SAD at
each MV-ref candidate and picks the best as the NEWMV diamond seed.
Currently we always seed from `nearest`, which is often (0,0). This
should improve NEWMV quality on motion content.

**4b. UV RD integration (~50 LOC)**
Add `model_rd_for_sb_uv` to Phase 1's `model_rd.rs`. Thread UV
rate+dist into the picker's candidate comparison. Prevents the
picker from choosing a mode that looks good in Y but destroys chroma.

**4c. block_yrd with Hadamard + quantize_fp (~80 LOC)**
Port `vpx_hadamard_{8x8,16x16}` (the scalar Hadamard kernel already
exists in `mode_decision/hadamard.rs` from Track F night-8). Port
`vp9_quantize_fp` (zbin-free variant) to `quant/forward.rs`. Wire
both into `block_yrd`. Remove K1=4 calibration constant — Hadamard +
quantize_fp produces magnitudes that match libvpx's SATD-to-bits
model without a correction factor.

**4d. Duplicate-MV dedup + const_motion skip (~20 LOC)**
Add `mode_checked[][]` dedup and `const_motion` NEARMV skip. Small
speed improvement.

## 5. Caller-side changes in lib.rs

The current `pick_and_simulate_inter_encode_partitions` function
(~1700 lines) does three things:
1. Partition descent (variance or nonrd)
2. Per-leaf mode pick (calling `pick_inter_mode_luma`)
3. Reconstruction (forward quant + coef collection)

Phases 1-2 change (2) only. The function's structure stays the same —
the per-leaf loop body calls the new `pick_inter_mode` instead of the
old `pick_inter_mode_luma`, and the dual-ref argmin wrapper around the
old call is deleted.

The reconstruction step (3) stays unchanged: the picker returns the
winning mode/mv/filter, and the existing forward-quant + coef-collection
code runs exactly as before.

## 6. What this does NOT change

- **Partition decision.** The variance-based partitioner
  (`choose_partitioning`) and the gated `nonrd_pick_partition` skeleton
  stay as-is. Activating motion-aware partition is a separate track.
- **Rate control.** No RC changes. The picker produces better
  predictions → fewer bits per frame → RC sees lower overshoot → q
  drops → quality improves. This is the same mechanism that closed the
  overshoot in Track E.
- **Decoder.** No decoder code changes. Phase 0b flips
  `refresh_frame_context: true` in the bitstream, which activates the
  decoder's existing backward-adapt path — no new decoder code needed.
- **Wire format.** No new bitstream features. The picker may select
  different modes/MVs/TXsizes/filters than before, but the wire format
  is unchanged.
- **SVC.** SVC-specific paths inside `vp9_pick_inter_mode` are out of
  scope (PLAN.md §4d).
- **Denoiser.** The denoiser interaction points inside
  `vp9_pick_inter_mode` are out of scope (PLAN.md §4c).

## 7. Expected outcome

Phase 0 (input fixes) is expected to close 1-2 dB:
- `inter_mode_ctx` threading: ~0.5-1 dB (NEWMV rate penalty drops 35%)
- Frame context adaptation: ~0.5-1 dB (cost model tracks content stats)

Phases 1-2 (RD model + restructured picker) is expected to close
another 2-3 dB:
- `model_rd_for_sb_y` + TX-size selection: ~1-2 dB (better TX choices →
  fewer wasted bits on high-frequency coefficients)
- Intra-in-inter: ~0.3-1 dB (content-dependent; 0.3 dB on steady-motion
  foreman, 1-2 dB on scene-change content)
- Encode-breakout: ~0.3-0.5 dB (freed bits reallocated to blocks that
  need them)

Phases 3-4 (720p gate + polish) is expected to close another 1-2 dB:
- 720p gate removal: enables measurement at the target resolution
- UV RD: ~0.3-0.5 dB
- vp9_mv_pred seeding: ~0.3-0.5 dB
- Hadamard + quantize_fp: ~0.3-0.5 dB

**Honest hedges:**
- These are estimates, not measurements. Track F showed that
  single-knob interventions can regress. The measurement-after-
  each-phase discipline catches this.
- model_rd doesn't eliminate the prediction build (sub-pel convolution
  still runs for every candidate). The speed saving is ~60% of per-
  candidate cost, not 10×. Phase 3's 720p gate removal should be
  validated empirically.
- The partition self-correction hypothesis (better picker → better
  mi_grid → lower residual variance → less over-splitting) is
  untested. The decision gate after Phase 2c checks this. If partition
  doesn't converge, explicit partition work is needed before Phase 3.
- Intra-in-inter impact may be <0.5 dB on foreman (F.0.2 oracle
  showed 1.7% intra vs libvpx's 1.6% on this clip). A second test
  clip with scene changes would validate the estimate.

**Target:** Foreman PSNR-delta ≤ +4 dB after Phase 2c (curves overlap,
BD-rate becomes computable). BD-rate ≤ +5% after Phase 4. The
PLAN.md ±0.5% BD-rate gate is likely reachable after the Tier 3
inventory items (partition, speed features) but is out of scope for
this HLD.

## 9. Risks

| Risk | Mitigation |
|---|---|
| model_rd_for_sb_y is less accurate than DCT round-trip → quality regression on some content | Keep DCT round-trip for the final winner; model_rd is only used for candidate screening and skip-txfm. Measure after Phase 1. |
| 720p gate removal exceeds RT budget | model_rd saves ~60% of per-candidate cost, not 100%. Phase 3 is gated on Phase 0-2 meeting budget. If not, add `model_rd_for_sb_y_large` (Phase 3b). |
| Intra-in-inter over-selects intra (wrong `intra_cost_penalty` calibration) | Port `vp9_get_intra_cost_penalty` exactly as libvpx. Measure. Impact may be small on foreman (F.0.2 oracle: 1.7% vs 1.6% intra). |
| Non-monotonic interaction between phases | Phases 2a/2b/2c are split so regressions are isolatable. Measure after each. |
| Partition doesn't self-correct after picker improvements | Decision gate after Phase 2c explicitly checks. If 8×8 fraction stays at ~64% (vs libvpx 41%), partition needs its own track. |
| Frame context adaptation introduces encoder/decoder mismatch | The backward-adapt functions are the same code the decoder uses. `refresh_frame_context: true` ensures decoder tracks the same tables. Cross-decoder gate catches any mismatch. |
| Touching `pick_inter_mode_luma` conflicts with concurrent work | Coordinate — this is a replacement, not incremental modification. The old function is deleted in Phase 2a. |

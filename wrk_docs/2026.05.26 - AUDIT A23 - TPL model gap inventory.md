# AUDIT A23 — TPL model / non-greedy MV / mbgraph gap inventory

**Date:** 2026-05-26
**Audit zone:** A23 (TPL model / non-greedy MV / mbgraph)
**Status:** READ-ONLY comparative audit, single pass
**Scope:** vpxenc faithful-port — full parity, all profiles, all RC modes, all `cpu-used 0..=8`. TPL is IN-SCOPE per Arthur 2026-05-25 (it is enabled by libvpx default and gated by `--enable-tpl` in `vpxenc`).

## Method

Line-by-line comparison of three libvpx encoder source files against the entire rvp9 codebase:

- `third_party/libvpx/vp9/encoder/vp9_tpl_model.c` (1541 LOC) — TPL data structures, GOP init, motion-comp dispenser, propagation, non-greedy MV mode picker.
- `third_party/libvpx/vp9/encoder/vp9_non_greedy_mv.c` (536 LOC, ~370 net of the 1024-entry `log2_table`) — MotionField allocation, MV inconsistency, motion-field smoothing, local-structure tensor.
- `third_party/libvpx/vp9/encoder/vp9_mbgraph.c` (388 LOC) — 16x16 motion-graph stats over the GOP lookahead, feeding `separate_arf_mbs` segmentation.
- `third_party/libvpx/vpx/vpx_tpl.h` (103 LOC) — public `VpxTplGopStats` ABI used by the ext-ratectrl integration.

Consumer wiring grepped in libvpx: `vp9_encoder.{c,h}`, `vp9_encodeframe.c`, `vp9_rdopt.c`, `vp9_ratectrl.c`, `vp9_speed_features.c`, `vp9_ext_ratectrl.c`, `vp9_cx_iface.c`, `simple_encode.cc`.

rvp9 grepped exhaustively across `crates/` for tokens: `tpl`, `TPL`, `non_greedy`, `mc_flow`, `mbgraph`, `tpl_dep`, `tpl_model`, `tpl_stats`, `motion_field`, `MotionField`, `nb_mvs_inconsistency`, `wht_fwd_txfm`, `setup_tpl`, `init_tpl`, `mode_estimation`, `update_mbgraph`. Result: **zero matches** across all `rvp9-core` and `rvp9-encoder` crates. The only `enable_tpl` references in the repo are in archived `notes/vp9-analysis/`, the A12/A3/A7 audit gap docs, and the A23 follow-up note in `wrk_journals/`. There is **no implementation** of any TPL/non-greedy/mbgraph subsystem in rvp9 today.

Combined libvpx LOC: ~2465. Picker baseline = 45 rows for 2820 LOC → scale factor 0.87 → expected row band 18-60. Audit lists **49 rows** (44 NOT PORTED, 5 OUT OF SCOPE, 0 PORTED, 0 PARTIAL). Sanity-check passes.

Because rvp9 has zero TPL infrastructure, the audit's row-by-row "rvp9 file:line" citation is trivially "absent — confirmed via grep". To satisfy the anti-G3 rule, the cross-cutting absence is documented once in section 0 with the grep evidence, and individual NOT-PORTED rows do not repeat it.

## 0. Cross-cutting gap — entire subsystem absent

**Status: NOT PORTED**

Confirmation via grep across the rvp9 source tree:

```
Grep tpl|TPL|TplDep|non_greedy|mc_flow|mbgraph|tpl_dep|tpl_model|tpl_stats|motion_field  -i  crates/
→ No files found.

Grep tpl|TPL|non.greedy|mc_flow|mbgraph|motion_field  -i  crates/
→ No matches found.

Grep enable_tpl|setup_tpl|init_tpl|mc_flow_dispenser|mode_estimation|update_mbgraph|wht_fwd_txfm|nb_mvs_inconsistency|motion_field|MotionField  crates/
→ No files found.
```

The only references to `enable_tpl` in the repository are in archived `notes/vp9-analysis/01-architecture.md`, `notes/vp9-analysis/06-threading-svc.md`, `notes/hld/04-svc.md` (architecture notes describing libvpx, not rvp9 code), and the A3 / A7 / A12 gap inventories plus the A23 follow-up note in `wrk_journals/2026.05.26 - JRN - vpxenc parity audit drive.md`. No CLI flag `--enable-tpl` is plumbed in `rvp9-cli`; the A12 audit row 95 already classifies `--enable-tpl` as NOT PORTED.

This means every TPL-related quality consumer in libvpx is currently a quality regression vs vpxenc:

- **`r0` cost-model normaliser**: libvpx computes `r0 = intra_cost_base / mc_dep_cost_base` from TPL accumulators (vp9_encodeframe.c:6141-6163). rvp9 has no `rd.r0`, no TPL accumulators, no per-frame intra-vs-MC ratio. The frame-level RD scaling is therefore content-blind in rvp9.
- **Per-64x64 rdmult delta (`get_rdmult_delta`)**: libvpx perturbs `x->cb_rdmult` per 64x64 SB based on the TPL `intra/mc_dep` ratio (vp9_encodeframe.c:3717-3760). rvp9 always uses the frame-level `rdmult`. Quality cost: blocks with high downstream mc_dep_cost (high motion-trail importance) get the same lambda as throwaway blocks, so the picker over-spends on terminal blocks and under-spends on reference blocks.
- **NEWMV discount (`discount_newmv_test` NGM branch)**: libvpx (rdopt.c:2767-2798) discounts NEWMV cost when the TPL MV for the same block is within 8 pels of the candidate. rvp9 has no TPL MV → can't run this path at all, and falls back to the non-NGM branch which is also NOT PORTED (rvp9 hardcodes a separate NEWMV-bias heuristic, see A1-P0 `inter_mode_ctx`).
- **Ext-rc TPL forward (`vp9_extrc_send_tpl_stats`)**: classified OUT OF SCOPE here only because rvp9 has no ext-ratectrl surface at all (none of `vpx_ext_ratectrl.h` is plumbed). Documenting the absence so it's not mistaken for a TPL-internal gap.
- **2-pass ARF preamble (`vp9_setup_tpl_stats` call from `encode_frame_to_data_rate`)**: gated on `gf_group_index == 1 && update_type == ARF_UPDATE && sf.enable_tpl_model` (vp9_encoder.c:6614-6626). rvp9 has no 2-pass / ARF path today (A10 / A16), so even if TPL were ported, the call site itself is absent.

Cross-zone dependencies (must land before TPL is wireable):
- **A10 (ALTREF construction)** — TPL is keyed off the GF/ARF GOP boundary; without ARF the call site never fires.
- **A19 (lookahead pipeline)** — `init_gop_frames` peeks `cpi->lookahead`; without lookahead, GF_PICTURE entries 2..N can't be populated.
- **A3 (rate control, 2-pass)** — TPL only runs in 2-pass-VBR-with-lag mode (`oxcf.lag_in_frames > 0 && rc_mode == VPX_VBR`). Without 2-pass + lag, the entire subsystem is inert.
- **A11 (segmentation / AQ)** — `mbgraph` writes directly into `cpi->segmentation_map` and calls `vp9_enable_segmentation` to mark static MBs.
- **A12 (CLI / config)** — `--enable-tpl` flag and `oxcf.enable_tpl_model` default `1` are NOT PORTED per A12 row 95 / row 151.

### `TplDepStats` (vp9_encoder.h:292-301) — NOT PORTED
Per-mi-block stats holding `intra_cost`, `inter_cost`, `mc_flow` (accumulated downstream propagation), `mc_dep_cost = intra_cost + mc_flow` (recomputed on every store), `mc_ref_cost` (accumulated reference-cost reduction), `ref_frame_index` and the picked `mv`. ### `TplDepFrame` (vp9_encoder.h:312-326) — NOT PORTED

### `cpi->tpl_stats[MAX_ARF_GOP_SIZE]` array + sidecars (vp9_encoder.h:751-772) — NOT PORTED

## 2. TPL stats setup pipeline

### `vp9_setup_tpl_stats` (vp9_tpl_model.c:1492-1540) — NOT PORTED
Top-level driver. Sets `tpl_bsize = BLOCK_32X32` (line 1498), calls `init_gop_frames`, zeros stats via `init_tpl_stats`, allocates the pre-propagation block arrays via `init_tpl_stats_before_propagation`, then runs the backward propagation loop `for (frame_idx = tpl_group_frames - 1; frame_idx > 0; --frame_idx)` calling `mc_flow_dispenser`. Finally `trim_tpl_stats` strips the 2-frame look-past, and if ext-rc is wired, forwards via `vp9_extrc_send_tpl_stats`.

### `init_gop_frames` (vp9_tpl_model.c:25-155) — NOT PORTED
Builds the `GF_PICTURE` table for the current GOP plus 2 frames into the next GOP. Reserves recon buffer slots from the frame pool (`recon_frame_index` array, line 40, plus the loop at 45-62 that walks `frame_bufs` looking for ref_count==0 slots). Slot 0 = GOLDEN, slot 1 = base-layer ARF (cpi->Source), slots 2..N = P-frames or nested ARFs walked via an `arf_index_stack` (push on ARF_UPDATE, pop on OVERLAY/USE_BUF). The `ref_frame[3]` per GF_PICTURE entry mirrors libvpx's 3-deep MAX_INTER_REF_FRAMES (LAST/GOLDEN/ALTREF) GOP layout.

### `init_tpl_stats` (vp9_tpl_model.c:157-166) — NOT PORTED
Zeros `tpl_stats_ptr` and `is_valid = 0` for every slot. Necessary precondition for the propagation loop because `mc_flow` / `mc_ref_cost` accumulate over multiple `tpl_model_update_b` calls.

### `init_tpl_stats_before_propagation` (vp9_tpl_model.c:176-199) — NOT PORTED
Allocates the `VpxTplFrameStats[tpl_group_frames]` array plus per-frame `VpxTplBlockStats[mi_rows*mi_cols]` arrays into `cpi->tpl_gop_stats`. Re-runs `free_tpl_frame_stats_list` on every call to handle reallocation.

### `vp9_init_tpl_buffer` (vp9_tpl_model.c:1376-1428) — NOT PORTED
Per-encode lazy allocation: `tpl_stats_ptr` heap for each of `MAX_ARF_GOP_SIZE` frame slots, sized to mi_cols × mi_rows aligned to SB. Under NGM also allocates `select_mv_arr` (size `mi_rows*mi_cols*4`) and per-frame `mv_mode_arr[rf_idx]` + `rd_diff_arr[rf_idx]` arrays (size `mi_rows*mi_cols*4` each).

### `vp9_free_tpl_buffer` (vp9_tpl_model.c:1430-1448) — NOT PORTED
Mirror of init. Called from `vp9_remove_compressor` (vp9_encoder.c:2885).

## 3. Per-frame TPL build — `mc_flow_dispenser`

### `mc_flow_dispenser` (vp9_tpl_model.c:1138-1255) — NOT PORTED
Top-level per-frame routine. Stages:

1. Setup: scale-factors (line 1173-1187), ref-frame pointer table built from `gf_picture[frame_idx].ref_frame[idx]` indices, `xd->cur_buf = this_frame`, rdmult set from `tpl_frame->base_qindex` via `vp9_compute_rd_mult_based_on_qindex` (line 1201), `vp9_initialize_me_consts`, `vp9_frame_init_quantizer` (line 1208).
2. Mark `tpl_frame->is_valid = 1` (line 1205).
3. NGM path (lines 1211-1228): four-pass `build_motion_field` over square block sizes 4x4 → 32x32, then `predict_mv_mode_arr` per ref frame.
4. Main loop (lines 1231-1254): for each `(mi_row, mi_col)` at `tpl_bsize == BLOCK_32X32` stride, call `mode_estimation` → `tpl_model_store` → `tpl_store_before_propagation` → `tpl_model_update`.

This is the quality-critical heart of TPL — the propagation pass that turns per-frame intra/inter costs into the `mc_dep_cost` field consumed by `get_rdmult_delta`.

### `mode_estimation` (vp9_tpl_model.c:571-727) — NOT PORTED
Per-block: scans 4 intra modes (DC, V, H, TM), computes Hadamard SATD as `intra_cost`. Then scans 3 ref frames; under non-NGM does a fresh `motion_compensated_prediction`, under NGM looks up the precomputed `MotionField` MV (line 663-664). Selects best ref by SATD. On the winning candidate, runs `get_quantize_error` + `rate_estimator` to populate `recon_error` and `rate_cost`. Stores `intra_cost`, `inter_cost`, `ref_frame_index`, `mv` into `tpl_stats[mi_row * stride + mi_col]`. The cost normalisation at 720-723 divides by `(mi_height * mi_width)` and shifts by `TPL_DEP_COST_SCALE_LOG2 = 4` (header line 23) — be aware these scale factors must match exactly when porting because every consumer reads scaled costs.

### `vp9_wht_fwd_txfm` (vp9_tpl_model.c:538-546 + .h:35-36) — NOT PORTED
TPL-specific Walsh-Hadamard switchboard over TX_8X8 / TX_16X16 / TX_32X32, calling `vpx_hadamard_{8,16,32}x{8,16,32}`. rvp9 has scalar `hadamard_8x8` and `hadamard_16x16` in `crates/rvp9-core/src/mode_decision/hadamard.rs` for the picker's SATD rate proxy (DV-F1-1), but no `32x32` Hadamard and no TPL switchboard wrapper. Both new size and new wrapper would be needed.

### `vp9_highbd_wht_fwd_txfm` (vp9_tpl_model.c:526-535 + .h:38-39) — NOT PORTED
HBD variant. Necessary for Profile 2/3 coverage (A20) — without it TPL is 8-bit-only.

### `get_quantize_error` (vp9_tpl_model.c:491-523) — NOT PORTED
Uses `vp9_quantize_fp_32x32` (TX-32 path always, regardless of `tx_size`!) to compute quantised+dequantised coefficients, then `vp9_block_error` to compute `recon_error` and the auxiliary `sse`. The `shift = tx_size == TX_32X32 ? 0 : 2` (line 500) accounts for the fact that 32x32 transforms already absorb the extra scaling.

### `rate_estimator` (vp9_tpl_model.c:558-569) — NOT PORTED
Per-coeff `get_msb(abs_level + 1) + 1 + (abs_level > 0)` summed over EOB, then `<< VP9_PROB_COST_SHIFT`. This is **not** the full entropy-coded coefficient cost — it's a cheap log2-magnitude approximation tuned for TPL's bulk-stats use case. Quality-critical to reproduce exactly because the resulting `rate_cost` is what populates `recrf_rate` in the public block stats.

### `set_mv_limits` (vp9_tpl_model.c:548-556) — NOT PORTED
TPL clamps MVs to the picture interior plus `(17 - 2 * VP9_INTERP_EXTEND)` border, not the standard search range. Necessary for `motion_compensated_prediction` to stay in-bounds.

### `motion_compensated_prediction` (vp9_tpl_model.c:280-330) — NOT PORTED
Non-NGM TPL MV search: `vp9_full_pixel_search` with NSTEP + `mv_sf->reduce_first_step_size` step param (clamped to `MAX_MVSEARCH_STEPS - 2`), then `find_fractional_mv_step` with `USE_2_TAPS` interpolation. This is a simpler search than the picker's `combined_motion_search` — single ref-frame, fixed NSTEP, 2-tap subpel.

### `tpl_model_store` (vp9_tpl_model.c:372-390) — NOT PORTED
After `mode_estimation` picks a winner, replicate the winning `TplDepStats` across all 8x8 sub-blocks within `bsize`, preserving the accumulated `mc_flow` and `mc_ref_cost` from earlier propagation passes and recomputing `mc_dep_cost = intra_cost + mc_flow`. Critical: the `mc_dep_cost` recompute is what makes the propagation loop converge.

### `tpl_store_before_propagation` (vp9_tpl_model.c:392-417) — NOT PORTED
Mirror per-block stats into `VpxTplBlockStats` for the public ABI: pixel-space row/col, `inter_cost`, `intra_cost`, `recrf_dist = recon_error << TPL_DEP_COST_SCALE_LOG2`, `recrf_rate = rate_cost << TPL_DEP_COST_SCALE_LOG2`, MV row/col, ref_frame_index. Consumed by external rate-control / QMODE.

### `tpl_model_update_b` (vp9_tpl_model.c:419-473) — NOT PORTED
The propagation kernel. For the current block's MV, compute the (potentially sub-block-fractional) ref-frame target rectangle. Split into up to 4 overlap rectangles aligned to the 8x8 grid in the ref frame. For each overlap rectangle, accumulate proportional shares of `mc_flow` and `mc_ref_cost` into the matching ref TplDepStats grid cells: `mc_flow += (mc_dep_cost * (1 - inter_cost/intra_cost) * overlap_area) / pix_num`, `mc_ref_cost += ((intra_cost - inter_cost) * overlap_area) / pix_num`. The math is order-of-evaluation sensitive because of integer division — must port exactly.

### `tpl_model_update` (vp9_tpl_model.c:475-489) — NOT PORTED
Walks each 8x8 sub-block within bsize and calls `tpl_model_update_b` per sub-block (always at `BLOCK_8X8` granularity, regardless of the picker's TPL block size).

### `get_overlap_area` / `round_floor` (vp9_tpl_model.c:333-360 + 362-370) — NOT PORTED
Tiny helpers used by `tpl_model_update_b`. `round_floor` is a signed-aware floor division (must match libvpx semantics for negative MVs).

### `trim_tpl_stats` (vp9_tpl_model.c:1257-1284) — NOT PORTED
After propagation, the GOP stats include 2 extra look-past frames. `trim_tpl_stats` deep-copies the head into a new array sized `size - extra_frames`. Used by `vp9_setup_tpl_stats:1517`.

## 4. Non-greedy MV (NGM) — `vp9_non_greedy_mv.c` module

### `MotionField` / `MotionFieldInfo` / `FloatMV` / `Status` (vp9_non_greedy_mv.h) — NOT PORTED
Data shapes for the smoothed motion field, indexed by `[frame][rf_idx][square_block_idx]` (4-deep over BLOCK_4X4 / 8X8 / 16X16 / 32X32). `mf` is the `int_mv` payload, `set_mv` is the dirty bit, `local_structure[4]` is the row-major 2x2 structure tensor M.

### `vp9_alloc_motion_field` + `vp9_alloc_motion_field_info` (vp9_non_greedy_mv.c:171-236) — NOT PORTED
4D allocation across frames × ref slots × square block sizes. Cleanup-on-failure path is multi-step and must mirror libvpx exactly to avoid double-frees.

### `vp9_free_motion_field` + `vp9_free_motion_field_info` (vp9_non_greedy_mv.c:238-264) — NOT PORTED
Cascaded free. Must zero the `allocated` byte.

### `vp9_motion_field_*` accessors (vp9_non_greedy_mv.c:266-318) — NOT PORTED
Trivial getters/setters with `assert(mi_row % mi_height == 0)` invariants. Need replicating because `mode_estimation` line 664 calls `vp9_motion_field_mi_get_mv` directly.

### `log2_table` + `log2_approximation` (vp9_non_greedy_mv.c:15-165 + 320-332) — NOT PORTED
1024-entry int64 LUT in Q20 fixed-point; linear-extrapolation slope 1477 for `v >= 1024`. Must port the LUT verbatim because `vp9_nb_mvs_inconsistency` returns these Q20 fixed-point values into the lambda calculation downstream.

### `vp9_nb_mvs_inconsistency` (vp9_non_greedy_mv.c:334-359) — NOT PORTED
Minimum squared (row_diff² + col_diff²) over up to 4 neighbour MVs, passed through `log2_approximation`. This is the consistency-penalty term added to `vp9_full_pixel_diamond_new`'s lambda objective. The 4-neighbour bound is fixed (`NB_MVS_NUM = 4`, header line 22).

### `vp9_get_smooth_motion_field` + `get_smooth_motion_vector` (vp9_non_greedy_mv.c:361-458) — NOT PORTED
Iterative Jacobi-style smoothing of the motion field. Uses a 3x3 weighted filter (corners 1/12, edges 1/6, centre 0) plus an alpha-regularised 2x2 inverse derived from the local structure tensor M. Runs `num_iters` sweeps; double-buffered `input` / `output`. Quality impact: this is the smoothing step that gives NGM its denoised, content-aware MV field — without it, the TPL MV is just the picker's diamond output.

### `vp9_get_local_structure` (vp9_non_greedy_mv.c:460-536) — NOT PORTED
Computes the per-block 2x2 tensor M from neighbour SAD differentials. M is the local image-gradient structure tensor: high M00 + M11 indicates fast-changing block (edges/texture), low values indicate flat regions. Used by `get_smooth_motion_vector` to regularise the smoothing across content-different blocks.

### TPL NGM motion-search functions (vp9_tpl_model.c:202-277 + 1080-1136) — NOT PORTED
`full_pixel_motion_search` calls `vp9_full_pixel_diamond_new` (a fresh function for NGM that incorporates the `vp9_nb_mvs_inconsistency` term into the lambda), `sub_pixel_motion_search` is the standard 2-tap subpel, `do_motion_search` glues them, `build_motion_field` iterates over `(mi_row, mi_col)` at the per-bsize stride. Note `tpl_frame->lambda = (pw * ph) >> 2` (vp9_tpl_model.c:1118) — the NGM lambda scales with block area.

### NGM mode-picker (`predict_mv_mode_arr`, `predict_mv_mode`, `find_best_ref_mv_mode`, `eval_mv_mode`, helpers) (vp9_tpl_model.c:763-1078) — NOT PORTED
Anti-diagonal sweep over the picture deciding for each block whether to commit a NEW_MV vs reuse a ZERO/NEAREST/NEAR-style decision. The 5-line preview (`kMvPreCheckLines = 5`) compares two RD sums to pick. The probabilities `zero_mv_prob = 16`, `new_mv_prob = 24`, `ref_mv_prob = 216` (line 869-871) are hardcoded "TODO(angiebird)" approximations of the default mode probs — note this is **not** the bitstream mode-prob table.

## 5. Block-graph / `mbgraph` module

The `mbgraph` module is run from `vp9_encoder.c:1176` as part of the ARF / GF preamble. It does a 16x16 motion-graph scan over the lookahead window and feeds segmentation, providing a "this region is static across the GF group, allocate fewer bits" signal. It's a separate pipeline from TPL (older, simpler, cheaper) but plays a similar role in driving per-block bit allocation decisions.

### `MBGRAPH_MB_STATS` + `MBGRAPH_FRAME_STATS` + `cpi->mbgraph_stats[]` (vp9_mbgraph.h:18-31 + vp9_encoder.h:831-833) — NOT PORTED

### `do_16x16_motion_search` (vp9_mbgraph.c:77-112) — NOT PORTED
Wrapper: zero-MV first, then ref-MV start, then optionally a (0,0)-ref iteration if the ref_mv is non-zero. Picks min error.

### `do_16x16_zerozero_search` (vp9_mbgraph.c:114-127) — NOT PORTED
Zero-MV-only SAD. Used for ALTREF where motion is assumed already-aligned.

### `find_best_16x16_intra` (vp9_mbgraph.c:128-156) — NOT PORTED
DC/V/H/TM intra-mode scan with `vp9_predict_intra_block` at TX_16X16, picking min SAD.

### `update_mbgraph_mb_stats` (vp9_mbgraph.c:158-209) — NOT PORTED
Per-16x16 block driver. Calls `find_best_16x16_intra` and stores `[INTRA_FRAME].err`. Conditionally runs GOLDEN motion-search and ALTREF zero-zero. Note the FIXME comment at line 169: "in practice we're completely ignoring chroma here" — must replicate exactly (luma-only mbgraph).

### `update_mbgraph_frame_stats` (vp9_mbgraph.c:211-278) — NOT PORTED
Per-frame raster over 16x16 blocks. Maintains `gld_top_mv` / `gld_left_mv` carry-state for the MV-prediction seed of `do_16x16_motion_search`. Sets up `mi_above` / `mi_left` signalling for `vp9_predict_intra_block`.

### `separate_arf_mbs` (vp9_mbgraph.c:281-349) — NOT PORTED
Backward-sweep marks each MB static-vs-dynamic. The criterion at line 312 is `altref_err > 1000 || altref_err > intra_err || altref_err > golden_err` — if ALTREF prediction is bad, the block is dynamic; otherwise it's static and gets segment 1 (with the segmentation map written at line 326-331). Final `vp9_enable_segmentation(&cm->seg)` at line 345 activates the feature.

### `vp9_update_mbgraph_stats` (vp9_mbgraph.c:351-388) — NOT PORTED
Driver. Gates on `n_frames > cpi->rc.frames_till_gf_update_due` (returns early if not). Allocates `mbgraph_stats[i].mb_stats` (already done at startup at vp9_encoder.c:2459-2463), zeros them, sweeps `vp9_lookahead_peek(cpi->lookahead, i)` for each frame, then `separate_arf_mbs`.

### Frame-loop call site (vp9_encoder.c:1167-1185) — NOT PORTED
The mbgraph wrapper disables segmentation, calls `vp9_update_mbgraph_stats` (which may re-enable segmentation if static blocks were found), then if `seg->enabled` sets the feature-update flags and computes the QI-delta segment data. ## 6. RDO / RC / partition consumers of TPL stats

### `discount_newmv_test` NGM branch (vp9_rdopt.c:2767-2798) — NOT PORTED
RDO inter-mode picker consults `tpl_stats[gf_group_idx].mv_mode_arr[gf_rf_idx][tpl_mi_row * stride + tpl_mi_col]`. If the TPL pre-decided this block as `NEW_MV_MODE` and the current candidate MV is within 8 pels of the TPL MV, return 1 to discount the NEWMV cost. Otherwise return 0 (no discount). Quality impact: this is how TPL biases the picker toward MVs it has already validated as good across the GOP propagation.

### `get_rdmult_delta` (vp9_encodeframe.c:3717-3760) — NOT PORTED
Per-64x64 SB, sums TPL `intra_cost` and `mc_dep_cost` over the (mi_row, mi_col) sub-grid, then `r0 = cpi->rd.r0`, `rk = intra_cost / mc_dep_cost`, `beta = r0 / rk`. Used to perturb `x->cb_rdmult` for blocks with unusually high (or low) downstream importance.

### `encode_b` + `init_plane_quantizers` rdmult hooks (vp9_encodeframe.c:1957-1958, 2235-2242) — NOT PORTED
The lambda override sites. Without these the perturbed rdmult is computed but never applied.

### `rd_pick_partition` cb_rdmult preamble (vp9_encodeframe.c:4570-4574) — NOT PORTED
The hook that calls `get_rdmult_delta` at the 64x64 root of the RDO partition descent. Gated by `cpi->twopass.gf_group.index > 0 && cpi->sf.enable_tpl_model`.

### Frame-loop `r0` recompute (vp9_encodeframe.c:6141-6163) — NOT PORTED
Per-frame: sum TPL `intra_cost` and `mc_dep_cost` over all blocks, set `cpi->rd.r0 = intra_cost_base / mc_dep_cost_base`. This is the frame-level constant that `get_rdmult_delta` references.

### `vp9_setup_tpl_stats` call site (vp9_encoder.c:6614-6626) — NOT PORTED
The frame-loop trigger. Gated tightly: only fires on `gf_group_index == 1 && update_type[1] == ARF_UPDATE && sf.enable_tpl_model`. So TPL is computed once per ARF GOP boundary, not per frame.

### `vp9_estimate_qp_gop` (vp9_ratectrl.c:1669-1692) — NOT PORTED
Pre-TPL forward pass through the GOP that runs `rc_pick_q_and_bounds_two_pass` for each frame and stashes the resulting q in `tpl_stats[idx].base_qindex`. Critical because `mc_flow_dispenser` reads this directly to set up its rdmult (line 1201).

## Cross-cutting gaps

Beyond the per-function items, these subsystem-wide observations apply:

### Frame-buffer pool slot reservation
TPL reuses recon buffer slots from `RefCntBuffer frame_bufs[FRAME_BUFFERS]` for its propagation passes (vp9_tpl_model.c:39-63). rvp9's ref-buffer pool is structured differently (`rvp9-encoder/src/lib.rs` uses separate `Vec<...>` allocations per ref slot), so the recon-slot-reservation idiom needs translating: rvp9 will either (a) grow a parallel TPL recon pool or (b) extend the existing pool with a `tpl_reserved: bool` slot flag.

### `MAX_ARF_GOP_SIZE = 32` constant
TPL allocates `MAX_ARF_GOP_SIZE` slots in `tpl_stats[]` (vp9_encoder.h:752). rvp9's GOP / GF group max is currently smaller (1-pass CBR only has GOLDEN_UPDATE on a smaller period). This constant must be ported AS-IS — TPL's backward-propagation iterates from frame `tpl_group_frames - 1` down to 1, and the array must be sized for the worst case.

### `TPL_DEP_COST_SCALE_LOG2 = 4`
Hardcoded shift used in 5+ places (`mode_estimation:721`, `tpl_store_before_propagation:410-411`, etc.). When porting, this must be a `pub const` shared across the module, **not** a magic number — otherwise per-consumer drift will silently break the propagation math.

### `MAX_INTER_REF_FRAMES = 3`
TPL hardcodes 3 ref slots (LAST/GOLDEN/ALTREF). The NGM motion_field is indexed `[frame][rf_idx][square_block_idx]` with `rf_idx in 0..3`. Matches libvpx's general ref-frame layout but worth flagging in case rvp9 reshapes ref-frame indexing during a future SVC port (A18).

### TPL writes outside the frame-loop's normal write surface
`mc_flow_dispenser` calls `vp9_frame_init_quantizer(cpi)` and mutates `cm->base_qindex` (vp9_tpl_model.c:1207-1208) and `cpi->td.mb` (line 1202 `set_error_per_bit`). These are state mutations on the encoder common that any port must isolate carefully — the TPL pass leaves Q-state altered when it returns, so the caller (`vp9_setup_tpl_stats:1517` and onward) implicitly assumes the next stage re-initialises. rvp9 will need to either preserve+restore or document this contract.

### NGM `lambda` vs picker `lambda`
`tpl_frame->lambda = (pw * ph) >> 2` (block-area / 4) is **not** the same as the RDO picker's `rdmult`. It's an NGM-only lambda for the motion-field smoothing objective. Don't conflate.

### `VP9_DIST_SCALE_LOG2` constant
Referenced at vp9_tpl_model.c:858 for the NGM distortion scaling. The constant lives in `vp9_encoder.h`; verify it's in the rvp9 import surface.

## Conclusion

- **Gap counts**: PORTED 0 / PARTIAL 0 / NOT PORTED 44 / OUT OF SCOPE 5 (49 rows total across 71-numbered items).
- **Cross-zone dependencies flagged for master inventory**:
  - **A3 (rate control / 2-pass)** — `vp9_estimate_qp_gop` lives in `vp9_ratectrl.c`; TPL only fires in 2-pass-VBR-with-lag.
  - **A7 (speed features)** — `sf.enable_tpl_model` plumbing (A7 row 98 already flagged).
  - **A10 (ref-frame management / ALTREF)** — `vp9_setup_tpl_stats` call site requires ARF.
  - **A11 (segmentation / AQ)** — `separate_arf_mbs` writes `segmentation_map` and enables segmentation.
  - **A12 (CLI / config)** — `--enable-tpl` flag (A12 row 95 already flagged).
  - **A13 (RDO path)** — `discount_newmv_test` lives in `vp9_rdopt.c`; depends on RDO inter-mode picker being ported first.
  - **A16 (temporal filtering / ALTREF)** — TPL's per-frame ARF preamble pairs with temporal filtering in the same frame-loop preamble.
  - **A19 (lookahead)** — `init_gop_frames` peeks `cpi->lookahead`.
  - **A20 (HBD)** — `vp9_highbd_wht_fwd_txfm` plus HBD `mode_estimation` branches.
- **Recommended sequencing for Phase 2**: TPL is large (~700 LOC core + ~115 LOC consumers, plus 1200 LOC NGM, plus 370 LOC mbgraph). Defer the entire subsystem until A10 / A16 / A19 / A3 prerequisites are in place — otherwise the call site is dead code. When the prerequisites land, port in the order P1-P13 (core data + propagation) → P14-P16 (consumers; the actual quality lift starts here) → P17-P22 (NGM, optional) → P23-P27 (mbgraph, optional segmentation lift) → P28-P30 (HBD + ABI).

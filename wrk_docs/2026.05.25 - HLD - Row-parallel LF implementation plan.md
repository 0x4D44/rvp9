# HLD: Row-parallel loopfilter — implementation plan

**Date:** 2026-05-25
**Author:** Plan agent (dispatched by team lead)
**Status:** Approved spec — ready for Wave 2 implementation
**Confidence:** medium that 5-10% materialises on multi-thread fixtures

## 1. Current LF architecture

Loopfilter runs strictly **after** tile decode joins. In `decode_keyframe` (`crates/rvp9-decoder/src/lib.rs:1947`) and `decode_inter_frame` (`:3014`), the tile-decode `worker_pool.scope` closure returns, the per-tile counts/seg_ids merge happens, then `apply_loop_filter_to_frame` runs single-threaded on the caller thread. `apply_loop_filter_to_frame` (`lib.rs:3306`) materialises a contiguous `Vec<ModeInfo>` from `frame_mi_grid`, builds the per-SB `lfm_grid` in a serial double-loop, then calls `loop_filter_frame_with_non420` (`crates/rvp9-core/src/loopfilter/apply.rs:168`), which itself walks SB raster order applying Y-V, Y-H, U-V, U-H, V-V, V-H per SB. No row-progress atomics exist today; the only sync primitive is the `WorkerPool::scope` join. Phase 1 already eliminated the per-tile pixel merge (workers write directly to `Yv12Buffer`), and Phase 2 eliminated the per-tile MI stitch (workers write directly to `frame_mi_grid`). Neither enabled decode/LF overlap.

## 2. Target architecture

Row-MT: tile decode workers publish a **per-SB-row decode-complete atomic** as they finish each SB row, and LF workers consume the same SB rows behind a 1-row wavefront stagger. The LF runs **inside the same `worker_pool.scope`** as decode, fed from a `next_lf_row: AtomicUsize` work queue; each LF worker waits on `decode_progress[r] >= sb_cols` (all tile cols done at this row) AND `lf_progress[r-1] == 1` (previous row's filter done) before filtering row `r`. With N=4 threads, the typical layout is 3 decode-only workers feeding 1 LF consumer for the first ~3 SB rows, then all 4 workers oscillate decode-or-LF as the queue dictates. libvpx's `row_mt_worker_hook` (vp9_decoder.c) is the model. Per-frame mask build (`setup_mask`/`adjust_mask`) moves into the per-row LF wavefront so it overlaps with decode too. Fallback: if `num_threads == 1` or `sb_rows < 4`, fall through to the existing serial path with zero overhead.

## 4. Synchronisation primitive design

Two atomic arrays, allocated on the caller stack inside the scope-launching frame:

```rust
// Decode side: per-SB-row counter, value = number of tiles that have
// finished this SB row. When == tile_cols_at_row[r], row r is
// fully decoded across the frame.
decode_progress: Vec<AtomicU32>, // len = sb_rows, init 0

// LF side: per-SB-row done flag. lf_progress[r] = 1 once row r's
// filter is fully complete (Y/U/V, V then H, all SB cols).
lf_progress: Vec<AtomicU32>,     // len = sb_rows, init 0

// LF work queue: monotonic row dispatcher.
next_lf_row: AtomicUsize,        // init 0
```

**LF worker hook** (matches libvpx `row_mt_worker_hook` semantics):

```rust
loop {
  let r = next_lf_row.fetch_add(1, Relaxed);
  if r >= sb_rows { break; }

  // Dep 1: this row's decode must be done frame-wide.
  while decode_progress[r].load(Acquire) < tile_cols_at_row[r] {
      std::hint::spin_loop();
  }
  // Dep 2: previous row's LF must be done (horizontal filter at
  // top edge of row r reads 8 px into row r-1).
  if r > 0 {
      while lf_progress[r-1].load(Acquire) == 0 {
          std::hint::spin_loop();
      }
  }

  build_lfm_row(r, ...);             // setup_mask + adjust_mask for row r
  loop_filter_sb_row(r, ...);        // Y/U/V V+H over all sb_cols

  lf_progress[r].store(1, Release);
}
```

**Why spin, not condvar / channel.** Wait latency at 1080p is ~200 us per SB row; futex wake is ~5–10 us round-trip — fine, but the spin path avoids any syscall budget on the row-stall hot loop. libvpx makes the same choice. Cap spins with a bounded `for _ in 0..8192 { hint } else { thread::yield_now(); }` to be friendly under oversubscription.

**Acquire/Release ordering** is sufficient: the writer emits `Release` after pixel writes for that row are visible; the reader does `Acquire` before reading those pixels. No fences needed.

**Pixel aliasing.** `SharedFrame` holds `*mut u8` per plane with `unsafe impl {Send, Sync}`. The temporal-exclusion argument in the existing HLD §4 (Phase 3 draft) carries over — the per-row progress protocol guarantees no two threads write the same byte.

## 5. Test plan

**Correctness:**
1. `cargo test -p rvp9-decoder conformance --release` — full 201-vector corpus, run twice: once with `RVP9_DISABLE_ROW_MT=1` (serial baseline) and once with row-MT on (default). Frame MD5s **must** match the existing pinned MD5 fixtures byte-for-byte. CI gate.
2. **Differential intra-run check.** A new test in `tests/row_mt_diff.rs` decodes the same 10-frame clip with 1, 2, 4, 8 threads and asserts all four outputs MD5-match.
3. **Edge-frame fuzz.** Frames with `sb_rows ∈ {1, 2, 3, 5, 17, 68}`. Includes the `sb_rows < num_threads` fall-back path.
4. **Miri shake** on a tiny (128×128) fixture exercising `SharedFrame` raw-pointer aliasing under the strict provenance model.

**Performance:**
1. `scripts/bench-headtohead.ps1` headline fixture: `testsrc_1080p30 t=4`. Target: 8.97× → ≤8.0× (close ~10% of the gap to 2×). Pass condition: ≥5% improvement vs `RVP9_DISABLE_ROW_MT=1` on the same binary.
2. Full bench matrix (3 fixtures × `t ∈ {1, 2, 4, 8}`). Expect: `t=1` unchanged (within noise), gains scale with `t`.
3. `profile-tiles` CSV review: `lf_wait_cycles` should drop frame-over-frame; `loopfilter` should overlap with `submit→join` rather than serialise after it.

## 6. Risk register

| # | Risk | Mitigation |
|---|------|------------|
| 1 | **Pixel write race at row boundary.** Top-edge horizontal filter on row r writes 8 px into row r-1. If lf_progress ordering slips, two threads could write the same byte. | `debug_assert!(lf_progress[r-1].load(Acquire) == 1)` immediately before the H-pass. Differential MD5 test catches any slip. Miri pass required. |
| 2 | **No win because decode dominates LF.** Profiling shows LF at 35.5% on 1080p, but if `testsrc t=4` is decode-bound (tile imbalance), overlapping LF saves little. | Measure on `bench-headtohead`. If gain <3%, pivot to extracting the LF mask build into decode workers and rely on Wave 4's tile-balance work. |
| 3 | **Tile-decode-complete granularity is per-SB-row of the tile, not per-frame-SB-row.** | Compute `tile_cols_at_row[r]` from `per_tile_bounds` before scope open. Assert `sum(tile_cols_at_row) == sb_rows * sb_cols` in debug. |
| 4 | **Spin-wait wastes cycles under oversubscription** (e.g. `t=8` on a 4-core box). | Yield after 8K spins (`thread::yield_now`). |
| 5 | **`SharedFrame` Send/Sync UB under TB / Miri** | Workers receive `*mut u8 + len + stride` only; reconstruct slices ephemerally inside `filter_block_plane_*` calls. Same pattern as Phase 1's `TileFrameView`. |

## 7. Rollout switch

Two gates, both default-on:

1. **Env var** `RVP9_DISABLE_ROW_MT=1` → forces serial path. Wired through `trace_flags.disable_row_mt`. Zero runtime cost when unset.
2. **CLI flag** `rvp9dec --row-mt=off` / `--row-mt=on` (default on).

Ship sequence:
- Land with `RVP9_DISABLE_ROW_MT` honoured AND default = serial for one merge (dark launch).
- Run a full conformance + perf cycle.
- Flip default to row-MT in the next merge.
- Remove the kill-switch two cycles later, once telemetry is clean.

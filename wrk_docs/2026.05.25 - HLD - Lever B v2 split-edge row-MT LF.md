## §1 One-line summary

Replace the **row-barrier** dependency (`lf_progress[r-1] == 1` before any of row r) with libvpx's **column-wavefront** (`cur_sb_col[r-1] >= cur_sb_col[r] + nsync`), unlocking up to `min(nworkers, num_tile_cols, sb_rows)`-way parallelism with `nsync = 4` columns of headroom for the cross-row 16-tap H-filter, so adjacent SB rows execute concurrently instead of strictly sequentially.

## §2 libvpx model — concrete code references

All citations are from `third_party/libvpx/vp9/common/vp9_thread_common.c` and `third_party/libvpx/vp9/decoder/vp9_decodeframe.c`. The key file is `vp9_thread_common.c` (the LF worker hook and sync primitives).

### §2.1 Per-row sync primitive (`vp9_thread_common.c:24-49` + `:329-339`)

```c
typedef struct VP9LfSyncData {
  pthread_mutex_t *mutex;   // one per SB row
  pthread_cond_t  *cond;    // one per SB row
  int *cur_sb_col;          // per SB row — most-recently-finished SB col
  int  sync_range;          // nsync — 4 for 1080p, 8 for 4K
  int  rows;
  LFWorkerData *lfdata;
  int num_workers;
  int num_active_workers;
  ...
};
// vp9_loop_filter_alloc allocates one mutex+cond per SB row and sets sync_range
// = get_sync_range(width) ∈ {1, 2, 4, 8}.
```

Per-row, libvpx allocates a `(mutex, cond, cur_sb_col)` triple. No separate V/H progress arrays — the per-SB unit (V then H of the same SB) is the atomic granule. The cross-tile decode-progress signal uses a *separate* `(recon_done_mutex, recon_done_cond, num_tiles_done)` triple per row.

### §2.2 The dependency gate (`vp9_thread_common.c:38-56`)

This is the load-bearing snippet. Row r at column c waits until row r-1 has reached at least column (c + nsync):

```c
static INLINE void sync_read(VP9LfSync *const lf_sync, int r, int c) {
  const int nsync = lf_sync->sync_range;
  if (r && !(c & (nsync - 1))) {                       // only at nsync boundary
    pthread_mutex_t *const mutex = &lf_sync->mutex[r - 1];
    mutex_lock(mutex);
    while (c > lf_sync->cur_sb_col[r - 1] - nsync) {   // r-1 must be nsync ahead
      pthread_cond_wait(&lf_sync->cond[r - 1], mutex);
    }
    pthread_mutex_unlock(mutex);
  }
}
```

Three facts to extract:
1. The check fires only at `c % nsync == 0` boundaries — coarse polling, not per-SB.
2. The condition is `c <= cur_sb_col[r-1] - nsync`, i.e. row r-1 must be **nsync columns ahead** of row r. For 1080p that's 4 SB columns = 256 pixels of horizontal headroom.
3. The cross-row hazard scope is the **top-of-SB H-edge**, which reads bottom 8 luma rows of row r-1 — those pixels are owned by row r-1's H-pass at the same SB column. Nsync columns of headroom guarantees row r-1's V+H at column c is complete before row r touches the cross-row pixels at column c.

### §2.3 How the top-edge filter is scheduled (`vp9_thread_common.c:115-143`)

The H-pass at the top of row r's SB is **part of row r's work** (not row r-1's). Row r's worker calls `vp9_filter_block_plane_ss00` (luma), which runs V then H back-to-back on the same SB. The H-pass at the top edge (`r == 0` line of the SB) reads the 8 luma rows *above* the SB top, i.e. row r-1's bottom 8 rows — already filtered by row r-1's H-pass at the same column. Hence the `nsync` column headroom requirement.

```c
for (mi_row = start; mi_row < stop; mi_row += num_active_workers * MI_BLOCK_SIZE) {
  for (mi_col = 0; mi_col < cm->mi_cols; mi_col += MI_BLOCK_SIZE, ++lfm) {
    const int r = mi_row >> MI_BLOCK_SIZE_LOG2;
    const int c = mi_col >> MI_BLOCK_SIZE_LOG2;
    sync_read(lf_sync, r, c);
    vp9_adjust_mask(cm, mi_row, mi_col, lfm);          // mask build co-located
    vp9_filter_block_plane_ss00(cm, &planes[0], mi_row, lfm);   // Y: V then H
    for (plane = 1; plane < num_planes; ++plane) { /* U, V */ }
    sync_write(lf_sync, r, c, sb_cols);                // publish at nsync boundary
  }
}
```

Also note the **static row distribution** (`mi_row += num_active_workers * MI_BLOCK_SIZE`): worker i handles rows `i, i+nworkers, i+2*nworkers, …` — not dynamic dispatch. Each worker walks all its rows in raster order.

And the **worker count cap** (`vp9_thread_common.c:165-170`): `num_workers = min(nthreads, num_tile_cols, sb_rows)`. The comment says the implementation "doesn't scale well beyond [num_tile_cols]" because tile decode workers are scheduled by tile-col count and oversubscribing LF hurts on Android.

### §2.4 Cross-row write zone (libvpx `vp9_loopfilter.c:1252-1322`)

V-pass: 2 luma rows at a time, processing left edges within the SB — no cross-row writes (left-edge filters write only within their own SB column).

H-pass: 1 luma row at a time. The top-of-SB H-edge reads luma rows `[mi_row-7..mi_row+8]` (16-tap variant of the loopfilter) when the edge mask is `mask_16x16`. That is, row r's H-pass at its top edge writes pixels in both row r-1's bottom 8 luma rows and row r's top 8 luma rows. Hence row r-1 must be **completely done with H** at the same SB column before row r touches the top edge — guaranteed by the nsync wavefront because row r-1's V+H at column c+nsync is finished before row r reaches column c+nsync−nsync = c.

## §3 rvp9 design — sync primitive

### §3.1 Decision: single per-row `cur_sb_col[r]` array (libvpx-faithful)

We do NOT introduce separate `vpass_progress[r]` and `hpass_progress[r]` arrays. The morning analysis suggested this, but reading libvpx confirms that:

- V and H are **not separated** in libvpx — they execute as a back-to-back per-SB unit inside `vp9_filter_block_plane_ss00`.
- The cross-row hazard (top-of-SB H-edge reading row r-1's bottom 8 pixels) is covered by the column-wavefront: when row r reads column c, row r-1 has completed both V and H at column c (and at least c+nsync−1 more). No V-only intermediate state is exposed.

A per-SB V/H split would (a) be a deviation from libvpx, (b) require restructuring `filter_block_plane_ss00` and the chroma filters to expose a mid-SB sync point, and (c) buy nothing meaningful because the per-SB H-pass takes ~half the per-SB time — the nsync=4 wavefront already provides enough slack.

### §3.2 The atomic vector

One vec: `cur_sb_col: Vec<AtomicI32>`, length `sb_rows`, initialised to `-1` (matching libvpx's `memset(cur_sb_col, -1, ...)` at `vp9_thread_common.c:181`). Use `AtomicI32` (not `AtomicU32`) so the `-1` sentinel models libvpx's "no SBs processed yet" state without an off-by-one shift; the wavefront math (`c <= cur_sb_col[r-1] - nsync`) needs signed semantics for the boundary case where `cur_sb_col[r-1] - nsync` goes negative.

Memory ordering: writer uses `Release` on the per-row store; reader uses `Acquire` on the per-row load. This pairs writer's pixel writes with reader's pixel reads through the cross-row hazard zone. **No mutex/condvar** — the existing `spin_then_yield` primitive suffices and avoids libvpx's pthread-mutex overhead.

### §3.3 Gates

- **Row r's V-pass at column c**: no separate gate. V at column c only reads/writes pixels owned by row r in the column-c SB, plus the left-edge interaction with column c-1 *of the same row* (which is sequential within the worker).
- **Row r's H-pass at column c** (which is what the cross-row hazard touches): gated by `cur_sb_col[r-1] >= c + nsync − 1` (libvpx's `c <= cur_sb_col[r-1] - nsync` rephrased — recall libvpx initialises to −1 and stores `c` after processing column c).
- **In practice**, because V and H are bundled per SB in `loop_filter_sb_row` (and inside `filter_block_plane_ss00`), the gate fires once **before** the entire per-SB unit, at column c. The check is "row r-1's cur_sb_col >= c + nsync − 1" — i.e. row r-1 is nsync columns ahead.

### §3.4 Mask-build placement

Mask-build stays **co-located** with the per-row worker (call to `build_lfm_row` happens once per SB row, before the inner column loop). The Wave 7 mask-build cost is 2.8% per the diagnostic — not material. Per-SB mask build (calling `setup_mask` / `adjust_mask` inside the column loop, libvpx-style) would be even closer to libvpx, but the per-row variant is already what we have and is bitwise-identical.

### §3.5 Removing the decode-progress gate

The existing `decode_progress[r]` + `tile_cols_at_row[r]` Acquire gate (`apply.rs:381`) is **dead code** today: the LF scope opens only after the tile-decode scope has joined. Keep it for now — it is harmless and forward-compatible with a future single-scope topology — but the spin will trivially pass on first load. The diagnostic confirms the wait-time is the row-r-1 LF gate, not this one.

### §3.6 Worker count cap

Mirror libvpx: `num_lf_workers = min(num_workers, max(1, num_tile_cols), sb_rows)`. Today `num_tile_cols` is `1 << log2_tile_cols`. Cap is critical because the column-wavefront's effective parallelism is bounded by the number of independent rows in flight — beyond `num_tile_cols`, adding workers just adds contention. (See `vp9_thread_common.c:170` and the surrounding comment.)

**Pre-flight confirmed**: `testsrc_1080p30.ivf` is encoded with `--tile-columns=2` (= 4 tile columns) per `scripts/bench-headtohead.ps1:96`. The cap `min(4 threads, 4 tile_cols, 17 sb_rows) = 4` — full parallelism preserved on the headline fixture.

### §3.7 nsync value

`get_sync_range(width)` from libvpx (`vp9_thread_common.c:264-275`):

| width      | nsync |
|------------|-------|
| < 640      | 1     |
| ≤ 1280     | 2     |
| ≤ 4096     | 4     |
| > 4096     | 8     |

For 1080p (target fixture), nsync = 4. Implement as `const fn nsync_for_width(w: u32) -> u32`.

### §3.8 Spin/yield budget

Diagnostic showed the current `SPIN_YIELD_THRESHOLD = 8192` is too generous when workers spin on a row barrier (every worker waits ~entire previous row). Under the column-wavefront, spin episodes are short (one SB worth of headroom at most). Propose **`SPIN_YIELD_THRESHOLD = 256`** — enough to absorb the ~few-microsecond per-SB latency without burning CPU. Re-tune if a follow-up measurement shows yield rate too high.

## §4 Per-row worker pseudocode

Replace `run_row_mt_lf_worker` with `run_split_edge_lf_worker` (named per the user's directive even though the design is column-wavefront, not V/H split — see §3.1 for rationale). Below is the new shape — Rust pseudocode, not compilable.

```rust
const NSYNC_BOUND_FOR_1080P: i32 = 4;
const SPIN_YIELD_THRESHOLD: u32 = 256;

pub struct ColumnWavefrontLfState<'a> {
    pub shared: SharedFrame,
    pub info: &'a LoopFilterInfo,
    pub row_inputs: RowMaskInputs<'a>,
    pub non420: Option<Non420Inputs<'a>>,
    pub sb_rows: usize,
    pub sb_cols: usize,
    /// libvpx vp9_thread_common.c VP9LfSync::cur_sb_col.
    /// Initialised to -1 (signed). Worker stores c (>= 0) after each SB.
    pub cur_sb_col: &'a [AtomicI32],
    pub nsync: i32,
    /// libvpx's static row distribution: worker `i` of `n` handles
    /// rows i, i+n, i+2n, .... We also expose a dispatcher counter for
    /// the dynamic-claim option, but the static path is the default
    /// for libvpx parity (and avoids one atomic fetch_add per row).
    pub worker_id: usize,
    pub num_workers: usize,
}

unsafe fn run_split_edge_lf_worker(
    state: &ColumnWavefrontLfState<'_>,
    dispatch: &SimdDispatch,
) {
    let mut row_lfm: Vec<LoopFilterMask> =
        vec![LoopFilterMask::default(); state.sb_cols];

    // libvpx static row distribution — worker i handles rows
    // i, i+nworkers, i+2*nworkers, ...
    let mut r = state.worker_id;
    while r < state.sb_rows {
        // Per-row mask build (co-located, Wave 7 model).
        build_lfm_row(r, state.sb_cols, &state.row_inputs, &mut row_lfm);

        let mi_row = r * MI_BLOCK_SIZE;
        let sb_cols = state.sb_cols as i32;

        // Per-column wavefront sync — mirrors vp9_thread_common.c sync_read.
        for c in 0..sb_cols {
            // Gate: only check at nsync boundary (libvpx :42).
            if r > 0 && (c & (state.nsync - 1)) == 0 {
                let prev = &state.cur_sb_col[r - 1];
                let required = c + state.nsync - 1; // r-1 must be nsync ahead
                spin_then_yield(|| prev.load(Ordering::Acquire) >= required);
            }

            // Apply the per-SB unit: Y V+H, then U V+H, then V V+H.
            // Same kernel as serial path — bitwise-identical pixels.
            apply_one_sb(
                &state.shared,
                &row_lfm[c as usize],
                mi_row,
                (c as usize) * MI_BLOCK_SIZE,
                state.row_inputs.mi_rows,
                state.row_inputs.mi_cols,
                state.info,
                state.non420,
                dispatch,
            );

            // Publish: mirror vp9_thread_common.c sync_write (libvpx :58).
            // Only signal at nsync boundary, except for the last column
            // which signals "sb_cols + nsync" so trailing rows always
            // wake. (libvpx writes `sb_cols + nsync` for c == sb_cols-1.)
            let publish = if c == sb_cols - 1 {
                sb_cols + state.nsync
            } else if (c & (state.nsync - 1)) == (state.nsync - 1) {
                c
            } else {
                continue;           // skip store this iteration
            };
            state.cur_sb_col[r].store(publish, Ordering::Release);
        }

        r += state.num_workers;
    }
}
```

### §4.1 Ordering rationale

- **Reader** (`prev.load(Acquire)`): the Acquire fence guarantees all pixel writes published by row r-1's worker (which used `Release`) are visible to row r's worker before it dereferences the pixels at columns `[c-nsync..c]` of row r-1.
- **Writer** (`state.cur_sb_col[r].store(c, Release)`): the Release fence flushes all pixel writes in this row's SB columns `[..c]` so the next row r+1's worker sees them after its Acquire-load.
- **No mutex / no condvar**: pure atomic + `spin_then_yield`. The spin budget is small (~256) because the wavefront is tight.

### §4.2 What `apply_one_sb` does

Factors out the per-SB body of `loop_filter_sb_row`. Today `loop_filter_sb_row` walks `for sb_col in 0..sb_cols { … }`; we need to externalise that loop so the sync_read/sync_write straddles it. New helper: `apply_one_sb(shared, lfm, mi_row, mi_col, mi_rows, mi_cols, info, non420, dispatch)` calls `filter_block_plane_ss00` (Y) then chroma per the chroma-format dispatch. This is a mechanical extract from `apply.rs:684-800`.

## §6 Test plan

### §6.1 Bit-exact gate (load-bearing)

Run the 201-vector conformance suite twice in CI:

1. `RVP9_ROW_MT=0` (env var unset or `0`): serial LF path. **Required: 201/201 pass.**
2. `RVP9_ROW_MT=1`: column-wavefront LF path. **Required: 201/201 pass.**

Both runs must produce **identical per-frame MD5s**. The harness already does this via the `RVP9_DISABLE_ROW_MT` toggle (now `RVP9_ROW_MT`). No new test code needed for the 201-vector gate.

### §6.2 Differential test (`crates/rvp9-harness/tests/row_mt_lf_diff.rs`)

Extend `MULTI_TILE_VECTORS` from 3 entries to 6+, covering each nsync bucket:

- 640px or less: at least one vector. (Existing `vp90-2-08-tile_1x2.webm` is 1080p — find a smaller one in the conformance pool.)
- ≤ 1280px: at least one (existing fixtures fit).
- ≤ 4096px: existing 1080p / 1280 fixtures.

This exercises the per-width nsync dispatch path. Same `threads=1` vs `threads=4` MD5 comparison.

### §6.3 Soundness instrumentation (optional, dev-only)

Add a debug-build assertion inside `apply_one_sb`: when `r > 0` and `c == 0`, assert `state.cur_sb_col[r-1].load(Acquire) >= nsync - 1` (row r-1 has crossed the first nsync threshold before row r starts). If the assertion fires, the wavefront is broken. Gate behind `cfg(debug_assertions)`.

### §6.4 Miri / TSan feasibility

- **Miri**: feasible for the LF worker on a tiny synthetic frame (sb_rows=4, sb_cols=4, num_workers=2). Real LF requires the SIMD dispatch table — Miri can't run AVX2 intrinsics. We'd need a scalar-only build (`RVP9_SIMD=0` if such a flag exists; otherwise gate on `cfg(miri)`). Not load-bearing for landing — defer to a follow-up.
- **TSan**: rust does not ship with TSan stable. ThreadSanitizer would catch the Acquire/Release pairing bug; runnable on nightly via `-Zsanitizer=thread`. Recommend running once before merge as a one-off, not in CI.

### §7.1 Gate semantics

- **Pre-flip gate** (before flipping default to ON): LF wall ≤ 790 µs **and** frame wall ≤ 3848 µs (≥5% improvement on the headline benchmark). Both must hold.
- **Lower bound for landing dormant** (`RVP9_ROW_MT=1` opt-in stays the default): the code lands if conformance passes and the LF differential test passes. Perf gate not blocking for landing — only for default-flip.
- **If gate not met**: hold code dormant. Same posture as Wave 2 today. Do NOT revert. Report measured numbers and stop.

### §7.2 Confidence

Modeled parallelism: 4 workers × nsync=4 column wavefront on a 1080p frame (`sb_cols = 30`, `sb_rows = 17`). Per-SB cost is ~221 µs / 17 SB rows / 30 SB cols ≈ 433 ns at serial baseline. Wavefront fill cost (3 workers idle while worker 0 walks first 4 columns) = ~1.7 µs (negligible at 1080p, ~5% at smaller frames). Expected speedup ≈ `min(4, sb_rows, num_tile_cols) × (1 − wavefront_fill_fraction)` ≈ 3.8× — far in excess of the 30% target. **High** confidence the gate will be met **if** the implementation matches §3-§4 cleanly. ## §10 DO-NOT list

Mistakes informed by Wave 2 + Wave 7 history.

1. **DO NOT submit per-SB scope jobs.** Wave 2 measured the per-`scope.submit()` overhead at ~50-100 µs; submitting 510 jobs (sb_rows × sb_cols on 1080p) burns the whole LF budget. Submit `num_lf_workers` jobs, one per worker, and let each worker walk its assigned rows.
2. **DO NOT amend or revert prior commits if the perf gate isn't met.** Wave 2 left dormant code on the branch; we do the same here. Reverting would lose the bit-exact differential infrastructure and the worker-pool plumbing.
3. **DO NOT broaden scope to frame-pipelining or single-scope (LF overlaps tile decode).** That's a separate, larger effort with `frame_mi` materialisation concerns (see Wave 2 §"Topology choice"). This HLD is column-wavefront only.
4. **DO NOT replace `spin_then_yield` with parking-lot / `std::thread::park`.** The expected wait under a healthy wavefront is sub-microsecond; OS-level parking has a tens-of-microseconds wake latency that would dwarf the savings.
5. **DO NOT change `SharedFrame` ownership semantics.** The raw-pointer + lifetime contract is the load-bearing soundness argument from Wave 2 — touching it invalidates the prior soundness review.
6. **DO NOT introduce per-row `Vec<LoopFilterMask>` re-allocations inside the inner loop.** Wave 2 already allocates once per worker invocation outside the row loop. Keep that pattern; allocating per row would re-introduce a Wave 4-style alloc regression.
7. **DO NOT skip the differential test on any commit.** Even "mechanical refactor" commits (C1, C4) must pass it — Wave 2 caught a covert refactor bug only by running the diff on every step.
8. **DO NOT cap `num_lf_workers` below the libvpx formula.** Capping is per `min(nthreads, num_tile_cols, sb_rows)`; under-capping wastes parallelism; over-capping causes the regression Wave 2 already measured.
9. **DO NOT commit with environment variables changed in tests leaking to the next test process.** `row_mt_lf_diff.rs` already documents this — keep the `set_var` discipline.
10. **DO NOT introduce a mutex/condvar.** The atomic+spin protocol is sufficient and lower-overhead. libvpx uses pthread for portability across pre-C11 platforms; we don't have that constraint.

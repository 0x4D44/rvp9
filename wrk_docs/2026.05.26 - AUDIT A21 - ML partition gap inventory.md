## Section-by-section narrative

### Section 1 — Generic NN inference + model schema

#### `nn_predict` (item #1)
Generic forward pass: per hidden layer, dot-product with `weights` (row-major `[num_output_nodes × num_input_nodes]`), add per-node bias, ReLU; final layer skips activation. Uses two `[NN_MAX_NODES_PER_LAYER]` ping-pong buffers on stack. `assert(num_layers <= NN_MAX_HIDDEN_LAYERS=10)`. **Status: NOT PORTED.** rvp9 has zero NN inference primitives.

#### `NN_CONFIG` (item #2)
Pure data layout: `num_inputs`, `num_outputs`, `num_hidden_layers`, `num_hidden_nodes[NN_MAX_HIDDEN_LAYERS]`, `weights[NN_MAX_HIDDEN_LAYERS+1]`, `bias[NN_MAX_HIDDEN_LAYERS+1]`. Defined once, consumed by every ML helper. **Status: NOT PORTED.**

#### `vpx_clear_system_state` (item #3)
Wraps the `_mm_empty()` / `fninit` sequence; libvpx calls it before every float-feature build to reset x87/MMX state inherited from SIMD residual code. **Status: OUT OF SCOPE** — rvp9 has no x87/MMX state to clear (pure-Rust f32 arithmetic; aligns with Arthur 2026-05-25 ARM-SIMD-only scope cut by analogy: it is x86-CPU-only machine-state housekeeping with no algorithmic effect).

### Section 2 — RDO-side (GOOD-quality, cpu-used 0..=4) ML helpers — all guarded by `#if !CONFIG_REALTIME_ONLY`

#### `ml_pruning_partition` (item #4, helper) / call site (item #14)
After a successful PARTITION_NONE pick for BLOCK_16X16/32X32/64X64, runs a 7-feature linear model first (`rate, dist, mag_mv/2, (left_par+above_par)/2, sum_y_eobs, base_qindex, last_par` z-scored by per-bsize mean/std), bails fast if `linear_score > 0.1f`, otherwise runs an 8-node NN and combines linear + NN scores to set `do_split = do_rect = 0`. Used when `sf.rd_ml_partition.search_early_termination` is on — only at GOOD speed 0 with `min(w,h) ≥ 480`.

#### `ml_predict_breakout` (item #5, helper) / call site (item #15)
Pure linear model (no NN). 4 features: scaled `rate`, `dist >> num_pels_log2`, `var >> num_pels_log2` (variance of source vs zero-buffer at this bsize), `ac_q`. Linear weights are looked up per `(bsize, resolution_ctx, q_ctx)` — 4 bsizes × 2 res × 3 q tiers = 24 weight vectors of length 5. Compared against `sf.rd_ml_partition.search_breakout_thresh[q_ctx]`. Gated by `cpi->sf.rd_ml_partition.search_breakout && cm->base_qindex >= 100`, only runs when `ctx->skippable`. Active across GOOD speeds 0..=2 with bsize-dependent thresholds.

#### `ml_prune_rect_partition` (item #6, helper) / call site (item #17)
Runs before HORZ/VERT search. 8 features: `log(dc_q+1)`, `partitioning == NONE`, `log(ref_rd/bs²+1)`, NONE-vs-ref RD ratio (capped 2.0), and 4 split-quad RD ratios. NN produces 4 label scores (one per HORZ/VERT combination); decision: any label ≥ `max_score − sf.rd_ml_partition.prune_rect_thresh[bsize_idx]` keeps that horz/vert allowed. Active for BLOCK_16X16/32X32/64X64 across GOOD speeds 0..=1.

#### `simple_motion_search` (item #7)
Coarse motion search wrapper: `vp9_full_pixel_search(NSTEP, step_param=1, sadperbit16)`, writes the inter prediction to a caller-supplied 64-byte-stride pred buffer via `vp9_build_inter_predictors_sby`. Used only by #8.

#### `ml_predict_var_rd_partitioning` (item #8, helper) / call site (item #16)
Pre-PARTITION_NONE NN run for BLOCK_8X8/16X16/32X32/64X64. Calls `simple_motion_search` first (BLOCK_64X64 uses zero ref-MV; smaller bsizes use `pc_tree->mv` from the parent), then builds 12 features: `log(dc_q+1)`, `has_above`, `b_w_log2(above)`, `b_h_log2(above)`, `has_left`, `b_w_log2(left)`, `b_h_log2(left)`, `log(var+1)`, and 4 quarter-block `sub_var / var` ratios. NN produces a single score; `score > thresh` zeroes `partition_none_allowed`, `score < -thresh` zeroes `do_split`. Threshold varies by `(bsize, speed)` and (for BLOCK_8X8) by `min(w,h) >= 720`. Active when `sf.rd_ml_partition.var_pruning && !intra_only` — GOOD speeds 0..=1 (speed 1 only for non-boosted).

### Section 3 — RT-side (cpu-used 5..=8) ML helpers

#### `ml_predict_var_partitioning` (item #9) / call site (item #13)
Inside `nonrd_pick_partition`, when `sf.partition_search_type == ML_BASED_PARTITION` is active, gates split-vs-none decision for BLOCK_16X16/32X32/64X64. 6 features: `log((dc_q²)/256 + 1)`, `log(var+1)`, 4 quarter-block `sub_var/var` ratios. 2-output NN; `score[0] > thresh` returns PARTITION_SPLIT, `< -thresh` returns PARTITION_NONE. Threshold = `speed <= 5 ? 1.25f : 0.0f`. **Critical input dependency:** reads source-vs-`x->est_pred` variance, so requires #10.

#### `get_estimated_pred` (item #10)
Called once per 64×64 SB before `nonrd_pick_partition` when `partition_search_type == ML_BASED_PARTITION`. For inter frames: picks LAST_FRAME (or ALTREF in lag-VBR, or GOLDEN if `y_sad_g < y_sad_thr`), runs `vp9_int_pro_motion_estimation` to find a 64×64 ref-MV, runs `vp9_build_inter_predictors_sb` with `interp_filter = BILINEAR` to fill `x->est_pred[64*64]`. For keyframes: DC fill (128, 128*4, or 128*16 by bit depth). Also writes `x->sb_use_mv_part = 1` and the SB-level MV components — these are read by `combined_motion_search`'s GOLDEN fast path in `vp9_pickmode.c`.

#### `ML_BASED_PARTITION` enum + dispatch (items #11, #12)
`PARTITION_SEARCH_TYPE` enum value at `vp9_speed_features.h:155`. The dispatch arm in `encode_nonrd_sb_row` (`vp9_encodeframe.c:5637-5645`) sets `x->sb_pickmode_part = 1`, calls `get_estimated_pred`, then `nonrd_pick_partition` with `max_partition_size = BLOCK_64X64`, `min_partition_size = BLOCK_8X8`. Selected when `sf.nonrd_use_ml_partition` is true at `vp9_speed_features.c:825-826`.

### Section 4 — Trained model data (`vp9_partition_models.h`)

13 distinct `NN_CONFIG` model objects:
- 3 partition-NONE-prune models (16x16/32x32/64x64) — 7 inputs, 8 hidden, 1 output (item #20)
- 3 rect-prune models (16/32/64) — 8 inputs, 8-24 hidden, 4 outputs (item #19)
- 3 RT var-part models (16/32/64) — 6 inputs, 8 hidden, 2 outputs (item #21)

Plus the breakout-LUTs (item #18) and the linear normalization + linear-model coefficients (item #23). All are `static const float` arrays. None are present in rvp9.

## Cross-cutting gaps

### Speed-feature struct extensions (gates the entire subsystem)

`vp9_speed_features.h:549-569` defines an anonymous nested struct `rd_ml_partition { search_breakout; search_breakout_thresh[3]; search_early_termination; var_pruning; prune_rect_thresh[4]; }` plus `nonrd_use_ml_partition` at line 644. rvp9's `mode_decision/speed_features.rs` does not contain any of these field names (grep returns nothing). All five gates default to OFF in rvp9 by construction (the fields don't exist). This means even if individual helpers were ported in isolation, the encoder hot path would never call them. Porting the gates is the prerequisite for everything else in A21.

### `MACROBLOCK::est_pred` storage + producer (`get_estimated_pred`)

Item #29 is a 4 KB aligned scratch buffer on the per-thread `MACROBLOCK`. Item #10 (`get_estimated_pred`) is the producer. The RT-side ML model (#9) reads it as the prediction source for the variance ratio features. There is no analogue in rvp9 today. Even the RT-side hooks `x->sb_use_mv_part`, `x->sb_mvcol_part`, `x->sb_mvrow_part` written by `get_estimated_pred` (and read by `combined_motion_search` in pickmode.c) are absent — see A1 row #3 "scaled reference handling" / "sb_use_mv_part short-circuit" in `2026.05.24 - pick_inter_mode gap inventory.md` which flags this as the same gap from the picker side.

### `PC_TREE` carry-state for ML

`pc_tree->mv` (written by #8 at `vp9_encodeframe.c:3548`, propagated at `:4116-4118`, read at `:3545`) requires PC_TREE to retain an MV field across recursive `rd_pick_partition` calls. A4's audit (`nonrd_pick_partition` PARTIAL) already flagged "PC_TREE state management" as missing; A21 adds the requirement that PC_TREE must also carry this `mv` field. Same applies to `pc_tree->none.rdcost`, `pc_tree->split[i]->none.rdcost`, `pc_tree->partitioning` — all read by #6 (`ml_prune_rect_partition`).

### NN inference primitive is a one-shot foundation

`nn_predict` is generic across all 13 trained models — porting it once unlocks every model. It is tiny (~45 LOC) and dependency-free (just f32 arithmetic + ReLU). The bulk of the work is faithfully transcribing the 975 LOC of trained float constants from `vp9_partition_models.h` into a Rust module, and wiring the call sites + gates.

### Bit-depth handling

Every ML helper has `#if CONFIG_VP9_HIGHBITDEPTH` paths: `vp9_high_get_sby_variance` instead of `cpi->fn_ptr[bsize].vf` for source variance (#5), `vp9_dc_quant(...) >> (bd-8)` (#6, #8), `(xd->cur_buf->flags & YV12_FLAG_HIGHBITDEPTH)` byte-pointer conversions (#8, #10). All of these will land in A21 along with the rest of HBD per A20 — when HBD is in scope (per goal: Profile 2/3 in scope), A21's HBD paths must port too.

### Floating-point determinism

`nn_predict` uses single-precision multiply-add chains in fixed left-to-right order. To be bitstream-identical to libvpx, rvp9's port must use the same order (no fused-multiply-add, no SIMD horizontal sum, no parallel reduction). Any deviation can flip the sign of a tight `score > thresh` decision and cascade into different partition choices. This is a portability discipline note, not a separate gap — but it must be captured in the port commit.

## Porter's Checklist (Priority Order)

Tiers are ordered by `(expected coding-efficiency or quality impact) × (probability of activation at default speeds)`. Note: at cpu-used 0 with `min(w,h) ≥ 480` and base_qindex ≥ 100 (common test corpus, e.g. foreman 352×288 → 480p is the boundary), several gates fire by default; at cpu-used 6+ (libvpx's RT default), `nonrd_use_ml_partition` is OFF by default — so RT ML is effectively dormant in current libvpx behaviour but the structure is in-scope per goal.

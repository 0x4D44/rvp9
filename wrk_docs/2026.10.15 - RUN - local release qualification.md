# Local release qualification

This runbook describes existing local gates. Running a command is not release approval. Keep a clean, recorded candidate and separate evidence for macOS Apple Silicon and native Windows x86-64. Use a task worktree and pass it as the tool's working directory; do not switch the trunk-holder. Build distributable artifacts only from the approved integrated source. Do not publish, tag, push or integrate as part of qualification.

## Acceptance boundary

Production-quality modes are single-stream CBR, denoiser CBR and spatial CBR, 8-bit profile 0, realtime CPU-used 6–8. VBR and temporal SVC keep the ceilings in README and PLAN and retain every correctness, speed, latency and safety gate. Frame dropping and EXT_RATECTRL remain unresolved roadmap requirements pending Arthur's explicit release-boundary decision.

The checked-in performance scripts enforce p50/p99 budgets of 33.333/50 ms at 720p30 and 1080p30, and 16.667/25 ms at 1080p60. PLAN §2 currently says 33/16 ms for the medians. Until that discrepancy is explicitly reconciled, report actual results against both and require the stricter 33/16 ms for the written §2 claim. Do not silently round a failing measurement into a pass.

`RVP9-BUG-FLU-00042` remains an open numeric blocker: the shared BD-rate solver accepts inaccurate finite results on narrow realistic PSNR curves. Repair and qualify the affected numerical tooling before expensive quality campaigns; inspect the separate standalone solver too. Singular-fit rejection does not settle numerical accuracy. `RVP9-BUG-FLU-00041` also leaves the spatial quality summary malformed: unquoted bitrate lists expand its CSV rows beyond the header. Preserve raw per-layer measurements and cross-decoder records, but do not accept that summary as a valid CSV or silently substitute a repaired result for the bug owner's fix.

The conformance script's forced-scalar labels are currently invalid on AArch64: native capability detection ignores `RVP9_FORCE_SCALAR` (`RVP9-BUG-FLU-00043`). Its macOS scalar-labelled runs do not provide scalar coverage. Keep native checks independent and leave the scalar gate incomplete until the owner repairs and verifies the mechanism.

## Quality, speed and latency

Build the host/source/toolchain-specific production PGO artifact using the unchanged 28-row/60-frame recipe:

```sh

```

Take the exact manifest path printed by that build. Do not select an old profile by version string. Hash the binary, manifest and profile. All builds must finish before timing, including unrelated local checks. Request a `deltic quiet` window using fleet-workflow; the host-load ceiling remains 0.75 busy logical cores. A quiet lease does not override excessive observed load.

Production phases need distinct registered external scratch directories. Allocate their common parent with `deltic scratch new --label rvp9-release-acceptance`; do not hand-pick an external temporary path. The following uses that returned path as `rvp9_acceptance_root` and the exact build manifest as `rvp9_pgo_manifest`:

deltic timeout 86400 bash scripts/qualify-production-encoder.sh \

The production matrix has 200 quality curves, 129 aggregate layer checks, 344 important-clip guards, 2,640 streams/7,920 decoder runs, 75 speed groups and 200 latency rows/1,000 measured runs. ## Bounded safety and packaging

Review the existing safety journal and current unsafe inventory, then collect missing candidate evidence. Miri must cover non-SIMD library paths, including dependent libraries; the four-module helper is only a subset. The current AArch64 dependent-library compile failure is `RVP9-BUG-FLU-00037`. Native sanitizer tests must exercise native SIMD on each target; forced-scalar or Rosetta results do not establish AVX2 coverage. Use installed compatible nightly/Miri/sanitizer tools, separate scratch targets and bounded tracked execution. Record unavailable tools rather than claiming unrun campaigns.

For bounded fuzzing, require both parser and full-frame targets, nonzero executions, raw-packet reconstruction seeds, terminal completion and no sanitizer/crash output. For soak, require nonzero iterations, decoded frames and encoded bytes; disclose its CPU0 configuration and absence of macOS RSS measurement. The approved billion-iteration/72-hour deferrals remain separate from these bounded checks.

`cargo package --offline --locked` is a local assembly/verification check, not publication. For this workspace, pass all five packages in one Cargo invocation so Cargo verifies the freshly packaged sibling graph instead of resolving a cached alpha.4 crate from the registry:

```sh
deltic timeout 1800 cargo package --offline --locked \
  -p rvp9-core -p rvp9-io -p rvp9-decoder -p rvp9-encoder -p rvp9-cli </dev/null
```

On the candidate, this command exited 0 on both native platforms and verified all five production packages. Check that each finalized archive matches Cargo's staging-registry archive and index checksum, and that the CLI lock checksums resolve to those exact sibling archives. The archived results are linked from the readiness report. A one-package-at-a-time CLI command resolved the cached encoder alpha.4 and failed E0603; keep that method-specific result visible. Neither graph qualifies a newly versioned release.

Cargo's verification build does not run the archive's tests. Extracted-archive test attempts remain separate and currently fail for decoder/encoder because packaging strips required development dependencies (FLU38); do not count them as passes. Use registered scratch, a separate target, and no manifest patches, dependency overrides or verification bypass. Missing cached dependencies are an offline prerequisite failure. Run extracted-archive commands with their external scratch directory as the working directory: Cargo discovers configuration from that directory, so an external `--manifest-path` alone does not isolate the workspace's native Rust flags.

`cargo doc --offline --locked --no-deps -p rvp9-core -p rvp9-io -p rvp9-decoder -p rvp9-encoder -p rvp9-cli` refreshes shipped public API documentation. Bound it and retain warnings separately; success alone does not establish warning-free documentation or API compatibility.

The existing `package-alpha.sh` only accepts an alpha version from clean integrated `origin/main` and creates portable plain-release macOS binaries. Preserve that guard. It is not a final-RC packager and its binaries do not inherit native PGO performance results. Do not pre-bump versions or publish during this task.

Canonical scripts hardcode `target/release`; if using an external target directory, record a task-local symlink/junction only after proving the destination path is absent. The repository ignores `*.log`, so staging an evidence directory alone does not preserve those files: explicitly force-stage the intended raw log paths or retain byte-identical `.raw.txt` copies and record their hashes. Check every manifest entry against both the filesystem and the staged/tracked file list. Never reconstruct a missing original log from a summary or treat an unavailable artifact as freshly hash-verified.

# G2 — Per-context switchable-filter rate in the inter-mode picker

**Date:** 2026-05-24
**Status:** Design
**Scope:** Replace flat `F5_SWITCHABLE_FILTER_RATE` constant with context-dependent
`switchable_interp_costs[ctx][filter]` lookup in `evaluate_candidate_for_filter`

## 1. Problem

When the filter search loop (`evaluate_candidate_for_filter`) picks a
non-EightTap filter, it charges a flat penalty:

```rust
// crates/rvp9-core/src/mode_decision/inter.rs:1269
const F5_SWITCHABLE_FILTER_RATE: u32 = 2048;
```

This is a conservative upper-bound approximation. In libvpx the cost is
context-dependent: `vp9_get_switchable_rate(cpi, xd)` returns
`switchable_interp_costs[ctx][filter]` where `ctx` comes from
`vp9_get_pred_context_switchable_interp(xd)` (examines above/left
neighbours' interpolation filter). The flat constant over-penalises
filter switching when neighbours already use the same non-default filter
(ctx matches, cost is low) and slightly under-penalises in rare contexts.

## 2. Existing infrastructure

**Cost table** — already ported and tested:

```rust
// crates/rvp9-core/src/cost/symbol_costs.rs:44-45, 170-179
pub type SwitchableInterpCosts = [[i32; SWITCHABLE_FILTERS]; SWITCHABLE_FILTER_CONTEXTS];
// SWITCHABLE_FILTERS = 3, SWITCHABLE_FILTER_CONTEXTS = 4

pub fn switchable_interp_costs(fc: &FrameContext) -> SwitchableInterpCosts;
```

**Context function** — already ported and tested:

```rust
// crates/rvp9-core/src/inter/mode_info.rs:147-188
pub fn get_pred_context_switchable_interp(
    above: Option<&ModeInfo>,
    left: Option<&ModeInfo>,
) -> usize;  // returns 0..=3
```

Both are already used by the decoder/writer paths (`read_switchable_interp_filter`,
`write_inter_block_mode_info`). Neither is wired into the picker.

**Encoder mi_grid** — the encoder maintains `mi_grid: Vec<Option<ModeInfo>>`
and splats each picked leaf (including `interp_filter`) via
`splat_inter_leaf_into_mi_grid` (lib.rs:2179-2224) in raster order. Above
and left neighbours are therefore available at pick time.

## 3. What changes

### 3.1 New field on `PickInterModeParams` (inter.rs)

| Field | Type | Purpose |
|---|---|---|
| `switchable_interp_costs` | `&'a SwitchableInterpCosts` | Pre-built per-context filter cost table |
| `switchable_interp_ctx` | `usize` | Context (0..4) from above/left neighbour filters |

**Rationale:** Compute both at the call site (`lib.rs:~3213`), not inside the
picker. The call site already has `InterPickerMiGridLookup` with above/left
`ModeInfo` access (used for `get_mode_context`). The cost table is frame-level
(built once from `FrameContext`), so it is cheap to share by reference.

### 3.2 Thread into `InterModeSearchParams` (single-ref legacy path)

Same two fields. The `TestHarness` helper adds default values
(`switchable_interp_costs: &default_table`, `switchable_interp_ctx: 3`
where ctx=3 = "no neighbour" sentinel, matching the flat-constant regime).

### 3.3 Plumbing at call site (lib.rs `encode_inter_frame`)

Before the leaf loop, build the table once:

```rust
use rvp9_core::cost::switchable_interp_costs;
let sic = switchable_interp_costs(&fc);
```

Inside the leaf loop, after `neighbours` is built and before
`PickInterModeParams` construction:

```rust
use rvp9_core::inter::get_pred_context_switchable_interp;

let nb_above: Option<&ModeInfo> = /* mi_grid[(mi_row-1)*mi_cols + mi_col] */
    if leaf_mi_row > 0 {
        mi_grid[(leaf_mi_row - 1) * mi_cols_us + leaf_mi_col].as_ref()
    } else {
        None
    };
let nb_left: Option<&ModeInfo> =
    if leaf_mi_col > 0 {
        mi_grid[leaf_mi_row * mi_cols_us + (leaf_mi_col - 1)].as_ref()
    } else {
        None
    };
let switchable_interp_ctx = get_pred_context_switchable_interp(nb_above, nb_left);
```

### 3.4 Replace flat constant in `evaluate_candidate_for_filter`

```rust
// Before (inter.rs:1552-1562):
let filter_rate: u32 = if matches!(filter, InterpFilter::EightTap) {
    0
} else {
    F5_SWITCHABLE_FILTER_RATE
};

// After:
let filter_rate: u32 = params.switchable_interp_costs
    [params.switchable_interp_ctx][filter as usize]
    .max(0) as u32;
```

Note: ALL filters (including EightTap) get their true cost from the table.
The `EightTap == 0` special-case disappears; the table already encodes
EightTap's cost (which is low in context 0 but nonzero).

Delete `const F5_SWITCHABLE_FILTER_RATE`.

## 4. Test plan

1. **Unit: known-context cost oracle.** Build `SwitchableInterpCosts` from
   default probs. For each context 0..3, assert
   `evaluate_candidate_for_filter` charges `costs[ctx][filter]` (not the
   old flat constant). Construct `InterModeSearchParams` with explicit
   `switchable_interp_ctx` values and verify the rate sum.

2. **Unit: context function wiring.** Set up a synthetic mi_grid with
   known above/left `interp_filter` values, compute ctx via
   `get_pred_context_switchable_interp`, verify it matches expected
   (0 = both EightTap, 1 = both Smooth, 3 = mismatch/absent).

3. **Regression: F.0.1 foreman gate.** Re-run the foreman PSNR-delta
   bench. The per-context rate is slightly more permissive than the 2048
   flat constant in common contexts, so expect modest PSNR improvement
   (more filter switching allowed where it genuinely helps). A regression
   beyond the F.0.1 threshold warrants investigation.

4. **Existing tests:** Update `f5_per_filter_evaluation_differs_and_tags_picked_filter`
   and the zero-distortion EightTap-wins test to supply the new fields
   (use ctx=3 sentinel + default-prob table to approximate the old flat
   behaviour for backward compatibility of assertions).

## 5. Risks

- **Quality shift.** The per-context rate is lower than 2048 in contexts
  0-2 (ranges ~300-2120). More filter switching will occur. If this
  causes regression, the remedy is the same as the original F.5 fix:
  tighten the per-context costs by scaling (a multiplier field on
  `PickInterModeParams`). Unlikely given this matches libvpx exactly.

- **Test churn.** ~4-6 existing tests reference `F5_SWITCHABLE_FILTER_RATE`
  by name or value. All need updating to supply the new params fields.
  Mechanical, not risky.

# G7.1 — VP9 Profile 1 decode: scope / HLD

**Status:** SCOPE (no implementation yet). Authored Wave M (2026-05-22) as the M2
deliverable. Companion to the Wave M journal.

**One-line:** Lift the decoder's hardcoded 4:2:0 assumption so it decodes VP9
**Profile 1** (8-bit, non-4:2:0 chroma: 4:2:2 / 4:4:0 / 4:4:4), then remove the
`UnsupportedProfile` gate.

---

## 1. Background & scope

VP9 profiles differ by bit depth and chroma subsampling:

| Profile | Bit depth | Chroma | `(ss_x, ss_y)` |
|---------|-----------|--------|----------------|
| 0       | 8         | 4:2:0  | (1, 1)         |
| **1**   | **8**     | **4:2:2 / 4:4:0 / 4:4:4** | **(1,0) / (0,1) / (0,0)** |
| 2       | 10/12     | 4:2:0  | (1, 1)         |
| 3       | 10/12     | 4:2:2 / 4:4:0 / 4:4:4 | as profile 1   |

**In scope:** Profile 1 decode of the three non-4:2:0 8-bit formats.
**Out of scope:** Profiles 2/3 (high bit depth — a separate, larger effort: 16-bit
pixel pipeline), Profile 1 *encode*, alpha planes.

**Why now / why separate from M1:** This is genuinely engineering-gated (a
cross-cutting invariant change), independent of vpxenc availability, and large
enough to warrant its own wave. The M1 fix (frame_parallel adaptation gate) is
unrelated and already landed.

## 2. Current state

### 2.1 The gate (the last thing to delete)
- `crates/rvp9-decoder/src/lib.rs:1148-1154` — `decode_frame()` rejects any
  non-`ShowExistingFrame` frame whose `chroma != ChromaFormat::Yuv420` with
  `DecodeError::UnsupportedProfile { profile }` (variant at `lib.rs:3200`).
  Comment already flags this as the "G7.1" gate.

### 2.2 What already works (no change needed)
- **Profile + subsampling parse:** `crates/rvp9-core/src/bitstream/header.rs:220-230`
  (`read_profile_raw` / `Profile::from_u8`) and `:508-534`
  (`read_bitdepth_colorspace_sampling` — reads `subsampling_x`/`subsampling_y` for
  profiles 1/3; defaults to Yuv420 for 0/2). **The bitstream already parses the
  subsampling correctly for Profile 1.**
- **`ChromaFormat` model:** `crates/rvp9-core/src/bitstream/frame.rs:169-218` — four
  variants + `subsampling_x()/subsampling_y()` bool accessors.
- **Frame-buffer allocation is fully parametric:** `crates/rvp9-core/src/frame.rs:154-402`
  — `Yv12Buffer` carries a `chroma: ChromaFormat`; `alloc()` computes UV plane dims as
  `y_dim >> ss` (`:226-240`); `plane_with_border()` applies per-plane `ss` shifts
  (`:494-520`); `chroma_width()/chroma_height()` use `(crop + ss) >> ss`.

**Consequence:** the infrastructure cost is largely paid. The work is replacing
*static* 4:2:0 constants in the per-block hot paths with *frame-driven* `(ss_x, ss_y)`.

### 2.3 Where 4:2:0 is hardcoded (the work)
| # | Site | File:line | Nature |
|---|------|-----------|--------|
| A | `SUBSAMPLING_X/Y[3] = [0,1,1]` static arrays | `reconstruct_inter.rs:67-73`, `tile.rs:313-314` | per-plane ss looked up from a constant, not the frame |
| B | `uv_plane_block_size()` (+ `uv_plane_tx_size()`) | `tile.rs:695-710` | 13 hardcoded 4:2:0 match arms |
| C | Sub-8 chroma MV averaging `avg_split_mv_q4_4x4()` | `reconstruct_inter.rs:312, 670-683` | assumes 4 luma → 1 chroma (4:2:0 geometry) |
| D | Loop filter chroma geometry | `crates/rvp9-core/src/loopfilter.rs` | mask/edge handling; subsampling-awareness TBD (long pole) |
| E | Intra/residual chroma plane iteration | `tile.rs:574-620` (uses A) | falls out once A+B are frame-driven |

**Already-parametric formula worth noting:** the inter chroma MV→Q4 conversion at
`reconstruct_inter.rs:327-336` (`mv_q4 = mv * (1 << (1 - ss))`) is *already general*
in `ss` — it yields the correct ×1 (4:2:0 chroma), ×2 (4:4:4 chroma / luma) scaling
for any subsampling. It only needs the *right* `ss` fed in (item A). The scaling math
is not a rewrite.

## 3. Design approach

### 3.1 Thread `(ss_x, ss_y)` from the frame, not a constant
Replace the static `SUBSAMPLING_X/Y[plane]` lookups (item A) with the per-frame value
derived from `Yv12Buffer::chroma()` (or the resolved header `ChromaFormat`), passed
into the per-block reconstruction drivers. Concretely: `ss_x = if plane == 0 { 0 }
else { chroma.subsampling_x() as usize }` (and likewise `ss_y`). This is the keystone
change — items B, C, E all consume it.

### 3.2 Parametrize chroma block sizing (`uv_plane_block_size`)
Replace the 13 match arms with libvpx's `ss_size_lookup[bsize][ss_x][ss_y]` semantics:
chroma block = luma block with width `>> ss_x`, height `>> ss_y`, floored at 4×4
(`BLOCK_INVALID` cases — e.g. a 4×4 luma block in 4:4:4 keeps a 4×4 chroma block; in
4:2:0 it shares one 4×4 chroma block across the 8×8 parent). Mirror libvpx
`vp9_common_data.c ss_size_lookup` exactly; transcribe the full 4-D table as a const
and assert against it. `uv_plane_tx_size()` then follows from the corrected block size.

### 3.3 Generalize sub-8 chroma MV derivation (`average_split_mvs`)
libvpx `average_split_mvs` (`vp9_reconinter.c`) averages the sub-8 luma MVs that map
to one chroma sub-block, where the count depends on `(ss_x, ss_y)`:
- 4:2:0 (1,1): average all 4 bmis → 1 chroma block (current behavior).
- 4:2:2 (1,0): average the 2 horizontally-adjacent bmis per chroma sub-block (chroma
  keeps full height).
- 4:4:0 (0,1): average the 2 vertically-adjacent bmis.
- 4:4:4 (0,0): no averaging — per-bmi MV used directly (chroma block == luma block).

Replace `avg_split_mv_q4_4x4` with a function parametric in `(ss_x, ss_y)` selecting
the bmi index set, matching libvpx's `ss_idx = (ss_x << 1) | ss_y` switch.

### 3.4 Loop filter (the long pole)
The VP9 loop filter builds per-plane masks and filters chroma edges on a grid scaled
by subsampling. Audit `loopfilter.rs` for any `>> 1` / 4:2:0-implicit chroma geometry
and make the mask construction + edge iteration `(ss_x, ss_y)`-driven. This is the
highest-risk subsystem because the mask packing (`above`/`left` 64-bit edge masks) is
laid out for the 4:2:0 chroma grid; 4:4:4 chroma has the same grid as luma, 4:2:2 is
asymmetric. Budget the most time and the densest differential testing here.

### 3.5 Remove the gate
Delete `lib.rs:1148-1154` only after A–D are differential-clean for all three formats.

## 4. Conformance & test plan

The scalar path is the spec; the oracle is libvpx `vpxdec`. Two vector sources:

1. **Official corpus.** Add Profile-1 vectors to `scripts/fetch-vectors.sh` (the WebM
   bucket carries `vp91-2-*` / 4:2:2 / 4:4:4 vectors; the canonical list is
   libvpx `test/test-data.sha1`). Wire them into the conformance harness
   (`crates/rvp9-harness`) the same way as Profile 0 — paired `.md5` ledgers, the
   `md5_of_yv12_visible` Y-then-U-then-V crop hash already handles arbitrary plane
   dims, so no harness change beyond the vector list. Conformance floor rises above 201.
2. **Self-encoded.** `build/libvpx/vpxenc.exe --profile=1` with explicit
   `--i444`/`--i422`/`--i440` inputs (need 4:2:2/4:4:4 `.y4m` sources, or convert
   `foreman_cif.y4m` via the libvpx tools). Extend `scripts/encode-corpus.ps1` to pass
   `--profile` and the chroma flag. Note the M1 lesson: self-encoded `-WithLedger`
   ledgers are now trustworthy for default-feature encodes since M1 landed, but treat a
   freshly-touched chroma path as guilty until the official corpus agrees.

**Differential discipline (per-format):** for each of 4:2:2 / 4:4:0 / 4:4:4, decode a
multi-frame inter clip and assert byte-identical to `vpxdec --i420`/per-plane output,
frame-for-frame — exactly the M1 methodology. Add a unit-level differential for the new
parametric helpers (B, C) asserting they reduce to the current 4:2:0 behavior when
`(ss_x, ss_y) = (1, 1)` (regression guard for Profile 0).

## 5. Phasing

- **G7.1a — thread subsampling + chroma sizing (items A, B, E).** Frame-driven `ss`,
  parametric `uv_plane_block_size`/`uv_plane_tx_size`. Gate stays up; verify Profile 0
  unchanged (201/201) — pure refactor, no behavior change at (1,1).
- **G7.1b — inter chroma MV (item C).** Generalize sub-8 averaging; differential-test
  4:4:4 first (simplest: chroma == luma), then 4:2:2 / 4:4:0.
- **G7.1c — loop filter (item D).** The long pole; `ss`-aware mask + edges.
- **G7.1d — lift the gate + conformance.** Delete the gate, add Profile-1 vectors,
  raise the conformance floor. Wave exit when all three formats are byte-exact.

Each phase is independently committable and keeps Profile 0 green throughout.

---

## 6. Effort & risk

- **Effort:** ~10–15 engineer-days, loopfilter being ~half of it. A–C are mechanical
  given the parametric frame buffer; D carries the schedule risk.
- **Risks / open questions:**
  - Loop-filter mask packing for asymmetric (4:2:2) chroma is the most likely place for
    a subtle, M1-style "passes-most-vectors-but-not-all" bug — front-load its
    differential coverage.
  - 4:4:0 is rare in the wild and may be under-represented in the official corpus;
    self-encoded vectors may be the only coverage. Confirm vpxenc can emit it.
  - Confirm the intra chroma prediction path (`tile.rs:528-600`) needs nothing beyond
    the corrected block size — verify no other 4:2:0-implicit arithmetic hides there.
  - Encoder is hardcoded to Profile 0 (`header.rs:599`); leave it — decode-only scope.

---

## 7. Recommendation

Schedule G7.1 as its own wave. Start with G7.1a (zero behavior change at (1,1), so it
de-risks the refactor against the existing 201 corpus before any new format is enabled),
then G7.1b→c→d. Do **not** bundle with high-bit-depth (profiles 2/3) — that's a separate
pixel-width project.

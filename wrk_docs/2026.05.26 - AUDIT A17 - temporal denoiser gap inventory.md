# AUDIT A17 — Temporal denoiser gap inventory

**Date:** 2026-05-26
**Audit zone:** A17 — Temporal denoiser (`CONFIG_VP9_TEMPORAL_DENOISING`)
**Scope statement:**
- **libvpx side:** `third_party/libvpx/vp9/encoder/vp9_denoiser.{c,h}` (839+132 = 971 LOC), `third_party/libvpx/vp9/encoder/x86/vp9_denoiser_sse2.c` (327 LOC), plus integration call sites in `vp9_pickmode.c`, `vp9_encoder.c`, `vp9_encodeframe.c`, `vp9_svc_layercontext.c`, `vp9_cx_iface.c`. Total denoiser surface ~1.3k LOC plus ~200 LOC of caller/state integration.
- **rvp9 side:** Compared against `crates/rvp9-core/src/mode_decision/{inter,partition,intra}.rs`, `crates/rvp9-core/src/mv_search/`, `crates/rvp9-encoder/src/{lib,frame_loop,aq_cyclic_refresh}.rs`, `crates/rvp9-cli/src/bin/rvp9enc.rs`.
- **HBD note:** libvpx explicitly disables the denoiser for `bit_depth > 8` (`vp9_cx_iface.c:585-591`) because `vp9_denoiser_filter` is 8-bit only. The denoiser is therefore IN SCOPE for Profile 0 (and the 8-bit subset of Profile 1) only; Profile 2/3 HBD parity does **not** require HBD denoiser variants because libvpx itself has none.

**Method:** Read-only comparative grep + line-by-line review of libvpx denoiser sources, picker integration points, encoder lifecycle hooks, RTCD definition, SSE2 SIMD variant, and configuration plumbing. rvp9 grep for `denois|denoise|vp9_denoiser|recheck_zeromv|running_avg_y|zeromv_sse|newmv_sse|best_sse_mv|consec_zero_mv|sb_skip_denoising|noise_sensitivity` across `crates/`.

**Method deviation (row-count sanity check):** Picker baseline is 45 rows / 2820 LOC ≈ 1 row per 63 LOC. Denoiser surface here is ~1.3k LOC libvpx + ~200 LOC integration ≈ 1.5k LOC, so expected ~24 rows. This inventory has **31 rows** which lands inside the 50%–150% band (12–36 rows). The bias toward more rows reflects the fact that the denoiser couples to many small pieces of caller state (`PICK_MODE_CONTEXT` SSE fields, `consec_zero_mv`, `sb_skip_denoising`, `sb_pickmode_part`, `noise_estimate`, `resize_pending`) — each of which is its own gap row even though small in LOC.

**Headline finding:** Zero denoiser code is ported in rvp9. The only references to "denoise" / "denoiser" in `crates/` are: (a) a CLI flag stub `--noise-sensitivity` (`crates/rvp9-cli/src/bin/rvp9enc.rs:117`) that has no `apply` callback (`apply: None`), (b) plan-comment mentions in `frame_loop.rs:123`, `lib.rs:8`, `lib.rs:32`, (c) two prose comments in `mode_decision/{inter.rs:3184, partition.rs:282}` acknowledging absence, (d) one comment-only reference to `consec_zero_mv` in `aq_cyclic_refresh.rs:48`. No data structures, no filter kernel, no state fields, no integration with the picker, no allocation. **Every row below is NOT PORTED** except for the OUT-OF-SCOPE rows (HBD denoiser, ARM NEON).

## Section-by-section narrative

### 1. Filter kernel (per-block 8-bit Y-only temporal filter)

libvpx's per-block kernel takes `(sig, mc_avg, avg)` and produces a new `avg` (running average) by clamping per-pixel adjustments to a small set of levels (`adj_val[] = {3,4,6}`, motion-modulated by `MOTION_MAGNITUDE_THRESHOLD = 24`). It first applies a "strong" filter; if the accumulated adjustment exceeds `total_adj_strong_thresh`, it computes a `delta` and reapplies a weaker dampened pass. Returns `FILTER_BLOCK` (kept) or `COPY_BLOCK` (fall back to source).

- **Row 1** `vp9_denoiser_filter_c` (vp9_denoiser.c:68-180) — **NOT PORTED**. Reference implementation, 115 LOC. No analogue in rvp9.
- **Row 2** `vp9_denoiser_filter_sse2` (x86/vp9_denoiser_sse2.c:308-327) plus `vp9_denoiser_16x1_sse2` (39-90), `vp9_denoiser_adj_16x1_sse2` (~91-117), `vp9_denoiser_NxM_sse2_small` (120-205), `vp9_denoiser_NxM_sse2_big` (208-306) — **NOT PORTED**. SSE2 variants for 8x{8,16} and 16x{8,16,32}, 32x{16,32,64}, 64x{32,64}. ~320 LOC. In scope per Arthur's "all x86_64 paths" rule.
- **Row 3** Threshold helpers (`absdiff_thresh`, `delta_thresh`, `noise_motion_thresh`, `sse_thresh`, `sse_diff_thresh`, `total_adj_weak_thresh` at vp9_denoiser.c:28-63 and `total_adj_strong_thresh` at vp9_denoiser.h:107-110) — **NOT PORTED**. Small but feed both the C kernel, the SIMD kernel, and `perform_motion_compensation`.
- **Row 31** RTCD dispatch (vp9_rtcd_defs.pl:125-126: `add_proto qw/int vp9_denoiser_filter/...; specialize qw/vp9_denoiser_filter neon sse2/`). rvp9's SIMD dispatch crate has no entry for the denoiser kernel.

### 2. Per-block driver and motion-compensation

`vp9_denoiser_denoise` is invoked at the end of `vp9_pick_inter_mode` per superblock. It (a) extracts motion magnitude from `ctx->best_sse_mv`, (b) optionally runs skin detection on the block (when `cpi->use_skin_detection` and `bs <= BLOCK_32X32`) using `consec_zero_mv` history, (c) calls `perform_motion_compensation` which selects between `best_reference_frame` (NEWMV winner) and `best_zeromv_reference_frame` (ZEROMV winner) based on `sse_diff_thresh`, sets up MACROBLOCKD plane pointers to the denoiser's `running_avg_y` ring, runs `vp9_build_inter_predictors_sby`, and restores saved state, (d) calls `vp9_denoiser_filter` on the MC result, (e) copies either the filtered avg back into `mb->plane[0].src` (FILTER_BLOCK) or the source forward into `running_avg_y` (COPY_BLOCK).

- **Row 4** `perform_motion_compensation` (vp9_denoiser.c:187-334) — **NOT PORTED**.
- **Row 5** `vp9_denoiser_denoise` (vp9_denoiser.c:336-437, prototype vp9_denoiser.h:79-82) — **NOT PORTED**. Note dependency on A5 (`vp9_compute_skin_block`), which is also NOT PORTED per A5 (skin detector).

### 3. Per-block statistics (the picker → denoiser data bus)

The denoiser consumes four fields of `PICK_MODE_CONTEXT` that the picker populates as it iterates candidates:
- `zeromv_sse`, `zeromv_lastref_sse`, `best_zeromv_reference_frame` — best SSE among ZEROMV candidates
- `newmv_sse`, `best_sse_inter_mode`, `best_sse_mv`, `best_reference_frame` — best SSE among non-zero MV candidates
- `sb_skip_denoising` — superblock-level "skip denoise" flag set when `x->sb_pickmode_part` is on

- **Row 6** `vp9_denoiser_reset_frame_stats` (vp9_denoiser.c:526-531, header :84) — **NOT PORTED**. Clears the four SSE fields to `UINT_MAX` / zero.
- **Row 7** `vp9_denoiser_update_frame_stats` (vp9_denoiser.c:533-548, header :86-88) — **NOT PORTED**. Called per candidate; updates the running ZEROMV/NEWMV minima.
- **Row 10** `PICK_MODE_CONTEXT` field set (vp9_context_tree.h:54-70 typedef, used at vp9_denoiser.c:193-246, vp9_pickmode.c:2436-2446) — **NOT PORTED**. The Rust `PickModeContext` equivalent has none of these fields.
- **Row 11** `MACROBLOCK::sb_pickmode_part` (vp9_block.h:193, set in vp9_encodeframe.c:5579,5641,5659; used at vp9_pickmode.c:2686 to set `sb_skip_denoising`) — **NOT PORTED**.

### 4. Picker integration sites

Three sites inside `vp9_pick_inter_mode` couple the picker to the denoiser:

- **Row 12** Reset-on-entry (vp9_pickmode.c:1900-1906): when `noise_sensitivity > 0` and `denoising_level > kDenLowLow`, call `vp9_denoiser_reset_frame_stats(ctx)`. Also computes `denoise_svc_pickmode = vp9_denoise_svc_non_key(cpi)` for SVC.
- **Row 13** Per-candidate update (vp9_pickmode.c:2436-2446): after each inter candidate's RD is computed, call `vp9_denoiser_update_frame_stats(mi, sse_y, this_mode, ctx)`. Also tracks `zero_last_cost_orig` (RD cost of ZEROMV on LAST) for the post-denoise recheck.
- **Row 14** End-of-pick driver (vp9_pickmode.c:2677-2696): if `noise_sensitivity > 0 && resize_pending == 0 && denoise_svc_pickmode && denoising_level > kDenLowLow && reset == 0`, call `vp9_pickmode_ctx_den_update` → `vp9_denoiser_denoise` → optional `recheck_zeromv_after_denoising`. **Updates `best_pickmode.best_ref_frame` from `ctx_den.best_ref_frame`** — i.e. the denoiser can change which ref frame the bitstream commits to.
- **Row 8** `recheck_zeromv_after_denoising` (vp9_pickmode.c:1375-1440) — **NOT PORTED**. If best mode was INTRA or GOLDEN and denoiser decided to FILTER, re-evaluate `LAST + ZEROMV` on the denoised source and switch to it if it wins.
- **Row 9** `VP9_PICKMODE_CTX_DEN` struct + `vp9_pickmode_ctx_den_update` (vp9_denoiser.h:58-68, vp9_pickmode.c:1359-1373) — **NOT PORTED**. The bridge struct: ref-frame costs, `frame_mv` array pointer, best-pickmode fields.

### 5. Threshold scaling (denoiser ↔ partition/skip interactions)

The denoiser influences other speed-feature decisions:
- **Row 15** `model_rd_for_sb_y_large` ac-skip scaling (vp9_pickmode.c:478-490): when `noise_sensitivity > 0 && speed > 5`, `ac_thr` is multiplied by `vp9_scale_acskip_thresh` instead of `ac_thr_factor`. **NOT PORTED**.
- **Row 16** `vp9_scale_part_thresh` (vp9_denoiser.c:747-759) — **NOT PORTED**. Scales partition threshold by 1.25× / 1.5× / 1.75× depending on content state, noise level, temporal layer.
- **Row 17** `vp9_scale_acskip_thresh` (vp9_denoiser.c:763-772) — **NOT PORTED**. Multiplies ac-skip threshold by 2/6/10 depending on noise level + temporal layer.
- **Row 18** `choose_partitioning` integration (vp9_encodeframe.c:600-603) — **NOT PORTED**. Calls `vp9_scale_part_thresh` when `noise_sensitivity > 0 && speed > 5 && denoising_level >= kDenLow`.

### 6. Frame-buffer lifecycle (running_avg_y / mc_running_avg_y / last_source ring)

- `mc_running_avg_y[num_layers]` — scratch buffer for MC-predicted denoised pixels.
- `last_source` — used by `vp9_update_noise_estimate` (A5).

- **Row 19** `vp9_denoiser_alloc` (vp9_denoiser.c:606-696, header :95-101) — **NOT PORTED**. ~91 LOC, allocates the full ring including SVC scaled-layer geometry.
- **Row 20** `vp9_denoiser_free` (vp9_denoiser.c:698-717, header :113) — **NOT PORTED**.
- **Row 21** `vp9_denoiser_realloc_svc` + `vp9_denoiser_realloc_svc_helper` (vp9_denoiser.c:550-604, header :90-93) — **NOT PORTED**. Reallocates buffer slots on SVC refresh events.
- **Row 22** `vp9_denoiser_update_frame_info` (vp9_denoiser.c:464-524, header :73-77) — **NOT PORTED**. Per-frame ring rotation: on KEY/resize, copy source into all slots; otherwise swap/copy `INTRA_FRAME` slot into the slots indicated by `refresh_{alt,golden,last}_frame`.
- **Row 23** `copy_frame` / `swap_frame_buffer` (vp9_denoiser.c:439-462) — **NOT PORTED**. Plane-wise memcpy and pointer swap helpers.

## Cross-cutting gaps

### CCG-1: `PICK_MODE_CONTEXT` SSE bookkeeping is entirely absent
Across the picker, the denoiser depends on the picker writing per-candidate `(zeromv_sse, newmv_sse, best_sse_mv, ...)` into the `PICK_MODE_CONTEXT`. rvp9's `PickModeContext` analogue (in `crates/rvp9-core/src/mode_decision/`) has none of these fields and the picker never produces them. Even if the denoiser kernel were ported, it would have no input data — the picker integration (Rows 12-13) is the data-bus that the kernel reads from.

### CCG-2: Frame-buffer lifecycle has no allocation owner
rvp9 has no equivalent of `setup_denoiser_buffer` / `VP9_DENOISER` struct. The encoder lifecycle in `crates/rvp9-encoder/src/lib.rs` and `frame_loop.rs` has no init/teardown/resize hook for denoiser buffers. Plumbing this in needs decisions about where the `running_avg_y` ring lives (encoder-owned vs frame-loop-owned vs core-owned) — this is an architectural decision Arthur and Claude should align on before P-tier execution starts.

### CCG-3: `consec_zero_mv` is a shared dependency, not denoiser-private
`consec_zero_mv` is consumed by **three** subsystems (denoiser skin gate, AQ cyclic refresh A11, noise estimator A5). The audit row (Row 29) belongs to A17 because the denoiser is the only consumer that materially needs it for correctness at default settings, but porting it must coordinate with A11 and A5. Recommend porting `consec_zero_mv` once as a `crates/rvp9-encoder/src/state/consec_zero_mv.rs` module and wiring all three consumers off it.

### CCG-4: Denoiser changes the bitstream
The end-of-pick path (Row 14, vp9_pickmode.c:2694) reassigns `best_pickmode.best_ref_frame = ctx_den.best_ref_frame` — meaning the denoiser can switch the selected ref frame from {INTRA, GOLDEN} to LAST when it finds the LAST-denoised ZEROMV better. This is not just a quality knob: the chosen ref/mode/MV that the bitstream encodes depends on denoiser decisions. Any cross-decoder gate must encode WITH denoiser enabled at the right `noise_sensitivity` to exercise this path.

### CCG-5: HBD denoiser is OUT OF SCOPE by libvpx behaviour, not by deferral
`vp9_cx_iface.c:585-591` overrides `oxcf.noise_sensitivity = 0` whenever `bit_depth != VPX_BITS_8`. Profile 2/3 parity therefore requires **the same disable behaviour**, not a port of an HBD kernel. The rvp9 config layer must replicate this override (no-op the noise sensitivity for HBD inputs) when Row 30 is upgraded from PARTIAL to PORTED.

### CCG-6: Skin detector (A5) is a prerequisite, not a co-traveller
Row 5 (`vp9_denoiser_denoise`) calls `vp9_compute_skin_block` at vp9_denoiser.c:399-402 to gate motion-compensated denoising on skin tones. A5 (`vp9_skin_detection.c`) is also NOT PORTED. Row 5 cannot ship without A5 also shipping (or being explicitly stubbed-disabled at the call site, with a documented deviation).

### CCG-7: Noise estimator (also A5) is a prerequisite for `recheck_zeromv_after_denoising`
Row 8 (`recheck_zeromv_after_denoising`) is gated by `cpi->noise_estimate.enabled && cpi->noise_estimate.level > kLow` at vp9_pickmode.c:1384. A5 (`vp9_noise_estimate.c`) is also NOT PORTED. Row 8 can ship in skeleton form (no-op when noise estimator is absent) but its activation requires A5.

### CCG-8: ALTREF / SVC dependency reaches into core lifecycle
`force_refresh_longterm_ref` (vp9_denoiser.c:719-730) sets `cpi->alt_fb_idx` and forces `cpi->refresh_alt_ref_frame = 1` when SVC's `use_gf_temporal_ref_current_layer` is on. This couples A17 to A10 (ref-frame management) and A18 (SVC). Order the porting: A10 + A18 must define the refresh-flag surface that A17 hooks into.

# Bitstream Packing (Zone A6) — Gap Inventory

**Date:** 2026-05-26
**Audit zone:** A6 — Bitstream packing (`vp9_pack_bitstream` + everything it calls)
**Scope (libvpx):** `third_party/libvpx/vp9/encoder/vp9_bitstream.c` (1451 LOC) + the encoder-side helpers it calls in `vp9_encodemv.c`, `vp9_subexp.c`, `vp9_segmentation.c` and `vp9_pred_common.h`.
**Scope (rvp9):** `crates/rvp9-core/src/bitstream/{modes_writer.rs (8080), compressed_header.rs (2416), header.rs (2012), sub_parsers.rs (1057), superframe.rs (548), tile.rs (347), raw.rs (398), {inter,intra}_coef_source.rs}`, `crates/rvp9-core/src/inter/{mode_info.rs, mv.rs}`, `crates/rvp9-core/src/entropy/{detokenize.rs (3547), prob_diff_writer.rs (317), diff_update.rs (259), adapt.rs (1416), mv_probs.rs (270), frame_context.rs (163)}`, plus the encoder callers `crates/rvp9-encoder/src/{lib.rs, frame_loop.rs}`.

**Method:** Line-by-line comparison of `vp9_bitstream.c` against the rvp9 writer surface. Every PORTED row was cross-checked: search-grep for the function name AND the encoder caller (`build_keyframe_packet` / `build_inter_packet_with_residuals` in `frame_loop.rs`, plus `lib.rs:452 / :604 / :770 / :5896`), then chase the call stack down to confirm the writer is actually invoked on the encoder hot path. Every NOT PORTED / PARTIAL row was cross-checked with two greps (function name + a body-token). Anti-G3 protocol: token names matching across decoder/encoder were qualified by the call site (e.g. `read_mv_component` exists; the encoder hot path uses `write_mv_component`).

**Row-count sanity:** picker baseline = 45 rows for 2820 LOC; this subsystem's libvpx side is ~1451 LOC ⇒ scale factor ≈ 0.51 ⇒ expected band ≈ 12–35. Reporting 52 rows because the writer's surface naturally fans out — every libvpx static helper (`write_skip`, `write_segment_id`, `update_skip_probs`, `pack_mb_tokens`, etc.) is its own row. The libvpx LOC under-counts because helpers in `vp9_encodemv.c`, `vp9_subexp.c`, `vp9_segmentation.c::vp9_choose_segmap_coding_method` are pulled in by `vp9_bitstream.c`. Including them, effective LOC is ~2200 and the expected band shifts to ~20–55.

## Section-by-section Narrative

### 1. Top-level driver (`vp9_pack_bitstream`)

libvpx orchestrates: write uncompressed header into a `vpx_write_bit_buffer`, reserve 16 bits for `first_partition_size`, write compressed header, write tiles, then patch the 16-bit size in place (vp9_bitstream.c:1396-1451). rvp9's `build_keyframe_packet` (frame_loop.rs:1536) and `build_inter_packet_with_residuals` (frame_loop.rs:1688) reimplement this skeleton — they call `write_compressed_header` → tile writer → `write_uncompressed_header` with the already-computed `compressed_len` and concatenate. The wire shape is the same; the `saved_wb` patch-up is sidestepped because the compressed size is known before the uncompressed header is emitted. **PARTIAL** — there is no unified `pack_bitstream` entry point; instead three separate copy-pasted assemblies live in `lib.rs:452, 604, 770, 5896` (intra-only keyframe, regular keyframe, inter, test). Show-existing-frame is wired (header.rs:612 emits the slot bit and returns).

### 2. Uncompressed header writer

`write_uncompressed_header` (header.rs:594) emits the libvpx wire form for profile, show_existing_frame, frame_type, sync code, bit-depth/colorspace, frame size, refresh mask, ref-frame indices, allow_hp, interp filter, refresh_frame_context, frame_parallel_decoding_mode, frame_context_idx, loopfilter, quantization, segmentation, tile info, and the trailing 16-bit `first_partition_size`. **PARTIAL** because the inter-frame path emits "fresh frame size" (three `0` inheritance bits + literal w/h, header.rs:692-697) every time — it never sets one of the three inheritance bits to inherit from a referenced frame even when the dimensions match. libvpx's `write_frame_size_with_refs` (vp9_bitstream.c:1166-1198) walks LAST/GOLDEN/ALTREF in order and emits the first match as a `1` bit. Also the `cm->error_resilient` branch is supported but never exercised by callers; SVC special-cases (svc.layer_context, temporal_layers, spatial-key-frame) are not ported.

### 3. Compressed header writer

`write_compressed_header` (compressed_header.rs:987) follows the libvpx walk order: tx_mode, optionally `write_tx_mode_probs`, `write_coef_probs` gated per TX size, `write_skip_probs`, and for non-intra-only frames the inter-mode / switchable / intra_inter / reference_mode / single+comp_ref / y_mode / partition / nmv prob diff-updates. The walk is bit-for-bit faithful to `write_compressed_header` (vp9_bitstream.c:1316-1394). **PARTIAL** because:

- `write_coef_probs_common` (compressed_header.rs:703) uses a "force update on any diff" policy. libvpx's `update_coef_probs_common` (vp9_bitstream.c:545-680) runs a per-slot cost-benefit search via `vp9_prob_diff_update_savings_search{,_model}` and emits the per-TX-size gate bit only when `savings >= 0`. Without this, rvp9 spends bits emitting probability deltas that don't save coding bits (and skips bits emitting probability deltas where libvpx's heuristic decided the cost outweighed the savings). For uniformly-near-default frames the bytes match closely; for adapted frames with many small drifts they diverge significantly.
- The two `cpi->sf.use_fast_coef_updates` modes (TWO_LOOP and ONE_LOOP_REDUCED) are both absent. libvpx uses TWO_LOOP for cpu-used 0..=5 and ONE_LOOP_REDUCED for the RT path (cpu-used 6..=8). The "first-update prefix" sequence in ONE_LOOP_REDUCED (writes a `1` bit at the first update slot followed by `noupdates_before_first` 0-bits at `upd`, then continues normally) is a wire-format optimisation rvp9 doesn't perform.
- The `update_coef_probs` driver gate `cpi->td.counts->tx.tx_totals[tx_size] <= 20` (vp9_bitstream.c:690) is not ported — rvp9 always tries to update every reachable TX size.
- `cpi->sf.tx_size_search_method == USE_TX_8X8` skip-large-tx gate is not ported.
- `xd->lossless` gate that forces `tx_mode = ONLY_4X4` is enforced by the caller (debug_assert in compressed_header.rs:999-1002) rather than by the writer itself.

### 4. Per-tile mode emission

`write_modes` (vp9_bitstream.c:490) walks an SB-row scan, resets `xd->left_seg_context` per row (line 508 — `vp9_zero(left_seg_context)`), and calls `write_modes_sb` per SB column.

rvp9's `write_tile_inter` (modes_writer.rs:1474) / `write_tile_intra_keyframe` (modes_writer.rs:530) do an SB-row walk and reset the `PartitionCtx::left` array per row + reset the left coef context (`coef_ctx.reset_left_coef`, modes_writer.rs:569 / 1519). **PARTIAL** for one missing reset: libvpx's `vp9_zero(xd->left_seg_context)` (line 508) — rvp9 has no `left_seg_context` array because the segment-id writer ignores the per-row segment context (it always emits a fresh tree decode). When segment ID prediction across a tile row is added, this row-reset will need to land. Also the `tok` / `tok_end` per-SB-row threading via `cpi->tplist` is replaced by a per-leaf `coef_source` callback — the encoder stages coefficients in `IntraCoefSource` / `InterCoefSource` traits rather than libvpx's pre-computed `TOKENEXTRA` array.

`write_modes_sb` (vp9_bitstream.c:427) drives partition recursion. The PORTED mirror is `write_partition_tree` (modes_writer.rs:826) for keyframes and `write_inter_partition_tree` (modes_writer.rs:1561) for inter frames. Both faithfully replicate the partition recursion, the per-bsl `partition_plane_context` lookup, the SPLIT 4-way recursion order, and the post-recurse partition-context update (`bsize >= BLOCK_8X8 && (bsize == BLOCK_8X8 || partition != SPLIT)`).

`write_partition` (modes_writer.rs:776) implements the partition-tree walk for the `has_rows && has_cols` case (NONE → `0`, HORZ → `1,0`, VERT → `1,1,0`, SPLIT → `1,1,1`). **PARTIAL** — the frame-edge `!has_rows` / `!has_cols` / `!has_rows && !has_cols` branches at vp9_bitstream.c:416-424 are not implemented (rvp9 rejects non-multiple-of-64 frame dims at the writer entry via `ModesWriterError::NonMultipleOfSb`). When non-multiple-of-64 frames are accepted, these branches must land.

`write_modes_b` (vp9_bitstream.c:377) dispatches to `write_mb_modes_kf` or `pack_inter_mode_mvs` per leaf, then calls `pack_mb_tokens`. The rvp9 mirrors are `write_block_intra_keyframe` (modes_writer.rs:1014) and `write_inter_block_leaf` (modes_writer.rs:1780); coef-token emission is inlined as `write_intra_block_residual` / `write_inter_block_residual`. **PARTIAL** because the libvpx call assert `*tok < tok_end` (line 401) has no analogue — instead rvp9 relies on `IntraCoefSource::get_block_coefs` / `InterCoefSource::get_block_coefs` returning a slice with a debug-asserted length.

### 5. Keyframe per-block (`write_mb_modes_kf`)

libvpx emits: `write_segment_id` (gated by `seg->update_map`), `write_skip`, `write_selected_tx_size` (gated by `bsize >= BLOCK_8X8 && tx_mode == TX_MODE_SELECT`), `write_intra_mode` for Y (parent or per-4×4-sub for sub-8) against `get_y_mode_probs(mi, above_mi, left_mi, block)`, and `write_intra_mode` for UV. **PARTIAL** in rvp9 because:

- `get_y_mode_probs` is implemented inline (modes_writer.rs:1079 walks `VP9_KF_Y_MODE_PROB[above_mode][left_mode]` from the `NeighbourCtx`) — but BLOCK < BLOCK_8X8 (sub-8 keyframe leaves with per-4×4 Y mode) is rejected by the writer scope. libvpx's loop at vp9_bitstream.c:281-291 emits a separate `write_intra_mode` per 4×4 sub-block against `cm->fc->y_mode_prob[0]`. Sub-8 keyframe intra is therefore NOT PORTED (the writer's scope `infer_partition` pins BLOCK_8X8 to `PARTITION_NONE`, modes_writer.rs:652-659).

### 6. Inter per-block (`pack_inter_mode_mvs`)

libvpx walks: `write_segment_id` (incl. temporal-update branch with `seg_id_predicted` and `vp9_get_pred_prob_seg_id`), `write_skip`, intra_inter bit (gated by `!segfeature_active(seg, segment_id, SEG_LVL_REF_FRAME)`), `write_selected_tx_size` (gated by `!(is_inter && skip)`), then either the intra-in-inter Y/UV mode walk OR the inter mode + ref frames + switchable interp + MV emission. For NEWMV, `vp9_encode_mv` is called once per active ref against the best ref MV.

rvp9's `write_inter_block_leaf` (modes_writer.rs:1780) + `write_inter_block_mode_info` (inter/mode_info.rs:987) implement this faithfully for the no-segmentation / segmentation-with-cyclic-refresh case. **PARTIAL** because:

- The `segfeature_active(seg, segment_id, SEG_LVL_REF_FRAME)` gate (vp9_bitstream.c:270) is not applied — rvp9 always writes the `is_inter` bit even when the segment forces the ref frame. AQ.3 cyclic refresh doesn't set SEG_LVL_REF_FRAME so this is latent today.
- The `segfeature_active(seg, segment_id, SEG_LVL_SKIP)` gate around `write_inter_mode` (vp9_bitstream.c:299) is also not applied. With SEG_LVL_SKIP set on a segment, libvpx skips emitting the mode bit entirely (mode is forced to ZEROMV). rvp9 always writes the mode tree walk regardless.
- The temporal-update branch (vp9_bitstream.c:257-265): rvp9 rejects `mi.seg_id_predicted = true` (modes_writer.rs:1810). Temporal-update segmentation (the `seg.temporal_update == true` path) requires this branch and `seg.pred_probs` lookups.
- `interp_filter_selected[0][mi->interp_filter]++` (line 310) is the per-tile interp filter usage counter that `fix_interp_filter` reads to decide whether to collapse Switchable → a single literal. Not ported.

### 7. MV emission

`vp9_encode_mv` and `encode_mv_component` (vp9_encodemv.c:159-242) are PORTED bit-for-bit as `write_mv` / `write_mv_component` (inter/mv.rs:652, 525). The joint tree, class tree, class0 vs general bits split, fractional-pel tree, and HP bit are all present. `use_mv_hp` gates HP emission per the libvpx behaviour. `vp9_write_nmv_probs` (compressed header) is PORTED as `write_mv_probs` (compressed_header.rs:911). The `MV_UPDATE_PROB`-gated wire format with the 7-bit-literal-forced-odd payload is implemented at `write_update_mv_probs` (compressed_header.rs:893).

The `max_mv_magnitude` per-tile bookkeeping (vp9_bitstream.c:241-244, 1017, 1061) — libvpx tracks the largest emitted MV magnitude so it can short-circuit later rate model lookups — is **NOT PORTED**.

### 8. Coef-token emission (`pack_mb_tokens`)

libvpx walks the per-block `TOKENEXTRA` array, emitting EOB/ZERO_TOKEN/CATEGORY1-6 tokens against `context_tree`, with the `vp9_pareto8_full[ctx-1]` table feeding the high-magnitude `vp9_coef_con_tree` walk and the `extra_bits` LUT supplying the trailing magnitude bits.

rvp9's `pack_mb_tokens` analogue is `write_block_tokens` (entropy/detokenize.rs:1324) and `encode_coefs` it dispatches to. **PARTIAL** because:

- `vp9_extra_bits_high10` / `high12` (vp9_bitstream.c:137-140) — the HBD extra-bits LUT — is NOT PORTED. The encoder is hard-wired to 8-bit `extra_bits`.
- The `ZERO_TOKEN` run-length compaction loop (vp9_bitstream.c:152-158) is encoded one-by-one rather than run-length packed; the resulting wire form is identical because every ZERO_TOKEN emits a single bit at `context_tree[1]`, but the encoder pays redundant context updates per zero. Functional parity, perf delta only.

### 9. Coef-prob updates (`update_coef_probs`)

The largest gap in the audit. libvpx's `update_coef_probs` (vp9_bitstream.c:683) gates per TX size:

```
if (cpi->td.counts->tx.tx_totals[tx_size] <= 20 ||
    (tx_size >= TX_16X16 && cpi->sf.tx_size_search_method == USE_TX_8X8)) {
  vpx_write_bit(w, 0);  // no update for this TX size
} else {
  build_tree_distribution(...);
  update_coef_probs_common(...);  // TWO_LOOP or ONE_LOOP_REDUCED
}
```

`build_tree_distribution` (vp9_bitstream.c:518-543) folds `cpi->td.rd_counts.coef_counts[tx][plane][ref]` plus `cpi->common.counts.eob_branch[tx][plane][ref]` into `(coef_branch_ct, coef_probs)` per (plane × ref × band × ctx × node) using `vp9_tree_probs_from_distribution`. The `coef_branch_ct[..][0][1] = eob_branch_ct - coef_branch_ct[..][0][0]` line (line 533) is the key piece that derives the actual EOB branch count for the savings search.

`update_coef_probs_common` (vp9_bitstream.c:545-680) is split:

- **TWO_LOOP** (cpu-used 0..=5): a dry-run pass accumulates `savings` and emits a per-TX gate bit; only then does the second pass emit the per-slot gate-and-payload sequence.
- **ONE_LOOP_REDUCED** (cpu-used 6..=8, RT path): a single pass with a "first-update prefix" — the first update slot writes a `1` bit followed by `noupdates_before_first` 0-bits at `upd` (this is the RT-optimised wire format).

Both paths rely on `vp9_prob_diff_update_savings_search{,_model}` (in `vp9_subexp.c`) to decide whether updating a slot saves enough bits to justify the gate-bit cost.

**NOT PORTED** end-to-end. The compressed-header writer instead force-updates every slot (`write_coef_probs_common`, compressed_header.rs:703) regardless of savings. This produces a wire form that decodes correctly but is suboptimal: it spends gate bits on every slot that differs and pays the term-subexp cost even when the savings are tiny. The encoder also has no way to selectively skip per-TX-size updates based on `tx_totals` — every TX size up to `tx_mode_to_biggest_tx_size(tx_mode)` is unconditionally walked.

Tracking ledger for this row: `coef_counts` accumulation does happen in rvp9 (entropy/detokenize.rs's `encode_coefs` accepts `Option<&mut CoefCountsBank>` and the inter writer threads it through, modes_writer.rs:2278). The infrastructure exists; the savings-search policy is what's absent.

### 10. Loopfilter / quantization / segmentation headers

- `encode_loopfilter` (vp9_bitstream.c:701-739) emits `filter_level`, `sharpness_level`, `mode_ref_delta_enabled`, optionally per-ref / per-mode delta `changed` bits. The encoder tracks `last_ref_deltas` / `last_mode_deltas` to compute the `changed = delta != last_delta` bit (vp9_bitstream.c:717-735). rvp9's `write_loopfilter` (sub_parsers.rs:135) emits the same wire form via `Option<i8>` semantics — `Some(_)` ⇒ `changed = 1` + value, `None` ⇒ `changed = 0`. **PARTIAL** because the encoder has no `last_*_deltas` state machine; it just emits whatever the caller put in the params.

- `encode_quantization` (vp9_bitstream.c:751-757) is PORTED bit-for-bit as `write_quantization` (sub_parsers.rs:239) with the matching `write_delta_q` helper.

- `encode_segmentation` (vp9_bitstream.c:759-816) is PARTIAL. The wire walk (enabled bit, update_map → tree_probs MAX_PROB sentinel, temporal_update → pred_probs sentinel, update_data → abs_delta + per-feature signed/unsigned data) is fully ported as `write_segmentation` (sub_parsers.rs:423). What's missing:

  - `vp9_choose_segmap_coding_method(cm, xd)` (vp9_segmentation.c, called at vp9_bitstream.c:772) decides between spatial (`temporal_update = false`) and temporal (`temporal_update = true`) segment-id coding. The choice depends on per-block segment-id prediction-flag cost vs raw tree-decode cost. **NOT PORTED** — rvp9's `build_segmentation_params` (frame_loop.rs:1954) hardcodes `temporal_update = false` regardless of content.
  - `tree_probs` are emitted at `MAX_PROB` (modes_writer.rs:1791-1795 + frame_loop.rs:1962) — no per-frame training. libvpx also defaults to MAX_PROB on update but allows the encoder to train them; rvp9 doesn't expose a path to override.

- `encode_txfm_probs` (vp9_bitstream.c:818-852) is PARTIAL. The wire walk for tx_mode + tx_probs is at compressed_header.rs:617-655 (`write_tx_mode` + `write_tx_mode_probs`). The libvpx path that goes through `tx_counts_to_branch_counts_{8,16,32}x32` to convert per-context counts into branch counts before `vp9_cond_prob_diff_update` is not present — rvp9 emits prob diffs directly from `pre` / `post` `DefaultTxProbs` slots. Since rvp9 forces `tx_mode = AllowTx32x32` everywhere (frame_loop.rs:1559 + 1747), the `TX_MODE_SELECT` path is never exercised, so this is latent.

### 11. Tile assembly (`encode_tiles`)

libvpx has two paths:

- `encode_tiles_mt` (vp9_bitstream.c:991-1090) — RT-mode parallel tile encoding using `VPxWorker` workers, with per-worker scratch buffers allocated by `encode_tiles_buffer_alloc`.
- `encode_tiles` (vp9_bitstream.c:1092-1145) — serial driver. For each tile in row-major order, writes the 4-byte BE size prefix (except last tile) followed by the tile's bool-coded payload.

rvp9 has a single-tile assumption everywhere. `frame_loop.rs:1635` hardcodes `log2_tile_cols = 0, log2_tile_rows = 0`. `write_tile_buffers` (tile.rs:140) **does** implement the multi-tile size-prefix wire format and is exercised by tests, but no encoder caller produces multi-tile payloads. The MT worker dispatch, per-worker buffer pool, and `cpi->max_mv_magnitude` / `interp_filter_selected` aggregation across workers are NOT PORTED. The `above_seg_context` memset (vp9_bitstream.c:1101-1102) is also NOT PORTED — the encoder never reads back any per-row segment-id-prediction context. **PARTIAL** at the encoder caller layer; PORTED at the byte-format layer.

### 12. Reference-frame management (`vp9_get_refresh_mask`)

libvpx's `vp9_get_refresh_mask` (vp9_bitstream.c:902-940) computes the 8-bit `refresh_frame_flags` slot mask. It handles three sub-cases: `vp9_preserve_existing_gf` (preserve the existing golden frame as ARF — swap gld_fb_idx and alt_fb_idx outside the recode loop); `multi_layer_arf` (walk `gf_group->arf_index_stack` to find an unused slot); SVC `use_set_ref_frame_config` (consume the SVC layer's pre-set update mask). **NOT PORTED** — rvp9 hardcodes the mask via `refresh_frame_flags` in the `WireFrameKind::InterFrame` literal (frame_loop.rs:1896, lib.rs:865-866). The multi-layer-ARF case is irrelevant at single-pass CBR but is in scope for the full vpxenc port (it activates under 2-pass + multi-ARF GOPs).

### 13. Backward adaptation + `refresh_frame_context`

libvpx's encoder calls `vp9_adapt_{mode,mv,coef}_probs` after each frame and sets `refresh_frame_context = true` so the decoder runs the same adapt path on its bank. The adapt functions exist in rvp9 (`adapt_coef_probs`, `adapt_mode_probs`, `adapt_mv_probs` in entropy/adapt.rs:582, 678, 807) and the encoder DOES call them at frame_loop.rs:1128-1138. But the encoder force-emits `refresh_frame_context: false` in the uncompressed header (frame_loop.rs:1604, 1857). The compromise is documented in the source: the encoder adapts internally and diff-encodes its adapted FC against the decoder's default FC in the compressed header, so the decoder lands on the same FC without running the adapt path. **PARTIAL** — wire form differs from libvpx (libvpx emits `refresh_frame_context: true` + an empty diff sequence; rvp9 emits `refresh_frame_context: false` + a full diff sequence). Decode-equivalent but ~tens-of-bytes-per-frame more compressed-header overhead.

### 14. HBD bitstream (Profiles 2 / 3)

Profile 2 / 3 bit-depth (10 / 12) bit emission in `write_bitdepth_colorspace_sampling` is PORTED for the header bit (header.rs:771 emits `bit_depth == Twelve`). But the HBD `pack_mb_tokens` `extra_bits` selection (vp9_bitstream.c:137-140 picks `vp9_extra_bits_high12` / `_high10` based on `cm->bit_depth`) is **NOT PORTED**. The 10/12-bit coef-magnitude extra-bits LUT differs from 8-bit's, so emitting HBD blocks with the 8-bit LUT produces a stream the decoder reads incorrectly. The encoder is hard-wired to 8-bit profiles today (lib.rs and frame_loop.rs pin `bit_depth: BitDepth::Eight`).

### 15. Cross-cutting / wire-format helpers

- `vp9_diff_update_prob` (decoder) / `cond_prob_diff_update` (encoder) — the per-prob-slot wire format gate + term-subexp payload is fully PORTED in `cond_prob_diff_update` (prob_diff_writer.rs:166) + `write_prob_diff_update` (prob_diff_writer.rs:149) + `encode_term_subexp` (prob_diff_writer.rs:120). The MAP_TABLE / INV_MAP_TABLE pair is sourced verbatim from libvpx. **PARTIAL** because libvpx's `vp9_cond_prob_diff_update` runs a cost-benefit decision against per-symbol counts (which determines whether to emit the gate bit as 1 with payload vs 0 with no payload) — rvp9 force-updates whenever `newp != *oldp`. Effect: rvp9 emits the gate bit + term-subexp payload for every probability change including tiny ones libvpx would skip.

- `RawBitWriter` (raw.rs:398 LOC) is the MSB-first byte-level writer used for the uncompressed header. PORTED bit-for-bit against `vpx_dsp/bitwriter_buffer.{h,c}`.

- `BoolWriter` (entropy/mod.rs) is the boolean coder used for the compressed header + tile payloads. PORTED.

- Superframe index writer (`SuperframeBuilder` in superframe.rs, plus `MAX_SUPERFRAME_FRAMES`) — exists. Used to bundle altref-show=0 + show frames into one packet. libvpx's `vp9_pack_bitstream` does NOT include the superframe wrapping (that's left to the caller of `vpx_codec_encode`); rvp9's encoder caller chain (`Encoder::encode_inter_internal`) also leaves superframe assembly to the caller. PORTED, in scope.

## Cross-Cutting Gaps

### Single-tile-only scope baked into the writer

**Status: PARTIAL (functional for 1-tile only)**

`write_inter_block_residual` (modes_writer.rs:2180) and `write_intra_block_residual` (modes_writer.rs:1159) both hardcode `mi_col_in_tile = mi_col` rather than `mi_col - tile_bounds.mi_col_start`. The comments on those lines (`// single-tile scope (see fn doc)`) document the assumption. `TileCoefCtx` is sized per-tile but the writer indexes into it with frame-absolute coordinates. For multi-tile output the second-and-beyond tiles would read wrong `above_coef` / `left_coef` cells, the `initial_pt` for the first token would mismatch the decoder's, and the bool coder would desync.

Encoder callers reinforce this: every site sets `log2_tile_cols = 0, log2_tile_rows = 0` (frame_loop.rs:1635, 1882; lib.rs:516, 673, 857, 5966). Multi-tile output is not exercised by any current encoder caller.

**LOC to fix:** ~10 LOC at each of the two residual writers; medium impact, prerequisite for `encode_tiles_mt` (low priority but in scope).

### `pre_fc` rebuilt from defaults every frame (no FC carry-over)

**Status: PARTIAL**

Every packet builder rebuilds `pre_fc` from `FrameContext::new_default()` or maintains a tracked `decoder_fc` mirror (frame_loop.rs:340-380 docs the persistence). On keyframes the writer force-emits `refresh_frame_context: false`, meaning the decoder's FC bank 0 stays at default. Subsequent inter frames diff-encode the encoder's adapted FC against `decoder_fc` (frame_loop.rs:1754). This works end-to-end but the wire form differs from libvpx's: libvpx emits `refresh_frame_context: true` and lets the decoder re-run adapt, producing a smaller compressed header.

**LOC to fix:** ~30 LOC to flip the writer to emit `refresh_frame_context: true` and stop diff-encoding when the encoder's `post_fc` equals `adapt_*_probs(pre_fc, frame_counts)`. Requires count accumulation to be 100% faithful (today's writer threads counts through inter-block code but coef counts for the keyframe path are not accumulated, modes_writer.rs:1252 explicitly passes `None`).

### Encoder-side per-tile aggregation state absent

**Status: NOT PORTED**

`cpi->max_mv_magnitude` (encoder-tracked largest absolute MV emitted, used by the rate model to scale later MV-cost lookups) and `cpi->interp_filter_selected[0][SWITCHABLE_FILTERS]` (used by `fix_interp_filter` at vp9_bitstream.c:863-884 to detect "only one filter is used" and collapse `cm->interp_filter` to that fixed filter before emitting the frame header bits) are both NOT PORTED. `fix_interp_filter` decision-makes the frame-level `interp_filter` field. Without it, rvp9 always emits `Switchable` even when every block in the frame picked the same filter — paying 1 bit per block for switchable_interp probability + 1 bit for the frame-level Switchable flag instead of a 3-bit literal frame filter and 0 bits per block.

**LOC to fix:** ~20 LOC; low-medium quality impact on uniform-filter content (large fraction of cpu-used 6+ output once `cb_pred_filter_search` chessboard is added).

### Cost-benefit-aware prob-diff-update policy

**Status: NOT PORTED**

`cond_prob_diff_update` (prob_diff_writer.rs:166) emits the gate + payload whenever `newp != *oldp`. libvpx's `vp9_cond_prob_diff_update` (`vp9_subexp.c:182-196`) runs `vp9_prob_diff_update_savings_search` (which evaluates `cost(*oldp, count_0, count_1) - cost(newp, count_0, count_1) - cost_one(DIFF_UPDATE_PROB)`) and only emits the update when savings ≥ 0. Three call paths consume this: `update_coef_probs_common` (most bits), `prob_diff_update` (mode/partition/y-mode tables), and the standalone `vp9_cond_prob_diff_update` call sites in `write_compressed_header` (intra_inter, comp_inter, single_ref, comp_ref, skip).

**LOC to fix:** ~80 LOC for the savings-search helpers; medium impact on compressed-header bit budget (savings around 5-50 bytes per frame on adapted content).

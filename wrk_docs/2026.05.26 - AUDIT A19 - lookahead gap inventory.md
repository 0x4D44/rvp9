## Section-by-section narrative

### 1. Data structures and constants

#### `MAX_LAG_BUFFERS` (= 25)
libvpx ceiling on user-requested lag depth. Used both as the clamp in `vp9_lookahead_init` and as the array bound for `rc->avg_source_sad[]`, `mbgraph_stats[]`, `gf_group.arf_index_stack[]`. **Status:** NOT PORTED. `vp9_lookahead.h:22`.

#### `MAX_PRE_FRAMES` (= 1)
The number of *past* frames kept in the queue after pop, so consumers can `peek(-1)` for the prior source frame. libvpx adds it to the user-requested depth in `init` (`depth += MAX_PRE_FRAMES`) and subtracts it again in `pop`'s ready-condition (`sz == max_sz - MAX_PRE_FRAMES`). **Status:** NOT PORTED. `vp9_lookahead.h:33`.

#### `struct lookahead_entry`
Holds `YV12_BUFFER_CONFIG img`, `int64_t ts_start/ts_end`, `int show_idx`, `vpx_enc_frame_flags_t flags`. **Status:** NOT PORTED. `vp9_lookahead.h:24-30`. rvp9's `encode_frame` takes a `&YuvFrameRef` directly (`frame_loop.rs:530`) — no per-frame metadata struct exists.

#### `struct lookahead_ctx`
Ring buffer: `max_sz`, `sz`, `read_idx`, `write_idx`, `next_show_idx`, `*buf`. **Status:** NOT PORTED. `vp9_lookahead.h:35-43`.

### 2. Init / destroy

#### `vp9_lookahead_init`
Clamps depth to `[1, MAX_LAG_BUFFERS]`, adds `MAX_PRE_FRAMES`, allocates the ctx + N per-frame `YV12_BUFFER_CONFIG`s with encode-border padding (`VP9_ENC_BORDER_IN_PIXELS`). **Status:** NOT PORTED. `vp9_lookahead.c:44-82`. Called from `alloc_raw_frame_buffers` (`vp9_encoder.c:1287`) and `update_initial_width` (`vp9_encoder.c:2371`).

#### `vp9_lookahead_destroy`
Per-entry `vpx_free_frame_buffer` then `free(ctx)`. **Status:** NOT PORTED. `vp9_lookahead.c:32-42`.

### 3. Producer side

#### `vp9_lookahead_push`
- Rejects if `vp9_lookahead_full`.
- Bumps `sz` and advances `write_idx` via the static `pop` helper.
- Reallocates the destination buffer when the new source has larger dimensions; otherwise just rewrites `*_crop_*` fields on dimension change.
- Calls `vp9_copy_and_extend_frame` to copy + extend the border.
- Records `ts_start`, `ts_end`, `flags`, `show_idx = next_show_idx++`.
- The active-map partial-copy path is `#if USE_PARTIAL_COPY` and `USE_PARTIAL_COPY` is `#define`d to `0` (vp9_lookahead.c:84) so it is compiled out. **Status:** OUT OF SCOPE for row 13 (the path is disabled in libvpx itself).

**Status:** NOT PORTED. `vp9_lookahead.c:93-199`. Called from `vp9_receive_raw_frame` at `vp9_encoder.c:5977`.

#### `vp9_lookahead_full`
`sz + 1 + MAX_PRE_FRAMES > max_sz`. **Status:** NOT PORTED. `vp9_lookahead.c:85-87`.

#### `vp9_lookahead_next_show_idx`
Returns the show_idx that the next push will stamp. Used by tooling to map decoded frame number → source frame number. **Status:** NOT PORTED. `vp9_lookahead.c:89-91`.

### 4. Consumer side

#### `vp9_lookahead_pop`
Returns the head entry and decrements `sz` either when `drain` is set (flush) or when the queue has reached `max_sz - MAX_PRE_FRAMES` (steady-state depth). **Status:** NOT PORTED. `vp9_lookahead.c:201-210`.

#### `vp9_lookahead_peek`
Forward peek (`index >= 0`, must be < `sz`) or backward peek (`-MAX_PRE_FRAMES <= index < 0`, the just-popped slot). Backward peek is what lets the encoder access `last_source` after the current frame has been popped (vp9_encoder.c:6479). **Status:** NOT PORTED. `vp9_lookahead.c:212-233`.

#### `vp9_lookahead_depth`
Returns `sz`. **Status:** NOT PORTED. `vp9_lookahead.c:235`.

### 5. ALTREF source-index selection (consumers in `vp9_encoder.c`)

#### `get_arf_src_index`
The ALTREF picker. In pass 2, reads `gf_group.arf_src_offset[gf_group.index]` when the current update type is `ARF_UPDATE`. In pass 1 / one-pass-VBR, returns `rc->frames_till_gf_update_due` while `source_alt_ref_pending` is set. **Status:** NOT PORTED. `vp9_encoder.c:6049-6063`. Cross-zone: requires A3 (rate-control twopass `GF_GROUP` populated) and A16 (ALTREF construction).

#### `is_altref_enabled`
Returns true when mode ≠ `(REALTIME && CBR)`, `lag_in_frames >= MIN_LOOKAHEAD_FOR_ARFS (= 4)`, and `enable_auto_arf` is set. **Status:** NOT PORTED. `vp9_encoder.h:1422-1427`.

#### Forced-keyframe collision sweep
Before locking in `arf_src_index`, peeks every frame in `[0..=arf_src_index]` and aborts the ARF if any carries `VPX_EFLAG_FORCE_KF`. **Status:** NOT PORTED. `vp9_encoder.c:6410-6424`.

#### `cpi->alt_ref_source = vp9_lookahead_peek(arf_src_index)`
Captures the future source frame, runs `vp9_temporal_filter` into `cpi->alt_ref_buffer` (when not REALTIME), sets `refresh_alt_ref_frame=1`, `show_frame=0`, etc. **Status:** NOT PORTED. `vp9_encoder.c:6432-6473`.

#### Backward peek for `last_source`
`vp9_lookahead_peek(ctx, -1)` provides the previous source for `unscaled_last_source`. The whole point of `MAX_PRE_FRAMES = 1`. **Status:** NOT PORTED. `vp9_encoder.c:6479`.

#### `check_src_altref`
After the pop, detects whether the popped frame *is* the ARF source (overlay) and clears `refresh_last_frame`. **Status:** NOT PORTED. `vp9_encoder.c:6065-6086`.

### 6. SVC lookahead pop

`vp9_svc_lookahead_pop` peeks the head, only actually pops when the current spatial layer is the highest, so multiple SL passes share one queue entry. **Status:** NOT PORTED. `vp9_svc_layercontext.c:996-1010`. Cross-zone with A18.

### 7. Lookahead-driven analysis modules

#### Scene-change / VBR-lag SAD scan
`vp9_ratectrl.c:2900-2970` walks `vp9_lookahead_depth() - 1` forward frames computing avg-source-sad; `:3067-3100` peeks the start-frame source images for the cross-frame SAD comparison. **Status:** NOT PORTED. Cross-zone A3.

#### Temporal filter
`vp9_temporal_filter.c:1031-1140` walks `which_buffer = lookahead_depth - distance - 1` forward and `+ distance` for the backward arm to build the ARF filter sample set. **Status:** NOT PORTED. Cross-zone A16.

#### TPL-model
`vp9_tpl_model.c:88-140` peeks `frame_gop_offset - 1` to source the propagated stats for each GOP slot. **Status:** NOT PORTED. Cross-zone with A3 (two-pass GF group).

#### mbgraph
`vp9_mbgraph.c:351-388` peeks every frame in `[0..n_frames)` to fill the `mbgraph_stats[]` MB-motion grid. **Status:** NOT PORTED. Used by ALTREF/AQ decisioning.

#### first-pass driver
`simple_encode.cc:897-906` and `:1169-1180` show the canonical use pattern: while `!vp9_lookahead_full`, push, then call `vp9_get_compressed_data(flush=1)` so first-pass consumes one frame per push. **Status:** NOT PORTED. Cross-zone A3.

#### AQ mode lookahead
`vp9_pickmode.c:1915`, `:2142`, `:2504` gate behaviours on `oxcf.lag_in_frames > 0 && rc_mode == VPX_VBR`. **Status:** NOT PORTED. Cross-zone A11.

## Cross-cutting gaps

### CC-1. rvp9's `encode_frame` API has no producer/consumer split
`crates/rvp9-encoder/src/frame_loop.rs:530` accepts one source frame and immediately emits one packet. There is no `receive_raw_frame` / `get_compressed_data` split as in libvpx (`vp9_encoder.c:5977` push, `:6362` consume). Adding lag-in-frames requires either (a) a buffered façade around `encode_frame` that delays packet emission, or (b) splitting the API. (a) is cheaper but (b) is what libvpx and `simple_encode.cc` actually do — and what 2-pass / ALTREF drivers expect.

### CC-2. No `YV12_BUFFER_CONFIG`-equivalent owned frame storage
rvp9 currently passes `&YuvFrameRef<'_>` (borrowed slices) into `encode_frame`. A queue needs *owned* storage so the caller can free their buffer before the encoder is done. Either `Vec<u8>` triplets per entry or an owned `OwnedYuvFrame`. The libvpx side uses `vpx_alloc_frame_buffer` per entry with `VP9_ENC_BORDER_IN_PIXELS` of border (vp9_lookahead.c:70-75).

### CC-3. Lookahead is a *prerequisite* for in-scope features
The GOAL document lists IN-SCOPE: 2-pass VBR + lag-in-frames, ALTREF (filtered), temporal denoiser, AQ-lookahead, SVC. Every one of these consumes the queue (rows 22, 25, 29, 30, 31, 32, 34 above). A19 unblocks A3 (2-pass / VBR), A11 (AQ-lookahead), A16 (ALTREF + temporal filter), A18 (SVC), A21 (ML partition, which depends on TPL stats). **The audit zone is therefore a *gate* on the wave-sequencing of A3 / A11 / A16 / A18 / A21.**

### CC-4. `MIN_LOOKAHEAD_FOR_ARFS = 4` is the natural enablement boundary
libvpx (vp9_encoder.h:1422) only enables ALTREF when `lag_in_frames >= 4`. A faithful port can be built and tested in two stages: stage A — queue infrastructure + producer/consumer split at `lag_in_frames = 0` (no behaviour change); stage B — flip the gate at `lag_in_frames >= 4`. This is the path of least risk.

### CC-5. `next_show_idx` / `show_idx` numbering must survive into the bitstream pipeline for diagnostics parity
libvpx stamps each entry with a monotonically-increasing `show_idx` (vp9_lookahead.c:196-197) that is propagated through `ENCODE_FRAME_RESULT::show_idx` (`vp9_encoder.c:6352`-init). The F.0.2 oracle and various diagnostic dumps depend on this matching libvpx's numbering. rvp9 currently increments `self.frame_idx` (`frame_loop.rs:537`) per call to `encode_frame`, which conflates "frame received from caller" with "frame shown" — once ALTREF lands, these diverge (an ARF source is *received* before the overlay it sits behind is *shown*).

### CC-6. `MAX_LAG_BUFFERS = 25` propagates as an array bound elsewhere
The 25-frame ceiling is hard-coded into `rc->avg_source_sad[MAX_LAG_BUFFERS]` (`vp9_ratectrl.h:178`), `mbgraph_stats[MAX_LAG_BUFFERS]` (`vp9_encoder.h:831`), `arf_index_stack[MAX_LAG_BUFFERS * 2]` (`vp9_firstpass.h:93`), `frames[MAX_LAG_BUFFERS]` (`vp9_encoder.h:500`). Port must adopt the same constant or these structures will under-allocate.

## Conclusion

**Gap counts:** PORTED 0 / PARTIAL 0 / NOT PORTED 33 / OUT OF SCOPE 1 (total 34 rows).

**Row-count sanity check:** Expected band 0.5× – 1.5× of `45 × (363 / 2820) ≈ 5.8` for the lookahead module proper, which would be 3–9 rows. The 34 rows here exceed that band because the audit zone explicitly includes the *consumers* of the queue (`get_arf_src_index`, scene-change SAD scan, temporal filter, TPL, mbgraph, SVC pop wrapper, AQ gates), which are where the porting work actually lives — the queue itself is small (~363 LOC) but it gates ~500+ LOC of analytical wiring scattered across `vp9_encoder.c`, `vp9_ratectrl.c`, `vp9_temporal_filter.c`, `vp9_tpl_model.c`, `vp9_mbgraph.c`, `vp9_svc_layercontext.c`, `vp9_pickmode.c`. Deviation justified.

**Cross-zone dependencies flagged for the master inventory:**
- A19 → A3: scene-change SAD scan (Row 29), 2-pass twopass-`GF_GROUP` consumers (Row 22), first-pass driver pattern (Row 33).
- A19 → A11: AQ-lookahead pickmode gates (Row 34).
- A19 → A16: ARF source selection (Rows 22-25, 27), temporal-filter peek loop (Row 30).

- A19 → A18: SVC pop wrapper (Row 28).

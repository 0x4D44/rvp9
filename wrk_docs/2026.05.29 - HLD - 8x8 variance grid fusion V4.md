## 1. The decision

### 1.1 Three options on this hot path — ranked

`compute_variance_8x8` feeds an RD *model* (a skip / TX-size heuristic) for ≥32×32
leaves. There are three ways to spend effort here, and they are not close:

| Option | What | Ceiling | Risk | Verdict |
|---|---|---|---|---|
| **(c) Phase-2** | Eliminate the 52.7 % partition double-pick | Large | Decision-changing (quality-gated) | **Do this** — the real lever |
| **(b) Quality-gated variance** | A cheaper / vectorized variance that is *not* byte-identical, bounded by the existing PSNR/SSIM oracles | Medium — can re-shape the algorithm, not just re-order ops | Low-moderate (oracle-bounded) | **Better than (a)**; revisit only if a Phase-1 variance lever is wanted |
| **(a) PR5 — this doc** | Byte-identical re-packaging of the per-cell reduction into one dispatched call | **Low** — can only re-order the same integer ops; may be ~0 | ~0 (byte-identical) | **Defer.** Smallest, expected-null |

The honest crux (was buried in V3 §3.1): byte-identity is a *self-imposed*
constraint that **caps PR5's ceiling at "re-order the same integers"**. It buys
zero-risk reviewability, but in a dev sandbox already protected by PSNR/SSIM
oracles, choosing the provably-smallest win is hard to justify when (b) and (c)
exist. **PR5 should not be built when (c) is sitting there and (b) dominates it on
expected value.** This doc proceeds only to specify the *cheap probe* that would
confirm (a) is dead, so the campaign can move on with data rather than assumption.

### 1.2 Why PR5's ceiling is low (the retracted justification)

V1/V2/V3 inherited a justification that does not survive scrutiny:

- **The "37.4 %" was misattributed.** The predecessor HLD
  (`Encoder hot-path SIMD (speed).md:29`) defines 37.4 % as the **whole final-leaf
  `pick_inter_mode` cost** (MC convolve + SAD + sub-pel + `block_yrd` + this), not
  `compute_variance_8x8`. That baseline predates PR2–PR4 (which SIMD-ported SAD /
  sad4d / variance / sub-pel) and the Phase-2 option-A commit. The predecessor
  (`:510-511`, `:649`) and the Phase-2 HLD (`R6`) **mandate re-baselining** first.
- **The "~10–15 % of pickmode" Amdahl input was invented** — it appears in no
  profiling document.
- **The only real saving is the per-cell call boundary.** Pulling the cell loop
  into one dispatched kernel replaces 16/64 *un-inlinable* indirect per-cell calls
  with one indirect call per block plus a *direct, inlinable* call to the existing
  `var_sum_sse_inner(8,8)`. But the indirect branch itself is near-free (one
  repeated BTB target); fusion does **not** halve horizontal reductions (still
  2 `hsum256`/cell — `sum_acc` and `sse_acc` are distinct registers,
  `variance_avx2.rs:188-189`); it adds **no** cross-cell row-load reuse; and the
  hoistable `ones16` setup is **one broadcast uop per cell**. The saving is
  essentially the call ABI alone, against ~64 madds + 2 hsums + 16 loads of real
  per-cell work.
- **It may be a *pessimization*.** The current loop computes each cell's
  `(sum, sse)` and consumes it immediately while hot in registers. The fused design
  writes all `nw*nh` pairs to stack arrays, then a second loop reads them back
  (≤512 B from L1 for 64 cells) to run the finisher. That extra L1 round-trip,
  which the interleaved code avoids entirely, can equal or exceed the call-boundary
  saving — i.e. the microbench speedup **`S` can be `< 1`** even cache-hot. And the
  loop streams 16 KB (64×64 src+pred) at low arithmetic intensity, so on cold input
  it may be **bandwidth-bound** (`S ≈ 1`).

Net: the best case is small, the expected case is null, and a real-loss case
exists. This is why Stage 0 is a *go/no-go on an upper bound*, not an estimate.

### 1.3 Stage 0 — the only thing to do now (zero production code)

Cheapest test first. **No dispatch slot, no permanent tests, no kernel.**

1. **Microbench `S` (the kill gate).** Write a *throwaway* local bench (scratch
   file / `#[bench]`, deleted after) comparing today's per-cell path against the
   Appendix-A simple kernel on cache-hot and cache-cold 32×32 and 64×64. Confirm
   via disassembly (`cargo asm` / `objdump`) that `var_sum_sse_inner` actually
   inlined into the grid loop — if it did not, `S ≈ 1` and the spike is over.
   **`S` is an *upper bound* on the realizable encode speedup** (in the real
   encoder the function competes for L1/L2 and ports with the rest of pickmode).
   **If `S < ~1.15` cache-hot on 64×64 — including any `S < 1` from the two-pass
   round-trip — STOP and cancel.** This is the expected branch and needs none of
   the machinery below.
2. **Self-cost `F` (only if `S` surprises upward).** Profile the
   **post-Phase-2-core**, post-option-A `target/release` binary for the wall-clock
   fraction in `compute_variance_8x8` *itself* (scoped counter / `perf annotate`
   around `model_rd.rs:706`). Measure `F` and the bench `S` over the **identical
   code span** (the whole function incl. finisher + round-trip), or the projection
   is apples-to-oranges. **`F` must be taken after Phase-2's core lands** — Phase-2
   changes how often `model_rd_for_sb_y_large` runs, which moves `F`; measuring now
   measures a target about to shift.
3. **Gate.** Projected ceiling `≈ F·(1 − 1/S)`. Proceed to Stage 1 **only if all**:
   (a) `F·(1 − 1/S) ≥ +3 %`; **and** (b) Phase-2's core has landed; **and** (c) the
   lead judges a marginal byte-identical `+3 %` worth the LOC over starting the next
   lever. `+3 %` is **necessary, not sufficient** — even a clean `+3 %` moves an
   ~18× gap to ~17.5×, negligible beside Phase-2. Otherwise record the negative
   result in the journal, delete the throwaway bench, and go to Phase-2.

The full statistical campaign (pinned CPU, ≥10 runs, bootstrap CI — Appendix A §A.7)
is **Stage-1 ship-acceptance only** and never runs unless the kernel is built.

# Appendix A — Contingent Stage-1 kernel spec

> Authored for the record. **Build this only if Stage 0 (§1.3) clears the gate —
> expected never.** The design is deliberately minimal: a double loop over the
> proven inner. No lane discipline, no per-cell-column accumulators, no Option A/B
> (all retired from V1; do not reintroduce the halved-hsum / row-reuse framing —
> §1.2 explains why they are false).

## A.1 The grid kernel

```rust
/// AVX2 unsafe core: per-8×8-cell `(sum, sse)` reduction over a `bw × bh` region.
/// `bw, bh ∈ {32, 64}`; `nw = bw/8`, `nh = bh/8`. Writes per-cell `(sum, sse)` in
/// row-major order (`k = i*nw + j`), byte-exact with `nh*nw` calls to
/// `var_sum_sse_inner(8,8)`.
///
/// # Safety
/// AVX2 must be available. `src.len() >= (bh-1)*src_stride + bw`,
/// `pred.len() >= (bh-1)*pred_stride + bw`, `sse_out.len() == sum_out.len() == nw*nh`.
#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
unsafe fn get_var_sse_8x8_grid_inner(
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
    sse_out: &mut [u32], sum_out: &mut [i32],
) {
    debug_assert!(matches!(bw, 32 | 64) && matches!(bh, 32 | 64));
    let nw = bw / 8;
    let nh = bh / 8;
    debug_assert_eq!(sse_out.len(), nw * nh);
    debug_assert_eq!(sum_out.len(), nw * nh);
    debug_assert!(src.len() >= (bh - 1) * src_stride + bw);
    debug_assert!(pred.len() >= (bh - 1) * pred_stride + bw);

    for i in 0..nh {
        for j in 0..nw {
            let k = i * nw + j;
            let s_off = (i * 8) * src_stride + j * 8;
            let p_off = (i * 8) * pred_stride + j * 8;
            // Direct in-module call into the same #[target_feature] fn → the
            // compiler is FREE to inline it (LLVM cost heuristic; not guaranteed —
            // Stage 0 must verify it actually inlined). Only 2 accumulators live
            // (inside one var_sum_sse_inner): same register pressure as today, no spill.
            let (sum, sse) = var_sum_sse_inner(
                &src[s_off..], src_stride, &pred[p_off..], pred_stride, 8, 8);
            sum_out[k] = sum as i32;
            sse_out[k] = sse as u32;
        }
    }
}

/// Thin safe wrapper installed in the dispatch slot (mirrors `var_sum_sse_avx2`,
/// `variance_avx2.rs:200`). The slot holds this, never the unsafe `_inner`.
#[cfg(target_arch = "x86_64")]
pub fn get_var_sse_8x8_grid_avx2(
    src: &[u8], src_stride: usize, pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize, sse_out: &mut [u32], sum_out: &mut [i32],
) {
    // SAFETY: installed only on AVX2 hosts by SimdDispatch::build (caps.avx2).
    unsafe {
        get_var_sse_8x8_grid_inner(src, src_stride, pred, pred_stride, bw, bh, sse_out, sum_out)
    }
}
```

The AVX2 and scalar grid loops are kept **monomorphic** (each calls its inner
directly). Factoring the index loop over a `CellVarFn` parameter — tempting for
DRY — would reintroduce the per-cell fn-pointer indirection this whole change
removes, so the ~10-line duplication is deliberate.

## A.2 Why this is byte-identical

`get_var_sse_8x8_grid_inner` calls `var_sum_sse_inner(8,8)` — the same function the
current per-cell slot calls — once per cell, in the same `k = i*nw + j` order, so
its integers are definitionally equal to `nh*nw` per-cell calls. The scalar
reference (§A.4) loops the existing scalar `get_var_sse_8x8` by the same argument.
The differential test (§A.6) pins the two.

## A.3 Size domain

The lone caller (`model_rd_for_sb_y_large`, `model_rd.rs:688`, dispatched only for
`block_size ≥ Block32x32`) reaches exactly **32×32, 32×64, 64×32, 64×64** →
`nw, nh ∈ {4, 8}`, 4 shapes (max 64 cells). The `matches!(bw,32|64)` assert
**documents intent and catches debug-build mistakes; it is NOT a safety guard** —
memory safety holds for any multiple-of-8 size because every cell is 8 wide
(only `var_sum_sse_inner`'s `tail==8` 8-byte path runs). The lone caller guarantees
the domain regardless.

pub fn get_var_sse_8x8_grid_scalar(

## A.5 Call-site rewiring

`compute_variance_8x8` (`model_rd.rs:578`): one slot call + the finisher.

```rust
fn compute_variance_8x8(
    grid: CellVarGridFn,            // was: reduce: fn(&[u8],usize,&[u8],usize)->(i32,u32)
                                    //      (a bare fn-ptr inline at model_rd.rs:579, NOT CellVarFn)
    src: &[u8], src_stride: usize, pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
) -> (u64, i64, [u32; 64], [i32; 64], [u32; 64]) {
    let nw = bw / 8; let nh = bh / 8;
    debug_assert!(nw * nh <= 64);
    let mut sse8x8 = [0u32; 64];
    let mut sum8x8 = [0i32; 64];
    let mut var8x8 = [0u32; 64];

    grid(src, src_stride, pred, pred_stride, bw, bh, &mut sse8x8[..nw*nh], &mut sum8x8[..nw*nh]);

    // FINISHER. The abs-diff `>>6` arithmetic is verbatim from PR4. The total
    // accumulation is RELOCATED into this second loop (it was interleaved before).
    // Byte-identical because this loop visits cells in the IDENTICAL k = i*nw + j
    // order, so the running u64/i64 sums see the exact same operand sequence in the
    // exact same order — no reordering (stronger than an associativity argument).
    // The read-back of sse8x8/sum8x8 is ≤512 B from L1; its cost is part of what
    // Stage 0's end-to-end microbench measures (and may make S < 1 — §1.2).
    let mut total_sse: u64 = 0; let mut total_sum: i64 = 0;
    for k in 0..(nw * nh) {
        let cs = sum8x8[k]; let csse = sse8x8[k];
        let k_sqr = ((cs as i64 * cs as i64) >> 6) as u32;
        var8x8[k] = if csse > k_sqr { csse - k_sqr } else { k_sqr - csse };
        total_sse += csse as u64; total_sum += cs as i64;
    }
    (total_sse, total_sum, sse8x8, sum8x8, var8x8)
}
```

Caller hoist (`model_rd.rs:706`):
`let grid = crate::dsp::get_ref().get_var_sse_8x8_grid();`.

The two unit tests (`model_rd.rs:1545/1564`) pass the scalar reducer today; because
the first param's **arity changes**, they are **rewritten** (not symbol-swapped) to
pass `get_var_sse_8x8_grid_scalar`. They must assert the **full returned tuple**
(`total_sse`, `total_sum`, `var8x8`) — not just per-cell `(sum, sse)` — so they pin
the **relocated finisher** (the second new surface alongside the write-index). Their
existing concrete values (per cell `sse=256, sum=128, var=0`; totals `256·16`,
`128·16`) still hold because the grid scalar ref delegates to the same
`get_var_sse_8x8`.

## A.6 Test plan

The grid kernel re-loops the already-tested `var_sum_sse_inner(8,8)`, so the new
tests target the **two new surfaces only**: the per-cell write-index (`k = i*nw+j`)
and the relocated finisher. Over the 4 reachable shapes `(bw,bh) ∈ {32,64}²`:

- **Cross-cell isolation sweep (primary, the write-index oracle).** Set exactly one
  cell to max-diff (`src=0, pred=255`), all others to `diff=0`; sweep the hot cell
  across all `nw*nh` positions. Assert the hot cell equals the **exact** known value
  `(sum = -16320, sse = 4_161_600)` **and** every other cell is `(0, 0)`. The exact
  magnitude (not just non-zero) also catches a wrong-but-nonzero value landing at
  the right index.
- **Buffer-tight safety case.** One iter with `stride == bw`,
  `len == (bh-1)*stride + bw` (no padding) to exercise the bottom-right cell against
  the buffer end. Its sub-slice length is exactly `7*stride + 8`, which **discharges
  `var_sum_sse_inner`'s own `debug_assert` precisely** (`(h-1)*stride + w` for
  `h=w=8`, `variance_avx2.rs:134`) — so the inner assert never spuriously fires on a
  tight buffer. **Memory-safety evidence:** the entry `debug_assert`s + the fact
  that an 8-wide cell only hits the `tail==8` `_mm_loadl_epi64` path (exactly 8
  bytes/row, never the `tail==4` `u32` read) ⇒ no load exceeds the cell. Verify with
  **ASAN** (`cargo +nightly … -Zsanitizer=address` on the real AVX2 binary). **Not
  Miri** — Miri cannot execute AVX2 intrinsics and the test module is already
  `not(miri)`-gated (`variance_avx2.rs:280`).
- **Grid dispatch round-trip.** Replacing the deleted per-cell sub-test:
  `build(avx2:true)` vs `build(avx2:false)` must produce identical out-arrays.
- The full-array AVX2-vs-scalar random differential is **dropped** — it is
  redundant with `differential_8x8_cell` (same inner, 2048 iters already), adding
  permanent maintenance for ~zero marginal oracle value.

System oracle (the gate, unchanged, no new env var): the cross-process
`RVP9_FORCE_SCALAR` IVF md5 must match on **both** foreman_320x256 and
testsrc_720p30; `cross_decoder_gate` stays 4/4; `quality_gate` PSNR/SSIM identical
to the PR4 baseline.

## A.8 Risks (Stage-1)

| # | Risk | Handling |
|---|---|---|
| R1 | A per-cell `(sum, sse)` is written to the wrong `k` (cells swap). | §A.6 cross-cell sweep asserts only the single hot cell holds the exact known value, across all positions and all 4 shapes — a direct pin on the write index. |
| R2 | Overflow where the per-cell call wouldn't. | Impossible: same `var_sum_sse_inner(8,8)` per cell, same casts, no cross-cell accumulation. 8-bit 8×8 cell: `diff ∈ [-255,255]`, `\|sum\| ≤ 16320` (i32), `sse ≤ 4,161,600` (u32). Each accumulated i32 madd-lane partial ≤ `8 rows · (2·255²) = 8·130050 = 1,040,400` (~1.04M), far below the i32 ceiling. Visitation order is preserved, so no reordering. |
| R3 | Memory safety / OOB read. | `var_sum_sse_inner(8,8)`'s `tail==8` path reads exactly 8 bytes/row (`_mm_loadl_epi64`) — never past the cell. Entry `debug_assert`s on buffer + out-array lengths; §A.6's buffer-tight case + **ASAN** (not Miri) exercise the bottom-right edge. |
| R4 | Win below `+3 %`, or `compute_variance_8x8` no longer hot, or `S < 1`. | **The expected case.** Stage 0 (§1.3) catches it before any production code; cancel → Phase-2. |
| R5 | Two-pass round-trip / bandwidth bound makes fusion a net loss. | Stage 0's end-to-end hot-vs-cold microbench measures the whole function incl. the round-trip and **may legitimately return `S < 1` — a hard cancel, not a re-tune**. §A.7's no-regression CI guard blocks shipping a slowdown if Stage 1 is ever built. |

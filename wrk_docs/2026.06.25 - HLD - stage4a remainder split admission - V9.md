## 4. Design

### 4.1 Shared Product Runner

Create one shared Stage 4a product runner used by quality, cross-decoder, timing, block-stat, and diff checks. This keeps validation coherent and avoids each test inventing a slightly different encode path.

Configuration:

- Source: `tests/corpus/foreman_cif.y4m`, expected source SHA-256 `b0e3c35eff9fe1da91521a02eb9f0e3ef4bc5aec341ecef1567cd87f1711267b`, expected byte length `45_621_044`, 256x256 center crop, 64 frames.
- Targets: `[25_000, 50_000, 75_000, 100_000, 150_000, 250_000, 400_000]` bps.
- Encoder: `AqMode::Off`, one-pass `RcMode::Vbr`, realtime deadline, speed 7, `lag_in_frames=0`, no alt-ref, min q 4, max q 255.
- Tools: resolve `vpxenc`, `vpxdec`, and `ffmpeg` through one strict resolver. Check `build\libvpx-win-tools-nodeps\`, sibling `vpxdec` next to `vpxenc`, then PATH. No Arthur-specific absolute tool path is an acceptance requirement, but product sign-off accepts a PATH-discovered `vpxenc`/`vpxdec` pair only if their binary hashes match an approved libvpx tool manifest (§4.4).
- Output root: `target\stage4a_product\<run-id>\`, where `<run-id>` includes run role, git short SHA, and UTC timestamp.

The runner writes one report per run:

```text
target\stage4a_product\<run-id>\stage4a_product_report.json
```

Report schema must include:

- `run_role`: `"preenable-preflight"`, `"strict-baseline"`, or `"candidate"`,
- `overall_status`: `"PASS"` or `"FAIL"`,
- `status_reasons`: array of machine-readable reason codes,
- `split_policy`: `"Strict"` or `"Slack1Over8"`,
- `split_override`: `"Auto"` or `"ForceStrict"`,
- `git_sha`: `git rev-parse HEAD` for the validation worktree,
- `worktree_path`,
- `validation_clean`: boolean,
- `validation_clean_paths`: the exact paths checked by §4.2,
- `tracked_diff_empty`: boolean,
- `staged_diff_empty`: boolean,
- `untracked_validation_files`: array,
- `ignored_validation_files`: array,
- `allowed_ignored_inputs`: array of `{ path, sha256, role }`,
- `source_tree_hash`: hash of tracked validation-path file content at HEAD,
- `host_id`,
- `utc_started`,
- `source_path`,
- `source_expected_sha256`,
- `source_expected_bytes`,
- `source_sha256`,
- `product_config_hash`,
- tool paths, versions/probe text, fingerprints, and approved manifest identity,
- exact encoder config,
- per-target rvp9 and libvpx bitrate/PSNR points,
- BD-rate and matched PSNR-delta summary,
- `bd_psnr_overlap_db`,
- per-target rvp9 IVF path and libvpx IVF path,
- per-target typed `NonRdSplitStats`,
- timing median for the rvp9 leg,
- decoder verdicts,
- block-stat summary for 250 kbps or the best-overlap target,
- for candidate reports only: `baseline_report_path`, `baseline_report_sha256`, `baseline_git_sha`, `baseline_host_id`, `baseline_product_config_hash`, `baseline_source_sha256`, `baseline_source_tree_hash`.

Final product comparison uses two reports produced at the same candidate commit:

- `strict-baseline`: same candidate commit, product runner forces `split_policy = Strict` through a hidden product-test override.
- `candidate`: same candidate commit, normal encoder policy selects `Slack1Over8`.

The earlier `preenable-preflight` report is only a go/no-go decision before enabling policy selection. It is not the final non-regression baseline.

Product sign-off fails unless every `preenable-preflight`, `strict-baseline`, and `candidate` report used for evidence has:

- `overall_status == "PASS"`,
- no status, decoder verdict, quality verdict, timing verdict, block-stat verdict, or differential verdict equal to `"SKIPPED"`, `"DEFERRED"`, `"PARTIAL"`, `"MISSING"`, or `"UNVERIFIED"`,
- `validation_clean == true`.

The `preenable-preflight` report is valid only if its `git_sha` equals the strict diagnostics commit that produced it and the worktree was clean at that commit. The final `strict-baseline` and `candidate` reports are valid only if both have `git_sha == git rev-parse HEAD` for the final candidate commit under review and both `source_tree_hash` values match that candidate HEAD for validation paths.

A product test that cannot produce a complete `PASS` report must fail the test process. It may write a diagnostic `FAIL` report, but it must not return success with a `SKIPPED`, `DEFERRED`, `PARTIAL`, `MISSING`, or `UNVERIFIED` report. Legacy non-product tests may keep skip-clean behavior; these product variants may not.

If product gates are run from a data-populated worktree, that worktree must be checked out at the exact candidate commit and pass the same cleanliness checks. A stale or dirty worktree report is invalid.

Candidate report pairing is valid only if:

- candidate `baseline_report_path` points to the exact strict-baseline report used,
- candidate `baseline_report_sha256` matches that file,
- baseline report `run_role == "strict-baseline"`,
- baseline report `split_policy == "Strict"`,
- candidate report `split_policy == "Slack1Over8"`,
- candidate and baseline reports have the same `git_sha`, `host_id`, `source_sha256`, `source_tree_hash`, `product_config_hash`, and tool fingerprints,
- candidate report `baseline_git_sha`, `baseline_host_id`, `baseline_product_config_hash`, `baseline_source_sha256`, and `baseline_source_tree_hash` match the baseline report.

The strict-baseline override surface is explicit and non-env:

```rust
#[doc(hidden)]
pub enum Stage4aProductSplitOverride {
    Auto,
    ForceStrict,
}
```

Add it as a hidden field or builder option on `EncoderConfig`, defaulting to `Auto`. The product runner may set `ForceStrict` only for `run_role == "strict-baseline"`. Candidate product runs and normal encoder callers must use `Auto`; product gates hard-fail if `ForceStrict` appears in a candidate report. This is not a user-facing feature flag and must not be surfaced through CLI or environment variables.

### 4.2 Validation Cleanliness Contract

Product runs hard-fail unless the validation-relevant tree is clean.

Validation paths:

```text
Cargo.toml
Cargo.lock
rust-toolchain.toml
.cargo
crates
scripts
tests
```

Before producing any product report, the runner must verify:

```powershell
git diff --quiet -- Cargo.toml Cargo.lock rust-toolchain.toml .cargo crates scripts tests
git diff --cached --quiet -- Cargo.toml Cargo.lock rust-toolchain.toml .cargo crates scripts tests
git ls-files --others --exclude-standard -- Cargo.toml Cargo.lock rust-toolchain.toml .cargo crates scripts tests
git ls-files --others --ignored --exclude-standard -- Cargo.toml Cargo.lock rust-toolchain.toml .cargo crates scripts tests
```

The first two commands must exit 0. The third must return no files. The fourth must return no files except explicitly allowed input corpora:

- `tests/corpus/foreman_cif.y4m` for the Stage 4a product runner.
- `tests/corpus/testsrc_720p30.y4m` for the existing 720p realtime gate, when that gate is run.

Every allowed ignored corpus input must be recorded in `allowed_ignored_inputs` with `path`, `sha256`, and `role`. Any ignored file under `.cargo`, `crates`, `scripts`, `Cargo.toml`, `Cargo.lock`, or `rust-toolchain.toml` hard-fails product validation. Any ignored file under `tests` that is not one of the allowed input corpora hard-fails product validation. Generated artifacts under `target\` are allowed because `target\` is outside the validation paths.

For `tests/corpus/foreman_cif.y4m`, product validation also hard-fails unless `sha256 == b0e3c35eff9fe1da91521a02eb9f0e3ef4bc5aec341ecef1567cd87f1711267b` and `len == 45_621_044` before cropping. This is the SHA-256 of the canonical Xiph Derf file documented in `tests/corpus/sources/README.md`. The report must record both the expected and observed values.

A broadly data-populated checkout with fetched `tests/conformance/vectors/`, `tests/corpus/sources/*`, or extra root `.y4m` files is not a product-validation worktree. For product sign-off, use a clean validation worktree containing only the tracked tree plus the allowed hashed input corpora, or copy just the allowed corpora into the candidate worktree.

Docs/journal/ledger edits do not affect the encoded bytes and are not part of this validation cleanliness gate. The build still must commit required docs/ledger changes before integration under normal repo rules.

### 4.4 Hash And Report Mechanics

Product report JSON and SHA-256 hashing may use test/harness-only `serde_json` and `sha2`. These are not encoder runtime dependencies. If an equivalent dependency already exists by the time implementation starts, reuse it instead of adding another.

Reference libvpx identity is pinned separately from the rvp9 source tree:

- Source URL: `https://chromium.googlesource.com/webm/libvpx`.
- Expected tag: `v1.14.1`.
- Expected peeled commit: `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`.
- Expected superproject gitlink: `third_party/libvpx` at `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`.

Add the approved tool manifest at:

```text
tests/reference/stage4a_libvpx_tools.json
```

The manifest contains approved `vpxenc`/`vpxdec` pairs. Each row must include:

- `platform`,
- `target_triple`,
- `libvpx_url`,
- `libvpx_tag`,
- `libvpx_commit`,
- `build_script`,
- `configure_args`,
- `vpxenc_sha256`,
- `vpxdec_sha256`,
- optional `notes`.

The product runner hard-fails unless:

- `git ls-tree HEAD third_party/libvpx` reports the expected gitlink commit,
- `vpxenc` and `vpxdec` resolve to files in the same directory,
- their binary SHA-256 values match the same approved manifest row,
- that manifest row has the expected libvpx URL, tag, and commit,
- `vpxenc --help` exits successfully and the normalized stdout/stderr hashes are recorded,
- `vpxdec --help` or the existing `vpxdec` version probe exits successfully and the normalized stdout/stderr hashes are recorded.

`ffmpeg` is not source-pinned, but its path, binary SHA-256, version command, and normalized version stdout/stderr hashes must be recorded and must match between paired strict-baseline and candidate reports. Missing `ffmpeg` hard-fails product sign-off.

Hash algorithms:

- Paths use repo-relative forward-slash form.
- File ordering is lexicographic by normalized path.
- `source_tree_hash` is SHA-256 over every tracked file under the validation paths. For each file, feed `path`, NUL, decimal byte length, NUL, raw file bytes, NUL. Because validation cleanliness is required first, working-tree bytes must match `HEAD` for tracked files.
- `source_sha256` is SHA-256 over the raw allowed input corpus file bytes.
- `baseline_report_sha256` is SHA-256 over the exact JSON report file bytes.
- `product_config_hash` is SHA-256 over canonical UTF-8 JSON built from a `BTreeMap`/sorted-key object containing source geometry, expected source hash/length, frame count, target list, encoder config excluding `Stage4aProductSplitOverride`, libvpx config, approved tool manifest row identity and binary hashes, `ffmpeg` version/hash fingerprint, and validation allowlist. It excludes split policy, hidden split override, and volatile fields such as paths, timestamps, run role, report paths, measured metrics, and git SHA.
- `split_policy` and `split_override` are explicit report fields and pairing assertions, not part of `product_config_hash`. This lets strict-baseline and candidate reports prove they share every product input while intentionally differing only in effective split policy.
- normalized probe text replaces `\r\n` with `\n`, trims trailing whitespace-only lines, and is hashed as UTF-8. Reports may include the first 20 normalized lines for debugging, but the hash is the pairing oracle.

Product JSON should be emitted from typed structs. Do not parse stdout to reconstruct the report.

### 4.5 Typed Split-Stats Evidence Channel

Do not make product gates depend on `RVP9_A4_SPLIT_STATS`.

Preferred implementation:

```rust
impl StreamEncoder {
    pub fn diag_take_stage4a_split_stats(&mut self) -> NonRdSplitStats;
}
```

Fallback implementation, allowed only if the per-encoder method is disproportionately invasive, must expose explicit scope boundaries:

```rust
pub mod stage4a_splitstat {
    pub fn reset_for_product_target();
    pub fn take_snapshot() -> NonRdSplitStats;
}
```

If the fallback is used:

- counters must be thread-local,
- the product runner must run target encodes serially on one thread,
- it must call `reset_for_product_target()` immediately before each target encode,
- it must call `take_snapshot()` immediately after that target encode,
- it must assert the snapshot is empty immediately after reset and non-absent after encode,
- no product test may aggregate counters across targets without preserving each target's separate snapshot.

Either implementation must be typed, in-process, and independent of env-gated printing. Missing counters hard-fail the product runner.

### 4.6 Split Diagnostics

Extend `NonRdSplitStats` narrowly for `Block16x16 -> 8x8`:

- `block16_partial_early_out_after_child[4]`
- `block16_slack_would_continue`
- `block16_slack_completed`
- `block16_slack_split_eligible`
- `block16_slack_split_committed`
- `block16_slack_rect_override`
- `block16_slack_rejected`

Strict-policy preflight must not complete skipped children through a shadow descent. It records only counters available at the real strict early-out point:

```text
strict early-out fires
and parent NONE is feasible
and partial_split_rd <= none_rd + floor(none_rd / 8)
=> block16_slack_would_continue += 1
```

Materiality threshold before enabling behavior:

- `block16_attempts > 0`.
- `block16_child_infeasible <= 5% of block16_attempts`.
- `block16_slack_would_continue >= max(200, 2% of block16_partial_rd_early_out)`.
- `block16_slack_would_continue > 0` at two or more product targets.

If preflight fails, stop. Do not sweep ratios or force split.

After behavior is enabled, `block16_slack_completed`, `block16_slack_split_eligible`, and `block16_slack_split_committed` become product evidence. Product sign-off requires `block16_slack_split_committed > 0` for at least one product target, proving the changed path ran.

### 4.7 Split-Admission Policy

Add:

```rust
pub enum Block16SplitAdmission {
    Strict,
    Slack1Over8,
}
```

Add it to `NonRdDescentParams`, defaulting to `Strict`. Do not expose `{ num, den }`, env control, CLI control, or a user-facing config knob.

The encoder selects `Slack1Over8` only when all are true:

- `RcMode::Vbr`,
- `Deadline::Realtime`,
- `speed >= 7`,
- P8 is enabled for the frame,
- `rt_large_recovery` is false.

All other modes remain strict.

### 4.8 Early-Out And Selection Semantics

These semantics apply only to `Block16x16 -> 4x Block8x8` when `Slack1Over8` is active and parent `PARTITION_NONE` is feasible. If parent NONE is not feasible, there is no parent-NONE cap and behavior remains strict.

Define:

```text
none_rd = RD(parent PARTITION_NONE with NONE partition cost)
slack_cap = none_rd + floor(none_rd / 8)
strict_best = best candidate by actual RD under today's strict rules
```

During SPLIT child evaluation:

```text
strict early-out: partial_split_rd >= strict_best_rd
Slack1Over8 early-out: partial_split_rd > slack_cap
```

If all four children complete:

```text
split_actual_rd = RD(sum child rate + SPLIT cost, sum child dist)
split_slack_eligible = split_actual_rd <= slack_cap
```

Candidate arbitration:

1. Strict non-NONE wins are unchanged. If SPLIT, HORZ, or VERT has `actual_rd < none_rd`, choose the best strict candidate.
2. If no non-NONE candidate strictly beats NONE and `split_slack_eligible` is true, SPLIT may override NONE.
3. RECT remains enabled. Slack admission does not reopen or relax the existing rect pruner. RECT override applies only to HORZ/VERT arms the existing pruner allowed. A RECT arm that strictly beats NONE wins normally. If no RECT arm strictly beats NONE but SPLIT is only slack-admitted, RECT may override that slack SPLIT only when:

```text
rect_actual_rd < split_actual_rd
rect_actual_rd <= slack_cap
```

4. Ties keep existing ordering. Slack does not change tie behavior outside the parent-NONE band.

Rect-prune inputs:

- `RectPruneRdContext.best_rd_cost` is the strict actual-RD best after NONE and any strict SPLIT, not the slack cap and not discounted SPLIT RD.
- `RectPruneRdContext.partitioning_is_none` means the strict current winner is NONE.
- `split_none_rd_cost` may include child NONE costs from a SPLIT that genuinely completed under the active child loop.

Parent propagation always uses real accounting:

- Return actual `rate`, actual `dist`, and actual `rd_cost`.
- Do not discount rate, distortion, or parent RD when a candidate was admitted by slack.
- A parent SPLIT sees the true cost of a slack-admitted child.

### 4.9 Causal Emit Boundary

Do not make the dry-run descent own final mode, residual, skip, or neighbor state.

The current final per-leaf pass remains the source of emitted reconstruction and `mi_grid` updates. The descent may choose shape and may continue to seed/reuse existing safe picker data, but final emit stays raster/causal.

### 4.10 Implementation Sequencing

The build should proceed in two green steps:

1. **Diagnostics and gates, policy still strict.**
   - Add typed split stats.
   - Add the shared product runner and strict-product assertions.
   - Add `Block16SplitAdmission` and unit tests, but keep encoder selection at `Strict`.

   - Enable policy selection for the Stage 4a slice only.

## 7. Residual Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Slack1Over8 is the wrong prior. | Quality or block stats regress. | Single compiled constant; stop if gates fail, no ratio sweep. |
| Strict preflight predicts little useful work. | Behavior path cannot finish Stage 4a. | Stop before behavior enablement. |
| Product gates validate stale, dirty, ignored, or wrong-toolchain code. | False sign-off. | Report `git_sha`, clean validation paths, ignored-file allowlist, `rust-toolchain.toml`, and source tree hash must match candidate HEAD. |
| Product gates validate the wrong Foreman file or wrong libvpx tools. | False BD-rate sign-off. | Pin Foreman SHA-256/length and require approved libvpx v1.14.1 tool-manifest binary hashes. |
| Product gates miss the changed path. | False confidence. | Product report requires typed `block16_slack_split_committed > 0`. |
| BD-rate looks good due to poor curve overlap. | False sign-off. | Expanded targets, finite BD-rate, monotonic curves, and >=3 overlap points. |
| Extra 8x8 evaluation hurts realtime. | Stage 4a fails performance. | Limit to Block16/P8/VBR/non-large-recovery slice; realtime gates are blocking. |
| RECT inherits unintended slack. | Partition shape drifts unpredictably. | Existing rect pruner remains authoritative; slack override only inside parent-NONE band. |
| Descent/final emit mismatch. | Invalid or poor bitstream. | Preserve causal final emit and run product cross-decoder gate. |
| Foreman overfit. | Product does not generalize. | This HLD signs off Stage 4a's current product gate, not broad content parity. |

## 8. Decision Log

| Decision | Rationale |
|---|---|
| Base design chosen from simplest-viable draft by 2-of-3 judge majority. | It targets the diagnosed code path with the smallest implementation surface. |
| Grafted risk-first oracle requirements. | The current `-3.99%` BD-rate result has thin overlap and missing `ffmpeg`; product sign-off must be stricter. |
| Grafted testability-first structured diagnostics narrowly. | Need machine-checkable evidence without a broad diagnostics API or descent rewrite. |
| Replaced `SmallShapeSlack { num, den }` with `Slack1Over8`. | A ratio field is a tuning surface. |
| Removed V2's shadow no-behavior descent. | Round-2 simplicity review correctly flagged it as over-engineered. Preflight now records only cheap strict-path counters. |
| Added typed split-stats evidence channel. | Round-2 Devil's Advocate found a critical gap: product tests required counters without defining how they were available. |
| Added strict report SHA, clean-tree, ignored-file, toolchain, and pairing contract. | Round-3/4/5 review found stale, dirty, ignored-file, and toolchain validation loopholes. |
| Compare candidate to strict-baseline at the same commit. | Avoids comparing final behavior against an older pre-enable commit while still proving the policy delta. |
| Added hidden strict-baseline override API. | External Codex review found "force Strict" was otherwise undefined without env/CLI knobs. |
| Allow test/harness-only `serde_json` and `sha2`. | External Codex review correctly rejected hand-rolled JSON/SHA mechanics. These are not encoder runtime dependencies. |
| Added `bd_psnr_overlap_db >= 0.50`. | External Codex review found bitrate-in-range count alone did not prove BD-rate integration overlap. |
| Kept the ignored-file allowlist narrow. | External Codex suggested either broader hashing or a clean product-validation worktree; the simpler route is only the named hashed inputs. |
| Excluded split policy/override from `product_config_hash`. | Confirmation review found matching baseline/candidate hashes impossible while the hash included the one field that must differ. |
| Pinned the Foreman corpus and libvpx reference tools. | Completeness check found same-between-runs was not enough to prove the intended source/reference inputs. |
| Product variants fail on `SKIPPED`, `DEFERRED`, `PARTIAL`, `MISSING`, or `UNVERIFIED`. | Completeness check found those statuses were named as unacceptable but not defined as machine oracles. |
| Reject all `RVP9_*` env vars for product sign-off. | "Unexpected behavior-affecting" was too vague for a hard gate. |
| Scoped fallback split stats with reset/take boundaries. | Prevents counter contamination across product targets. |
| Use one shared product runner. | Avoids CBR/testsrc false coverage and duplicated harness variants. |
| Product gates hard-fail on missing prerequisites and `DEFERRED`/`PARTIAL`. | Report-only gates are not sign-off evidence. |
| Added `diff_bitstream`/divergence-ledger acceptance. | PLAN requires documented differentials. |
| Made block-stat sanity coarse. | Detailed per-metric thresholds would invite threshold chasing. |
| Keep Foreman as the primary quality corpus but limit claims. | Existing Track F gates center Foreman; broader content parity is a separate requirement. |
| Keep `InterRdCalibration::stage4a_vbr()` unchanged. | It is the promoted baseline and already moved the product curve. |
| Keep RECT enabled and do not reopen pruned rect arms. | Rect-disable was measured harmful; the issue is split admission, not forcing SPLIT. |
| Stop if Slack1Over8 fails. | Prior work already refuted many scalar-only tweaks. |

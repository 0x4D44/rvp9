## Confirmed Findings

| Bug | Summary | Impact |
|---|---|---|
| `RVP9-BUG-KILN-00020` | Public `v_predictor_avx2` is safe but exposes AVX2, slice, stride, and geometry preconditions that are only comments or `debug_assert!`s. | Safe public callers can reach target-feature or raw-pointer UB through a direct SIMD entry point. |
| `RVP9-BUG-KILN-00021` | Public `ScanOrder` fields let safe callers pass malformed scan tables into `decode_coefs`, which uses unchecked table indexing. | Safe public API can drive out-of-bounds reads or writes in coefficient decoding. |
| `RVP9-BUG-KILN-00022` | Custom YV12 borders are bounded only by the multiple-of-32 rule before `u32` allocation geometry arithmetic. | Huge aligned borders can overflow or wrap padded dimensions before the total allocation check. |
| `RVP9-BUG-KILN-00023` | Public tile buffer helpers do not enforce VP9 tile limits or release-mode payload count checks. | Public callers can request unbounded allocation or emit tile layouts that do not match the supplied geometry. |
| `RVP9-BUG-KILN-00024` | Direct-to-frame tile decode and loop-filter workers create full-plane mutable slices from shared backing storage. | Parallel paths can create overlapping `&mut` references, undermining Rust's aliasing guarantees. |
| `RVP9-BUG-KILN-00025` | One-axis scaled inter prediction is routed through the full two-dimensional scaled kernel without satisfying both-axis pre-shift assumptions. | Width-only or height-only scaling can sample the wrong row or column and drift from libvpx. |

## Refuted Or Held

- A superframe size-sum suspicion was refuted. `crates/rvp9-decoder/src/lib.rs` checks that tile slicing remains inside the packet payload before decode.
- `merge_tile_rect_from` has release panic risk when called with invalid geometry, but this pass did not file it because the stronger confirmed issue is the direct-to-frame aliasing model.
- Public bitstream writer value-domain validation gaps, public intra predictor panic surfaces, and release-mode inter-mode writer assertions were observed but held because they were not in the skeptic-confirmed candidate set.
- Three performance candidates were held for a later performance-focused pass because they did not receive the required skeptic verification in this bounded pass: per-candidate AVX2 subpel variance heap allocation, eager worker-pool spawning for one-thread decoders, and an avoidable encoder hot-path `Arc` clone in `inter_predictor`.

- **Method:** correctness, security/input-safety, performance, reliability/unsafe, API/docs, and test-oracle lenses, followed by three skeptic passes. Findings below survived at least the required 2-of-3 skeptic bar.

## Confirmed Findings

| Bug | Summary | Impact |
|---|---|---|
| `RVP9-BUG-KILN-00026` | Tile entropy decode creates `BoolReader`s in `decode_tile_intra` and `decode_tile_inter` but returns success without checking `has_error()`. | Truncated tile payloads can be accepted as valid by substituting zero bits after EOF, hiding malformed streams and potentially corrupting decoded output. |
| `RVP9-BUG-KILN-00027` | LF-overlap keeps immutable MI-grid slices while tile workers mutate the same grid through `TileMiView` raw pointers. | The threaded decoder can create shared-reference/raw-mutable aliasing on the MI grid; this is separate from the existing full-plane pixel aliasing bug `RVP9-BUG-KILN-00024`. |
| `RVP9-BUG-KILN-00028` | `parse_packet` mutates stream metadata such as `established_chroma` and `ref_frame_sizes` before frame decode succeeds. | A failed or dropped decode can leave decoder metadata advanced ahead of the last committed frame state, affecting subsequent frames. |
| `RVP9-BUG-KILN-00029` | Public `decode_tile_inter` accepts any non-empty `prev_segment_ids` slice and can index it out of bounds through `read_inter_segment_id`. | Safe public callers can trigger a panic with malformed segment-map inputs; the full decoder guards this path, but the exported helper does not. |
| `RVP9-BUG-KILN-00030` | Public `frame_pool_mut` exposes mutable frame-pool operations without preserving the decoder's private reference-map invariants. | Safe callers can desynchronize pool refcounts from the decoder ref map and break later decode or retention behavior. |
| `RVP9-BUG-KILN-00031` | Profile-1 AQ2 non-420 segmentation decode mismatches remain ignored and untracked after the kfonly subset was closed. | A known decoder correctness gap can stay invisible to the bug queue because the remaining ignored AQ2 tests are not represented by an open bug. |
| `RVP9-BUG-KILN-00032` | Decoder-facing corpus and conformance tests can pass without required oracle data. | Local gates can go falsely green when MD5 ledgers or conformance vectors are absent, so decoder regressions may be missed. |

## Refuted Or Held

- The suspected segmentation-state commit before failed decode was held rather than filed. The mutation is real, but `Decoder::decode_frame` documents that `Err` leaves decoder state well-defined but non-transactional; this is a docs-clarity concern unless the contract changes.
- Public tile buffer helper validation was not re-filed because it is already tracked by `RVP9-BUG-KILN-00023`.
- Full-plane direct-to-frame aliasing was not re-filed because it is already tracked by `RVP9-BUG-KILN-00024`; the new MI-grid aliasing issue is adjacent but distinct.
- Eager worker-pool spawning, full-frame per-tile `seg_ids`/`mv_grid` slabs, and stale decoder module docs were kept report-only. They are real maintenance or performance debt, but this bounded pass did not turn them into new behavior bugs.

Six lens readers produced candidate findings, then three skeptic readers tried to refute them. The report includes only candidates that survived that adversarial pass. No source edits, tests, app commands, or benchmarks were run; this pass wrote only review, journal, and bug-ledger artifacts.

## Confirmed Findings

| Bug | Summary | Impact |
|---|---|---|
| `RVP9-BUG-KILN-00020` | Public `v_predictor_avx2` is safe but exposes AVX2, slice, stride, and geometry preconditions that are only comments or `debug_assert!`s. | Safe public callers can reach target-feature or raw-pointer UB through a direct SIMD entry point. |
| `RVP9-BUG-KILN-00021` | Public `ScanOrder` fields let safe callers pass malformed scan tables into `decode_coefs`, which uses unchecked table indexing. | Safe public API can drive out-of-bounds reads or writes in coefficient decoding. |
| `RVP9-BUG-KILN-00022` | Custom YV12 borders are bounded only by the multiple-of-32 rule before `u32` allocation geometry arithmetic. | Huge aligned borders can overflow or wrap padded dimensions before the total allocation check. |
| `RVP9-BUG-KILN-00023` | Public tile buffer helpers do not enforce VP9 tile limits or release-mode payload count checks. | Public callers can request unbounded allocation or emit tile layouts that do not match the supplied geometry. |
| `RVP9-BUG-KILN-00024` | Direct-to-frame tile decode and loop-filter workers create full-plane mutable slices from shared backing storage. | Parallel paths can create overlapping `&mut` references, undermining Rust's aliasing guarantees. |
| `RVP9-BUG-KILN-00025` | One-axis scaled inter prediction is routed through the full two-dimensional scaled kernel without satisfying both-axis pre-shift assumptions. | Width-only or height-only scaling can sample the wrong row or column and drift from libvpx. |

## Refuted Or Held

- A superframe size-sum suspicion was refuted. `crates/rvp9-decoder/src/lib.rs` checks that tile slicing remains inside the packet payload before decode.
- `merge_tile_rect_from` has release panic risk when called with invalid geometry, but this pass did not file it because the stronger confirmed issue is the direct-to-frame aliasing model.
- Public bitstream writer value-domain validation gaps, public intra predictor panic surfaces, and release-mode inter-mode writer assertions were observed but held because they were not in the skeptic-confirmed candidate set.
- Three performance candidates were held for a later performance-focused pass because they did not receive the required skeptic verification in this bounded pass: per-candidate AVX2 subpel variance heap allocation, eager worker-pool spawning for one-thread decoders, and an avoidable encoder hot-path `Arc` clone in `inter_predictor`.

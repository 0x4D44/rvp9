> **One-line thesis.** `compute_variance_8x8` calls the PR4 per-cell AVX2
> `(sum, sse)` reducer **once per 8×8 cell** — 16 calls for 32×32, 64 for 64×64.
> Each call pays a function-pointer indirection, an AVX2 epilogue, and **two**
> horizontal-sum reductions (one for sum, one for sse). A composite 2-D kernel
> processes the whole grid in **one** sweep — one row-load (32 B) covers up to
> four horizontally-adjacent cells, per-cell accumulators stay separate, the
> horizontal reduction runs once per cell at the end. **Same per-cell `(sum, sse)`
> values feed the unchanged scalar finishers → bitstream byte-identical.**

## 1. Problem

PR4 (`f7a965a`) landed `get_var_sse_8x8_avx2` and was the biggest single
Phase-1 win (+11 %). It is consumed by `compute_variance_8x8`
(`model_rd.rs:578-621`), the per-leaf hot loop for ≥32×32 blocks (the 37.4 %
per-final-leaf cost in the §1 profiling of the speed HLD). The consumer looks
like this today:

```rust
for i in 0..nh {
    for j in 0..nw {
        let k = i * nw + j;
        let s_off = (i * 8) * src_stride + j * 8;
        let p_off = (i * 8) * pred_stride + j * 8;
        let (cell_sum, cell_sse) =
            reduce(&src[s_off..], src_stride, &pred[p_off..], pred_stride); // <- per-cell AVX2 call
        sse8x8[k] = cell_sse;
        sum8x8[k] = cell_sum;
        // var = |sse − (sum² >> 6)|  (finisher, scalar, untouched)
        let k_sqr = ((cell_sum as i64 * cell_sum as i64) >> 6) as u32;
        var8x8[k] = if cell_sse > k_sqr { cell_sse - k_sqr } else { k_sqr - cell_sse };
        total_sse += cell_sse as u64;
        total_sum += cell_sum as i64;
    }
}
```

Three structural costs per cell that are now the long pole:

1. **Function-pointer indirection** — one `OnceLock`-resolved fn call per cell
   (`reduce` is the slot fn pointer). The slot lookup itself is hoisted, but the
   indirect call is not.
2. **Per-cell AVX2 epilogue.** `var_sum_sse_inner` (`variance_avx2.rs:125`) runs
   `hsum256_epi32` twice (once for sum, once for sse, `variance_avx2.rs:188-189`)
   **per cell** — eight `_mm_add_epi32` + two `_mm_cvtsi128_si32` pulls per call.
   For 64×64 that's 128 horizontal reductions where one per cell would suffice.
3. **Lost cross-cell row reuse.** Horizontally-adjacent cells share rows: a
   32-pixel-wide row already covers four 8-wide cells. Today each cell reloads
   its own 8 bytes from its own offset; the kernel never sees that four cells
   are striding through the same row of memory.

For 32×32 leaves (nh×nw = 4×4 = 16 cells) and 64×64 leaves (8×8 = 64 cells),
these costs add up — and the ≥32×32 path is where PR4's measured 11 % gain lives.

## 2. Prior art (the pattern is in-tree and proven)

- **PR4** wired the per-cell `get_var_sse_8x8` slot and proved the byte-identity
  story end-to-end: per-kernel differential tests assert the AVX2 `(sum, sse)`
  equals the scalar accumulation exactly; the cross-process `RVP9_FORCE_SCALAR`
  oracle (PR1, `caps.rs:55-63`) confirms the AVX2 IVF byte-equals the scalar IVF
  on both foreman and testsrc. **PR5 inherits both layers unchanged** — the
  composite kernel must satisfy the same equality vs the same scalar reference.
- **libvpx prior art.** `vpx_dsp/x86/variance_avx2.c::vpx_get8x8var` is the
  per-cell kernel PR4 mirrored; `vpx_variance{W}x{H}_avx2` are the per-block
  size-generic reductions. The grid-fused form below is not a literal libvpx
  port (libvpx's pickmode loops cell-by-cell, paying the same per-call cost we
  do); it is the natural composition of the existing `madd`-reduction kernel
  scaled out to a 2-D walk. The math is unchanged.
- **Size-generic AVX2 reduction.** `var_sum_sse_inner` (`variance_avx2.rs:125`)
  already handles `w ∈ {4, 8, 16, 32, 64}` × any `h` by chunking each row into
  16-byte sub-blocks. PR5 generalises the same row walk to **keep per-cell
  accumulators instead of one block-level accumulator**, terminating each cell's
  accumulator at the cell-boundary row (`r % 8 == 7`).

## 3. Goal & non-goals

**Goal.** Add a composite **`get_var_sse_8x8_grid`** AVX2 kernel + dispatch slot
that processes the whole 8×8-cell grid in a single call, writing per-cell
`(sum, sse)` out-params. Re-point `compute_variance_8x8` at the slot. Keep the
three scalar finishers (`compute_variance_8x8`'s abs-diff `>>6`, the
`total_sse`/`total_sum` accumulation, and the downstream `aggregate_to_tx_size`)
**byte-for-byte untouched**. Bitstream byte-identical before/after.

**Non-goals.**
- No decision change. PR5 is a pure latency optimization; the per-cell `(sum,
  sse)` values are the same.
- No new finishers, no new slots beyond the one grid kernel. The three Phase-1
  scalar variance finishers stay exactly where PR4 left them.
- No HBD. The encoder is 8-bit; HBD path stays scalar.
- No re-pointing other callers. `model_rd_for_sb_y_large` is the one call site
  in-tree; we re-point it and the unit test (`model_rd.rs:1545,1564`) and stop.
- No replacement of `get_var_sse_8x8` (the PR4 per-cell slot). It stays
  for the tests that pin it; the composite slot is additive.

## 4. Design

### 4.1 The composite kernel

```rust
/// AVX2 composite 8×8-cell `(sum, sse)` reducer over a 2-D `bw × bh` region.
/// `bw, bh` MUST be multiples of 8 and ≥ 8; `sse_out.len() == sum_out.len() ==
/// (bw/8) * (bh/8)`. Writes per-cell `(sum, sse)` in row-major order
/// (`k = i * nw + j` for cell `(i, j)`), byte-exact with calling the per-cell
/// `get_var_sse_8x8` reducer `nh*nw` times.
#[target_feature(enable = "avx2")]
unsafe fn get_var_sse_8x8_grid_inner(
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
    sse_out: &mut [u32], sum_out: &mut [i32],
);
```

The body walks **cell-rows of height 8** then **cell-columns of width 8** in
row-major order. Inside one cell-row (rows `r ∈ ri*8 .. ri*8 + 8`), the kernel:

- Loads each row in 16-byte chunks (the same `_mm_loadu_si128` → `cvtepu8_epi16`
  → `_mm256_sub_epi16` shape `var_sum_sse_inner` already uses).
- Maintains **one `__m256i` sum accumulator + one `__m256i` sse accumulator per
  cell-column** (max `nw = bw/8 ≤ 8`, so up to 8 sum + 8 sse = 16 ymm registers
  — fits AVX2's 16 ymm budget without spill on the 8-cell column case;
  4-cell case uses 8 registers).
- Inside each row, for cell-column `j ∈ 0..nw`, accumulates that 8-pixel slice
  via the existing `accumulate_diff` helper (`variance_avx2.rs:99`):
  `sum_acc[j] += madd(diff_j, ones16)` and `sse_acc[j] += madd(diff_j, diff_j)`.
- Each 32-byte ymm row-load **covers four cell-columns at once** when
  `bw ≥ 32`; the per-column accumulators are kept distinct by **masking the
  `madd` output to one cell's lane group** (or by loading only the 8 bytes
  belonging to one cell — see §4.2). The exact lane discipline is a
  micro-architectural choice within the kernel and is pinned by the
  differential test (§5.1); the **mandate** is that each per-cell
  `(sum_acc[j], sse_acc[j])` ends a cell-row holding exactly the same `i32`
  partials the per-cell `var_sum_sse_inner(8, 8)` call would have ended with.
- At the cell-row boundary (after row `ri*8 + 7`), horizontally reduce each
  cell's `(sum_acc[j], sse_acc[j])` via `hsum256_epi32` and write
  `sum_out[ri*nw + j] = sum`, `sse_out[ri*nw + j] = sse as u32`, then zero
  the per-column accumulators for the next cell-row.

That gives **one `hsum256_epi32` per cell** (down from two per cell today —
the sum and the sse share the cell boundary), **no fn-pointer indirection per
cell** (one indirect call per block instead), and **one ymm load per 32-byte
row stride** (covering four cells horizontally; the 8-cell case uses two loads
per row).

### 4.2 Lane discipline (the one micro-arch choice)

Two equivalent ways to keep per-cell accumulators distinct:

**Option A — per-cell 8-byte loads.** Inside the row loop, load each cell's 8
bytes with `_mm_loadl_epi64` (already used by `var_sum_sse_inner` for the
`tail == 8` case, `variance_avx2.rs:166-168`), widen to one ymm of `i16`,
`madd`-reduce into the cell's accumulator. Simple, no masking, one
`_mm_loadl_epi64` per (row, cell). 8 loads per cell-row of width 8 cells.

**Option B — 32-byte row loads + lane segregation.** Load 32 bytes once,
widen to ymm of `i16` (16 lanes). The 16 `i16` lanes partition into
two groups of 8 lanes — one per cell when stepping by 8 pixels. After
`madd(diff, diff)` the eight `i32` lanes split as `[c0, c0, c0, c0, c1, c1,
c1, c1]` (each cell contributes 4 of the 8 i32 partials, because madd folds
2 i16 lanes → 1 i32). Add lane-masked: `sse_acc[j_base+0] += madd_low_4`,
`sse_acc[j_base+1] += madd_high_4` via `_mm256_and_si256` with the appropriate
mask. Two cells per ymm load → 2 loads per row for the 4-cell case, 4 for
the 8-cell case.

**Recommendation: Option A** for the first cut. It is mechanically obvious
(re-uses the existing `_mm_loadl_epi64`-path code), correctness is by
inspection, and the per-cell-load cost is small (the loads are L1-resident
within a cell-row). The PR can drop in Option B later under the same slot if
microbench shows lane-segregation is faster on the available µarch — but
that decision is a measurement, not part of this design. Both produce the
**identical** per-cell `(sum, sse)` integers (integer addition is
commutative+associative), so byte-identity is preserved either way.

### 4.3 Size dispatch

`bw, bh` must each be a multiple of 8 (debug-asserted). The kernel is one
`(bw, bh)`-generic body; the dispatch slot is a single fn pointer (no per-size
table — there is only one composite kernel). Today's call sites are
`bw,bh ∈ {32, 64}`, but the kernel handles `bw,bh ∈ {8, 16, 24, 32, 40, 48,
56, 64}` because the row-walk is already generic. No speculative extra
abstraction is added — the size range is exactly what the existing
`for i in 0..nh, for j in 0..nw` loop already accepts. (The scalar arm of the
slot is the existing `compute_variance_8x8` body, generic by construction.)

### 4.4 Slot wiring (matches the established convention)

```rust
// dispatch.rs — add one slot alongside `get_var_sse_8x8`
pub(crate) type CellVarGridFn = fn(
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
    sse_out: &mut [u32], sum_out: &mut [i32],
);

pub(crate) get_var_sse_8x8_grid: CellVarGridFn,

// SimdDispatch::build (one clause, mirrors the PR4 get_var_sse_8x8 clause):
#[cfg(target_arch = "x86_64")]
let get_var_sse_8x8_grid: CellVarGridFn = if caps.avx2 {
    crate::dsp::x86_64::get_var_sse_8x8_grid_avx2
} else {
    crate::dsp::distortion::get_var_sse_8x8_grid_scalar
};
#[cfg(not(target_arch = "x86_64"))]
let get_var_sse_8x8_grid = crate::dsp::distortion::get_var_sse_8x8_grid_scalar;

// Accessor (mirrors get_var_sse_8x8):
pub fn get_var_sse_8x8_grid(&self) -> CellVarGridFn { self.get_var_sse_8x8_grid }
```

The **scalar reference** `get_var_sse_8x8_grid_scalar` is the trivial loop:

```rust
pub fn get_var_sse_8x8_grid_scalar(
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
    sse_out: &mut [u32], sum_out: &mut [i32],
) {
    let nw = bw / 8;
    let nh = bh / 8;
    for i in 0..nh {
        for j in 0..nw {
            let k = i * nw + j;
            let s_off = (i * 8) * src_stride + j * 8;
            let p_off = (i * 8) * pred_stride + j * 8;
            let (cs, csse) = get_var_sse_8x8(
                &src[s_off..], src_stride, &pred[p_off..], pred_stride);
            sum_out[k] = cs;
            sse_out[k] = csse;
        }
    }
}
```

This **is** the existing per-cell loop body, lifted into the dsp crate. The
scalar arm of the new slot calls it; the AVX2 arm calls the fused kernel. Both
must produce identical out-arrays (proven by §5.1).

### 4.5 Call-site rewiring

In `compute_variance_8x8` (`model_rd.rs:578`), replace the per-cell loop with
one slot call + the unchanged scalar finisher loop:

```rust
fn compute_variance_8x8(
    grid: CellVarGridFn,           // <- was `reduce: CellVarFn`
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
) -> (u64, i64, [u32; 64], [i32; 64], [u32; 64]) {
    let nw = bw / 8;
    let nh = bh / 8;
    debug_assert!(nw * nh <= 64);

    let mut sse8x8 = [0u32; 64];
    let mut sum8x8 = [0i32; 64];
    let mut var8x8 = [0u32; 64];

    // ONE call — fused per-cell (sum, sse) reductions.
    grid(src, src_stride, pred, pred_stride, bw, bh,
         &mut sse8x8[..nw*nh], &mut sum8x8[..nw*nh]);

    // FINISHER — byte-for-byte unchanged from PR4. Same |sse − (sum²>>6)|
    // per cell, same total_sse / total_sum accumulation.
    let mut total_sse: u64 = 0;
    let mut total_sum: i64 = 0;
    for k in 0..(nw * nh) {
        let cs = sum8x8[k];
        let csse = sse8x8[k];
        let k_sqr = ((cs as i64 * cs as i64) >> 6) as u32;
        var8x8[k] = if csse > k_sqr { csse - k_sqr } else { k_sqr - csse };
        total_sse += csse as u64;
        total_sum += cs as i64;
    }

    (total_sse, total_sum, sse8x8, sum8x8, var8x8)
}
```

The caller hoist is one line: `let grid = crate::dsp::get_ref().get_var_sse_8x8_grid();`
at `model_rd.rs:706`, replacing the existing
`let reduce_8x8 = crate::dsp::get_ref().get_var_sse_8x8();`.

The two existing unit tests at `model_rd.rs:1545,1564` are re-pointed at the
new slot's scalar reference identically. The PR4 per-cell slot
(`get_var_sse_8x8`) stays — it remains the trivial building block for
`get_var_sse_8x8_grid_scalar` and keeps its differential test as the
single-cell pin.

## 5. Test plan

Two layers, mirroring the PR4 plan exactly.

### 5.1 Per-kernel equivalence (unit oracle)

A differential test in `variance_avx2.rs` asserting the **composite kernel
output equals the per-cell scalar reference**, byte-exact, over:

- **All in-scope grid shapes:** `(bw, bh) ∈ {8, 16, 24, 32, 40, 48, 56, 64}²`
  (multiples of 8, both axes). That is 64 shapes; the four hot-path shapes
  ({32,64}²) are tested explicitly, the others rolled into the random sweep.
- **Randomised inputs** (LCG seeded — same RNG `variance_avx2.rs:292`
  already uses) ≥ 256 iterations per shape.
- **Non-contiguous strides** — `src_stride > bw`, `pred_stride > bw`, mirroring
  the convolve/SAD test convention.
- **Corner inputs** — all-zero, all-255, max-diff (`src=0, pred=255`),
  alternating bands (one cell saturating sse, neighbours quiet) — pins
  cross-cell isolation.
- **Assertion shape:**
  ```rust
  let mut sse_a = [0u32; 64]; let mut sum_a = [0i32; 64];
  let mut sse_s = [0u32; 64]; let mut sum_s = [0i32; 64];
  get_var_sse_8x8_grid_avx2(&src, ss, &pred, ps, bw, bh,
      &mut sse_a[..nw*nh], &mut sum_a[..nw*nh]);
  get_var_sse_8x8_grid_scalar(&src, ss, &pred, ps, bw, bh,
      &mut sse_s[..nw*nh], &mut sum_s[..nw*nh]);
  assert_eq!(&sse_a[..nw*nh], &sse_s[..nw*nh], "sse mismatch shape {bw}x{bh}");
  assert_eq!(&sum_a[..nw*nh], &sum_s[..nw*nh], "sum mismatch shape {bw}x{bh}");
  ```
- **Dispatch round-trip** — mirror `variance_avx2.rs:477-479`: a forced-AVX2
  dispatch and a forced-scalar dispatch on the same input must produce
  identical out-arrays. Reachable from inside `rvp9-core` where
  `SimdDispatch::build` is `pub(crate)`.

### 5.2 Encoder byte-identity (system oracle, the gating proof)

**The PR1 cross-process `RVP9_FORCE_SCALAR` oracle is the gate, no changes.**
Run the encoder binary twice on foreman_320x256 and testsrc_720p30:

```
RVP9_FORCE_SCALAR=1 rvp9enc → ivf_scalar
                   rvp9enc → ivf_avx2
md5sum ivf_scalar ivf_avx2     # MUST match
```

Byte-identical IVF on both clips ⇒ the fused kernel moved no decision. Plus:

- `cross_decoder_gate` stays 4/4 (rvp9-encoded byte-exact through rvp9dec
  vs vpxdec).
- `quality_gate` PSNR/SSIM identical to PR4 baseline (belt-and-braces — byte
  equality implies quality equality).

### 5.3 Speed measurement (success criterion)

Foreman 320×256 cpu7 CBR @ {100k, 250k, 500k, 1000k, 2000k} fps measurement,
median of three runs. **PR5 ships iff:**
1. Both oracles green (IVF byte-identical on foreman AND testsrc).
2. cross_decoder_gate 4/4.
3. **Median ≥+3 % fps** over PR4 baseline on the 32×32+ leaf path
   (foreman saturates at small blocks; cif256 / testsrc are the better
   ≥32×32 stress — measure on both).
4. No regression on any clip.

If criterion 3 fails (≤ +2 %), the fused kernel has the right correctness
properties but isn't worth the maintenance burden — **hold and report**
rather than ship. PR4 already gave +11 %; PR5 is incremental.

**Honest expectation.** Per-cell call overhead is real but bounded —
microbench-only estimate is ~2× per-cell reduction throughput (one hsum +
one indirection saved per cell). Translating that through Amdahl with
`compute_variance_8x8` taking maybe 10–15 % of pickmode on ≥32×32 leaves
yields an overall encode-fps win of **~2–4 %**. State this honestly to the
lead: PR5 is a tightening pass on the biggest Phase-1 winner, not a new
multiplier.

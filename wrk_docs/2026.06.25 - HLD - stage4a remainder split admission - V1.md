## 1. Summary

Stage 4a is close enough that the remaining work should be narrow. HEAD `ffc4e7e` already promoted the coupled realtime VBR RD/rate calibration:

- `InterRdCalibration::stage4a_vbr()` enables coefficient-domain RD, `skip_shift=2`, and skip-modecost retention for one-pass VBR + realtime + speed >= 7.
- One-pass VBR's default `bits_per_mb_multiplier` is now 4.0.
- Latest no-env journaled Foreman result: BD-rate `-3.99%`, matched PSNR delta mean `+0.99 dB`, realtime median `25.02 ms`, `vpxdec` byte-exact, `ffmpeg` missing, with only two rvp9 points inside the libvpx bitrate range.

That is not yet Stage 4a sign-off. The PLAN exit still requires:

- 720p30 realtime median <= 33 ms.
- BD-rate within 2% of libvpx at matched config.
- Produced bitstreams decode cleanly under `vpxdec`, `ffmpeg`, and rvp9-decoder.
- Differential differences from libvpx are documented or explained.

The remaining implementation target is **not** more rate-control spend. Prior diagnostics showed extra bits can be spent, but the current picker/partition/TX stack still does not convert them into libvpx-like PSNR. The next build should refine one diagnosed mechanism: A4 `Block16x16 -> 4x Block8x8` split admission in the non-RD partition descent.

## 4. Design

### 4.1 Product Gate Hardening

The current ignored gates skip or report PARTIAL when corpora/tools are absent. That is useful for local development but insufficient for Stage 4a sign-off.

Add strict product variants, or equivalent strict modes in the existing helpers:

1. `quality_gate_stage4a_realcontent_product`
   - Reuses the current Foreman 256x256, 64-frame, one-pass VBR runner.
   - Requires live `vpxenc` and sibling `vpxdec`.
   - Requires finite BD-rate.
   - Requires at least three rvp9 points inside libvpx's bitrate range.
   - Requires monotonic rvp9 and libvpx curves.
   - Requires BD-rate <= +2.0%.
   - Requires matched PSNR delta mean <= +1.0 dB.
   - Reports the old PSNR-delta threshold only as historical context, not as product exit.

2. `cross_decoder_gate_vpxdec_ffmpeg_product`
   - Reuses the current cross-decoder gate.
   - Requires both external decoders for product sign-off.
   - `rvp9-decoder` vs `vpxdec` must be byte-exact.
   - `ffmpeg` must decode all frames and satisfy the existing byte-exact-or-PSNR fallback.

3. `realtime_gate_720p30`
   - Existing gate remains binding: median <= 33 ms.
   - If the product run lands within 2 ms of the budget, run it three times and require all runs to pass.

These variants are ignored tests. They are not normal CI work unless explicitly invoked.

### 4.2 Split Diagnostics

Extend `NonRdSplitStats` narrowly. Keep existing `RVP9_A4_SPLIT_STATS`; do not add a new env flag.

Add counters for `Block16x16 -> 8x8` only:

- `block16_partial_early_out_after_child[4]`: which child index triggered strict early-out.
- `block16_slack_would_continue`: strict early-out would stop, but the proposed slack threshold would continue.
- `block16_slack_completed`: all four children completed under the slack threshold.
- `block16_slack_split_eligible`: completed split was within the slack admission band.
- `block16_slack_split_committed`: final winner at the node was SPLIT via slack.
- `block16_slack_rect_override`: RECT beat a slack-eligible SPLIT within the same admission band.
- `block16_slack_rejected`: completed split exceeded the slack band.

The preflight artifact must be produced under the current promoted baseline before behavior is promoted. The useful question is not "would strict SPLIT have won?" It usually cannot, because strict early-out already says the partial sum exceeded current best. The useful question is "how many failures are close enough to NONE that a bounded small-shape prior could admit them, and do those admitted shapes move block stats in the intended direction?"

### 4.3 Split-Admission Policy

Add a typed policy:

```rust
pub enum Block16SplitAdmission {
    Strict,
    SmallShapeSlack { num: u32, den: u32 },
}
```

Add it to `NonRdDescentParams`, defaulting to `Strict`.

The encoder selects `SmallShapeSlack { num: 1, den: 8 }` only for the Stage 4a realtime VBR/P8 slice described in §3. All other modes keep `Strict`.

The `1/8` value is deliberately a single bounded local calibration constant, not a new sweep surface. It is chosen as the smallest simple band wide enough to test whether the hard early-out is rejecting useful small shapes while still failing closed for grossly bad splits. If this value fails the product gates, do not add env-driven tuning; record the negative result and reopen RD/picker calibration under a new HLD.

### 4.4 Early-Out And Selection Semantics

For `Block16x16 -> 4x Block8x8` only when `SmallShapeSlack` is active:

1. Compute `none_rd` as today.
2. Define `slack = none_rd * num / den`.
3. During the SPLIT child loop, replace the strict early-out threshold:

```text
strict:       partial_split_rd >= current_best_rd
slack-active: partial_split_rd > none_rd + slack
```

This allows finishing children only when the partial sum remains inside the admission band.

4. After all four children complete:

```text
split_actual_rd = rd_cost(sum_rate, sum_dist)
split_eligible = split_actual_rd <= none_rd + slack
```

5. Candidate selection:
   - Strict SPLIT win: unchanged, if `split_actual_rd < current_best_rd`.
   - Slack SPLIT win: allowed if `split_eligible` and no strict candidate beat it.
   - Store and propagate actual `rate` and `dist`; do not discount the bitstream accounting.

6. RECT interaction:
   - RECT remains enabled.
   - A strict RECT win remains unchanged.
   - If SPLIT was selected only by slack, RECT may override it only if:

```text
rect_actual_rd < split_actual_rd
and rect_actual_rd <= none_rd + slack
```

This keeps RECT competitive without accidentally widening the admission policy beyond the parent-NONE slack band.

7. All other block sizes and all non-Stage-4a modes keep existing strict early-out and selection behavior.

### 4.5 Causal Emit Boundary

Do not make the dry-run descent own final mode, residual, skip, or neighbor state.

The current final per-leaf pass remains the source of emitted reconstruction and `mi_grid` updates. The descent may choose shape and may continue to seed/reuse existing safe picker data, but final emit stays raster/causal. This preserves the invariant that the decoder sees the same neighbor state the encoder committed.

### 4.6 Stop Conditions

Stop the build and report rather than stacking more heuristics if any of these are true:

- Preflight stats show almost no slack-eligible cohort.
- Slack-eligible cohorts do not improve block stats.
- Product quality is worse than HEAD after a fair live-libvpx run.
- Realtime fails.
- Cross-decoder validity fails.
- The implementation needs a broad descent refactor to make the policy correct.

If this happens, the next HLD should return to RD-domain/picker/TX ownership, not add another partition scalar.

## 7. Residual Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The 1/8 slack constant is wrong. | Quality or block stats regress. | Single bounded constant, no env sweep; reject if gates fail. |
| BD-rate looks good due to poor curve overlap. | False sign-off. | Require finite BD-rate, monotonic curves, and >=3 overlap points. |
| Extra 8x8 evaluation hurts realtime. | Stage 4a fails performance. | Limit to Block16/P8/VBR slice; realtime gate is blocking. |
| RECT inherits unintended slack. | Partition shape drifts. | RECT override limited to same parent-NONE slack band. |
| Descent/final emit mismatch. | Invalid or poor bitstream. | Preserve causal final emit and run cross-decoder gate. |
| Foreman overfit. | Product does not generalize. | Add held-out natural/WebRTC clips when available; do not claim broader parity from Foreman alone. |
| Preflight refutes split admission. | This HLD's implementation path cannot finish Stage 4a. | Stop and reopen RD/picker/TX ownership design; do not stack scalar tweaks. |

## 8. Decision Log

| Decision | Rationale |
|---|---|
| Base design chosen from simplest-viable draft by 2-of-3 judge majority. | It targets the diagnosed code path with the smallest implementation surface. |
| Grafted risk-first oracle requirements. | The current `-3.99%` BD-rate result has thin overlap and missing `ffmpeg`; product sign-off must be stricter. |
| Grafted testability-first structured diagnostics narrowly. | Need machine-checkable evidence, but broad public diagnostics API and full descent refactor are over-scoped. |
| Use typed policy, not env flag. | Env flags were diagnostic scaffolding; permanent feature toggles add untested modes. |
| Keep `InterRdCalibration::stage4a_vbr()` unchanged. | It is the promoted baseline and already moved the product curve. |
| Keep RECT enabled. | Rect-disable was measured harmful; the issue is split admission, not blindly forcing SPLIT. |
| Use product gate, not historical `+9.1 dB` threshold. | Stage 4a exit is PLAN-level BD-rate/realtime/decode validity. |
| Stop if slack path fails. | Prior work already refuted many scalar-only tweaks; continuing to stack heuristics would be overfitting. |

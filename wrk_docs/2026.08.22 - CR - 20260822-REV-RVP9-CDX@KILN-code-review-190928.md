# Code review — `crates/rvp9-encoder/`

## Result

This bounded static pass reviewed `crates/rvp9-encoder/` through six mixed lenses—correctness, security, performance/scale, reliability, maintainability, and test coverage—plus a devil's-advocate pass. It confirmed five new defects, created five Open bug records, and captured one deliberate loop-filter performance refactor as a Draft Heavy requirement. No Critical finding was confirmed.

The worktree was the fresh `origin/main` baseline supplied by Deltic. Per the review contract, this pass did not fetch, run the application, run tests, run the exploratory harness, modify shipped files, stage, commit, or integrate.

## Confirmed findings

### Medium — qindex 0 is silently changed to 1

- **Confidence:** High
- **Location:** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-190928\crates\rvp9-encoder\src\rate_control\config.rs:117`; `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-190928\crates\rvp9-encoder\src\rate_control\state.rs:532`; `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-190928\crates\rvp9-encoder\src\frame_loop.rs:2983`
- **Impact:** Documented Q mode accepts `cq_level = 0` and selects the lossless edge, but the stream encoder succeeds with qindex 1. An explicit CBR floor of 0 can be overridden the same way.
- **Fix:** Reject qindex-0 configurations at construction until the lossless path exists, or implement lossless end to end and remove the clamp.
- **Effort:** Small to reject; large to implement lossless
- **Tracking:** `RVP9-BUG-KIL-00101`

### Low — enabled E12 diagnostics trust unchecked public geometry

## Confirmed performance and maintainability debt

- **Full-frame loop-filter adapter — Priority Should, confidence high, effort large.** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-190928\crates\rvp9-encoder\src\loopfilter.rs:224` allocates a bordered frame and copies all planes both ways for the default/no-pool path and partial-row heights. This deliberate adapter needs a bit-exact, allocation-counted redesign, captured as `RVP9-REQ-KIL-00106` rather than mislabeled as a correctness bug.
- **Spatial SVC top-source clone — confidence high, effort small.** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-190928\crates\rvp9-encoder\src\spatial_encoder.rs:545` first copies the top source; `spatial_encoder.rs:591` clones the complete tight frame again. Move ownership for ordinary layouts and clone only for the special direct-4x fallback. Report-only optimization.
- **Inter-frame MV-grid churn — confidence high, effort medium.** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-190928\crates\rvp9-encoder\src\frame_loop.rs:4112` allocates and fills a new grid per inter frame, then replaces the previous grid at `frame_loop.rs:5170`. A retained double buffer could remove churn. Report-only optimization.
- **Rate-control documentation drift — confidence high, effort small.** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-190928\crates\rvp9-encoder\src\rate_control\config.rs:108` still says only CBR is ported and other modes panic, while `rate_control/state.rs:451` implements VBR, CQ, Q, and two-pass dispatch. This is a direct documentation correction, not durable requirement work.

## Not reported and why

### Refuted

- `EncoderConfig::use_prev_frame_mvs` appears unused in one gate, but the decoder derives that gate structurally. An independent config switch there would desynchronise encoder and decoder reconstruction.
- The loop-filter parallel wrapper invokes one core worker by design. Its documentation explicitly limits it until row-bounded plane slices make multiple workers alias-safe; the actionable cost is tracked as performance debt.
- Trellis coefficient copies and band-table allocation do not affect the default realtime CPU 6–8 path; their gates restrict them to slower presets.
- Spatial bitrate division truncation matches the documented independent C integer divisions.

### Unverified — held out of the bug queue

- Frame encoding mutates reference, rate-control, cadence, and ALTREF state before some fallible packet writes. A later source might observe partial state after an error, but this static pass did not establish a deterministic valid-input failure plus corrupted reuse. The existing synthetic flush test proves only that another push returns `Ok`. This remains UNVERIFIED and was not filed.
- Several ignored, optional external-decoder tests return early when `vpxdec` is absent. Those skipped checks are UNVERIFIED, not passes; their current comments describe them as informational, so no defect was filed.

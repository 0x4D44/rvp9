# G1 — Wire UV RD into the inter-mode picker

**Date:** 2026-05-24
**Status:** Design
**Scope:** Add chroma (U+V) model-RD to the per-candidate cost in `pick_inter_mode`

## 1. Problem

The inter-mode picker (`pick_inter_mode`) evaluates candidates on luma-only
RD cost. Chroma planes are ignored during mode selection, which means the
picker cannot distinguish candidates that differ significantly in chroma
fidelity (e.g. a ZEROMV that nails luma but destroys chroma vs a NEWMV that
handles both). libvpx's `vp9_pick_inter_mode` (pickmode.c:2378-2393) adds
UV model-RD to `this_rdc` after the luma model_rd + block_yrd steps.

## 2. Existing infrastructure

`model_rd_for_sb_uv` in `crates/rvp9-core/src/mode_decision/model_rd.rs:441`
already implements the UV variance-domain RD model. Signature:

```rust
pub fn model_rd_for_sb_uv(
    src_u: &[u8], src_u_stride: usize,
    pred_u: &[u8], pred_u_stride: usize,
    src_v: &[u8], src_v_stride: usize,
    pred_v: &[u8], pred_v_stride: usize,
    bw: usize, bh: usize,          // luma dimensions (halved internally)
    bsize: BlockSize,
    dc_quant: u32, ac_quant: u32,   // chroma dequant values (raw)
) -> ModelRdUvResult { rate: i32, dist: i64 }
```

It is tested but uncalled from the picker.

## 3. What changes

### 3.1 New fields on `PickInterModeParams` (inter.rs)

| Field | Type | Purpose |
|---|---|---|
| `src_u` | `&'a [u8]` | Source U plane (full frame buffer) |
| `src_u_stride` | `usize` | Stride of U plane |
| `src_v` | `&'a [u8]` | Source V plane (full frame buffer) |
| `src_v_stride` | `usize` | Stride of V plane |
| `last_ref_u` | `&'a [u8]` | LAST recon U plane (full frame buffer) |
| `last_ref_v` | `&'a [u8]` | LAST recon V plane (full frame buffer) |
| `golden_ref_u` | `&'a [u8]` | GOLDEN recon U plane (full frame buffer) |
| `golden_ref_v` | `&'a [u8]` | GOLDEN recon V plane (full frame buffer) |
| `uv_stride` | `usize` | Stride of all UV planes (= w/2 for 4:2:0) |
| `uv_dc_quant` | `u32` | Chroma DC dequant (`dequant[0]` from UV quantizer) |
| `uv_ac_quant` | `u32` | Chroma AC dequant (`dequant[1]` from UV quantizer) |

**Design note — raw slices, not `PlaneRef`:** The UV planes are only used
for variance computation (no MV search), so the lighter `&[u8]` + stride
avoids adding `PlaneRef` width/height fields the model never reads. The
chroma block offset is derived from the luma `src_offset` via `>> 1` (4:2:0).

**Quantizer:** The caller already has `q_index` and currently sets
`uv_dc_delta_q = 0`, `uv_ac_delta_q = 0` everywhere, so UV dequant equals
`plane_dequant_pair(q_index, QuantizerDeltas { dc_delta: 0, ac_delta: 0 })`.
Rather than threading a full `PlaneQuantizers` for UV, pass just the two
dequant values the model needs. If deltas become non-zero later, the caller
updates the values it passes.

### 3.2 New fields on `InterModeSearchParams` (inter.rs)

Same UV fields as 3.1 above, minus the GOLDEN/LAST split (this struct is
per-ref). Add:

| Field | Type |
|---|---|
| `src_u` | `&'a [u8]` |
| `src_v` | `&'a [u8]` |
| `ref_u` | `&'a [u8]` |
| `ref_v` | `&'a [u8]` |
| `uv_stride` | `usize` |
| `uv_dc_quant` | `u32` |
| `uv_ac_quant` | `u32` |

### 3.3 Integration point: `evaluate_candidate_for_filter` (inter.rs:1313)

After the luma `model_rd_for_sb_y` call (line ~1363) and before the rate
accumulation (line ~1564), insert:

1. **Build UV MC prediction.** Call `build_inter_prediction` for U and V
   into local scratch buffers `pred_u: [u8; 32*32]`, `pred_v: [u8; 32*32]`.
   The MV is the same luma MV, scaled for 4:2:0 chroma:
   - `uv_mv.col = mv.col`  (no scaling for 4:2:0 in non-sub-8 blocks)
   - `uv_mv.row = mv.row`
   - Chroma src offset: `(src_offset.0 >> 1, src_offset.1 >> 1)`
   - Chroma block dims: `(bw >> 1, bh >> 1)`

2. **Call `model_rd_for_sb_uv`.** Pass the source UV slices at the chroma
   offset, the scratch prediction buffers, luma `bw`/`bh`, `block_size`,
   and the chroma dequant pair.

3. **Add UV rate+dist to `this_rdc`.** Mirror libvpx pickmode.c:2390-2393:
   ```
   rate += uv_result.rate.max(0) as u32;
   dist  = (dist as i64 + uv_result.dist).min(u32::MAX as i64) as u32;
   ```
   These feed into the existing `rd_cost(lambda, rate, dist)` computation.

### 3.4 Caller wiring: `encode_inter_frame_sb` (lib.rs:3213)

At the `pick_params` construction site (~line 3213), populate the new UV
fields from the existing `input_yuv.1`/`.2` and `last_recon_yuv.1`/`.2` /
`golden_recon_yuv.1`/`.2` buffers. These are already available in scope.
UV stride = `w / 2` (already computed as `uvw`).

UV dequant: call `plane_dequant_pair(leaf_qindex as i32,
QuantizerDeltas { dc_delta: 0, ac_delta: 0 })` to get `(dc_quant, ac_quant)`.

### 3.5 Intra-in-inter fallback

The `evaluate_intra_fallback` function (inter.rs:866) does NOT need UV RD
in this phase. libvpx's intra-in-inter path at speed >= 5 also skips UV
model_rd for the intra candidates. Defer to a follow-up if needed.

## 4. UV MC prediction — dependency analysis

The picker's `build_inter_prediction` (inter.rs:1653) works on a single
plane. It takes a `PlaneRef` for the reference, an offset, an MV, block
dims, a scratch buffer, and a filter. It already handles sub-pel
interpolation via `convolve8*`.

For UV, we need to call this function twice (U, V) with:
- `ref_plane` pointing at the chroma ref buffer (not a `PlaneRef` today)
- Chroma offset = `(luma_x >> 1, luma_y >> 1)`
- Chroma block dims = `(bw >> 1, bh >> 1)`
- Same filter as luma (libvpx behaviour)
- MV: same Q3 MV as luma (VP9 4:2:0 non-sub-8 blocks use the full-res
  MV directly on the chroma plane; the sub-pel phase doubles via the
  `1 << (1 - ss)` formula at the call site)

**Issue:** `build_inter_prediction` takes `PlaneRef` but the new UV fields
are `&[u8]` + stride. Options:
- **(A)** Construct temporary `PlaneRef` values at the call site.
  Cheap (4-field struct copy), no API change. **Preferred.**
- **(B)** Refactor `build_inter_prediction` to take `&[u8]` + stride.
  Wider blast radius, not needed.

**MV bounds:** The luma `mv_limits` already ensures the MV stays inside
the reference frame. Chroma dims are smaller, so the same MV guarantee
holds (the chroma plane is half the frame and the chroma block is half the
luma block; the margin is preserved). No additional bounds check needed.

## 5. Open questions

1. **Lambda calibration.** Adding UV rate+dist changes the RD landscape.
   The current lambda was calibrated for luma-only RD. UV RD may shift
   mode preferences (especially at low q where chroma detail matters).
   Monitor PSNR-Y and PSNR-UV on the standard test clips after wiring.
   If PSNR-Y regresses, the UV contribution may need a dampening factor
   (e.g. `uv_rate >> 1`) — but start with the 1:1 libvpx behaviour.

2. **Block8x8 chroma.** At 4:2:0, an 8x8 luma leaf has a 4x4 chroma
   block. `model_rd_for_sb_uv` calls `uv_plane_block_size` which handles
   this. Verify `num_pels_log2(Block4x4)` returns 4 (= log2(16)).

3. **Skip-flag tie-break (F.1).** The skip-flag comparison at line ~1611
   uses `sse_after_pred` which is luma-only. libvpx's pickmode.c:2355
   uses `this_sse` which is also luma-only at that point (UV SSE is
   NOT added to `this_sse`, only to `this_rdc.dist`). So no change
   needed to the skip-flag path.

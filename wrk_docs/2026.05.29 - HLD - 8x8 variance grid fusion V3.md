> **One-line thesis.** `compute_variance_8x8` resolves the per-cell AVX2 `(sum,
> sse)` reducer through a dispatch **function pointer and calls it once per 8×8
> cell** (16× for 32×32, 64× for 64×64). An indirect call to a separate
> `#[target_feature]` function cannot be inlined, so each cell pays a full call
> prologue/epilogue. Move the cell loop *inside* one dispatched grid kernel: one
> indirect call per block, and the per-cell 8×8 reduction becomes a **direct,
> inlinable** call to the existing `var_sum_sse_inner(8,8)`. Same `(sum, sse)`
> integers → bitstream byte-identical.

> **⚠ This is a measurement-gated spike, expected to CANCEL.** The win is *only*
> per-cell call-overhead; it does **not** halve horizontal reductions and adds
> **no** row-load reuse. The honest projection is below the `+3 %` ship gate. **The
> default outcome is: do Stage 0 (measure), then cancel and go to Phase-2.** Stage
> 1 (the kernel) is written *only if* Stage 0 surprises upward. Read §1.0 and §6
> first.

## 1. Problem

### 1.0 Stage 0 — measure first; the justification below is UNVERIFIED for the current binary

V1 justified targeting `compute_variance_8x8` by citing "the 37.4 % per-final-leaf
cost". That number is **misattributed**: the predecessor HLD
(`Encoder hot-path SIMD (speed).md:29`) defines **37.4 % as the cost of the entire
final-leaf `pick_inter_mode` evaluation** — MC convolve + SAD + sub-pel variance +
`block_yrd` + this — **not** `compute_variance_8x8` alone. That baseline predates
PR2/PR3/PR4 (which SIMD-ported SAD / sad4d / variance / sub-pel; commits `1806f7a`,
`9a9ef93`, `f7a965a`) and the Phase-2 option-A commit (`c5c9b9f`) that changed the
descent. The predecessor (`:510-511`, `:649`, `:683-685`) and the Phase-2 HLD
(`R6`) **mandate re-baselining** before sizing further work. V1's "~10–15 % of
pickmode" Amdahl input is **unsourced** — it appears in no profiling document.

**Stage 0 is the actual first deliverable. It writes NO production code, NO
dispatch slot, and NO permanent tests.** It produces two numbers and a decision:

1. **Self-cost `F`.** Profile the post-Phase-1, post-option-A `target/release`
   binary on a 64×64-heavy clip and measure the wall-clock fraction spent in
   `compute_variance_8x8` *itself* (not the whole leaf) — e.g. `perf annotate`, or
   a scoped counter around `model_rd.rs:706`.
2. **Microbench speedup `S`.** Write a **throwaway** local bench (scratch file or
   `#[bench]`, *not* wired into dispatch, deleted after) comparing today's per-cell
   path against the Stage-1 simple kernel, on cache-hot and cache-cold inputs for
   32×32 and 64×64. This measures the real per-cell call-overhead saving **and**
   settles the bandwidth question (§1.2): if the kernel is memory-bound, `S ≈ 1`.
   Because the bench times the whole `compute_variance_8x8` (kernel + finisher), it
   also captures the two-pass round-trip (§4.5) — no separate assertion needed.
3. **Decision gate.** Projected overall win ≈ `F · (1 − 1/S)`. **Proceed to Stage 1
   only if that projection is `≥ +3 %`.** Otherwise record the negative result in
   the journal, delete the throwaway bench, and redirect to Phase-2 (the 52.7 %
   partition double-pick). **This is the expected branch.**

Everything from §1.1 onward specifies Stage 1, which is built only if the gate
above clears.

### 1.1 The one real cost (Stage-1 rationale)

`compute_variance_8x8` (`model_rd.rs:578-621`) is the per-leaf variance grid loop
for ≥32×32 blocks. Today it calls a dispatch function pointer `reduce` once per
cell. The pointer lookup is already hoisted and the indirect *branch* is near-free
(a single repeated BTB target). The cost is **not** misprediction; it is that the
callee (`get_var_sse_8x8_avx2` → `var_sum_sse_inner`) is a separate
`#[target_feature]` function reached through a pointer, so the compiler **cannot
inline it**, and each cell pays a full **call prologue/epilogue** (16× / 64×).

Honesty about magnitude: the only other per-cell item that inlining would remove is
the loop-invariant `ones16 = _mm256_set1_epi16(1)` setup (`variance_avx2.rs:139`) —
but that is **one broadcast uop per cell**, negligible against the cell's ~64 madds
+ 2 hsums + loads. So the saving is essentially **the call boundary alone**. Whether
that is worth anything against the per-cell arithmetic is exactly what Stage 0's
microbench measures; it is **expected, not proven**, that the per-cell version
stalls on the call boundary rather than on loads.

Moving the cell loop into one dispatched kernel turns 16/64 un-inlinable indirect
calls into **one** indirect call per block, with the per-cell reduction inlinable.

### 1.2 What this does NOT fix (so the win is not over-sold)

- **Horizontal reductions are unchanged at 2 per cell.** `var_sum_sse_inner` keeps
  two independent accumulators (`sum_acc`, `sse_acc`) and reduces each with its own
  `hsum256_epi32` (`variance_avx2.rs:188-189`). A grid kernel must still produce
  both `(sum, sse)` per cell → still **2 hsum256 per cell**, exactly as today. V1's
  "one hsum per cell (down from two)" was arithmetically wrong (sum and sse are
  distinct registers). **This design saves zero hsum operations.**
- **No cross-cell row-load reuse.** The simple kernel calls `var_sum_sse_inner(8,8)`
  per cell, which loads each cell's own 8 bytes per row. The theoretical "one wide
  load feeds several cells" win needs per-cell-column accumulators + lane masking
  (V1's withdrawn Option B), the loads are already L1-resident, and the spill risk
  is not worth a marginal unproven gain. A future row-reuse kernel is a **separate
  PR**, not a fork here.
- **It cannot beat a memory-bandwidth bound.** `compute_variance_8x8` streams the
  full src+pred (64×64 = 16 KB touched) at ~2 ops/byte — low arithmetic intensity.
  If bandwidth-bound, removing the call boundary changes nothing. **Stage 0's
  cache-hot-vs-cold microbench is the test of this**; if `S ≈ 1`, cancel.

## 3. Goal & non-goals

**Goal (Stage 1, contingent on Stage 0).** Replace the per-cell dispatch with one
block-level grid slot: add `get_var_sse_8x8_grid_avx2` (an inlinable cell loop over
`var_sum_sse_inner(8,8)`) + its scalar reference, wire one `get_var_sse_8x8_grid`
slot, re-point `compute_variance_8x8`. Keep the finisher arithmetic
(`compute_variance_8x8`'s abs-diff `>>6`, and downstream `aggregate_to_tx_size`)
verbatim. Bitstream byte-identical.

**Non-goals.**
- No decision change (pure latency).
- No per-cell-column accumulators, no lane masking, no Option A/B (withdrawn).
- No cross-cell row-load reuse (§1.2 — deferred).
- No HBD (8-bit encoder; HBD stays scalar).
- No speculative size genericity — asserted to the 4 reachable shapes
  (`bw, bh ∈ {32, 64}`); see §4.3.

### 3.1 Why byte-identity (and its ceiling)

Byte-identity is a **deliberate de-risking choice**, not a law.
`compute_variance_8x8` feeds an RD *model* (a skip / TX-size heuristic), not a
reconstruction path; its finishers are already `>>6` approximations. A
*quality-gated, non-byte-identical* variance could in principle yield a much larger
speedup at negligible BD-rate cost, bounded by the existing PSNR/SSIM oracles. We
**explicitly defer** that larger lever: byte-identity is what makes PR5 zero-risk
and reviewable in one sitting. The cost is a **low ceiling** — PR5 can only
re-package the same integer ops, which (§1.2) may be near-zero gain. The lead should
weigh "safe-but-small PR5" against "skip to a quality-gated variance, or Phase-2"
with this ceiling in mind.

## 4. Design (Stage 1 — built only if §1.0 clears)

### 4.1 The grid kernel

```rust
/// AVX2 unsafe core: per-8×8-cell `(sum, sse)` reduction over a `bw × bh` region.
/// `bw, bh ∈ {32, 64}`; `nw = bw/8`, `nh = bh/8`. Writes per-cell `(sum, sse)` in
/// row-major order (`k = i*nw + j`), byte-exact with calling `var_sum_sse_inner(8,8)`
/// `nh*nw` times.
///
/// # Safety
/// AVX2 must be available. `src.len() >= (bh-1)*src_stride + bw`,
/// `pred.len() >= (bh-1)*pred_stride + bw`, `sse_out.len() == sum_out.len() == nw*nh`.
#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
unsafe fn get_var_sse_8x8_grid_inner(
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
    sse_out: &mut [u32], sum_out: &mut [i32],
) {
    debug_assert!(matches!(bw, 32 | 64) && matches!(bh, 32 | 64));
    let nw = bw / 8;
    let nh = bh / 8;
    debug_assert_eq!(sse_out.len(), nw * nh);
    debug_assert_eq!(sum_out.len(), nw * nh);
    debug_assert!(src.len() >= (bh - 1) * src_stride + bw);
    debug_assert!(pred.len() >= (bh - 1) * pred_stride + bw);

    for i in 0..nh {
        for j in 0..nw {
            let k = i * nw + j;
            let s_off = (i * 8) * src_stride + j * 8;
            let p_off = (i * 8) * pred_stride + j * 8;
            // Direct call into the same #[target_feature] fn → INLINABLE. Each cell
            // keeps only its own (sum_acc, sse_acc) live: 2 accumulators, no spill.
            let (sum, sse) = var_sum_sse_inner(
                &src[s_off..], src_stride, &pred[p_off..], pred_stride, 8, 8);
            sum_out[k] = sum as i32;
            sse_out[k] = sse as u32;
        }
    }
}

/// Thin safe wrapper installed in the dispatch slot (mirrors `var_sum_sse_avx2`,
/// `variance_avx2.rs:200`). The slot holds this, never the unsafe `_inner`.
#[cfg(target_arch = "x86_64")]
pub fn get_var_sse_8x8_grid_avx2(
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
    sse_out: &mut [u32], sum_out: &mut [i32],
) {
    // SAFETY: installed only on AVX2 hosts by SimdDispatch::build (caps.avx2).
    unsafe {
        get_var_sse_8x8_grid_inner(
            src, src_stride, pred, pred_stride, bw, bh, sse_out, sum_out)
    }
}
```

A double loop calling the proven inner. No accumulator sweep, no lane discipline,
no masks, no spill. Two accumulators are live at any moment (inside one inlined
`var_sum_sse_inner`), so the 64×64 case has the same register pressure as today.

### 4.2 Why this is byte-identical

`get_var_sse_8x8_grid_inner` calls `var_sum_sse_inner(8,8)` — the **same** function
the current per-cell slot calls — once per cell, in the **same** `k = i*nw + j`
order, so the integers it writes are definitionally equal to `nh*nw` per-cell calls.
The scalar reference (§4.4) loops the existing scalar `get_var_sse_8x8` by the same
argument. The differential test (§5.1) pins the two against each other.

### 4.3 Size domain (no speculative generality)

`compute_variance_8x8`'s only caller is `model_rd_for_sb_y_large`
(`model_rd.rs:688`, dispatched only for `block_size ≥ Block32x32`), so the reachable
shapes are exactly **32×32, 32×64, 64×32, 64×64** → `nw, nh ∈ {4, 8}`, 4 shapes
(max 64 cells). The kernel `debug_assert!`s that domain, mirroring how
`var_sum_sse_inner` asserts `w ∈ {4,8,16,32,64}`.

### 4.4 Slot wiring (matches convention)

### 4.5 Call-site rewiring

In `compute_variance_8x8` (`model_rd.rs:578`), replace the per-cell loop with one
slot call + the finisher:

```rust
fn compute_variance_8x8(
    grid: CellVarGridFn,            // was: reduce: fn(&[u8],usize,&[u8],usize)->(i32,u32)
                                    //      (a bare fn-ptr inline at model_rd.rs:579,
                                    //       NOT the CellVarFn alias)
    src: &[u8], src_stride: usize, pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
) -> (u64, i64, [u32; 64], [i32; 64], [u32; 64]) {
    let nw = bw / 8; let nh = bh / 8;
    debug_assert!(nw * nh <= 64);
    let mut sse8x8 = [0u32; 64];
    let mut sum8x8 = [0i32; 64];
    let mut var8x8 = [0u32; 64];

    grid(src, src_stride, pred, pred_stride, bw, bh, &mut sse8x8[..nw*nh], &mut sum8x8[..nw*nh]);

    // FINISHER. The abs-diff `>>6` arithmetic is verbatim from PR4. The total
    // accumulation is RELOCATED into this second loop (it was interleaved in the
    // per-cell loop before). That relocation is byte-identical: u64/i64 integer
    // addition is associative and the visitation order (k = i*nw + j) is preserved.
    // The read-back of sse8x8/sum8x8 is ≤512 B from L1 (64 cells × 8 B); its cost
    // is included in Stage 0's end-to-end microbench, not assumed away.
    let mut total_sse: u64 = 0; let mut total_sum: i64 = 0;
    for k in 0..(nw * nh) {
        let cs = sum8x8[k]; let csse = sse8x8[k];
        let k_sqr = ((cs as i64 * cs as i64) >> 6) as u32;
        var8x8[k] = if csse > k_sqr { csse - k_sqr } else { k_sqr - csse };
        total_sse += csse as u64; total_sum += cs as i64;
    }
    (total_sse, total_sum, sse8x8, sum8x8, var8x8)
}
```

The caller hoist (`model_rd.rs:706`) becomes
`let grid = crate::dsp::get_ref().get_var_sse_8x8_grid();`.

The two unit tests at `model_rd.rs:1545,1564` currently pass
`crate::dsp::distortion::get_var_sse_8x8` to `compute_variance_8x8`. Because the
first parameter's **arity changes** (per-cell `fn` → grid `CellVarGridFn`), they are
**rewritten** to pass `get_var_sse_8x8_grid_scalar` with the new call shape — not a
symbol swap. Their concrete assertions (e.g. `sse=256, sum=128, var=0` per cell) are
**unchanged** and still hold, because the grid scalar ref delegates to the same
`get_var_sse_8x8`.

## 5. Test plan (Stage 1)

Two layers, mirroring PR4. Note the grid kernel just re-loops the already-tested
`var_sum_sse_inner(8,8)`, so the new tests target the **only new surface: the
per-cell write-index** (`k = i*nw + j`) and the slot wiring — not the reduction math
(already pinned by `differential_8x8_cell`).

### 5.1 Per-kernel equivalence (unit oracle)

A differential test in `variance_avx2.rs` asserting **grid AVX2 == grid scalar**,
byte-exact, over the **4 reachable shapes** `(bw, bh) ∈ {32, 64}²`:

- **Primary new test — cross-cell isolation sweep.** The kernel's only real failure
  mode is a cell's bytes landing in a neighbour's output slot. For each shape, set
  exactly one cell to max-diff (`src=0, pred=255`), all others to `diff=0`, sweep
  the hot cell across all `nw*nh` positions, and assert **only** that cell's
  `(sum, sse)` is non-zero. This pins the write-index directly (random content
  masks an off-by-one).
- **Defense-in-depth random differential** — the existing LCG (`variance_avx2.rs:292`),
  ≥512 iters per shape, non-contiguous strides (`stride > bw`). This largely
  overlaps `differential_8x8_cell` (same inner); keep it thin, as a cheap belt.
- **Buffer-tight safety case** — one iter with `stride == bw` and
  `len == (bh-1)*stride + bw` (no padding) to exercise the bottom-right cell against
  the buffer end. (`var_sum_sse_inner`'s `tail==8` path reads exactly 8 bytes via
  `_mm_loadl_epi64`, so this is safe; run under Miri/ASAN where available.)
- **Dispatch round-trip** — replace the deleted per-cell sub-test
  (`variance_avx2.rs:470-480`): `build(avx2:true)` vs `build(avx2:false)` must
  produce identical out-arrays for the grid slot.

### 5.2 Encoder byte-identity (system oracle, the gate)

The PR1 cross-process `RVP9_FORCE_SCALAR` oracle, unchanged (no new env var):

```
RVP9_FORCE_SCALAR=1 rvp9enc → ivf_scalar
                   rvp9enc → ivf_avx2
md5sum ivf_scalar ivf_avx2     # MUST match
```

Byte-identical IVF on **both** foreman_320x256 and testsrc_720p30 ⇒ no decision
moved. Plus `cross_decoder_gate` stays 4/4 and `quality_gate` PSNR/SSIM identical to
the PR4 baseline.

### 5.3 Speed measurement (success criterion — statistically powered)

This is Stage 0's measurement, re-run as the Stage-1 acceptance check. A 2–4 %
effect is below typical run-to-run fps variance, and byte-identity tests cannot see
a *slowdown*, so:

1. Pin the CPU (fixed frequency / turbo off / `taskset` to isolated cores).
2. Foreman 320×256 + testsrc_720p30, cpu7 CBR @ {100k, 250k, 500k, 1000k, 2000k}.
   **≥10 runs**; report median **and** a bootstrap / Mann-Whitney CI plus the
   observed per-run stddev.
3. **Ship-gate (all required):** both oracles green (both clips); `cross_decoder_gate`
   4/4; median **≥ +3 %** over PR4 baseline **AND** the CI lower bound clears 0
   (no-regression guard — a CI including a regression ⇒ hold, even if the median
   looks positive); no regression on any clip.

**Honest expectation.** With hsum-halving and row-reuse removed (§1.2) and the
`ones16` hoist worth ~one uop/cell (§1.1), the only saving is the per-cell call
boundary — likely a small fraction of the per-cell reduction, itself only fraction
`F` of encode. The realistic overall win is **likely below `+3 %`**, so the
**expected outcome is hold-and-report** with Phase-2 (52.7 %) as the real lever.

## 7. Risks & rollback

| # | Risk | Handling |
|---|---|---|
| R1 | A per-cell `(sum, sse)` is written to the wrong `k` (cells swap). | §5.1 cross-cell isolation sweep asserts only the single hot cell is non-zero across all `nw*nh` positions, all 4 shapes — a direct pin on the write index. Full-array differential vs the scalar ref blocks any other mismatch. |
| R2 | Overflow where the per-cell call wouldn't. | Impossible: same `var_sum_sse_inner(8,8)` per cell, same `i32`/`u32` cast, no cross-cell accumulation. 8-bit 8×8 cell: `diff ∈ [-255,255]`, `\|sum\| ≤ 16320` (i32), `sse ≤ 4,161,600` (u32); each mid-cell madd-lane partial ≤ `8·4·65025 ≈ 2.08M` (i32). Integer add is associative. |
| R3 | Memory safety / OOB read. | `var_sum_sse_inner(8,8)` uses `_mm_loadl_epi64` (exactly 8 bytes/row) — no over-read past the cell. Entry `debug_assert`s on buffer + out-array lengths; §5.1's buffer-tight case exercises the bottom-right edge under Miri/ASAN. |
| R4 | Win below `+3 %` (or `compute_variance_8x8` no longer hot). | **The expected case.** Stage 0 catches it before any production code; hold and redirect to Phase-2. |
| R5 | The fusion is a *pessimization* (two-pass round-trip, or bandwidth-bound). | Stage 0's end-to-end, hot-vs-cold microbench measures the whole function incl. the round-trip; §5.3's no-regression CI guard blocks shipping a slowdown byte-identity tests cannot see. |

**Rollback.** If Stage 1 ships and regresses, reverting the single PR restores the
per-cell slot and `model_rd.rs:706`. (Trivial; no migration concerns.)

## 8. Executive summary (for the lead)

- **This is a measurement spike, not a feature PR.** Stage 0 measures
  `compute_variance_8x8`'s real self-cost `F` and a throwaway microbench speedup `S`
  — **zero production code**. Stage 1 (the kernel) is written **only if**
  `F·(1−1/S) ≥ +3 %`. The expected branch is **cancel → Phase-2**.
- **Why the doubt.** V1's "37.4 %" justification was a misattributed, pre-Phase-1
  whole-leaf number; its "10–15 %" Amdahl input was invented. The genuine saving is
  *only* the per-cell call boundary — fusion does **not** halve hsums (still 2/cell)
  and adds **no** row reuse; the `ones16` hoist is one uop. The loop streams 16 KB
  at ~2 ops/byte and may be bandwidth-bound.
- **If built, it is correct and tiny.** Stage 1 loops the same proven
  `var_sum_sse_inner(8,8)` per cell → byte-identical by construction; finisher
  arithmetic verbatim (accumulation merely relocated, associativity-exact); the
  `RVP9_FORCE_SCALAR` IVF oracle gates it; ~175 LOC, no lane discipline, no spill,
  no unreachable-size generality, and it **deletes** the now-dead per-cell slot.
- **Phase 2 (52.7 % partition double-pick) remains the real lever.** A Phase-2
  option-A commit (`c5c9b9f`) just landed and changed the descent this PR's baseline
  assumed — another reason to re-baseline (Stage 0) before spending kernel effort.

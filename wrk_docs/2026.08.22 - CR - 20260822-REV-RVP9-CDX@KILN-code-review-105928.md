## Actionable detail

### RVP9-BUG-KIL-00081 — tile-view soundness

`TileMiView::new` documents lifetime, exclusivity, non-overlap, and row ordering, but not bounds/stride validity. Safe `new_with_view` then accepts unrelated dimensions and offsets. A consistent one-cell view paired through the safe constructor with an offset outside that cell passes `mi_at`'s release build because its only check is `debug_assert!`; the following raw-pointer dereference is out of bounds. Separately, an out-of-range safe `write_block` origin can underflow the slice length before `from_raw_parts_mut`.

The fix should concentrate unsafe geometry in one validated abstraction. The regression should cover mismatched context/view offsets and writes beginning beyond the right or bottom bound, preferably under Miri.

### RVP9-BUG-KIL-00082 — per-tile metadata amplification

The intra path retains one full-frame segment map per tile. The inter path retains both that map and a full-frame previous-MV grid per tile. The merge loops prove only each tile rectangle is needed. This is independent of active worker count and persists at the maximum tile count seen.

This does not duplicate `RVP9-BUG-KIL-00080`, which covers full-frame YUV scratch and its allocation panic. Both fixes may share a scheduler-level design, but they own different buffers and need separate capacity assertions.

### RVP9-BUG-KIL-00083 — false-green recovery oracle

The public `Decoder` documentation promises a successful valid-inter decode after a mid-tile failure. The named test treats every non-`EmptyInterRef` failure as acceptable. That branch proves only that the reference map survived; it cannot detect broken recovery decoding.

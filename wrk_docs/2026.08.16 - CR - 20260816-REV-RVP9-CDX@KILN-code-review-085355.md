# Code review: `crates/rvp9-encoder/`

Date: 2026-08-16  
Baseline: Deltic-supplied fresh `origin/main` worktree; no fetch was run by contract.  
Method: static source review only. No application, test suite, benchmark, or exploratory harness ran.

## Outcome

This pass confirmed five shipped-behavior defects: two High and three Medium. It filed all five in the Open bug queue. It also captured three bounded structural improvements as Draft heavy requirements. No source files were changed.

Seven independent lenses covered correctness, security, performance and scale, reliability, maintainability, test coverage, and implicit assumptions. The lead then re-read each cited implementation path and rejected or held claims without a reachable failure or a clear contract.

## Confirmed defects

### High — ALTREF panics on legal partial-height streams

- Bug: `RVP9-BUG-KILN-00069`
- Confidence: High
- Evidence: `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:2117` accepts every positive even height. The ALTREF trigger at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:3108` can then call `vp9_temporal_filter`, whose public implementation asserts 32-row alignment at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\temporal_filter.rs:1528`. Thus ordinary 1280×720 and 1920×1080 streams panic once ALTREF is due. A height divisible by 32 but not 64 reaches a second mismatch: the ARF uses visible-height planes at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:5282`, while reference commits require height rounded to 64 at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\buffer_pool.rs:690`.
- Concrete fix: process visible edge macroblocks and use reference-pool padded storage for the ARF reconstruction. Add delayed encode plus flush regressions at 720p, 1080p, and a height divisible by 32 but not 64; decode the emitted superframe.
- Effort: Medium, about 2–4 engineer-days.

### High — parallel tile scratch retains one full frame per tile

- Bug: `RVP9-BUG-KILN-00070`
- Confidence: High
- Evidence: `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:2096` permits 64 threads and six tile-column bits. When at least two workers are active, `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:2191` allocates full-frame YUV, MV-grid, and partition-grid scratch for every tile. Resizing the YUV vectors to tile width at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:4466` does not release their capacity. At the supported 16,384×4,096 luma envelope, 64 YUV scratch sets retain 6 GiB before MV grids, partitions, references, or the main reconstruction.
- Concrete fix: allocate tile-local scratch or one reusable set per active worker. Expose a pure allocation plan and test its retained-capacity budget at maximum supported geometry without attempting an OOM-sized allocation.
- Effort: Medium to large, about 3–6 engineer-days.

### Medium — the legacy public `Encoder` accepts dimensions that overflow derived geometry

- Bug: `RVP9-BUG-KILN-00071`
- Confidence: High
- Evidence: `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\lib.rs:339` checks only nonzero, 64-aligned dimensions. The keyframe path multiplies `u32` MI dimensions before converting to `usize` at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\lib.rs:729`, then allocates derived tile storage infallibly at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\lib.rs:774`. A documented-valid 524,288×524,288 configuration overflows in debug builds or wraps in release builds. This is not a duplicate of the earlier modern `StreamEncoder` bounds bug.
- Concrete fix: share the modern maximum dimension and luma-pixel validation, then use checked arithmetic for every derived count and allocation size. Reject oversized aligned configurations before allocation.
- Effort: Small, less than one engineer-day.

### Medium — saturating stream counters eventually freeze GOP and keyframe cadence

- Bug: `RVP9-BUG-KILN-00072`
- Confidence: High
- Evidence: the `u32` counter declared at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:1331` advances with `saturating_add` at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:3239`. GOP scheduling takes that frozen value modulo the interval at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\gop.rs:199`. `SpatialEncoder` repeats the pattern at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\spatial_encoder.rs:115` and `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\spatial_encoder.rs:319`. At 60 fps the boundary arrives after about 2.27 years; later cadence either stops or repeats a boundary forever, depending on the interval.
- Concrete fix: use `u64` counts or explicit wrapped modulo counters. Seed regression state near `u32::MAX`, cross the boundary, and verify keyframe, golden-frame, and ALTREF cadence.
- Effort: Small to medium, about 1–2 engineer-days.

- Bug: `RVP9-BUG-KILN-00073`
- Confidence: High
- Evidence: the public configuration promises a valid range of 0 through 6 and magnitude-to-level mapping at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:506`. - Effort: Small to medium, about 1–2 engineer-days.

## Confirmed design and performance work

### Medium — temporal filtering allocates repeatedly inside both hot loops

- Requirement: `RVP9-REQ-KILN-00074` (Draft, heavy)
- Confidence: High
- Evidence: each macroblock allocates accumulator and count vectors at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\temporal_filter.rs:1287`; each candidate application allocates three difference vectors at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\temporal_filter.rs:897`; predictor staging allocates again at lines 694 and 758. A 1920×1088 frame has 2,040 32×32 macroblocks before multiplying by candidate frames.
- Concrete fix: introduce bounded per-row or per-worker scratch while keeping filtered bytes identical.
- Effort: Medium, about 2–4 engineer-days.

### Medium — TPL mode estimation allocates three vectors per block

- Requirement: `RVP9-REQ-KILN-00075` (Draft, heavy)
- Confidence: High
- Evidence: `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\tpl\mode_est.rs:240` allocates predictor, source-difference, and coefficient vectors per call. `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\tpl\driver.rs:400` calls the path for every block of every window frame. At 1920×1088, those three buffers account for 97,920 heap allocations per analyzed frame.
- Concrete fix: move the three buffers into reusable analysis scratch and prove allocation reuse without changing mode decisions.
- Effort: Medium, about 2–3 engineer-days.

### Medium — spatial decoder-visible state relies on two manually synchronized field lists

- Requirement: `RVP9-REQ-KILN-00076` (Draft, heavy)
- Confidence: High
- Evidence: `SpatialSharedState` lists nine fields at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:1916`. `swap_spatial_shared_state` separately swaps the same nine fields at `D:\worktrees\rvp9-2\20260816-REV-RVP9-CDX@KILN-code-review-085355\crates\rvp9-encoder\src\frame_loop.rs:2406`. ## Test coverage implications

- Existing ALTREF emission tests use only 64- or 128-row frames, so they cannot expose either partial-height panic.
- Parallelism validation tests cover illegal option values, but no allocation-plan oracle protects retained scratch capacity.
- Counter tests exercise ordinary cadence but do not seed state near overflow.
- Denoiser tests check enabled versus disabled allocation, not the documented sensitivity levels.
- The performance requirements need allocation-count or capacity-reuse oracles. Wall-clock timing alone would be too noisy.

# Exact picker tile-loser certificate

The production-PGO profile assigns substantial Tree and Town CPU samples to large-block filter-candidate round trips. A cross-family consult identified a possible *picker-level* shortcut, not an evaluator-level equivalent: after some Hadamard/quantized tiles, prove the candidate cannot beat the current best and omit its remaining tiles and chroma model. The candidate's internal result fields would be incomplete, so this is valid only when the picker will not retain or trace that result. The [exact census](evidence/2026-09-27-picker-tile-lb-census-no-go/README.md) rejected a production prototype under the gate below.

## Bound and proof

This applies only to the large-block Hadamard-only S3 path in `crates/rvp9-core/src/mode_decision/inter.rs`. Let `n` be its total luma transform tiles. After tile `k`, let `satd_k` and `dist_k` be the accumulated non-negative SATD and coefficient error. Each tile incurs one EOB charge, so the eventual coefficient rate is at least `R_k = min(u32::MAX, (satd_k << 11) + (n << 9))`; coefficient distortion is at least `dist_k`. Let `S0` be the already-known mode, MV, reference and filter rate, excluding non-negative UV rate; let `K = rd_cost(lambda, S0 + skip_true, sse_y << live_skip_shift)` and `E_k = rd_cost(lambda, S0 + R_k + skip_false, dist_k)`, with the same saturating arithmetic as the encoder. Then `LB_k = min(K, E_k)` is no greater than either possible final branch: skip costs at least `K`, and encode costs at least `E_k`. UV rate and non-negative UV distortion can only raise the final cost. The existing RD bias and optional screen-content multiplier are monotone, and the picker replaces its incumbent only on strict `<`. Thus, if `biased(LB_k) >= incumbent`, the candidate cannot win.

The bound cannot usually fire before a transform: `E_0` has only syntax and EOB rate. It can fire at any tile only when `biased(K) >= incumbent`; that prediction-only skip cost is the reachability gate. `model_rd` is not substituted for a lower bound, because its distortion prediction is not guaranteed below the true round trip.

## Zero-behaviour-change census

Instrument only `RVP9_DIAG_TILE_LB=1` builds. Record each tile's partial SATD/distortion while the unchanged round trip runs, then calculate the earliest certifying `k` against the *pre-update* incumbent and the exact bias/screen predicate after the candidate returns. Count, by block and TX size, candidates, total tiles, certifiable candidates, earliest `k`, avoidable tiles, Tx8/Tx16-weighted avoidable work, candidates where `K` makes certification unreachable, uncertified losers, avoidable UV models, and any certified winner. A certified winner is an oracle violation and must be zero. Check the diagnostic encodes against the three pinned 60-frame IVF hashes; diagnostic CPU is not a speed measure. Make a focused counter/bound test fail deliberately once, then restore it.

Stop before a production prototype if avoidable weighted round-trip work is below about 15% on both Tree and Town. Above about 25% on Tree, a bounded prototype is worth testing. Between those figures, inspect the per-mode and per-tile distribution before deciding. These are eligibility thresholds, not predicted CPU gains: earlier exact loop savings often lost to code layout under production PGO.

## Prototype tripwires

- Preserve the normal path for small blocks, reconstruction mode, non-S3 calibration, diagnostics that consume full candidate fields, and any future caller that reads a losing candidate's result.
- Use the live skip shift, all saturating adds/casts, actual `uv_dist.max(0)`, and the current NEWMV bias and screen-content multiplier. Keep the strict new-best comparison.
- Preserve `sse_y`, MV, filter and early-term metadata for denoiser bookkeeping and mode-loop exits, even on a certified loser. The shortcut must not alter the prediction buffer already written for the candidate.
- Compare the full picker result and output prediction buffer with the shortcut on/off for 32×32 and 64×64 cases, both TX8 and TX16, and force at least one certificate. Deliberately corrupt the bound or retained metadata to prove the test goes red. Then require canonical Crucible hashes and two independent paired production-PGO CPU screens before integration.

The exact integrated baseline remains **1.057638×** pinned libvpx equal-clip process CPU against a **1.05×** target. The 11–13% Tree/Town evaluator sample shares are ceilings on broad work, not removable CPU. The certificate's useful fraction is unknown until the census runs. This design condenses a read-only Fable consult; its formula was checked against the current `rd_cost`, round-trip accumulators, skip tie-break, and picker comparison in source.

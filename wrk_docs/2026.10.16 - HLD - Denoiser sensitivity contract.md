# Denoiser sensitivity contract — KILN-00073

KILN-00073 combines a confirmed missing range check with an incorrect premise about the temporal denoiser's public sensitivity magnitude. Arthur must choose the contract before the recorded acceptance criteria can be changed or implemented.

## Verified source evidence

The repository pins libvpx v1.14.1 at `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`. All source links below name that exact revision.

- [vp9_cx_iface.c](https://chromium.googlesource.com/webm/libvpx/+/12f3a2ac603e8f10742105519e0cd03c3b8f71dd/vp9/vp9_cx_iface.c#276): `validate_config` bounds sensitivity at six. RVP9's `StreamEncoder::new` has no corresponding check.
- [vp9_denoiser.c](https://chromium.googlesource.com/webm/libvpx/+/12f3a2ac603e8f10742105519e0cd03c3b8f71dd/vp9/encoder/vp9_denoiser.c#691): allocation initializes current and previous level to Medium. RVP9 allocation matches this startup behavior.
- [vp9_noise_estimate.c](https://chromium.googlesource.com/webm/libvpx/+/12f3a2ac603e8f10742105519e0cd03c3b8f71dd/vp9/encoder/vp9_noise_estimate.c#287): estimate publication calls the level setter using the measured level; a separate high-motion branch can force LowLow. Sensitivity is an enable predicate, not this setter's level input.
- [vp9_denoiser.c setter](https://chromium.googlesource.com/webm/libvpx/+/12f3a2ac603e8f10742105519e0cd03c3b8f71dd/vp9/encoder/vp9_denoiser.c#732): LowLow-to-positive transitions set reset and refresh the SVC long-term reference when applicable. Other transitions clear reset; previous level is then updated.
- [vp9_encoder.c](https://chromium.googlesource.com/webm/libvpx/+/12f3a2ac603e8f10742105519e0cd03c3b8f71dd/vp9/encoder/vp9_encoder.c#3788): the magnitude strength switch belongs to `CONFIG_VP9_POSTPROC && !CONFIG_VP9_TEMPORAL_DENOISING`, a different path.

RVP9's estimator publishes four-tier `noise_estimate.level` in `pre_analysis.rs`, but no code writes denoiser levels after allocation. Production filtering uses `lib.rs::denoise_inter_leaf`, which does not mirror all the standalone wrapper's level gates. Wiring a setter into the standalone wrapper alone would not repair production behavior.

The estimator also differs from the temporal-enabled reference in its resolution gate and consecutive-zero-MV threshold. Its caller uses the GOP counter tracked by separate Open bug KILN-00072. Correct adaptation must preserve publication timing and reset/reference ordering rather than copying the estimator's initial cached level every frame. Existing denoiser stream tests use dimensions too small to exercise estimator adaptation. Existing `notes/lld/denoiser.md` describes adaptive intent, but does not resolve the conflicting public magnitude promise in this bug.

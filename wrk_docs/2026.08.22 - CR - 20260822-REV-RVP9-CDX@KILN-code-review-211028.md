## Confirmed defects

### RVP9-BUG-KIL-00117 — CLI destination aliases can destroy inputs and outputs

- **Severity / confidence:** High / high.
- **Where:** `crates/rvp9-cli/src/bin/rvp9enc.rs:932-935,1019,1090-1092,1144,1191-1192,1267`; `crates/rvp9-cli/src/bin/rvp9dec.rs:400-401,499-500,630-637`.
- **Failure:** neither binary checks whether input, primary output, and diagnostic output paths resolve to the same file. Equal paths, hardlinks, or symlinks can make `File::create` truncate an input still being read. A frame-timing CSV path equal to `-o` replaces a successfully written IVF.
- **Fix:** compare file identity for every path role before opening outputs, or stage output in sibling temporary files and atomically rename only after complete success.
- **Effort:** small–medium.

### RVP9-BUG-KIL-00119 — Decoder emits invalid Y4M across dynamic stream changes

- **Severity / confidence:** High / high.
- **Where:** `crates/rvp9-cli/src/bin/rvp9dec.rs:430,582-589,609-627`; supporting dynamic-format paths in `crates/rvp9-decoder/src/lib.rs:968-987,1118-1144`.
- **Failure:** `rvp9dec` writes one Y4M header from the first displayed frame, then writes later frame payloads without checking width, height, or chroma. A legal resize or chroma change makes payload lengths disagree with the latched header, corrupting downstream parsing while the CLI can still exit successfully.
- **Fix:** retain the first `(width, height, chroma)` tuple and fail before writing a changed frame, naming its index and both formats; full support requires normalization/scaling.
- **Effort:** small for fail-loud behavior; medium for normalization.

### RVP9-BUG-KIL-00118 — Invalid-Unicode argv panics both CLI binaries on Unix

- **Severity / confidence:** Medium / high.
- **Where:** `crates/rvp9-cli/src/bin/rvp9enc.rs:881`; `crates/rvp9-cli/src/bin/rvp9dec.rs:354`.
- **Failure:** both binaries use `std::env::args()`, whose iterator panics on non-UTF-8 Unix arguments. A valid OS filename can therefore abort before controlled error handling.
- **Fix:** preserve path arguments as `OsString`/`PathBuf`, or explicitly reject invalid option text without panicking.
- **Effort:** medium.

### RVP9-BUG-KIL-00120 — Two-pass encoding ignores thread and tile-column options

- **Severity / confidence:** Medium / high.
- **Where:** `crates/rvp9-cli/src/bin/rvp9enc.rs:958-982,1257,1567-1573`; `crates/rvp9-encoder/src/frame_loop.rs:850,892`.
- **Failure:** the two-pass branch bypasses `build_encoder_parallelism`; both passes construct the default single-threaded, single-tile encoder even when `--threads` or `--tile-columns` is accepted as supported.
- **Fix:** pass `EncoderParallelism` into both passes, or reject those flags with `--passes 2` until supported.
- **Effort:** small for rejection; medium for plumbing.

### RVP9-BUG-KIL-00121 — Two-pass encoding silently disables requested lookahead and ALTREF

- **Severity / confidence:** Medium / high.
- **Where:** `crates/rvp9-cli/src/bin/rvp9enc.rs:1532-1546`; `crates/rvp9-encoder/src/frame_loop.rs:845-850,887-892,3166-3185`.
- **Failure:** two-pass forcibly sets lag to zero in both passes. That discards `--lag-in-frames`, and it makes `--auto-alt-ref` inert because ALTREF construction needs a forward lookahead frame. The library comment documents the divergence, but the CLI accepts the requests silently.
- **Fix:** reject these two-pass combinations until delayed scheduling exists, or implement the missing schedule.
- **Effort:** small for rejection; medium–large for support.

### RVP9-BUG-KIL-00122 — Two-pass temporal SVC discards first-pass allocations

- **Severity / confidence:** Medium / high.
- **Where:** `crates/rvp9-encoder/src/frame_loop.rs:843-851,2279-2295,3777-3795`; `crates/rvp9-encoder/src/rate_control/two_pass.rs:255-264`; CLI admission at `crates/rvp9-cli/src/bin/rvp9enc.rs:955-975`.
- **Failure:** the two-pass state attaches only to the stream-level controller. Temporal SVC replaces that controller before Q selection with a per-layer controller whose `two_pass` state is empty, so the picker falls back to flat average bandwidth instead of consuming first-pass allocations.
- **Fix:** reject `--passes 2` with temporal layers 2/3 until every layer carries first-pass state, or implement that per-layer state.
- **Effort:** small for rejection; medium for support.

### RVP9-BUG-KIL-00123 — Raw invalid geometry allocates a frame before encoder validation

- **Severity / confidence:** Medium / high.
- **Where:** `crates/rvp9-cli/src/bin/rvp9enc.rs:932-949,1335-1431`; validation in `crates/rvp9-encoder/src/rate_control/config.rs:239-240,280-288`.
- **Failure:** the raw reader allocates and reads the first full frame before encoder construction checks the supported dimension/pixel envelope. Dimensions just above the 16,384 limit can consume hundreds of megabytes before returning `InvalidConfig`.
- **Fix:** expose/reuse the encoder geometry validator and apply it before opening or reading raw frame data.
- **Effort:** medium.

### RVP9-BUG-KIL-00124 — `--noise-sensitivity` silently clamps out-of-range values

- **Severity / confidence:** Low / high.
- **Where:** `crates/rvp9-cli/src/bin/rvp9enc.rs:482-488,1520-1523,1833-1841`.
- **Failure:** the handler accepts any `u32`, then the config builder silently clamps values above the documented `0..=6` range. The test comment says the parser should catch this, but it does not.
- **Fix:** parse through the existing `parse_range(..., 0, 6)` helper and retain the builder clamp as defence in depth.
- **Effort:** trivial.

### RVP9-BUG-KIL-00125 — Symmetric fixtures make CLI plane and geometry oracles vacuous

- **Severity / confidence:** Low / high.
- **Where:** `crates/rvp9-cli/tests/cli_arg_coverage.rs:33-35,59-75,1233-1280`; `crates/rvp9-cli/tests/cli_roundtrip.rs:24-26,47-68`.
- **Failure:** the principal fixtures are square and generate identical U and V patterns. The YV12 swap test passes even if the planes are not swapped, while width/height transpositions evade most byte-count assertions.
- **Fix:** use distinct U/V patterns and at least one rectangular successful roundtrip that asserts IVF/Y4M dimensions and plane boundaries.
- **Effort:** small.

## Draft requirement

`RVP9-REQ-KIL-00126` records the systemic remedy: every encoder flag advertised as supported must reach its intended behavior on every applicable one-pass, spatial-SVC, temporal-SVC, and two-pass path, or the path must reject it explicitly. The requested oracle enumerates the live flag table and exercises the cross-path combinations that the current unit tests miss. Priority is Should; Flow is heavy for human Gate-1 triage.

## Confirmed report-only debt

- **Opt-in timing CSV scales with the full run.** `rvp9enc.rs:1024-1055,1149-1169,1216-1224` retains every timing, then duplicates the data into one `String`. Stream or chunk rows. Medium-low impact; small–medium effort.
- **Raw one-pass input allocates three plane buffers per frame.** `rvp9enc.rs:1311-1322,1406-1431` lacks the reuse path already present for Y4M. Add `RawFrameReader::next_frame_into`. Medium impact; medium effort.
- **Decoder pixel output allocates and copies three planes per frame.** `rvp9dec.rs:571-580,608-627` could write visible rows directly or reuse scratch. Low-medium impact; medium effort.
- **Decode timing runs when no summary is requested.** `rvp9dec.rs:450-454` calls `Instant::now/elapsed` for every component even though only `--summary` consumes the counter. Guard it. Low impact; trivial effort.
- **Coverage gaps remain around positive lookahead/flush, two-pass decodability, and Profile-1 Y4M output.** These are useful follow-ups, but none demonstrated incorrect current behavior after source verification.

## Section-by-section Narrative

### 1. AQ mode enum + dispatch

**Row 1 — `AQ_MODE` enum (NO_AQ … LOOKAHEAD_AQ, 8 values).**
libvpx exposes 8 AQ modes via `VP9EncoderConfig::aq_mode`. rvp9 ships `AqMode::{Off, CyclicRefresh}` (`frame_loop.rs:109-116`) — 2 of 8. **PARTIAL** (6 of 8 missing: VARIANCE_AQ, COMPLEXITY_AQ, EQUATOR360_AQ, PERCEPTUAL_AQ, PSNR_AQ, LOOKAHEAD_AQ).

**Row 2 — dispatch in `encode_with_recode_loop` (vp9_encoder.c:4205-4239).**
libvpx's `if/else if` ladder routes each AQ mode to its frame-setup fn (`vp9_vaq_frame_setup`, `vp9_360aq_frame_setup`, `vp9_setup_in_frame_q_adj`, `vp9_alt_ref_aq_setup_map`, `vp9_cyclic_refresh_setup`). rvp9 has only the CR branch wired (`frame_loop.rs:862-880` / `1054`). **PARTIAL** — the ladder structure is wrong shape (no `match` over `AqMode`), so adding new modes requires restructuring not just adding a case.

**Row 3 — two-pass-mirror dispatch (vp9_encoder.c:4655-4666).**
A second copy of the ladder lives in the two-pass first-pass path including `vp9_psnr_aq_mode_setup` (only emitted here). **NOT PORTED** — 2-pass is itself out of scope at present but the AQ-mode ladder will need rebuilding when 2-pass lands (cross-zone → A3).

### 2. Segmentation primitives (libvpx `vp9_segmentation.c` helpers)

**Rows 4-9 — `vp9_enable_segmentation`, `vp9_disable_segmentation`, `vp9_set_segment_data`, `vp9_disable_segfeature`, `vp9_clear_segdata`, `vp9_clearall_segfeatures`, `vp9_set_segdata`, `vp9_enable_segfeature`, `vp9_reset_segment_features`.**
These are the bookkeeping API used by every AQ mode to toggle `seg->enabled`, mask in/out individual features, and write `feature_data[seg_id][feat_id]`. rvp9's `SegmentationParams` (`sub_parsers.rs:289-309`) has the field shape (`enabled`, `update_map`, `update_data`, `temporal_update`, `tree_probs`, `pred_probs`, `abs_delta`, `feature_data[8][4]`) and `build_segmentation_params` (`frame_loop.rs:1954-1981`) implements the CR-specific subset (ALT_Q only). There is no general-purpose `enable_segfeature` / `disable_segfeature` API — every other AQ mode would have to rebuild the writer from scratch.

Note: rvp9 stores `feature_data[seg][feat]` as `[[Option<i16>; 4]; 8]` — `None` ⇔ feature disabled, `Some(v)` ⇔ feature enabled with value `v`. This is structurally equivalent to libvpx's `feature_mask` + `feature_data` split, but the per-feature setter/clearer surface is missing.

### 3. PSNR_AQ + PERCEPTUAL_AQ (segmentation.c-resident frame-setup fns)

**Row 10 — `vp9_psnr_aq_mode_setup`** (`vp9_segmentation.c:50-61`): seeds `SEG_LVL_ALT_Q` with `2 * (i - MAX_SEGMENTS/2)` over all 8 segments. **NOT PORTED.**

**Row 11 — `vp9_perceptual_aq_mode_setup`** (`vp9_segmentation.c:63-101`): k-means Wiener-variance frame-setup. Uses `cpi->kmeans_ctr_ls[]` (populated upstream by the perceptual analyser) to derive per-segment q-deltas around the midpoint centroid via `target_qstep = base_qstep / (1 + wiener_var_diff/4)` (and the dual scaling for high-variance segments). **NOT PORTED.** Prerequisite: k-means centroid table + Wiener-variance pre-pass (cross-zone → A5).

### 4. Segment-map coding-method choice (`vp9_choose_segmap_coding_method`)

**Rows 12-15 — `count_segs` / `count_segs_sb` / `calc_segtree_probs` / `cost_segmap` / `vp9_choose_segmap_coding_method`.**
This walks the SB grid, counts segment-id occurrences and temporal-predictor hits, builds the 7-prob segment tree, and chooses between spatial (`temporal_update = 0`) and temporal (`temporal_update = 1`) coding by cost comparison. rvp9 hardcodes `seg.temporal_update = false` (`frame_loop.rs:1961`) and writes the constant-prob tree (`tree_probs[i] = MAX_PROB` ⇒ "no update" per-prob bit, fall back to defaults). Decoder parser handles both branches (`tile.rs:1862-1925`); encoder side never produces `temporal_update = true`. **NOT PORTED.** Cost impact: every segmentation-enabled inter frame pays the spatial-coding cost even when temporal would be cheaper (libvpx empirically chooses temporal often for stable maps).

### 5. EQUATOR360_AQ (360° video)

**Rows 16-17 — `vp9_360aq_segment_id` + `vp9_360aq_frame_setup`.**
Static three-zone mapping by `mi_row` (polar/temperate/equator), 7-segment q-delta table `{1.0, 0.75, 0.6, 0.5, 0.4, 0.3, 0.25}`. Frame-setup gates on `frame_is_intra_only || force_update_segmentation || error_resilient_mode`. **NOT PORTED.**

### 6. COMPLEXITY_AQ

**Rows 18-20 — `get_aq_c_strength`, `vp9_setup_in_frame_q_adj`, `vp9_caq_select_segment`.**
5-segment scheme with neutral middle segment (`DEFAULT_AQ2_SEG = 3`). Per-block segment-id chosen by `(projected_rate < target_rate * transition) && (logvar < threshold)`. The mode-selection path requires the encoder to expose `projected_rate` per block at `rd_pick_sb_modes`-time (called from `encodeframe.c:2090`). **NOT PORTED.** Prerequisite: `vp9_log_block_var` (row 25), `mb_av_energy` (2-pass twopass stats — A3), and a per-block `rd_cost->rate` callback into the picker.

### 7. VARIANCE_AQ

**Rows 21-26 — `vp9_vaq_segment_id`, `vp9_vaq_frame_setup`, `aq_variance` family, `block_variance`, `vp9_log_block_var`, `vp9_block_energy` / `vp9_get_sub_block_energy`.**
5-segment scheme keyed by 6-bin energy (`ENERGY_MIN..ENERGY_MAX = -4..1`). The per-block call sites are `encodeframe.c:189-209` (`set_segment_id`), `encodeframe.c:2705 / 4056 / 4071` (RDO-path `mb_energy` setup), and `rdopt.c:3937` (sub-8x8 path). **NOT PORTED end-to-end.** Both the mode-selection path AND the per-block segment-id assignment are missing.

### 8. CYCLIC_REFRESH_AQ — the only mode rvp9 has plumbed

**Row 27 — `CYCLIC_REFRESH` struct.**
libvpx state lives in `cpi->cyclic_refresh` (`vp9_aq_cyclicrefresh.h:32-74`): `percent_refresh`, `max_qdelta_perc`, `sb_index`, `time_for_refresh`, `target_num_seg_blocks`, `actual_num_seg{1,2}_blocks`, `rdmult`, `map`, `last_coded_q_map`, `thresh_rate_sb`, `thresh_dist_sb`, `motion_thresh`, `rate_ratio_qdelta`, `rate_boost_fac`, `low_content_avg`, `qindex_delta[3]`, `reduce_refresh`, `weight_segment`, `apply_cyclic_refresh`, `counter_encode_maxq_scene_change`, `skip_flat_static_blocks`, `content_mode`. rvp9 has `map`, `last_coded_q_map`, `sb_cursor`, `mi_rows`, `mi_cols`, `config` (`aq_cyclic_refresh.rs:155-178`) + a hard-coded `segment1_q_delta` in config. **PARTIAL** — missing 18 of the 24 fields; the in-flight ones (`rate_ratio_qdelta`, `rate_boost_fac`, `motion_thresh`, `weight_segment`, `qindex_delta[3]`, `low_content_avg`, `apply_cyclic_refresh`, `counter_encode_maxq_scene_change`, `skip_flat_static_blocks`, `content_mode`, `time_for_refresh`, `reduce_refresh`, `rdmult`, `thresh_rate_sb`, `thresh_dist_sb`, `target_num_seg_blocks`, `actual_num_seg{1,2}_blocks`, `max_qdelta_perc`) drive every adaptive behaviour.

**Row 28 — `candidate_refresh_aq` per-block decision.**
Returns one of `BASE / BOOST1 / BOOST2` from `(dist, rate, mv, bsize)` w/ `motion_thresh`, `thresh_dist_sb`, `thresh_rate_sb`, `rate_boost_fac`. rvp9's whole-SB painter never demotes to BOOST2 nor evicts a block back to BASE on high-motion / high-dist. **NOT PORTED.**

**Row 29 — `compute_deltaq` (rate-ratio → q-delta, `max_qdelta_perc` clamp).**
rvp9 uses a hard-coded `segment1_q_delta = -8` (`aq_cyclic_refresh.rs:137`); libvpx derives `qindex_delta[1] = compute_deltaq(cpi, base_qindex, rate_ratio_qdelta)` per frame and clamps to `-max_qdelta_perc * q / 100`. **NOT PORTED.** Direct quality impact: a fixed `-8` is wrong at low base-Q (under-boost) and at high base-Q (over-boost).

**Rows 30-31 — RC feedback: `estimate_bits_at_q` + `rc_bits_per_mb`.**
The CR-aware bit-rate accountant. Called from `rc_update_rate_correction_factors` and `rc_regulate_q`. rvp9's rate controller has no CR coupling, so the rate model and the AQ map drift apart — every CR-enabled frame is mispriced. **NOT PORTED.** Cross-zone → A3.

**Row 32 — `vp9_cyclic_refresh_update_segment` (per-block postpick reset).**
Reads `(rate, dist, skip, mv, bsize)`, decides `BASE/BOOST1/BOOST2`, conditionally clears `mi->segment_id` if the block is skipped. Also runs `vp9_compute_skin_block` for low-bsize blocks under `use_skin_detection` and forces BOOST1. Also forces `BASE` if `rc_mode == VBR && ref == GOLDEN`. Also runs the `cyclic_refresh_segment_id_boosted` branch for `use_nonrd_pick_mode`. **NOT PORTED** in rvp9 — the rvp9 `gather_coded_segments_and_skip` (`frame_loop.rs:1986-2014`) just splats the picked seg id, no postpick adjustment. Significant: libvpx's CR is **dual-pass** (pick + adjust); rvp9's is single-pass.

**Row 33 — `vp9_cyclic_refresh_update_sb_postencode` (`last_coded_q_map` skip-aware update).**
**PORTED (subset)** at `aq_cyclic_refresh.rs:449-478`. rvp9's `post_encode_update` matches libvpx's three branches: non-skipped → write `base + delta[seg]`; inter-skip-on-boost → MIN with previous; inter-skip-on-base → unchanged. AUDIT-VERIFIED.

**Row 34 — `vp9_cyclic_refresh_postencode` (frame-end stats + GOLDEN refresh force).**
Computes `actual_num_seg{1,2}_blocks` (rvp9 has nothing equivalent), accumulates `low_content_frame` for the recursive `low_content_avg`, force-refreshes GOLDEN on `resize_pending`, and gates the GOLDEN-refresh decision on `fraction_low < 0.65 || low_content_avg < 0.6`. **NOT PORTED.** rvp9's GOLDEN cadence (A10) is content-blind and never coupled to CR's low-motion estimator.

**Row 35 — `vp9_cyclic_refresh_set_golden_update` (golden interval from `percent_refresh`).**
`baseline_gf_interval = min(4 * 100/percent_refresh, 40)` for CBR; `20` for VBR; collapses to `10` under low-motion + post-key. **NOT PORTED.** Cross-zone → A10.

**Row 36 — `cyclic_refresh_update_map` + `is_superblock_flat_static`.**
The SB-grid walk that builds the segmentation map. Inputs: `cr->map`, `last_coded_q_map`, `consec_zero_mv`, `noise_estimate`, screen-content flag, `Last_Source` for flat-static detection. rvp9 ports the cursor walk + "≥ half eligible" rule + the `last_coded_q_map > qindex_thresh` filter (`aq_cyclic_refresh.rs:330-390`). **PARTIAL** — missing: `consec_zero_mv_thresh` (pre-analysis pipeline, A5), `noise_estimate` (A5), screen-content gate, `is_superblock_flat_static` (variance + last-source SAD), `reduce_refresh` flag, low-res `consec_zero_mv_thresh_block = 4` branch.

**Row 37 — `vp9_cyclic_refresh_update_parameters`.**
Sets per-frame `percent_refresh`, `rate_ratio_qdelta`, `rate_boost_fac`, `motion_thresh`, `apply_cyclic_refresh`, weight-segment averaging, plus the `cr->skip_flat_static_blocks` screen-content gate and the VBR-vs-CBR branch. rvp9 has the `apply_cyclic_refresh` frame-gate only (`aq_cyclic_refresh.rs:235-254`) — the other parameter adaptation (`rate_ratio_qdelta` ramp post-key, noise-aware shrink, low-res motion-thresh bump, VBR branch, screen-content branch) is all **NOT PORTED**. The current `target_refresh_fraction_256 = 25` and `segment1_q_delta = -8` are frozen at the libvpx mid-CBR-camera defaults; everything that varies them is missing.

## Cross-cutting Gaps

### CC-1. Only one of eight AQ modes is plumbed.
The audit-scoped surface is `NO_AQ + 7 others`. rvp9 has `Off + CyclicRefresh`. The remaining six (VARIANCE_AQ, COMPLEXITY_AQ, EQUATOR360_AQ, PERCEPTUAL_AQ, PSNR_AQ, LOOKAHEAD_AQ) have **neither** the mode-selection dispatch **nor** the per-mode segment-feature setup. The `AqMode` enum, the CLI parser (only 0 and 3 accepted), the dispatch ladder, and `build_segmentation_params` are all CR-specific.

### CC-2. No general per-feature segmentation API.
libvpx's `vp9_enable_segfeature` / `vp9_disable_segfeature` / `vp9_set_segdata` / `vp9_clear_segdata` / `vp9_clearall_segfeatures` / `vp9_set_segment_data` / `vp9_reset_segment_features` are how every AQ mode and `setup_segmentation` mutate `cm->seg`. rvp9 has the field shape on `SegmentationParams` but no API; every AQ mode would have to re-implement the toggling logic. ROI / active-map / ALTREF segmentation use cases also depend on this API.

### CC-3. `vp9_compute_qdelta_by_rate` is the missing prerequisite shared by VAQ + COMPLEXITY_AQ + EQUATOR360_AQ + CR `compute_deltaq`.
Every AQ frame-setup function that produces per-segment ALT_Q deltas calls this. **NOT PORTED.** Cross-zone with A3.

### CC-4. `vp9_choose_segmap_coding_method` is missing → `temporal_update` permanently `false`.
The decoder, the core parser, and the writer all support the temporal-update path; the encoder never produces it. On stable inter sequences this is a measurable cost overhead in the segmentation header + per-block bits.

### CC-5. CR's two-pass shape collapses to one pass.
libvpx's CR is **pick segment 1 candidates (`cyclic_refresh_update_map`) → encode → post-pick adjust per block (`cyclic_refresh_update_segment`) using observed `(rate, dist, skip, mv)`**. rvp9's CR is **pick → encode**, no post-pick adjustment. Result: no BOOST2 (large zero-MV inter blocks never get the extra boost), no skin-detection promotion, no VBR-GOLDEN demotion. This is the single biggest deviation in the one AQ mode rvp9 does ship.

### CC-6. Encoder never emits ALT_LF / SKIP / REF_FRAME segment features.
Decoder + core honour them (`loopfilter.rs:1087-1180`, `bitstream/sub_parsers.rs`), but the encoder produces only ALT_Q deltas. ROI, active-map, and the `setup_segmentation` ALTREF branch all need these.

### CC-7. CR `cr->rdmult` (boosted-segment RD multiplier) is unwired.
libvpx feeds `cr->rdmult` (computed via `vp9_compute_rd_mult` on the segment-1 effective qindex) into the picker's RD lambda for boosted blocks. rvp9 has the segment-1 q-delta on the wire (so dequant is correct) but the picker uses the frame-level RD multiplier for every block. Result: the picker doesn't know it should be more lenient on boosted blocks.

### CC-8. CR feedback into rate control is severed.
`vp9_cyclic_refresh_estimate_bits_at_q` (postencode) and `vp9_cyclic_refresh_rc_bits_per_mb` (preencode) couple CR to libvpx's bits-per-mb model. rvp9's rate controller (A3) is CR-blind, so the q-trajectory drifts when CR is active. (Hidden by the `apply_cyclic_refresh` gate suppressing CR in many problem ranges — but the gate is a workaround, not a fix.)

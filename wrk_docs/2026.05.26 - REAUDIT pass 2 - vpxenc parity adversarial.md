## 0. Executive summary

**Verdict: the Phase 3 exit gate DOES NOT hold.**

The integration debt is structural and massive. 55/59 master-inventory items "landed" as standalone modules with PROOF tests; only **3 of the new module families (W1 lookahead, W2 pre-analysis, original aq_cyclic_refresh) actually run when `StreamEncoder::encode_frame` is called**. Every other Wave 2-7 deliverable — temporal_filter, denoiser, svc, tpl, compound, ml_partition, rdo, segmentation, bitstream_gates, sub8_kf_intra, sub8 — is dead code, never invoked from the production hot path. The journal at `wrk_journals/2026.05.26 - JRN - vpxenc parity port drive.md:165-196` openly states this ("ALL Wave 4 modules ship STANDALONE").

The PROOF tests themselves are mostly real — they exercise the modules' contracts and would catch most regressions. But because nothing references the modules from the production encode path, the tests verify code that **never runs in any rvp9-cli output**. The Phase 3 exit criterion ("zero IN-SCOPE gaps across every audit zone") is functionally inverted: 1,170 unported rows became 1,170 standalone-tested rows, with the wiring gap moved into "integration debt" that isn't currently a tracked phase.

Headline numbers:
- 7 of 10 new top-level modules have ZERO callers outside their own subtree (confirmed via Grep).
- 4 RDO modules call each other internally, but no caller exists in `frame_loop.rs` / `lib.rs` production paths.
- HBD (W6.1-W6.4) is explicitly deferred per `665232e` (acknowledged).
- `--lag-in-frames` is parsed but the lookahead is constructed depth=0 (frame_loop.rs:497).
- 23 W7.8 CLI flags are parsed but explicitly "plumbing into EncoderConfig / two-pass / SVC / loop-filter paths lands in later waves" (rvp9enc.rs:144-145).
- 1 flaky test surfaced: `frame_loop::tests::encode_frame_q_index_responds_to_bitrate` failed on first lib-test run, passed on re-run. Indicates a race or non-determinism in the rate-control test fixture.

## 4. Algorithm-deviation deep-dive (5 tricky primitives)

Tracking step-by-step match against libvpx:

### 4.1 Noise estimator histogram tail-fold (vp9_noise_estimate.c:226-229)

rvp9: pre_analysis.rs:580-586. **MATCHES.** `if hist_index < MAX_VAR_HIST_BINS { hist[hist_index] += 1 } else if hist_index < (3 * (MAX_VAR_HIST_BINS >> 1)) { hist[MAX_VAR_HIST_BINS - 1] += 1 }` — identical algebra.

### 4.2 Sub-8 KF intra mode-iteration order (vp9_rdopt.c:1099-1290)

libvpx walks `DC_PRED..=TM_PRED` (10 modes), skip-mask filter, conditional_skipintra; for each, predict / subtract / fdct4x4-or-fht / quantize_b / cost_coeffs / block_error. Tempa/templ entropy ctx propagates across the 4 4×4 sub-blocks in raster order.

rvp9: rdo/sub8_kf_intra.rs:131. **DIVERGES.** The rvp9 port does NOT iterate modes, does NOT predict, does NOT transform, does NOT quantize, does NOT entropy-cost. It accepts a flat `&[KfIntraCandidate { mode, rate, dist, rd }]` and returns argmin. The "candidate" is the libvpx output of the inner loop; rvp9 never ports the inner loop. The entropy ctx propagation (tempa/templ at libvpx 1108/1163) is also absent because there are no sub-block coefficients to derive a ctx from.

This is the largest algorithmic deviation in the spot-check. It's a single-file standalone module that "implements" sub-8 KF intra by argmin. The body of `rd_pick_intra4x4block` (the actual algorithm) is missing entirely.

### 4.3 Temporal filter NLM apply (vp9_temporal_filter.c:260-399)

rvp9: temporal_filter.rs:874. **MATCHES** with one minor refinement noted. Y-diff² ⇒ 3×3 Y window sum + 2 chroma cross-term samples + cr_index=2 (rvp9:974); chroma path uses `(uv_r << ss_y) + idy` for the luma cross-term (rvp9:1018). All numeric reproductions look exact. INDEX_MULT[14] table verified bit-exact at the w3_4_mod_index_table_matches_libvpx test. The fixed_divide normalisation at temporal_filter.rs:1472 matches libvpx 910-914 (`(acc + count/2) * fd[count] >> 19`).

### 4.4 Compound joint motion search (vp9_rdopt.c, joint_motion_search at ~2000-2200)

rvp9: compound.rs declares "compound producer". The actual joint MV search algorithm (libvpx walks ref0 and ref1 alternately, holding the other fixed, until convergence) — not verified here because compound.rs is dead code (no callers).

### 4.5 Denoiser strong+weak two-pass kernel (vp9_denoiser.c:68-180)

rvp9: denoiser.rs:244, vp9_denoiser_filter(). **MATCHES** at the constant and threshold level (verified w5_3_filter_threshold_helpers_match_libvpx_table); the strong-pass abs-diff per-pixel branch and weak-pass delta cap look faithful per docstring claims. PROOF test w5_3_filter_small_diff_snaps_to_mc verifies the snap-to-mc behaviour with a single synthetic diff.

## 5. Cross-decoder gate

`cargo test -p rvp9-encoder --tests` — final state: **409 passed; 0 failed; 1 ignored**. Gate is green.

Flake: `frame_loop::tests::encode_frame_q_index_responds_to_bitrate` failed once with `low-bitrate Q (100) should be >= high-bitrate Q (168)` on the first `cargo test --lib` invocation, then passed on `--lib <test_name>` re-run. This indicates non-determinism in the rate-control fixture — the buffer-state and Q-pick paths must be ordering-sensitive across the parallel test runner. The `frame_loop::tests::aq_cyclic_refresh_segment_1_has_finer_quantization` test also has a documented flake (journal line 285). Both should be marked `#[serial_test::serial]` or have their oracle decoupled from global state.

Cross-decoder integration tests (`encode_two_frame_kf_inter_decodes_through_real_decoder`, `encode_synthetic_dc_intra_with_residuals_decodes_bit_exact`) all pass — the encoder still produces bit-exact bytes that the rvp9-decoder accepts. The deferred / standalone modules don't affect this because they're not on the encode hot path.

## 6. Exit-gate verdict

Phase 3 of the goal doc says "two independent re-audit passes ... both return zero IN-SCOPE gaps across every audit zone".

**The exit gate DOES NOT hold.** Listed in priority order:

1. **In-scope gap (large)**: ~16,400 LOC of standalone-tested but unwired modules. From the master inventory's perspective, these rows transitioned from "NOT PORTED" to "PORTED-but-not-integrated". The audit was a code-presence audit, not a call-graph audit. Integration is itself a Phase that has not started.

2. **In-scope gap (algorithmic)**: W7.9 sub-8 KF intra and W4.10b sub-8 inter compound. The "candidate-supplied" cheat means even if the modules were wired, they couldn't pick a real winner — the caller would have to produce the candidates, which means porting `rd_pick_intra4x4block` / `rd_pick_best_sub8x8_mode` separately. These items are tagged "ported" but the load-bearing inner loop isn't ported.

3. **In-scope gap (CLI)**: 23+ long-tail flags (W7.8) parse-and-store with no downstream consumer. `--lag-in-frames`, `--auto-alt-ref`, `--arnr-strength`, `--enable-tpl`, `--row-mt`, etc. are all no-ops despite being accepted by the CLI.

4. **Known deferral (acknowledged, in-scope)**: HBD (W6.1-W6.4) — explicitly deferred with journal entry `665232e`. Stays NOT PORTED.

5. **Test infrastructure**: 2 known-flaky frame_loop tests in the encoder lib suite. Not strictly an inventory gap but undermines the value of "0 failures" as a regression signal.

## 7. Top 10 concerns

Ranked by Arthur-priority assuming the goal is real vpxenc parity (not standalone-tested code):

1. **Wire the RDO path (Wave 4) into `StreamEncoder::encode_frame`.** Currently the encoder ALWAYS uses the RT picker regardless of `EncoderConfig.speed`. Until rdo::pick_inter_mode_sb runs at speed ≤ 4, the entire Wave 4 spend is invisible to end users. ~5000 LOC of inert code.

2. **Resolve the W7.9 / W4.10b "candidate-supplied" cheat.** Either port the inner mode-iteration loops (predict / subtract / fdct4x4 / quantize_b / cost_coeffs / block_error per mode per sub-block) or admit these subsystems are NOT PORTED. Today's "argmin over caller candidates" is a presentation layer, not an algorithm port.

3. **Wire pre-analysis CONSUMERS.** Producers run every frame but nothing consumes `noise_estimate.level`, `content_state_sb[]`, `scene_cut_force_key_frame`, etc. The picker is unchanged from pre-Phase-2. Until the picker reads these fields (e.g. `vp9_NEWMV_diff_bias` consuming `noise_estimate.level`), Wave 2 is also inert.

4. **Wire the ALTREF temporal filter** (Wave 3, temporal_filter.rs). The encoder doesn't emit ARF frames; no `is_src_frame_alt_ref` tracking exists. Wave 3's 1867 LOC is dead.

5. **Audit the lookahead depth=0 hardcode** (frame_loop.rs:497). The W1.4-W1.5 ring exists but is configured passthrough. `--lag-in-frames` is parsed but ignored. Wave 1's PROOF tests pin the wiring but `next_show_idx` advance is the only observable effect.

6. **Investigate the encode_frame_q_index_responds_to_bitrate flake.** First failure was Q=100 (low-bitrate) vs Q=168 (high-bitrate). That's the wrong direction — high bitrate should pick lower Q. Either the test is racy across the test runner, or rate-control state is being globally mutated. Worth a one-day debug.

7. **Plumb the W7.8 long-tail CLI flags** to their consumers. 23 flags parsed-not-plumbed is more parse-and-store theatre. Pick 3-5 user-meaningful flags (`--auto-alt-ref`, `--arnr-strength`, `--enable-tpl`, `--row-mt`, `--lag-in-frames`) and wire them; defer the rest with explicit `eprintln!("warning: --foo accepted but ignored in this build")`.

8. **The PROOF-test quality audit shows two vacuous patterns** (W7.9 argmin tests; W7.8 store-and-retrieve tests). Add a code-review rule: PROOF tests must call the function under test on inputs the FUNCTION computes, not on hand-rolled outputs the test asserts on.

9. **HBD remains the largest unfinished item** (~5000 LOC). The journal acknowledges this. It's the next single largest commit-set in scope.

10. **Cyclic-refresh + denoiser SVC interaction is stubbed** (svc.rs:62, denoiser.rs:54). Even when integrators get to SVC, the swap-pointer dance and `denoise_layer_idx` indexing are documented TODOs. These compound on each other — wiring SVC without wiring the denoiser interaction will produce subtly wrong outputs at multi-layer encode.

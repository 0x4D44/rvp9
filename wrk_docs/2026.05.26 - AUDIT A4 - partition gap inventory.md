## Section-by-section narrative

### 1. Variance-partition picker (RT path) — `choose_partitioning`

libvpx's `choose_partitioning` (`vp9_encodeframe.c:1261-1762`) is the cpu-used 5-8 partition driver. It does five logical jobs:

1. **Pre-roll setup** — segment_id, `force_64_split`, `content_state`, `vbp_thresholds` (q/noise/content scaled), `low_res` branch, scene-change detection. Status: **PARTIAL** — `set_vbp_thresholds` keyframe path is faithful (`partition.rs:228-247`), inter path is partial (`partition.rs:285-334`: missing `disable_16x16part_nonkey`, `scale_part_thresh_sumdiff`, noise_level scaling, the `cpi->oxcf.speed` shift on `thresholds[2]`, and the `width >= 1280 && speed < 7` thresholds[2] boost). `force_64_split`, `content_state`, `scene_change_detected`, `vbp_threshold_sad`, `vbp_threshold_copy`, `vbp_threshold_minmax`, `vbp_bsize_min` are **all NOT PORTED**.
2. **Reference frame pick** (LAST vs GOLDEN vs ALTREF; `int_pro` MV refinement on LAST). libvpx computes `y_sad_g`, `y_sad`, runs `vp9_int_pro_motion_estimation`, picks ref by SAD, and sets `sb_use_mv_part`/`sb_mvcol_part`/`sb_mvrow_part` for downstream pickmode. Status: **NOT PORTED**. rvp9 always uses ZEROMV against LAST (`partition.rs:359-368`).
3. **Variance tree fill** at 4x4 / 8x8 averages → variance pyramid 4→8→16→32→64. Status: **PARTIAL** — rvp9 computes per-block per-pixel variance directly at each recursion level (`partition.rs:421-431`) via `crate::dsp::distortion::variance`. The hierarchical fill_variance / fill_variance_tree / fill_variance_4x4avg / fill_variance_8x8avg helpers and `compute_minmax_8x8` are **NOT PORTED**. This means rvp9 cannot do the 8x8-minmax force-split (`encodeframe.c:1593-1612`) nor the 4x4 KF descent.
4. **Per-level force_split propagation** (`force_split[21]` indexed: 0=64x64, 1-4=32x32, 5-20=16x16). libvpx propagates upward when any child exceeds threshold, when 8x8-minmax exceeds threshold, or when max-min spread of 32x32 variances exceeds threshold. Status: **PARTIAL** — rvp9's top-down recursive descent (`partition.rs:401-512`) achieves the same final split density for the basic threshold case but is structurally a different algorithm (top-down vs bottom-up fill + force_split flags). The 32x32 spread-based force-split (`encodeframe.c:1671-1696`) and noise-level threshold scaling (`:1634, 1671-1675, 1686, 1693`) are NOT PORTED.
5. **HORZ/VERT emission** in `set_vt_partitioning` (`encodeframe.c:472-548`). libvpx checks the `part_variances.horz[2]` and `part_variances.vert[2]` arrays and can emit BLOCK_64X32 / BLOCK_32X64 / BLOCK_32X16 / BLOCK_16X32 / BLOCK_16X8 / BLOCK_8X16 leaves. Status: **NOT PORTED**. rvp9 emits NONE / SPLIT only (`partition.rs:23-28` documents this divergence).

Final post-roll: `chroma_check` (`:1517, 1534`), `set_low_temp_var_flag` (`:1758-1760`), `copy_partitioning` / `update_prev_partition` / `update_partition_svc` are all **NOT PORTED**.

### 2. Variance-partition threshold setup — `set_vbp_thresholds`, `vp9_set_variance_partition_thresholds`

KF path: PORTED faithfully (`partition.rs:228-247`).

Inter path: PARTIAL. The base formula at speed 7 small-res is in `partition.rs:295-315`. Missing (NOT PORTED):

- Noise-level scaling (`encodeframe.c:589-598`) — needs A5 noise estimate.
- Denoiser-driven scaling via `vp9_scale_part_thresh` (`encodeframe.c:600-604`) — needs A17.
- `scale_part_thresh_sumdiff` (`:611`) — content-state scaling, A5.
- `disable_16x16part_nonkey` (`:633`) — A7 speed feature.
- The `speed`-indexed shift `thresholds[2] = threshold_base << cpi->oxcf.speed` at `:615` (rvp9 hardcodes `<< 7`).

`vp9_set_variance_partition_thresholds` (the public entry) also computes `vbp_threshold_sad`, `vbp_threshold_copy`, `vbp_threshold_minmax`, `vbp_bsize_min` (`:648-674`) — all **NOT PORTED**, used by the y_sad-low fast-out, copy-partition, and 8x8-minmax paths inside `choose_partitioning`.

### 3. Pre-roll source classification — `avg_source_sad`, `content_state_sb`

`avg_source_sad` (`:1209-1257`) computes a per-SB SAD against `Last_Source` and classifies `content_state_sb` into one of `kLowSadLowSumdiff` / `kLowSadHighSumdiff` / `kHighSadLowSumdiff` / `kHighSadHighSumdiff` / `kLowVarHighSumdiff` / `kVeryHighSad`. Also sets `zero_temp_sad_source`. **NOT PORTED** — rvp9 has `ContentStateSb::Normal` plumbing in the inter picker but does not compute it. Affects: scale-of-thresholds, scene-change classification, screen-content gating, force-64-split gating, and several pickmode early-exits.

`force_64_split` (`:1294-1297`): scene-change OR (`VP9E_CONTENT_SCREEN` AND `compute_source_sad_onepass` AND `use_source_sad` AND NOT `zero_temp_sad_source`). **NOT PORTED**.

### 4. Motion-aware partition descent (RT path) — `nonrd_pick_partition`

libvpx's `nonrd_pick_partition` (`vp9_encodeframe.c:4922-5181`) does RD-driven partition search at cpu-used 5-8 when `partition_search_type ∈ {ML_BASED_PARTITION, REFERENCE_PARTITION}`. Structure:

1. Compute `partition_none_allowed` / `partition_horz_allowed` / `partition_vert_allowed` from `auto_min_max_partition_size` + `use_square_partition_only`.
2. Optional ML predictor (`use_ml_based_partitioning` → `ml_predict_var_partitioning`).
3. Try PARTITION_NONE via `nonrd_pick_sb_modes`, add `partition_cost[ctx][NONE]`, compare against best.
4. PARTITION_NONE breakout: if rate AND dist are both far below the q-conditional `partition_search_breakout_thr` thresholds → skip SPLIT/HORZ/VERT.

## Cross-cutting gaps

### G1 — Partition shape is square-only (no HORZ / VERT)

rvp9's variance picker (F8.2) and motion-aware descent (F.3) both emit only `{PARTITION_NONE, PARTITION_SPLIT}` square leaves. libvpx emits BLOCK_64X32 / BLOCK_32X64 / BLOCK_32X16 / BLOCK_16X32 / BLOCK_16X8 / BLOCK_8X16 in `set_vt_partitioning` (`vp9_encodeframe.c:472-548`) and in `rd_pick_partition` (the HORZ/VERT branches `:4342-4436`). The wire format supports these (rvp9-decoder handles them), and the mi-grid carries `sb_type`, but the encoder side never picks them.

**Impact:** medium-high. Rectangular partitions are load-bearing for motion boundaries (a horizontally-moving object's lower edge benefits from BLOCK_64X32). The mode-pick rate-cost analysis in libvpx repeatedly shows H/V partitions winning ~15-25 % of decisions on natural-content frames; rvp9 cannot reach those decisions today.

**LOC to close:** ~80 (set_vt_partitioning extension to variance picker) + ~85 (nonrd HORZ/VERT in nonrd_pick_partition) + ~92 (rd_pick_partition HORZ/VERT, also requires rd_pick_partition itself).

### G2 — No source-SAD pre-pass / content classification (`content_state_sb`, `force_64_split`, `zero_temp_sad_source`)

`avg_source_sad` (`vp9_encodeframe.c:1209-1257`) is the cross-cutting input for: `set_vbp_thresholds` (via `scale_part_thresh_sumdiff`), `choose_partitioning` (force_64_split, vbp_threshold_sad-zero override, copy_partition gate), pickmode (`skip_low_source_sad`, `lowvar_highsumdiff`, `force_skip_low_temp_var`), and rate-control (`high_source_sad`). **NOT PORTED** anywhere.

**Impact:** medium-high — affects partition decisions on scene changes (no force-64-split → no big-block fallback on uncovered regions) AND on stable content (no copy-partition → wasted decisions on identical SBs frame-over-frame).

**LOC to close:** ~50 (avg_source_sad in pre-analysis pipeline A5) + ~20 (wire content_state into partition + pickmode).

### G3 — No MV-based partition ref pick / `int_pro_motion_estimation` integration

libvpx's `choose_partitioning` runs `vp9_int_pro_motion_estimation` on the 32x32 / 64x64 SB (`vp9_encodeframe.c:1455-1481`) before the variance pyramid, then uses the resulting `y_sad` (vs `y_sad_g` for GOLDEN) to pick the partition reference frame AND populates `pred_mv[LAST_FRAME]`, `sb_mvcol_part`, `sb_mvrow_part` for downstream pickmode use. rvp9's `choose_partitioning` always uses ZEROMV against LAST.

`vp9_int_pro_motion_estimation` itself is ported (`crates/rvp9-core/src/mv_search/int_pro_me.rs`, A1 zone) but **not wired into the partition path**.

**Impact:** high — the partition variance computation against a static reference systematically over-splits on high-motion content (everything looks high-variance vs the previous frame's pixels), and the picker then doesn't get the SB-level MV that primes its diamond searches.

**LOC to close:** ~30.

### G4 — No PC_TREE / save_context / restore_context

libvpx maintains a per-thread PC_TREE that carries `PICK_MODE_CONTEXT` state across the recursive partition descent. `save_context` / `restore_context` (`vp9_encodeframe.c:2170-2226`) snapshot the entropy + segment + above/left contexts before each speculative branch and roll back after. rvp9's descent carries state on the stack, doesn't snapshot, and doesn't roll back — which is fine for the current square-only NONE-vs-SPLIT decision (no speculative encode happens during descent), but is load-bearing for HORZ/VERT trials (where libvpx actually `encode_superblock`s the first child of HORZ to update entropy context for the second child at `:4363, 4412`).

**Impact:** medium. Implementation gap that blocks HORZ/VERT and rd_pick_partition adoption.

**LOC to close:** ~150 (PC_TREE struct + save/restore + threading).

### G5 — No copy-partition / prev-partition reuse

libvpx's `copy_partitioning` (`:938-966`) reuses the previous frame's partition for SBs with low source-SAD, controlled by `vbp_threshold_copy`, `max_copied_frame`, and `copied_frame_cnt[]`. Saves ~30 % of partition-decision work on stable content. **NOT PORTED**.

`scale_partitioning_svc` and `update_partition_svc` (SVC variants) also NOT PORTED — A18 territory.

**Impact:** low for quality (the decision is "reuse same partition" — same output bits), medium-high for encode speed on stable content.

### G6 — No `chroma_check` / `color_sensitivity`

libvpx's `chroma_check` (`:1173-1207`) runs UV SAD comparison and sets `x->color_sensitivity[0/1]`, used by pickmode to enable UV-plane work selectively. **NOT PORTED**.

**Impact:** medium. Affects UV residual coding decisions; on chroma-significant content (skin, sky), the absence forces always-on UV processing.

### G7 — No `set_low_temp_var_flag` / `variance_low[25]`

Sets per-32x32-block `variance_low[]` bits from the partition pass (`:829-893`), which pickmode then reads to short-circuit modes (`force_skip_low_temp_var`). **NOT PORTED**.

**Impact:** low-medium quality, medium encode speed.

### G8 — RDO partition (cpu-used 0-4) is entirely absent

`rd_pick_partition` + `rd_use_partition` + `rd_pick_sb_modes` + `rd_auto_partition_range` + `set_partition_range` + `set_fixed_partitioning` + `find_partition_size` are **all NOT PORTED**. rvp9 has no cpu-used 0-4 path today.

**Impact:** **high** for cpu-used 0-4 quality parity. The goal doc explicitly scopes all cpu-used 0..=8 as IN scope.

**LOC to close:** ~1200+ (rd_pick_partition body + dependencies). Cross-zone dependencies: A13 (RDO mode-decision), A14 (sub-8x8 picker), A15 (compound prediction), A11 (segmentation/AQ feeding `wiener_var_segment`, `set_ssim_rdmult`).

### G9 — ML partition (cross-zone A21) entirely absent

All `ml_*` helpers and the `nn_predict` runtime are NOT PORTED. Affects: cpu-used 0-4 RDO breakout (`ml_predict_breakout`), cpu-used 0-4 partition pruning (`ml_pruning_partition`, `ml_prune_rect_partition`, `ml_predict_var_rd_partitioning`), cpu-used 5-8 ML_BASED_PARTITION path (`ml_predict_var_partitioning`).

**Impact:** medium for cpu-used 0-4 (speed feature, mostly orthogonal to quality but skipping it bloats decode-time and risks suboptimal partitions); low for cpu-used 5-8 (only ML_BASED_PARTITION mode uses it, and that's not the default).

**LOC to close:** ~600 (5 ML helpers + nn_predict + 4 NN weight tables).

### G10 — High-bit-depth partition paths absent

`compute_minmax_8x8`, `fill_variance_4x4avg`, `fill_variance_8x8avg`, and the threshold-table setup all have `CONFIG_VP9_HIGHBITDEPTH` branches in libvpx. rvp9's partition picker is u8-only (`partition.rs:74` imports `u8` plane data). **NOT PORTED**.

**Impact:** Profile 2/3 partition is blocked entirely (and Profile 2/3 RT encode would call this path).

**LOC to close:** ~120 (parametrize PlaneRef + variance over `u8`/`u16`).

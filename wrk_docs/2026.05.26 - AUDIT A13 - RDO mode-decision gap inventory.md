## Section-by-Section Narrative

### 1. Driver entries (rows 1-4)

`vp9_rd_pick_inter_mode_sb` (rdopt.c:3438) is the main RDO inter-mode driver, called by `rd_pick_partition` at every leaf decision when `cpi->sf.use_nonrd_pick_mode == 0` (i.e., cpu-used 0..=4). It iterates `MAX_MODES = 30` candidates from `vp9_mode_order[]` (rdopt.c:88-128), maintains per-tile RD thresholds (`tile_data->thresh_freq_fact` / `rd_opt->threshes`), and dispatches to `handle_inter_mode` for inter candidates and `super_block_yrd` + `choose_intra_uv_mode` for intra. **Status: NOT PORTED.** rvp9's `lib.rs:1909` (intra picker call) and `lib.rs::3252-3254` (inter picker call) wire only the RT picker. Grep for `rd_pick_inter_mode_sb` in `crates/` returns zero matches.

`vp9_rd_pick_intra_mode_sb` (rdopt.c:3222) is the intra-only driver used for keyframes and intra-only frames at cpu-used 0..=4. It calls `rd_pick_intra_sby_mode` (>=8x8) or `rd_pick_intra_sub_8x8_y_mode`, then `rd_pick_intra_sbuv_mode`. **Status: NOT PORTED.** rvp9's keyframe path uses `pick_intra_mode_luma` (rvp9-core/mode_decision/intra.rs) which is the RT-equivalent function and only iterates Y; it lacks the per-bsize TX-size RD search and the UV intra search.

`vp9_rd_pick_inter_mode_sub8x8` (rdopt.c:4285) handles BLOCK_8X8 with 4×4/4×8/8×4 leaves. It iterates `MAX_REFS = 6` ref combinations (`vp9_ref_order[]`) and calls `rd_pick_best_sub8x8_mode` for each. **Status: NOT PORTED.** rvp9 doesn't have a sub-8x8 inter picker — covered in zone A14.

`vp9_rd_pick_inter_mode_sb_seg_skip` (rdopt.c:4189) handles the segment-skip case (`SEG_LVL_SKIP` active). Forces ZEROMV/LAST_FRAME and only searches the switchable filter. **Status: NOT PORTED.**

### 2. Per-mode RD wrapper (rows 5, 35, 39, 40, 41)

`handle_inter_mode` (rdopt.c:2812) is the per-mode core. For one `(this_mode, ref_frame[2])` combination it: (a) runs the MV search (single or joint), (b) runs the discount-NEWMV test, (c) runs the switchable-filter inner loop (rdopt.c:3010-3116) including `build_inter_pred_model_rd_earlyterm`, (d) calls `super_block_yrd` + `super_block_uvrd` for the final full RD, and (e) decides skip via the cost-of-skip-flag tie-break. **Status: NOT PORTED — entire 410-LOC function is absent.** rvp9's `evaluate_candidate` (`mode_decision/inter.rs:1517+`) is the RT-equivalent and is structurally simpler — no filter inner loop with model-RD early-term, no joint MV search, no compound branch, no `build_inter_pred_model_rd_earlyterm`. Helpers `discount_newmv_test`, `restore_dst_buf`, `compare_mv_mode_rate`, `skip_single_mode_based_on_mode_rate` are all referenced only from `handle_inter_mode`, all NOT PORTED.

### 3. Transform-size RD search (rows 6-15)

`super_block_yrd` (rdopt.c:1025) is a 17-line dispatcher: if `tx_size_search_method == USE_LARGESTALL || lossless` → `choose_largest_tx_size`, else `choose_tx_size_from_rd` (rdopt.c:907-1023). The latter loops TX sizes from `max_tx_size` down to `max(start - tx_size_search_depth, 0)`, calls `txfm_rd_in_plane` per size, picks the lowest RD including the `r_tx_size = tx_size_cost[max_tx_size-1][ctx][n]` signalling cost. **Status: NOT PORTED.** rvp9 always uses `max_txsize(block_size)` and never RD-searches across TX sizes (cf. `block_yrd.rs:max_txsize`).

`txfm_rd_in_plane` → `block_rd_txfm` → `dist_block` is the transform-domain RD-evaluation chain (rdopt.c:854 → 699 → 561). `block_rd_txfm` performs full forward+quantize, optional trellis (`vp9_optimize_b`), computes both transform-domain and pixel-domain distortion, and short-circuits via `skip_txfm[]` flags. `dist_block` computes `(coeff - dqcoeff)^2 >> shift` (TX-domain, the canonical libvpx distortion model) **or** the pixel-domain SSE post-iDCT depending on `x->block_tx_domain`. **All NOT PORTED.** rvp9 has `block_yrd::block_error_fp` and `intra::block_yrd_distortion` which implement the TX-domain residual energy with the same shift table, but the per-TX-block iteration + trellis + skip_txfm short-circuit is absent.

`pixel_sse` (rdopt.c:521-559) computes visible-region SSE post-iDCT, used by `dist_block` when `block_tx_domain == 0`. **NOT PORTED.** rvp9's intra/inter RT path uses full-block SSE without the visible-region clipping (block-edge pixels in partial blocks are scored against garbage in the un-visible region).

### 4. MV search inside RDO (rows 17-20, 81-87)

`single_motion_search` (rdopt.c:2564) is the RDO-side MV search. It honours `auto_mv_step_size` (rdopt.c:2616), `adaptive_motion_search` with a `pred_mv_sad`-based step-param boost + ratio bail-out (rdopt.c:2634-2659), and `enhanced_full_pixel_motion_search` which tries up to 3 candidate seeds and picks the best (rdopt.c:2679-2723). It dispatches to `vp9_full_pixel_search` with the `search_method` from sf (NSTEP / HEX / BIGDIA / SQUARE / FAST_DIAMOND), then `find_fractional_mv_step`. **Status: NOT PORTED.** rvp9 has `mv_search/full_pixel.rs::diamond_search_sad` (the NSTEP fallback) and `mv_search/sub_pixel.rs::vp9_find_best_sub_pixel_tree_pruned_more` only. The multi-seed + adaptive-step + scaled-ref logic is absent.

`joint_motion_search` (rdopt.c:1907) is the compound-prediction MV refine — iterative motion search where each iteration fixes one ref's MV and refines the other. Up to 4 iterations, with `skip_iters` early-bail. **Status: NOT PORTED.** rvp9 has no compound prediction support at all (zone A15).

`get_joint_search_iters` (rdopt.c:1896-1905) is a tiny helper that selects 0/2/4 iterations from the `comp_inter_joint_search_iter_level` speed feature; also NOT PORTED.

### 5. Intra search (rows 21-24, 42-44, 50)

`rd_pick_intra_sby_mode` (rdopt.c:1363) loops `mode ∈ DC_PRED..=TM_PRED`, sets `mic->mode`, calls `super_block_yrd` (which RD-searches TX sizes), and picks the min-RD mode. **Status: NOT PORTED.** rvp9's `pick_intra_mode_luma` (intra.rs) is structurally similar but uses fixed `max_txsize(block_size)` and TX-domain distortion only.

`rd_pick_intra_sbuv_mode` (rdopt.c:1468) iterates the UV mode candidate set (subject to `intra_uv_mode_mask[max_tx_size]`), calls `super_block_uvrd` per mode. **Status: NOT PORTED.** rvp9 has `pick_intra_mode_uv` but it doesn't run the full TX-size RD, just a single TX iteration.

`rd_pick_intra4x4block` (rdopt.c:1061-1297) is the per-4×4 intra search used inside `rd_pick_intra_sub_8x8_y_mode`. Per mode: predict → subtract → fdct/fht4x4 → quantize_b → cost_coeffs → block_error → iht4x4_add (so the next 4×4 sees the actual recon). **Status: NOT PORTED.**

`rd_pick_intra_sub_8x8_y_mode` (rdopt.c:1299) drives `rd_pick_intra4x4block` over the 4 sub-blocks of an 8×8 with the libvpx canonical above/left mode-context lookup for KF rate. **NOT PORTED.**

`choose_intra_uv_mode` (rdopt.c:1531) selects between the cheap `rd_sbuv_dcpred` (DC only) and full `rd_pick_intra_sbuv_mode` based on `sf.use_uv_intra_rd_estimate`. `conditional_skipintra` (rdopt.c:1044) prunes oblique directional modes when the current best intra is not a neighbour direction. Both NOT PORTED.

### 6. Sub-8x8 inter (rows 25-29)

`rd_pick_best_sub8x8_mode` (rdopt.c:2077-2428) iterates each of the 4 sub-blocks within an 8×8 across `NEARESTMV / NEARMV / ZEROMV / NEWMV`, including per-sub-block NEWMV searches, with `vp9_append_sub8x8_mvs_for_idx` for the per-sub MV-ref candidates. `encode_inter_mb_segment` (rdopt.c:1608) is the actual fwd-DCT + quantize + cost_coeffs + block_error for each sub-block. `set_and_cost_bmi_mvs` is the per-sub MV-cost helper, and `cost_mv_ref` and `check_best_zero_mv` are the mode-cost lookups. **All NOT PORTED.** This is the entire sub-8x8 chain (zone A14 overlap).

### 7. Ref-frame book-keeping (rows 30-33, 53-71)

`estimate_ref_frame_costs` (rdopt.c:2430) computes the 6 per-ref-frame costs (intra cost, three single-ref combos with two probs each, two compound combos). Uses `vp9_get_intra_inter_prob`, `vp9_get_reference_mode_prob`, `vp9_get_pred_prob_single_ref_p1/p2`, `vp9_get_pred_prob_comp_ref_p`. **Status: NOT PORTED.** rvp9 uses a constant approximation in the RT picker (gap #19 in the picker inventory).

`setup_buffer_inter` (rdopt.c:2511) does per-ref-frame `vp9_setup_pred_block` + `vp9_find_mv_refs` + `vp9_find_best_ref_mvs` + `vp9_mv_pred`. **PARTIAL** (find_mv_refs ported; vp9_mv_pred and vp9_find_best_ref_mvs not — same as A1 picker rows 27 and 32).

`store_coding_context` (rdopt.c:2490) snapshots the picked mode + buffers + diff arrays into the `PICK_MODE_CONTEXT`. `swap_block_ptr` (rdopt.c:137) is the coeff/qcoeff/dqcoeff buffer-ring swap (PICK_MODE_CONTEXT has 3 such buffers per plane). Both **NOT PORTED**. rvp9 stores the picked mode directly in its `mode_info::ModeInfo`; there's no PICK_MODE_CONTEXT recurse-and-restore.

`mode_skip_mask[]` (per-ref bitmask) and `ref_frame_skip_mask[2]` (rdopt.c:3480-3612, 3685-3689) encode the dynamic mode-pruning rules: `is_src_frame_alt_ref` → only ZEROMV/ALTREF; `alt_ref_search_fp` → ALTREF-only fast path; `adaptive_mode_search` → GOLDEN-out when SAD ratio bad; `max_intra_bsize` → INTRA-out for large blocks; `FLAG_SKIP_INTRA_LOWVAR` / `FLAG_SKIP_INTRA_BESTINTER` / `FLAG_SKIP_INTRA_DIRMISMATCH` / `FLAG_SKIP_COMP_BESTINTRA`. The `LAST_FRAME_MODE_MASK`, `GOLDEN_FRAME_MODE_MASK`, `ALT_REF_MODE_MASK` macros (rdopt.c:47-54) drive the "after best-mode found at midx == mode_skip_start, suppress siblings of that ref" rule. **All NOT PORTED.**

`vp9_mode_order[MAX_MODES = 30]` (rdopt.c:88-128) is the master mode-iteration order (NEARESTMV-LAST, NEARESTMV-ALT, NEARESTMV-GOLD, DC, NEWMV-LAST, NEWMV-ALT, ..., D45_PRED) — drives the entire driver. **NOT PORTED.** `vp9_ref_order[6]` for the sub-8x8 driver also absent.

`schedule_mode_search` (rdopt.c:3622-3638) re-sorts the mode-map by `mode_threshold` so cheap modes try first. **NOT PORTED.** `motion_field_mode_search` (rdopt.c:3700-3745) uses neighbour MVs to detect `const_motion` regions and prune NEARMV/ZEROMV. **NOT PORTED.**

`alt_ref_search_fp`, `adaptive_mode_search`-GOLDEN-prune, `max_intra_bsize`, the four `FLAG_SKIP_INTRA*` and the compound-pred sign-bias / `allow_comp_inter_inter` gates are all in-loop continue-statements. **All NOT PORTED.**

### 8. Switchable-filter loop (rows 74-78)

The filter inner loop inside `handle_inter_mode` (rdopt.c:3010-3116) iterates `EIGHTTAP / EIGHTTAP_SMOOTH / EIGHTTAP_SHARP`, builds inter prediction, calls `build_inter_pred_model_rd_earlyterm` (variance-domain RD with skip-flag detection), and picks the min-RD filter. Gated by `disable_filter_search_var_thresh` (source-variance below → force EIGHTTAP), `interp_filter_search_mask` (adaptive prune of filters), `cb_pred_filter_search` (chessboard pre-pick from neighbours), `early_term_interp_search_plane_rd` (per-plane early bail). **Status: NOT PORTED for the RDO path.** rvp9 has a 2-filter RT-side loop in `inter.rs:1517` (eight-tap + smooth only), no rd-earlyterm integration.

### 9. Post-pick fix-ups & adaptation feedback (rows 69-73)

After the best mode is picked, rdopt.c:4085-4104 checks "if best is NEWMV but its MV equals NEAREST/NEAR/ZERO of the same ref, rewrite the mode to that cheaper one" — a critical correction because NEWMV costs ~1 bit more than NEAREST/NEAR. **NOT PORTED** — rvp9 emits NEWMV unconditionally when the winner uses an MV that the searcher found.

`best_pred_rd[REFERENCE_MODES]` (rdopt.c:4026-4049) tracks single/compound/hybrid wins for the encoder-side `vp9_adapt_mode_probs` feedback. `best_filter_rd[]` + `filter_cache[]` (rdopt.c:3514, 4052-4073) does the same for switchable-filter adaptation. `best_pred_diff[]` / `best_filter_diff[]` (rdopt.c:4142-4160) emit the deltas to the PICK_MODE_CONTEXT. **All NOT PORTED.** This is the producer side of the frame-context adaptation feedback (related to cross-cutting gap #45 in the picker inventory).

`vp9_has_high_freq_in_plane` post-pick check (rdopt.c:4166-4180) adjusts `best_mode_skippable` based on whether any plane has high-freq coefficients. **NOT PORTED.**

### 10. Film-mode / variance adjustment (row 34, 52)

`rd_variance_adjustment` (rdopt.c:3281-3363) compares source-block variance vs reconstructed-block variance, and biases the RD value upward (penalising the candidate) when reconstruction has much lower variance than source — anti-blur heuristic for film content. Has a `VP9E_CONTENT_FILM` special path. **NOT PORTED.** rvp9 has no content-type handling.

The `recon_buf[64*64]` infrastructure inside `vp9_rd_pick_inter_mode_sb` (rdopt.c:3497-3508) exists only to feed `rd_variance_adjustment` (recon is otherwise unused). **NOT PORTED.**

### 11. Image-edge helpers (rows 48-49)

`vp9_active_edge_sb` / `vp9_active_h_edge` / `vp9_active_v_edge` / `vp9_internal_image_edge` (rdopt.c:3367-3435) use 2-pass first-pass stats (`inactive_zone_rows/cols`) to detect "real edge" inside the active image (e.g. letterbox bars). Used by the sub-8x8 driver (rdopt.c:4324) to override the RD threshold. **All NOT PORTED.** Requires 2-pass stats infra (zone A3).

### 12. Coef-cost path (row 13, 50)

`cost_coeffs` (rdopt.c:358-459) is the full per-block coefficient rate calculation: walks the qcoeff array in scan order, looks up `token_costs[tx_size][type][is_inter][band][ctx][token]` for each non-zero coeff, plus the trailing EOB token. The `use_fast_coef_costing` path uses a 2-token-context approximation. **Status: PARTIAL.** rvp9 has the token-cost table in `cost/coef_cost.rs` and the full-cost `vp9_cost_coeffs` equivalent in the same file, but the band-table walker and the `use_fast_coef_costing` fast path are not driven from any RDO entry — they're consumed only by the RT block_yrd.

### 13. Encode/quant helpers from outside rdopt.c that the RDO path needs (rows 88-92, 97)

`vp9_optimize_b` / `do_trellis_opt` (encodemb.c) — coefficient trellis optimisation, gated by `trellis_opt_tx_rd.method/.thresh`. **NOT PORTED.** This is a significant quality lever at low cpu-used.

`vp9_xform_quant_fp` / `vp9_xform_quant_dc` / `vp9_xform_quant` — encode-side fwd-DCT + quantize. rvp9 has `vp9_quantize_b` and `vp9_quantize_b_32x32` but not the `_fp` (fast no-zbin) or `_dc` (DC-only) variants. **PARTIAL.**

`vp9_encode_block_intra` — intra-block encode for the in-RD search (needed by block_rd_txfm's intra branch). **NOT PORTED.**

`vp9_get_entropy_contexts` / `vp9_foreach_transformed_block_in_plane` — entropy-context prep and per-TX-block iteration. Decoder side exists in rvp9 but the encoder-side per-plane RD-search variant is absent. **PARTIAL / NOT PORTED.**

### 14. Pre-existing pieces (rows 46, 93-96, 98)

Several helpers exist in rvp9 because the RT picker shares them with RDO:

- `vp9_block_error_fp_c` → `mode_decision/block_yrd.rs::block_error_fp` (PORTED).
- `vp9_get_intra_cost_penalty` → `cost::get_intra_cost_penalty` — PORTED but **only consumed by `inter.rs:1686` (RT picker)**; an RDO path would need to call it from the (absent) `vp9_rd_pick_inter_mode_sb`.
- `vp9_update_rd_thresh_fact` → `mode_decision/rd_thresh.rs::update_thresh_freq_fact` (PORTED).
- The `model_rd_for_sb_y` family in `mode_decision/model_rd.rs` (PORTED but RT-only consumer).
- `get_uv_tx_size` LUT in `block::uv_plane_block_size` (PORTED).

These are PORTED-as-libraries but the RDO **caller** is missing, so they currently contribute nothing to cpu-used 0..=4. Re-using them when porting `handle_inter_mode` is a major LOC saving.

## Cross-Cutting Gaps

### A — PICK_MODE_CONTEXT and the RD-search recurse/restore protocol
**Status: NOT PORTED.** libvpx's RDO recursively descends the partition tree at non-RT speeds. At each node, `rd_pick_partition` (encodeframe.c — zone A4) calls `rd_pick_sb_modes` → `vp9_rd_pick_inter_mode_sb` and stashes the result in a `PICK_MODE_CONTEXT` so the recursion can compare NONE vs SPLIT vs HORZ vs VERT cleanly. The context owns 3 buffers per plane (coeff/qcoeff/dqcoeff) which `swap_block_ptr` rotates so the search can roll back. rvp9 has no equivalent — its partition is fixed (zone A4) and mode picking is single-pass. Wiring this requires both the `PICK_MODE_CONTEXT` struct and `swap_block_ptr` / `store_coding_context`, neither ported.

### B — `tx_size_search_method` is hardcoded to USE_LARGESTALL
**Status: NOT PORTED.** rvp9 always uses `max_txsize(block_size)` for every block (cf. `intra.rs`, `block_yrd.rs`). libvpx's `choose_tx_size_from_rd` RD-searches TX sizes when `tx_mode == TX_MODE_SELECT` (the cpu-used 0..=4 default). On textured content this costs noticeable BD-rate because the encoder cannot trade TX-size bits for coefficient bits. Already flagged in picker inventory P2; surfaces here as the same gap with a different driver.

### C — Frame-context adaptation feedback (producer side)
**Status: NOT PORTED.** rdopt.c:4026-4076 + 4142-4160 emit `best_pred_diff[REFERENCE_MODES]` and `best_filter_diff[CTX]` per block, consumed at frame-end by `vp9_adapt_mode_probs` / `vp9_adapt_mv_probs` / `vp9_adapt_coef_probs` (encoder.c:5833-5836, picker inventory cross-cutting #2). Without these, even if the decoder-side adapt functions ARE wired (the picker inventory P5), there are no per-frame statistics being collected on the encoder side. RDO is the natural producer.

### D — `block_tx_domain` flag (default vs trellis-on)
**Status: NOT PORTED.** libvpx's `block_rd_txfm` distinguishes TX-domain vs pixel-domain SSE for the same residual based on `x->block_tx_domain`. At cpu-used 0..=2 with trellis on, the pixel-domain path is used (it sees the actual quantization error after iDCT). At higher cpu-used the TX-domain path is used (cheaper, same shift table as rvp9's current intra/inter block_yrd). rvp9 only has the TX-domain path; the pixel-domain RDO path for low cpu-used is absent.

### E — Inter-mode order matters (RDO's interleave vs RT's per-ref loop)
**Status: NOT PORTED.** `vp9_mode_order[MAX_MODES]` interleaves modes across refs (rdopt.c:88-128). The driver loops mode-by-mode, and after `mode_skip_start` it prunes whole-ref-families based on best-so-far. rvp9's RT picker loops by-ref, by-mode (lib.rs:3252-3254). Same divergence as picker row 28, but more severe at non-RT because the mode count is 30 (vs 12 for RT).

### F — Compound-pred path is wholly absent
**Status: NOT PORTED.** Compound is "in scope" per the goal doc, but the entire compound code path inside `handle_inter_mode` (joint MS, compound MV cost, compound ref probs) is missing. This is the natural intersection with zone A15. RDO is the only entry point that activates compound (`vp9_mode_order` has compound entries 14, 15, 17-22), so until A15 + A13 driver land together, compound stays at zero PSNR contribution.

### G — Sub-8x8 inter is its own driver (sub8x8 picker missing)
**Status: NOT PORTED.** `vp9_rd_pick_inter_mode_sub8x8` and its workhorse `rd_pick_best_sub8x8_mode` are the entire BLOCK_8X8 search at non-RT speeds. rvp9's encoder never invokes a sub-8x8 inter picker (zone A14). Without this, 4×4/4×8/8×4 leaves go unused.

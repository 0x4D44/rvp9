## 0. Cross-Cutting Gaps (outside `vp9_pick_inter_mode` itself)

### `inter_mode_ctx` hardcoded to 0
**Status: NOT PORTED**

The encoder passes `inter_mode_ctx: 0` on every call to the picker (`lib.rs:3217`). libvpx computes this per-block from neighbour modes via `x->mbmi_ext->mode_context[ref_frame]` (populated by `find_mv_refs` / `mv_refs_rt`). The `find_mv_refs` output already includes `mode_context` — rvp9 calls `find_mv_refs` and ignores the returned context.

Context 0 ("both neighbours have zero MV") has probs `[2, 173, 34]`:
- NEARESTMV: ~0.6 bits
- NEARMV: ~2.5 bits
- NEWMV: **~2.9 bits**

Context 3 ("one predicted/zero + one new MV", typical mixed motion) has probs `[7, 94, 66]`:
- NEARESTMV: ~1.4 bits
- NEARMV: ~1.4 bits
- NEWMV: **~1.9 bits**

By always using context 0, the encoder **over-charges NEWMV by ~1 bit per block** relative to the actual bitstream cost. On foreman at 100 kbps (~2,500 NEWMV-eligible blocks), this artificially inflates NEWMV's rate penalty and is a direct contributor to the "picker rejects NEWMV" finding from Track G's F.0.2 oracle.

**~10 LOC** to thread the `mode_context` return from `find_mv_refs` into the picker params. **HIGH impact** — the cheapest single fix likely to move the needle on NEWMV picks.

### Frame context adaptation (`refresh_frame_context`)
**Status: NOT PORTED**

The encoder always emits `refresh_frame_context: false` (`frame_loop.rs:1503`) and builds ALL cost tables from `FrameContext::new_default()` (`lib.rs:2439-2440`). libvpx adapts per-frame via `vp9_adapt_mode_probs`, `vp9_adapt_mv_probs`, `vp9_adapt_coef_probs` (encoder.c:5833-5836) and sets `refresh_frame_context: true` so the decoder tracks the same adapted tables.

This means:
- MV-cost table frozen at default NMV probs. If content has consistent motion direction, libvpx adapts so those MVs are cheap; rvp9 charges symmetric default rates forever.
- Inter-mode costs frozen. If NEARESTMV dominates (64% on foreman), libvpx adapts so NEARESTMV costs fewer bits; rvp9 charges default rates.
- Skip probs, partition probs, coef probs — all frozen at defaults.

The encoder and decoder agree (both use defaults), so there is no encoder/decoder mismatch. But the cost model systematically diverges from the true bitstream cost over multi-frame sequences, producing suboptimal RD decisions.

**~60 LOC** (backward-adapt functions exist in the core crate for the decoder; wiring them into the encoder frame loop and flipping `refresh_frame_context: true` is the work). **MEDIUM-HIGH impact** — systematic miscalibration that compounds over the sequence.

## 1. Candidate Enumeration

### Multi-reference iteration
**Status: PARTIAL**

libvpx iterates `RT_INTER_MODES = 12` candidates: `{LAST, GOLDEN, ALTREF} x {ZERO, NEAREST, NEAR, NEW}` in a specific interleaved order (pickmode.c:1239-1246). The SVC variant uses 8 modes. `usable_ref_frame` gates which refs are actually tested (pickmode.c:1908-1976).

rvp9 iterates `{ZERO, NEAREST, NEAR, NEW}` on LAST, then separately on GOLDEN, taking the min-RD winner (lib.rs:3252-3254). This is functionally close but differs in:

- **Interleaved order**: libvpx interleaves refs (LAST-ZERO, LAST-NEAREST, GOLDEN-ZERO, LAST-NEAR, LAST-NEW, GOLDEN-NEAREST, ...) which matters because early-exit logic (`x->skip`, `best_early_term`) can prune later candidates based on earlier results from a DIFFERENT ref frame. rvp9 evaluates all 4 LAST candidates, then all 4 GOLDEN candidates -- no cross-ref early exit.
- **ALTREF ref frame**: not tested. `usable_ref_frame = ALTREF_FRAME` occurs in VBR lag mode, which is out of scope for CBR-RT but is still active in the realtime path when `cpi->oxcf.lag_in_frames > 0`.
- **No `usable_ref_frame` gating**: libvpx dynamically limits the ref search based on `frames_since_golden`, `avg_frame_low_motion`, `content_state_sb`, etc.
- **No `ref_frame_skip_mask`**: libvpx skips entire ref frames when `pred_mv_sad` is much worse than another ref.
- **No duplicate-MV dedup**: libvpx's `mode_checked[][]` + the duplicate-zero-MV skip (pickmode.c:2259-2270) avoid re-evaluating when NEARMV == NEARESTMV == 0. rvp9 evaluates all 4 candidates unconditionally.

**PARTIAL notes for GOLDEN**: A15 Phase B (2026-05-22) added dual-ref {LAST, GOLDEN} support. The iteration structure diverges from libvpx's interleaved order but the mode set is the same for non-SVC, non-VBR-lag usage.

### `find_predictors`
**Status: PARTIAL**

libvpx's `find_predictors` (pickmode.c:1256-1297) does per-ref-frame setup: `vp9_setup_pred_block`, `vp9_find_mv_refs` (or `mv_refs_rt`), `vp9_find_best_ref_mvs`, and `vp9_mv_pred`. rvp9 covers:

- `find_mv_refs` -- PORTED (spatial + temporal via A18)
- `lower_mv_precision` -- PORTED
- `vp9_find_best_ref_mvs` -- NOT PORTED (selects between candidates[0] and candidates[1] based on `allow_hp`; rvp9 just uses `mvs[0]` directly)
- `vp9_mv_pred` -- NOT PORTED (computes `pred_mv_sad[ref_frame]` and `mv_best_ref_index[ref]` which seed `combined_motion_search`'s `mvp_full`)
- `vp9_setup_pred_block` -- NOT PORTED (rvp9 builds PlaneRef manually)

### `mv_refs_rt`
**Status: PARTIAL**

libvpx's `mv_refs_rt` (pickmode.c:60-153) is a stripped-down MV-ref search that returns a `const_motion` flag. rvp9 uses the full `find_mv_refs` from the core crate (originally written for the decoder), which is functionally equivalent but heavier. The `const_motion` flag (used to skip NEARMV when all neighbours have the same MV) is not surfaced.

**Status: NOT PORTED**

- `mv_best_ref_index[ref]` which seeds the full-pel search start position in `combined_motion_search`
- `best_pred_sad` threshold for GOLDEN NEWMV skip (pickmode.c:2273-2284)

Without this, rvp9 always seeds the diamond from `nearest` and has no ref-frame-level SAD-based pruning. ~50 LOC. Medium impact.

## 3. RD Model

### `model_rd_for_sb_y`
**Status: NOT PORTED**

This is the **primary** RD cost estimator (pickmode.c:636-717). It:
1. Computes `var = fn_ptr[bsize].vf(src, dst)` (full-block variance and SSE of src vs predicted)
2. Calls `calculate_tx_size` to pick TX size adaptively based on var/sse ratio
3. Sets `skip_txfm[0]` to `SKIP_TXFM_AC_ONLY` / `SKIP_TXFM_AC_DC` / `NONE` based on quantizer-dependent thresholds
4. Calls `vp9_model_rd_from_var_lapndz` separately for DC and AC components
5. Returns `(rate, dist)` in RD-scaled units

rvp9 skips this entirely. Instead, it runs the full forward/inverse transform round-trip and computes pixel-domain SSE(src, recon) as the distortion. This is more accurate per-candidate but ~10x more expensive and, critically, does not drive the TX-size selection or the skip_txfm early-exit that libvpx uses to short-circuit later computation.

~80 LOC. **HIGH impact** -- this is the #1 quality-relevant gap because it drives TX-size selection and the early-term flag.

### `model_rd_for_sb_y_large`
**Status: NOT PORTED**

Extended version of `model_rd_for_sb_y` for large blocks (>=32x32 at CBR, pickmode.c:430-634). Computes 8x8-granularity variance/SSE, aggregates to the TX-size level, and evaluates skip_txfm with per-sub-block thresholds. Also precomputes UV skip for the early-term exit. ~200 LOC. **HIGH impact** (the early-term flag it produces short-circuits the entire `block_yrd` step at pickmode.c:2348).

### `vp9_model_rd_from_var_lapndz`
**Status: NOT PORTED**

The Laplacian-Gaussian rate-distortion model (rd.c:518-570). Maps `(variance, n_log2, quantizer)` to `(rate, distortion)` using a lookup table + polynomial fit. This is the heart of the variance-domain RD model that makes `model_rd_for_sb_y` fast. ~50 LOC, no dependencies. **HIGH impact** -- prerequisite for `model_rd_for_sb_y`.

### `calculate_tx_size`
**Status: NOT PORTED**

Adaptive TX-size selection (pickmode.c:354-385). Uses the var/sse ratio from `model_rd_for_sb_y` to choose between TX_8X8, TX_16X16, TX_32X32. Also interacts with cyclic-refresh segment boosting and screen content detection. rvp9 always uses `max_txsize(block_size)` -- no adaptive TX. ~30 LOC. **HIGH impact** -- a 32x32 TX on a textured 32x32 block wastes bits on high-frequency coefficients that would be better served by four 16x16 TXes.

### `block_yrd` (libvpx variant with Hadamard + quantize_fp)
**Status: PARTIAL**

libvpx's `block_yrd` (pickmode.c:719-845) uses `vpx_hadamard_{8x8,16x16}` + `vp9_quantize_fp` (no zbin). rvp9's implementation in `block_yrd.rs` / inlined in `inter.rs::reconstruct_via_round_trip` uses DCT + `vp9_quantize_b` (with zbin). The SATD-to-bits scaling uses K1=4 (F.4-2 calibration). Divergences documented as DV-F1-1 (Hadamard vs DCT) and DV-F1-2 (`quantize_fp` vs `quantize_b`).

Additionally, libvpx's `block_yrd` has a `use_simple_block_yrd` speed-feature gate (pickmode.c:738-749) that bypasses the Hadamard path entirely at speed >= 8 or for SVC temporal layers, falling through to `model_rd_for_sb_y` as the rate estimate. This gate is NOT PORTED.

~125 LOC. **HIGH impact** due to the `quantize_fp` vs `quantize_b` divergence affecting the coefficient magnitude and hence the SATD-to-bits calibration.

### `compute_rd_mult`
**Status: PORTED**

Faithful port in `crates/rvp9-core/src/cost/rd_mult.rs`. Same qindex-to-lambda mapping.

## 6. Skip / Breakout

### `encode_breakout_test`
**Status: NOT PORTED**

libvpx's `encode_breakout_test` (pickmode.c:933-1036) tests whether a block can be reconstructed by prediction alone (no residual) based on quantizer-dependent AC/DC variance thresholds. If the Y-plane variance is below threshold, it checks UV planes too, and if all pass, sets `x->skip = 1` with rate = mode_cost_only, dist = sse. This produces a hard early-exit from the mode loop (pickmode.c:2468-2471).

Without this, rvp9 always runs the full transform round-trip even for perfectly-predicted blocks, paying both compute cost and unnecessary coefficient bits. ~100 LOC. **Medium impact** -- the quality effect is indirect (it lets the RC allocate bits to blocks that need them instead of wasting zero-coefficient overhead on well-predicted blocks).

### Skip-flag tie-break
**Status: PARTIAL**

The libvpx skip-flag tie-break at pickmode.c:2348-2376 compares `RDCOST(rate, dist)` vs `RDCOST(0, sse)` and either adds `cost_bit(skip_prob, 0)` or collapses to `cost_bit(skip_prob, 1)` with `dist = sse`. rvp9 has this implemented but gated behind `RVP9_F1_SKIP_TIE_BREAK_ENABLE` (disabled by default; causes +3 dB regression without lambda recalibration).

### `skip_txfm[]` early-exit
**Status: NOT PORTED**

libvpx's `model_rd_for_sb_y` sets `x->skip_txfm[0]` to `SKIP_TXFM_AC_DC` when variance is below the quantizer threshold, signalling to `block_yrd` that it can skip the transform entirely. This is the fastest path for well-predicted blocks. rvp9 always runs the full transform.

### `early_term` flag
**Status: NOT PORTED**

`model_rd_for_sb_y_large` can set `*early_term = 1` when UV planes also pass the skip test (pickmode.c:600-603). This causes `block_yrd` to be skipped entirely (pickmode.c:2348), saving the Hadamard + quantize cost. It also triggers a hard early-exit from the mode loop after 2 modes (pickmode.c:2474-2478). **HIGH impact** for speed; the quality effect is that it prevents overriding a good early candidate with a marginally-better later one.

## 7. Filter Search

### `search_filter_ref`
**Status: PARTIAL**

libvpx's `search_filter_ref` (pickmode.c:1489-1574) iterates `EIGHTTAP .. EIGHTTAP_SMOOTH` (2 filters), rebuilds inter prediction per filter, runs `model_rd_for_sb_y` (or `model_rd_for_sb_y_large`), adds `vp9_get_switchable_rate`, and picks the lowest-RD filter. Prediction buffers are managed via the PRED_BUFFER ring.

rvp9 has a filter search loop in `evaluate_candidate` (inter.rs:710-721) that iterates `[EightTap, EightTapSmooth]` when `RVP9_F5_FILTER_SEARCH=1`. Each iteration rebuilds prediction + full transform round-trip + pixel SSE. Differences:

- Uses full transform round-trip instead of `model_rd_for_sb_y` (much heavier)
- Uses a flat constant `F5_SWITCHABLE_FILTER_RATE = 2048` instead of the per-context `vp9_get_switchable_rate`
- No pred-buffer reuse across filters
- Gated behind env var (disabled by default; causes +0.6-1.7 dB regression due to rate-cost mismatch)

### `vp9_get_switchable_rate`
**Status: PARTIAL**

libvpx computes the exact per-context switchable-filter rate from `switchable_interp_costs[ctx][filter]` where `ctx = vp9_get_pred_context_switchable_interp(xd)`. rvp9 has the `switchable_interp_costs` table built in `cost::symbol_costs` but the per-block context lookup is not threaded into the picker. The flat constant approximation is used instead.

## 8. Intra-in-Inter Search

### Intra fallback inside `vp9_pick_inter_mode`
**Status: NOT PORTED**

After the inter mode loop, libvpx optionally runs an intra-mode search (pickmode.c:2517-2646) gated by:
- `best_rdc.rdcost > inter_mode_thresh` (inter RD exceeds intra penalty)
- `perform_intra_pred` flag (various SVC/VBR/segment gates)
- `!x->skip_low_source_sad` and `!x->lowvar_highsumdiff`
- `bsize <= cpi->sf.max_intra_bsize`

The intra search evaluates DC/V/H/TM modes with `model_rd_for_sb_y` + `block_yrd`, then adds `intra_cost_penalty + mbmode_cost + ref_frame_cost[INTRA_FRAME]`. If any intra mode beats the best inter RD, it replaces the result.

rvp9 has a separate `pick_intra_mode_luma` in `intra.rs` but it is NOT called from within the inter picker path. The encoder calls the intra picker independently for keyframes only. On inter frames, the intra fallback is absent -- blocks that would benefit from intra prediction (scene changes, uncovered regions, static backgrounds with local texture changes) are forced into inter modes.

~130 LOC. **HIGH impact on scene-change / uncovered-region content; moderate on steady motion content.** On foreman_cif specifically, the F.0.2 oracle measured rvp9 at 1.7% intra in inter frames vs libvpx's 1.6% — nearly identical, suggesting the intra fallback fires rarely on this clip. Impact is content-dependent: expect 1-2 dB on scene-change-heavy clips, 0.3-0.5 dB on steady-motion clips like foreman.

### `vp9_get_intra_cost_penalty`
**Status: NOT PORTED**

The intra cost penalty (rd.c:778-810) is a qindex-dependent rate penalty added to intra modes to bias toward inter. Without this, if intra-in-inter were enabled, it would over-select intra. ~30 LOC. **HIGH impact** (prerequisite for intra-in-inter).

### `inter_mode_thresh`
**Status: NOT PORTED**

`inter_mode_thresh = RDCOST(rdmult, rddiv, intra_cost_penalty, 0)` (pickmode.c:1709-1710) gates the intra search. Without this, there is no threshold to decide when to try intra modes.

## Porter's Checklist (Priority Order)

Priority is estimated by expected PSNR-delta improvement on real content (foreman_cif at matched bitrate). Items are ordered by ROI = expected_quality_gain / porting_effort.

### Tier 0 -- Highest ROI (expected 1-2 dB, minimal effort)

| Priority | Item | LOC | Why |
|---|---|---|---|
| **P0** | **`inter_mode_ctx` threading** | ~10 | Thread the `mode_context` value returned by `find_mv_refs` into `InterModeSearchParams::inter_mode_ctx` instead of hardcoding 0. Currently over-charges NEWMV by ~1 bit per block (context 0 charges ~2.9 bits for NEWMV vs ~1.9 bits at context 3). Direct contributor to Track G's "picker rejects NEWMV" finding. Cheapest single fix likely to move the needle. |

### Tier 1 -- High Impact, Moderate Effort (expected to close 2-4 dB)

| Priority | Item | LOC | Why |
|---|---|---|---|
| **P1** | **`model_rd_for_sb_y` + `vp9_model_rd_from_var_lapndz`** | ~130 | Enables TX-size selection, skip_txfm early-exit, and the early-term flag. Without this, every candidate pays full transform cost and the picker can't distinguish "prediction so good we should skip the residual entirely" from "prediction needs significant correction". Prerequisite: the Laplacian model LUT port. |
| **P2** | **`calculate_tx_size` (adaptive TX selection)** | ~30 | Directly depends on `model_rd_for_sb_y`. Currently rvp9 always picks max TX, wasting bits on textured content where smaller TXes would zero out more coefficients. |
| **P3** | **Intra-in-inter search** | ~160 | Blocks that should be intra (scene changes, uncovered regions) are forced to inter. Needs `vp9_get_intra_cost_penalty` + the intra-fallback body from pickmode.c:2517-2646. Content-dependent: 1-2 dB on scene-change clips, 0.3-0.5 dB on steady-motion (foreman). |
| **P4** | **`block_yrd` Hadamard + `vp9_quantize_fp`** | ~80 | Switch from DCT+quantize_b to Hadamard+quantize_fp matches libvpx's rate model calibration. The K1=4 SATD-to-bits scale was empirically tuned against rvp9's DCT-based coefficients; switching to Hadamard may require recalibrating K1 but will align the rate model with libvpx's. |

### Tier 2 -- Medium Impact, Low-Medium Effort (expected to close 1-2 dB)

| Priority | Item | LOC | Why |
|---|---|---|---|
| **P5** | **Frame context adaptation** | ~60 | Wire `vp9_adapt_{mode,mv,coef}_probs` into the encoder frame loop; flip `refresh_frame_context: true`. Fixes systematic cost-model drift across the sequence. The backward-adapt functions already exist in the core crate (decoder uses them). Orthogonal to picker restructuring — can land independently. |
| **P6** | **UV RD integration** (`model_rd_for_sb_uv`) | ~85 | Currently the picker is luma-only for RD. Adding UV rate+dist to the candidate comparison prevents the picker from choosing a mode that looks good in Y but destroys chroma. |
| **P7** | **`encode_breakout_test`** | ~100 | Lets well-predicted blocks skip the transform entirely. Frees bits for blocks that need them. Also a significant speed improvement. |
| **P8** | **Skip-flag tie-break activation** (lambda recalibration) | ~15 | The infrastructure exists but is disabled. Activating it requires recalibrating lambda so that the encode-vs-skip RD comparison is well-balanced. |
| **P9** | **`vp9_mv_pred`** | ~50 | Better full-pel search seeding. Currently the diamond always starts from `nearest` which is (0,0) at frame boundaries. `vp9_mv_pred` evaluates SAD at each MV-ref candidate and picks the lowest as the seed -- better seeds = better NEWMV results. |
| **P10** | **`model_rd_for_sb_y_large`** + early-term | ~200 | The large-block extended variant with 8x8-granularity skip detection and UV early-term. High LOC but high payoff for 32x32+ blocks. |
| **P11** | **Switchable-filter per-context rate** | ~20 | Replace the flat `F5_SWITCHABLE_FILTER_RATE = 2048` with `switchable_interp_costs[ctx][filter]`. The picker then correctly prices the filter switch and avoids the +0.6 dB regression from over-switching. |

### Tier 3 -- Lower Impact, Various Effort (expected to close 0.2-0.5 dB each)

| Priority | Item | LOC | Why |
|---|---|---|---|
| **P12** | `nonrd_pick_partition` real callback | ~50 | Currently uses a ZERO-MV SSE proxy. Replacing with the real picker enables motion-aware partition decisions. |
| **P13** | `vp9_NEWMV_diff_bias` | ~60 | Biases against NEWMV vectors that differ greatly from neighbors. Stabilizes output on noisy content. |
| **P14** | Adaptive `subpel_force_stop` | ~15 | Large MVs use half-pel only; small MVs get eighth-pel. Saves bits on large-motion blocks. |
| **P15** | `const_motion` NEARMV skip | ~5 | Skip NEARMV when all neighbors have the same MV. Saves compute, not quality. |
| **P16** | `source_variance` + flat-block gates | ~20 | Content-adaptive mode pruning for flat blocks. |
| **P17** | Duplicate-MV dedup | ~12 | Avoid re-evaluating when NEARMV == NEARESTMV. Saves compute. |
| **P18** | `ref_frame_skip_mask` / `reference_masking` | ~25 | Skip entire ref frames when SAD evidence says they are poor. |
| **P19** | Real skip-prob context | ~15 | Thread `vp9_get_pred_context_skip` through the skip-flag tie-break instead of using the flat default. |
| **P20** | `adaptive_rd_thresh` | ~40 | Frequency-based RD threshold adaptation. Mostly a speed feature. |
| **P21** | Pred-buffer reuse | ~30 | Performance optimization, no quality impact. |

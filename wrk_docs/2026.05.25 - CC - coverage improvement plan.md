# Coverage Improvement Plan — rvp9-2

**Date:** 2026-05-25
**Companion to:** `2026.05.25 - CC - coverage baseline report.md`
**Goal:** Branch coverage **69.41% → ≥ 98.00%** on the workspace (minus harness/bench/fuzz). Net: cover 1,329 more branches out of 1,422 currently missed.
**Workflow:** Each stage dispatches one or more agents in `isolation: "worktree"` mode so concurrent work doesn't conflict. After each stage we re-run `cargo +nightly llvm-cov --workspace --branch --summary-only --ignore-run-fail --exclude rvp9-harness --exclude rvp9-bench` and commit.

---

## Anti-gaming rules (apply to every stage)

These are **non-negotiable** invariants for every test added under this plan. The reviewing agent (or human) rejects PRs that break them.

1. **Every test asserts.** No `let _ = function(...);` "exercise" tests. The expected return value, side effect, or error variant must be checked.
2. **No tautologies.** Don't test a constant against itself, or assert `func(x) == func(x)`. Tests must encode a property that would fail if the implementation regressed.
3. **No coverage annotations.** No `#[cfg(coverage_off)]`, `#[coverage(off)]`, `#[cfg_attr(coverage, ...)]`, or `// cov:ignore` markers added unless the file is genuinely unreachable (we'll list any such cases in a separate doc, requires sign-off).
4. **No `cov_*` named tests.** Tests must describe the behaviour ("`set_threshold_clamps_below_min`"), not the file/region they happen to cover.
5. **Tests must use real types.** No mock structs that bypass the implementation; use the real `BoolReader`, real `FrameContext`, real `Mv` etc. (the `rust-best-practices` skill spells this out).
6. **One assertion per expected outcome.** Either a single decisive assertion or a small set per test; if a test asserts five unrelated things, split it.
7. **Property tests welcome.** `proptest` (already in `Cargo.lock`) is allowed and encouraged for arithmetic / encode-decode roundtrip oracles.

## Stage gate

After **every** stage, run:
```bash
rm -rf target/llvm-cov-target
cargo +nightly llvm-cov --workspace --branch --summary-only \
    --ignore-run-fail --exclude rvp9-harness --exclude rvp9-bench \
  > target/coverage/stage-<N>-summary.txt 2>&1
```

Then **commit** the new tests + summary file with a message referencing the stage and the branch coverage delta. Do not merge the next stage's work until the current stage's coverage has been measured.

If a stage misses its branch-coverage target by > 3 percentage points, **stop and re-plan**. The cost-per-branch estimates below are not load-bearing — they are best-guess starts.

## Stage 2 — CLI binaries (rvp9enc + rvp9dec)

**Target:** 95%+ branch coverage on both CLI binaries.

**Files:**
| File | Missed branches | Branches |
|:-----|---:|:---|
| `rvp9-cli\src\bin\rvp9dec.rs` | 29 | 54 |
| `rvp9-cli\src\bin\rvp9enc.rs` | 16 | 28 |

**Approach.** Both files are `parse args → set up codec → drive loop` shells with many `if flag { ... } else { ... }` switches. Most missed branches are:
* Unknown / unsupported flag rejection paths
* Conflicting flag combinations
* Output-format selection (`--y4m` vs `--i420` vs `--yv12` vs `--rawvideo`)
* `--limit`, `--skip`, `--summary`, `--progress` flow control
* Container demux failures (truncated IVF, bad WebM)

**Test fixtures:** the existing `cli_roundtrip.rs` tests already exercise the binary via `Command::new(bin)`. Extend with one test per missed-branch class. Use synthetic 64×64 raw fixtures (already used).

**Anti-gaming reminder.** Many CLI tests will assert on `out.status.success()` + a stderr substring. The substring must be one the test author would actually want to lock in — e.g. `"multiple of 64"` for the existing dimension-rejection test, not just `out.stderr.is_empty() == false`.

**Estimate:** ~45 missed branches → ~5 covered. Net + ~40 → workspace ≈ 71.5% branch.

**Dispatch:** one agent for both files (they share `cli_roundtrip.rs`), isolation worktree.

## Stage 3 — Container + Y4M I/O error paths

**Target:** 90%+ branch coverage on `rvp9-io`.

**Files:**
| File | Missed branches | Branches |
|:-----|---:|:---|
| `rvp9-io\src\container.rs` | 34 | 51 |
| `rvp9-io\src\y4m.rs` | 12 | 30 |

**Approach.** Truncated-input fixtures — for each `?` propagation in the container/Y4M parser, construct a buffer that succeeds up to byte `n` and fails at `n+1`. The IVF/WebM/Y4M wire formats have a small number of header fields; iterate `n` over the cumulative parse offsets.

**Test fixtures:** programmatic — build a valid IVF in-memory, then truncate it at each known offset. Same for Y4M (header end, frame header end, plane data end).

**Anti-gaming reminder.** Each truncated-input test must assert the specific `Err` *variant* — not just `result.is_err()`. The point is to lock in the error contract, not just exercise the bytes.

**Estimate:** ~46 missed branches → ~5 covered. Net + ~41 → workspace ≈ 72.4% branch.

**Dispatch:** one agent, isolation worktree.

## Stage 4 — Loop-filter `apply.rs` + `setup_mask.rs`

**Target:** 90%+ branch coverage on these two files.

**Files:**
| File | Missed branches | Branches |
|:-----|---:|:---|
| `rvp9-core\src\loopfilter\apply.rs` | 104 | 208 |
| `rvp9-core\src\loopfilter\setup_mask.rs` | 17 | 32 |

**Approach.** Many of the unhit branches are `if filter_level == 0 { continue }`-style fast-paths, and per-edge type (Y vs UV, horizontal vs vertical, 16-wide vs 8-wide vs 4-wide). The right test surface is a curated fixture set:
* 4×4 block, filter_level = 0 (skip)
* 4×4 block, filter_level > 0 (apply)
* 8×8 block at every filter_level breakpoint (0 / 1 / 16 / 63)
* 16×16 / 32×32 / 64×64 same sweep
* Both chroma subsampling modes (4:2:0 only is supported, but the dispatch arms still vary)
* Edge cases: top-row block (no top edge), left-column block (no left edge), bottom-right corner

The kernels are already well-tested at the DSP level (per-direction kernels in `dsp/x86_64/lpf_*_avx2.rs` are at 100%); the gap is the *driver* `apply` that decides which kernel to call.

**Anti-gaming reminder.** Don't test by encoding-then-decoding-and-checking-pixel-equality (existing conformance tests already do that). Construct the driver inputs (filter mask, plane buffer) directly and assert post-state. Cross-check by running the same fixture through `vpx_lpf_horizontal_4_c` and confirming bit-identity if possible.

**Estimate:** ~121 missed branches → ~20 covered. Net + ~101 → workspace ≈ 74.6% branch.

**Dispatch:** one agent, isolation worktree.

## Stage 5 — Inter mode-info reader/writer pair

**Target:** 90%+ branch coverage on the inter-mode-info path.

**Files:**
| File | Missed branches | Branches |
|:-----|---:|:---|
| `rvp9-core\src\inter\mode_info.rs` | 197 | 328 |
| `rvp9-core\src\bitstream\modes_writer.rs` | 73 | 272 |
| `rvp9-core\src\inter\mv_ref.rs` | 43 | 100 |

**Approach.** The encoder writes a packet, the decoder reads it; the right oracle is a **roundtrip property**: for every `(BlockSize, BlockMode, RefFrame, Mv, ...)` tuple the encoder emits, the decoder must read back the same tuple.

* Reference-mode selection (`SINGLE_REFERENCE` / `COMPOUND_REFERENCE` / `REFERENCE_MODE_SELECT`)
* Compound reference pair (5 fixed pairs in VP9)
* Single reference (3 candidates)
* `interp_filter` switchable case (3 filters)
* `inter_mode` (NEARESTMV / NEARMV / ZEROMV / NEWMV)
* Sub-8 blocks (4×4 / 4×8 / 8×4) — per-bmi mode + MV
* Segment-feature SEG_LVL_SKIP / SEG_LVL_REF_FRAME (currently out-of-scope per file header; check whether any branches there are reachable)

The MV-ref builder (`find_mv_refs`, `append_sub8x8_mvs_for_idx`) has its own combinatorial surface — `proptest` over neighbour configurations is appropriate here.

**Anti-gaming reminder.** "Set up the inputs, call the function, assert no panic" is not a test. Assert the *output mode-info* matches expected for the input bytes. The roundtrip oracle is the cheapest defensible test here.

**Estimate:** ~313 missed branches → ~50 covered. Net + ~263 → workspace ≈ 80.3% branch.

**Dispatch:** two agents (split: one on reader/writer, one on mv_ref builder), isolation worktree, sequential not parallel (they touch overlapping fixtures).

## Stage 6 — Decoder tile + lib

**Target:** 90%+ on these large state-machine files.

**Files:**
| File | Missed branches | Branches |
|:-----|---:|:---|
| `rvp9-decoder\src\tile.rs` | 143 | 298 |
| `rvp9-decoder\src\lib.rs` | 50 | 138 |
| `rvp9-decoder\src\reconstruct.rs` | 26 | 70 |
| `rvp9-decoder\src\reconstruct_inter.rs` | 37 | 128 |

**Approach.** The tile decoder + top-level decoder are best tested with **micro-bitstream fixtures**: a few-byte slice of a synthetic stream that exercises one specific arm. Drive `Decoder::decode_frame` or `tile::decode_tile_buffered` with the fixture, assert the resulting `Frame` state.

Branches concentrated in:
* Profile detection (Profile 0 / 1 / 2 / 3 selection)
* Show-frame vs invisible-frame
* Frame-parallel resync
* Tile-row vs single-tile path
* Threading: 0 / 1 / 2 / 4 / 8 threads
* Show-existing-frame path
* Error-concealment hook

Many of these arms are reachable via short crafted inputs — much cheaper than waiting for a conformance vector to happen to exercise them.

**Anti-gaming reminder.** Don't use `Decoder::decode_packet(b"")` and assert it errors. Assert the *specific* error variant (e.g. `DecodeError::TruncatedFrame { .. }`). The plan target is to lock in error contracts, not to bump line counts.

**Estimate:** ~256 missed branches → ~40 covered. Net + ~216 → workspace ≈ 84.9% branch.

**Dispatch:** one agent, isolation worktree, sequential.

## Stage 11 — DSP SIMD arm coverage + final sweep

**Target:** **Workspace branch coverage ≥ 98%.**

**Files:** All remaining files at 50–80% branch coverage that the previous stages haven't already moved. By this point we expect a long tail of:
* AVX2 fast-path vs scalar-fallback arm-pairs in `dsp/x86_64/*.rs` (currently many at 50% because only the AVX2 path is exercised on this machine — the scalar fallback's `cfg(not(target_feature = "avx2"))` arm doesn't fire under coverage instrumentation).
* `RuntimeCaps`-gated dispatch — both `RuntimeCaps::scalar()` and `RuntimeCaps::avx2()` arms need exercising via a sibling test.
* `proptest`-style sweeps to catch the last few stragglers in arithmetic kernels.

**Approach.** For every AVX2 file at 50% branch coverage (e.g. `d135_predictor_avx2`, `dc_pred_4x4_avx2`), add a test that explicitly invokes the dispatcher with `RuntimeCaps::scalar()` and asserts the scalar path produces bit-identical output to the AVX2 path. This both lifts coverage *and* adds a real correctness oracle.

**Anti-gaming reminder.** This is the last stage; if any file refuses to climb to 98%, document the specific unreachable arms in `notes/coverage-exclusions.md` with a one-line justification each. Acceptable exclusions:
* `unreachable!()` arms guarding internal invariants
* `cfg(target_arch = ...)` not matching the test platform
* Panic-on-`Drop` paths that can only fire via thread-panic (testable, but expensive)

**Stop condition:** workspace branch coverage ≥ 98.00%. Per-file branch coverage need not be ≥ 98%; aggregate is what matters.

**Estimate:** Last ~250 branches → workspace 98%+.

**Dispatch:** one or two agents, isolation worktree.

## Risk register

| Risk | Mitigation |
|:-----|:-----------|
| Coverage tooling instability on Windows (`cargo-llvm-cov` clean races) | Always `rm -rf target/llvm-cov-target` before each run; run sequentially, not in parallel with other builds. |
| Adding flaky tests under coverage instrumentation (10–50× slowdown) | Each new test should also pass under `cargo test` (no instrumentation). |
| Tests that depend on file-system fixtures racing | Use `tempfile` crate (already a dep); never share fixture filenames. |
| Agent introduces `#[cfg(coverage_off)]` "to hit target" | Lead-agent reviewer scans diff for the substring before accepting any stage commit. |
| Reaching 98% requires unreachable arms be excluded | Maintain a `notes/coverage-exclusions.md` ledger; each entry needs justification. |
| Encoder mode-decision tests entangled with libvpx parity goals | Constructed-input tests should NOT depend on libvpx oracle (that's the conformance suite's job); they should test the *Rust* implementation's contract. |

# Stage 4b cyclic-refresh AQ HLD

Status: DRAFT V2

## Quality brief

- Simplicity and cleanliness matter. Do not overengineer; solve the problem at hand. If you can't hold the design in your head, it's wrong.
- Development sandbox: no migration or rollback support, no backwards compatibility with old code, no ops choreography.
- Minimize environment variables; avoid feature flags.
- Design for testability: the HLD must specify how correctness will be verified (acceptance criteria / test oracles).

## Executive summary

Stage 4b completes the existing cyclic-refresh AQ mode 3 path. It does not create a new AQ framework.

The live code already has `AqMode::Off | CyclicRefresh`, optional CR state, spatial segmentation, segment-1 ALT_Q, per-leaf effective q, keyframe reset, and post-encode age/q feedback. The remaining work is the load-bearing part of mode 3: dynamic BOOST1/BOOST2 deltas, production per-block cyclic-refresh update, CR-owned VBR/golden interactions, narrow CR-aware RC estimates, and hard AQ-on gates.

The main correctness invariant is transactional: a leaf may be trial-encoded more than once, but side effects are committed exactly once, after the final segment and final effective q are known. No stale coefficients, recon pixels, skip state, RD-threshold learning, MI-grid data, MV-grid data, or AQ feedback may survive a segment change.

Stage 4b design and bounded implementation can proceed in parallel with Stage 4a. Stage 4b acceptance is blocked until Stage 4a AQ-off quality, cross-decoder, and realtime gates are green.

## Scope

In scope:

- VP9 cyclic-refresh AQ mode 3 only.
- `AqMode::Off` remains default and preserves Stage 4a behavior.
- `AqMode::CyclicRefresh` for one product operating point: realtime VP9, speed / `cpu-used=7`, `lag=0`, one-pass VBR, single layer, 8-bit Profile 0, no altref, no denoiser, TPL off, and libvpx compared with `--aq-mode=0|3`.
- Dynamic segment ALT_Q deltas for BOOST1 and BOOST2.
- Production per-block cyclic-refresh segment update before final quant/recon commit.
- CR-owned VBR/golden interactions that libvpx cyclic refresh depends on: `vp9_cyclic_refresh_set_golden_update`, VBR-golden CR parameter behavior, and postencode golden demotion.
- Narrow RC integration required by the LLD: CR weighted `bits_per_mb` inside q regulation and CR weighted `estimate_bits_at_q` inside rate-correction-factor update.
- Hard acceptance gates for AQ quality, AQ-on VBR external decode, AQ-on VBR realtime, and non-vacuous AQ activation.

Out of scope:

- AQ modes 1, 2, or 4.
- SVC, resize, ROI/active-map, screen-content special cases, denoiser interactions, altref interaction, TPL interaction, two-pass AQ tuning, Profile 1, or high bit depth.
- New environment variables, feature flags, or product knobs.
- A new RC mode, broad RC rewrite, target/buffer rewrite, or general GOP rewrite beyond the CR-owned golden hooks above.
- Byte-identical libvpx output as a release gate. BD-rate gain parity, CR-state oracles, and decoder-valid streams are the gates.

## Current state

The implementation is partially live:

- `frame_loop.rs` exposes `AqMode::Off | CyclicRefresh`; default config and CLI default keep AQ off.
- `StreamEncoder` allocates `CyclicRefresh` only for `AqMode::CyclicRefresh`.
- Inter frames can build a segmentation map and emit segment ALT_Q data.
- `lib.rs` already computes effective per-leaf q from segment deltas.
- Keyframes reset CR state and do not emit AQ segmentation.
- Post-encode feedback updates CR age and `last_coded_q_map` from actual coded segment and skip data.

The missing pieces are:

- BOOST2 is not live; current production deltas only use segment 1.
- The dynamic q-delta ramp exists but is not wired as the production policy.
- The production path does not use the full per-block rate/distortion/MV/skip cyclic-refresh update before committing leaf coefficients and recon.
- RC remains cyclic-refresh blind.
- CR-owned VBR/golden behavior is not clearly wired.
- The existing Stage 4b quality harness prints the 0.3% AQ-gain result but does not assert it.
- AQ-on VBR cross-decoder and AQ-on VBR realtime gates are missing.

## Design

### Ownership boundary

Rate control owns base q, RC mode, target bitrate, buffer model, and correction-factor state. AQ owns cyclic-refresh state, segment ALT_Q deltas, segment selection, CR-specific golden decisions, and weighted estimates that RC asks for when AQ mode 3 is active.

`AqFramePlan` is a frame-local snapshot. It must not become a second owner of RC decisions or a generic future AQ framework.

### Public configuration boundary

For Stage 4b, `AqMode::CyclicRefresh` is only supported for the scoped product profile.

Construction or CLI parsing must reject unsupported combinations rather than silently running untested behavior:

- `aq_mode == CyclicRefresh && enable_tpl`
- `aq_mode == CyclicRefresh && temporal_layers > 1`
- `aq_mode == CyclicRefresh && enable_alt_ref`
- `aq_mode == CyclicRefresh && denoiser enabled`
- `aq_mode == CyclicRefresh && profile != 0`
- any reachable resize, SVC, high-bit-depth, or screen-content-only CR mode under `AqMode::CyclicRefresh`

If one of these fields is not currently exposed in public config, no new knob is needed. The requirement is to reject only combinations that can actually be constructed.

### Frame ordering

Use a two-step cyclic-refresh setup around base-q selection:

1. Before base-q selection, update q-independent CR frame parameters from previous-frame state: active/gated status, refresh percentage, rate ratio, segment weighting, CR golden-update decision, and any gating reason needed for tests.
2. RC picks base q. If AQ is active, the candidate-q loop must call a CR weighted `bits_per_mb(candidate_q)` calculation that computes candidate BOOST1/BOOST2 deltas for that candidate q. It must not reuse stale deltas from the previous frame or from a later chosen base q.
3. After base q is chosen, finalize the frame-local AQ plan: BOOST1/BOOST2 q deltas for the chosen base q, thresholds, and the initial cyclic-refresh map.
4. Inter mode/partition selection sees the initial segment ID for each leaf.
5. Leaf encoding is transactional:
   - A trial encode produces a side-effect-free `LeafTrialResult` containing rate, distortion, MV/ref, skip/eob, chosen mode/tx data, candidate coefficients/recon, and any data needed to commit that exact result later.
   - The trial path may read source/reference state, but it must not mutate committed recon, coefficient storage, MI-grid, MV-grid, frame counts, RD-threshold learning, AQ state, or postencode counters.
   - The AQ per-block segment update consumes the trial result and returns a final segment.
   - If the final segment differs from the trial segment, rerun the trial at the final segment's effective q.
   - Recompute the AQ segment decision from the second trial. If it is stable, commit that second trial. If it changes again, choose the least-boosted segment among the two decisions, run one final trial at that segment, and commit it without another segment promotion. This bounded fallback prevents an AQ/skip fixed-point loop while preserving validity.
   - RD-threshold learning and any other adaptive counters are updated only from the committed final trial.
6. Emit spatial segmentation with ALT_Q deltas for segment 1 and segment 2 when AQ is active. Keyframes and gated-off inter frames emit segmentation disabled.
7. Post-encode feedback updates age, `last_coded_q_map`, and actual BOOST1/BOOST2 counts from the final committed segment IDs and skip/eob flags. BOOST1 and BOOST2 both count as refreshed segments, and each writes the final effective q for its own segment.
8. Rate-correction-factor update uses the CR weighted `estimate_bits_at_q` when AQ was active. Actual emitted bits remain the feedback truth.

### Segment model

Segment 0 is base q. Segment 1 is BOOST1. Segment 2 is BOOST2.

The dynamic q-delta ramp must mirror the existing libvpx-shaped helpers:

- `compute_deltaq(qindex, rate_ratio_qdelta, max_qdelta_perc, Inter, best_quality, worst_quality)` for BOOST1.
- `compute_deltaq(qindex, min(CR_MAX_RATE_TARGET_RATIO, 0.1 * rate_boost_fac * rate_ratio_qdelta), max_qdelta_perc, Inter, best_quality, worst_quality)` for BOOST2.
- segment 0 delta is zero / no ALT_Q.
- BOOST1 and BOOST2 deltas are non-positive.
- under product defaults, `BOOST2 <= BOOST1 <= 0`.
- deltas clamp to the legal qindex range.

Tests must pin concrete expected deltas for representative base q values such as 32, 80, and 160. Monotonicity alone is not enough.

### CR state and golden behavior

Stage 4b includes the CR-owned VBR/golden hooks because the scoped product gate is VBR:

- CR golden interval selection equivalent to `vp9_cyclic_refresh_set_golden_update`.
- VBR-golden parameter behavior in CR setup, including the frame cases where refresh percentage or rate-ratio behavior changes because the current frame is a golden refresh.
- Postencode low-content / golden demotion behavior owned by cyclic refresh.

This is not permission for a broad GOP rewrite. The implementation should touch the existing RC/GOP fields only through the CR-specific decisions above.

### Threading and aliasing

The current product encode path may be effectively single-threaded for this work. If Stage 4b moves CR map writes into a parallel leaf/tile path, it must use tile- or row-disjoint mutable slices for `cr.map`, `last_coded_q_map`, and `segmentation_map`. Do not introduce shared mutable CR state behind `UnsafeCell` or locks for this stage.

## Acceptance criteria

These gates are the build run's definition of done.

### Preconditions

Stage 4a AQ-off product gates must be green and non-skipped:

```powershell
$null | mdtimeout 1800 cargo test -p rvp9-encoder --release --test quality_gate quality_gate_stage4a_realcontent -- --ignored --nocapture
$null | mdtimeout 600 cargo test -p rvp9-encoder --release --test cross_decoder_gate cross_decoder_gate_vpxdec_ffmpeg -- --ignored --nocapture
$null | mdtimeout 600 cargo test -p rvp9-encoder --release --test realtime_gate realtime_gate_720p30 -- --ignored --nocapture
```

Missing corpus/reference binaries are allowed to skip ordinary diagnostic runs, but Stage 4b sign-off tests must fail rather than skip when required evidence is absent.

### Focused AQ correctness

```powershell
$null | mdtimeout 180 cargo test -p rvp9-encoder --lib aq_cyclic_refresh -- --nocapture
$null | mdtimeout 300 cargo test -p rvp9-encoder --test aq_cyclic_refresh_frame_loop aq_segment_flip_commits_only_final_trial -- --nocapture
```

Required oracles:

- AQ-off keeps segmentation disabled and effective q equal to base q.
- Keyframes keep segmentation disabled.
- Dynamic q deltas match pinned formula outputs for representative q values and remain monotone under product defaults.
- Segment 2 is emitted through `segment_q_deltas` and the segmentation header.
- AQ-on positive controls observe non-zero refreshed cells and at least one committed BOOST1 and BOOST2 segment.
- High-motion/high-distortion blocks demote to base.
- A low-rate, zero-MV, eligible block promotes to BOOST2.
- A forced segment-flip case commits coefficients, recon, skip state, MI-grid, MV-grid, counters, and RD-threshold learning from the final trial only.
- Post-encode feedback updates age, `last_coded_q_map`, and actual BOOST1/BOOST2 counts from final committed data.

### CR state oracle

Add one focused CR-state oracle against pinned libvpx behavior:

```powershell
$null | mdtimeout 600 cargo test -p rvp9-encoder --release --test quality_gate aq_cyclic_refresh_state_oracle_foreman_vbr -- --ignored --nocapture
```

The oracle may use a small generated fixture from the pinned libvpx revision rather than compiling an instrumented libvpx during every run. It must compare, for a short fixed Foreman VBR run:

- `apply_cyclic_refresh`
- `percent_refresh`
- `rate_ratio_qdelta`
- BOOST1/BOOST2 q deltas
- `weight_segment`
- CR cursor / refreshed counts
- actual BOOST1/BOOST2 counts
- segmentation-map segment counts

This oracle does not need byte-identical full bitstreams. It exists to prevent a false green where the aggregate BD-rate gain happens to pass while CR state is wrong.

### AQ quality gate

```powershell
$null | mdtimeout 1800 cargo test -p rvp9-encoder --release --test quality_gate bdrate_gate_stage4b_aq_realcontent -- --ignored --nocapture
```

Required oracles:

- Foreman real-content input is present.
- libvpx `vpxenc` and `vpxdec` are present.
- All four curves are finite: rvp9 AQ off, rvp9 AQ on, libvpx AQ off, libvpx AQ on.
- Curves have valid PSNR overlap and no gate-breaking monotonicity failure.
- AQ activates on the measured rvp9 AQ-on curve: segmentation emitted on inter frames, non-zero BOOST1 and BOOST2 counts over the measured frames, and AQ-on/off streams differ.
- `abs(gain_rvp9 - gain_libvpx) <= 0.3%`.

The existing 2.0% line may remain informational. It is not an acceptance threshold.

### AQ-on VBR interoperability and realtime

```powershell
$null | mdtimeout 600 cargo test -p rvp9-encoder --release --test cross_decoder_gate cross_decoder_gate_aq_cyclic_refresh_vbr_vpxdec_ffmpeg -- --ignored --nocapture
$null | mdtimeout 900 cargo test -p rvp9-encoder --release --test realtime_gate realtime_gate_720p30_aq_cyclic_refresh_vbr -- --ignored --nocapture
```

Required oracles:

- These tests construct the same VBR product profile as the Stage 4b quality gate. They are not AQ-on variants of the older CBR gate.
- rvp9 AQ-on output decodes through rvp9-decoder and libvpx `vpxdec`.
- The tested stream emits segmentation, BOOST1, BOOST2, and ALT_Q data.
- ffmpeg follows the existing cross-decoder gate contract.
- No available external decoder may fail.
- Missing external decoders fail the sign-off gate.
- AQ-on 720p30 median frame time is `<= 33 ms` in release mode and no single frame exceeds `66 ms`.

### Standard local gates

```powershell
$null | mdtimeout 120 cargo fmt --all --check
$null | mdtimeout 300 cargo clippy --workspace --all-targets
$null | mdtimeout 600 cargo test --workspace
```

The fresh worktree may lack ignored corpus data. If workspace tests fail only because ignored test data is absent, rerun from a data-populated checkout or fetch the data before treating it as a code failure.

## Parallelization guidance

Stage 4b design can proceed while another team finishes Stage 4a.

Stage 4b implementation can begin in parallel if the teams hold these boundaries:

- Stage 4a owns the AQ-off baseline, core quality gap, and baseline gates.
- Stage 4b owns AQ mode 3 behavior and AQ-on VBR gates.
- RC owns base q. AQ may add only the CR weighted estimate hooks and CR-owned golden decisions.
- Any Stage 4a change to picker RD, partitioning, skip decisions, motion search, or RC can move AQ feedback. Stage 4b must rebase and rerun the product gates after Stage 4a lands.

Do not accept Stage 4b from a branch whose AQ-off Stage 4a gates are not green.

## Residual risks

- The 0.3% AQ-gain delta is tight and can be masked by unrelated Stage 4a quality movement.
- The transactional trial/commit refactor may expose broader inter-path coupling. If it grows beyond leaf-local commit control, pause for a smaller implementation design before coding further.
- The bounded fixed-point fallback is deliberately simple. It may cost a small amount of compression efficiency on rare unstable leaves, but it protects correctness.
- The AQ-on realtime budget has limited margin. If it fails, optimize the new AQ work first; do not hide it behind a flag.
- Screen-content `limit_q`, SVC, denoiser, altref, resize, and TPL/AQ interactions remain excluded. A failure clearly attributable to one of them needs a new scoped design.
- Cross-decoder and CR-state evidence depends on local reference binaries and corpus availability.

## Decision log

- Draft selection: three independent HLD drafts were produced. All three judges selected Draft B, the risk-first design, as the spine.
- Runner-up grafts: V1 kept Draft A's narrow implementation scope and Draft C's oracle-first acceptance structure.
- Round 1 critical verification: the segment re-simulation boundary and hidden golden-cadence dependency were confirmed by 2-of-3 skeptic votes. V2 adds a transactional trial/commit boundary and moves CR-owned VBR/golden hooks into scope.
- Round 1 non-critical clarification: the VBR-vs-CBR product gate mismatch was not verified as Critical, but V2 makes AQ-on cross-decoder and realtime gates explicitly VBR product-profile gates.
- Tie-break: narrow AQ-aware RC integration is included because PLAN Stage 4b says "Integrate with rate control" and `notes/lld/rate-control.md` assigns the two CR estimate hooks to Stage 4b. Broader RC behavior remains out of scope.
- Correctness invariant: final committed coefficients, recon, skip state, MI-grid, MV-grid, counters, and RD-threshold learning must all come from one final trial at the final segment.
- Stage 4a dependency: Stage 4b work may proceed in parallel, but acceptance is blocked until Stage 4a gates are green.
- TPL: product profile keeps TPL off. Constructible TPL+CR combinations must be rejected until a separate design covers them.
- Evidence: reporter-only output and skipped external prerequisites are not signed-off Stage 4b evidence.

# A3 Rate-Control Gap Inventory

**Date:** 2026-05-26
**Audit zone:** A3 — Rate control (CBR + VBR + 2-pass + lag-in-frames + external RC + cyclic-refresh interactions + scene detection)
**Scope (libvpx):** `third_party/libvpx/vp9/encoder/vp9_ratectrl.c` (3351 lines), `vp9_firstpass.c` (3906 lines), `vp9_ext_ratectrl.c` (281 lines), plus the cyclic-refresh RC entry points in `vp9_aq_cyclicrefresh.c`.
**Scope (rvp9):** `crates/rvp9-encoder/src/rate_control/{mod,config,state,cbr,postencode}.rs` (~2900 LOC), encoder hot-path call sites in `crates/rvp9-encoder/src/frame_loop.rs` and `lib.rs`.
**Method:** Function-by-function comparison of every public + private function in the three libvpx C files against the rvp9 implementation. Where rvp9 lacks the function, grepped `crates/` for the function name AND a body token (e.g. `vbr_bits_off_target`, `kf_zeromotion_pct`, `frames_till_gf_update_due`, `pcnt_inter`) to confirm genuine absence. The picker-inventory density baseline is 45 rows / 2820 LOC ≈ 1.6 rows / 100 LOC; this zone covers ~7.5 kLOC of libvpx source, so the expected row count is ~120. The table delivers 95 rows; the deviation is because large blocks of libvpx (the entire 2-pass GF-group structure, the entire firstpass encoder, the scene-detection lag block) are wholly absent in rvp9 and collapse into a small number of "whole-module NOT PORTED" rows rather than dozens of per-function entries.

## 0. Cross-Cutting Gaps

These items aren't a single function but distort the entire subsystem.

### 0.1 No rc_mode dispatch — CBR is the only path

**Status: NOT PORTED**

libvpx's `vp9_rc_pick_q_and_bounds` (`vp9_ratectrl.c:1587-1609`) dispatches by `(oxcf.pass, oxcf.rc_mode)` into one of four pickers: 1-pass CBR (`rc_pick_q_and_bounds_one_pass_cbr`), 1-pass VBR/CQ/Q (`rc_pick_q_and_bounds_one_pass_vbr`), 2-pass (`rc_pick_q_and_bounds_two_pass`), or 2-pass constant-Q (`rc_constant_q`). rvp9's `RateControl::pick_q_and_bounds` (`rate_control/state.rs:272`) calls `cbr::pick_q_and_bounds` (`rate_control/cbr.rs:528-610`) unconditionally — there is no `pass` field, no `rc_mode` enum, no VBR/CQ/Q branches. The encoder's `EncoderConfig` exposes only `target_bitrate_bps`, not a rate-control mode (`frame_loop.rs:124-163`).

This is the single largest gap in the zone: every libvpx mode except 1-pass CBR returns essentially no implemented code from any rvp9 file.

### 0.2 No recode loop / no frame dropping / no dynamic resize

**Status: NOT PORTED**

libvpx's encoder hot path runs **three rate-control hooks per frame**: (1) preencode pick (`vp9_rc_pick_q_and_bounds`), (2) optional recode loop with `vp9_encodedframe_overshoot` triggering re-encode at max-Q, and (3) post-encode `post_encode_drop_cbr` that drops a frame if the buffer would go negative. rvp9 has only hook (1) and a fixed-Q-per-frame post-encode update; the recode and drop hooks are not wired anywhere. The `RateControl::drop_count` field (`rate_control/state.rs:136-137`) is carried for "ABI shape" but never written, and `frame_loop::encode_frame` always emits exactly one packet per input — there is no path through the encoder that returns "frame dropped".

`vp9_resize_one_pass_cbr` (`vp9_ratectrl.c:2741`) — 141 lines that resize the output mid-stream when the buffer underflows — is also entirely absent. `RESIZE_DYNAMIC` is a libvpx CBR-RT feature.

### 0.3 No GF/ARF/Overlay frame types

**Status: NOT PORTED**

libvpx treats every frame as one of `{KF_UPDATE, LF_UPDATE, GF_UPDATE, ARF_UPDATE, OVERLAY_UPDATE, MID_OVERLAY_UPDATE, USE_BUF_FRAME}` (see `vp9_configure_buffer_updates`, `vp9_ratectrl.c:1611-1667`). The rate-factor-level enum has five slots (`INTER_NORMAL`, `INTER_HIGH`, `GF_ARF_LOW`, `GF_ARF_STD`, `KF_STD`); the per-level correction-factor table is indexed by these.

rvp9's `FrameKind` is `Key | Inter` only (`rate_control/mod.rs:121-127`). The `RateFactorLevel` enum carries the libvpx-shape (`cbr.rs:43-58`) but `RateFactorLevel::for_frame` only ever returns `KfStd` or `InterNormal` (`cbr.rs:71-78`); the three GF/ARF slots are `#[allow(dead_code)]`. The encoder unconditionally writes `refresh_alt_ref_frame: false` and emits no ARF/overlay frames.

This blocks: golden-frame Q boosting, ARF construction, all VBR boost logic, multi-layer ARF, source-alt-ref-pending tracking.

### 0.4 No HBD (high-bit-depth) Q tables

**Status: NOT PORTED**

`vp9_rc_init_minq_luts` initialises six tables × three bit-depths (8/10/12) totalling ~4600 LUT entries (`vp9_ratectrl.c:142-154`). `vp9_convert_qindex_to_q` (`vp9_ratectrl.c:159-172`) dispatches by `bit_depth` and divides by 4 / 16 / 64. rvp9's `qindex_to_q` (`cbr.rs:83-87`) is hard-coded `BitDepth::Eight`, and there is only one set of motion-minq tables (KF only; the ARFGF, inter, RTC tables don't exist because the consumers don't exist). Grep `BitDepth::Ten\|BitDepth::Twelve` across `crates/rvp9-encoder/` returns no rate-control matches.

This is in-scope per the GOAL doc (HBD is IN-SCOPE; Profiles 0/1/2/3 are all targets) but unported.

### 0.5 No lookahead pipeline

**Status: NOT PORTED**

libvpx's RC reads `cpi->lookahead` in multiple places: `vp9_scene_detection_onepass` reads up to `lag_in_frames` future frames, `adjust_gf_boost_lag_one_pass_vbr` walks `rc->avg_source_sad[]` per future frame, `vp9_get_frames_to_next_key` walks first-pass stats forward. The encoder's `frame_loop::encode_frame` is a strict 1-frame-in, 1-frame-out function — there is no buffering of source frames, no `lag_in_frames` config knob, no `lookahead_depth` API. (Audit zone A19 — Lookahead — is independently classified "absent" in the GOAL doc.)

This means: `lag_in_frames > 0` (a CLI flag of vpxenc) is unsupported, and every RC feature that conditions on `oxcf.lag_in_frames > 0` is unreachable.

### 0.6 No rolling/long-rolling target+actual bit tracking

**Status: NOT PORTED**

libvpx tracks four EWMAs (`vp9_ratectrl.c:1923-1931`): `rolling_target_bits`, `rolling_actual_bits` (window ≈ 4 frames via `(prev*3+new)>>2`), and `long_rolling_target_bits`, `long_rolling_actual_bits` (window ≈ 32 frames via `(prev*31+new)>>5`). These feed VBR `adjust_gf_boost_lag_one_pass_vbr`, 2-pass `vp9_twopass_postencode_update`, and the GF-update heuristics. rvp9 records only `total_actual_bits` and `total_target_bits` (`state.rs:128-132`); the rolling fields are absent.

### 0.7 No `last_boosted_qindex` / `this_key_frame_forced` / forced-KF Q matching

**Status: NOT PORTED**

`rc_pick_q_and_bounds_one_pass_cbr:1018-1023` special-cases forced keyframes: if `rc->this_key_frame_forced`, the KF Q is locked to `last_boosted_qindex` + 0.75-Q delta to prevent quality popping at forced-KF boundaries. rvp9 has no concept of forced KF (its GOP-length is driven by the encoder's own `frame_idx % gop_length` rather than the rate controller's `frames_to_key`, see `frame_loop.rs:571-576`) and no `last_boosted_qindex` field.

### 0.8 Postencode total_target_bits is unconditional

**Status: PARTIAL (DIVERGENCE)**

libvpx (`vp9_ratectrl.c:1936`): `rc->total_target_bits += cm->show_frame ? rc->avg_frame_bandwidth : 0;` — only show frames accumulate target bits. rvp9 always accumulates (`postencode.rs:180-183`, comment cites "no show-frame distinction at this layer"). With the rvp9 wire-format always emitting show=true, this is currently safe but breaks the moment ARF/overlay (`show=false`) frames are added.

### 0.9 No `sb64_target_rate` plumbing

**Status: NOT PORTED**

libvpx (`vp9_ratectrl.c:1735-1736`) computes `sb64_target_rate = this_frame_target * (64*64) / (width*height)` and uses it downstream in the recode loop and AQ-CR per-SB bit budgeting. rvp9's `this_frame_target` is the only target value exposed; there is no per-SB target.

### 0.10 RD-mult / lambda override (libvpx `vp9_extrc_get_frame_rdmult` + `cpi->rd_mult`)

**Status: NOT PORTED**

The rate controller and the picker share a lambda through `cpi->rd.RDMULT`, which the external-RC plugin can override per-frame. rvp9's `cost::rd_mult` is configured directly from qindex (no RC override path).

## Cross-Zone Dependencies Flagged

- **A4 (Partition logic)**: `first_pass_motion_search` (P20) reuses the same `vp9_diamond_search_sad` infrastructure as the partition picker.
- **A8 (Quantizer setup)**: HBD `vp9_convert_qindex_to_q` (P28) needs HBD `ac_quant`, currently 8-bit only.
- **A10 (Reference-frame management)**: GF/ARF refresh flags (P1) are written into the bitstream by A10; the RC tells A10 which slots to refresh, A10 emits the wire-format flags.
- **A11 (Segmentation / AQ)**: AQ-CR ↔ RC plumbing (P27) — every CR call from RC is in this zone but lives in the AQ-CR module.
- **A12 (CLI / config defaults)**: vpxenc `--end-usage`, `--pass`, `--fpf`, `--lag-in-frames`, `--cq-level`, `--gf-cbr-boost`, `--undershoot-pct`, `--overshoot-pct`, `--drop-frame`, `--resize-allowed`, all `--rc-min/max-*-bitrate-pct` flags map to RC fields not exposed by `EncoderConfig`.
- **A16 (ALTREF / temporal filtering)**: ARF construction (`update_alt_ref_frame_stats`, ARF Q-bounds, ARF source frames) is the post-encode half of A16; the RC pre-encode half is the GF/ARF picker in this zone.
- **A18 (SVC paths)**: every `cpi->use_svc` branch in `vp9_ratectrl.c` is in scope of A18 but the buffer-level fanout (`update_layer_buffer_level_postencode`, `update_buffer_level_svc_preencode`) and the layer-aware `vp9_rc_get_svc_params` need the SVC layer_context plumbing.
- **A19 (Lookahead pipeline)**: scene detection (P9) and `adjust_gf_boost_lag_one_pass_vbr` (P10) require lookahead; they're useless without it.
- **A20 (High-bit-depth)**: HBD Q tables (P28) sit on top of A20's HBD plumbing.
- **A22-related (TPL, vizier params)**: `vp9_estimate_qp_gop` (P26), `vp9_init_vizier_params`, `vbr_corpus_complexity` are independent of TPL but co-dependent on the first-pass infrastructure.

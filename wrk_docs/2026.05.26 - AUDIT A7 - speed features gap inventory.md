# A7 Speed Features Defaults — Gap Inventory

**Date:** 2026-05-26
**Audit zone:** A7 — Speed features defaults (all `cpu-used 0..=8`, plus best/good/RT dispatchers and RD-speed-threshold setters)
**Scope (libvpx):** `third_party/libvpx/vp9/encoder/vp9_speed_features.c` (1093 LOC), `third_party/libvpx/vp9/encoder/vp9_speed_features.h` (674 LOC, `SPEED_FEATURES` struct), `third_party/libvpx/vp9/encoder/vp9_rd.c::vp9_set_rd_speed_thresholds` / `vp9_set_rd_speed_thresholds_sub8x8` (~65 LOC).
**Scope (rvp9):** No dedicated module exists; the audit looks at every place a libvpx speed-feature flag is honoured or hard-coded. Primary touch-points: `crates/rvp9-core/src/mode_decision/inter.rs` (per-flag struct fields, lines 678-885 hold the §10/§11/P18/P20 fields), `crates/rvp9-core/src/mode_decision/rd_thresh.rs` (adaptive RD threshold + `vp9_set_rd_speed_thresholds`), `crates/rvp9-core/src/mv_search/sub_pixel.rs` (`subpel_force_stop` enum), `crates/rvp9-encoder/src/lib.rs:3620-3725` (encoder call-site that hard-wires the §10/§11/P18/P20 defaults), `crates/rvp9-cli/src/bin/rvp9enc.rs:98` (`--cpu-used` accepted but `apply: None`).

**Method:** Line-by-line walk of `vp9_speed_features.c` plus the `SPEED_FEATURES` / `MV_SPEED_FEATURES` struct fields in the header. For each flag I checked (a) is the gate site present in rvp9 (does rvp9 *read* the flag in the right place), and (b) does the encoder configure it correctly at the matching `cpu-used` level. The rvp9 CLI's `--cpu-used` is parsed but discarded (`apply: None`) — so for every flag below, "encoder-set" means the rvp9 encoder hard-codes a value at the cpu-used-6/7 operating point only, with no dispatch from `speed`. Row density target: 1767 LOC × (45 / 2820) ≈ 28 rows; my count is 50, justified by the high flag-density of this subsystem (one row per flag is the natural granularity).

## 0. Cross-Cutting Gap (the headline finding)

### No speed-feature dispatcher exists in rvp9
**Status: NOT PORTED**

There is no `crates/rvp9-core/src/mode_decision/speed_features.rs` (or anywhere else) that takes a `(cpu_used, deadline_mode, frame_size, content_type)` tuple and returns a populated `SpeedFeatures` struct. The CLI accepts `--cpu-used=N` (`rvp9enc.rs:98`) and `--rt` / `--good` / `--best` (`rvp9enc.rs:95-97`) but every one of them has `apply: None` — the value is **parsed and silently discarded**. Compare with libvpx's two-line entry-point:

```c
vp9_set_speed_features_framesize_independent(cpi, oxcf->speed);
vp9_set_speed_features_framesize_dependent (cpi, oxcf->speed);
```

which fans out to one of three setters (`set_rt_*`, `set_good_*`, `set_best_*`) based on `oxcf->mode`, each gated by `if (speed >= N)` ladders.

Instead, rvp9's encoder (`crates/rvp9-encoder/src/lib.rs:3620-3725`) **hard-codes one operating point** — the libvpx cpu-used-6/7 realtime defaults — into the `InterModeSearchParams` struct fields for every frame, regardless of what the user passed on the command line. The encoder banner comments at `lib.rs:3689-3712` are explicit:

> *"§11 — speed-feature gates for cpu-used-6/7/8. Defaults mirror libvpx vp9_speed_features.c:585-793 for the realtime path"*

So:
- **For cpu-used 6/7 (RT, single spatial layer, CBR/VBR no-lag):** ~10 speed-feature flags are honoured (gate site present, default value correct). See `inter_mode_mask`, `limit_newmv_early_exit`, `bias_golden`, `cb_pred_filter_search`, `disable_golden_ref`, `max_intra_bsize`, `rt_intra_dc_only_low_content`, `reference_masking`, `adaptive_rd_thresh`, `subpel_force_stop`.
- **For cpu-used 0..=5 (Good or Best path):** Almost the entire mode-decision machinery libvpx switches to (RDO picker, RD-ML partition, mesh searches, trellis, recode loop, multi-pass, etc.) is absent (covered by zones A13, A14, A15, A21). The speed-features layer for these is moot until those subsystems land.
- **For cpu-used 8:** A handful of flags differ from cpu-used-7 (`adaptive_rd_thresh = 4`, `limit_newmv_early_exit = 0`, `nonrd_keyframe = 1`, `rt_intra_dc_only_low_content = 1`, `short_circuit_low_temp_var = 3`, `use_simple_block_yrd = 1`). These are not dispatched.
- **For cpu-used 9:** ML partition, adaptive subpel force stop, GOLDEN disable, intra-DC-only, BILINEAR filter — all distinct from cpu-used-8. Not dispatched.

### Implication for parity

Even when every gate-side flag is honoured (best case for the rvp9 op point), running `rvp9enc --cpu-used=3 --good ...` produces **the same encode as `--cpu-used=8 --rt`**. The audit zones A13/A14/A21 cover the missing producers (RDO picker etc.); but this zone's specific gap is that there is **no plumbing layer** between `cpu-used` and the per-picker-call configuration. That plumbing is a prerequisite to anything in Phase 2 that touches multi-speed behaviour.

### Frame-size dispatch is also absent

`set_rt_speed_feature_framesize_dependent` (speed_features.c:414-450) flips `disable_split_mask` and `encode_breakout_thresh` based on `VPXMIN(cm->width, cm->height) >= 720`. `set_good_speed_feature_framesize_dependent` (speed_features.c:64-214) has 4 resolution tiers (480p/720p/1080p/2160p). None of this is wired in rvp9 — flags are constant regardless of frame size. For the 352×288 (foreman_cif) and 1280×720 (parkrun_720p) corpora rvp9 currently benches against, this means the same flag set is applied at both resolutions.

## 1. Dispatch / Best-Quality Defaults

### `vp9_set_speed_features_framesize_independent` (speed_features.c:915-1093)
**Status: PARTIAL** (only the per-picker hard-coded RT cpu-used-6/7 subset of effective values matches; the function itself doesn't exist).

Libvpx's pre-init block lines 924-1036 establishes the **best-quality defaults** for every field of `SPEED_FEATURES`. These are the values used when `speed = 0` and `mode = BEST`, and they are the baseline that the RT and GOOD setters then partially override. In rvp9 there is no equivalent struct to hold these defaults; every field that the gate-side picker reads is a separate parameter on `InterModeSearchParams`, with the call-site supplying a hard-coded value (which happens to match libvpx's cpu-used-6/7 effective value, not the best-quality default).

### `vp9_set_speed_features_framesize_dependent` (speed_features.c:869-913)
**Status: NOT PORTED**

The frame-size-aware setter is called per frame in libvpx (after the framesize-independent setter, since the resolution may change frame-to-frame in dynamic-resize mode). rvp9 has no equivalent. The post-setter cross-checks at lines 889-913 (`disable_split_mask == DISABLE_ALL_SPLIT` ⇒ `adaptive_pred_interp_filter = 0`; `encode_breakout_thresh` floor; row-MT bit-exact `adaptive_rd_thresh = 0` override) are also absent.

### `set_best_speed_feature_framesize_independent`
**Status: OUT OF SCOPE**

There is no separate setter for `BEST` in libvpx — the "best" defaults are just the pre-init block at lines 924-1036 plus a fall-through that skips the RT and GOOD branches. Documented here so the row count includes the audited zone-scope.

## 2. The Good path (speed 0..=5)

`set_good_speed_feature_framesize_dependent` (lines 64-214) and `set_good_speed_feature_framesize_independent` (lines 219-411) together set ~50 distinct flags across speeds 0-5. **None of these are honoured by rvp9 because the RDO picker (zone A13), sub-8x8 picker (A14), compound prediction (A15), and RD-ML partition (A21) — the things these flags configure — are absent or stubbed.** The pre-condition for porting the Good speed setters is the producer-side subsystems landing.

Examples of high-impact Good-path flags that are dead-letter today:
- `sf.mv.subpel_search_method = SUBPEL_TREE_PRUNED` / `_MORE` (lines 362, 389): rvp9 only implements `SUBPEL_TREE_PRUNED_MORE` (`crates/rvp9-core/src/mv_search/sub_pixel.rs`); no dispatch on this field exists.
- `sf.tx_size_search_method` (lines 327, 361, 387, 938): A13 / A4.
- `sf.mode_search_skip_flags` (lines 329-333, 392): mode-prune flags are not threaded into rvp9's picker at all.
- `sf.recode_loop` (lines 322-324, 368): rvp9 has no recode loop.
- `sf.mesh_patterns` (lines 264-270): no mesh search.
- `sf.rd_ml_partition.*` (lines 84-103, 113-127, etc.): A21.

## 3. The RT path framesize-independent (speed 0..=9)

This is the only setter with partial coverage. The flags listed in the §10/§11/P18/P20 banners in `crates/rvp9-core/src/mode_decision/inter.rs:678-885` are the rvp9-honoured subset. The encoder at `crates/rvp9-encoder/src/lib.rs:3680-3724` hard-wires their values.

What gets honoured (gate-side present, encoder-set to the cpu-used-6/7 value):
- `sf.adaptive_rd_thresh = 4` — via `rd_thresh::ADAPTIVE_RD_THRESH` constant (`rd_thresh.rs:90`). Bound by `update_thresh_freq_fact_with_s11`.
- `sf.inter_mode_mask[bsize]` — via `default_inter_mode_mask()` (`inter.rs:964-969`).
- `sf.limit_newmv_early_exit = true` — gate at `inter.rs:1147-1149`, encoder at `lib.rs:3715`.
- `sf.bias_golden = true` — gate at `inter.rs:2237-2239`, encoder at `lib.rs:3716`.
- `sf.cb_pred_filter_search = false` — gate at `inter.rs:1852-1858` (chessboard), encoder at `lib.rs:3718` (note: libvpx sets `2` at cpu-used-6/7 above 720p; rvp9 always passes `false`).
- `sf.disable_golden_ref = false` — gate at `inter.rs:1964-1966`, encoder at `lib.rs:3722`.
- `sf.max_intra_bsize = BLOCK_32X32` — gate at `inter.rs:2523`, encoder at `lib.rs:3723`.
- `sf.rt_intra_dc_only_low_content = false` — gate at `inter.rs:2571`, encoder at `lib.rs:3724`.
- `sf.reference_masking = true` — gate at `inter.rs:2195`, encoder at `lib.rs:3647`.
- `sf.short_circuit_flat_blocks = false` — gate exists at `inter.rs:1882, 2563`, encoder at `lib.rs:3682` (default disabled).
- `sf.mv.subpel_force_stop` — `SubPixelForcedStop` enum (`sub_pixel.rs:55-65`), `adaptive_subpel_force_stop()` helper (`sub_pixel.rs:96-106`) ports speed-9 logic but is not invoked at cpu-used-6/7.
- `sf.mv.subpel_search_level` — `iters_per_step` (`sub_pixel.rs:138-147`), hard-coded to 2 (libvpx cpu-used-6/7 default).

What is **not** honoured (gate site is hardcoded or absent), even on the RT path at cpu-used-6/7:
- `sf.mv.search_method` (line 668: `NSTEP`; line 702: `FAST_DIAMOND` at speed 7): rvp9 always runs `diamond_search_sad` (`crates/rvp9-core/src/mv_search/full_pixel.rs`); the search method is not a configurable dispatch.
- `sf.mv.fullpel_search_step_param = 10` at speed 7 (line 703): rvp9's MV-search seeding does not respect this.
- `sf.tx_size_search_method = USE_TX_8X8` at speed 4/5 (lines 581, 613): rvp9 picks max-TX always (see also A13's `calculate_tx_size` gap from the picker inventory).
- `sf.use_quant_fp = !is_keyframe` at speed 4+ (lines 573, 587): rvp9's `block_yrd` is `quantize_fp` always (Phase 4c switch resolves the metrics path, but the gate field is not actually consulted — it's a constant choice).
- `sf.partition_search_type = REFERENCE_PARTITION` at speed 5 (line 596) and `VAR_BASED_PARTITION` at speed 6 (line 667): rvp9 has variance-based partition (`mode_decision/partition.rs`) but no `REFERENCE_PARTITION`, no dispatch.
- `sf.use_nonrd_pick_mode = 1` at speed 5 (line 601): rvp9 has only non-rd; there is no RDO alternative to switch to.
- `sf.use_source_sad = 1` at speed 5 (line 659): no source-SAD pre-pass.
- `sf.adapt_partition_source_sad = 1` at speed 6 (line 673): not wired.
- `sf.lpf_pick = LPF_PICK_FROM_Q` at speed 3 (line 555): A9 hardcodes Q-derived pick already, so this happens to match — but the field isn't read.
- `sf.short_circuit_low_temp_var = 1 / 3` at speed 6/8 (lines 687, 774): not wired.
- `sf.use_simple_block_yrd = 1` at speed 7/8 (lines 713, 791): the block_yrd "simple" shortcut is not implemented.
- `sf.encode_breakout_thresh` (line 447-449): rvp9's encode-breakout uses a constant 20 (`lib.rs:3630`), not the speed/resolution-dispatched value.
- `sf.copy_partition_flag` (lines 727-734): no inter-frame partition copy.
- `sf.overshoot_detection_cbr_rt` (lines 649-651, 696): no scene-change overshoot handler (this overlaps with A3 rate-control).
- `sf.nonrd_keyframe` (lines 470, 644, 757, 866): no keyframe-specific dispatch.

# 2026-06-21 - CR - VBR product-gate divergence analysis

First clean block-level diagnosis of the **actual Stage 4a VBR product gate**
(foreman 256x256, one-pass VBR, `vpxenc --rt --cpu-used=7 --lag-in-frames=0`),
not the contaminated fixed-Q E9 path. Both rvp9 and libvpx streams decoded
through the same rvp9 decoder (oracle). Tool:
`cargo run --release -p rvp9-harness --bin e1_block_stats -- --foreman <y4m>
--vpxenc D:\language\libvpx-stock\vpxenc.exe --frames 64`.

Baseline product metric (this host, origin/main e678386):
BD-rate **+6.43%**, matched-bitrate mean **Δ +1.16 dB**.

## The divergences (consistent across 25/50/100/250 kbps targets)

### 1. Reference-quality cadence — DOMINANT

rvp9 starves the keyframe and never builds high-quality references; libvpx
invests heavily in the keyframe AND fires a periodic golden/ARF-like boost
(~15000 bits at q~130 with intra refresh) every ~10 frames, then coasts.

| 100 kbps | rvp9 | libvpx |
|---|---:|---:|
| keyframe bits / q | 16608 / 164 | 74536 / 57 |
| avg inter bits | 2088 | 3376 |
| avg inter base_qindex | 236.5 (226–255) | 204.9 (114–255) |

Per-frame (100 kbps): libvpx spends ~15–19 kbits at q~130 on frames
10/20/30/40/50/60 (boost cadence); rvp9 has NO comparable boosts — uniform
q~236. libvpx's coasting frames then predict from a fresh high-quality
reference; rvp9's predict from a degrading chain.

This is the biggest lever but it is **rate allocation**, and prior attempts
regressed: "split VBR keyframe bit estimator" (+69% BD-rate, overspend) and
the full "VBR GOLDEN target/active-best port" (+46% BD-rate, over-allocate).
The challenge is calibrating boost magnitude, not its existence. The keyframe
q=164 @ 100 kbps is egregious (cf. E1 post-seed-fix reported q=65) and worth a
focused look — but it is the myopic one-pass VBR not valuing the keyframe
investment, the same wall.

### 2. ZEROMV over-use — rvp9 ~26% vs libvpx ~4% (area-weighted, every point)

| mode (100 kbps) | rvp9 | libvpx |
|---|---:|---:|
| NEARESTMV % | 56.4 | 63.2 |
| ZEROMV % | 27.8 | 3.8 |
| NEWMV % | 11.2 | 25.9 |
| skip=1 % | 69.1 | 86.5 |

NOT a missing-temporal-MV problem: `use_prev_frame_mvs` is a **vestigial
no-op** config field (the encoder computes the gate purely structurally per the
SIG-1 drift fix, frame_loop.rs:2570-2589, and already uses temporal MV salvage
for eligible inter frames). Flipping the gate config true→false is byte-identical.
So the ZEROMV gap is a **mode-RD/labelling** divergence, not candidate
availability. Hypothesis to test next: for static blocks both encoders code
(0,0) motion but libvpx labels it NEARESTMV (cheaper context) while rvp9 labels
it ZEROMV — i.e. an inter-mode cost/tie-break issue beyond the existing
`nearest_tie_fix` (which only covers exact NEAREST==(0,0) ties).

### 3. Partition too fine — rvp9 94–96% 16x16, libvpx uses a 32x32 mix

| 250 kbps area% | rvp9 | libvpx |
|---|---:|---:|
| 8x8 | 0.0 | 37.1 |
| 16x16 | 95.7 | 52.3 |
| 32x32 | 2.6 | 10.7 |

rvp9 is stuck at 16x16 (RT descent rarely selects 32x32 NONE; 64x64 ~0%),
paying ~4× per-area partition/skip/header/TX overhead. At its HIGHER q rvp9
should use LARGER partitions, not smaller — so this is RD-calibration, not a q
effect. Note `RVP9_RT_MIN_PARTITION32` is area-gated to ≥700k px so it never
applied to this 256x256 gate (prior "inert" result explained).

### 4. Residual spread / skip — rvp9 codes residual on many marginal blocks

rvp9 ~278 EOB blocks/frame each ~1 coef vs libvpx ~86 blocks with more coefs
each (25 kbps: rvp9 zero/one/two+/eob 21/66/1/278 vs libvpx 35/40/6/86). rvp9
skips less (80% vs 94%) and spreads thin residual; libvpx concentrates. This is
the residual-coding/skip efficiency seen earlier — and the adapted-skip-prob
fix (2026-06-21 JRN) is refuted because the skip RD tie-break dist-domain isn't
calibrated.

## Verdict / roadmap

All four divergences trace to two coupled root systems:
(A) **one-pass VBR reference-allocation** (keyframe + boost cadence), and
(B) **picker RD-domain calibration** (S3 coef-dist ↔ lambda ↔ coef_rate scale
↔ skip tie-break ↔ partition/TX granularity).

Every isolated perturbation of either has regressed (this session's
adapted-skip-prob; prior sessions' keyframe-BPM-split, VBR-GOLDEN port,
S3_DOMAIN=1, ~20 micro-probes). The product BD-rate gate (gate 3) is dominated
by (A); the fixed-Q residual (gate 4, +1.29 dB at matched Q) isolates (B).

Recommended next program (focused, not one-shot levers):
1. **Reference-allocation calibration** — a *bounded* keyframe + periodic-GF
   quality investment for one-pass VBR, swept against the 4-point gate so it
   raises low/mid-rate PSNR without the prior overspend (watch coverage —
   don't let rvp9 fall out of libvpx's bitrate range).
2. **Picker RD-domain co-calibration** — S3 coef-dist↔lambda as a *pair* (the
   inter.rs note's stated "real magnitude lever"), validated to simultaneously
   improve partition-size selection (more 32x32), skip rate, and the ZEROMV
   labelling — these are downstream of the same RD balance.

Both are multi-session efforts; rushing either in isolation reproduces the
documented regressions.

## ADDENDUM (2026-06-21, same session): A and B are NOT co-equal — do B first

An env-gated keyframe-BPM sweep (`RVP9_KF_BPM`, the genuinely binding keyframe
lever) settled the ordering empirically. More keyframe investment
(KF_BPM 5.0→1.5) monotonically WORSENED the matched-bitrate Δ
(+1.16→+1.21→+1.28→+1.38→+1.42→+1.59). So **reference allocation (A) is a dead
end until inter-prediction efficiency (B) improves** — rvp9's starved-keyframe
allocation is already near-optimal for its (weak) prediction; a better reference
isn't capitalised on, so the bits are wasted at matched bitrate. libvpx's
keyframe investment pays off only because its inters are efficient.

Revised priority: **(B) picker RD-domain / inter-prediction efficiency is THE
lever and the prerequisite.** (A) reference allocation should be revisited ONLY
after B closes, at which point the verified KF-boost bug (scratchpad) and a
bounded KF/GF investment become worth re-testing. Don't spend further effort on
A in isolation — it's measured as net-negative.

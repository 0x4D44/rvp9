## Section-by-Section Narrative

### Section 1 — Data structures (rows 1-6)
libvpx defines a top-level `SVC` struct stored on `cpi->svc` (`vp9_svc_layercontext.h:80-208`). It carries the spatial/temporal IDs, layer counts, per-layer rate-control fanout via `LAYER_CONTEXT layer_context[VPX_MAX_LAYERS]` (row 2), the temporal layering mode (`VP9E_TEMPORAL_LAYERING_MODE_0101 / _0212 / _NOLAYERING / _BYPASS`), per-spatial-layer reference-frame buffer indices (`lst_fb_idx[VPX_MAX_LAYERS]`, `gld_fb_idx`, `alt_fb_idx`), the long-term GF reference slot table `buffer_gf_temporal_ref[2]` (row 3), the four-way `INTER_LAYER_PRED` enum (row 4) and many supporting fields (downsample filter type/phase per layer, framedrop thresholds per layer, scaled frame storage). `is_one_pass_svc` (row 5) is a one-line inline that gates the majority of SVC code paths; `denoise_svc` (row 6) similarly gates SVC+denoiser interaction. **rvp9 has no `Svc` struct, no `LayerContext`, no `InterLayerPred` enum, no `is_one_pass_svc` predicate** — confirmed by grep across `crates/rvp9-core/` and `crates/rvp9-encoder/`.

### Section 2 — Lifecycle: init, change-config, restore/save (rows 7-13)
`vp9_init_layer_context` (row 7) is called once from `vp9_encoder.c::vp9_create_compressor` and populates `svc->layer_context[sl*ts + tl]` for every (sl, tl) pair, initialising starting buffer level, worst/best quality, target_bandwidth, per-CBR vs non-CBR `last_q`/`avg_frame_qindex`, and the cyclic-refresh maps on the base temporal layer. `vp9_update_layer_context_change_config` (row 8) re-runs that fanout when bitrate changes mid-stream. `get_layer_context` (row 9) is the static dispatcher: it returns the per-(sl, tl) LC for one-pass-SVC, otherwise indexes by temporal layer for CBR or spatial for two-pass. `vp9_update_temporal_layer_framerate` (row 10) recomputes `avg_frame_bandwidth` and `avg_frame_size` from `ts_rate_decimator[tl]`; the spatial counterpart (row 11) additionally calls `vp9_rc_set_gf_interval_range`. The save/restore pair (rows 12-13) is the key flush mechanism — it swaps `cpi->rc`, `cpi->twopass`, and (for the CR-on-base-TL case) the CR map pointers in and out of the LC before/after each layer is encoded. **None of this exists in rvp9** — `rate_control/state.rs` is explicitly documented as a single-context, non-SVC port (`state.rs:7`).

### Section 3 — Per-frame counters and resolution helpers (rows 14-16)
`vp9_init_second_pass_spatial_svc` (row 14, gated by `!CONFIG_REALTIME_ONLY`) initialises a separate `TWO_PASS` struct per spatial layer for stat aggregation. `vp9_inc_frame_in_layer` (row 15) is called once per encoded layer-frame; it advances `current_video_frame_in_layer` and `frames_from_key_frame`, and increments `current_superframe` only when the top spatial layer is encoded. `get_layer_resolution` (row 16) is the helper that converts a (scaling_factor_num, scaling_factor_den) pair into an even-rounded (width, height) for the layer. None ported.

### Section 4 — Reference-frame buffer routing (rows 17-23)
Rows 17-22 implement libvpx's static temporal-layering dispatch. `reset_fb_idx_unused` (row 17) is the cleanup pass: any reference that is neither referenced nor refreshed has its fb_idx redirected to the first valid slot. `non_reference_frame_simulcast` (row 18) zeroes all refresh flags on the top temporal layer in simulcast mode. The three `set_flags_and_fb_idx_for_temporal_mode*` functions (rows 19, 20, 21) drive the three fixed patterns (0-2-1-2, 0-1-0-1, no-layering); they set `cpi->lst_fb_idx`, `cpi->gld_fb_idx`, `cpi->alt_fb_idx`, `cpi->ref_frame_flags`, and the three `ext_refresh_*_frame` flags. `set_flags_and_fb_idx_bypass_via_set_ref_frame_config` (row 22) is the BYPASS mode entry: it reads the application-supplied per-spatial-layer `lst_fb_idx[sl]`, `gld_fb_idx[sl]`, `alt_fb_idx[sl]`, and `reference_last/golden/altref[sl]` flags. `vp9_copy_flags_ref_update_idx` (row 23) writes the per-layer refresh flags back into `svc->update_buffer_slot[sl]`, `svc->update_last/golden/altref[sl]` for the GET_SVC_REF_FRAME_CONFIG API. **No equivalent in rvp9** — the encoder's reference-frame management treats LAST/GOLDEN/ALTREF as global slots and there is no per-spatial-layer fb_idx array.

### Section 5 — One-pass-SVC layer-start (row 24)
`vp9_one_pass_svc_start_layer` (row 24) is the largest function in the file (225 LOC). Per layer it: sets `simulcast_mode` based on `INTER_LAYER_PRED_OFF` and layer-count <=3, sets `use_base_mv` and `use_partition_reuse` when number_spatial_layers > 1, runs the `force_drop_constrained_from_above` pre-scan for the constrained-drop mode, dispatches to the temporal-mode setter (rows 19-22), tracks the long-term GF buffer (`svc->buffer_gf_temporal_ref[0/1].is_used`), enables the second long-term temporal reference when the conditions hold (`use_gf_temporal_ref && spatial_layer_id >= number_spatial_layers - 2` and inter-layer pred is not full-ON), resets per-superframe SAD/motion counters on SL0, applies the rate-control worst/best-quality push-down for SET_SVC_PARAMETERS, handles dynamic resize for single-layer SVC, picks the downsample filter (Eightap_smooth for ≤320×240 sources), enforces the `use_base_mv` / `use_partition_reuse` scaling constraints (2x or 4x only), detects non-reference frames, applies the prev-layer-dropped recovery (`fb_idx_upd_tl0`), and finally calls `vp9_set_size_literal`. **No equivalent in rvp9.**

### Section 6 — Lookahead / cyclic-refresh / temporal-layer reset (rows 25-28)
`vp9_svc_lookahead_pop` (row 25) is the SVC-aware pop helper: it `peek`s the lookahead, and only `pop`s when the *top* spatial layer is being encoded (so all lower spatial layers reuse the same source frame). `vp9_free_svc_cyclic_refresh` (row 26) walks the (sl, tl) grid and frees per-layer CR maps. `vp9_svc_reset_temporal_layers` (row 27) is called on key frames: it zeros `current_video_frame_in_layer` (and `frames_from_key_frame` if `is_key`), re-runs the temporal-mode setter, then `vp9_update_temporal_layer_framerate` and `vp9_restore_layer_context`. `vp9_svc_check_reset_layer_rc_flag` (row 28) resets RC 1-frame/2-frame state and buffer level when `avg_frame_bandwidth` jumps by >1.5× or <0.5× its previous value. None ported.

### Section 7 — Inter-layer prediction constraints (rows 29-32)
`vp9_svc_constrain_inter_layer_pred` (row 29) is the heart of the inter-layer mode-decision restriction: it walks LAST/GOLDEN/ALTREF, finds those whose `scale_factors` are scaled (i.e. they point at a different-resolution reference), and clears the corresponding flag in `cpi->ref_frame_flags` when the inter-layer pred mode is OFF, OFF_NONKEY, or the previous spatial layer was dropped. For INTER_LAYER_PRED_ON_CONSTRAINED it ensures GOLDEN can only predict from sl-1 of the same superframe by cross-checking `svc->lst_fb_idx[sl-1]`, `svc->gld_fb_idx[sl-1]`, `svc->alt_fb_idx[sl-1]` against `update_buffer_slot[sl-1]`. `vp9_svc_assert_constraints_pattern` (row 30) is the corresponding runtime audit (debug assertions on `fb_idx_temporal_layer_id` / `fb_idx_spatial_layer_id`). `vp9_denoise_svc_non_key` (row 31, behind `CONFIG_VP9_TEMPORAL_DENOISING`) gates the temporal denoiser to non-key frames on the SVC layers that should denoise. `vp9_svc_check_spatial_layer_sync` (row 32) handles layer-sync frames: on sync, it disables LAST temporal prediction for the synced spatial layer and rotates `alt_fb_idx` to the long-term GF buffer slot. **None ported.**

### Section 8 — Reference-frame slot tracking after encode (rows 33-35)
`vp9_svc_update_ref_frame_buffer_idx` (row 33) marks `svc->fb_idx_base[]` for any slot the base spatial layer used or refreshed; this is what feeds into the inter-layer-pred constraint check on later layers. `vp9_svc_update_ref_frame_bypass_mode` (row 34, static) is the BYPASS-mode variant — it walks `update_buffer_slot[sl]` and calls `ref_cnt_fb` to attach the new frame buffer to every slot the API said to update. `vp9_svc_update_ref_frame` (row 35) is the public entry that runs after each frame encode: on KEY frames (non-simulcast) it fans the new buffer out to all 8 ref slots; otherwise it updates only the LAST/GOLDEN/ALTREF slots whose refresh flag is set, then calls rows 23 and 33. **None ported.**

### Section 9 — Frame-rate and qindex adjustments (rows 36-38)
`vp9_svc_adjust_frame_rate` (row 36) recomputes `cpi->framerate` from `svc->duration[sl] * svc->timebase_fac` for timestamp-driven framerate-per-layer. `vp9_svc_adjust_avg_frame_qindex` (row 37) is a key-frame overshoot handler: when the projected frame size is >3× the average bandwidth in CBR, it pushes `avg_frame_qindex[INTER_FRAME]` upward (toward worst_quality) on both `cpi->rc` and every base-spatial-layer `LAYER_CONTEXT.rc`. `vp9_svc_check_skip_enhancement_layer` (row 38) skips encoding when the layer's target bandwidth is 0 and the framedrop logic agrees — it calls `vp9_rc_postencode_update_drop_frame`, clears `ext_refresh_frame_flags_pending`, marks `last_frame_dropped`/`last_layer_dropped[sl]`/`drop_spatial_layer[sl]`, and increments the in-layer counter. **None ported.**

## Cross-Cutting Gaps

### CG-1. `cpi->use_svc` and `cpi->oxcf.pass` are not modelled
libvpx gates the entire SVC subsystem on the `is_one_pass_svc` predicate (`vp9_encoder.h:1411-1413`), which is `cpi->use_svc && cpi->oxcf.pass == 0`. rvp9 has no `use_svc` flag, no `pass` field tracking 0/1/2 (one-pass / first-pass / second-pass), and no encoder-config plumbing to surface either. Every SVC code path downstream depends on this predicate. **Impact: high** — the predicate is the gate; without it, every other SVC function is dead.

### CG-2. `VP9E_TEMPORAL_LAYERING_MODE` enum is not modelled
The four-mode enum (`_0101`, `_0212`, `_NOLAYERING`, `_BYPASS`) drives the static-pattern dispatch in `vp9_one_pass_svc_start_layer` at `vp9_svc_layercontext.c:819-830` and `vp9_svc_reset_temporal_layers` at `:1039-1046`. rvp9 has no enum and no dispatch. **Impact: high** — without these four patterns the CLI's `--svc` flag cannot do anything useful even after wiring.

### CG-3. `LAYER_IDS_TO_IDX(sl, tl, ts_layers)` is not defined
The flat-index macro `LAYER_IDS_TO_IDX(sl, tl, n_t) = (sl * n_t + tl)` is the addressing scheme used at `vp9_svc_layercontext.c:107, 204, 209, 286, 1018, 1056, 1064, 1209, 1346`. rvp9 has no `LayerContext` array, no flat-index helper. **Impact: high** — fix this and rows 1-2 (struct definitions) at the same time.

### CG-4. Per-spatial-layer reference-frame buffer indices
libvpx's `SVC` struct carries `lst_fb_idx[VPX_MAX_LAYERS]`, `gld_fb_idx[VPX_MAX_LAYERS]`, `alt_fb_idx[VPX_MAX_LAYERS]` (`vp9_svc_layercontext.h:110-112`) plus per-frame `fb_idx_spatial_layer_id[REF_FRAMES]` and `fb_idx_temporal_layer_id[REF_FRAMES]` tracking arrays (`:175-176`). rvp9's reference-frame management at `crates/rvp9-encoder/src/lib.rs` treats the 8 reference slots as encoder-global, with no per-layer fanout. **Impact: high** — this is the single largest data-structure gap and feeds rows 19-23, 29, 32-35, 38-46.

### CG-5. `svc_force_zero_mode[3]` pickmode gate produces a systematic NEWMV miscalibration
At `vp9_pickmode.c:1934-1969`, the picker sets `svc_force_zero_mode[LAST_FRAME - 1] = 1` when the spatial reference for LAST is the lower spatial layer of the same superframe and `svc->force_zero_mode_spatial_ref` is set — same for GOLDEN. The picker then forbids any non-zero MV from that reference at `:2186, 2323`. **Without this gate (rvp9's current state)** the encoder freely tries arbitrary MVs against a reference that, in real SVC, is constrained to scaled-inter-layer prediction at MV=0. Result: wasted RD work AND a real bitstream miscalibration if SVC was ever enabled. Cross-zone: same root cause as Track G's NEWMV rejection, but isolated to the SVC path.

### CG-6. The `--svc` CLI flag is a no-op stub
`crates/rvp9-cli/src/args.rs:265-270` declares the flag with `apply: None`. `args.rs:268` annotates the help as `[not yet]`. `cli_roundtrip.rs:138` asserts the flag is rejected as an error. **Impact: high** for any user-facing SVC parity — even the entry point is missing. The CLI surface for SVC in libvpx is far richer: `--passes`, `--lag-in-frames`, `--ts-number-layers`, `--ts-rate-decimator`, `--ts-target-bitrate`, `--ts-layer-id`, `--ss-number-layers`, `--ss-target-bitrate`, `--ss-scale-factors`, `--use-bypass-tl-pattern`, etc. None of these are present in rvp9.

### CG-7. Frame loop is single-frame, no superframe concept
libvpx's frame loop in `vp9_encoder.c::encode_frame_to_data_rate` iterates `svc->spatial_layer_to_encode` across all spatial layers and emits a superframe at the top. rvp9's `frame_loop.rs` produces one bitstream frame per input frame. **Impact: high** — SVC requires superframe assembly, but that infrastructure is also absent (touches A6 Bitstream packing and A19 Lookahead pipeline).

## Cross-zone dependencies flagged for master inventory

- **A2 (Frame loop):** SVC drives a superframe loop layered over the input-frame loop; A18 P5.1 cannot land before A2 supports multi-encode-per-input-frame.
- **A3 (Rate control):** SVC needs per-layer `RATE_CONTROL` clones; A18 P1.1-P1.2 require `RateControl` to be `Clone`-able and Box-able into a `LayerContext`. Currently `rate_control/state.rs:7` explicitly documents the single-context design.
- **A6 (Bitstream packing):** SVC emits a superframe-index trailer (`vp9_pack_bitstream.c` has the marker writer); A18 P5.1 requires it.
- **A10 (Reference-frame management):** A18 P0.2 + P2.1-P2.3 fundamentally restructure the ref-frame slot model from "encoder-global" to "per-spatial-layer".
- **A11 (Segmentation / AQ):** A18 P4.4 frees per-layer CR maps and A18 P1.2 swaps them in/out; the AQ port must allow CR map ownership transfer.
- **A12 (CLI / config):** A18 P5.4 adds ~10 new flags.
- **A16 (ALTREF / temporal filtering):** SVC also stores scaled source frames for temporal filtering (`svc->scaled_frames[MAX_LAG_BUFFERS]` at `vp9_svc_layercontext.h:95`); A18 and A16 share this buffer.
- **A17 (Temporal denoiser):** A18 P6.2 is gated on `CONFIG_VP9_TEMPORAL_DENOISING`.
- **A19 (Lookahead pipeline):** A18 P1.4 (`vp9_svc_lookahead_pop`) requires A19 to expose peek-without-pop.
- **A1 (pick_inter_mode):** A18 P3.2 plugs picker-side SVC gates that interact with `force_skip_low_temp_var`, ref-frame mask iteration, and the NEWMV path — all already PARTIAL in the A1 audit.

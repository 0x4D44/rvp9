## 0. TL;DR — what changed from the two half-designs

The prior Lever-3a HLD claimed its fix makes **"picker-skip == emit-skip by
construction."** A devil's-advocate review and a follow-up assessment found:

1. **That invariant is FALSE.** The picker's skip round-trip is **Y-luma only**,
   but the emit's skip override (`leaf_total_eob == 0`) sums eob over **Y+U+V**,
   AND the picker round-trip runs at a tx size **capped at Tx16x16** while the
   emit walks **Tx4x4..Tx32x32**. Two code-verified holes remain even after the
   Lever-3a Y-eob gate. The fix closes the **Y-luma slice** of the divergence,
   not the whole thing. (§1.2)
2. **Lever-3a and Lever-3b are two halves of one fix.** The skip reconciliation
   (3a) *un-masks* a rate/distortion **domain mismatch** (3b) that, left
   uncorrected, will likely *regress* quality — the same −6 dB pattern F.4
   already measured. They must be designed, measured, and (probably) landed
   together. (§4)
3. **The real magnitude lever is the RD-domain mismatch (DV-F1-3), not K1.**
   K1 is a dead end (~0.1 dB); the in-tree F4 note claiming "K1=4 winning" is
   **stale and misleading** and must be retired (§2.3).

This HLD therefore: (S1) **measures first and gates**, breaking the divergence
down **by cause**; (S2) reconciles the **Y-only** skip slice honestly (no
"by construction" claim) and resolves AcDc concretely; (S3) aligns the encode
RD **domain** (`dist → coef_dist`) with the explicit `u64` `rd_cost` widening
that has stalled this twice.

**None of this is a correctness bug.** The emit's `lib.rs:5263` override keeps
the bitstream self-consistent; `cross_decoder_gate` stays 4/4 throughout. This
is a *quality-optimality* limitation in the picker's mode ranking, not a
decode-correctness defect. Said plainly so the lead does not over-weight risk.

## 1. Problem

### 1.1 The decoupling (code-verified)

The inter mode picker's skip decision is **decoupled** from the emit's. The
picker prices most leaves as *skip* (residual ≈ 1 bit, distortion =
prediction-only SSE), while the emit actually *codes residual* on the same
leaves. The picker's RD ranking is therefore computed against a cost the
bitstream never pays, biasing mode selection toward the cheapest-rate
(NEARESTMV / ZEROMV) candidate.

**Picker tie-break** — `crates/rvp9-core/src/mode_decision/inter.rs:2656-2666`:

```rust
let rd_encode = rd_cost(lambda, rate, dist);            // rate INCLUDES effective_coef_rate
let rd_skip   = rd_cost(lambda, 0, sse_after_pred_u32); // ~0 rate, pred-only SSE
let (final_rate, final_dist) = if rd_encode < rd_skip {
    (rate.saturating_add(skip_false_cost), dist)        // pay residual + skip=0 bit
} else {
    (skip_true_cost, sse_after_pred_u32)                // collapse to skip=1 bit, pred SSE
};
```

When the skip branch wins, the `rate` it computed — which **includes** the real
`effective_coef_rate` (`inter.rs:2500/2611`) — is **discarded**. The
`(final_rate, final_dist)` feeds `best_rate`/`best_distortion`
(`inter.rs:2677-2678`) and thus the candidate's `best_rd_cost`
(`inter.rs:2676`) used to rank modes.

**Emit re-decision** — `crates/rvp9-encoder/src/lib.rs:5263-5265`:

```rust
if leaf_total_eob == 0 {
    sb_partitions[sb_idx][leaf_idx].skip = true;
}
```

`leaf_total_eob` (`lib.rs:5241`) is summed over **every transform tile of
every plane** — the enclosing loop is `for plane in 0..3` (`lib.rs:4970`), so
this is **Y + U + V**. The emit skips only if every quantized coefficient in
all three planes is zero. The picker's skip decision never reaches the emit;
the struct that returns from the picker (`InterModeSearchResult`,
`inter.rs` ~315) carries no skip flag, and the emit re-decides independently.

### 1.2 Why "picker-skip == emit-skip by construction" is FALSE — two holes

The prior HLD's central invariant claimed the Lever-3a fix (gate the picker's
skip branch on the picker's own DCT eob) makes the picker's skip set *identical*
to the emit's. It does not. Two code-verified divergence sources survive that
gate:

**(a) Chroma-eob hole.** The picker's reconstruction round-trip
(`reconstruct_via_round_trip`, `inter.rs:2854-3101`) operates on **luma only** —
it reads `params.src_plane` / `pred` (the Y plane) and produces a Y-only
`BlockYrdResult` eob. Chroma RD comes from a **separate variance model**
(`model_rd_for_sb_uv`, called at `inter.rs:2584`), which produces a rate/dist
estimate but **no eob** — there is no chroma forward-transform/quantize in the
picker at all. The emit, by contrast, forward-transforms and quantizes U and V
(`lib.rs:4970` `for plane in 0..3`) and folds their eobs into `leaf_total_eob`.

→ A leaf whose **Y residual quantizes to zero but whose U or V residual does
not** desyncs: the Y-only picker gate says "skip", the emit's Y+U+V eob says
"don't skip." The Lever-3a gate fixes only the **Y-luma slice** of the
divergence. The chroma slice is structurally invisible to the picker.

**(b) Tx-size hole.** The picker round-trip runs at `mrd.tx_size`
(`inter.rs:2320`), which `model_rd.rs:196` **caps at Tx16x16**. The emit picks
its Y tx size with `choose_inter_luma_tx_size` (`lib.rs:6221`), which walks the
**full** `(0..=max_tx).rev()` ladder — `Tx4x4, Tx8x8, Tx16x16, Tx32x32`
(`lib.rs:6260-6266`). The eob of a residual depends on the transform size used.
So picker-eob and emit-eob are computed at **different, only-partially-
overlapping tx ranges**; on leaves where the emit chooses Tx32x32 (or sub-8
Tx4x4, which the picker round-trip cannot even do — it `debug_assert!`s false at
`inter.rs:2941`), the picker's eob is not the emit's eob.

**Consequence for the design:** the Lever-3a Y-eob gate is **necessary but not
sufficient**. We must (i) say so honestly — no "by construction" — and (ii)
*measure* how much of the ~97 % divergence each hole accounts for **before**
committing to implementation, so we know the achievable ceiling of the skip fix.
That is S1.

### 1.3 The magnitude problem (DV-F1-3) — the other half

Even with the Y-skip slice reconciled, the picker's mode RD on the ~97 % of
leaves that *do* code residual is computed in a **mismatched domain**:

- The picker's **rate** for residual is `effective_coef_rate` — a
  **coefficient-domain** quantity (Hadamard SATD of qcoeff, scaled
  `<< (2 + VP9_PROB_COST_SHIFT)`, `inter.rs:3093` / `block_yrd.rs:165`),
  exactly libvpx's `block_yrd` rate proxy.
- The picker's **distortion** is `dist` = **pixel-SSE-of-recon**
  (`inter.rs:2378`, plus UV dist at `inter.rs:2606`), a *pixel-domain* quantity.
- libvpx pairs its coefficient-domain rate with a **coefficient-domain**
  distortion: `block_error_fp >> 2` (the same `coef_dist` the picker already
  computes and surfaces but never feeds to `rd_cost` — `inter.rs:2349-352`
  doc-comment: *"Not consumed by `rd_cost` in F.1"*).

So the picker's `RDCOST = rate·rdmult + dist<<7` mixes a coef-domain rate with a
pixel-domain distortion. The `<< 2` SATD-to-bits scale and lambda were both
ported faithful to libvpx, but libvpx tuned them against a coef-domain `dist`.
Mixing domains shifts the rate/distortion balance, so the coef-rate
**overprices** residual candidates → picker falls back to worse modes. F.4 §1.2
measured the bare exposure: `coef_rate` ON with the skip tie-break OFF collapsed
the 250 kbps point **−6 dB** (26.96 → 20.91 dB). That collapse is the
domain mismatch, not K1.

## 2. Prior art

### 2.1 How libvpx couples picker and emit

libvpx's RT path (`use_nonrd_pick_mode`) makes the picker's skip decision the
one the bitstream emits, *for the whole MB* — and it has **no transform/quant
split** that rvp9 has. Verified in the local tree (`D:\language\libvpx\vp9\
encoder\`):

- `vp9_pick_inter_mode` runs `block_yrd` (`vp9_pickmode.c:2349`) which sets
  `is_skippable` from the **real** quantize (`*skippable &= (*eob == 0)`,
  `block_yrd:804`). `is_skippable` is the **first gate**: if every coefficient
  zeroes, libvpx skips unconditionally and does NOT run the RD tie-break
  (`vp9_pickmode.c:2350-2362`).
- The tie-break, when it runs, sets `x->skip_txfm[0] = SKIP_TXFM_AC_DC` — the
  decision is recorded into block state, restored into the pick context
  (`vp9_encodeframe.c`), and the emit honors `x->skip` and codes **no residual**
  (`vp9_encodemb.c:743-774`). There is no second, independent emit re-decision.

**Two things rvp9 cannot trivially copy:**
1. libvpx's RT emit reuses the **same `quantize_fp`** the picker used
   (`vp9_encodemb.c:591`), so picker-eob == emit-eob *for the whole MB
   including chroma*. rvp9's picker is Y-only + variance-chroma and uses
   DCT/`quantize_b` for recon but Hadamard/`quantize_fp` for the rate proxy
   (`inter.rs:2953-3040`) — three separate quantize outcomes, none matching the
   emit's Y+U+V DCT/`quantize_b` (`inter_forward_quant_one_tx`). So rvp9 *cannot*
   get "by construction" equality without porting chroma transforms into the
   picker (large, out of scope).
2. libvpx records skip into block state and the emit honors it. rvp9's emit
   re-decides from `leaf_total_eob`. We **keep** the emit re-decision
   (`lib.rs:5263`) — it is what keeps the bitstream self-consistent — and make
   the picker *predict* it as well as a Y-only picker can.

### 2.2 Current measured state (the baseline this HLD moves)

Per the 2026-05-27 journal (HEAD 9114d46): drift is **fixed**, RD curves now
overlap libvpx, BD-rate is **+86 % (cpu7) / +95 % (cpu4)** — i.e. ~2× off
libvpx on coding efficiency, no longer "unmeasurable." The keyframe is
near-lossless (53.9 dB); inter PSNR is stable/rising across the GOP. The
remaining gap is *coding-efficiency / mode-decision quality*, which is exactly
what this HLD targets. This is the regression baseline.

### 2.3 STALE-NOTE WARNING — retire the in-tree "K1=4 winning" claim

`inter.rs:2487-2494` carries an **F.4-2 note (2026-05-23)** stating that a sweep
"picked **K1=4** … as the winning SATD-to-prob-cost scale exponent." **This note
is now stale and misleading.** The assessment found:

- K1=4 was landed, then **reverted to K1=2** after the Hadamard port. The *live*
  code uses **K1=2**: `block_yrd.rs:165` shifts `<< (2 + VP9_PROB_COST_SHIFT)`
  and `inter.rs:3093` does the same, with the in-tree comment at `inter.rs:3087`
  explicitly saying *"K1=2 (the libvpx default) is correct."*
- So the code says K1=2 while a neighbouring doc-comment says K1=4 was the
  winner. They contradict. The K1 sweep is a **dead end (~0.1 dB)** — even the
  surviving F.4-2 note admits only "+0.07 dB."

**Action (part of this HLD's landing):** delete/replace the K1=4 narrative at
`inter.rs:2487-2494` and the F.4 §3 K1-sweep framing, and point both at this
HLD's S3 (domain alignment) as the real magnitude lever. Do **not** resurrect a
K1 sweep. (Documentation-only change; no behavior.)

### 2.4 Lambda is faithful — keep it OUT

`cost/rd_mult.rs` (`compute_rd_mult` / `compute_rd_mult_based_on_qindex`) is a
verified line-for-line port of libvpx `vp9_compute_rd_mult_based_on_qindex`
(unit tests at `rd_mult.rs:123-241` pin q0/q128/q255 to hand-derived values).
**Lambda is not a lever here** — touching it is a non-goal (§5).

## 3. Staged design

Three stages, **gated**. S1 is a measurement gate that *decides* the shape of S2
and S3. Nothing in S2/S3 lands until S1's pre-registered numbers are in.

### S1 — Measure first; break the divergence down BY CAUSE (GATE)

**Goal:** quantify the achievable ceiling of the skip fix *before* writing it,
and pre-register a numeric threshold. The prior HLD asserted the fix would drive
the disagreement "97 % → ~0"; that is unprovable a priori given the two holes
(§1.2). S1 replaces the assertion with a measurement.

**Build the qp=70 cross-tab `(picker_skip, emit_code)`** AND decompose the
disagreement cell by cause:

| Cause bucket | Definition (per leaf) | Fixable by | Diag source |
|---|---|---|---|
| **Y-eob-only** | picker Y round-trip eob == 0 **and** emit Y eob == 0, but emit still codes (chroma) — i.e. the *only* reason picker said skip and emit didn't is **not** Y | nothing on Y; this is the chroma/tx residue | compare picker Y-eob vs emit per-plane eob |
| **Chroma-eob-driven** | emit `leaf_total_eob > 0` solely from U/V eob (Y eob == 0) | NOT fixable by a Y-only gate (§1.2a) | `lib.rs` per-plane eob split |
| **Tx-size-range-driven** | picker eob (≤Tx16x16) and emit eob (chosen tx, possibly Tx32x32/Tx4x4) disagree on the same Y residual | NOT fixable without porting tx selection into picker (§1.2b) | log `mrd.tx_size` vs `chosen_luma_tx` |
| **Y-skip-gate-fixable** | picker priced skip but its *own* Y DCT eob > 0 — the leaf the Lever-3a gate actually catches | **S2** | picker branch vs picker Y-eob |

**Instrumentation (reuse, no new heavy tooling):**
- Picker side: the `RVP9_DIAG_EVAL` hook (`inter.rs:2404`) gains a 2-line emit of
  *which branch won* + the picker Y DCT-eob sum (the value S2 will gate on, today
  computed in the round-trip and dropped).
- Emit side: `RVP9_DIAG_PICKER` (`lib.rs:5272`) already prints `leaf_total_eob`
  and final `skip`; extend it to print the **per-plane** eob split (Y / U / V)
  and `chosen_luma_tx`. `skipstat::record_leaf` (`skipstat.rs`, env
  `RVP9_E4_SKIPSTAT`) already aggregates skip/nonskip/eob-sum.

**Pre-registered S1 outputs (fill in from the run; these are the gate):**
- `D_total` = % of leaves where picker_skip ≠ emit_code at qp=70 (prior ~97 %).
- `D_Y` = share of `D_total` attributable to the **Y-skip-gate-fixable** bucket
  (the only part S2 can close).
- `D_chroma`, `D_tx` = the residual S2 *cannot* close.

**S1 gate / threshold (pre-registered):**
- **If `D_Y` ≥ 0.60 · `D_total`** (S2 can close most of the disagreement):
  proceed to S2 as designed.
- **If `D_Y` < 0.60 · `D_total`** (chroma/tx dominate): the Y-only skip gate is
  cosmetic. Escalate to Arthur — either descope S2 to "honest pricing only"
  (keep `coef_rate` in the non-skip branch, drop the skip-gate change) or scope a
  chroma-eob / tx-size follow-up. **Do not ship a skip gate that closes <60 % of
  the gap and call it reconciliation.**
- Separately, S1 records **how often AcDc leaves diverge from the emit** — this
  decides §S2's AcDc resolution (below).

**Cost:** S1 is pure instrumentation + one harness run. ~15 LOC of diag, no
production-path change. This is the cheapest possible de-risking of the whole
plan.

### S2 — Y-only skip reconciliation + AcDc resolution

**Premise (honest):** S2 closes the **Y-luma slice** of the divergence
(`D_Y`). It does **not** make picker-skip == emit-skip; the chroma and tx-size
slices (§1.2) survive and are quantified by S1, not eliminated by S2.

**S2.1 — Gate the picker's skip branch on the picker's own Y DCT-eob.**
The picker already computes the per-tile DCT + `vp9_quantize_b` eob inside
`reconstruct_via_round_trip` (`inter.rs:2953-2980`); today it is used only to
build `recon` and then dropped. The change:

1. Accumulate `sum(eob)` across tiles into the returned `BlockYrdResult` (a new
   `dct_eob_total: u64` field), mirroring the emit's `leaf_total_eob` **for Y**.
2. Make the skip branch require the picker's Y-eob be zero *before* it may
   collapse to skip:

   ```text
   let y_skippable = (dct_eob_total == 0);
   let (final_rate, final_dist) =
       if !y_skippable {
           // Y residual WILL be coded → price the non-skip path honestly.
           (rate.saturating_add(skip_false_cost), dist)   // keeps effective_coef_rate
       } else if rd_encode < rd_skip {
           (rate.saturating_add(skip_false_cost), dist)
       } else {
           (skip_true_cost, sse_after_pred_u32)
       };
   ```

   This is libvpx's `is_skippable`-first-gate (§2.1) restricted to Y. The
   surviving non-skip branch **keeps `effective_coef_rate`** — that is the
   "cost-the-non-skip-path-honestly" half (the old HLD's option C, folded in).

**Why the DCT eob, not `by.skippable`:** the picker holds two Y quantize
outcomes — DCT/`quantize_b` (matches the emit's `inter_forward_quant_one_tx`)
and Hadamard/`quantize_fp` (`by.skippable`, the libvpx rate proxy). Only the
**DCT** path matches the emit's transform+quantizer, so it is the faithful
Y-eob predictor. Key the gate off the DCT eob.

**S2.2 — Resolve AcDc concretely.** The AcDc short-circuit (`inter.rs:2339-2347`)
returns early with `coef_rate=0, coef_dist=0, skippable=true` and **no DCT eob**
(it never runs the round-trip). So S2.1's `dct_eob_total` is undefined for AcDc
leaves. Two options:

- **(i) Run the DCT round-trip even on AcDc leaves**, so the skip gate keys
  uniformly off the real Y eob. **Cost:** the AcDc short-circuit exists to skip
  the expensive forward-DCT + quantize when the variance model is confident the
  residual vanishes; the speed work shows the picker dominates encode time
  (it is the hot path — the journal's cpu7 RT path is ~90 % picker), so removing
  this short-circuit on AcDc leaves adds a full DCT+quantize per such leaf.
- **(ii) Keep AcDc as a model skip**, and accept it as part of the *measured
  Y-only-partial story* — no false "by construction." An AcDc leaf is priced
  skip by the variance model; the emit may still find a coefficient and code it,
  but that is now a **known, S1-quantified** divergence bucket, not a silent one.

**Recommendation — decide from the S1 measurement (pre-registered):**
- If S1 shows AcDc leaves **rarely** diverge from the emit (the variance model is
  a good predictor): choose **(ii)** — keep the speed short-circuit, accept the
  small measured divergence.
- If AcDc leaves **often** diverge: choose **(i)** for the diverging block sizes,
  OR a **minimal skip-propagation** (a single bool from picker→emit *only* for
  AcDc leaves, so the emit honors the picker's AcDc skip and doesn't re-quantize
  — far narrower than full skip plumbing).

Default lean: **(ii)** — AcDc is a confident model call; the journal shows the
variance model is not the dominant error source. But this is a *measured*
decision, not a prediction. (This replaces the old HLD's "drop AcDc-as-skip"
recommendation, which was justified by the now-retracted "by construction"
goal.)

**S2 scope / LOC (honest):**

| Path | Change | Est. LOC |
|---|---|---|
| `block_yrd.rs` (`BlockYrdResult`) | add `dct_eob_total: u64` | ~3 |
| `inter.rs` (`reconstruct_via_round_trip`) | accumulate DCT eob across tiles | ~6 |
| `inter.rs` (`evaluate_candidate`) | gate skip branch on `dct_eob_total==0`; keep `coef_rate` in non-skip branch | ~12 |
| `inter.rs` / `lib.rs` | AcDc resolution per S1 (option ii ≈ 0 LOC; option i ≈ 6; minimal bool ≈ 20) | 0–20 |
| `inter.rs` diag (S1 carry-over) | branch + eob emit under `RVP9_DIAG_EVAL` | ~4 |
| `inter.rs` `#[cfg(test)]` | self-consistency test: nonzero Y DCT eob ⇒ picker non-skip | ~30 |
| **S2 total** | | **~55–75 LOC** |

### S3 — RD-domain alignment (`dist → coef_dist`) + `u64` `rd_cost` widening

**This is the magnitude lever.** Switch the encode-side picker `dist` from
pixel-SSE-of-recon to **coefficient-domain `coef_dist`** so it shares the domain
of `coef_rate`, matching libvpx (`block_error_fp >> 2` paired with the SATD rate
proxy). The picker already computes `coef_dist` (`inter.rs:3039-3040`,
`by_dist += block_error_fp_i32(...) >> 2`) and surfaces it on the result
(`coef_dist: i64`, `inter.rs:352`) but never feeds it to `rd_cost`.

**S3.1 — Prerequisite: widen `dist` through `rd_cost` to `u64`/`i64`.**
`rd_cost(rd_mult: u32, rate: u32, dist: u32) -> i64` (`mode_decision/mod.rs:65`)
takes `dist: u32`. `coef_dist` is an `i64` accumulator that, at low q with large
qcoeffs, **saturates `u32::MAX`** — this is exactly why F4 stalled
(`coef_dist`-as-`dist` clipped, killing the signal, the mirror of the `coef_rate`
`u64` widening already done at `block_yrd.rs:165` / the night-8 fix). Design:

```text
// mode_decision/mod.rs
pub fn rd_cost(rd_mult: u32, rate: u32, dist: u64) -> i64 {
    let r_rm     = (rate as i64).saturating_mul(rd_mult as i64);
    let rate_term = (r_rm + (1 << (VP9_PROB_COST_SHIFT - 1))) >> VP9_PROB_COST_SHIFT;
    let dist_term = (dist as i64).saturating_shl(RDDIV_BITS); // saturating: dist<<7 must not wrap i64
    rate_term + dist_term
}
```

- Signature change `dist: u32 → dist: u64`. Every caller passes a `u32` today
  (`dist`, `sse_after_pred_u32`, `final_dist`) — they widen for free (`as u64`).
  `choose_inter_luma_tx_size`'s local `rdcost` closure (`lib.rs:6250`) already
  uses `i64` dist; align it the same way for consistency (it does not call the
  shared `rd_cost`, so it is independent, but should match the domain).
- `dist_term` must **saturate** the `<< 7`: a saturated `coef_dist` near
  `i64::MAX >> 7` shifted left 7 would wrap. Use `saturating_shl` / explicit
  clamp. (This is the bug that bites if you naively widen the type without
  re-checking the shift — call it out in the LOW-LEVEL note for the implementer.)

**S3.2 — Feed `coef_dist` to the encode side; rescale the skip side.**
- Encode branch: `rd_encode = rd_cost(lambda, rate, coef_dist_as_u64)` — rate and
  dist now both coefficient-domain.
- Skip branch (`rd_skip`): libvpx compares `RDCOST(rate, coef_dist)` against
  `RDCOST(0, sse_pred << 4)` — the skip side stays a **pixel** SSE but rescaled
  `<< 4` to sit in the coef-dist domain (libvpx `vp9_pickmode.c` skip tie-break;
  flagged in F.4 §1.2 follow-up). So: `rd_skip = rd_cost(lambda, 0,
  (sse_after_pred as u64) << 4)`. The exact rescale (`<< 4`) is pre-registered
  but **A/B-confirmed in S3's sweep** — if the cross-tab/PSNR says a different
  shift matches libvpx, adopt the measured one (F.0.1 discipline).
- `final_dist` for the chosen branch follows the same domain so `best_rd_cost`
  is internally consistent. Note `best_distortion` is surfaced to the F.0.2
  oracle — document the domain change so the oracle's downstream readers are not
  silently misinterpreted.

**S3 scope / LOC (honest):**

| Path | Change | Est. LOC |
|---|---|---|
| `mode_decision/mod.rs` (`rd_cost`) | widen `dist: u32 → u64`; saturating `<<7` | ~6 |
| all `rd_cost` callers | `as u64` at call sites (mechanical) | ~10 |
| `inter.rs` (`evaluate_candidate`) | `rd_encode` uses `coef_dist`; `rd_skip` uses `sse<<4`; set `final_dist` domain | ~12 |
| `inter.rs` / oracle | document `best_distortion` domain change | ~3 |

## 4. Sequencing honesty — S2 and S3 probably must co-land

**The skip fix ALONE, at the current domain mismatch, LIKELY regresses.**

Mechanism: today the skip branch discards `coef_rate` on ~97 % of leaves
(§1.1), so the domain mismatch (§1.3) is **masked** — the mis-domained
`coef_rate` rarely reaches mode RD. S2 *un-masks* it: the ~97 % of leaves that
code residual now carry `effective_coef_rate` (coef-domain rate) against
pixel-SSE `dist` into mode ranking. That is precisely the F4 §1.2 configuration
(`coef_rate` ON, tie-break OFF) that collapsed 250 kbps by **−6 dB**. So S2 in
isolation reproduces a controlled slice of that collapse.

**Pre-registered plan:** **co-land S2 + S3 as the PRIMARY plan.** S2 is the
mechanism (honest skip + honest non-skip pricing); S3 is the calibration (same
domain so the honest pricing ranks modes like libvpx). F.4 already proved
neither works alone (K1 sweep on the mismatched domain bought ~0.07 dB; bare
`coef_rate` collapsed −6 dB).

**S1 decides whether they *must* land together:**
- If S1 + a quick S2-only A/B shows S2 alone moves foreman PSNR-delta in the
  **right** direction (ZEROMV% drops, NEWMV/NEARESTMV rises, PSNR not worse):
  land S2, set the new threshold by measurement, then S3 on top.
- If S2 alone **regresses** (the F4 −6 dB pattern): co-land S2+S3 in one PR.
  **Do not abandon S2** — it is the mechanism; S3 is the calibration.

**Honest ceiling:** S2 buys the *direction* (mode-mix shift); S3 buys the
*magnitude* (domain-correct RD ranking). Neither is expected to fully close the
remaining BD-rate +86–95 % (§2.2) alone — they target the inter mode-decision
component of it. The intra/keyframe gap and other Track-F levers are separate.

**Kept OUT (verified faithful / self-consistent — non-goals):**
`compute_rd_mult`/lambda (§2.4); the emit's `lib.rs:5263` override (it is what
keeps the bitstream self-consistent and stays a no-op-tightening for Y).

- **No K1 sweep, no K1 change.** Dead end (~0.1 dB). The stale K1=4 note is

- **No change to the emit's `leaf_total_eob == 0` override** (`lib.rs:5263`). It

- **No intra-path skip changes; no new SIMD; no Hadamard re-port** (DV-F1-1 is a

## 9. Executive summary

1. **The old "picker-skip == emit-skip by construction" claim is false and is
   retired.** The picker's skip round-trip is **Y-only**; the emit's
   `leaf_total_eob` is **Y+U+V** (`lib.rs:4970`), and the picker runs at a tx
   size **capped Tx16x16** while the emit walks **Tx4x4..Tx32x32**
   (`lib.rs:6260`). The skip fix closes only the **Y-luma slice**. None of this
   breaks the bitstream — `lib.rs:5263` keeps it self-consistent and
   `cross_decoder_gate` stays 4/4; it is a quality-optimality limit, not a
   correctness bug.

2. **Measurement is the first stage and the gate (S1).** Build the qp=70
   picker-skip/emit-code cross-tab and decompose the ~97 % divergence **by
   cause** (Y-eob-fixable vs chroma-eob vs tx-size-range). A pre-registered
   threshold (`D_Y ≥ 0.60·D_total`) decides whether the Y-only skip fix is worth
   shipping; S1 also sizes AcDc divergence to choose its resolution.

3. **Lever 3a and 3b are one fix.** S2 (honest skip + honest non-skip pricing)
   *un-masks* the rate/distortion **domain mismatch** (DV-F1-3: coef-domain
   `coef_rate` vs pixel-SSE `dist`, `inter.rs:2378`) on ~97 % of leaves — the
   same exposure that collapsed 250 kbps −6 dB in F4. S3 fixes it by switching
   the encode `dist` to **`coef_dist`** with the skip-side `sse<<4` rescale, plus
   the prerequisite **`u64` `rd_cost` widening** that has stalled this twice.
   K1 is a dead end and the in-tree "K1=4 winning" note (`inter.rs:2487-2494`) is
   **stale** and retired; lambda is verified faithful and stays out.

4. **Co-land S2+S3 as the primary plan.** S2 alone, at the current domain
   mismatch, **likely regresses** (the F4 −6 dB pattern). S2 buys the *direction*
   (ZEROMV% drops); S3 buys the *magnitude*. S1 decides whether they *must* ship
   together. ~110–130 LOC total, all reversible single commits; the emit and
   byte-exact tests are untouched.

5. **Oracles:** cross-tab by cause (re-run after each stage), ZEROMV%/mode-mix,
   matched-byte PSNR / BD-rate on the 2026-05-27 regression harness,
   `cross_decoder_gate` 4/4, byte-exact emitter tests green, a Y-slice
   self-consistency unit test, and a `rd_cost`-widening unit test pinning the
   un-saturated path to the old `u32` result.

**Single biggest open question for the lead:** **Do we accept the chroma-eob and
tx-size holes as permanently measured-but-unclosed divergence (S2 ships as a
Y-only reconciliation), or does the S1 cross-tab obligate a follow-up that ports
chroma transforms / tx-size selection into the picker?** The honest position is
that S2+S3 fix the Y-luma + domain components of the inter mode-decision gap, but
if S1 shows chroma/tx dominate the ~97 % (`D_Y < 0.60·D_total`), the skip fix is
cosmetic and the real work is a larger picker/emit unification that this HLD
deliberately scopes out — that is a strategy call only the lead should make
before S2 is written.

### RVP9-BUG-KIL-00080 — decoder scratch scales with tiles, not workers

The decoder's parallel gate allows one tile row, multiple columns, and more than one thread. It then asks `Yv12ScratchPool` for `buffers.len()` full-frame allocations. Valid tile parsing permits up to 64 columns on this path. Two active workers can therefore cause 64 buffers to be allocated and retained. The core type itself estimates about 3 MiB per 1080p scratch, making the valid 64-column case about 192 MiB before other per-tile state. Larger supported frames amplify this further. Allocation failure is converted to a panic by `.expect("scratch Yv12Buffer allocation")`.

This is distinct from RVP9-BUG-KILN-00070. That Open bug covers a separate encoder allocation in `rvp9-encoder`; RVP9-BUG-KIL-00080 covers the decoder and the core scratch-pool contract.

### RVP9-BUG-KILN-00020 — the previous AVX2 safety fix is incomplete

RVP9-BUG-KILN-00020 is currently Fixed, not Closed. Its repair validates the V predictor, and `dsp::x86_64` is now crate-private. That does not make the public `SimdDispatch` function-pointer accessors unsafe. A safe caller on an AVX2 host can still pass an invalid block size or undersized destination to D45/D117 and reach raw stores after checks compiled only as `debug_assert!`. The sampled vertical-convolution wrapper has the same release boundary.

This pass does not mint a competing bug because the defect is the unresolved scope of RVP9-BUG-KILN-00020. Its verifier should reopen it and require a family-wide audit. Only the cited wrappers are confirmed here; claiming every SIMD wrapper has the defect would exceed the evidence.

### RVP9-BUG-KIL-00078 — tile-info writer returns `Ok` after invalid input

For columns below the computed minimum, the release writer silently emits the minimum representation. For columns above the maximum, it emits excess increment bits that consume positions intended for later fields. Any row value above 2 is silently encoded as 2. The helper returns `Result`, and sibling tile-buffer helpers already return typed geometry errors, so fail-loud validation is the established contract.

This is not a duplicate of closed RVP9-BUG-KILN-00023. That record covered tile payload-buffer dimensions and counts, not header tile-info syntax.

### RVP9-BUG-KIL-00077 — larger inverse transforms skip acceleration

`reconstruct_via_round_trip` obtains the dispatch table and uses it for 8x8, but its adjacent 16x16 and 32x32 branches import and invoke scalar transforms directly. The dispatch table selects SSE2 for 16x16 and AVX2 for 32x32 when available. The bypass is therefore source-confirmed. The actual encoder slowdown is unverified because this pass correctly ran no benchmark.

### RVP9-BUG-KIL-00079 — public scaling constructor panics on zero axes

All four ratio inequalities in `valid_ref_frame_size(0, 0, 0, 0)` are true. The constructor proceeds to divide by the zero current dimensions. Valid VP9 headers cannot carry zero dimensions, so this is a public safe-API defect rather than a confirmed malformed-stream decoder crash.

## Confirmed quality debt — report only

- **Loop-filter skip test cannot distinguish the behavior it names.** `crates/rvp9-core/src/loopfilter/apply.rs:3213-3265` uses a flat U plane and admits that unchanged output can mean either short-circuit or filter-no-op. Put a step on the internal 4x4 edge; prove `skip_this = true` preserves it and `false` changes it. Confidence high; effort medium.
- **Two border tests prove only that the call returns.** `loopfilter/apply.rs:3367-3420` and `:3851-3891` snapshot output without a behavioral assertion. Use one protected final edge and one earlier edge that must filter. Confidence high; effort medium.
- **The overlap-named partition test reaches a different condition.** `crates/rvp9-core/src/mode_decision/partition.rs:3242-3294` says the `visited` branch is unreachable with its representation, then supplies an inconsistent footprint already covered elsewhere. Rename it or construct a real overlap oracle. Confidence high; effort small to medium.
- **AArch64 directional dispatch lacks a routing oracle.** `crates/rvp9-core/src/dsp/dispatch.rs:1575-1627,4092-4210` installs six scalar slots on AArch64, while the relevant routing tests are x86-only. Add an AArch64 scalar-reference matrix for D45/D63/D207/D117/D135/D153 at block sizes 4, 8, 16, and 32. Confidence high; effort medium.
- **Count and emit duplicate the inter partition traversal.** `crates/rvp9-core/src/bitstream/modes_writer.rs:2199-2954` maintains parallel recursive walkers. No current branch mismatch was found, so this stays below the bug and requirement bars. A shared event traversal would reduce future drift risk. Confidence high; effort large.

No Draft requirement was created. The test gaps are concrete but belong with future fixes or ordinary test work; the traversal and loop-filter structure need an architectural decision before they are requirement-ready.

## Unverified — not promoted

- A full audit of every x86_64 and AArch64 raw-pointer dispatch wrapper was not completed. D45, D117, and vertical convolution are confirmed samples; other wrappers are `needs_reverify`, not implied passes or failures.
- `from_tight_yuv420_with_sb_tail` at `loopfilter/apply.rs:134-146` has no direct core boundary test. The absence is confirmed, but no out-of-bounds behavior was demonstrated.

## Not reported — refuted, duplicate, or by design

- **Loop-filter `filter16` q7 weights are not reversed.** The proposed error at `crates/rvp9-core/src/loopfilter.rs:801-811` was refuted against the endpoint-accumulation sequence in the [official libvpx loop-filter source](https://chromium.googlesource.com/webm/libvpx/%2B/refs/heads/main/vpx_dsp/x86/loopfilter_avx2.c). The increasing q7 multiplier is intentional.
- **`DecoderFramePool::assign_slot` / `release_slot` do not expose a shipped decoder corruption path.** `crates/rvp9-core/src/frame.rs:1558-1585` can violate logical counts if misused directly, but RVP9-BUG-KILN-00030 already removed the decoder's public mutable-pool accessor; surviving decoder callers are tests. The core type documents that callers own the paired ref-map invariant.
- **`Yv12ScratchPool::put` heterogeneous input is outside its stated lifecycle.** `frame.rs:1103-1117` checks only a representative buffer, but its contract is to return buffers previously obtained from the same homogeneous `take`; both shipped decoder call sites do that. No product trigger was shown.
- **`SharedFrame` does not create safe-code UB by itself.** `loopfilter/apply.rs:68-225` cannot express its backing lifetime, but the methods that reconstruct mutable slices are `unsafe` and document the liveness/exclusivity obligations. This is hazardous structure, not a demonstrated safe-API defect.
- **The loop-filter worker count of one is explicit current design.** `loopfilter/apply.rs:406-509` carries parallel-looking state but asserts serial ownership to preserve plane alias safety. No incorrect output or deadlock follows from the current setting.
- **Superframe slicing is bounded before use.** The suspected size omission in `bitstream/superframe.rs:75-129` is checked by the decoder before slicing at `crates/rvp9-decoder/src/lib.rs:1085-1100`.
- **The one-gibipixel frame cap is policy, not a newly demonstrated bug.** `frame.rs:168-169,244` deliberately enforces that bound. Memory amplification from per-tile duplication is instead tracked precisely as RVP9-BUG-KIL-00080.
- **No present count/write walker mismatch was found.** The duplication remains report-only maintainability debt.

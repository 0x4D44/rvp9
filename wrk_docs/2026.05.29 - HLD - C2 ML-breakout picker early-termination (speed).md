> **One-line thesis.** The per-candidate mode evaluation is the picker's irreducible cost. C2 makes it
> cheaper by **early-terminating** candidate evaluation once a mode is decisively good — using
> mechanisms that are **already ported into rvp9 but partly dormant**. The cheapest, lowest-risk win is
> to **wire the `handle_inter_mode_single_ref` RD-breakout that is currently hardcoded off** in the
> speed≤4 RDO path, and (for the cpu7 RT path) to **enable the already-wired ML partition-search
> breakout that the RT preset leaves inert**. Decision-changing ⇒ quality-gated, NOT byte-identical.

---

## 1. Problem

### 1.1 The deep cause (measured, given — not re-litigated)

rvp9 is ~18× slower than vpxenc (cpu7 RT). 96 % of inter time is the picker. Phase-1 SIMD +
Phase-2-A cache-reuse give cumulatively ~1.3–1.4×. The deep cause is structural: **rvp9's picker does
far MORE work per block than libvpx's RT picker.** libvpx cpu7 uses `VAR_BASED_PARTITION` + a single
cheap mode pass with aggressive early-outs; rvp9 runs a recursive RD descent (Phase-2-A now reuses its
leaf picks) plus a per-candidate mode evaluation that is much heavier than libvpx's model-RD pass.

The Phase-2 HLD measured that **disabling the RD descent costs −1.0…−1.3 dB** (the descent earns its
quality). So the lever is NOT removing the descent — it is **making the per-candidate mode evaluation
cheaper via early-termination**, which is exactly C2.

### 1.2 There are TWO inter pickers, on TWO speed paths (code-verified)

This is the load-bearing structural fact for C2. `pick_and_simulate_inter_encode_partitions`
(`crates/rvp9-encoder/src/lib.rs:2374`) routes the per-leaf mode decision two ways, gated by
`rdo_speed_gated = speed.unsigned_abs() <= 4` (`lib.rs:2602`):

| Speed | Path | Entry | Per-candidate cost |
|---|---|---|---|
| **≤ 4** (RDO) | `rdo_unified` (`lib.rs:4179-4182`) → `pick_inter_sb_leaf` → `handle_inter_mode_single_ref` | `inter_dispatch.rs:475` / `handle_inter.rs:378` | **3 switchable filters × full `super_block_yrd`** (forward-quant + recon round-trip + chroma RD) per `(mode, ref)` |
| **≥ 5** (RT, **incl. cpu7 target**) | RT picker `pick_inter_mode` (`None` arm, `lib.rs:4576`) | `crates/rvp9-core/src/mode_decision/inter.rs:509`+ | model-RD + per-block filter search; **breakout/early-term already active** (§2.1) |

**The two paths have very different early-termination status today**, so C2's lever differs by path. The
brief's stated target speed is **cpu7 ⇒ the RT path**; the RDO path matters because Phase-2-A and
S2/Lever-3b both touch it and the brief explicitly asks about it.

### 1.3 What the picker spends per candidate, and where the cut is

The picker iterates `{ZEROMV, NEARESTMV, NEARMV, NEWMV} × {LAST, GOLDEN[, ALTREF]}` ≈ 8–12 candidates.
For each it builds a real inter prediction and prices the residual. **Early-termination wins by not
evaluating later candidates (or later transform sizes/filters) once a mode is provably good enough.**
Three libvpx mechanisms do this; all three are partly present in rvp9 (§2):

1. **`encode_breakout`** — if a mode's prediction SSE/variance is below a quant-derived threshold, the
   block is "good enough": skip residual coding AND break the mode loop.
2. **`early_term`** — if the large-block model-RD detects a full AC+DC skip, exit the mode loop after ≥2
   candidates.
3. **RD-threshold mode-skipping** (`rd_less_than_thresh` / `ref_best_rd` breakout) — skip a candidate
   whose historical/running RD makes it unlikely to win, or bail a candidate's residual evaluation once
   its partial RD exceeds the running best.

## 2. Prior art — what ML / early-termination infra ALREADY exists in rvp9

This is the most important section: **most of C2 is already ported.** The gap is wiring/activation, not
porting. Verified by reading the cited files.

### 2.1 RT picker (`inter.rs`) — breakout/early-term ALREADY WIRED AND ACTIVE

`pick_inter_mode` in `crates/rvp9-core/src/mode_decision/inter.rs` has all three libvpx mechanisms
ported and live on the cpu7 path:

- **`encode_breakout` test (G4)** — `inter.rs:1794-1825`, model in
  `mode_decision/model_rd.rs:524` (`encode_breakout_test`, port of `vp9_pickmode.c:933-1036`). After a
  new best, if `var_y <= thresh_ac && (sse_y - var_y) <= thresh_dc` it **breaks the mode loop**.
  Gated by `params.encode_breakout > 0 && !scene_change_detected`. **The encoder sets
  `encode_breakout: 20`** on both call sites (`lib.rs:3344`, `lib.rs:4447`) — the libvpx RT default.
  **ACTIVE.**
- **`early_term` mode-loop exit (G6)** — `inter.rs:1827-1841`, set when the large model detects an AcDc
  full skip on a block ≥ 32×32 (`inter.rs:2961-2963`, `early_term` field `inter.rs:489`). Breaks after
  ≥2 candidates. Port of `vp9_pickmode.c:2474-2478`. **ACTIVE.**
- **Adaptive RD-threshold gate (P20)** — `inter.rs:1601-1637`. When a `rd_thresh_table` is attached,
  skips a candidate whose running best RD is below the per-`(bsize, ref, mode)` effective threshold
  (with the GOLDEN bias `<<3`). Port of `vp9_pickmode.c:2241-2247`. The encoder threads a **live**
  `RdThreshTable` and mutates it post-pick (`lib.rs:4477`, update at `:4485`). `rd_thresh` module:
  `crates/rvp9-core/src/mode_decision/rd_thresh.rs`. **ACTIVE on the RT path** (the descent passes
  `rd_thresh_table: None`, `lib.rs:3370`, by design).

**So on the cpu7 RT path the per-candidate breakout/early-term/rd-thresh trio is already on.** The
incremental per-candidate lever left in the RT path is therefore NOT these three — it is the
**partition-level ML breakout** (next bullet), which the RT preset leaves inert.

### 2.2 ML partition breakout — PORTED, WIRED to the descent, but INERT at cpu7

The full libvpx ML-partition family is ported into `crates/rvp9-encoder/src/ml_partition/` (a faithful
transcription per AUDIT A21, which originally found it absent — it has since landed):

- `nn_predict.rs` — generic MLP forward pass + all 13 NN configs + linear LUTs (`vp9_partition_models.h`).
- `pruners.rs` — `ml_predict_breakout` (linear, `vp9_encodeframe.c:3248-3329`), `ml_pruning_partition`
  (`:3157-3245`), `ml_prune_rect_partition` (`:3332-3427`).
- `var_partition.rs` — `simple_motion_search` + `ml_predict_var_rd_partitioning` (`:3489-3618`).

These are **wired into the partition-shape descent**, NOT the per-candidate mode loop. The breakout
hook lives at `lib.rs:3441-3534`: after the descent's NONE pick wins at a block, the real NN breakout
model votes and, when positive, forces `do_split = 0` to suppress that block's SPLIT recursion
(counter `ML_PARTITION_BREAKOUT_FIRED`, `inter_dispatch.rs:157`; rect pruner
`ML_PARTITION_RECT_PRUNED`, `:174`). Gated by `sf.rd_ml_partition.search_breakout && base_qindex >= 100`
(`lib.rs:3455`).

**The catch (code-verified):** `RdMlPartition::defaults()` sets `search_breakout: false` and
`prune_rect_thresh: [-1,-1,-1,-1]` (`speed_features.rs:112-114`). The **GOOD-quality setters enable it
at speed 0/1** (`speed_features.rs:295-338`; test `a21_rd_ml_partition_breakout_gate` confirms speed
0/1 on, speed 3 off), but the **RT preset (cpu5-8) leaves it inert** (test
`a21_rd_ml_partition_rect_prune_thresh_gate` confirms `rt7` → `[-1,-1,-1,-1]`). **So at the cpu7 target,
the ML partition breakout is dormant.** This is the Phase-2-HLD "(C2)" lever: it attacks the *descent's
own interior shape-ranking picks* — the part Phase-2-A's cache-reuse cannot touch.

### 2.3 RDO-path per-candidate breakout — PORTED into `handle_inter`, but HARDCODED OFF

`handle_inter_mode_single_ref` (`crates/rvp9-encoder/src/rdo/handle_inter.rs:378`) accepts
`ref_best_rd: i64` and `use_rd_breakout: bool` (`:286-289`), and ports libvpx's
`build_inter_pred_model_rd_earlyterm` (`vp9_rdopt.c:165-282`) at `handle_inter.rs:150-220`: when
`do_earlyterm` and `RDCOST(model_rate, model_dist) >= best_rd`, it sets `early_terminated = true`
(`:207-211`; `PredModelRdResult.early_terminated`, `:113`; test
`pred_model_early_terminates_when_over_best_rd`, `:1510`).

**But the dispatch hardcodes the lever off.** `make_handle_params` (`inter_dispatch.rs:429`) sets
`use_rd_breakout: false` and `ref_best_rd: i64::MAX` (`:452-453`) for **every** candidate. And the
driver `pick_inter_mode_sb` (`pick_inter_sb.rs:210`) tracks a running `best_rd` (`:211, :274-277`) but
the runner closure signature is `(InterMode, Mv, u32, u32)` (`HandleInterRunner`, `:130-132`) — **it
has no parameter to thread `best_rd` down into `handle_inter_mode_single_ref`.** So the early-term path
exists, is unit-tested, and is **structurally unreachable from the encoder hot path.** This is the
single cleanest dormant lever C2 can light up.

### 2.4 libvpx's RT early-termination (what we are matching)

From `vp9/encoder/vp9_pickmode.c` (`vp9_pick_inter_mode`, the cpu≥5 RT picker):
- **`rd_thresh` mode-skipping** (`vp9_pickmode.c:2241-2247`): `if (rd_less_than_thresh(best_rdc.rdcost,
  mode_rd_thresh, …)) { … continue; }` — skip the candidate, with the zero-MV exemption and the
  `mode_rd_thresh <<= 3` GOLDEN bias. **rvp9 = ported & active (§2.1, P20).**
- **`x->encode_breakout` SSE breakout** (`vp9_pickmode.c:933-1036`, called `:2415`): the
  `encode_breakout_test` short-circuit. **rvp9 = ported & active (§2.1, G4).**
- **`early_term`** (`vp9_pickmode.c:560-603`, exit `:2474-2478`): model-RD AcDc skip exit. **rvp9 =
  ported & active (§2.1, G6).**
- **ML partition models** (`vp9_encodeframe.c:3108-3620`): the partition-shape pruners. **rvp9 =
  ported & wired to the descent, but INERT at cpu7 (§2.2).**
- **`nonrd_use_partition` one-shot pass** (`vp9_encodeframe.c:5317-5424`): pick once, emit
  immediately, no recursive RD. **rvp9 = NOT adopted** (this is the structural-ceiling item, §7).

**Summary of what rvp9 is missing vs libvpx-RT:** not the per-candidate breakout trio (present & active
on the RT path) — but (a) the **RDO-path** `handle_inter` breakout is unreachable (§2.3), (b) the **ML
partition breakout is inert at cpu7** (§2.2), and (c) the **whole one-shot RT picker architecture** is
absent (§7, the real 18× gap).

## 3. Design options

All options are **decision-changing** (an early-out can change which mode wins) ⇒ quality-gated (§4),
not byte-identity. Listed lowest-risk-first.

### 3.1 (C2-α) — Thread the running best RD into the RDO-path `handle_inter` breakout (RECOMMENDED FIRST)

**Change.** Light up the already-ported, already-unit-tested early-term in `handle_inter_mode_single_ref`
for the speed≤4 RDO path:
- Widen `HandleInterRunner` (`pick_inter_sb.rs:130`) to pass the driver's running `best_rd` (and a
  `use_rd_breakout` flag) into the closure — a 5th/6th argument, OR thread it via a small struct.
- In `make_handle_params` (`inter_dispatch.rs:429`) set `ref_best_rd = running_best` and
  `use_rd_breakout = true` (replacing the hardcoded `i64::MAX`/`false`).
- The driver already evaluates candidates in a fixed order (`INTER_MODE_ORDER`) and tracks `best_rd`
  (`pick_inter_sb.rs:274`); pass it down so a candidate whose **model-RD lower bound** already exceeds
  the running best skips its full `super_block_yrd` (the expensive part — forward-quant + recon + chroma).

**ROI.** This skips the dominant per-candidate cost (the 3-filter × full transform RD) for candidates
that cannot win. libvpx's `handle_inter_mode` does exactly this (`vp9_rdopt.c` `ref_best_rd` plumbing).
The mechanism is local, tested, and reversible.

**Risk.** LOW-MEDIUM. The model-RD lower bound must be a true lower bound (libvpx's is conservative —
it uses the model rate/dist BEFORE the real transform, which is ≤ the real RD in the regimes where it
fires). A too-aggressive bound could skip the true winner ⇒ quality loss. Mitigation: it is a
*candidate-evaluation* skip, not a *mode* skip — the running best is always retained; only worse
candidates are cut. The gate (§4) measures any quality movement.

**Scope note.** This only helps **speed ≤ 4** (the RDO path). At cpu7 (RT path) this code isn't
reached. So C2-α is the right first step ONLY IF speed≤4 is a measured operating point we care about
(it is — S2/Lever-3b and Phase-2-A both touch `rdo_unified`, and the brief asks about it). For the cpu7
headline, pair with C2-β.

### 3.2 (C2-β) — Enable the inert ML partition breakout at cpu7 (RT path)

**Change.** Make `sf.rd_ml_partition.search_breakout` (and optionally `prune_rect_thresh`) reachable at
the RT speeds, behind an env gate first, then a tuned preset value:
- Add an RT-preset write in the speed-feature setter (the inert path, `speed_features.rs` RT branch) so
  `search_breakout = true` with a cpu7-tuned `search_breakout_thresh` (libvpx's RT presets keep it off,
  so we are deviating — the threshold needs tuning, §4). Gate the experiment with an env var (e.g.
  `RVP9_C2_ML_BREAKOUT=1`) so it is OFF by default until the gate passes.
- The hook is already in place (`lib.rs:3441-3534`); flipping the gate makes it fire.

**ROI.** Attacks the **descent's own interior shape-ranking picks** — the cost Phase-2-A's cache-reuse
explicitly cannot recover (Phase-2 HLD §4.4 names this the "irreducible interior shape-ranking cost").
This is the natural stack on Phase-2-A.

**Risk.** MEDIUM. The breakout suppresses SPLIT recursion when NONE is decisively best; an over-eager
threshold under-splits high-motion content (the inverse of the variance-hint over-split the descent was
added to fix). The libvpx RT presets keep this OFF, so we have **no upstream tuning to inherit** — the
threshold is ours to find. This is the single largest tuning risk in C2.

### 3.3 (C2-γ) — Per-candidate `rd_thresh` table on the RDO path

**Change.** Port the RT path's adaptive `rd_thresh_table` gate (§2.1, P20) into the RDO driver
(`pick_inter_mode_sb`) so the speed≤4 path also skips historically-unlikely candidate modes.

**ROI.** Lower than C2-α (the RDO driver evaluates ≤12 candidates; the threshold gate skips a fraction,
each skip saving one `handle_inter` call). Real but smaller; mostly subsumed by C2-α (which skips the
expensive *part* of every losing candidate, not just the historically-unlikely ones).

**Risk.** MEDIUM. The `rd_thresh_table` is a *stateful, frame-adapted* structure; threading it through
the RDO descent + final pass without coupling descent decisions to post-pick state is the same hazard
Phase-2-A flagged (the descent deliberately passes `rd_thresh_table: None`). More plumbing than C2-α
for less win.

### 3.4 Recommendation

**Land (C2-α) first** — it lights up a ported, tested, hardcoded-off mechanism with the least plumbing
and the cleanest revert, and it is the per-candidate cut the brief is really asking for. **Then layer
(C2-β)** for the cpu7 headline (the RT-path partition breakout), behind an env gate, tuning the
threshold against the §4 corpora. **Defer (C2-γ)** — mostly subsumed by C2-α and carries the
stateful-table hazard for little marginal win.

This ordering also matches the strategic reality: C2-α/β are **incremental** levers worth ~1.5–2×
cumulatively (§7); the real 18× requires the architecture port (§7), which is out of scope here.

## 4. Quality oracle + test plan (pre-registered, before any code)

C2 is decision-changing ⇒ the gate is **matched-bitrate Y-PSNR** on TWO corpora plus the conformance
gates, NOT byte-identity. Mirrors the Phase-2-A gate (§4 of that HLD) so the two stack cleanly.

### 4.1 Primary oracle — matched-bitrate Y-PSNR, two corpora

Reuse `scripts/agent_psnr_sweep.py` (rvp9enc → vpxdec → per-frame Y-PSNR) and the in-tree
`quality_gate` test (`crates/rvp9-encoder/tests/quality_gate.rs`, `--ignored`):
- **foreman** `tests/corpus/foreman_320x256_60f.y4m` (320×256, multiple-of-64 — the Phase-2-A corpus)
  and `foreman_cif` 256×256 centre-crop (`quality_gate_stage4a_realcontent`, the headline Track-F gate).
- **testsrc** — the raw `testsrc_720p30.y4m` is 1280×720; **720 is NOT a multiple of 64 ⇒ the Stage-4a
  encoder rejects it** (verified in the Phase-2-A HLD §4.1). Use the **256×256 centre-crop** the
  existing `quality_gate_stage4a` test already uses (`read_cropped`), matching the brief's testsrc intent.

Bitrates: 400k, 1200k (foreman); the gate's 250–2000k range (testsrc crop). Speeds: **cpu7** (the
target — exercises C2-β) AND **cpu4** (the RDO path — exercises C2-α, since it touches `rdo_unified`).

**Baseline (must re-measure on the post-Phase-2-A binary before C2 — DO NOT reuse the pre-Phase-2-A
numbers).** The Phase-2-A HLD measured the *pre*-Phase-2-A descent-ON foreman cpu7 baseline at 33.392 dB
@ 400k / 38.657 dB @ 1200k. **C2 must baseline against the binary with Phase-2-A landed**, because
Phase-2-A is decision-changing too (≤0.1 dB by its own gate, but non-zero). Re-run the baseline as step 0.

### 4.2 Pass criteria (pre-registered)

- **Quality:** matched-bitrate mean Y-PSNR regression **≤ 0.1 dB on foreman AND on the testsrc-crop**,
  at every measured bitrate, vs the post-Phase-2-A baseline (§4.1). C2-α (candidate-eval skip that
  retains the running best) is expected ≈0.00 dB; C2-β (partition breakout) carries the real tuning
  risk and is the one most likely to consume the tolerance.
- **Speed:** **≥ 1.3× foreman cpu7 fps for ≤ 0.1 dB quality cost on BOTH clips** is the headline pass
  bar (the brief's bar). Report fps + ratio-vs-vpxenc, best-of-3 wall-clock, release build. C2-α alone
  helps the RDO path (cpu4); the cpu7 ≥1.3× needs C2-β. If C2-β cannot reach ≥1.3× within 0.1 dB,
  report the achieved (speed, dB) pair and let the lead set the trade.
- **Conformance (MUST hold):**
  - **`cross_decoder_gate`** (`crates/rvp9-encoder/tests/cross_decoder_gate.rs`, `--ignored`) **stays
    4/4** — rvp9-decoder vs vpxdec/ffmpeg byte-exact across its scenarios. An early-out that changes the
    *emitted* mode/MV must still decode identically through both decoders.
  - **`decode_failed == 0`** — every post-change fixture decodes cleanly through `vpxdec` AND
    `rvp9-decoder` (exit 0, pixel counts match).
- **Regression guards green:** `quality_gate` (both stage4a tests), `realtime_gate` (median frame-time
  ≤ 33 ms budget — C2 should *improve* this), `w_ml_partition` / `w_ml_rect_prune` (the ML-breakout
  PROOF tests — C2-β must not break the model wiring), `w_rd_partition` / `w_rd_partition_rect` (the
  descent PROOF tests), `cargo test -p rvp9-encoder --lib`, `cargo test -p rvp9-core --lib`.

### 4.3 Positive controls — the early-out actually fired (anti-G3)

Each lever needs a witness that it did real work, mirroring the in-tree anti-G3 discipline
(`ML_PARTITION_BREAKOUT_FIRED`, `RD_PARTITION_RESHAPED_SBS`, `PHASE2_NEWMV_REUSED`):
- **C2-α:** a per-frame counter of `handle_inter` calls **skipped by the breakout** (bump when
  `early_terminated` would-have-fired path is taken). Target: > 0 on real content; a change claiming
  C2-α but leaving it at 0 is a no-op masquerade.
- **C2-β:** `ML_PARTITION_BREAKOUT_FIRED` (`inter_dispatch.rs:157`) advances when enabled and stays 0
  when the gate is off — already exists; reuse it as the C2-β witness.
- **Total picker / `super_block_yrd` invocations per frame must drop** measurably with C2 on. Report
  the before/after counts alongside fps so the speed win is attributed to fewer evaluations, not noise.

### 4.4 Attribution

Run each lever in isolation (C2-α only at cpu4; C2-β only at cpu7) and combined, so the (speed, dB)
contribution of each is separable. Re-run the Phase-2-A `RVP9_A4_RD_PARTITION_DISABLE` A/B with C2-β on
to confirm C2-β shrank the descent's interior cost (the Phase-2-A §4.4 budget).

## 5. Risks + rollback

| ID | Risk | Likelihood | Severity | Mitigation |
|---|---|---|---|---|
| **R1** | **C2-β under-splits high-motion content** (the inverse of the variance over-split the descent fixes) → > 0.1 dB regression. libvpx keeps RT breakout OFF, so we have NO upstream threshold to inherit. | **Medium-High** | **High** | Env-gate OFF by default; tune `search_breakout_thresh` against §4 corpora; gate is the hard stop. If no threshold hits ≥1.3× within 0.1 dB, C2-β does not land — fall back to C2-α only. |
| **R2** | C2-α's model-RD lower bound is not a true lower bound in some regime → skips the real winner → quality loss. | Low-Medium | Medium | It is the same conservative model libvpx uses (model rate/dist before the real transform). Retain the running best always (skip only *losing* candidates' residual eval). Gate measures it. |
| **R3** | An early-out changes the emitted `(mode, mv, ref, filter)` in a way that the decoder re-derives differently → `cross_decoder_gate` break (the DRIFT hazard Phase-2-A §R1 flagged on the SAME picker). | Medium | High | C2 changes *which candidate wins*, not how the winner's MV is derived; the existing DRIFT-FIX (`lib.rs:4504-4533`) re-pins NEAREST/NEAR from the causal grid post-pick regardless of the pick's source. `cross_decoder_gate` 4/4 is the backstop; 4/4→<4 is a hard stop. |
| **R4** | C2-α plumbing (widen `HandleInterRunner`) collides with S2/Lever-3b, which also edits the picker's return / `handle_inter` skip tie-break. | Medium | Low-Med | Both touch `handle_inter`/`pick_inter_sb`. Sequence: land S2/Lever-3b first (quality fix), re-baseline, then C2 (speed fix) on the stable picker. Coordinate the runner signature if both in flight. |
| **R5** | C2-β couples with Phase-2-A's cache-reuse: the cached descent pick was made under a breakout that the final pass doesn't re-run. | Medium | Low-Med | C2-β changes the *descent's shape search* (which leaves exist), not the cached leaf *pick*. Phase-2-A caches per committed leaf; a leaf that breakout suppressed is simply not in the list. No new divergence; verify via the §4.3 counters + quality gate. |
| **R6** | Reported speed win is noise / measured on a stale binary. | Expected | Low | Best-of-3 wall-clock, release build, post-Phase-2-A binary; §4.3 invocation-count drop must corroborate the fps gain. |

**Rollback.** All three levers are localized and independently revertible:
- **C2-α:** revert the runner-signature widening + the two `make_handle_params` field flips → restores
  `use_rd_breakout: false` / `ref_best_rd: i64::MAX`. The `handle_inter` early-term code stays (it is
  already there, just unreached).
- **C2-β:** flip the env gate / preset write OFF → the ML breakout returns to inert (its default). The
  hook (`lib.rs:3441-3534`) and model (`ml_partition/`) are untouched.
- **C2-γ:** not recommended for v1; if landed, a single revert of the table-threading.

No kernels, no descent/picker *algorithm* changes — only activation of existing mechanisms.

## 6. Interactions

- **Phase-2-A (cache-reuse) — stacks, shares the picker.** Phase-2-A removes redundant *picker calls*
  (the double-pick); C2 makes the *surviving* calls cheaper (C2-α) and shrinks the descent's interior
  shape-ranking cost C2-A leaves on the table (C2-β). They multiply. **C2 must baseline against the
  post-Phase-2-A binary** (§4.1). The Phase-2-A HLD §3.3 explicitly names C2-β as its "(C2)" follow-up.
- **Phase-1 SIMD — independent, composes.** SIMD speeds the kernel; C2 removes evaluations. Orthogonal;
  C2 touches no SIMD slot.
- **S2 / Lever-3b — the SAME picker (`handle_inter` skip tie-break + coef-rate domain).** C2-α widens
  the same `handle_inter`/`pick_inter_sb` plumbing S2 edits. **Sequence S2 first** (it has a measured
  ~6 dB headline), re-baseline, then C2 (quality-neutral-ish speed) on top. Coordinate the runner
  signature / `PickInterModeResult` field set if both are in flight (Phase-2-A §6 raised the identical

### 7.2 The strategic ceiling — BE HONEST WITH THE LEAD

**Incremental breakout (C2-α + C2-β) likely reaches ~1.5–2× cumulative** (Phase-1 ~1.3-1.4× × C2's
per-candidate + partition-breakout cuts). This is real and worth landing. **It does NOT close the ~18×
gap to vpxenc**, and no stacking of breakout heuristics will, for a structural reason:

> rvp9's picker is architecturally a **GOOD-quality RD picker** (`handle_inter_mode_single_ref` runs a
> real `super_block_yrd` per candidate — forward-quant + recon round-trip + chroma) plus a **recursive
> RD partition descent**. libvpx at cpu7 runs **neither**: it uses `VAR_BASED_PARTITION`
> (`choose_partitioning`, non-recursive, no RD) + `nonrd_use_partition`, a **single cheap model-RD mode
> pass that emits from the pick in the same call** (`vp9_encodeframe.c:5317-5424`, verified in the
> Phase-2-A HLD §2.1). The ~18× is the cost of doing transform-domain RD where libvpx does a variance
> model — early-termination shaves the constant, it does not change the algorithm class.

**Matching vpxenc fundamentally requires adopting libvpx's RT-picker architecture** — a one-shot
variance partition + a single model-RD mode pass with emit-from-pick — which is a **MAJOR separate
effort** (the AUDIT A4 Tier-0/1 variance-hint-to-parity work + a new `nonrd_use_partition`-style emit
path + the RT `ml_predict_var_partitioning` path, A21 Tier-2). The Phase-2-A HLD already measured that
the *partial* version of this (deleting the descent) costs −1.0…−1.3 dB because rvp9's variance hint is
not yet at libvpx parity. So the architecture port is gated on first bringing the variance partition to
parity — a large workstream, not a heuristic tweak.

**Is C2 worth it vs the architecture port?** Yes, as a near-term lever: C2 is ~185 LOC, fully
revertible, activates already-ported/tested code, and stacks cleanly on Phase-2-A for a measurable
~1.5–2×. It buys runway while the architecture decision is made. But the lead should know C2 is the
**last cheap incremental lever** — after it, further speed requires the architecture port (a multi-week
effort), not more breakout heuristics. C2 should not be sold as a step toward 18×; it is a step toward
~2×, after which the curve flattens until the architecture changes.

## 8. Executive summary (for the lead)

- **Most of C2 is already ported — the gap is activation, not porting (code-verified).** The RT picker
  (cpu7 path) already runs `encode_breakout` + `early_term` + adaptive `rd_thresh` live
  (`inter.rs:1794-1841`, `:1601-1637`). The ML-partition breakout family is ported and wired to the
  descent (`ml_partition/`, hook `lib.rs:3441-3534`). The `handle_inter` RD-breakout is ported and
  unit-tested (`handle_inter.rs:150-220`).
- **Two dormant levers remain.** (C2-α) `handle_inter_mode_single_ref`'s RD-breakout is **hardcoded
  off** (`inter_dispatch.rs:452-453` set `use_rd_breakout: false`, `ref_best_rd: i64::MAX`) and the
  driver has no path to thread the running best down — lighting it up is ~65 LOC, lowest risk, helps the
  speed≤4 RDO path. (C2-β) the ML partition breakout is **inert at cpu7** (RT preset leaves
  `search_breakout: false`, `speed_features.rs:112`) while GOOD speeds 0/1 enable it — flipping it on
  (env-gated) attacks the descent's interior cost Phase-2-A's cache-reuse can't touch.
- **Recommendation: land C2-α first** (wire the ported, tested, hardcoded-off RDO breakout), **then
  layer C2-β** (enable the inert RT-path partition breakout, env-gated, threshold tuned to the gate).
  Defer C2-γ (rd_thresh on RDO — subsumed by C2-α, more plumbing). ~185 LOC, fully revertible.
- **Quality oracle (pre-registered): matched-bitrate Y-PSNR ≤ 0.1 dB on foreman AND testsrc-crop, at
  ≥1.3× cpu7; `cross_decoder_gate` stays 4/4; `decode_failed == 0`.** Baseline must be re-measured on
  the post-Phase-2-A binary (Phase-2-A is itself decision-changing). Anti-G3 witnesses: skipped-eval
  counters must advance.
- **Strategic ceiling (honest): C2 gets to ~1.5–2× cumulative; it does NOT approach vpxenc's ~18×.**
  That gap is architectural — rvp9 does transform-domain RD + a recursive RD descent where libvpx cpu7
  does a one-shot variance partition + a single model-RD pass with emit-from-pick. Closing it requires
  adopting libvpx's RT-picker architecture (a MAJOR separate effort, gated on first bringing the
  variance hint to A4 parity). C2 is the last cheap incremental lever; after it the curve flattens.

**Single biggest open question for the lead:** **Incremental breakout now (C2-α + C2-β, ~185 LOC,
~1.5–2×, ≤0.1 dB) vs. investing in the libvpx RT-picker architecture port (VAR_BASED_PARTITION + single
cheap mode pass + emit-from-pick — the only path to ~18×, but multi-week and gated on A4 variance-hint
parity)?** Recommendation: **land C2 now for the near-term win and runway, but do NOT frame it as
progress toward 18×** — make the architecture-port decision explicitly and separately, with eyes open
that the −1 dB Phase-2-A measured for the partial version means the variance hint must reach parity

declare C2 done?**

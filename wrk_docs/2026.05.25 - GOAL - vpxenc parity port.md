# GOAL — Faithful rvp9 port of vpxenc

**Date written:** 2026-05-25
**Owners:** Arthur + Claude
**Status:** Active North Star — supersedes prior scoped goals (Track F, gap-closure waves, Tier-3/§10/§11 drive) which were tactical milestones toward this end.

---

## North-Star statement

> **Achieve quality, compression-efficiency, and performance parity with libvpx's `vpxenc` by reimplementing it faithfully in Rust. Parity is measured against `vpxenc` at matched configurations on a representative corpus.**

## Strategy — faithful port first, then measure-improve

We do **not** enter the measure-improve loop until the comparative audit certifies that no in-scope subsystem has unported in-scope code from vpxenc. Tuning while the producer side is stubbed and PARTIAL items remain partial wastes cycles fighting symptoms instead of porting code.

Two-stage flow:

1. **Faithful-port stage (Phases 1-3)** — compare codebases, identify gaps, plug them, iterate.
2. **Measure-improve stage (Phase 4)** — once the audit shows no in-scope gaps, switch to quality / BD-rate / throughput measurement vs vpxenc and drive the residual delta to zero or to a justified, documented deviation.

---

### Audit rules

- Read-only — no implementation changes during audit.
- Cite libvpx by `file:line` for every gap.
- Classify each gap as: **PORTED** / **PARTIAL** (what exists, what's missing) / **NOT PORTED** / **OUT OF SCOPE** (with rationale).
- Tag impact: high / medium / low — drives Phase 2 priority.
- Independent re-audit (different agent, different session) must reproduce the list within ±1 item.

### Aggregation

All audit outputs merge into `wrk_docs/<date> - vpxenc parity gap inventory.md`. Arthur reviews. Together we agree IN-SCOPE / DEFERRED-with-v2-ticket / OUT-OF-SCOPE-with-rationale.

## Phase 2 — Plug gaps in waves (IMPLEMENT)

Execute master inventory in priority order (high-impact first, cheapest-LOC tie-breaker). Each item follows the **anti-false-pass protocol**:

1. The function/flag is called from the encoder hot path — not just defined.
2. A **PROOF test** with positive assertion that fails if the wiring is stripped.
3. Cross-decoder gate stays green (output decodes through rvp9-decoder AND vpxdec).
4. Test count increases by ≥ 1.
5. Commit message cites the libvpx source line(s) ported.

### Anti-pattern guards (from prior lessons)

- **G3 lesson**: pattern-search verification must specify the EXACT function. "Does this pattern exist anywhere?" is insufficient — same token names can live in `decode_coefs` (decoder) and `encode_coefs` (encoder) with opposite effect.
- **Faithful-port stubs**: when a producer module is too large to port atomically, stub the data source with libvpx-pre-init defaults, BUT the gate-honouring side must be faithful AND the stub is documented in a central deviations ledger so re-audits flag it.
- **Agent self-reports are not evidence**. Arthur or a separate verification agent reads the actual code change before declaring done.
- **Sensible-decision policy** when running unattended: don't block on missing infrastructure — document, skip, move on; surface in the journal.

## Phase 3 — Re-audit pass (READ-ONLY)

After each implementation wave, re-run audits on touched zones. Iterate Phase 2 / Phase 3 until the exit criterion is hit.

### Exit criterion — "as faithful as we can be"

> **Two independent comparative audit passes — different agents, different sessions, ≥ 24 hours apart — both return zero IN-SCOPE gaps across every audit zone. Every DEFERRED item has an explicit v2 ticket and rationale in `wrk_docs/<date> - vpxenc parity deferred items.md`. Every OUT-OF-SCOPE item is similarly documented.**

Only after this criterion is met do we move to Phase 4.

---

## Phase 4 — Measurement-iteration loop

`quality_gate` becomes meaningful: residual delta is genuine algorithmic divergence, not stub-induced noise.

### Measurement axes

1. **Quality**: PSNR-delta mean vs vpxenc at matched bitrate across foreman / testsrc / Profile-1 corpus.
2. **Compression efficiency**: BD-rate (computable once curves overlap); bits/frame distribution sanity.
3. **Encode performance**: encode-throughput head-to-head bench (parallel to existing `decode-headtohead.md` infra).

### Exit criterion — "parity achieved"

> **Quality**: PSNR-delta mean ≤ 0.1 dB on every corpus item at every operating point.
> **Compression**: BD-rate within ±1 % of vpxenc.
> **Performance**: encode throughput within 1.5× of vpxenc on each fixture.
>
> Residuals beyond these bars are explicit acceptable deviations, each documented and reviewed by Arthur.

## Scope (resolved 2026-05-25)

**Rule:** if vpxenc does it, we do it. Default is INCLUDE; OUT-OF-SCOPE requires explicit per-item justification that the feature is not present in libvpx/vpxenc.

### In scope — full vpxenc parity

**Profiles (all four bit-depth × chroma combinations):**
- Profile 0 (8-bit 4:2:0)
- Profile 1 (8-bit 4:2:2 / 4:4:0 / 4:4:4)
- Profile 2 (10/12-bit 4:2:0)
- Profile 3 (10/12-bit 4:2:2 / 4:4:0 / 4:4:4)

**Rate-control modes:**
- CBR (real-time)
- VBR (1-pass)
- 2-pass VBR + lag-in-frames
- Constrained-Quality / Constant-Quantizer modes that vpxenc surfaces

**Speed presets:**
- All `cpu-used` levels 0..=8 (covers RDO paths at low speeds AND the realtime path at high speeds)

**Reference-frame features:**
- ALTREF (including filtered ALTREF construction)
- Compound prediction
- Multi-ref decision logic (LAST / GOLDEN / ALTREF interleave + masking)

**Encoder subsystems:**
- Pre-analysis pipeline (noise estimator, skin detector, scene-change, content-state classifier, source-variance pre-pass)
- Temporal denoiser (`vp9_denoiser.c`)
- All AQ modes (variance / complexity / cyclic-refresh / equator / 360 / lookahead-based)
- Segmentation (full `vp9_segmentation.c`)
- SVC paths (spatial + temporal layering, inter-layer refs, `use_base_mv`)
- `vp9_pick_inter_mode_sub8x8` (sub-8x8 inter picker)
- RDO intra path (`vp9_rd_pick_intra_mode_sb`)
- ML partition (where libvpx uses it at non-RT speeds)
- All speed-feature gates across the full `cpu-used 0..=8` range

**SIMD coverage:**
- All x86_64 paths libvpx ships (SSE2, SSSE3, SSE4.1, AVX, AVX2)
- **ARM NEON / SVE: out of scope for this port** (Arthur 2026-05-25). Revisit if/when an ARM target is added.

### Out of scope — explicit justifications required

Only items absent from libvpx/vpxenc OR explicitly scope-cut by Arthur go here:
- GPU acceleration — libvpx is CPU-only
- ARM SIMD (NEON / SVE) — Arthur 2026-05-25, this port is x86_64-only; revisit if ARM target added
- (Add others here only with libvpx-source citation showing absence, or with an Arthur sign-off line)

## Honesty rules (apply to every phase)

- Tests are tests. Don't add tests that don't fail when the code is broken. (Coverage stage exclusions ledger documents this.)
- Bench numbers are valid only when (a) machine is pinned, (b) build is clean, (c) source ledger SHA is recorded.
- Document deviations from vpxenc in source comments AT the deviation site AND in a central deviations ledger.
- The 9.1 dB `quality_gate` threshold stays frozen during Phases 1-3 (it's not a goal — it's a regression guard). It moves only after Phase 4 measurement establishes the real baseline.
- Agent prompts may be wrong. Agents may push back. Both are healthy.

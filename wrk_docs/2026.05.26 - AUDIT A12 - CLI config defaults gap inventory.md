# AUDIT A12 — CLI / config defaults gap inventory

**Date:** 2026-05-26
**Audit zone:** A12 (CLI / config defaults)
**Scope:**
- libvpx: `third_party/libvpx/vpxenc.c` (CLI arg-parse, 2070 LOC), `third_party/libvpx/vp9/vp9_cx_iface.c` (config defaults + `set_encoder_config` + `encoder_set_config` + `encoder_init` + `encoder_encode`, 2457 LOC)
- rvp9: `crates/rvp9-cli/src/bin/rvp9enc.rs` (368 LOC), `crates/rvp9-encoder/src/frame_loop.rs::EncoderConfig` (≈ lines 109-211), `crates/rvp9-encoder/src/rate_control/config.rs::RateControlConfig` (≈ lines 15-179)
**Method:** Enumerated every `ARG_DEF*(…, "flag-name", …)` macro across `vpxenc.c`; traced each through `parse_global_config`, `parse_stream_params`, `new_stream`, and the `vp9_args[]` ctrl-map. Cross-referenced default values from `encoder_usage_cfg_map[]` (`vp9_cx_iface.c:2122-2200`), `default_extra_cfg` (`vp9_cx_iface.c:69-106`), and the `cfg → oxcf` mapping function (`vp9_cx_iface.c:500-668`). Compared flag-by-flag against `flag_table()` in `rvp9enc.rs:61-123` and the field set of `EncoderConfig` (`frame_loop.rs:125-163`) + `RateControlConfig` (`rate_control/config.rs:15-127`). Status PORTED requires both (a) `rvp9enc` parses the flag AND (b) the parsed value reaches the encoder hot path (not just stored in `EncOpts` and dropped).

Row-count sanity: vpxenc.c CLI is ~600 LOC of arg parsing + cx_iface.c is ~750 LOC of cfg mapping ≈ 1350 LOC of audited surface. Picker baseline 45 rows / 2820 LOC → scale 0.48 → expected band ≈ 11–32 rows. This inventory has 88 rows; the deviation is justified because each individual CLI flag is in scope per Arthur's "every flag in scope" rule (audit-prompt §"SCOPE RULES"), not because of LOC density. All 88 flags map to one row each.

## 1. Main / global args (vpxenc.c:170-244)

The `main_args[]` group is the I/O shell — output file, help, deadline, passes, container choice. The `global_args[]` group is the input-side shell — color format, width/height, timebase, error-resilient, lag-in-frames. rvp9 ports `--help`, `--output`, `--limit`, `--verbose`, `--width`, `--height`, `--fps`, `--codec` (validation), `--ivf` (recognised). Everything else in these groups is either NOT PORTED (deadline, passes>1, pass=N, debug, q-hist, rate-hist, color formats other than I420, stereo-mode, timebase, error-resilient, lag-in-frames) or OUT OF SCOPE per Phase / SIMD constraints. `--passes`/`--pass` is PARTIAL — only `--passes=1` is accepted (rvp9enc.rs:81-82); 2-pass mode is unported.

`--threads`, `--profile`, `--bit-depth`, `--input-bit-depth` are recognised by `rvp9enc.rs` (lines 94, 99, 119) but their `apply` is `None`, so any usage errors out. The values therefore never reach the encoder — this is the **NOT PORTED (parsed-not-plumbed)** classification used throughout the table.

## 2. Rate-control args (vpxenc.c:281-286)

`rc_args[]` covers `--drop-frame`, `--resize-{allowed,width,height,up,down}`, `--end-usage`, `--target-bitrate`, `--min-q`, `--max-q`, `--undershoot-pct`, `--overshoot-pct`, `--buf-{sz,initial-sz,optimal-sz}`. rvp9 ports `--target-bitrate` (`rvp9enc.rs:77-78` → `EncoderConfig.target_bitrate_bps` → `RateControlConfig.target_bitrate_bps`), validates `--end-usage=cbr` only, and recognises (but errors on) `--min-q`/`--max-q`/`--undershoot-pct`/`--overshoot-pct`/`--buf-*`. The buffer-size defaults match libvpx exactly (6000/4000/5000 ms — `rate_control/config.rs:112-114` vs `vp9_cx_iface.c:2159-2161`), but they cannot be overridden by CLI. `min_qindex` defaults to **4** in rvp9 vs **0** in libvpx (documented at `rate_control/config.rs:38-40`).

## 3. Vizier 2-pass args (vpxenc.c:289-326)

Fifteen rational-valued knobs (`--use-vizier-rc-params`, `--active-wq-factor`, `--err-per-mb-factor`, `--sr-default-decay-limit`, `--sr-diff-factor`, `--kf-err-per-mb-factor`, `--kf-frame-min-boost-factor`, `--kf-frame-max-boost-first-factor`, `--kf-frame-max-boost-subs-factor`, `--kf-max-total-boost-factor`, `--gf-max-total-boost-factor`, `--gf-frame-max-boost-factor`, `--zm-factor`, `--rd-mult-inter-qp-fac`, `--rd-mult-arf-qp-fac`, `--rd-mult-key-qp-fac`). All NOT PORTED. All are 2-pass-only and would require A3 (rate-control 2-pass + lag-in-frames). rvp9 has no scaffolding for any of these.

## 4. 2-pass VBR rc args (vpxenc.c:354-357)

`--bias-pct`, `--minsection-pct`, `--maxsection-pct`, `--corpus-complexity` — all NOT PORTED, all dependent on A3 (2-pass VBR).

## 5. Keyframe placement (vpxenc.c:364-366)

`--kf-min-dist`, `--kf-max-dist`, `--disable-kf`. Only `--kf-max-dist` is wired (`rvp9enc.rs:84` → `EncoderConfig.gop_length`). Default in libvpx is 128 (`vp9_cx_iface.c:2171`); rvp9 default is 60 (`frame_loop.rs:177`) — **documented divergence**. `--kf-min-dist` and `--disable-kf` are not even recognised by `rvp9enc.rs`.

## 6. VP9-specific args (vpxenc.c:537-572)

This is the high-impact zone. All 27 entries map to ctrl IDs in `vp9_arg_ctrl_map` (vpxenc.c:573-601) and most flow into `oxcf` via the `cfg → oxcf` mapping function (`vp9_cx_iface.c:500-668`). rvp9 status:

- **`--cpu-used`**: NOT PORTED. `rvp9enc.rs:98` recognises the flag but errors on use. This is the single most quality-impactful gap because it should select between `set_rt_speed_feature_framesize_independent` (cpu-used 5-9) and `set_good_speed_feature_framesize_independent` (cpu-used 0-4) in libvpx's `vp9_speed_features.c`. Today rvp9 always runs the cpu-used 6/7-equivalent code path (the only one ported per audit zone A7).
- **`--auto-alt-ref`**: NOT PORTED. Default in libvpx is 1; rvp9 has no ALTREF.
- **`--sharpness`**: NOT PORTED. `oxcf.sharpness` → loopfilter offset; rvp9 hardcodes `sharpness_level: 0` everywhere.
- **`--static-thresh`**: NOT PORTED. `oxcf.encode_breakout` → A1 P7 (`encode_breakout_test`).
- **`--tile-columns`** / **`--tile-rows`**: NOT PORTED. libvpx default 6/0 (= up to 64-column wide tile grid); rvp9 hardcodes single tile. This is a load-bearing parity gap because the picker / writer all run sequentially per tile, and libvpx's row-MT depends on it.
- **`--enable-tpl`**: NOT PORTED. Default in libvpx is ON; no TPL in rvp9.
- **`--arnr-maxframes`** / **`--arnr-strength`**: NOT PORTED. A16 ALTREF temporal filter — defaults 7/5.
- **`--arnr-type`**: OUT OF SCOPE (libvpx accepts but no longer reads — value sits in `cfg` and never reaches `oxcf` in `set_encoder_config`).
- **`--tune`**: NOT PORTED. `oxcf.tuning = PSNR/SSIM`; rvp9 always-PSNR.
- **`--cq-level`**: NOT PORTED. CQ / Constrained-Q mode.
- **`--max-intra-rate`** / **`--max-inter-rate`** / **`--gf-cbr-boost`**: NOT PORTED. RC sub-budget caps.
- **`--lossless`**: NOT PORTED.
- **`--frame-parallel`**: NOT PORTED. libvpx default ON; rvp9 hardcodes OFF (frame_loop.rs:1605, 1858).
- **`--aq-mode`**: PARTIAL. Only modes 0 / 3 parsed.
- **`--alt-ref-aq`** / **`--frame-boost`** / **`--min-gf-interval`** / **`--max-gf-interval`**: NOT PORTED.
- **`--noise-sensitivity`**: NOT PORTED. A17 denoiser.
- **`--tune-content`**: NOT PORTED. Screen / film gates.
- **`--color-space`**: NOT PORTED. rvp9 hardcodes BT.601; libvpx default is UNKNOWN.
- **`--target-level`**: NOT PORTED.
- **`--row-mt`**: NOT PORTED. Default OFF in libvpx, but the in-flight "Wave 7" row-MT plan in `wrk_docs/2026.05.25 - HLD - Row-parallel LF implementation plan.md` and `Wave 6 tile load balance plan.md` will need this gate.
- **`--disable-loopfilter`**: NOT PORTED. libvpx default 0 (LF on).

## 7. HBD args (vpxenc.c:487-498)

`--bit-depth` (8/10/12), `--input-bit-depth`, `--test-16bit-internal`. All NOT PORTED — A20 covers HBD; rvp9 is Profile 0 only.

## 8. Defaults (vp9_cx_iface.c:2122-2200, 69-106)

Two structures define the libvpx defaults:
1. **`encoder_usage_cfg_map[0].cfg`** (`vp9_cx_iface.c:2122-2199`) — the public `vpx_codec_enc_cfg_t` defaults applied by `vpx_codec_enc_config_default()` (called from `vpxenc.c:857-859`). Then `vpxenc.c:864` overrides `g_timebase.den = 1000`, and `vpxenc.c:869-870` zeros W/H.
2. **`default_extra_cfg`** (`vp9_cx_iface.c:69-106`) — the private `vp9_extracfg` defaults applied by `encoder_init` at `vp9_cx_iface.c:1135`.

The major default divergences (rows 125-174 in the summary):
- libvpx defaults to **VBR** with **target=256 kbps**; rvp9 defaults to **CBR** at **1000 kbps**.
- libvpx defaults to **`tile_columns = 6`** (multi-tile); rvp9 is single-tile.
- libvpx defaults to **`frame_parallel_decoding_mode = 1`**; rvp9 hardcodes OFF.
- libvpx defaults to **`cpu_used = 0`** (best quality) or 5 in `CONFIG_REALTIME_ONLY`; rvp9 behaves like cpu-used 6/7 always.
- libvpx defaults to **`enable_auto_alt_ref = 1`** + **`arnr_max_frames=7`, `arnr_strength=5`**; rvp9 has no ALTREF.
- libvpx defaults to **`enable_tpl_model = 1`**; rvp9 has no TPL.
- libvpx defaults to **`g_lag_in_frames = 25`** (but the RT-CBR override sets it to 0 in vpxenc.c:884-887); rvp9 has no lookahead either way.
- libvpx defaults to **`kf_max_dist = 128`** (= 128-frame keyframe cap); rvp9 defaults to 60.

## 9. encoder_set_config / encoder_encode plumbing (vp9_cx_iface.c:500-668, 794-832, 1312+)

`set_encoder_config` (`vp9_cx_iface.c:500-668`) is the single point where 70+ cfg-→-oxcf mappings happen. rvp9 has no equivalent of this function — the `EncoderConfig → RateControlConfig` translation in `frame_loop.rs:186-211` covers only **six** of those fields: `target_bitrate_bps`, `framerate`, `gop_length`, `frame_width`, `frame_height`, `bits_per_mb_multiplier`. Every other libvpx oxcf field is either hardcoded at use site (sharpness, color_space, profile, tile geometry, frame_parallel) or absent entirely (lag, alt-ref, all VBR/CQ knobs).

`encoder_set_config` (`vp9_cx_iface.c:794-832`) supports mid-stream reconfiguration (e.g. resolution change). rvp9 has no reconfiguration API — `StreamEncoder::new` consumes the config once and freezes it.

`encoder_encode` (`vp9_cx_iface.c:1312+`) is the per-frame entry that pumps `oxcf` into `vp9_get_compressed_data`. rvp9's equivalent is `StreamEncoder::encode_frame` (`frame_loop.rs`); it reads `self.config` for each frame so swap-on-write reconfiguration would be feasible but is not wired.

## 10. Cross-cutting gaps

### 10.1 Parsed-but-not-plumbed flags

22 flags in `rvp9enc.rs:94-121` have `apply: None`. They are recognised by the help text (so `--help` lists them) but using any of them errors out with "not supported yet". From a parity standpoint these count as NOT PORTED — the flag *appears* in the CLI surface but the value never reaches `EncoderConfig`. The list:

```
--profile  --rt  --good  --best  --cpu-used  --threads
--tile-columns  --tile-rows  --kf-min-dist  --disable-kf
--min-q  --max-q  --cq-level  --buf-sz  --buf-initial-sz
--buf-optimal-sz  --undershoot-pct  --overshoot-pct  --lossless
--frame-parallel  --error-resilient  --tune  --tune-content
--noise-sensitivity  --svc  --bit-depth  --psnr  --webm
```

Anti-G3 note: a future implementer who grep's for `--cpu-used` in `rvp9enc.rs` will find the literal flag at line 98 and might mistakenly classify it as PORTED. The `apply: None` is the load-bearing detail.

### 10.3 No `encoder_set_config` equivalent

There is no rvp9 function corresponding to `set_encoder_config` (vp9_cx_iface.c:500-668). The mapping from public config → encoder internal state is split across:
- `EncoderConfig::to_rate_control_config` (`frame_loop.rs:186-211`)
- inline hardcoded constants in `build_keyframe_packet` / `build_inter_packet_with_residuals` (see 10.2)
- the rate controller's own `RateControlConfig::default` (`rate_control/config.rs:104-127`)

This means every new flag requires touching 3 sites. Recommend collapsing into a single `set_encoder_config(EncOpts → InternalEncoderState)` to match libvpx's structure.

### 10.4 No `usage` (profile/preset) layer

libvpx's `encoder_usage_cfg_map[]` (`vp9_cx_iface.c:2122-2200`) supports multiple "usage" presets selectable via `--usage`. Only usage 0 ships, but the array dimensionality is in libvpx's public API. rvp9 has no equivalent — `EncoderConfig::new` returns one preset hardcoded as "1 Mbps WebRTC".

### 10.5 No deadline-based default selection

vpxenc.c:884-887 has an important RT-CBR override: when deadline is REALTIME and end-usage is CBR, `g_lag_in_frames` is forced to 0. Similar deadline-conditional defaults exist for `passes`. rvp9 has no `--rt` / `--good` / `--best` parsing → no such overrides apply → if/when lag-in-frames is added, the deadline coupling will need to come with it.

### 10.6 Validation surface

libvpx's `validate_config` (`vp9_cx_iface.c:176-437`) range-checks every cfg/extra_cfg field with explicit `RANGE_CHECK*` macros. rvp9 has `RateControlConfig::validate` (`rate_control/config.rs:149-178`) covering ~7 fields. The full libvpx validator is unported.

Sequencing suggestion for Phase 2:

1. Land **P0** (drop `apply: None`) — unblocks head-to-head benches with libvpx-style invocations.
2. Land **P5** (single `set_encoder_config` site) — reduces marginal cost of every subsequent flag.
3. Land **P1** (`--cpu-used` wire) before A7 implementation work — gives A7 a stable knob to test against.
4. Land **P2** (`--tile-columns`/`--tile-rows` wire) in lock-step with Wave 6/7 (row-MT, tile load balance).
5. Land **P3** + **P6**–**P9** (RC knobs + sharpness + disable-loopfilter) as a batch — cheap, defensive, parity-improving.
6. Land **P12**–**P15** (default divergence fixes) immediately after P2 — required for libvpx-defaults benches to be meaningful.
7. The remaining tiers gate on other audit zones (A3, A10, A11, A16, A17, A18, A19, A20) and follow the master inventory order.

# Goal: Recover Compressor Stage 4a

## Objective

Bring the rvp9 compressor back onto the Stage 4a path: decodable VP9 bitstreams, 720p30 real-time performance, and BD-rate within 2% of libvpx at matched `--cpu-used 7 --rt --tune-content default`.

Treat Stage 4a as open. Current main is functionally capable and cross-decoder clean on the exercised gate, but it does not meet the speed or compression-efficiency exits in `PLAN.md`.

## Current Evidence

- Encoder library tests pass: `cargo test -p rvp9-encoder --lib` reported 456 passed, 0 failed, 1 ignored.
- Cross-decoder gate passes: rvp9 decoder, `vpxdec`, and `ffmpeg` produced byte-exact output on the exercised stream.
- Quality is still behind libvpx. The current real-content quality gate reported `+22.88%` BD-rate, with matched-bitrate PSNR delta mean `+2.36 dB` where positive means rvp9 trails libvpx.
- The stronger six-point foreman sweep in `notes/bdrate-sweep-2026-05-31.txt` reported about `+29.4%` BD-rate / `-0.91 dB` BD-PSNR, with rvp9 crossing libvpx only at higher bitrates around 750 kbps.
- 720p30 real-time currently fails badly. Repeated release runs of `realtime_gate_720p30` measured about `162 ms/frame` against a `33 ms/frame` budget.
- The older apparent 720p pass came from an earlier large-frame shortcut. Current main no longer has that area-based picker bypass; the current fallback only excludes sub-8 block sizes.

## Constraints

- Keep libvpx parity as a diagnostic discipline, not the product goal. BD-rate and latency are the gates.
- Do not weaken tests or thresholds to claim progress.
- Preserve cross-decoder correctness after every encoder behavior change.
- Prefer existing code paths, diagnostics, and harnesses. Add dependencies only after discussion.
- Record deliberate libvpx divergences in `notes/divergence-ledger.md`.

## Work Plan

1. Establish a clean baseline on current main.
   - Run the focused encoder library tests.
   - Run the cross-decoder gate.
   - Run the real-content quality gate.
   - Run the 720p realtime gate in release twice to confirm the speed baseline is not noise.

2. Fix validation debt before interpreting later numbers.
   - Remove the unused `bmode` warning in `crates/rvp9-encoder/src/rdo/sub8_kf_intra.rs`.
   - Confirm the touched test subset remains warning-clean.

3. Profile the current realtime failure.
   - Use the existing realtime harness and its flamegraph guidance.
   - Start with `pick_inter_mode`, RD partition descent, and double-pick behavior.
   - Verify SIMD dispatch is active before doing algorithmic work; use `RVP9_FORCE_SCALAR` only as a diagnostic control.

4. Triage unmerged compressor work.
   - Inspect `track2-longclip-differential-gate`.
   - Revalidate promising changes independently, especially motion-search and keyframe partition work.
   - Do not merge branch results wholesale: branch notes indicate at least one headline win did not generalize and conformance bugs were found.

5. Attack speed with measurable gates.
   - Revisit the Phase 2 partition double-pick plan, but do not assume seed-only reuse is enough; prior measurements showed only about `1.09x` geomean on foreman.
   - Consider larger safe wins: picker early termination, variance-partition parity, ML breakout, or speed-feature pruning.
   - Every speed change must report median frame time and quality delta.

6. Attack low-bitrate efficiency.
   - Use the six-point foreman sweep as the main signal, not the loose PSNR-delta pass threshold.
   - Focus on the low-bitrate/high-Q region where rvp9 trails most.
   - Re-measure BD-rate after each coupled quality change; avoid single-clip conclusions.

## Acceptance Criteria

- Cross-decoder gate remains byte-exact against rvp9 decoder, `vpxdec`, and `ffmpeg`.
- `realtime_gate_720p30` reaches at most `33 ms/frame` median, or the remaining gap is documented with a quantified profile.
- Real-content BD-rate reaches within 2% of libvpx for Stage 4a, or the next residual gap is decomposed into specific, measured causes.
- Quality gates use meaningful BD-rate or matched-bitrate thresholds; a `+20%`-class BD-rate result must not be treated as a pass.
- Any merged branch work has independent before/after numbers on current main.

## Stop Conditions

Stop and report instead of stacking fixes if:

- A change breaks cross-decoder byte-exactness and the root cause is not obvious.
- A speed win regresses BD-rate without a clear tradeoff decision.
- A branch result cannot be reproduced on current main.
- Profiling contradicts the assumed hot path.

# Final inter-emission quant-zero census

**Decision:** test a bounded x86 TX8/TX16 fast-quant zero precheck before considering a production candidate. This diagnostic shows a large *reachable* zero-quantization population, not removable CPU or a measured gain. The integrated production-PGO parity result remains [1.057638× pinned libvpx equal-clip process CPU](../2026-09-27-integrated-pgo-direct-repeat/README.md), above the 1.05× bar.

The opt-in diagnostic extends the isolated final-TX census branch with per-plane outcomes: `exact_zero` means all pixel residuals are zero and the existing code skips transform/quant; `quant_zero` means a nonzero residual was transformed and quantized to EOB zero; `eob_nonzero` means positive EOB. Each plane's three outcomes sum to its final residual-TX count. `source`, `direct`, and `direct_deferred` separately classify coefficient recording; deferred means a zero-EOB TX was queued before that leaf's first nonzero TX. They also sum to the plane count. Bulk luma-skip markers and the earlier chroma-proof bypass never enter this final per-TX closure and are not included.

The focused merge/classification test was made red by deliberately misclassifying a deferred case, then restored. Both `emit_profile_` tests passed on AArch64 and native x86; AArch64 default encoder check, formatting, and diff checks passed. The canonical one-thread CPU6/CBR1260 60-frame Ducks, Tree, and Town input hashes were checked, and all three encoded IVF hashes matched the integrated reference exactly. The [prior runner](../2026-09-28-final-inter-tx4-residual-census/run-tx4-census.sh) holds the encode command and expected hashes. The diagnostic EXE has per-TX clocks and branches, so its 90.43/72.71/81.46 ms reported transform/quant phase sums are **not** process-CPU savings or a production performance screen.

The remaining hypothesis is an x86 encoder-side predicate, restricted to fast-quant TX8/TX16 with trellis off, that proves EOB zero *before* qcoeff/dqcoeff stores. The current AVX2 zero-EOB shortcut runs after those stores; the AArch64 encoder already uses a separate early predicate. This needs an exact x86-arithmetic differential and a batch microbenchmark on representative transformed coefficients and quantizer parameters, including failed-predicate overhead. The current aggregate bins do not yet split quant-zero counts by TX size or preserve coefficient positions, so they cannot predict its net saving. Ducks alone would need about 39.8 ms less process CPU to close the gap, equivalent to at least 31.7 ns per observed Ducks quant-zero block even if every one were eligible and misses cost nothing; the actual requirement is higher. Only a positive microbenchmark should advance to unchanged-recipe production-PGO paired CPU screens, independently repeated, then direct integrated/libvpx parity.

# Four-tile TX4 SIMD prototype: rejected CPU screen

Arthur approved a bounded prototype that groups four 4×4 DCTs in each aligned 8×8 inter-luma region without changing raster-order quantization, entropy updates, or selector pruning. The candidate was based on the earlier scalar staging branch at `44a406ce`; its four changed source files were `crates/rvp9-core/src/transforms/forward.rs` (`6a4872d33775a875fa087ab1b7e58f2d809fe25a9fae0b5a63d5c97732d69bec`), `forward_sse2.rs` (`28a31f0d5fd46e8ac25a21b16b27c3a91df98de3628ef7ec48bc8aa41bcc783b`), `mod.rs` (`352be584364eba12ffbf16c6511a109d068a24c4aacd34f0e383a5a1a15ad2bb`), and `crates/rvp9-encoder/src/lib.rs` (`ca90e6776960cfde5cdf5b8b6151fdaf5c586d83828cd763e360dbb08ff036bb`). These were uncommitted prototype bytes in the local worktree; they were not integrated. The Crucible release executable SHA-256 was `66be5f485d58dccec92e40c36c513ec912b0d73a8a16dee23b7122d42537b2a7`.

The x86 AVX2 four-tile coefficient differential and encoder selector differential passed. Changing the AVX2 pass-0 input scale from ×16 to ×8 made the coefficient test fail on a constant residual, then restoring it made both tests pass. The local AArch64 selector test and core transform tests passed. The three-clip smoke and every full-screen encode produced the integrated baseline IVF hash.

The 15-pair-per-clip Crucible screen measured candidate/current process-CPU ratios of Ducks **1.058912**, Tree **1.015720**, Town **1.022036**, and equal-clip corpus **1.032048**. All 45 pairs were retained. A positive ratio above 1 means slower, so the result is a 3.20% CPU regression overall. The prior scalar staging prototype had also regressed at 1.028993× current. A second screen or pinned-libvpx comparison would not change the decision to reject this candidate. The AVX2 implementation still gathers and scatters intermediate values between its two vectorized passes; that overhead is a plausible cause, not a measured attribution.

`screen-a/` retains the exact runner, binary/source/input identities, manifest, raw paired timings, summary, output-stability hashes, and host-load samples. Encoded IVF files were not checked in; their hashes and byte counts are recorded. The prototype worktree is `/Users/md/worktrees/rvp9-2/20260925-TSK-HUM-prototype-exact-tx4-batching-in-inter-lu` and must not be treated as the integrated encoder.

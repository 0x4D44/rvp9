# Narrow Laplacian quotient: exact, slower in production PGO

**Decision:** do not integrate the code prototype. On a quiet-lease Crucible screen, it increased process CPU by **5.4583% on Ducks**, 1.9708% on Tree, and 1.0870% on Town. The equal-clip candidate/control geometric mean was 1.028215×. All outputs were canonical and exact. The integrated encoder remains 1.057638× pinned libvpx equal-clip process CPU; this candidate was not compared directly with libvpx because it failed the current-code gate.

The x86 production-PGO image uses both `div r9` and `div r9d` in the inlined Laplacian model. A standalone 131,072-input probe suggested an exact guarded 64-by-32 divide could reduce its own arithmetic time from about 2.99 to 1.10 ns/call. The source's post-wrap numerator is compared with `MAX_XSQ_Q10 * var`; a saturated result returns the cap, while the unsaturated quotient is proven smaller than 245727 and fits the 32-bit `divl` output. An earlier exact-output census found 2,713,714 nonzero Ducks calls, only 5.13% saturated. The microbenchmark was a kernel result, not an encoder-speed prediction.

The unintegrated one-file prototype is commit `d5a1251f` on `task/20260928-TSK-HUM-prototype-exact-narrow-quotient-for-lapl`; its native x86 patch equivalent is `203fac18` in the isolated Crucible worktree. It kept the `var == 0` return and original wrapped numerator, used an x86 `divl` only after the quotient proof, and retained ordinary division on other architectures. A boundary-and-random quotient differential failed deliberately at `245727/1` when the saturation return was changed to `MAX_XSQ_Q10 - 1`, then passed when restored. A second old-formula differential and all 52 model-RD tests passed on AArch64 and native x86. AArch64 core all-target Clippy with warnings denied, CLI build, format and diff checks passed. The native production-PGO build used the unchanged 28-row/60-frame training recipe.

The first five-pair Crucible screen was not a retention gate: both arms ran around 3–4× slower than the pinned direct baseline and the clip ratios swung widely. Its raw rows are retained. A fresh eight-minute quiet lease then reported zero heavy build processes. Under that lease the integrated control returned to its usual CPU range (Ducks about 1.77–1.80 s; Tree 0.94–0.97 s; Town 0.86–0.88 s per 60-frame encode). Five alternating measured pairs per clip, plus warmups, all exited zero and reproduced canonical IVF hashes. No pair was dropped. The native candidate production-PGO EXE SHA-256 was `19f1cbc591e95ad5b2da488d27c126a4a0ac88907d7a02048e990afc3a739560`; the control EXE was pinned `3c294166213bce7dc707734bf6fbe86e2387b23ef533c16ed16acf4780aaf3ad`.

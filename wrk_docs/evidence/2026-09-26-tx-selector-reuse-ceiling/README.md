# TX-selector luma forwarding opportunity census

This is an exact-output **work census, not a CPU speed result**. A read-only cross-family design consult proposed forwarding the chosen luma TX's `qcoeff`, `dqcoeff`, and EOB from `choose_inter_luma_tx_size` into final emission. Before changing that interface, temporary diagnostic commit `c7ffcf39` counted the overlap on the three pinned CPU6/CBR1260 60-frame clips. The code is archived as [diagnostic.patch](diagnostic.patch), a zero-context patch against integrated `ba8cb440` (`git apply --unidiff-zero`); it is not integrated. The integrated production PGO/libvpx result remains [1.099305× equal-clip CPU](../2026-09-26-nstep-duplicate-variance-pgo/README.md), above the ≤1.05× target.

The diagnostic recorded only selector-called leaves. It counted the chosen TX, whether the luma emit loop was skipped by `skip_txfm`, actual luma tiles traversed, tiles with a nonzero pixel residual (which enter forward transform/quant), and final skip. There were no per-tile timers. `luma_tiles` increments once per traversed tile; a first draft double-counted nonzero tiles and was corrected before this run. The revised focused test deliberately failed (`TX8 tiles: expected 3, actual 2`) and passed after restoration. Root reran it on AArch64; the worker also passed explicit AArch64 tests, encoder checks with and without `runtime-profiling`, rustfmt, and diff hygiene. Crucible's x86-64 release build and focused release test passed; its two warnings were in untouched files.

This substantially narrows, but does not measure, the attainable saving. A full result-forwarding design could remove final luma transform/quant work on at most the traversed tiles above; it cannot help the 304,058 Ducks or 43,122 Tree selector-called leaves whose luma emit loop was skipped. Tree's overlap is particularly small. It would still pay scratch-buffer and branch costs on every eligible leaf. The data do **not** price those costs or prove that forwarding would be faster. The next decision is whether a bounded ~4 KB two-slot selector/emitter result buffer is worth a prototype; any candidate must preserve raster-order entropy updates, strict TX ties, trellis fallback, both-architecture exact differentials, and repeatable paired production PGO CPU before integration.

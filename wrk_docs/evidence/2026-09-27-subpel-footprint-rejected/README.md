# Checked sub-pixel source footprint: exact, kernel-faster, not retained

The source-only prototype is local commit `6ac90e06` on `task/20260927-TSK-HUM-prototype-checked-subpel-source-footprin`. It checks the complete horizontal source footprint once before exact-width 4/8/16-byte AVX2 loads, retaining the old checked loader for short, overflowed, or non-production shapes. It was **not integrated**: two exact-output production-PGO screens both cost more equal-clip process CPU than the integrated control. The last direct integrated-code result remains **1.099305× pinned libvpx**.

The exact integrated Ducks profile placed 725/60,215 direct samples (1.20%) at RVA `0x10be76`, a loop-state instruction next to repeated per-load overflow and slice-length checks. In the candidate's exact PGO image, one complete-footprint check at VA `0x14010a95e..0x14010a98c` precedes repeated exact 16-byte left/right loads at `0x14010a992/997`, `0x14010a9da/9e0`, and later pairs, with no intervening source-length checks. This proves the intended instruction change, **not** a CPU saving. Candidate EXE SHA-256: `208bb6048ad32f9fa896b387072dd8f13ca8ef39c93e6a08a1598592748dedd4`; matching PDB SHA-256: `bd3221def0e1f5078c1d5b961e112572b6b3bda839c5236b72bfa42f2ae63e4b`; CodeView GUID `{C1FACB29-CFA3-17B3-4C4C-44205044422E}`, age 1. The control EXE SHA-256 was `3caee3f4416087ffe13069b4280f48fe92435bc32c9c0a41bebb7c187a73b3ee`.

The new boundary test covers all 11 production shapes and 64 phase pairs with exact-minimum source slices, overlapping/padded strides, and one-byte-short panic behavior. Seven focused tests passed on native AVX2 Crucible. Deliberately reading the left tap twice made the new differential fail at 4×4, stride 0, phase (1,1); reversing that patch restored all seven passes. AArch64 `cargo check --locked -p rvp9-encoder`, formatting, and diff checks passed. Rosetta on the local Mac does **not** expose AVX2, so its SIMD tests skipped; they were not counted as AVX2 evidence. Two native non-PGO `dsp-microbench subpel_variance` runs improved the 32×32 two-axis dispatch case from roughly 232–239 ns to 164–171 ns, and 64×64 from 797–812 ns to 596–598 ns; identity-phase timings stayed essentially flat. These are kernel-only measurements.

The candidate used the same 28-row, 60-frame PGO training recipe as the integrated control; `pgo-manifest.txt` records the build. Each screen alternated control/candidate order over 15 measured pairs per clip, plus one warmup per arm. The pinned 60-frame 1080p Ducks, In-to-Tree, and Old-Town Y4Ms used CPU6/CBR1260, one thread/no tiles, AQ0/noise0/lag0/KF60. All **192 encodes** exited zero and matched canonical IVF SHA-256. No pair was excluded for load or wall stalls. Ratios below are candidate/control process CPU; smaller is better. Equal-clip is the geometric mean of clip ratios, not a direct candidate/libvpx comparison.

Town regressed about 2.3% in both runs, outweighing inconsistent small gains elsewhere. Removing the identified checks and speeding the kernel did not yield a repeatable encoder gain. This is a performance rejection, not a correctness rejection. `screen-subpel-footprint.ps1`, `*-identity.csv`, `*-raw.csv`, and `*-summary.csv` preserve the commands, identities, all individual CPU/wall observations, output hashes, and paired ratios. CSV line endings were normalized for Git without changing values. The unintegrated local and Crucible prototype worktrees remain available for forensic reproduction.

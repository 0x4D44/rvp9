# Unit 1434 — integrated x86 three-clip sampled-IP attribution

This is a hotspot map, **not a performance comparison**. It samples the integrated `origin/main` commit `88644d86641f99a4291c21842bdc17aec9baee8e` on Crucible, after the x86 frame-HF Laplacian landing. The pinned CPU6/CBR1260, one-thread, 60-frame Ducks, Tree, and Town encodes each reproduced the existing exact IVF SHA-256. The executable SHA-256 was `1b64fc5f3de6dc3cfe9d486f6b2515be7a44354eeb0b025ca28e6e9903d1470a`; its paired PDB was `27c0b186f4a2a5b2edd19a665ccf8cc1bff1786c90df3a906ed9a1a6e58f72b4`.

Each clip directory retains `samples.csv` (every direct target-EXE row, its raw dumper fields, PID/TID/IP, and resolved symbol/line), `ip-symbols.csv`, per-symbol and per-source-line summaries, `summary.json`, the capture log, and the xperf `tracestats` and `profile` reports. `tracestats` reports **zero lost buffers and zero lost events** in all three ETLs. Those numeric reports, not the WPR stop wording, support the loss claim. The ETLs themselves remain in the Crucible task worktree's `.scratch/unit1434-ip-profile/<clip>/capture.etl`; they are 170/126/128 MB and are not checked in. The table hashes identify them.

The extractor in `extract-ip.py` was first replayed against Unit 1432's archived Tree raw rows and exact old EXE/PDB: 1,067 direct rows, 747 IPs, 1,065 counts on nonzero lines, and **zero** per-IP base/RVA/count/symbol/file/numeric-line mismatches. An independent second replay gave the same result. One archived `line_ok` flag incorrectly marked a numeric-zero line as resolved (one IP, two rows); comparison ignores only that derived flag. A deliberate old-EXE/new-PDB pairing with both real SHA-256 values exited 2 at the PE/PDB GUID-and-age check, before output creation. The live extractor also rejected malformed target rows while tolerating xperf's malformed quoting in unrelated `Unknown` process rows. The bundled `capture-clip.ps1` is the exact one-clip runner; its first Ducks preflight exposed a multiple-`wpr.exe` PowerShell discovery bug, fixed before WPR recording. No trace was lost to that preflight.

The sample mix differs sharply by clip. Ducks' largest symbols were inter-partition simulation (338/2,505), AVX2 quantization (188), and SAD4D (122). Tree and Town instead had `reconstruct_via_round_trip` (189/1,274 and 122/947) and AVX2 sub-pixel variance (184/1,274 and 125/947) at the top. `inter.rs:5590` alone received 157 Tree and 109 Town samples, but that macro source line covers generated code and is **not** an isolated-operation cost. These are sampled self weights and only upper bounds on a possible gain; they do not imply a speedup. The last separate paired pinned-libvpx screen remains **1.182520×** process CPU ([Laplacian evidence](../2026-09-25-hf-laplacian-avx2/README.md)); Unit 1434 did not rerun that comparison.

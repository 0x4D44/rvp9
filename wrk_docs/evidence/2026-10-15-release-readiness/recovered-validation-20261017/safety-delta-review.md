## Windows path guard FFI extension

Read `crates/rvp9-cli/src/path_guard.rs` in full, including `PathGuard::new/create`, `path_identity`, `file_identity` and `windows_identity`.

- `File` owns the handle throughout each synchronous `GetFileType`/`GetFileInformationByHandleEx` call; `AsRawHandle` is not retained. The output buffer is initialized, mutable for the call and `repr(C)` with u64 volume ID followed by16 bytes; the passed size is the exact Rust struct size. Class18 is used for FILE_ID_INFO. Source-level layout/ownership is consistent with the stated interface contract; no native Windows ABI test was run, and external API documentation was not re-fetched during this local review.
- GetFileType failure and GetFileInformationByHandleEx failure propagate an OS error. Non-disk/non-file handles are treated as nonregular; a zero ID is rejected. Only successful queries create an identity used for alias checks. File identity values are copied after the call, with no dangling pointer.
- Output opening uses create+write without truncation; actual handle identity is compared with both captured role IDs and current path identities before set_len(0) on that same handle. This reduces precheck-to-truncate alias risk and does not reopen a pathname for truncation. A failed alias check can still create an empty formerly absent output, per the observable contract.
- This is not a proof against all concurrent path replacement, device/reparse/network filesystem semantics or unsupported filesystem ID behavior. Native Windows alias/race/error-path tests and platform API validation remain necessary. No additional confirmed defect found in this bounded FFI read.

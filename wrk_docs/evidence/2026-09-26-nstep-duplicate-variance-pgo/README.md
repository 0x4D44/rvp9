# NSTEP duplicate variance score reuse: exact, repeatable small gain

The exact production PGO Ducks profile assigned 4,302/52,418 direct encoder samples to `nstep_search_sad` and 2,633 to its SAD4D helper. These are symbol self samples, not removable-cost estimates. Source inspection found one bounded redundant operation: distinct diamond starts, or final unit refinement, can return the current best full-pel coordinate. `full_pixel_variance_cost` depends on that coordinate and fixed search parameters, so scoring the same coordinate again cannot win the strict `<` tie-break. The change preserves search order, every candidate result, `num00`, and the best result fields; it only avoids those repeated variance calls.

The code is commit `39d02d8f` on `task/20260926-TSK-HUM-prototype-nstep-duplicate-variance-score`. A focused test compares the optimized NSTEP against a test-local copy of the former unconditional-scoring algorithm over four deterministic motion patterns, and asserts that at least one duplicate is actually reached. Deliberately reversing the coordinate guard made that test fail for seed 17 (chosen vector `(0,16)` instead of `(0,-6)`); restoring the guard passed. AArch64 and Crucible x86-64 each passed all 21 focused full-pixel tests. AArch64 `cargo check --locked -p rvp9-encoder`, `cargo fmt --all --check`, and `git diff --check` passed.

Crucible built the candidate from source base `8c5df486` plus the one changed file, using the unchanged 28-row, 60-frame production PGO recipe (31 raw profiles).

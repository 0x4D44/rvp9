# Lazy NSTEP initial variance: exact, slower

**Decision: reject the code prototype.** Deferring NSTEP's initial variance score preserved the canonical output on Ducks, Tree and Town, but a 15-pair production-PGO Crucible screen increased process CPU by 5.15%, 1.17% and 1.03% respectively (candidate/control). The equal-clip geometric ratio was 1.0243×. This is not a reproducible gain, so the code is not integrated. The integrated encoder remains at [1.057638× pinned libvpx CPU](../2026-09-27-integrated-pgo-direct-repeat/README.md), above the ≤1.05× target.

The candidate is local commit `3aa8e634` on `task/20260928-TSK-HUM-prototype-lazy-nstep-initial-variance-sc`, not on `origin/main`. It changes only `crates/rvp9-core/src/mv_search/full_pixel.rs`: the initial diamond winner's variance cost is computed at the first distinct diamond or refinement comparison, before the candidate's cost, and the strict `<` tie remains unchanged. The focused test covers both an unused initial score and a later comparison. It failed deliberately against the old unconditional path (one call versus the expected zero), then passed on the candidate. All 22 focused full-pixel tests passed independently on AArch64 and native x86; format and diff checks passed. No AArch64 encode differential was run because the exact x86 encodes and the CPU rejection were decisive.

Crucible built the candidate in its isolated x86 task worktree from the matching source-file SHA-256 `7bb21914473eacc2de16516631b5341584575c8286ecb4233ffee8f7dca7adac`. The remote source was copied from local commit `3aa8e634`; its manifest therefore records the clean base commit plus `-dirty`, not the local candidate commit. The unchanged 28-row, 60-frame [production-PGO recipe](../../../scripts/build-encoder-pgo.sh) emitted `rvp9enc.exe` SHA-256 `541737326b461bd3bb1a790d8b8091457872653b822f900d59a06dfdf971a644`; the integrated control was pinned SHA-256 `3c294166213bce7dc707734bf6fbe86e2387b23ef533c16ed16acf4780aaf3ad`. The [PGO manifest](candidate-pgo-manifest.txt), [paired runner](nstep-screen.ps1), [binary/input identities](screen-01-identity.csv), [raw rows](screen-01-raw.csv), and [per-clip summary](screen-01-summary.csv) retain the exact run. All 96 measured and warmup encodes exited zero and matched the integrated canonical IVF hashes; no pair was dropped.

The screen ran under an eight-minute `deltic quiet` lease with zero heavy build processes at grant and alternating arm/clip order; the lease was released immediately after the run. The earlier one-pair exact-output check was not used for the retention decision. Its raw files and all screen IVFs remain under the isolated Crucible task worktree's `.scratch`; no bulky IVF is committed.

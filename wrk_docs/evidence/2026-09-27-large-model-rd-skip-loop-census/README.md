# Large-model RD TX-cell early-break census

The exact integrated production-PGO profile attributed 342/18,127 Ducks, 440/8,195 Tree, and 422/8,629 Town direct samples to `model_rd_for_sb_y_large`. Those whole-symbol samples are not an estimate of removable loop CPU. This diagnostic counted the first TX cell after which both monotone skip tests (`ac_test`, `dc_test`) had failed. Later cells cannot change the model result, but the unchanged production loop still visited them. The opt-in `RVP9_DIAG_LARGE_MODEL_RD_SKIP_LOOP=1` counter groups calls by block shape and TX-cell count; it does not alter skip or encoding decisions. Its per-call mutex cost makes diagnostic CPU unusable as a performance number.

Decision: the large Tree/Town avoidable-cell counts warrant one exact-output early-break prototype. Ducks has little opportunity. The table is an upper bound on cell work, not a measured whole-encoder saving; branch overhead and PGO layout may erase it. Keep the diagnostic branch out of production. Gate a clean code prototype on deliberate-red old-path differentials, AArch64/x86 checks, exact canonical IVFs, and repeatable paired production-PGO CPU against integrated trunk.

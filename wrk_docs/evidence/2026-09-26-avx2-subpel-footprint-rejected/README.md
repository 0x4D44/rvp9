# AVX2 subpel source-footprint check hoist: exact, not retained

The integrated-code Ducks PGO profile put 725/60,215 direct samples (1.20%) at RVA `0x10be76`, adjacent to repeated row-offset and bounds work in the inlined AVX2 bilinear loader. This was a candidate-selection clue, **not** a removable-cost estimate. The previous one-axis halfpel experiment changed interpolation arithmetic; this one kept arithmetic and exact-width 4/8/16-byte loads unchanged.

Prototype commit `b1e6a8d5` on `task/20260926-TSK-HUM-prototype-avx2-subpel-footprint-check-ho` checked each pass's greatest source offset once with overflow-safe arithmetic, then selected a const-specialized unchecked loader for valid source slices. A checked specialization kept the old malformed-buffer behavior. The source extents were `(h−1)*stride+w+1` for horizontal-only, `h*stride+w` for vertical-only, and `h*stride+w+1` for two-dimensional interpolation. [The candidate patch](candidate.patch) preserves the exact code without landing it on main; it is a zero-context patch, so reproduction uses `git apply --unidiff-zero`.

Crucible x86-64 passed all seven `subpel_variance_avx2` tests, including a new differential over all 64 phases, every supported shape, two strides, and phase-minimal source slices. A separate test confirmed one-byte-short sources still take the checked panic path. The new differential failed deliberately after a horizontal filter-index mutation (`4x4`, phase `1,0`, actual `(83698,100598)` versus scalar `(97402,115157)`), then passed after restoration. AArch64 and x86-64 each passed `cargo check --locked -p rvp9-encoder`; local `cargo fmt --all --check` and `git diff --check` passed. No memory-safety instrumented run was done, and the prototype is not being retained.

Crucible built the candidate with the unchanged 28-row, 60-frame production PGO matrix; [the build manifest](build-manifest.txt) records 31 raw profiles and compiler identity.

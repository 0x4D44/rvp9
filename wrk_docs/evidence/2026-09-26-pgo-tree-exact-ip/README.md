These traces are selection evidence, not process-CPU timing.

The exact `0xf4560`–`0xf4630` loop accounts for **1,828 Tree samples (5.899%)**, with 6.867%, 4.600%, and 6.964% of each run. Disassembly shows the inlined Hadamard quantizer metric path: saturated absolute-value/rounding, high multiply, signed restoration, an exact narrow-difference check, and squared-error/SATD accumulation. Its hottest instruction, `vpmaddwd` at RVA `0xf45c5`, has 355 Tree samples. The same loop has only 11/52,418 Ducks samples (0.021%). PDB maps the inlined code broadly to `inter.rs:4627`; that line is the `reconstruct_via_round_trip` call, not an operation-cost attribution.

Conversely, the two leading Ducks sampled loads at RVAs `0xe322d` and `0xaa825` account for 2,496/52,418 Ducks samples (4.762%) but only 244/30,988 Tree samples (0.787%). The two source-scaling RVAs `0x152ed1` and `0x15349a` are a smaller common cluster: 1.345% of Ducks and 0.933% of Tree samples. Compare **shares**, not raw counts: ETW sample intervals and instrumented CPU duration can vary. These sample shares bound neither removable work nor product speedup.

Selection verdict: no new shared bounded kernel is established by these two profiles. The prior [error-only AVX2 metrics screen](../2026-09-26-error-only-metrics-avx2-rejected/README.md) was slower; an earlier full-metrics AVX2 rewrite was also rejected, and the exact narrow-difference guard has no proven removable invariant. Do not repeat either variant because this inlined loop is hot. Ducks' partition/picker loads require producer/consumer attribution before a code edit. The current direct PGO/libvpx result remains **1.096110×** overall in `../2026-09-26-encoder-pgo-parity/README.md`.

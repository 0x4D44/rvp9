# Current production-PGO Tree and Town exact-IP profiles

This is instruction-location evidence, **not a new speed comparison**. Three fresh-process Crucible WPR captures per clip encoded the pinned 60-frame 1080p CPU6/CBR1260 Tree and Town Y4Ms with the integrated-code PGO image used in the [current Ducks profile](../2026-09-26-pgo-nstep-ducks-exact-ip/README.md). Its EXE SHA-256 is `3caee3f4416087ffe13069b4280f48fe92435bc32c9c0a41bebb7c187a73b3ee`, PDB SHA-256 `7672ad045a634a9278d7b9255e1a0b665e9e729f6a480438e9b22c50d330bc13`, PE/PDB GUID `d13af019-ee7e-d008-4c4c-44205044422e`, age 1, image size `0x211000`. `git diff a8f63fbe..origin/main -- crates scripts Cargo.toml Cargo.lock .cargo` was empty before the capture, so later trunk commits had not changed the PGO image's shipped source.

All six encodes exited zero and reproduced their clip's canonical IVF SHA-256. Every trace had zero lost buffers and events. The exact-image extractor verified the EXE/PDB pair, target PID and loaded image before retaining direct encoder samples. The identity-checked aggregator independently checked each run and produced the full ASLR-stable RVA and source-line tables here. WPR's sampling interval read 1221 units (0.1221 ms) both before and after the campaign; this is **not** a per-ETL interval assertion. Profiling-run CPU and raw sample counts must not be treated as paired performance numbers.

Disassembly places them in the inlined Tx8 Hadamard full-metrics quantizer: quantized-magnitude setup, signed restore/dequant, the exact difference guard, pairwise squared error, and SATD accumulation. The source-line label `inter.rs:4627` is the containing round-trip call, **not** a single expensive operation. The current loop includes the retained guarded pairwise-square optimization.

The zero-quantized group share measured earlier is high on Tree and Town, but an earlier exact eight-lane zero-metric branch [regressed CPU](../../../wrk_journals/2026.07.30%20-%20JRN%20-%20production%20parity%20drive.md) (Unit 773). That experiment used NEON and an older CPU7 VBR corpus, so it does not disprove every x86 design; it does remove any basis for assuming a branch win from the current sample share alone. Existing full-metrics AVX2 and error-only rewrites also lost. No shipped-code edit follows from this profile without a distinct, cheaply falsifiable instruction-chain change. The current direct PGO/libvpx parity remains [1.099305× equal-clip CPU](../2026-09-26-nstep-duplicate-variance-pgo/README.md), above the ≤1.05× target.

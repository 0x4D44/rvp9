# HLD -- G5: Intra Residual Coding for Intra-in-Inter Blocks

**Date:** 2026-05-24
**Status:** Design proposal

---

## 1. Problem

The intra-in-inter path (`lib.rs:3456-3565`) runs intra prediction into
the recon buffer then forces `skip = true`, discarding all prediction
error.  Inter blocks in the same function (`lib.rs:3566-3735`) do full
forward-DCT / quantize / collect-coefs / inverse-DCT.  The result: every
intra-in-inter block is prediction-only, hurting reconstruction quality.

## 2. Decoder Requirements (the ground truth)

The decoder's `reconstruct_intra_block` (`reconstruct.rs:165`) does:

1. Intra prediction into `dst`.
2. `tx_type = resolve_tx_type(plane, lossless, intra_mode)`:
   - Y plane, non-lossless: `intra_mode.tx_type()` (can be ADST variants).
   - UV planes or lossless: `DctDct`.
3. `decode_block_tokens` with `ref_type = 0` (intra context tables).
4. Inverse-transform-add (IHT for non-DctDct, IDCT for DctDct).

The writer's `write_inter_block_residual` (`modes_writer.rs:2151`)
currently hardcodes `TxType::DctDct` and `ref_type = 1` for every TX
position.  This must change for intra-in-inter leaves.

## 3. Design

### 3.1 Merged prediction + residual TX walk (encoder, `lib.rs`)

The current intra path walks TX blocks for prediction only.  The residual
pass needs the same walk but adds DCT/quant/IDCT per block.  These MUST
be a single walk because VP9 intra prediction is *causal* -- each TX
block's prediction reads from the recon buffer, which must already contain
the final (prediction + residual) output of previous TX blocks.

**Before (current):**
```
for each TX block:
    build_intra_predictors → intra_predict  // prediction only
skip = true
```

**After:**
```
for each TX block:
    build_intra_predictors → intra_predict     // step 1: prediction
    residual = source - recon                  // step 2: compute residual
    tx_type = resolve_tx_type(plane, intra_mode)
    forward_transform(residual, tx_type)       // step 3: FHT/FDCT
    quantize                                   // step 4: quant
    inverse_transform_add(recon, tx_type)      // step 5: IDCT/IHT add
    coef_source.insert(qcoeff, eob)            // step 6: stash for writer
    leaf_total_eob += eob
skip = (leaf_total_eob == 0)                   // step 7: data-driven skip
```

The single-walk approach is required (not optional) because the intra
predictor for TX block N reads reconstructed pixels from TX block N-1.
Separating prediction and residual into two passes would read stale
(prediction-only) pixels for all but the first TX block.

### 3.2 Forward transform: `intra_forward_quant_one_tx`

Factor a new helper alongside `inter_forward_quant_one_tx`:

```rust
fn intra_forward_quant_one_tx(
    residual: &[i16],
    tx_side: usize,
    plane_tx: TxSize,
    tx_type: TxType,      // ← key difference: not always DctDct
    quantizer: &PlaneQuantizers,
) -> (Vec<i32>, Vec<i32>, usize)
```

Differences from `inter_forward_quant_one_tx`:
- Uses `fht4x4/fht8x8/fht16x16` with the caller-supplied `tx_type`
  instead of hardcoded `fdct*` (DctDct). Tx32x32 always uses `fdct32x32`
  (VP9 has no hybrid 32x32).
- Scan order: `scan_for(plane_tx, tx_type)` instead of
  `scan_for(plane_tx, DctDct)`.

The body is nearly identical to the keyframe residual path
(`lib.rs:1529-1591`).  A shared function eliminates the 60-line
duplication.

### 3.3 Inverse transform: `intra_inverse_transform_add`

Factor a new helper alongside `inter_inverse_dct_add`:

```rust
fn intra_inverse_transform_add(
    plane_tx: TxSize,
    tx_type: TxType,      // ← dispatches IHT vs IDCT
    dq_input: &[i32],
    eob: usize,
    dst: &mut [u8],
    stride: usize,
)
```

Differences from `inter_inverse_dct_add`:
- For `tx_type != DctDct` and sizes 4x4/8x8/16x16, calls
  `iht4x4_16_add` / `iht8x8_64_add` / `iht16x16_256_add` with
  `tx_type`.
- For `DctDct` or Tx32x32, falls through to the IDCT variants
  (same as the inter path).
- The eob==1 fast path (`idct*_1_add`) applies only when
  `tx_type == DctDct` (the single-coef IHT variants don't exist in
  libvpx).

The body mirrors the keyframe inverse path (`lib.rs:1600-1664`).

### 3.4 `resolve_tx_type` for the encoder

Reuse the decoder's logic.  Either import from `rvp9-core` (if already
re-exported) or inline the three-line function:

```rust
fn resolve_tx_type_enc(plane: usize, intra_mode: IntraMode) -> TxType {
    if plane != 0 { TxType::DctDct } else { intra_mode.tx_type() }
}
```

Note: `lossless` is always false in the current encoder scope (no
lossless mode support), so the parameter is omitted.

### 3.5 Writer changes (`modes_writer.rs`)

`write_inter_block_residual` currently hardcodes two values that differ
for intra-in-inter:

| Parameter  | Inter block | Intra-in-inter block |
|------------|-------------|----------------------|
| `tx_type`  | `DctDct`    | `resolve_tx_type(plane, mode)` |
| `ref_type` | `1`         | `0` |

**Option A (recommended):** Pass `is_inter: bool` and `y_mode: IntraMode`
to `write_inter_block_residual`.  Inside the per-TX loop, derive:
```rust
let tx_type = if is_inter { DctDct }
              else if plane == 0 && plane_tx != Tx32x32 { y_mode.tx_type() }
              else { DctDct };
let ref_type = u8::from(is_inter);
```

This requires the caller (`write_tile_inter`) to thread `is_inter` and
the Y intra mode through.  The `ModeInfo` already carries both via the
`BlockMode` enum, so no new fields are needed.

**Option B:** Split into two writer functions.  Rejected: the only
differences are two local variables; duplicating the 100-line walk is not
justified.

## 4. Buffers and Tables

| Item | Source | Notes |
|------|--------|-------|
| `residual: Vec<i16>` | Stack alloc, `tx_side * tx_side` | Same as inter path |
| `PlaneQuantizers` | `init_plane_quantizers(leaf_qindex, Y)` | Already computed at `lib.rs:3134` before the if/else branch — shared |
| `input_plane: &[u8]` | `input_yuv.{0,1,2}` | Needs binding in intra branch (currently only in inter branch) |
| `coef_source` | Existing `InterCoefSource` map | Same `.insert()` API; intra-in-inter blocks use the same keying |
| Forward transform scratch | `[i32; 1024]` max (Tx32x32) | Stack, same as inter |
| Dequant scratch | `Vec<i32>` or `[i32; 1024]` | Same as inter |

No new heap allocations.  No new struct fields.  The `PlaneQuantizers`
instance is already live at the branch point.

## 5. Control Flow Summary

```
lib.rs encode_inter_frame, per-leaf:
  ┌─ leaf_total_eob = 0
  ├─ quantizer = init_plane_quantizers(...)     // already here
  │
  ├─ if picked_ref == IntraFrame
  │   ├─ for plane in 0..3
  │   │   ├─ bind input_plane, recon_plane      // NEW
  │   │   ├─ for each TX block (existing walk)
  │   │   │   ├─ build_intra_predictors         // existing
  │   │   │   ├─ intra_predict                  // existing
  │   │   │   ├─ residual = src - recon         // NEW
  │   │   │   ├─ tx_type = resolve(plane, mode) // NEW
  │   │   │   ├─ intra_forward_quant_one_tx     // NEW
  │   │   │   ├─ intra_inverse_transform_add    // NEW (if eob > 0)
  │   │   │   ├─ coef_source.insert(...)        // NEW
  │   │   │   └─ leaf_total_eob += eob          // NEW
  │   ├─ skip = (leaf_total_eob == 0)           // CHANGED from forced true
  │
  ├─ else (inter block)
  │   └─ ... unchanged ...
  │
  └─ RC.X1: if leaf_total_eob == 0 { skip = true }
```

## 6. Shared Code Opportunities

| Code region | Lines | Shareable? | Recommendation |
|-------------|-------|------------|----------------|
| Plane setup (ss_x/y, plane_bsize, plane_tx, stride) | ~20 | Identical in both branches | Extract to local closure or inline struct; low priority |
| TX walk (nested while loops) | ~10 | Identical structure | Keep inline; the bodies differ enough that a shared iterator adds complexity |
| Forward transform + quantize | ~60 | Keyframe path duplicates | `intra_forward_quant_one_tx` serves both keyframe and intra-in-inter |
| Inverse transform add | ~40 | Keyframe path duplicates | `intra_inverse_transform_add` serves both keyframe and intra-in-inter |
| Residual computation | ~8 | Identical across all three paths | Keep inline (too small to factor) |

Net new code: ~30 lines in the intra-in-inter branch (residual compute,
helper calls, coef_source insert, eob accumulation).  Two new helper
functions (~60 + ~40 lines) that also deduplicate the keyframe path.

## 7. Risks

1. **tx_type mismatch:** If the encoder uses `DctDct` but the decoder
   expects `AdstDct` (or vice versa), the inverse transform produces
   wrong pixels and the coef tokens desync.  Mitigation: use the same
   `resolve_tx_type` logic as the decoder.

2. **ref_type mismatch:** Using `ref_type = 1` (inter) instead of `0`
   (intra) selects the wrong probability tables for coef token coding.
   The writer and decoder would desync on the first non-zero coefficient.
   Mitigation: writer passes `ref_type = 0` for intra-in-inter blocks.

3. **Causal prediction order:** If the residual add is skipped or applied
   out of order, subsequent TX blocks in the same coding block read stale
   prediction pixels.  Mitigation: the single-walk design (section 3.1)
   prevents this by construction.

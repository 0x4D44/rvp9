# Inter TX-selector result forwarding

The inter luma TX-size selector computes forward transform, quantized and dequantized coefficients, and EOB for each candidate tile, but returns only the winning TX size. Final emission recomputes the winning luma tiles. A read-only Fable consult proposed preserving the winner's `qcoeff`, `dqcoeff`, and EOB in two leaf-sized scratch slots, then consuming them in the existing raster emission walk. This is an optional performance design, not an integrated change or a measured gain.

The [exact-output census](evidence/2026-09-26-tx-selector-reuse-ceiling/README.md) bounds where this can help. Over 59 inter frames, selector-called leaves actually traversed 430,782 luma tiles on Ducks, 2,117 on Tree, and 142,497 on Town. The selector ran on 439,604 / 43,817 / 41,550 leaves respectively. Thus most selector calls, especially on Tree, have no final luma transform/quant work to forward. Counts are not CPU time; no speed claim follows.

## Proposed ownership boundary

Only plane 0 leaves that run `choose_inter_luma_tx_size` are eligible. Each candidate writes its tile-order `qcoeff`, `dqcoeff`, and EOB to a current slot. A fully evaluated candidate that wins becomes the best slot; a pruned candidate can leave partial data in the other slot. The selector returns the chosen `TxSize` and a leaf-local slot token. Two slots sized for the largest eligible leaf need about 4 KB total for qcoeff/dqcoeff plus EOB. The token expires after that leaf's luma emit walk; chroma uses the existing path.

The emitter must keep its existing raster-order coefficient recording, inverse-transform dispatch, zero-EOB marker behavior, and final skip decision. Only the source of chosen luma coefficient bytes changes. The selector's candidate order, partial RD pruning, and strict larger-TX tie are unchanged. Trellis-on, residual diagnostics that need per-tile residual data, and any selector-ineligible leaf fall back to recomputation. A differential must compare chosen TX, each tile's qcoeff/dqcoeff/EOB, reconstructed pixels, recorded coefficient order, and final IVF hash against the old path; corrupting one stored tile must make it fail. Test TX4/8/16, edges, zero/nonzero residual, pruned candidates, trellis fallback, and both architectures.

## Decision gate

This changes the selector/emitter interface and scratch ownership, so discuss it before implementation. If approved, first prove the tile-level differential and inspect x86 quantizer assembly for a codegen regression; then build full production PGO, run exact-output three-clip paired process-CPU screens under Arthur's relaxed Crucible load policy, and integrate only a repeatable gain. The per-tile timer in the older selector diagnostic perturbed measured time roughly fourfold, so it is not a speed forecast. The current direct integrated-code parity remains 1.099305× pinned libvpx equal-clip CPU.

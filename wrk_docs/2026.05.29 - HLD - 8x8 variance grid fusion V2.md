> **One-line thesis.** `compute_variance_8x8` resolves the per-cell AVX2 `(sum,
> sse)` reducer through a dispatch **function pointer and calls it once per 8×8
> cell** — 16 indirect calls for 32×32, 64 for 64×64. An indirect call to a
> separate `#[target_feature]` function **cannot be inlined**, so each cell pays a
> full call prologue/epilogue and re-runs its loop-invariant setup. Move the cell
> loop *inside* one dispatched grid kernel: now there is **one** indirect call per
> block, and the per-cell 8×8 reduction is a **direct, inlinable** call to the
> existing `var_sum_sse_inner(8,8)`, so the compiler can hoist invariant setup and
> keep accumulators in registers across the cell loop. **Each cell still produces
> the same `(sum, sse)` integers, fed to the unchanged scalar finishers →
> bitstream byte-identical.**

> **⚠ Gate up front (read §1.0 first).** The win is *only* call-overhead/inlining;
> it does **not** halve horizontal reductions and does **not** add row-load reuse.
> The expected effect is small and **may not clear the ship gate**. This PR is
> structured as a **measurement-gated spike**: re-baseline the profile and
> microbench the simple kernel *before* treating it as shippable. If the measured
> self-cost of `compute_variance_8x8` is small, or the microbench is `<+3%`,
> **do not ship — go to Phase-2.**

## 1. Problem

### 1.0 Measure first — the justification below is UNVERIFIED for the current binary

V1 justified targeting `compute_variance_8x8` by citing "the 37.4 % per-final-leaf
cost". That number is **misattributed**: the predecessor HLD
(`Encoder hot-path SIMD (speed).md:29`) defines **37.4 % as the cost of the entire
final-leaf `pick_inter_mode` evaluation** — MC convolve + SAD + sub-pel variance +
`block_yrd` + this — **not** the cost of `compute_variance_8x8` alone. Worse, that
baseline was measured **before** PR2/PR3/PR4 SIMD-ported SAD / sad4d / variance /
sub-pel (commits `1806f7a`, `9a9ef93`, `f7a965a`) and before the Phase-2 option-A
commit (`c5c9b9f`) changed the descent. The predecessor itself
(`:510-511`, `:649`, `:683-685`) and the Phase-2 HLD (`R6`) **mandate
re-baselining** the profile after Phase-1 before sizing any further work. V1
ignored that mandate. V1's "~10–15 % of pickmode" Amdahl input is likewise
**unsourced** — it appears in no profiling document; it was invented in the
sentence that used it.

**Therefore, before any kernel code:**

1. Profile the **post-Phase-1, post-option-A** `target/release` binary on a
   64×64-heavy clip and report the **self-cost of `compute_variance_8x8`** (the
   function itself, not the whole leaf) as a fraction `F` of encode wall-clock —
   e.g. a counter / `perf annotate` around `model_rd.rs:706`.
2. If `F` is below a few percent, or `compute_variance_8x8` is no longer in the
   top-N after SAD/convolve/sub-pel were SIMD-ported, **cancel PR5** — the speed
   campaign's real lever is Phase-2 (52.7 % partition double-pick).

Everything below is contingent on step 1 showing `compute_variance_8x8` is still a
meaningful, **overhead-bound** (not memory-bandwidth-bound) slice of the profile.
See §1.2 for the bandwidth question, which step 1's microbench must also settle.

### 1.1 The structural cost (assuming §1.0 clears)

`compute_variance_8x8` (`model_rd.rs:578-621`) is the per-leaf variance grid loop
for ≥32×32 blocks. It looks like this today:

```rust
// reduce = SimdDispatch::get_var_sse_8x8 slot (fn pointer), hoisted once.
for i in 0..nh {
    for j in 0..nw {
        let k = i * nw + j;
        let s_off = (i * 8) * src_stride + j * 8;
        let p_off = (i * 8) * pred_stride + j * 8;
        let (cell_sum, cell_sse) =
            reduce(&src[s_off..], src_stride, &pred[p_off..], pred_stride); // indirect call per cell
        sse8x8[k] = cell_sse;
        sum8x8[k] = cell_sum;
        let k_sqr = ((cell_sum as i64 * cell_sum as i64) >> 6) as u32;       // finisher (scalar, untouched)
        var8x8[k] = if cell_sse > k_sqr { cell_sse - k_sqr } else { k_sqr - cell_sse };
        total_sse += cell_sse as u64;
        total_sum += cell_sum as i64;
    }
}
```

**The one real cost: the per-cell call cannot be inlined.** `reduce` is a dispatch
function pointer resolved at `OnceLock` init. The pointer lookup is already hoisted
out of the loop, and the indirect *branch* is near-free — a single, repeated
target is predicted essentially perfectly by the BTB after the first iteration.
The cost is **not** misprediction; it is that the callee
(`get_var_sse_8x8_avx2` → `var_sum_sse_inner`) is a separate `#[target_feature]`
function reached through a pointer, so **the compiler cannot inline it**. Each cell
therefore pays:

- a full call prologue/epilogue (16× for 32×32, 64× for 64×64), and
- re-setup of the loop-invariant `ones16 = _mm256_set1_epi16(1)`
  (`variance_avx2.rs:139`) that cannot be hoisted across an opaque call.

Moving the cell loop into one dispatched kernel turns 16/64 indirect, un-inlinable
calls into **one** indirect call per block, with the per-cell reduction becoming a
**direct** call the compiler can inline and hoist around.

### 1.2 What this does NOT fix (stated honestly so the win is not over-sold)

- **Horizontal reductions are unchanged at 2 per cell.** `var_sum_sse_inner`
  keeps two independent accumulators — `sum_acc` and `sse_acc` — and reduces each
  with its own `hsum256_epi32` (`variance_avx2.rs:188-189`). A grid kernel must
  still produce both `(sum, sse)` per cell, so it still does **2 hsum256 per
  cell**, exactly as today. V1's claim of "one hsum per cell (down from two)" was
  arithmetically wrong: sum and sse are distinct registers and cannot be reduced
  in one call. **This design saves zero hsum operations.**
- **No cross-cell row-load reuse.** Horizontally-adjacent cells share source rows,
  but the simple kernel calls `var_sum_sse_inner(8,8)` per cell, which loads each
  cell's own 8 bytes per row. The theoretical win (one wide load feeding several
  cells) is **not pursued here**: it requires per-cell-column accumulators and
  lane masking (V1's withdrawn "Option B"), the loads are already L1-resident, and
  the added complexity/spill risk is not worth a marginal, unproven gain. If a
  future microbench shows row-reuse is worth it, that is a **separate PR**, not a
  fork inside this one.
- **It cannot beat a memory-bandwidth bound.** `compute_variance_8x8` streams the
  full src+pred for the block (64×64 = 16 KB touched) at ~2 ops/byte — low
  arithmetic intensity. If the kernel is bandwidth-bound, removing call overhead
  changes nothing. §1.0's microbench (cache-resident vs cold, observed IPC) must
  confirm the per-cell version is actually stalling on the call boundary, not on
  loads, or this PR has no headroom.

## 2. Prior art (the pattern is in-tree and proven)

- **PR4** wired the per-cell `get_var_sse_8x8` slot and proved the byte-identity
  story end-to-end: per-kernel differential tests assert the AVX2 `(sum, sse)`
  equals the scalar accumulation exactly; the cross-process `RVP9_FORCE_SCALAR`
  oracle (PR1, `caps.rs:55-63`) confirms the AVX2 IVF byte-equals the scalar IVF.
  **PR5 inherits both layers unchanged** — the grid kernel must satisfy the same
  equality vs the same scalar reference.
- **The grid kernel is a thin wrapper over an already-proven core.** It does not
  re-derive any reduction math: it calls `var_sum_sse_inner(8,8)`
  (`variance_avx2.rs:125`), the exact function the current per-cell slot already
  uses. Byte-identity is therefore inherited by construction, not re-argued.
- **libvpx prior art.** `vpx_dsp/x86/variance_avx2.c::vpx_get8x8var` is the
  per-cell kernel PR4 mirrored; libvpx's pickmode also loops cell-by-cell. Pulling
  the loop into one dispatched call is a packaging change, not a new algorithm.

## 3. Goal & non-goals

**Goal.** Replace the per-cell dispatch with a single block-level grid slot.
Add `get_var_sse_8x8_grid_avx2` (an inlinable cell loop over `var_sum_sse_inner(8,8)`)
and its scalar reference, wire one `get_var_sse_8x8_grid` dispatch slot, and
re-point `compute_variance_8x8` at it. Keep the scalar finishers
(`compute_variance_8x8`'s abs-diff `>>6`, the `total_sse`/`total_sum`
accumulation, and downstream `aggregate_to_tx_size`) **byte-for-byte untouched**.
Bitstream byte-identical before/after.

**Non-goals.**
- No decision change. PR5 is a pure latency optimization; per-cell `(sum, sse)`
  is unchanged.
- No per-cell-column accumulators, no lane masking, no Option A/B fork (all
  withdrawn from V1).
- No cross-cell row-load reuse (see §1.2 — deferred to a possible future PR).
- No HBD. The encoder is 8-bit; HBD path stays scalar.
- No speculative size genericity. The kernel is asserted to the **4 reachable
  shapes** (`bw, bh ∈ {32, 64}`); see §4.3.

### 3.1 Why byte-identity (and what it costs us)

Byte-identity is a **deliberate de-risking choice**, not a law of nature.
`compute_variance_8x8` feeds an RD *model* (a skip / TX-size heuristic), not a
reconstruction path; its finishers are already `>>6` approximations. A
*quality-gated, non-byte-identical* variance (or a cheaper approximate variance)
could in principle yield a much larger speedup at negligible BD-rate cost, bounded
by the existing PSNR/SSIM oracles. We **explicitly defer** that larger lever:
PR5's value proposition is "zero-risk tightening", and byte-identity is what makes
it zero-risk and reviewable in one sitting. The cost of that choice is a **low
ceiling** — PR5 can only re-package the same integer ops, which (§1.2) may be
near-zero gain. The lead should weigh "safe-but-small PR5" against "skip to a
quality-gated variance or to Phase-2" with this ceiling in mind.

## 4. Design

### 4.1 The grid kernel

```rust
/// AVX2 unsafe core: per-8×8-cell `(sum, sse)` reduction over a `bw × bh` region.
/// `bw, bh ∈ {32, 64}` (the only shapes reaching the one caller); `nw = bw/8`,
/// `nh = bh/8`. Writes per-cell `(sum, sse)` in row-major order (`k = i*nw + j`),
/// byte-exact with calling the per-cell `var_sum_sse_inner(8,8)` `nh*nw` times.
///
/// # Safety
/// AVX2 must be available. `src.len() >= (bh-1)*src_stride + bw`,
/// `pred.len() >= (bh-1)*pred_stride + bw`, `sse_out.len() == sum_out.len() == nw*nh`.
#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
unsafe fn get_var_sse_8x8_grid_inner(
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
    sse_out: &mut [u32], sum_out: &mut [i32],
) {
    debug_assert!(matches!(bw, 32 | 64) && matches!(bh, 32 | 64));
    let nw = bw / 8;
    let nh = bh / 8;
    debug_assert_eq!(sse_out.len(), nw * nh);
    debug_assert_eq!(sum_out.len(), nw * nh);
    debug_assert!(src.len() >= (bh - 1) * src_stride + bw);
    debug_assert!(pred.len() >= (bh - 1) * pred_stride + bw);

    for i in 0..nh {
        for j in 0..nw {
            let k = i * nw + j;
            let s_off = (i * 8) * src_stride + j * 8;
            let p_off = (i * 8) * pred_stride + j * 8;
            // Direct call: same #[target_feature] fn, so the compiler INLINES it
            // and hoists the invariant `ones16` setup out of this loop. Each cell
            // keeps only its own (sum_acc, sse_acc) live — 2 accumulators total,
            // no register spill.
            let (sum, sse) = var_sum_sse_inner(
                &src[s_off..], src_stride, &pred[p_off..], pred_stride, 8, 8);
            sum_out[k] = sum as i32;
            sse_out[k] = sse as u32;
        }
    }
}

/// Thin safe wrapper installed in the dispatch slot (mirrors `var_sum_sse_avx2`,
/// `variance_avx2.rs:200`). The slot holds this, never the unsafe `_inner`.
#[cfg(target_arch = "x86_64")]
pub fn get_var_sse_8x8_grid_avx2(
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
    sse_out: &mut [u32], sum_out: &mut [i32],
) {
    // SAFETY: installed only on AVX2 hosts by SimdDispatch::build (caps.avx2).
    unsafe {
        get_var_sse_8x8_grid_inner(
            src, src_stride, pred, pred_stride, bw, bh, sse_out, sum_out)
    }
}
```

That is the whole kernel: a double loop calling the proven inner. No 2-D
accumulator sweep, no lane discipline, no masks, no spill. The per-cell `&src[s_off..]`
sub-slice bounds-checks the start; the SIMD load preconditions are debug-asserted
at entry. Two accumulators are live at any moment (inside one inlined
`var_sum_sse_inner`), so the 64×64 case has the same register pressure as today.

### 4.2 Why this is byte-identical

`get_var_sse_8x8_grid_inner` calls `var_sum_sse_inner(8,8)` — the **same**
function the current per-cell slot calls — once per cell, in the **same**
`k = i*nw + j` order. The integers it writes are therefore *definitionally* equal
to `nh*nw` per-cell calls. The scalar reference (§4.4) loops the existing scalar
`get_var_sse_8x8`, equal to the per-cell scalar path by the same argument. The
differential test (§5.1) pins the two against each other.

### 4.3 Size domain (no speculative generality)

`compute_variance_8x8`'s only caller is `model_rd_for_sb_y_large`
(`model_rd.rs:688`, dispatched at `inter.rs` only for `block_size ≥ Block32x32`),
so the reachable shapes are exactly **32×32, 32×64, 64×32, 64×64** →
`nw, nh ∈ {4, 8}`, 4 grid shapes (max 64 cells). VP9 has no 24/40/48/56-wide
blocks reaching this path. The kernel is `debug_assert!(matches!(bw, 32|64) &&
matches!(bh, 32|64))` — exactly the live domain, mirroring how `var_sum_sse_inner`
asserts `w ∈ {4,8,16,32,64}`. No generality is built for shapes that cannot occur.

### 4.5 Call-site rewiring

In `compute_variance_8x8` (`model_rd.rs:578`), replace the per-cell loop with one
slot call + the unchanged finisher:

```rust
fn compute_variance_8x8(
    grid: CellVarGridFn,            // was: reduce: fn(&[u8],usize,&[u8],usize)->(i32,u32)
                                    //      (a bare fn-ptr inline at model_rd.rs:579,
                                    //       NOT the CellVarFn alias)
    src: &[u8], src_stride: usize,
    pred: &[u8], pred_stride: usize,
    bw: usize, bh: usize,
) -> (u64, i64, [u32; 64], [i32; 64], [u32; 64]) {
    let nw = bw / 8;
    let nh = bh / 8;
    debug_assert!(nw * nh <= 64);

    let mut sse8x8 = [0u32; 64];
    let mut sum8x8 = [0i32; 64];
    let mut var8x8 = [0u32; 64];

    // ONE dispatched call — fused per-cell (sum, sse) reductions.
    grid(src, src_stride, pred, pred_stride, bw, bh,
         &mut sse8x8[..nw*nh], &mut sum8x8[..nw*nh]);

    // FINISHER — byte-for-byte unchanged from PR4. The accumulation is split into
    // its own loop; this is byte-identical because u64/i64 integer addition is
    // associative and the cell visitation order (k = i*nw + j) is preserved.
    // The read-back of sse8x8/sum8x8 is ≤512 B from L1 (64 cells × 8 B) — a
    // negligible round-trip, not a new bandwidth cost.
    let mut total_sse: u64 = 0;
    let mut total_sum: i64 = 0;
    for k in 0..(nw * nh) {
        let cs = sum8x8[k];
        let csse = sse8x8[k];
        let k_sqr = ((cs as i64 * cs as i64) >> 6) as u32;
        var8x8[k] = if csse > k_sqr { csse - k_sqr } else { k_sqr - csse };
        total_sse += csse as u64;
        total_sum += cs as i64;
    }

    (total_sse, total_sum, sse8x8, sum8x8, var8x8)
}
```

The caller hoist (`model_rd.rs:706`) becomes
`let grid = crate::dsp::get_ref().get_var_sse_8x8_grid();`.

The two unit tests at `model_rd.rs:1545,1564` currently do
`let reduce = crate::dsp::distortion::get_var_sse_8x8;` and pass it to
`compute_variance_8x8`. Because the first parameter's **arity changes** (per-cell
`fn` → grid `CellVarGridFn`), these are **rewritten** to pass
`get_var_sse_8x8_grid_scalar` with the new call shape — *not* a symbol swap. Their
concrete assertions (e.g. `sse=256, sum=128, var=0` per cell) are **unchanged** and
still hold, because the grid scalar ref delegates to the same `get_var_sse_8x8`.

## 5. Test plan

Two layers, mirroring the PR4 plan.

### 5.1 Per-kernel equivalence (unit oracle)

A differential test in `variance_avx2.rs` asserting **grid AVX2 == grid scalar**,
byte-exact, over:

- **The 4 reachable shapes** `(bw, bh) ∈ {32, 64}²` (the live domain; §4.3).
- **Randomised inputs** (the existing LCG, `variance_avx2.rs:292`) **≥512 iters
  per shape** — matching the existing `differential_random_all_sizes` (512) rather
  than regressing rigor on a byte-identity kernel.
- **Non-contiguous strides** — `src_stride > bw`, `pred_stride > bw` (the realistic
  raster call pattern).
- **A dedicated cross-cell isolation sweep** (the kernel's only real failure mode
  is a cell's bytes leaking into a neighbour's output). For each shape, set exactly
  one cell to max-diff (`src=0, pred=255`) and all other cells to `diff=0`, sweep
  the hot cell across all `nw*nh` positions, and assert **only** that cell's
  `(sum, sse)` is non-zero. This pins the row-major write-index (`k = i*nw + j`)
  directly; random content masks an off-by-one.
- **Corner inputs** — all-zero, all-255, max-diff whole block.
- **Assertion shape:**
  ```rust
  let mut sse_a = [0u32; 64]; let mut sum_a = [0i32; 64];
  let mut sse_s = [0u32; 64]; let mut sum_s = [0i32; 64];
  get_var_sse_8x8_grid_avx2(&src, ss, &pred, ps, bw, bh, &mut sse_a[..n], &mut sum_a[..n]);
  get_var_sse_8x8_grid_scalar(&src, ss, &pred, ps, bw, bh, &mut sse_s[..n], &mut sum_s[..n]);
  assert_eq!(&sse_a[..n], &sse_s[..n], "sse mismatch {bw}x{bh}");
  assert_eq!(&sum_a[..n], &sum_s[..n], "sum mismatch {bw}x{bh}");
  ```
- **Buffer-tight safety case** — one iteration with `src_stride == bw`,
  `pred_stride == bw`, and `len == (bh-1)*stride + bw` (no padding), to exercise
  the bottom-right cell against the buffer end. (The 8-byte `_mm_loadl_epi64` in
  `var_sum_sse_inner`'s `tail==8` path reads exactly 8 bytes, so this is safe; the
  test documents it. Run the suite under Miri/ASAN where available.)
- **Dispatch round-trip** — replace the deleted per-cell sub-test
  (`variance_avx2.rs:470-480`) with the grid slot: `build(avx2:true)` vs
  `build(avx2:false)` must produce identical out-arrays.

### 5.3 Speed measurement (success criterion — statistically powered)

V1's "median of three runs" cannot resolve a 2–4 % effect: encoder fps run-to-run
variance on a loaded box (thermal/turbo/scheduler) routinely exceeds 3 %.
Byte-identity tests will **not** catch a *slowdown*. So the gate is:

1. **Re-baseline first** (§1.0): report `compute_variance_8x8`'s measured self-cost
   fraction `F`. If `F` is small, stop here.
2. Pin the CPU (fixed frequency / turbo off / `taskset` to isolated cores).
   Foreman 320×256 + testsrc_720p30 (the better ≥32×32 stress), cpu7 CBR @
   {100k, 250k, 500k, 1000k, 2000k}. **≥10 runs**; report median **and** a
   bootstrap / Mann-Whitney CI plus the observed per-run stddev.
3. **Ship-gate (all required):**
   - Both oracles green (IVF byte-identical, both clips).
   - `cross_decoder_gate` 4/4.
   - Median **≥ +3 %** fps over PR4 baseline **AND** the CI lower bound clears 0
     (no-regression guard: a CI that includes a regression ⇒ hold, even if the
     median looks positive).
4. **No regression on any clip.**

**Honest expectation.** With the hsum-halving and row-reuse claims removed (§1.2),
the only saving is the per-cell call boundary + invariant-setup elision — plausibly
10–30 % of the per-cell reduction's *own* time, which is itself only fraction `F`
of encode. The realistic overall win is **likely below the +3 % gate**, so the
**expected outcome is hold-and-report**, with Phase-2 (52.7 %) as the real lever.
This PR ships only if the measurement surprises us upward.

## 7. Risks & rollback

| # | Risk | Handling |
|---|---|---|
| R1 | A per-cell `(sum, sse)` is written to the wrong `k` (cells swap). | §5.1 cross-cell isolation sweep asserts only the single hot cell is non-zero across all `nw*nh` positions, for all 4 shapes — a direct pin on the `k = i*nw + j` write index. The full-array differential vs the scalar ref blocks any other mismatch. |
| R2 | Overflow where the per-cell call wouldn't. | Impossible by construction: the kernel calls the **same** `var_sum_sse_inner(8,8)` per cell, with the same `i32`/`u32` cast, and never accumulates across cells. For an 8-bit 8×8 cell, `diff ∈ [-255,255]`, `|sum| ≤ 16320` (fits `i32`), `sse ≤ 64·65025 = 4,161,600` (fits `u32`); each mid-cell `i32` madd-lane partial ≤ `8·4·65025 ≈ 2.08M` (within `i32`). Integer add is associative, so order is irrelevant. |
| R3 | Memory safety / OOB read in the AVX2 kernel. | The per-cell `var_sum_sse_inner(8,8)` uses `_mm_loadl_epi64` (exactly 8 bytes/row, `variance_avx2.rs:166-168`) — no over-read past the cell. Kernel entry `debug_assert`s `src.len() ≥ (bh-1)*src_stride + bw` and the `pred` analogue; §5.1's buffer-tight case (`stride == bw`, no padding) exercises the bottom-right edge under Miri/ASAN. |
| R4 | The win is below +3 % (or `compute_variance_8x8` isn't even hot anymore). | The **expected** case. §1.0 re-baseline and §5.3's powered gate catch it; **hold and report**, keep the current per-cell path. No production change ships. |
| R5 | The fusion is a *pessimization* (two-pass round-trip, or kernel is bandwidth-bound). | §5.3's no-regression CI guard blocks shipping a slowdown that byte-identity tests cannot see. §1.2/§4.5 bound the round-trip at ≤512 B L1; §1.0's microbench settles the bandwidth question before code. |

**Rollback.** Single PR; reverting it restores the per-cell slot and
`model_rd.rs:706`. (Trivial in a dev sandbox; no migration concerns.)

## 8. Executive summary (for the lead)

- **What.** Pull `compute_variance_8x8`'s per-cell loop into one dispatched grid
  kernel that loops the existing `var_sum_sse_inner(8,8)` *inline*. 16/64 indirect,
  un-inlinable per-cell calls become **one** indirect call per block plus inlinable
  direct reductions.
- **The win is small and honestly bounded.** It does **not** halve horizontal
  reductions (still 2 hsum/cell) and adds **no** row-load reuse — V1 claimed both;
  both were wrong. The only saving is call-overhead + invariant-setup elision.
- **Byte-identity by construction.** The kernel calls the same proven inner per
  cell in the same order; the three scalar finishers stay verbatim; the
  `RVP9_FORCE_SCALAR` IVF oracle is the gate, unchanged.
- **Measurement-gated.** The V1 justification (37.4 %) was a misattributed,
  pre-Phase-1 whole-leaf number; the "10–15 %" Amdahl input was invented.
  **§1.0 mandates re-baselining `compute_variance_8x8`'s self-cost first.** The
  expected outcome is **hold-and-report** (likely `<+3 %`); ship only on a powered,
  no-regression `≥+3 %`.
- **Simpler than V1.** ~185 LOC (vs ~370), no lane discipline, no Option A/B, no
  register spill, no unreachable-size generality, and it **deletes** the now-dead
  per-cell slot.
- **Phase 2 (the 52.7 % partition double-pick) remains the real lever.** If §1.0
  shows `compute_variance_8x8` is no longer hot, skip PR5 and go straight there.

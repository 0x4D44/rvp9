# HLD --- Inter transform-size RD selection (BD-rate)

**Date:** 2026-05-30
**Status:** DESIGN ONLY --- no production code. Team-lead sign-off required before any implementation.
**Author:** investigation pass (read-only).
**Scope:** the INTER luma transform-size decision only. Not partition. Not KF/intra (intra already has its own `choose_intra_luma_tx_size` RD walk). 8-bit Profile 0.

---

## 0. TL;DR for the reviewer (read this first)

The brief assumed the inter TX-size choice is a *heuristic that needs replacing with an RD search*. **The investigation found something different and more important: rvp9 already runs a real per-size RD walk at EMIT time (`choose_inter_luma_tx_size`), and it is the thing producing the 76% TX_4x4 histogram. The picker (both the RT `model_rd` path and the RDO `handle_inter` path) does NOT search TX size at all --- it pins one size and that size is *thrown away*; the emit re-decides independently.**

So this is **not** "add an RD search". It is: **the emit's RD walk is mis-ranking toward small transforms**, most likely because (a) it omits the per-size tx-size **signaling cost** that libvpx charges, and (b) it uses a transform-domain distortion proxy rather than the pixel-domain SSE the rest of the inter picker uses. The fix is to make the emit's existing walk *faithful* (add the signaling cost, reconcile the distortion metric), not to bolt on a second search.

This is a measured-fact-vs-inference distinction the lead must weigh: **measured** = the walk exists and emits 76% 4x4; **inference** = the missing signaling cost is the dominant cause. See §4.6 (NULL) and §7 (open question).

## 1. Problem (measured --- given)

At MATCHED quantizer (rate control removed via the `e9_quality_gap` oracle), rvp9's inter-Y transform-size histogram is overwhelmingly small:

```
inter Y tx hist  [4x4: 87632, 8x8: 23020, 16x16: 4564, 32x32: 83]   (~76% TX_4x4)
```

libvpx at the same matched Q uses far larger transforms. Small transforms on smooth inter residual waste coefficient bits (every 4x4 tile pays its own EOB + context-tree overhead), so rvp9 spends MORE bits at the same Q for LOWER PSNR:

| Q | rvp9 | libvpx |
|---|---|---|
| Q80 | 33,262 b/frame @ 39.96 dB | 30,595 b/frame @ 41.78 dB |

TX-size is a meaningful slice of the ~1.8--2.2 dB matched-Q inter-coding inefficiency. The KF path is fine; the prize is the INTER path. The partition lever is separate and harder --- this HLD is TX-size only, which helps within the current blocks regardless of how partition lands.

## 2. Prior art

### 2.1 How rvp9 chooses inter TX size today (the real, surprising state)

There are THREE places a TX size is computed on the inter path. Two are in the *picker* and are effectively dead with respect to the wire; one is in the *emit* and is the one that actually decides what gets coded.

#### (a) RT picker --- `model_rd::calculate_tx_size` (HEURISTIC, capped, discarded)

`crates/rvp9-core/src/mode_decision/model_rd.rs:179-210`. A variance/SSE-ratio heuristic, a faithful port of libvpx `calculate_tx_size` (`vp9_pickmode.c:354-385`):

```rust
let tx_size = if sse > (var << 2) {
    // High SSE relative to variance -> big transform.
    ... max_txsize(bsize) capped by tx_mode_to_biggest_tx_size ...
} else {
    TxSize::Tx8x8
};
// Limit to TX_16X16 ...
if (tx_size as u8) > (TxSize::Tx16x16 as u8) { TxSize::Tx16x16 } else { tx_size }
```

This is a HEURISTIC, not an RD search, and it is **capped at TX_16X16** (`model_rd.rs:196`). It is used inside `mode_decision::inter` (`inter.rs:2592` `let tx_size = mrd.tx_size;`) only to size the picker's own round-trip distortion estimate. **It does not flow to the wire.**

#### (b) RDO picker --- `handle_inter` (pins ONE size, discards it, signaling cost dead)

`crates/rvp9-encoder/src/rdo/handle_inter.rs`. At `speed.unsigned_abs() <= 4` the leaf picker is the real RDO path (`pick_inter_sb_leaf`, `inter_dispatch.rs`). It calls `evaluate_filter_rd` -> `plane_super_block_yrd` with `y_tx = max_txsize(params.bsize)` (`handle_inter.rs:783`). There is a full libvpx-faithful TX-search primitive available (`rdo/block_yrd.rs::choose_tx_size_from_rd`, a port of `vp9_rdopt.c:907-1023` --- it walks sizes, composes RD *with* `tx_size_cost` and the skip-flag cost, returns the RD winner). **But `plane_super_block_yrd` deliberately PINS it off:**

```rust
// handle_inter.rs:947-957
// The reconstruction in `recon` is built at exactly `tx`, so we pin
// `super_block_yrd` to that single size. ... a walk over *smaller*
// sizes (TxModeSelect) would measure against a recon that was
// reconstructed at the wrong size. ...
let _ = tx_mode;
super_block_yrd(input, tx, TxMode::AllowTx32x32, /* inter = */ true, ...);
```

`AllowTx32x32` makes `tx_size_search_range` return `(pin, pin)` (`block_yrd.rs:357-376`) --- a single size = `max_txsize(bsize)`. So the RDO picker evaluates only the max TX. The `tx_size_cost` plumbed all the way from `lib.rs:2613` -> `inter_dispatch.rs:295` -> `handle_inter.rs` is **dead in this path** (it only matters when more than one size is compared). And the picker's chosen size is **not propagated to the emit** either.

#### (c) EMIT --- `choose_inter_luma_tx_size` (the REAL decision, and the one that produces 76% 4x4)

`crates/rvp9-encoder/src/lib.rs:6387-6567`, called at `lib.rs:5284` from the shared emit walk `pick_and_simulate_inter_encode_partitions`. **This is what actually decides the coded TX size.** It walks every candidate from `max_txsize(leaf_bsize)` down to TX_4x4, and for each: forward-DCT + `vp9_quantize_b` per tile, sums `cost_coeffs` (real coef-bit rate, with a leaf-local propagating entropy context) and `vp9_block_error >> shift` (transform-domain distortion), and keeps the min-RD size:

```rust
// lib.rs:6415-6419  --- the RD metric
let rdcost = |rate: u32, dist: i64| -> i64 {
    let rate_term = (rdmult.saturating_mul(i64::from(rate)) + 256) >> 9;
    rate_term.saturating_add(dist << 7)
};
// ... walk max..=Tx4x4, pick best_tx by rdcost(total_rate, total_dist) ...
```

The result is stored on the leaf (`lib.rs:5397 picked_tx_size = chosen_luma_tx`) and signaled on the wire under `tx_mode = TxModeSelect` (`write_inter_block_leaf`, `modes_writer.rs:2114-2156`, via `write_tx_size`). The matched-Q `txsize_hist` the oracle reports is incremented inside this same emit walk (`predstat::record_y_residual`, `predstat.rs:150`), so **the 76%-TX_4x4 number is `choose_inter_luma_tx_size`'s output, full stop.**

#### Picker/emit TX-size consistency note (the prior skip-reconciliation lesson)

The picker (a)/(b) and the emit (c) compute TX size **independently and never reconcile**. The picker's `tx_size` is used only to size *its own* RD estimate; the emit re-derives from scratch. This is the same shape of divergence the S2 skip-gate work hit: the picker's skip prediction (variance model) diverged from the emit's real DCT/quant_b eob, and the team had to make the picker honest (`inter.rs:2605-2637`, "S2 AcDc resolution --- always run the DCT round-trip"). **The same pattern applies here:** any change that improves the emit's TX RD ranking will *not* be seen by the picker's mode/MV decision, and any change to the picker's TX size is moot unless it is plumbed into and honored by the emit. The design below treats the **emit walk as the single source of truth** and explicitly does *not* introduce a second, divergent search.

### 2.2 What the missing signaling cost does to the ranking (the core inference)

VP9 signals per-block tx_size as a sequence of binary "is it still the bigger size?" decisions under `tx_probs` (`tx_size_costs`, `symbol_costs.rs:200-233`; `write_tx_size`, `mode_info.rs:745`). libvpx charges this `r_tx_size` cost in `choose_tx_size_from_rd` for **every** candidate (`block_yrd.rs:214-228` ports this faithfully: `r1 = r0 + r_tx_size`, and the skippable branch adds it for intra). rvp9's emit walk (`choose_inter_luma_tx_size`) **does not add `tx_size_cost` to any candidate.**

Why this biases toward 4x4 (inference): the signaling tree's cost is **not flat** across sizes --- under the default `tx_probs` the cost of coding "the smaller size" is generally *higher* than coding "the biggest" (the tree's first bit favors the max). By omitting that cost, the emit makes the smaller sizes look artificially cheap relative to coding them on the wire. Combined with a transform-domain distortion proxy (`block_error >> 2`) that under-weights the energy-compaction benefit of large transforms on smooth residual, the walk tilts to 4x4. This is the leading hypothesis; the NULL (§4.6) covers the case where it is wrong.

### 2.3 libvpx's inter TX-size RD (faithful summary)

libvpx good-quality path: `super_block_yrd` (`vp9_rdopt.c:1025`) -> `choose_tx_size_from_rd` (`vp9_rdopt.c:907-1023`).

- **Range.** `tx_size_search_range` walks from `max_tx_size` down to a depth-bounded min (under `TxModeSelect`); other tx modes pin one size. The allowed max per block is the VP9-spec `max_txsize_lookup[bsize]` (4x4 only for sub-8x8; 8x8 for 8x8; 16x16 for 16x16; 32x32 for >=32x32).
- **Per size.** `txfm_rd_in_plane` runs fdct+quant over every tile of that size and accumulates `(rate, dist, sse, skippable)`: `rate` = sum of `cost_coeffs` (the exact coef-prob-tree cost), `dist`/`sse` from `dist_block`.
- **Compose.** For each size it forms two candidate RDs: `r0` (coef bits) and `r1 = r0 + r_tx_size` (coef bits **plus the tx-size signaling bit**). Skippable blocks compare `RDCOST(s1, sse)` (charge the skip flag, distortion = sse). Non-skippable compare `RDCOST(r1 + s0, dist)` (coef + tx-size + not-skip flag). The size minimizing the composed RD wins, and `r_tx_size` for the winner is folded into the returned rate.
- **Realtime path.** `vp9_pickmode.c` does NOT RD-search tx size; it uses the variance heuristic `calculate_tx_size` (rvp9 ported this as (a) above). The RD walk is a good-quality (`cpu-used <= 4`) feature, gated by `cpi->sf.tx_size_search_method` (`USE_FULL_RD` vs `USE_LARGESTALL`).

**rvp9 already has a faithful port of the entire mechanism** in `rdo/block_yrd.rs::choose_tx_size_from_rd` --- including the `r_tx_size` charge and the skip-flag composition. It is unit-tested (`block_yrd.rs:414` `w4_1_super_block_yrd_picks_smallest_rd`) but is pinned to a single size by its only caller (§2.1b) and is **not** the function the emit uses (the emit has its own hand-rolled, signaling-cost-free walk in `lib.rs`).

## 3. Design

**Principle:** make the **emit walk** faithful and authoritative; do not add a second search. The emit (`choose_inter_luma_tx_size`) is already the place that decides and signals the coded size, the histogram is keyed off it, and the picker's size is discarded anyway. Fixing the emit moves the wire directly.

### 3.1 Allowed sizes per block (VP9 spec --- already correct)

The walk's range `0..=max_txsize(leaf_bsize)` is already spec-correct (`max_txsize` = `max_txsize_lookup`): sub-8 leaves return TX_4x4 immediately (`lib.rs:6407`); 16x16 walks {16,8,4}; 32x32 walks {32,16,8,4}; 64x64 leaves go through the picker fallback today (out of `handle_inter` scope) but the emit walk handles them by tiling. **No change needed here** --- the bug is in the RD ranking, not the candidate set.

### 3.2 Add the tx-size signaling cost (the primary fix)

In `choose_inter_luma_tx_size`, charge the per-candidate `tx_size_cost` the way libvpx does. The cost table already exists (`rvp9_core::cost::tx_size_costs`) and a flat `[u32; 4]` per-size row is already computed for the picker (`lib.rs:2613 rdo_tx_size_cost`, ctx=0, max=TX_32X32). Thread it into `choose_inter_luma_tx_size` and add `tx_size_cost[tx_size as usize]` to `total_rate` (or to the composed RD) for each candidate before `rdcost`. This mirrors `choose_tx_size_from_rd`'s `r1 = r0 + r_tx_size` (`block_yrd.rs:216`).

Two faithfulness sub-decisions for the lead:

- **Context.** libvpx indexes `tx_size_cost[max_idx][ctx][actual]` with the real above/left tx-size context (`get_tx_size_context`). The emit walk runs per leaf without that neighbour context wired in; using ctx=0 (as the picker already does) is a documented approximation. RECOMMEND ctx=0 for v1 (the *relative* cost across sizes is what drives the argmin, and the ctx mostly shifts the level), and wire real context only if the NULL probe shows the size decision is context-sensitive. (Honest: the emit *does* maintain a leaf-local above/left coef context for `cost_coeffs`; the tx-size context is a different neighbour lookup and is not currently available at this call site.)
- **Skip-flag composition.** libvpx's compose also folds the skip-flag cost (`s0`/`s1`) and treats skippable sizes specially (distortion = sse). The emit walk does not model the skip flag at all (skip is decided elsewhere, `leaf_total_eob` at `lib.rs:5382`). For the SIZE argmin the skip-flag term is *common across sizes that are all non-skippable*, so it largely cancels; it only matters when some candidate sizes are skippable and others are not. RECOMMEND v1 adds `tx_size_cost` only (the dominant missing term) and leaves the skip-flag composition out, matching the emit's existing skip handling, with a note to revisit if the NULL probe shows skippable-size crossover is material.

### 3.3 Reconcile the distortion metric (secondary fix --- gated on the NULL probe)

The emit walk uses **transform-domain** distortion (`vp9_block_error >> shift`, `lib.rs:6516-6519`). The rest of the inter picker uses **pixel-domain** SSE-of-recon (the F8.0/F8.1 decision, `inter.rs:48-57`). libvpx's `dist_block` has both branches; transform-domain is the faithful good-quality choice when `tx_type` is orthonormal, so this is *probably* fine. But if §3.2 alone does not move the histogram enough (the NULL fires), the second lever is to switch the emit walk's distortion to pixel-domain recon SSE (`dist_block_pixel_domain` already exists, `rdo/block_yrd.rs:101`), which would require building a per-candidate recon (the IDCT-add round-trip per size --- more work, see §6 speed). RECOMMEND: **do not** change the distortion metric in v1; hold it as the first fallback if §3.2 under-delivers.

### 3.4 Picker/emit consistency (do NOT diverge)

Keep the **emit as the single source of truth** for the coded TX size. Concretely:

- Do NOT add a separate TX-size search in the picker (`handle_inter` / `model_rd`). The picker's TX size remains an internal RD-estimation detail; it never reaches the wire and reconciling it is unnecessary complexity (and risks the S2-style divergence in reverse).
- The picker keeps pinning max for its own round-trip estimate (a known, documented approximation `inter.rs:44-47`). Its mode/MV ranking is computed against a max-TX residual estimate; the emit then picks the real coded TX size. This is *already* how the encoder behaves; §3.2 does not change the picker at all, so there is no new divergence introduced. (The existing picker-vs-emit TX gap is pre-existing and out of scope --- closing it is a separate, larger task; flag for the lead in §7.)
- The decoder re-derives nothing about TX size beyond reading the signaled bits, so as long as `picked_tx_size` (= emit's `chosen_luma_tx`) is what `write_tx_size` emits (it is, `lib.rs:5397` + `modes_writer.rs:2134`), the bitstream stays self-consistent.

### 3.5 Composing with the S2 skip gate + coef path

The emit's skip decision keys off `leaf_total_eob` (`lib.rs:5382`), computed AFTER the TX size is chosen (the residual is re-emitted at `chosen_luma_tx`). Changing the TX *size* changes the per-tile eobs and therefore the skip outcome --- this is expected and correct (a 16x16 transform that quantizes to all-zero is a legitimate skip the 4x4 walk would have coded as 16 EOB charges). The coef path (`inter_forward_quant_one_tx`, `lib.rs:5350`) already re-runs at whatever `chosen_luma_tx` the walk returns, so no plumbing change is needed there. **Risk:** the S2 picker skip-gate (`reconstruct_via_round_trip`, keyed off the picker's pinned-max TX eob) will now disagree more often with the emit's larger-TX eob. This is the same residual divergence S2 already tolerates (the picker's skip is a *prediction*, the emit re-decides); verify it does not worsen via the regression guard's skip/eob fields (§4).

### 3.6 Speed cost and gating

`choose_inter_luma_tx_size` already runs the full walk on every inter leaf at `speed <= 4` (it walks max..4x4 unconditionally today). Adding the `tx_size_cost` term is **O(1) per candidate** --- a table lookup and an add --- so §3.2 is **free** (no new transforms). The expensive option is §3.3 (per-candidate recon), which would add an IDCT-add per size; if pursued, gate it behind `speed <= 2` or `tx_size_search_method == USE_FULL_RD`. The RT/cpu>=6 path uses the variance heuristic (`model_rd::calculate_tx_size`) and is **out of scope** --- it never calls `choose_inter_luma_tx_size`. (Confirm with the lead: §3.2 changes the *emit*, which runs for all speeds that go through `pick_and_simulate_inter_encode_partitions`; verify the RT path's emit is the same walk and that the change is acceptable there, or gate the new term on `rdo_speed_gated` to match the picker. RECOMMEND: apply the `tx_size_cost` term unconditionally in the emit --- it is the *correct* cost regardless of speed, and the RT variance picker is a separate code path.)

### 3.7 Recommended approach (single sentence)

**Add the per-candidate `tx_size_cost` signaling charge to the existing emit walk `choose_inter_luma_tx_size` (ctx=0, signaling-cost only, no skip-flag composition, no distortion-metric change), keeping the emit as the single authoritative TX-size decision; hold the pixel-domain-distortion and skip-flag-composition refinements as gated fallbacks if the NULL probe shows the signaling cost alone is insufficient.**

## 4. Regression guard + oracle (pre-registered)

### 4.1 Primary scaffold --- `e9_quality_gap` (matched-Q)

`crates/rvp9-encoder/tests/e9_quality_gap.rs` already captures, per matched-Q point (Q in {80,120,160}), on foreman_cif (256x256, 64 frames):

- `inter_tx_hist: [u64; 4]` --- the Y inter TX histogram (the direct lever metric).
- `inter_coef_bits` --- coef-token bits per inter frame (bitacct).
- `inter_recon_psnr`, `inter_bits` --- matched-Q reconstruction PSNR and total bits.
- `inter_eob_sum`, `inter_skip_frac` --- skip/eob sanity (for §3.5).

This is the primary oracle. Run: `mdtimeout 600 cargo test --release --test e9_quality_gap -- --ignored --nocapture`.

### 4.2 Success criteria (ALL must hold)

1. **Histogram shifts toward larger transforms.** `inter_tx_hist` moves materially off 76% TX_4x4 toward 8x8/16x16/32x32 (directionally toward libvpx). Pre-register a concrete bar with the lead, e.g. TX_4x4 share drops below 55% at Q120.
2. **Matched-Q coef cost / bits per frame DROPS.** `inter_coef_bits` and `inter_bits` strictly decrease at matched Q (larger TX = fewer EOB/context charges on smooth residual).
3. **BD-rate / matched-bitrate mean-PSNR IMPROVES on foreman.** A matched-bitrate check (encode at a target bitrate, compare mean Y-PSNR) improves, OR the matched-Q PSNR-per-bit improves enough to imply a BD-rate win.
4. **No regression on a 2nd clip.** Repeat on a second clip (e.g. a testsrc/parkjoy crop already in `rvp9-harness`); matched-Q PSNR must not regress and bits must not increase.
5. **`cross_decoder` 4/4.** TX sizes are signaled, so the bitstream CHANGES --- goldens must be re-captured and the cross-decoder (rvp9-encoded -> libvpx-decoded, and round-trip) must pass 4/4.
6. **`decode_failed` 0.** No decode failures across the corpus.

### 4.3 Matched-bitrate check

In addition to matched-Q, run a fixed-target-bitrate encode (RC on) on foreman + the 2nd clip and compare mean Y-PSNR vs the pre-change baseline. This is the closest proxy to BD-rate without a full multi-point sweep; if the lead wants true BD-rate, run 4 bitrate points and compute BD-rate against libvpx.

### 4.4 Anti-gaming / positive control

- **Witness the cause, not just the effect.** Add an assertion-grade probe that the new `tx_size_cost` term is actually being added (e.g. count candidates whose argmin *changed* because of the term). A change that shifts the histogram for an unrelated reason (e.g. a quant bug) would not advance this counter --- it proves the histogram move is *because of the signaling cost*, the anti-G3 discipline used elsewhere (`inter_dispatch.rs` PROOF counters).
- **Bitstream-validity is non-negotiable:** §4.2.5/4.2.6 gate any merge.

| File | Change |

| `crates/rvp9-encoder/tests/e9_quality_gap.rs` | Add 2nd-clip arm + matched-bitrate arm + the §4.2.1 histogram bar (pre-registered) |

### 4.6 Pre-registered NULL

The change FAILS to help if:

- **(N1) The residual genuinely needs 4x4.** If foreman's inter residual is high-frequency/edge-dominated such that 4x4 really is RD-optimal even *with* the signaling cost charged, the histogram barely moves and PSNR/bits are flat. Then the 76% is *correct* and the matched-Q gap lives elsewhere (prediction quality, partition, entropy). ACTION: stop; the lever is smaller than hypothesized; report the corrected attribution.
- **(N2) The cost model mis-ranks TX sizes (the partition lesson).** Exactly as the partition RD probe (`E11`/`E14`) found the cost model could mis-rank shapes, the tx-size cost (or the transform-domain distortion proxy) may mis-rank sizes so that adding the signaling cost shifts the histogram the *wrong* way or hurts PSNR. ACTION: this is the trigger to try §3.3 (pixel-domain distortion) as the fallback; if that also fails, the emit's RD metric itself is the bug, not the missing cost.
- **(N3) Histogram moves but PSNR/bits do not improve.** If larger TX is chosen but matched-Q bits rise or PSNR drops, the distortion side of the RD is wrong (the walk is now over-charging small TX or under-charging large-TX distortion). ACTION: §3.3.

If N1 fires, the honest conclusion is that TX-size is NOT the lever and the brief's premise (mis-ranked toward small TX) is wrong --- the emit was already RD-correct modulo a small signaling term.

## 8. Exec summary (5 bullets)

- **The premise is half-right and the diagnosis is sharper than the brief:** rvp9 already runs a real per-size RD walk at EMIT time (`choose_inter_luma_tx_size`, `lib.rs:6387`) --- it is what produces the 76% TX_4x4. The picker's TX size (RT heuristic capped at 16x16, or RDO pinned to max) is computed and then **discarded**; it never reaches the wire.
- **The emit walk is faithful except for one omission:** it does NOT charge the per-candidate **tx-size signaling cost** that libvpx charges in `choose_tx_size_from_rd` (which rvp9 *has* a faithful port of, in `rdo/block_yrd.rs`, but doesn't use in the emit). Omitting it makes small transforms look artificially cheap --- the leading hypothesis for the 4x4 bias.
- **The fix is ~10 LOC, not a new search:** thread the existing `tx_size_cost` table into the emit walk and add it per candidate. Optional gated fallbacks (pixel-domain distortion, skip-flag composition) are held in reserve for the NULL.
- **Consistency is preserved by design:** the emit remains the single source of truth for the coded TX size (it already is); the picker is untouched, so no new picker/emit divergence is introduced --- avoiding the S2-style reconciliation trap.
- **Pre-registered guard + NULL:** success = histogram shifts large + matched-Q coef-bits drop + matched-bitrate PSNR improves on foreman + no 2nd-clip regression + cross_decoder 4/4 + decode_failed 0, with a cause-witness counter (anti-G3). NULL = the residual genuinely needs 4x4 (N1), or the cost model mis-ranks sizes like it did partitions (N2) --- in which case TX-size is not the lever and the attribution is corrected honestly.

## 9. The single biggest open question for the lead

**Is the missing `tx_size_cost` signaling charge actually the dominant cause of the 4x4 bias, or is the emit walk's transform-domain distortion proxy (`vp9_block_error >> 2`) systematically under-valuing the energy compaction of large transforms on smooth inter residual?** These are the two candidate root causes; §3.2 fixes the first cheaply, §3.3 fixes the second expensively. The NULL probe (§4.6) is designed to discriminate, but if the lead's prior is that the distortion proxy is the real culprit, we should run a quick **diagnostic** first --- log, per leaf, the per-size RD with and without the signaling cost AND with transform-domain vs pixel-domain distortion --- to attribute the bias *before* committing to §3.2, rather than shipping §3.2 and discovering via the NULL that §3.3 was needed all along. **Recommendation: a one-session read-only diagnostic to attribute the cause, then commit to §3.2 or §3.3 with evidence.**

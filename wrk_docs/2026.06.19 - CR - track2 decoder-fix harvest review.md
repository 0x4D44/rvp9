## Pass 1 — track2 decoder-fix harvest (`14f58ad..16801c8`)

### Slice & why

The 06.18 work landed a **track2 decoder-fix harvest** — six decoder correctness
fixes cherry-picked-with-rework onto main (`14f58ad..16801c8`, 17 files, ~1400
lines): SIG1 (reset all `FrameContext` banks on every keyframe), SIG2 (frame-edge
clamp on coef entropy-context writeback + new hand-written intra `max_blocks`
geometry), SIG4 (allow 4:2:2/4:4:0 inter decode), G-A (reject out-of-envelope ref
sizes), G-B (correct y4m chroma tag), G-C (consume per-segment SEG_LVL_REF_FRAME /
SEG_LVL_SKIP + new fallible `?`-propagation). It changes decode state, was manually
reworked during conflict resolution (SIG2's `reconstruct.rs`, G-C's `tile.rs`), the
full conformance gate was deliberately not re-run, and it had **not been
code-reviewed** — the highest-risk recently-landed slice. The prior pass (06.17)
covered the encoder frame-loop / rate-control slice.

### Method

Fanned out 6 reviewer lenses (correctness, safety/security, reliability,
maintainability+perf, test-coverage, devil's-advocate) reading the same slice in
parallel, then adversarially verified each finding with 3 distinct-angle skeptics
(reachability / libvpx-fidelity / code-accuracy). A finding is a **survivor** only
if ≥2 of 3 skeptics fail to refute it. First run was fully rate-limited (all finders
throttled) → discarded as UNVERIFIED, not reported; re-run with low-concurrency
pacing produced **6 raw → 6 deduped → 4 confirmed / 2 refuted / 0 degraded** (24
agents). Team-lead independently read SIG1/SIG2/G-A/G-B/G-C and confirmed the new
intra `max_blocks` geometry is textually identical to the proven inter path.

#### F1 — LF-overlap deadlock on mid-tile decode error (High) → `RVP9-BUG-KILN-00006`

G-C made `decode_inter_partition`/`decode_inter_block` fallible and threaded `?`
into `decode_tile_inter`'s SB-row loop (`tile.rs:1780`), **before** the per-SB-row
`decode_progress` publish (`tile.rs:1785-1793`). When a tile errors mid-frame (the
new `Sub8SegSkip` at `tile.rs:2496-2497` on a malformed stream), the failed tile
never publishes; the LF-overlap worker then spins in `spin_then_yield_wavefront`
with no abort/poison escape (`apply.rs:455-462`), and the decode entry point's
`handle.wait()` join (`lib.rs:3570-3571`) runs *before* `merge_err` is inspected
(`lib.rs:3578-3580`), so the API deadlocks instead of returning `Err`. Default-on
multithreaded path (≥4 cores, `filter_level>0`, `tile_rows==1`, ≥2 tile cols, ≥2 SB
rows). **Pre-existing in class** — the `InvalidTilePayload ?` at `tile.rs:1738`
hangs identically (present at base `14f58ad`) — but G-C adds a new in-loop trigger.
libvpx returns `CORRUPT_FRAME` here, so the hang is a divergence. Escalated to High
(untrusted-input DoS for the WebRTC/livestream target). **Fix at the LF-overlap-infra
layer:** release the wavefront consumer on the error path (advance `decode_progress`
to completion / poison the spin predicate) before returning `Err`. Effort M.
Verify: `RVP9_DISABLE_LF_OVERLAP_POOL=1` makes the error return correctly.

#### F2 — kfonly fix-lock tests left ignored (Medium) → `RVP9-BUG-KILN-00007`

The harvest fixed the tracked T-2 bug, but `profile1_{444,422,440}_kfonly_follow_up`
stay `#[ignore]d` with a now-inverted `assert!(mismatched > 0, "Bug appears fixed —
remove #[ignore]…")` self-check; running them under `--ignored` fails on
`mismatched == 0`. `cargo test --workspace` skips them, so SIG1 multi-keyframe
independence has no committed-vector guard (default vectors are single-keyframe;
fixtures are already committed at CIF 352×288). SIG2 intra partial-edge geometry is
already covered by the default `foreman_c444.ivf` keyframe-0. **Fix (trivial,
test-only):** un-ignore, flip to `assert_eq!(mismatched, 0)`, move to
`PROFILE1_VECTORS` — exactly what the test comment instructs. Effort S. Supersedes
the kfonly portion of the 06.18 scratchpad entry.

#### F3 / F4 — G-C decode_inter_block integration coverage (Low) → `RVP9-BUG-KILN-00008`

The SEG_LVL_REF_FRAME glue (segment-id index, `is_inter` derivation, `from_i8`
mapping, forced-INTRA routing) and the `Sub8SegSkip` guard Err path are never driven
through `decode_inter_block`: the unit oracles hit `read_ref_frames` /
`read_inter_block_mode_info` directly with hand-built params, and the differential
ROI fixture never lands an inter block on the REF_FRAME segment or a sub-8
SEG_LVL_SKIP block. Both branches verified **correct/libvpx-faithful** — a pure
coverage gap on author-flagged-TODO code that is effectively dead on all current
real-world/conformance content. **Fix:** a fixture or a `decode_inter_block`-level
integration test. Effort L. Resolves the in-code `TODO(G-C verify)`.

### Verdict on the slice

The six harvested fixes are **substantively sound**: SIG1, SIG2 (incl. the
hand-written intra geometry), SIG4, G-A, G-B and the G-C force logic are all
libvpx-faithful and correctly implemented — no correctness or safety defect was
confirmed in the decode logic itself. The confirmed issues are one **robustness gap
exposed (not originated) by the new fallible control flow** (F1 deadlock) and three
**test-coverage gaps** (F2 the highest-value: a free-to-activate end-to-end guard;
F3/F4 lower). The conformance + longclip re-runs remain the right next safety net
(already tracked in scratchpad).

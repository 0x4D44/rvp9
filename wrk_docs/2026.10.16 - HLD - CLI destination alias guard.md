# CLI destination alias guard

An encoder or decoder destination must not truncate another active path role.
The roles are encoder input, IVF output and optional frame-time CSV, or decoder
input and an explicit output when pixels or hashes are emitted. Pure `--noblit`
continues to ignore its output option.

## Decision and reasoning

Use an early identity preflight plus an identity check on every output handle
before truncation. Open destinations with write/create enabled and truncation
disabled. Compare the resulting handle with the other active roles, then truncate
only a regular file whose identity is distinct. Capture the input identity before
reading and retain the IVF identity for the later CSV check.

The preflight catches existing equal paths, symlinks and hardlinks before input
parsing or output creation. Equal prospective output paths can also be rejected
early. It cannot prove distinctness of two missing names on a filesystem that
folds case or Unicode. Once the IVF has been opened without truncation, querying
the CSV path delegates that comparison to the filesystem. Perform that comparison
before truncating the IVF, as well as before the later CSV write.

This keeps ordinary overwrite semantics, including an output hardlinked to an
unrelated file. Staging and atomic rename would change that behavior and are not
part of this fix. Preserve the decoder's existing late creation: a decode failure
before the first emitted frame leaves the destination untouched.

Unix identities use device and inode numbers. Windows uses a handle query for the
volume serial and 128-bit file identifier, with a small local Kernel32 binding and
no new dependency. Refuse to truncate a regular file if its identity cannot be
established. Do not use a possibly incomplete 64-bit ReFS identity as a successful
fallback. Nonregular sinks such as `/dev/null` retain their existing behavior;
do not call `set_len` on them. Share a private source module between the binaries.

## Failure behavior and limits

An alias error identifies both roles and paths. Existing role contents remain
unchanged. A previously missing destination can become an empty file when its
creation is what makes a future alias observable. Leave that new empty file in
place rather than introducing a racy deletion. This is a rejection with no old
content destroyed, not transactional cleanup of all failed commands.

The contract covers ordinary filesystem aliases. Adversarial concurrent renames
or replacement between path inspection and input opening are outside this fix.
The output comparison nevertheless uses the very handle that will be truncated.
Shell redirection can truncate a file before the CLI starts; stdout-handle alias
inspection is outside the reported explicit-path roles.

## Oracle and tripwires

Actual subprocess tests preserve input and existing output bytes for equal paths,
symlinks and hardlinks across all active roles. Test missing output/CSV aliases,
including dangling symlink chains and runtime-supported case/Unicode equivalents.
Missing aliases may leave only an empty file. Keep independent positive coverage
for distinct outputs, CSV, stdout, inactive decoder output, and nonregular sinks.
Guarded-open tests must demonstrate comparison before truncation. Existing decode
failure preservation coverage must remain green.

Case/Unicode equivalence depends on the fixture filesystem: an unsupported probe
is a reported limitation, not evidence that the alias branch ran. Native Windows
execution is separately distinguished from cross-target compilation.

## Consultation provenance

Claude Opus 5.5 at medium effort supplied the key correctness verdict: pure
preflight is incomplete for two missing outputs, and guarded nontruncating opens
let the filesystem resolve their identity at the necessary moment. Its read-only
consult session was `c7c4f573-eb66-478a-bbe1-68c9b434b61b`, following a successful
model-resolution smoke. No consultant edits or tests were performed.

The lead adopted that recommendation with three refinements: compare other paths
before the IVF truncation itself; use a private shared module; and fail closed on
unavailable Windows regular-file identity rather than accepting a potentially
incomplete legacy identity. The lead owns implementation and verification.

Windows identity layout and semantics are documented by Microsoft:
[FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info)
and [GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex).

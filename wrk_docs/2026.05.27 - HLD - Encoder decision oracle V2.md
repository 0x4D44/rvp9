## 1. Problem

rvp9enc is 86–95 % BD-rate behind libvpx. Our only attribution signal is
end-to-end PSNR, too noisy to localize a defect across thousands of per-block
decisions. Track-F: 8 iterations, +0.74 dB cumulative, per-iter gain now below
the measurement floor. We need to attribute the gap to specific decision
categories so the next fixes are directed.

## 2. Prior art (this is not greenfield)

**E1** (`E1_encoder_gap_analysis.md`, `e1_block_stats.rs`, 672 LOC, May 23)
decoded *both* libvpx's and rvp9enc's IVFs through the same rvp9 decoder and read
per-frame aggregates from `last_frame_mi_grid()`. It found the #1 lever —
**over-partitioning** (rvp9 ~85 % of inter area as 8×8 vs libvpx ~79 % as 64×64,
because rvp9 lacked `vp9_choose_partitioning`) — and finding #3, **keyframe
bit-starvation** (rvp9 KF ~13.7 kbit vs libvpx ~74.5 kbit at 100 kbps). It
flagged the partition (`block_size`) field as **trustworthy** (loop-filter
cross-validated) but the **mode/skip/ref columns as NOT trustworthy** (impossible
80–100 % intra on libvpx inter frames).

**F0.2** (`F0.2_HLD_per_block_oracle.md`, `f02_oracle.rs`, `f02_block_oracle.rs`)
built a per-block decision diff. Its §3.3 **explicitly rejected** "decode
libvpx's IVF through the rvp9 decoder and read decisions" (option a) on the
strength of E1's mode-column problem, and instead **patched libvpx** to emit
picker decisions, plus an env-gated encoder-side sink.

The original draft of this HLD re-proposed option (a) without knowing it had been
rejected. That was the central Round-1 finding.

## 3. Re-examining the rejection (the linchpin)

The F0.2 rejection assumes E1's mode problem is a *decoder bug*. Round-2 code
inspection says it almost certainly is not:

- The published `last_frame_mi_grid` **is the same `ModeInfo`** that the
  per-block decode writes via `write_block` (`tile.rs:858/2223/2278` →
  `TileMiView`, published at `lib.rs:2377`). There is **no separate
  mode-derivation or copy step** between parse and grid that could corrupt modes.
  "The grid is wrong but the parsed local is right" is not a real distinction —
  they are the same value.
- The grid is **pre-filled with padding `Intra{DC,DC}`** for uncovered cells
  (`lib.rs:4309`, "un-covered cells keep the padding default"). E1's
  area-weighted reader most plausibly **counted those padding cells as intra**,
  producing the impossible 80–100 %.

**Implication:** there was likely never a mode-parse bug. The decode-based
approach (option a) is probably clean, and F0.2's libvpx patch may have been
unnecessary. Emitting at the `write_block` site, restricted to *covered* cells,
yields correct modes regardless of the grid-padding question — and the same code
reads both legs, so any residual decoder quirk is common-mode and cancels in the
diff.

This is a hypothesis. **Phase 0 verifies it in ~1 hour with no new decoder code.**

## 4. Goal

Attribute rvp9enc's BD-rate gap to encoder-decision categories (frame-level and
per-block), ranked by **realized rate-distortion cost** (not raw divergence
count), so each fix targets the highest-impact lever.

## 5. Non-goals

- No libvpx patching if Phase 0 passes. No env vars, no feature flags (a
  decode-side diagnostic has no realtime budget, so no gating is needed — unlike
  F0.2's encoder-path sink). No migration/back-compat (dev sandbox). Not a
  BD-rate harness (`bdrate` still measures end-to-end). Not a fix for any
  decoder grid-padding behaviour.

## 6. Phase 0 — THE plan (~1–2 hours, no new tool)

Phase 0 is expected to answer the question on its own. Two checks, run first.

**6a. Mode-sanity spike (gates the decode-based approach).** Add a temporary
debug print at the three `write_block` sites dumping `(mi_row, mi_col, is_inter,
ref_frame, inter_mode, skip)` for **one libvpx inter frame** of `foreman`,
covered cells only. Assert the frame reads **mostly inter** (not 80–100 % intra).
Separately, re-read `e1_block_stats.rs`'s area-weighting to confirm whether it
counted uncovered/padding cells (the suspected E1 artifact).
- **Pass** (mostly inter) → §3 hypothesis holds; decode-based option (a) is
  clean. Discard the temporary print.
- **Fail** (still mostly intra at the covered-cell parse site) → a real parse
  problem exists; fall back to F0.2's libvpx patch for the libvpx leg. Phase 1's
  diff/report design is unchanged; only the libvpx data source changes.

**6b. Re-confirm the dominant lever on TODAY's encoder (HARD gate).** E1 predates
drift fixes, RDO dispatch, rect partitions, ML pruning, and Track-F iters 1–8.
Re-run E1's partition-size + bits histogram on the **current** encoder using only
the *trustworthy* `block_size` field and the IVF packet sizes (no mode data
needed; reuse `e1_block_stats.rs` largely as-is).
- **If over-partitioning (or KF bit-starvation) is still dominant → DO NOT build
  Phase 1.** Port `vp9_choose_partitioning` / fix the KF rate target directly.
  E1 already localized these; the multi-category tool would be solving a problem
  we already understand. This is the most likely — and cheapest — outcome.
- **Only if the gap is now diffuse across categories** (no single lever explains
  the bulk of the excess bits) is the Phase-1 tool justified.

## 7. Phase 1 — the decision oracle (CONDITIONAL on 6b showing a diffuse gap)

### 7.1 Frame-level record (diff these first — chosen before any block, so
directly comparable even after references diverge)

```rust
struct FrameDecision {
    frame_idx: u32,
    frame_type: FrameKind,     // KEY / INTER / INTRA_ONLY / SHOW_EXISTING
    show_frame: bool,          // SHOW_EXISTING/hidden ARF costs ~1 byte; don't double-count
    coded_bytes: u32,          // from IVF packet size — carries E1 finding #3 (KF starvation)
    base_qindex: u8,
    tx_mode: TxMode,
    loopfilter_level: u8,
    interp_filter: InterpFilter, // frame-level: per-block interp only meaningful if SWITCHABLE
}
```

Trimmed from V1's 13 fields. The segmentation arrays, ref-delta/mode-delta,
refresh flags, ref-index map, sign-bias, and compound-ref mode are **added only
if a diff on this core points at segmentation or ref-management** (don't predict
the future). `coded_bytes`, `interp_filter`, `show_frame` are kept because they
are free (header/IVF) and individually decisive.

### 7.2 Per-block record

```rust
struct BlockDecision {
    frame_idx: u32,
    mi_row: u16, mi_col: u16,
    sb_mi_row: u16, sb_mi_col: u16,  // 64x64 anchor for partition grouping
    bsize: BlockSize,                // = the partition outcome
    eff_qindex: u16,                 // get_qindex(seg_alt_q[id], abs_delta, base_q)
    skip: bool,
    tx_size: TxSize,
    bits: u32,                       // APPROXIMATE — see §7.3; ±~1 byte, monotone
    sse_y: u64,                      // computed in the harness, not the decoder (§7.3)
    kind: BlockKind,
}
enum BlockKind {
    Intra { y_mode: PredMode, uv_mode: PredMode },  // uv_mode is count-only (no Y-SSE backing)
    Inter {
        inter_mode: InterMode,                 // NEAREST/NEAR/ZERO/NEW
        ref_frame: [Option<RefFrame>; 2],      // 2nd = Some iff compound
        mv: [Mv; 2],                           // sub-8x8 collapses 4 sub-MVs; flagged, not expanded
        interp_filter: InterpFilter,
    },
}
```

Dropped vs draft: `tx_type` (not an independent decision — intra is a pure
`y_mode` lookup, inter is always DCT_DCT), `partition_path`/`ArrayVec` (partition
fully captured by the leaf multiset). Added: `inter_mode`, `eff_qindex`,
`bits`/`sse_y`.

### 7.3 Decoder integration (corrected + simplified)

Verified against the code:
- Entry is `decode_frame(&mut self, frame: &ParsedFrame<'_>) -> Result<FrameBuf,
  DecodeError>`, dispatching to keyframe / intra-only / inter, each with a
  **parallel (tile-threaded) and a serial** sub-path.
- **Force the serial path, single-threaded** (`Decoder::with_threads(1)`, as the
  conformance harness already does). A diagnostic has no realtime budget. This
  **eliminates** the per-tile `Vec`, the post-join merge/sort, and all `!Send`
  reasoning. Records emerge in MI order directly.
- Thread a single `decisions: &mut Vec<BlockDecision>` from a new
  `decode_frame_traced` entry down through the serial `decode_tile_*` into the
  three `write_block` sites. `decode_frame` is untouched (cross-decoder gate
  remains the regression guard).
- **`bits` is approximate.** The bool-coder (`bool_reader.rs`) is not
  byte-aligned per block and adapts probabilities across blocks. Add
  `fn tell_bits(&self) -> u64 = pos*8 - count` to `BoolReader`; snapshot it
  *before* a block and *after* its coefficient decode; the delta is the block's
  bit count to ±~1 byte. Monotone and sums to the total — adequate for ranking,
  not for exact per-block rate. Because `write_block` runs *before*
  reconstruction, push a partial record at `write_block` and finalize `bits`
  after the coefficient/reconstruct step.
- **`sse_y` is computed in the harness, not the decoder.** The binary has the
  decoded `FrameBuf` and the source y4m; per-leaf SSE = slicing the leaf rect
  `(mi_row, mi_col, bsize)`. Watch the reconstructed plane's padded stride vs the
  source's tight stride, and compare only the visible crop. No decoder hook for
  SSE at all.

### 7.4 `decision-diff` binary

`crates/rvp9-harness/src/bin/decision_diff.rs`:
```
decision-diff <a.ivf> <b.ivf> <source.y4m> [--out report.json]
```
1. Decode A and B traced, single-threaded; compute per-leaf `sse_y` against
   source.
2. **Assert per-frame `frame_type` + `show_frame` alignment** (not just count).
   Stop on mismatch — streams not comparable past that point.
3. Diff `FrameDecision` per frame.
4. Per superblock present in both: compare the leaf multiset
   `(local_offset, bsize)`. If different → partition divergence + count excluded
   leaves (honest denominator). If same → diff each leaf.
5. Emit the ranked report (§7.5), stratified (§7.6).

### 7.5 Metric — Pareto dominance + Σbits (no λ)

- **Pareto-dominance flag per block** (assumption-free, needs no λ, does not
  assume libvpx is optimal): rvp9's block is *strictly worse* iff
  `bits_rvp9 ≥ bits_libvpx` **and** `sse_rvp9 ≥ sse_libvpx` (≥, one strict).
  This answers "is rvp9's choice here actually worse?" — the only actionable
  signal; a mere *difference* from a non-optimal libvpx is not a defect.
- **Rank categories by (count of Pareto-dominated blocks, Σbits in those
  blocks).** `bits` is already plumbed for Pareto; summing it is free. No
  λ-derivation, no ΔJ overlap accounting (dropped from V1 as gold-plating). When
  count and Σbits disagree, Σbits wins.
- **MV pick-vs-context split.** For NEAREST/NEAR/ZERO the MV is *derived* from
  `find_mv_refs` (bitstream signals only the mode index), so an MV divergence is
  a **neighbour-context/cascade symptom**, routed to an `mv-ref-context` bucket.
  Only NEWMV codes an explicit mvd → routed to `mv-search`. This prevents
  misreading a context cascade as a search bug.
- `uv_mode` is reported **count-only** (Y-only SSE gives it no distortion
  backing). State the Y-only bias explicitly.

### 7.6 Cascade handling — stratified report (3 strata)

Report the category ranking for: **(a) keyframe**, **(b) first inter frame**,
**(d) all frames**. (V1's distance-1 stratum (c) dropped — extra bookkeeping for
a band acted on no differently from (b).) If the ranking is stable across
(a)/(b)/(d), the all-frames ranking is trustworthy; if it reorders, act on
(a)/(b) only. ΔJ-style per-block cost is a *local* proxy (a low-SSE block now may
feed worse references later), valid within (a)/(b), which is exactly why the
strata exist.

**Inter analysis gates on KF frame-STATE alignment** — `base_qindex`,
`coded_bytes`, `frame_type` — **not** on per-block KF divergence. KF partitions
*will* differ (over-partitioning), so a per-block KF gate would deadlock; a
differently-partitioned but similarly-coded KF is still a valid reference
baseline.

## 8. Test plan (all four kept — load-bearing, not over-engineered)

1. **Self-consistency:** `decision-diff a a src` → zero divergences. Necessary,
   not sufficient (passes even if the diff always returns zero).
2. **Injected-divergence positive control:** two streams differing in exactly one
   known block decision; assert the report names exactly that category at that
   `(frame, mi_row, mi_col)`, once. This is what proves the attribution works.
3. **Structural invariant:** KF divergence in inter-only categories
   (`ref_frame`/`mv`/`inter_mode`/`interp_filter`) is exactly zero (a KF has no
   inter blocks). Non-zero = tool bug.
4. **Decoder regression:** `cross_decoder_gate` stays 4/4 (`decode_frame`
   untouched).

## 11. Relationship to F0.2 (honest)

This tool **replaces F0.2's diff and (if Phase 0 passes) retires its libvpx
patch + `build_f02_libvpx.ps1` machinery** — that is the duplication resolved.
F0.2's encoder-side thread-local sink is a *different* instrument (it reads the
picker's internal **pre-clamp** decisions, which decode cannot recover, R3); it
is **not** replaced and not maintained unless a specific lever needs pre-clamp
intent. So: this is the primary, decode-based decision oracle; the encoder sink
is a narrower, orthogonal diagnostic retained as-is. (V1's "one oracle, not two"
claim was inaccurate and is withdrawn.)

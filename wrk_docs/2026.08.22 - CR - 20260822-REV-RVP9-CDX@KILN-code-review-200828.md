## Confirmed findings

### High — singular BD-rate curves silently become 0%

- **Confidence:** High
- **Location:** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\bdrate.rs:371`; singular return at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\bdrate.rs:462`; acceptance at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\bdrate.rs:415`
- **Impact:** Four or more RD points can contain fewer than four distinct PSNR values. The cubic solver returns zero coefficients for that rank-deficient matrix, and the caller accepts the resulting finite 0% BD-rate. A quality gate can therefore report equality for an undefined comparison.
- **Fix:** Make the fit fallible or delegate to the shared harness solver. Propagate singularity as measurement failure and add repeated-PSNR regression curves.
- **Effort:** Small
- **Tracking:** `RVP9-BUG-KIL-00107`

### High — corrupt or non-finite throughput CSV rows can pass the ratchet

- **Confidence:** High
- **Location:** raw writer at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\throughput.rs:454`; parser at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\throughput.rs:501`; ratchet comparison at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\throughput.rs:608`
- **Impact:** Caller-controlled fixture names are written without CSV escaping, while the reader splits on raw commas and accepts extra columns. It also accepts `NaN` and infinity as metrics. A shifted row can select the wrong values, and `NaN > budget` is false, so corrupt evidence can become a false-green baseline.
- **Fix:** Use a fixed-schema CSV encoder/decoder, require the exact column count, and reject non-finite or non-positive metrics before baseline selection. Cover commas, quotes, `NaN`, and infinities.
- **Effort:** Medium
- **Tracking:** `RVP9-BUG-KIL-00108`

### Medium — zero-frame soak runs can succeed or never terminate

- **Confidence:** High
- **Location:** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\soak.rs:146`; empty encode/decode path at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\soak.rs:375`; equality check at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\soak.rs:456`

### Medium — realtime runs share one default output file

- **Confidence:** High
- **Location:** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\realtime.rs:118`; use and frame count at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\realtime.rs:379`
- **Impact:** Every default invocation uses `rvp9_realtime_bench.ivf` in the system temp directory. Concurrent runs can overwrite or count one another's artifacts, and a stale output can survive an encoder that does not replace it correctly.
- **Fix:** Give each run a scoped unique temporary directory with create-new semantics, or require an explicit output and reject existing artifacts. Test concurrent and stale-output cases.
- **Effort:** Small to medium
- **Tracking:** `RVP9-BUG-KIL-00111`

### Medium — external encoder and decoder waits are unbounded

- **Confidence:** High
- **Location:** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\realtime.rs:379`; `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\bdrate.rs:322`; `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\bdrate-svc.rs:580`; `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\encode-headtohead.rs:825`

### Medium — throughput baselines ignore the recorded build profile

- **Confidence:** High
- **Location:** schema contract at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\throughput.rs:419`; selection at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\throughput.rs:557`; consumer at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\tests\decode_throughput_ratchet.rs:130`

### Medium — concurrent throughput writers can corrupt the CSV ledger

- **Confidence:** High
- **Location:** `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\throughput.rs:439`
- **Impact:** Header initialization checks existence before opening for append, and row writes have no process-level lock. Two first writers can both emit headers; concurrent row appends are not one protected transaction. The reader's malformed-row skipping can hide lost evidence.
- **Fix:** Serialize initialization and append with an exclusive lock or a dedicated atomic ledger writer. Add a concurrent first-writer regression.
- **Effort:** Medium
- **Tracking:** `RVP9-BUG-KIL-00115`

### Low — `--fps` overrides produce the wrong reported bitrate

- **Confidence:** High
- **Location:** encoder FPS at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\bdrate.rs:273`; source-header FPS at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\bdrate.rs:526`; measurement at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\bdrate.rs:576`
- **Impact:** The encoder receives the requested FPS, but realized bitrate divides by duration derived from the source header. When those differ, printed and CSV RD-point bitrates are wrong. The final BD-rate percentage is unchanged because both curves receive the same multiplicative scale.
- **Fix:** Derive duration from the effective encoder FPS or the written IVF header. Add an override-versus-source regression.
- **Effort:** Small
- **Tracking:** `RVP9-BUG-KIL-00116`

## Not reported and why

### Refuted

- `decode-headtohead` returning success with partial rows is an explicit contract at `D:\worktrees\rvp9-2\20260822-REV-RVP9-CDX@KILN-code-review-200828\crates\rvp9-bench\src\bin\decode-headtohead.rs:343`; the orchestrator intentionally joins partial result sets.
- The SVC bitrate and scale helpers are duplicated across two binaries, but source comparison found no behavioral mismatch and no proven design boundary that warrants a Draft requirement.
- Counting whole IVF file bytes for measured bitrate is documented behavior. Container overhead is small and common to both curves; no payload-only contract was found.
- The bdrate FPS mismatch does not alter the final BD-rate percentage because it scales both curves equally. It is reported only as wrong RD-point output, not as a wrong quality comparison.
- `Stats::from_sorted` relies on pre-sorted input by contract, and every measured caller sorts before construction.
- Exact Mann-Whitney enumeration is bounded by its documented threshold; no scale defect was confirmed.
- Captured child output inside an encode timing interval was not shown to be material because the reviewed wrapper is quiet and no contrary command contract was found.

### Held out of the queue

- Soak's cross-decoder leg checks `vpxdec` success but not exact output size. The reviewed comments establish a bitstream-acceptance oracle, not a bit-exact output oracle, so the stronger expectation was not proven.
- `count_ivf_frames` does not validate the IVF signature or codec. Its narrow helper contract says it counts frame records, and this static pass did not establish that container identity belongs at that layer.
- The benchmark Y4M comparison accepts tags beginning with `FRAME`, including `FRAMEX`. That parser is permissive, but no documented requirement in this area establishes rejection as observable benchmark behavior.
- Explicit work directories are checked before deterministic artifacts are created, but no supported concurrent-sharing contract was found. The fixed default realtime path is tracked because it collides without any opt-in.
- Broad CLI size controls were not treated as a security defect. They are explicit local operator inputs, and no external trust boundary exists in this crate.

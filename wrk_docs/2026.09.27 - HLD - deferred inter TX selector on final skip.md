# Defer inter luma TX selection on provably all-zero chroma

## Why this is worth a design decision

The exact-output [Crucible census](evidence/2026-09-27-dead-tx-selector-census/README.md) found `300,732 / 41,858 / 7,509` Ducks/Tree/Town selector calls on leaves that skipped luma transform and finished full-block skip. Those calls consumed `222.680 / 39.970 / 6.677 ms` of *instrumented plain-release wall time*, not removable process CPU. The cheap source-equals-prediction certificate matched **zero** eligible leaves. An exact post-emit probe of the *other* chroma TX size found all-zero EOB on `298,591 / 40,054 / 7,188` of them (`99.29 / 95.69 / 95.73%`). This substantially strengthens the opportunity case but does not price the extra early chroma work. Earlier selector coefficient forwarding, SAD envelope checks and chroma zero certificates do not measure this particular work removal; their neutral results are warnings about end-to-end cost, not permission to assume a gain.

## Proposed bounded path

Only consider inter leaves for which `should_redecide_inter_luma_tx` and `should_skip_realtime_luma_transform` both hold, with fast quant enabled. Keep the original path for trellis, F02, residual/selector diagnostics, unsupported geometry and any unproved edge or scaled/compound prediction case. Do not change the selector's candidates, pruning or tie rule on fallback.

At the current selector callsite, after Y prediction is ready, build U and V predictions using the *same* existing inter-prediction path and reference/MV/filter inputs that emission uses. Factor that prediction path into one helper rather than duplicating it. Probe exact chroma EOBs using the existing forward-transform/quantizer operation for both possible chroma sizes: TX8 for luma TX8/TX16, and TX4 if `rt_emit_tx4` permits a TX4 winner. Use the same visible-edge tile geometry, input padding and quantizer as emission. If **every** U/V tile has EOB0 at both sizes, the selected luma TX cannot affect residual reconstruction or coded coefficients; leave Y/U/V recon as their predictions, mark the leaf skip, and let the existing final-skip recorder/MI-grid/writer path handle context. Otherwise fall back to the unchanged selector and emit walk; the probe must not leak coefficient, entropy, or scratch state into fallback. A fallback may rebuild the predictions during an initial prototype, but a retained version must account for that overhead rather than assuming this census's gross time is available.

The reason the chosen TX is unobservable on this success path is specific: `InterPartitionLeafDesc::mode_info` substitutes the maximum TX on skipped leaves, and the modes writer omits coefficient tokens for skip. The leaf's recon remains prediction when every quantized EOB is zero. `f5_uv_plane_tx_size` maps the selector's TX4/8/16 choices to at most TX4/TX8 chroma, so checking both covers the possible chroma outcomes. This proof does **not** apply to luma-skipped leaves with nonzero chroma; the census counted `3,326 / 1,264 / 222` such selector calls.

## Oracle and decision gate

Write a focused differential against the current path for TX4/8/16 winners; zero and nonzero chroma; frame edges and compact row windows; LAST/GOLDEN/ALTREF, scaled and compound references; skip flag, selected TX, recon on all three planes, coefficient order and canonical IVF output. Make it fail by dropping the TX4 probe on a fixture with TX8 EOB0 but TX4 EOB>0. If that fixture cannot be constructed, use a mutation of a stored probe EOB and show the differential turns red. AArch64 and native x86 must pass. Then build both arms with the same production-PGO recipe and require repeatable paired process-CPU gain over the three pinned clips, retaining every pair under Arthur's relaxed Crucible load policy. No quality drift is allowed: exact IVF hashes are the gate.

This is an emit-path ownership change, not a one-line check. It moves chroma prediction/quant before the selector on eligible leaves and needs scratch/recon ownership that remains correct on fallback. The choice is whether to prototype that bounded refactor now or keep seeking a less invasive hotspot. The census proves an opportunity, not that the extra early chroma work is cheaper than the selector it could skip.

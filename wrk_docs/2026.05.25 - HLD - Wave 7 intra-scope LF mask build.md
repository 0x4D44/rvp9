# HLD: Wave 7 — Intra-scope LF mask build (W5b C2 redo)

**Date:** 2026-05-25
**Author:** Plan agent (focused decomposition after W5b stall)
**Status:** APPROVED spec — ready for implementation
**Confidence:** medium-high that the predicted −5 to −10% materialises
**Time-box:** C1+C2 within 90 min from agent start; hard stop at 120 min if C2 not landed.

## 1. One-line summary

Build per-row `LoopFilterMask` data inside the existing tile-decode `worker_pool.scope` by submitting **one dedicated mask-build job per scope** (not per row): the job pulls SB rows from a shared counter, gates each row on `decode_progress[r] >= tile_cols_at_row[r]`, writes into a pre-allocated frame-wide `lfm_grid`. After scope joins, `apply_loop_filter_to_frame_dispatching` skips the build phase and runs the existing edge-filter pass on the pre-built grid.

## 2. Design questions resolved

### Q1 — `build_lfm_row` signature
**Option (c) chosen.** Change `RowMaskInputs.mi_grid` from `&'a [ModeInfo]` to `&'a [Option<ModeInfo>]` and inline `cell.expect("Wave 5b: pre-filled")` at the two read sites in `setup_mask` (`top` lookup at `setup_mask.rs:147`; `idx_at` reads inside `walk_four_32x32` / `walk_four_16x16` at lines 162, 172, 221, 229, 239, 297, 305, 314, 325, 336). The Wave 5b C1 prereq (commit `fa06a1f`) guarantees every cell is `Some(_)` by the time any worker reads it. Do NOT materialise an MI `Vec` per row.

Rejected alternatives:
- (a) — pure refactor, no per-row materialisation: this is essentially (c). Picking (c) names it more clearly.
- (b) — `transmute` adapter: `Option<ModeInfo>` is NOT layout-compatible with `ModeInfo` unless `ModeInfo` has a niche. The safe `.expect()` is essentially free; optimiser hoists the discriminant check.

### Q2 — Does `build_lfm_row(r)` read row r+1?
**NO.** Confirmed at `setup_mask.rs:100-345`: the walker uses `idx_at(r, c) = (mi_row + r) * mi_stride + (mi_col + c)` where `r ∈ [0, 8)` is bounded by `max_rows = min(MI_BLOCK_SIZE, mi_rows - mi_row)`. The SB-internal walker never indexes past `mi_row + 7`. **Mask build for SB row r requires only `decode_progress[r] == tile_cols_at_row[r]`**.

### Q3 — Where does the mask-build worker run?
**Option (a) with N=1 worker job per scope.** Submit exactly one additional `scope.submit()` to the existing intra/inter tile-decode `worker_pool.scope`. That job runs the same "claim next row by `fetch_add`, spin on `decode_progress[r]`, build row" loop as `run_row_mt_lf_worker` already does (Wave 2 C3 pattern, `apply.rs:339-417`) — except the body calls only `build_lfm_row` + `adjust_mask`, not the edge filter.

**Rationale vs (b)/(c):**
- **(b) tile-tail fold** loses parallelism whenever a tile finishes early — exactly the `join` P95 = 3.1× spread the W1+W4 survey flagged. Bad fit.
- **(c) piggy-back on tile-col-0 worker** serialises that worker; fragile (if bitstream has 1 tile column, we're back to no parallelism).
- **(a) with N=1** keeps dispatch overhead minimal: exactly **+1 `scope.submit()`** per frame. The W2 trap was per-SB-row scope dispatch; here the internal `fetch_add` self-dispatcher is cheap relaxed atomic. If 1 worker can't keep up, bump N to 2 in a follow-up commit — don't pre-optimise.

### Q4 — `apply_loop_filter_to_frame_dispatching` after this
New signature adds `prebuilt_lfm: Option<&[LoopFilterMask]>` and `prebuilt_frame_mi: Option<&[ModeInfo]>`. When `prebuilt_lfm.is_some()`, the dispatcher:
1. Skips `frame_mi` materialisation (use the borrowed slice).
2. Skips the `for sb_row { for sb_col { setup_mask; adjust_mask } }` build loop.
3. Calls `loop_filter_frame_with_non420` directly with the borrowed `lfm_grid`.

Serial path (`prebuilt_lfm.is_none()`) unchanged. Row-MT path disabled when prebuilt. Debug_assert the prebuilt grid is `sb_rows * sb_cols` long.

## 4. Key code snippets

### `run_mask_build_worker` (the trickiest function)

```rust
pub struct MaskBuildState<'a> {
    pub row_inputs: RowMaskInputs<'a>,       // already &[Option<ModeInfo>] after C1
    pub sb_rows: usize,
    pub sb_cols: usize,
    pub decode_progress: &'a [AtomicU32],
    pub tile_cols_at_row: &'a [u32],
    pub lfm_grid: SendMutPtr<LoopFilterMask>,
    pub lfm_grid_len: usize,
    pub next_mask_row: &'a AtomicUsize,
    pub mask_progress: &'a [AtomicU32],
}

/// SAFETY: caller guarantees lfm_grid points to a slice of length
/// >= sb_rows*sb_cols that no other thread reads until scope joins.
pub unsafe fn run_mask_build_worker(st: &MaskBuildState<'_>) {
    loop {
        let r = st.next_mask_row.fetch_add(1, Ordering::Relaxed);
        if r >= st.sb_rows { return; }
        let required = st.tile_cols_at_row[r];
        spin_then_yield(|| st.decode_progress[r].load(Ordering::Acquire) >= required);
        let row_slice = unsafe {
            std::slice::from_raw_parts_mut(
                st.lfm_grid.ptr.add(r * st.sb_cols),
                st.sb_cols,
            )
        };
        build_lfm_row(r, st.sb_cols, &st.row_inputs, row_slice);
        st.mask_progress[r].store(1, Ordering::Release);
    }
}
```

### Intra-scope submission site

```rust
// After the tile-job submit loop, submit the mask-build worker.
if intra_scope_lfm_eligible {
    let mbst: &'frame MaskBuildState<'frame> = &mask_build_state;
    scope.submit(move || {
        unsafe { rvp9_core::loopfilter::apply::run_mask_build_worker(mbst); }
    });
}
```

`SendMutPtr<T>` is a 4-line `Copy + Send + Sync` newtype around `*mut T`; same pattern as `SharedFrame` (`apply.rs:82-99`).

## 6. Risk register

| # | Risk | Mitigation |
|---|---|---|
| 1 | **W2 trap recurrence (dispatch overhead).** | Exactly **one** `scope.submit` per frame, not per row. Internal `next_mask_row` self-dispatcher uses cheap relaxed `fetch_add`. If C2 bench shows >0% regression vs C1, **abort** and rethink — do NOT proceed to C3. |
| 2 | **Layout/aliasing on `lfm_grid`.** | Worker writes row r through raw pointer; post-scope serial code reads whole grid. Relies on `scope.join()` happens-before edge (already proven sound for `SharedFrame` in W2). |
| 3 | **`Option<ModeInfo>` discriminant overhead in `setup_mask` hot path.** | `setup_mask` is called ~510 times/frame at 1080p with ~5-15 cell reads each — ~5-8k branches, hyper-predictable (always `Some`). Negligible. Fallback: `unwrap_unchecked()` (same `unsafe` burden as `SharedFrame::y_slice`). Don't do preemptively. |

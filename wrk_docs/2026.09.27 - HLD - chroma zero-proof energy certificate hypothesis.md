# Chroma zero-proof energy certificate hypothesis

The current production-PGO profile attributes 1,794/16,158 direct Ducks samples to the inlined early chroma-proof call at `crates/rvp9-encoder/src/lib.rs:11766`. This is source attribution, **not** an estimate of removable CPU. A residual-reuse implementation was exact but 1.1–2.1% slower in two paired screens, so further loop rearrangement has no measured case.

The cross-family consult proposed a sufficient energy check before the TX8/TX4 chroma transforms. The tentative threshold is `T = min_b(ceil(65536 / quant_fp[b]) - round_fp[b])` over DC and AC bands. It suggested that `65 * sse < (T - 4)^2`, where `sse` is the sum of 64 squared pixel residuals, could certify all TX8 and four TX4 quantized coefficients zero. If true, the check would bypass transform and quantization while retaining the current proof result and entropy order. It also suggested a related Hadamard picker certificate; that is a separate, lower-priority hypothesis.

**Do not use this inequality in shipped code yet.** The consult did not supply a formal bound for the repo's exact integer 4×4/8×8 DCTs, their rounding and wrapping, quantizer clamp, and all supported Q tables. Random trials cannot prove it. The first implementation unit is diagnostic only: verify a conservative bound against the exact scalar and SIMD paths and count certificate hits, false certificates, and TX8/TX4 proof calls on the canonical clips. Deliberately test residuals at threshold edges. Any false certificate rejects the shortcut. If the bound is sound but hits few calls, reject it before a PGO performance build. A candidate still needs deliberate-red focused differentials, AArch64 and x86 checks, canonical output, and repeatable paired production-PGO CPU gain before integration.

The authoritative PGO source attribution and binary identities are in `wrk_docs/evidence/2026-09-27-current-pgo-ip/README.md`. The last direct parity result remains 1.061826× pinned libvpx equal-clip CPU against the ≤1.05× target.

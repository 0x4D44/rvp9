### Architectural prerequisite surfaced: single reference buffer (commit 038d4cc)

Attempting to wire the W5 denoiser into `encode_frame` surfaced a structural blocker (documented in `wrk_journals/2026.05.26 - JRN - denoiser integration assessment.md`): **rvp9 has ONE reference buffer per slot** (`StreamEncoder::last_recon_*`) that serves BOTH motion search AND residual prediction/recon, and is committed verbatim as the next LAST ref. The decoder rebuilds those exact pixels from the bitstream (the cross-decoder invariant at `frame_loop.rs:1284-1288`).

libvpx, by contrast, keeps the denoiser's filtered `running_avg_y[]` as a SEPARATE *ME-only* predictor, while `cm->frame_refs[]` (the residual-coding reference) stays the genuine decoded frame — so vpxdec reproduces it exactly. Naively denoising rvp9's single reference would make the encoder code residuals against denoised pixels while the decoder adds them to un-denoised pixels → drift → cross-decoder gate FAIL.

**Therefore the denoiser (and, by the same logic, the ALTREF ME-vs-pred-ref separation and compound) need a "split reference buffer" refactor first** — separate `me_ref` (denoised / filtered, ME only) from `pred_ref` (true decoded, residual coding) threaded through every inter call site. That's an invasive multi-call-site picker refactor warranting its own wave + BD-rate validation; per CLAUDE.md ("discuss invasive refactors first") the agent stopped at the assessment rather than landing a desyncing pass. Cross-decoder gate verified GREEN (byte-exact vs vpxdec) — no hot-path code changed.

This is the second structural correction to the master inventory's effort model (after the "stubbed RD kernels" finding): **the encoder needs a reference-buffer split before the ME-filtering features (denoiser, filtered-ALTREF, compound) can be wired gate-safe.**

# Shared cardinal interpolation rejected

The repeated exact-IP Tree profile put AVX2 subpixel interpolation on the hot
path. Astra suggested reusing the deterministic overlap between opposite
first-round half-pel cardinals; the Tree census recorded 121,772 horizontal
and 121,772 vertical 32×32 half-pel calls. This differs from the earlier
one-entry cache and the rejected Unit 1376 full-width-load edit.

Candidate `c251d0d0` proved each of the four `(variance, SSE)` results exact
against the scalar oracle and preserved the complete search result on interior,
ties, negative-MV, and border cases. A deliberate metric mutation failed the
differential. The AVX2-specific test ran on Crucible; AArch64 retained the
ordinary path.

Two 15-pair Crucible screens produced exact IVFs but corpus candidate/control
process-CPU ratios of 1.016010× and 1.033749×. The second run was slower on
all three clips. The saved interpolation work did not repay strip handling and
extra dispatch/search overhead at whole-encode level. Reject the code branch;
evidence is in `wrk_docs/evidence/2026-09-26-shared-cardinal-screen/`.

Next optimization should return to measured work origin, particularly Ducks'
larger search count, rather than another unproven interpolation cache. Do not
infer that exact call-count differences are removable without a policy oracle.

## What the writer does today (code-verified)

The encoder's real compressed-header writer is `rvp9-core::bitstream::compressed_header::write_compressed_header` (`crates/rvp9-core/src/bitstream/compressed_header.rs:987`), called from `frame_loop.rs:3068,3328` and `lib.rs:469,621,787,6419`.

Its coef-prob section is `write_coef_probs` → `write_coef_probs_common` (`compressed_header.rs:679-737`), which uses **"Strategy B — force-update on diff"** (documented at `:587-603`):
- Per TX size: emit gate=1 iff ANY slot differs (`pre != post`), then walk every slot calling `cond_prob_diff_update(bw, pre_slot, *post_slot)` — i.e. gate per slot on `pre != post`, writing `post` verbatim.
- It takes NO branch counts and runs NO savings search.

Critically, the tile coder uses **`decoder_fc`** (the FC *mutated in place by `write_compressed_header`*), not `post_fc` (`frame_loop.rs:3389-3407`). So encoder-tile and decoder both land on exactly the bits the writer emitted — that's why the current path is self-consistent and byte-exact.

The production inter path feeds a genuinely *differing* `post_fc`: `fc_override = Some(&self.frame_context)`, the backward-adapted FC (`frame_loop.rs:2098`). So coef-prob diff-updates ARE emitted on real inter frames — the coef-prob path is exercised by the sacred gate, not dormant.

## Why this is Path C (bitstream-changing), and why it's a blocker

### 1. The two algorithms emit different bits.
- **Strategy B (today):** update slot iff `pre != post`; write `post`.
- **`bitstream_gates` (libvpx TWO_LOOP):** update slot iff `savings > 0 && best_newp != oldp`; write `best_newp` (the search result, generally `!= post`); and suppress the WHOLE table (gate=0) if `savings_total < 0`.

These disagree whenever a real coef-prob update exists — which is every adapted inter frame in the gate. Wiring `update_coef_probs_common` into `write_coef_probs` therefore byte-changes the gate stream. (libvpx ref confirmed at `vp9_bitstream.c:556-624`.)

### 2. The module is NOT actually closer to libvpx for the pivot node.
libvpx's TWO_LOOP uses `vp9_prob_diff_update_savings_search_model` for `t == PIVOT_NODE` (node 0) and the plain search for nodes 1,2 (`vp9_bitstream.c:569-575`). `bitstream_gates::update_coef_probs_common` uses the **plain search for ALL nodes** — its own docs admit this deviation (`bitstream_gates.rs:201-208`). The model search (`vp9_subexp.c:141-181`) and `build_tree_distribution` (`vp9_bitstream.c:518-543`) are **not ported anywhere** (grep: zero hits outside doc comments). So wiring it yields a *third* distinct bitstream — not Strategy B, not real libvpx. The "more correct" precondition for Path C **fails**.

### 3. It is not a ~50 LOC wire; it's an architecture change to a byte-exact path.
The module's API (`old_probs: &mut [u8]` flat slices, one gate bit per call, `branch_ct` required) doesn't match the writer's 4-D `CoeffProbsModel` per-TX walk. Wiring needs: (a) flatten each TX table to the `[PLANE][REF][BAND][CTX][NODE]` order, (b) port `build_tree_distribution` to build per-slot `branch_ct` from `frame_counts.coef`+`eob_branch` (data exists — `adapt.rs:601-622` already does this shape — but the writer doesn't build it), (c) re-thread the savings-gated FC so the tile coder stays consistent, (d) decide PIVOT_NODE model-search. That's a real port touching the only byte-exact-through-vpxdec path we have.

Per the sacred-gate rule: a bitstream change is only allowed if the new stream is provably MORE correct AND byte-exact through both decoders. Precondition (more correct) fails on the PIVOT_NODE deviation, and the change is high-risk on the inviolable gate for **zero functional gain** (both streams are valid VP9; the only difference is compressed-header bit count — a few bytes/frame of rate, not decode correctness). **Stop.**

## On the other three helpers (also unwired, lower stakes)

- `fix_interp_filter`: the writer hardcodes frame-level `InterpFilter::Switchable` and emits per-block interp bits unconditionally (`frame_loop.rs:3284`). Collapsing to a fixed filter when only one was used would ALSO change the uncompressed-header `interp_filter` field + suppress per-block bits → bitstream change → same Path-C caution.
- `get_refresh_mask` / `preserve_existing_gf`: the writer passes explicit `refresh_frame_flags` literals per frame kind (`0xFF` KF, `0x01` inter, `0x04` ARF — `frame_loop.rs:2066,2461`, etc.). The multi-ARF stack + GF-preserve paths only matter once multi-layer ARF is live (deferred, A16). Wiring now would be premature abstraction.
- `tx_totals_gate_skips` / `prob_diff_update_savings_search`: only meaningful as inputs to the coef-prob updater above.

---

## Recommendation

1. **Do not wire any `bitstream_gates` helper into the writer now.** It is Path C with a failed "more-correct" precondition; the only payoff is compressed-header rate, which is not in the byte-exact gate's value model and not worth risking the gate.
2. **Reclassify the re-audit A6 item.** "Wire `bitstream_gates` (~50 LOC)" is mis-scoped. The honest statement: the writer already emits *valid, byte-exact* coef-prob updates via a simpler-than-libvpx Strategy B; matching libvpx's rate-optimal TWO_LOOP gating is a real port (~250-400 LOC incl. `build_tree_distribution` + the PIVOT_NODE model search) whose ONLY benefit is bitrate, and which must re-prove byte-exact through vpxdec+ffmpeg afterwards. It is a *rate-parity* item, not a *correctness/dead-code* item.
3. **Module disposition:** leave `bitstream_gates.rs` in place (do NOT delete without Arthur's sign-off). It's a faithful (modulo PIVOT_NODE) reference port with PROOF tests; it becomes the building block IF a future session ports the full TWO_LOOP coef updater + model search and re-establishes the gate. Until then it is documented-dead, not a bug.

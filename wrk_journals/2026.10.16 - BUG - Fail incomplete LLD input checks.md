# Fail incomplete LLD input checks — KIL-00091

The LLD format checker drops directory-entry errors with `flatten`, and a per-file read error is only warned about. Its final exit decision considers the successfully read structural reports, so omitted inputs can produce a successful check, including when no candidate was inspected successfully.

The correction must account for both directory-iteration and file-read failures and feed those failures into the actual command exit decision. Successfully inspected files should retain their report format and sorting, and README, underscore-prefixed and non-Markdown files should retain their existing skip rules. Directory setup errors and existing structural-check policy remain unchanged.

The directory-walk boundary is tested with an injected iterator error in the production scan helper. That helper was first extracted with the old behavior preserved; its existing five unit tests passed before the fixes. An initial extraction compile error is excluded from regression evidence. Actual CLI tests use invalid UTF-8 Markdown to trigger a deterministic read-to-string error without changing file permissions; mixed and valid-only controls distinguish failure propagation from an always-failing checker.

Observed reversal 1: the injected-entry regression selected one test and failed `input_failures.len()`, observing zero instead of one.

Observed reversal 2: the all-unreadable CLI regression selected one test and failed its exit assertion, observing status zero instead of one while stderr named `bad.md` and reported invalid UTF-8.

Observed reversal 3: the mixed valid/unreadable CLI regression selected one test and failed the same exit assertion, again observing zero instead of one. Its valid file has all required sections, a citation and a populated divergence section, so an unrelated structural failure cannot mask the input defect.

Observed reversal 4: the valid-only control first passed normally. Temporarily forcing the final successful exit to failure selected that one test and failed its success-status assertion. The mutation was restored. The lead inspected all four raw failure logs.

The production `read_dir` adapter passes each result directly to the scan helper. Entry and file-read errors carry their directory or file context, are reported as errors, and initialize the actual command's failure flag. The old warning-only and ignored-error scaffolding is gone. Successful report sorting, valid-only output and existing skip/structural policy are preserved.

The worker's six checker unit tests and six integration tests passed; the latter comprise three real CLI cases and three tests from the existing bounded-child helper. Formatting, scoped Clippy and diff checks passed without warnings. The lead independently reviewed the scan-to-exit wiring, inspected the lint log, checked the diff, and ran both targets: six unit tests and six integration tests passed. CLI subprocesses use the existing bounded runner with closed stdin and owned capture files, avoiding output-pipe hangs.

# Scaled NEON convolution rejects overflowing Q4 coordinates

RVP9-BUG-FLU-00053 came from unchecked signed multiplication and addition while computing the final horizontal and vertical Q4 coordinates. The safe AArch64 wrapper now computes each endpoint with checked arithmetic before deriving the source footprint or entering the raw-pointer passes. Since dimensions and nonnegative steps are validated first, a checked endpoint also bounds every coordinate used by the row and column loops. The intermediate height uses the checked vertical endpoint.

Fails-before evidence: on the pre-fix release build, the selected vertical regression failed because it did not panic as expected; unchecked arithmetic wrapped and the undersized fixture passed validation. In the earlier debug run, both selected tests instead saw Rust's generic multiply-overflow panic. The horizontal fixture was then set to `3 * 1_431_655_766`, which wraps to 2 in release and keeps the old computed source extent within 64 bytes. A later root-cause reversal compile hit its bound before that revised horizontal assertion ran; the direct release vertical red result is the observed fails-before proof.

On the final formatted source, `cargo test --release -p rvp9-core --lib dsp::aarch64::convolve8_scaled_neon::tests` passed all four tests on arm64, including both overflow cases and both scalar-vs-NEON differential tests. `cargo fmt --all --check` and `git diff --check` passed. The under-60-second smoke ran the two regression tests from the freshly built release test binary; a redundant Cargo-filter invocation attempted another slow crate rebuild and timed out at 60 seconds. No unsafe pointer operation was attempted with invalid coordinates.

# Unit 1401 — full-pixel SAD union rejected

## Scope

Fresh x86-64 Crucible profiling after integrated commit `32d0a9f7` selected
`sad4d_at_from_source` for the next small optimization experiment. The target
was to validate the union rectangle of four reference blocks once and retain
the existing per-lane fallback whenever that union clipped the plane.

## Correctness

The candidate added an in-plane four-lane differential case and retained the
clipped-lane case. The focused AArch64 suite passed 20/20 before timing. A
deliberate mutation that shifted the fast-path column by one byte failed with
`range end index 577 out of range for slice of length 576`; restoring it made
the suite pass again. The candidate x86 Crucible focused suite also passed
20/20. The restored integrated tree passed the full `rvp9-core` library suite:
1719 passed, 2 ignored.

## Performance

Both screens used the same control (`32d0a9f7`), candidate (`7c4d2d84`), three
canonical 1280×720@30/1 clips, 60 frames, CPU-used 6, CBR 1260, one thread,
zero tiles, AQ 0, noise 0, one warmup, three pairs, two rotations, and no
`--max-load1` ceiling. All candidate/control IVF hashes matched.

Screen A measured paired geomean `1.006035223x` (separate `1.006794617x`).
Screen B measured paired geomean `1.001172866x` (separate `1.001907767x`).
The ratios are candidate/control, so both runs are regressions. The first is
large enough to reject immediately; the repeat confirms a smaller but still
positive slowdown. The candidate was reverted as `7d9642cc`; no libvpx run was
needed.

## Outcome

The integrated scalar path remains in place. The profile, screen manifests,
raw CSVs, summaries, and the symbolized xperf report are in
`wrk_docs/evidence/2026-09-21-unit1401-*`. The next experiment should target a
different profile hotspot rather than tuning this union path further.

## Outcome: LANDED — temporal SVC (2-layer faithful; 3-layer tagged + scoped)

Wired the ported-but-inert `crates/rvp9-encoder/src/svc.rs` scaffold
(libvpx `vp9/encoder/vp9_svc_layercontext.c` port) into the encode path

## The key architectural finding (verified against libvpx)

VP9 **temporal SVC** with one spatial layer emits each access unit as a
SINGLE standalone VP9 frame. Temporal layers do NOT pack into a
superframe — superframes pack only SPATIAL layers within an access unit
(`vp9_svc_layercontext.c:451` `++cpi->svc.current_superframe` is per
access unit; one spatial layer ⇒ one frame). The `temporal_layer_id` is
NOT a VP9 wire field — it is encoder-side metadata (libvpx
`vpx_svc_layer_id`). What carries the layering on the wire is the
per-frame REFERENCE/REFRESH structure the temporal setters compute
(`set_flags_and_fb_idx_for_temporal_mode2`, `:626-684`): enhancement
frames are non-reference (refresh nothing the base reads), so the base
layer skips them — the stream is temporally scalable. vpxdec decodes it
as a normal frame sequence (plays all layers).

So the task brief's "layers pack into a superframe" applies to SPATIAL
SVC, not temporal. The superframe builder is NOT used for temporal SVC.
(SuperframeBuilder stays the ALTREF path's tool — A18 doesn't touch it.)

## What was wired

- `EncoderConfig::temporal_layers: u32` (1 = off / default). Validated in
  `StreamEncoder::new`: range 1..=3, mutually exclusive with
  `enable_alt_ref`.
- `StreamEncoder::svc: Option<svc::Svc>` built via `Svc::alloc_layers`
  (`vp9_svc_layercontext.c:105-181`), `temporal_layering_mode` =
  Pattern0101 (2) / Pattern0212 (3). `number_spatial_layers = 1`.
- `StreamEncoder::svc_assign_layer(frame_kind)` — the
  `vp9_one_pass_cbr_svc_start_layer` (`:769-830`) driver wrapper: sets
  `spatial_layer_to_encode = 0`, runs `Svc::apply_temporal_layering`
  (dispatches the configured setter, `:819-830`), reads
  `temporal_layer_id`, advances the base layer's
  `current_video_frame_in_layer`. KF resets the counter (tl0, 0xFF
  refresh untouched).
- Single-LAST-slot projection: tl0 → `refresh_frame_flags = 0x01`
  (refresh LAST); enhancement (tl > 0) → `0x00` (non-reference). Override
  applied in `encode_inter_internal` (replaces the GfGroup cadence flag).
  Frames still READ LAST (slot 0) → picker/residual path unchanged →
  standard VP9 bytes.
- `EncodedFrame::temporal_layer_id: u8` surfaces the tag.
- CLI `--temporal-layers <N>` (`rvp9enc.rs`), threaded through
  `build_encoder_config` (production mapping).

## Scope-downs (honest)

- **Spatial SVC deferred** (resolution scalability needs per-layer
  downscale + inter-layer prediction — much bigger). Documented follow-up.
- **3-layer (0-2-1-2) ref hierarchy simplified**: the tags are correct
  per libvpx (`:527-530`), but rvp9's single-LAST-slot pool projects the
  mid layer (tl1) to `0x00` too, so tl2 can't reference tl1 — it's
  "base + droppable rest", not a true 3-tier prediction structure. A
  faithful 3-tier hierarchy needs the multi-slot `current_{lst,gld,alt}_fb_idx`
  routing (`:591-616`) wired into a multi-slot encoder ref model — follow-up
  with spatial SVC. The **2-layer pattern is fully faithful** (the one
  enhancement layer is genuinely non-reference).
- Per-layer rate allocation is an even split (placeholder; libvpx reads
  `oxcf->layer_target_bitrate[]`, `:131`). Affects only per-layer RC
  budgeting, never the frame structure → byte-exact gate unaffected. A
  `--bitrate-per-layer` CLI flag is the follow-up.

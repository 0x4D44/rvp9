# Reject ignored two-pass lookahead requests — KIL-00121

The CLI accepted positive lookahead and ALTREF controls with two-pass encoding, although the synchronous library driver forces lookahead off in both passes. Positive ALTREF requests therefore could not become active and positive lookahead requests were silently discarded.

The CLI now rejects those explicit positive requests before file I/O. Two-pass omission and explicit zero values remain valid, as do one-pass positive controls. Help describes the restriction. The existing synchronous library contract and scheduling implementation remain unchanged; this fixes the CLI option contract rather than adding delayed two-pass scheduling.

Before the fix, both new unit rejection tests failed their expected error assertions. CLI negative cases reached the missing-input error instead of option validation, and a valid six-frame raw input with positive lag silently encoded successfully. After the fix, both controls reject split and inline positive arguments while preserving existing output sentinels.

Observed deliberate reversals, restored before final checks:

- Removing only the lag guard failed all four lag rejection cases; ALTREF rejection stayed green.
- Removing only the ALTREF guard failed all four ALTREF rejection cases; lag rejection stayed green.
- Applying validation to one-pass requests failed the positive one-pass acceptance assertion.
- Rejecting explicit lag zero failed its complete-IVF acceptance case.
- Rejecting explicit ALTREF zero failed its complete-IVF acceptance case.

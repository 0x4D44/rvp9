# TX pre-tile bound and hot-IP triage

The current CPU6 single-layer selector still evaluates TX16, TX8 and TX4 on eligible leaves. Before repeating a prior neutral fixed-rate prune from Unit 1165 (see `wrk_journals/2026.07.30 - JRN - production parity drive.md:33356`), an isolated count-only diagnostic measured its current hit rate. Canonical Crucible 60-frame runs found 17/141,013 Ducks TX4 candidates excluded before any tile, zero TX8 candidates, and zero hits on Tree or Town. All outputs were exact. The [raw evidence and source patch](../wrk_docs/evidence/2026-09-28-tx-pretile-bound-no-go/README.md) are integrated separately from the rejected diagnostic source branch. No production-PGO timing was run because even perfect removal of 272 Ducks TX4 tiles is negligible against the 1.057638× integrated parity ratio.

The separate exact-IP measurement audit found that the five repeated Ducks ETW captures prove a stable sampled location at `inter.rs:2428`, but not its latency. RVA `0x1a3c58` is one stack reload in a broad inlined candidate-loop frame. WPR's recorded scripts did not pin or record the sampling interval per ETL; asynchronous samples can skid; the source line covers 331 IPs. Multiplying samples by an assumed interval and dividing by a source-level call count cannot establish cycles per execution or a stall. A new measurement must time a precisely bounded logical stage with reconciled calls, or use suitable hardware counters; no stack-layout code change is justified from this sample alone. The existing filter-stage cycle census already covers broad prediction/model/round-trip spans, so repeating it would not add a target.

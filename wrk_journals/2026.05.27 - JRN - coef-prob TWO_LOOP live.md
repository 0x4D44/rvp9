## Count-bank sharing finding (the CRITICAL investigation)

**The encoder gathers its OWN 12-token distribution; the decoder's
`CoefCountsBank` / forward-adaptation path is UNTOUCHED.**

- `encode_coefs` (`crates/rvp9-core/src/entropy/detokenize.rs`) already
  classifies every coefficient to its EXACT token (ZERO/ONE/abs==2..4/
  CAT1..CAT6/EOB) at the emit points — it just collapsed TWO..CAT6 into
  the single `TWO_TOKEN` bucket for the 4-token model histogram. I added
  a parallel 12-token increment (`full_token_from_abs`) at those same
  points, gated on a new optional `DecodeCoefCounts::full_counts` field.
- The 12-token bank (`Coef12Bank`, `adapt.rs`) rides on a NEW optional
  `FrameCounts::coef_full: Option<Box<Coef12Bank>>` field — already
  threaded to the residual writers. The decoder constructs
  `FrameCounts::default()` (→ `None`) and `DecodeCoefCounts{..,
  full_counts: None}` (`rvp9-decoder/src/detokenize.rs:153`); it never
  allocates or populates the bank, so its `==`/`add`/memory behaviour is
  unchanged. `CoefCountsBank` (the wire-relevant 4-token forward-adapt
  bank, read by the decoder at ~10 sites) was NOT widened.

## How the 12-token counts are gathered + the reorder

rvp9 writes the compressed header BEFORE the count-bearing tile pass;
TWO_LOOP needs the counts first. **Count-pass-before-header**
(`frame_loop.rs::build_inter_packet_with_residuals`): run `write_tile_inter`
once into a throwaway buffer with a `FrameCounts{coef_full: Some(..)}`,
gathering the full histogram + `eob_branch`. Token VALUES come from
`coef_source` (residuals) and are probability-INDEPENDENT, so the counts
match the real tile pass regardless of FC. Then
`build_coef_prob_update_plan` (`bitstream_gates.rs`) runs the TWO_LOOP
dry-run (libvpx `vp9_bitstream.c:556-593`): per slot, `build_coef_branch_cts`
→ `prob_diff_update_savings_search[_model]` (PIVOT) against `oldp =
decoder_fc.coef_probs`; per TX size, suppress if `tx_total <= 20`
(`:690`) or `savings < 0` (`:590`). The plan is a wire-shaped
`CoefProbUpdatePlan` (core type, no core→encoder dep). `write_coef_probs`
gained a `plan` arg: `Some` → `write_coef_probs_common_twoloop`
(emit gate + per-slot updates, libvpx `:594-622`); `None` → Strategy-B
fallback (keyframe / legacy paths stay byte-identical).

## The real bug the gate caught (backward-adapt base)

First cut: within-frame header bit-exact (verified) but the stream went
corrupt at frame 4 (vpxdec rejected) + AQ tests desynced. Root cause: the
DECODER backward-adapts from the **PRE-header** FC
(`pre_fc = cm->frame_contexts[idx]`, snapshot BEFORE diff-updates,
`rvp9-decoder/src/lib.rs:2342`/`:3136`), but the encoder was adapting its
`decoder_fc_state` mirror from the POST-header FC. Under Strategy B these
were equal (full re-signal made post-header == prior-adapted), so it was
LATENT; TWO_LOOP's PARTIAL update made them differ → FC drift → invalid
stream. Fix: snapshot `pre_header_decoder_fc` before the header write and
adapt the decoder mirror from it (`frame_loop.rs`, all of mode/coef/mv).
This is the brief's "real test of correctness" — backward adaptation must
reproduce on the decoder.

# Restore x86 scalar diagnostic routing — CRU-00001

`RVP9_FORCE_SCALAR=1` masked the cached x86 dispatch table but compile-time encoder selections continued entering SSE2 kernels. The originally reported forward transforms, Hadamard transforms, integral projections and quantizer metrics still bypassed the mask. Current fused subtraction, partition statistics, SSE scoring and encoder Laplacian analysis had acquired the same selection gap.

The bounded fix consults the existing process-wide dispatch capabilities before these x86 selections and reaches existing scalar algorithms when masked. The cross-crate subtraction exports keep their signatures and validate the same supported sizes, strides and checked input spans before scalar execution. Ordinary x86 capability selection and Arm behavior remain unchanged. The override must be set before first dispatch initialization; only its exact value `1` enables it. Explicit ISA kernel tests and microbenchmarks retain explicit ISA selection.

This does not implement the draft structural requirement RVP9-REQ-CRU-00006, which proposes moving every kernel into dispatch slots. RVP9-BUG-CRU-00003's duplicate integral-projection test oracle and RVP9-BUG-CRU-00004's low-bit-depth transform optimization remain separate.

The regression traces 21 actual SSE2 backend entries under test configuration. Each child runs four concurrent first callers and one caller after initialization. Every caller exercises all 21 entries with the variable absent or set to `0`, `true` or `01`; exact `1` reaches none. Child command environments avoid process-wide mutation. The parent regression and the directly activated forced child both passed on x86 through Rosetta.

Observed reversals:

- Replaced the `fdct8x8` cached-capability guard with unconditional selection. The parent regression failed in the exact-`1` child; the directly activated child independently failed with actual `fdct8x8` bit 1 versus expected 0. Restoring the guard passed both tests.
- Replaced the encoder Laplacian selection predicate with `true`. The forced child failed its dispatch assertion (`true` versus expected `false`). Restoring the predicate passed the five-environment subprocess test. This is a supplementary policy mutant: Rosetta exposes no AVX2. The test also records actual AVX2 entry and requires two entries on capable unmasked hosts, zero otherwise; no positive AVX2 execution was observed here.

The initial x86 compile exposed scalar functions/imports still excluded by old architecture cfgs; those gates were corrected before the routing tests. These compile failures are not assertion-red evidence. No fixture calibration failure occurred.

Focused checks passed: x86 core forward transforms 44, Hadamard 12, integral projection 15, inter decisions 95 and partitions 46 tests, in both ordinary and forced-scalar processes (212 each). Native Arm passed the corresponding 46/12/15/95/46 tests (214). Encoder pre-analysis passed 36 x86 tests and 35 Arm tests. Scoped production Clippy for core and encoder passed with warnings denied on both architectures. Formatting and diff hygiene passed. An independent source review found no material issue.

A task-local four-frame 512×128 Y4M fixture encoded with cpu-used 7, 500 kbps, two threads and two tile columns (`--tile-columns=1`, log2) produced byte-identical IVF in separate exact-`1` and `0` x86 processes: 44,128 bytes, four packet frames, SHA-256 `31316cd157f3dbddb648034f977e0b28f7d731db93c8e7afdd49429534c00237`. This checks codec output alongside the nonvacuous routing oracle; it is not libvpx differential evidence.

The preselected final smoke is `RUSTFLAGS='-C target-cpu=x86-64' cargo test -p rvp9-core --target x86_64-apple-darwin --lib dsp::force_scalar_tests::force_scalar_subprocess_routes -- --exact`, with task-local absolute `TMPDIR`, closed stdin and a sixty-second bound. No whole-program throughput, physical x86, AVX2, live Windows or Miri runtime claim is made. The added cached checks affect hot selection paths; throughput was not measured.

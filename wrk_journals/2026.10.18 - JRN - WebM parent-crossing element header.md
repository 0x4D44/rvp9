# WebM parent-crossing element header

RVP9-BUG-FLU-00044 is fixed by bounding the in-memory VP9 track finder's EBML ID and size readers to the active parent's slice. A nested header can no longer consume bytes past its parent before the unknown-size payload extent is computed.

The regression test failed before the fix in a debug build: `read_webm_packets` panicked at `end - pos`, then the test failed with its assertion that names the unexpected panic. After the fix, cases where either the nested ID or its size field crosses the parent return `ContainerError::BadEbml` without panicking.

`cargo test -p rvp9-io` passed (61 unit tests, 76 error-path tests, 4 track-discovery tests; one doctest ignored). `cargo fmt --all --check` and `git diff --check` passed.

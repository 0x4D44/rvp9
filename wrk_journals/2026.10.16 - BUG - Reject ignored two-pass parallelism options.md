# RVP9-BUG-KIL-00120 — Reject ignored two-pass parallelism options

The CLI two-pass branch returned before building its parallelism configuration,
and the shared driver constructed default one-thread, single-tile encoders.
Explicit worker and tile-column requests therefore succeeded while being ignored.

The CLI now validates these requests before input or output file I/O. With
`--passes 2`, explicit thread values above one and nonzero tile-column values
return an error naming the unsupported option and the driver limitation.
Omitted controls, threads zero/one and tile columns zero remain accepted.
Help text describes the two-pass defaults and accepted values. The deliberate
support restriction is also recorded in `notes/divergence-ledger.md`.

This uses the bug's permitted rejection remedy. It does not add parallel
two-pass support or change the encoder API. RVP9-BUG-KIL-00121's separate delayed
scheduling/ALTREF behavior remains outside this fix.

## Evidence

The new actual-CLI regression ran against the old code and failed one aggregate
assertion after all four requests had executed: threads two/eight and tile-column
log2 counts one/two, with equals and split argument forms. All four commands
succeeded and omitted the required diagnostic. Three created output; the fourth
overwrote a pre-existing sentinel output. The final test requires rejection,
the option-specific diagnostic, preserved input and absent/unchanged output.

After the guard, that regression selected and passed one test. The expanded
existing two-pass positive selected and passed one test covering three settings:
defaults, threads zero with tile columns zero, and threads one with tile columns
zero. Each had the expected six-frame header and six parsed, nonempty IVF
packets. A deliberate expected-count calibration from six to seven failed all
three cases; restoring six returned the control to green. That calibration
checks the positive oracle rather than reproducing the defect.

The existing one-pass worker/tile mapping unit test and the existing two-pass
temporal-SVC rejection each selected and passed one test. An initial exact-filter
attempt selected zero unit tests and is not counted; its corrected final run
selected one. Actual help output showed the new restrictions. Formatting,
`cargo clippy -p rvp9-cli --all-targets` and diff checks passed with no warnings.

Commands used stdin at EOF, harness timeouts and a task-local `.scratch` TMPDIR.
The preselected final smoke after fetch/catch-up is:

```text
deltic timeout 60 cargo test -p rvp9-cli --test cli_arg_coverage enc_two_pass_rejects_explicit_parallelism_before_file_io -- --exact
```

The lead reviewed guard placement, option boundaries, help and red/green logs.
No external decoder, benchmark or full workspace test suite was needed. This
fixing pass leaves the bug Fixed for a different verifier and does not close it.

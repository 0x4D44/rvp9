# Unit 1418 — selector runtime diagnostic

This bounded run checked whether the existing runtime-profile feature gives a
useful `tx_select` signal at the line-11471 selector. It did not edit source,
the retained Unit 1416 profile, or unrelated remote work.

## Evidence

The clean Crucible worktree was at
`5b6822c05c8d7ff3005902715d618f0ecbfbfd2c`; its encoder source, manifest, and
lockfile blobs matched integrated `cf06dd816260efd246947c33385ffb7001729120`.
The feature build used a new `.scratch/unit1418-runtime-target` with
`CARGO_PROFILE_RELEASE_DEBUG=2` and completed successfully. The feature
executable SHA-256 was
`6d695a341f671169372237a416e8104ca634bef8b9306cc1069df7f6a0da1334`; its PDB
SHA-256 was
`ee23f680088d7e4b6f6536da5df3fe00cf96e4d919ba9ad322b3255bf5ce169e`.

The one-thread, CPU-used-6, CBR-1260, 1920×1080, 60-frame Ducks/In To
Tree/Old Town protocol produced byte-identical control and profiled IVF
outputs. The profiled logs contain 59 `RT_PROFILE` and 59 `EMIT_PROFILE`
records per clip: the key frame has no inter-frame record.

| Clip | RT total ms | `tx_select` ms | Share |
|---|---:|---:|---:|
| Ducks | 2,237.04 | 369.75 | 16.529% |
| In To Tree | 1,066.46 | 41.94 | 3.933% |
| Old Town | 1,084.74 | 43.83 | 4.041% |

The sums are profiling timers, not runtime comparisons. The extra timer and
counter branches can perturb the encoder, so this run makes no speed claim.

The separate exact-PDB inline query found all 1,525 direct line-11471 rows at
inline depth 0. DbgHelp therefore could not divide them among the suspected
inlined TX4 transform, quantizer, `block_error`, `cost_coeffs`, or loop.

## Decision

The runtime feature is sufficient to quantify the diagnostic `tx_select` share,
but not to establish a safe optimization or whole-encode gain. The exact IVF
match is a correctness check only. No code change is recommended from this
run.

## TX4-off follow-up

I reused the same feature executable and inputs with
`RVP9_RT_EMIT_TX4=0 RVP9_EMIT_PROFILE=1 RVP9_RT_PROFILE=1`. The existing
`bool_override` treats `=0` as false, and `realtime_tx4_candidate_enabled`
therefore disables the CPU6 TX4 candidate. The run wrote distinct
`toggleoff-{ducks,intree,oldtown}.ivf` and `.log.txt` files under the existing
remote `.scratch/unit1418-runs` directory.

All three logs had 59 `RT_PROFILE` and 59 `EMIT_PROFILE` records. Every toggle
IVF hash differed from its same-binary baseline:

| Clip | Toggle IVF bytes | Toggle IVF SHA-256 | RT total ms | `tx_select` ms | First RT / `tx_select` ms |
|---|---:|---|---:|---:|---:|
| Ducks | 527,906 | `b91073b1e51b8f1e8874f058f39e6061272376c6a6732f836ac2fb554cb605c4` | 2,045.46 | 234.51 | 21.03 / 2.81 |
| In To Tree | 339,035 | `5f11acee3f6a99534cf491f02c52e851d727d7cb7b56f09cdb958a2eef0d5387` | 1,123.49 | 26.92 | 8.29 / 0.29 |
| Old Town | 350,068 | `5cda8037a64e9d9c74d81a7ed7d44f856ecc2b2e8d703543886b8b5693da850f` | 976.18 | 24.38 | 11.85 / 0.46 |

Against baseline, `tx_select` fell by 36.576%, 35.813%, and 44.376% for
Ducks, Tree, and Town. Whole RT totals moved −8.564%, +5.348%, and −10.008%.
The first baseline/toggle RT pairs were 22.21/21.03 ms, 9.13/8.29 ms, and
9.55/11.85 ms; first `tx_select` pairs were 3.79/2.81 ms, 0.38/0.29 ms, and
0.42/0.46 ms.

This is a directional TX4-off ceiling only. The output changes mean it is not
an exact-output or quality-preserving comparison, and instrumentation makes
the timer totals unsuitable as speed claims. No code change follows.

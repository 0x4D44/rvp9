# 2026-06-23 - JRN - Fix KILN-00003 flush error drain

## Pick

Selected `RVP9-BUG-KILN-00003` from the Open queue after KILN-00004. It was Medium severity, localized to delayed flush/error handling, and could be fixed unattended with a focused regression.

## Diagnosis

`flush()` loops through `try_encode_one_popped(drain = true)`, but the error arm pushed the error and immediately broke. `try_encode_one_popped` pops the source frame before encoding, so an error after that point consumes the failed frame while leaving any later lookahead entries live.

That explains the observation: after a post-pop encode error, the first failed frame is gone, the remaining tail is still queued, and the documented "after flush the lookahead is empty and the encoder will accept new pushes" contract is false.

The explicit contract chosen for unattended fixing is fail-closed but reusable: report the first encode error once, discard the remaining live lookahead tail, clear volatile per-frame state, and return. Continuing to encode after a partial error would risk compounding state mutation, while poisoning the encoder would contradict the documented reuse contract.

## Regression Proof

Added `flush_discards_remaining_lookahead_after_encode_error`. The test fills a delayed encoder until the keyframe has encoded and multiple inter frames remain queued, then sets an empty pending ARF packet so the next flushed inter frame fails after the pop during superframe packing.

Pre-fix red proof:

```text
$null | mdtimeout 300 cargo test -p rvp9-encoder --lib flush_discards_remaining_lookahead_after_encode_error -- --nocapture
assertion `left == right` failed: flush must discard the remaining live lookahead frames after an encode error
left: 2
right: 0
```

## Fix

`flush()` now calls `discard_flush_tail_after_encode_error()` after recording the first error. The helper drains live lookahead entries with `pop(drain = true)`, clears `pending_arf_packet`, clears `svc_frame`, and resets the frame-local S2 gate.

Version bumped from `0.1.11` to `0.1.12` because this changes shipped encoder behavior.

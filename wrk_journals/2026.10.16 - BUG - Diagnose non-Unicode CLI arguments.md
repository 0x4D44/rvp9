# Diagnose non-Unicode CLI arguments — KIL-00118

Both encoder and decoder collected `std::env::args()` directly into strings. On Unix, an OS argument with invalid UTF-8 therefore panicked before the parser could return a controlled diagnostic.

Both mains now collect OS arguments through a shared `collect_args` helper and explicitly reject an argument that cannot be represented as Unicode, naming its one-based argument index. The existing string parser and Unicode path contract remain in place; this does not implement arbitrary OS-byte paths. No lossy replacement is used, since it could change a filename. Valid Unicode arguments retain their current behavior.

Observed assertion-red evidence, with temporary changes manually restored:

- Before the fix, the selected actual-CLI regression failed its normal-exit-code assertion: the encoder returned 101 instead of 1 and panicked in `std::env::args` on an invalid-byte positional argument.
- After fixing both, restoring only the decoder's old collector passed the encoder cases and failed on the decoder's 101-versus-1 exit assertion, with the same iterator panic.
- Inserting a skip into the shared helper made its valid-Unicode preservation control fail equality: only `résumé.y4m` remained instead of both `--label=東京` and `résumé.y4m`. Restoring it passed the exact test. This control mutation proves preservation separately from the panic defect.

All nine argument-library tests, 15 encoder binary tests, five decoder writer tests, the invalid-argv integration test, two help controls and two version controls passed. The integration test executes eight subprocess cases: invalid positional, long-option text and option value for each binary, plus existing output-sentinel preservation for each. Existing input sentinels also remain unchanged. The lead independently reran the nine library tests and the integration test. Workspace formatting, CLI-scoped Clippy with warnings denied and diff checks passed. This Mac's filesystem rejected creation of an invalid-byte filename with `EILSEQ`, so the fixture uses invalid bytes in real subprocess argv with valid sentinel filenames; that fixture adjustment is not regression proof. The invalid-argument subprocess coverage is Unix-only, and no Windows runtime claim is made. Tests used the task's absolute `.scratch` as `TMPDIR`.

The preselected final smoke after catch-up is `cargo test -p rvp9-cli --test cli_arg_coverage invalid_unicode_argv::both_clis_reject_invalid_unicode_in_every_argument_position -- --exact`, bounded to 60 seconds.

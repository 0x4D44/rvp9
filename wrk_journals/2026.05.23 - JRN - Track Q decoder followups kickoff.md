### Q.1 — HLDs dispatched, returned, reviewed, signed off ✓

Three `Plan`-agent design passes ran in parallel. All three came back
with strong file:line-grounded HLDs. Lead disposition:

- **Q.1.A (e2e perf):** SIGNED OFF with two revisions baked in:
  - Drop the per-host vpxdec calibration constant (it's brittle and
    unnecessary — on ≥1000-frame fixtures the construction overhead is
    <1% of total decode; on short fixtures we disclose in the ledger
    header and the rvp9 column is the authoritative number).
  - Report both rvp9 p50 AND rvp9 mean; ratio uses mean-to-mean only
    (apples-to-apples with vpxdec which has no p50 surface).
  - Confirmed Q.1.A is NOT blocked on Q.1.B (bench uses the
    `Decoder::with_threads` library, not the CLI subprocess).
  HLD saved to `wrk_docs/Track_Q/Q.1.A_e2e_perf_HLD.md`.

- **Q.1.B (--threads CLI):** SIGNED OFF with one revision:
  - Agent proposed `--threads 0` → auto-detect via
    `available_parallelism()`. This **diverges from libvpx**, which
    treats 0 as "no extra workers" (= 1 thread). For CLI parity (users
    coming from `vpxdec` expect identical semantics) the sign-off
    version is `--threads 0` → 1 thread; users omit the flag entirely
    to get auto-detect (matches `Decoder::new()`).
  HLD saved to `wrk_docs/Track_Q/Q.1.B_threads_cli_HLD.md`.

- **Q.1.C (frame-parallel decode):** SIGNED OFF with a phasing cut:
  - **Critical surprise finding** the agent flagged: our libvpx
    checkout (`third_party/libvpx/`) is the **stripped, tile-only**
    variant — `frame_workers`, `VP9FrameWorker`, the
    cross-frame sync primitives, all absent. The `frame_parallel_*`
    flag is still parsed but the supporting infrastructure is fossils
    only (e.g. `vp9_decoder.c:484` carries the commented intent with
    no implementation). So we cannot mirror libvpx line-for-line; we
    reconstruct the public design.
  - Architecture is sound (`StreamProgress` / `DecoderInstance` /
    `SharedFramePool`). Key insight: VP9 has no row-level
    cross-frame dependency at decode, so we don't need the
    `VP9FrameWorker` row-sync primitive — Arc-cloned ref frames at
    admit-time is enough.
  - Lead concern: this is a substantial refactor (`Decoder` split
    apart, mutex on the frame pool, async error propagation) and we
    have **no measured perf gap** vs PLAN gates today. Per
    CLAUDE.md ("don't predict the future"), building P2-P4 before
    measurement is premature.
  - **Scope for this /goal: P0 (no-op refactor) + P1 (two-frame
    pipeline, `frame_parallel=1` only) ONLY.** P2-P4 (widening pool,
    pipeline×tiles, default-on policy) are conditional on Q.1.A's
    measurement showing we need them. The HLD records this
    explicitly.
  HLD saved to `wrk_docs/Track_Q/Q.1.C_frame_parallel_decode_HLD.md`.

# Bound and isolate F02 anchor runs — KILN-00064

Both ordinary and spatial F02 anchor legs call `Command::output` without a deadline. The tool also creates retained run directories from whole-second timestamps with `create_dir_all`, allowing concurrent runs to reuse a directory and overwrite matching input, IVF, or sidecar names. This remains distinct from the already-fixed E1 leg.

The selected correction atomically reserves a unique retained directory under the requested output root and bounds both anchor child processes to 30 seconds. Diagnostic artifacts remain retained. The existing E1 polling runner is lifted into one private shared module used by both binaries; E1's option, measurement, report, and temporary-directory behavior stays in scope only for compatibility validation. F02 captures stderr to files rather than potentially blocking pipes, closes child stdin explicitly, and bounds capture reads and termination/reaping work.

Fake children prove deadlines are wired through both actual F02 legs, directory reservations do not collide, and success/error diagnostics remain meaningful. Finite slow fake children permit observing the old behavior fail timeout assertions without leaving an unbounded test. No separate stdin failure of the old `Command::output` path is claimed; the explicit EOF contract is tested for the replacement runner.

Observed reversals (restored manually after each experiment):

- Restoring legacy `Command::output` behavior selected 30 F02 tests and failed four assertions: ordinary/spatial deadlines returned missing-sidecar errors after the finite child exited instead of timeout errors; the loud-stderr case returned success instead of a bounded timeout; repeated invocation found zero retained capture files instead of two.
- Replacing atomic directory reservation with `create_dir_all` on the first generated candidate failed the preseeded-collision test: it returned `_0` instead of reserving `_1`. The concurrency test stayed green because unique sequence naming still separated its candidates; this partial reversal does not reproduce the entire old concurrency defect.
- Restoring timestamp-only naming plus directory reuse failed the concurrent test: eight callers received only one unique path instead of eight.
- Removing the shared runner's explicit stdin closure made its deliberately piped-stdin acceptance child block until timeout; the successful-result assertion failed.
- Injecting deletion of the owned test run directory failed the retained-artifacts assertion on `run_dir.is_dir()`.
- Moving raw-input cleanup after error propagation failed the spawn-failure assertion because the raw input remained.
- Disabling the injected shared-runner deadline made its finite child exit naturally with status zero; the expected-timeout assertion failed.

The successful fake anchor produces empty placeholder IVF/JSONL files solely to test process completion and artifact retention. Those placeholders are not codec-validity or nonempty-measurement evidence. The subprocess helper is registered as an actual test; its stdin acceptance case requires an execution marker reserved empty with `create_new`, so zero-test success or stale marker content cannot count as evidence. Initial helper registration and stale-marker risks were caught during review and corrected before acceptance.

Final worker and independent lead runs each passed `cargo test -p rvp9-harness --bin f02-block-oracle --bin e1_block_stats`: F02 30 tests and E1 24 tests. The worker also passed rustfmt, scoped Clippy for both binaries across all targets, and diff checks. The lead compiled both production binaries for `x86_64-pc-windows-gnu` with `RUSTFLAGS='-C target-cpu=x86-64'`; that is compilation evidence, not Windows runtime evidence. All validation used task-local `TMPDIR`, closed stdin, and Deltic timeouts. No actual patched-libvpx, codec-parity, physical Windows, or OS kill/reap-failure simulation is claimed.

The shared runner polls direct-child status, sends termination on timeout, and bounds reap polling to one additional second. It reports the PID if cleanup cannot complete. Capture reads are bounded to 64 KiB plus one truncation-detection byte; per-leg first-five/first-eight-line diagnostics remain. The deadline does not claim process-tree termination. Fake shell encoders use `exec sleep` where relevant so their deliberate delay is the direct child. Run/report/IVF/sidecar artifacts and captures remain retained; raw transient input is removed before propagating child errors. Scratch is left for authorized integration teardown.

Preselected final smoke after final fetch/catch-up: `TMPDIR="$PWD/.scratch" deltic timeout 60 cargo test -p rvp9-harness --bin f02-block-oracle </dev/null`.

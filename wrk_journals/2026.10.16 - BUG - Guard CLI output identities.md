# RVP9-BUG-KIL-00117 — Guard CLI output identities

The encoder and decoder opened outputs with truncation while still reading their
inputs. Encoder frame-time CSV could also replace a completed IVF. Equal paths,
symlinks and hardlinks therefore destroyed another active role's contents.

The private shared `path_guard.rs` captures existing role identities before input
parsing, then opens each output without truncation and checks its actual handle
against retained identities and freshly resolved other paths before truncating.
This also catches case/Unicode aliases and dangling links between initially
missing IVF and CSV destinations. All ordinary, spatial, two-pass, decoder and
CSV creation sites use the guard. Decoder output creation remains deferred until
the first emitted frame; pure `--noblit` keeps ignoring its output option.

Unix uses device/inode identities; Windows uses a small Kernel32 binding for
128-bit file IDs, with no new dependency. Unavailable regular-file identity fails
closed. Nonregular sinks keep working without a `set_len` call. Ordinary overwrite
semantics, including unrelated output hardlinks, remain in place.

## Evidence

- Before production edits, the new actual-CLI integration target executed 25
  tests: 24 alias regressions failed on changed bytes, unexpected output creation,
  or missing early alias diagnostics; the independent positive passed.
- After the fix, the expanded target executed 29 tests and all passed. Both
  filesystem capability probes were active here: future case and Unicode aliases
  were exercised, not skipped.
- Removing guarded-open identity comparisons while retaining preflight executed
  29 tests: six failed, specifically future case, future Unicode, dangling link,
  relative dangling-link chain, symlink-parent and a late hardlink introduced
  after preflight. The late-hardlink assertion observed input bytes change when
  comparison was omitted. Restoring the guard returned all 29 to green.
- Positive test calibration changed expected stdout MD5 lines from two to three:
  the selected test failed with actual two/expected three, then passed after
  restoration. The nonregular-sink test separately failed under an inverted
  expected-success assertion and passed after restoration. These calibrations
  verify the positive oracles; they are not defect reproductions.
- A mutant removing the nonregular truncation gate did not fail on this Mac:
  `set_len` on its null device succeeded. This is explicitly not counted as a
  failure proof for Linux or Windows device behavior.

## Review and limits

An independent GPT-6.1 Sol medium reviewer found no defect after the final source
reread, including all output branches, retained identities and Windows ABI. A
read-only Claude Opus 5.5 medium correctness consult supplied the missing-output
identity argument; the lead's accepted design and refinements are committed in
`wrk_docs/2026.10.16 - HLD - CLI destination alias guard.md`.

Windows validation is cross-target compilation, not native execution. Existing
role contents are preserved on rejection; a newly created future alias can leave
an empty file. Adversarial concurrent path replacement and shell redirection
before process startup are outside the explicit-path contract. The bug remains
Fixed for a different verifier; this fixing pass does not close it.

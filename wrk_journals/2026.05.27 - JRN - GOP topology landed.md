# 2026.05.27 — JRN — GOP topology (GfGroup) landed

**Status: LANDED.** Phase-I infra: a libvpx-faithful `GfGroup` struct is
now the single source of truth for the encoder's per-frame golden-frame-
group schedule. Gate-safe, byte-identical refactor. Unblocks TPL (A23)
and 2-pass VBR (both consume `update_type[]` / `arf_src_offset[]` /
`gf_group_size`).

## What was scheduling frame types before (file:line)

`crates/rvp9-encoder/src/frame_loop.rs`, three ad-hoc decision sites:

1. **KF cadence** (`:1101`): `frame_idx.is_multiple_of(gop)` → `Key`,
   refresh `0xFF` (`build_keyframe_packet`, KF reset at `:1446`).
2. **GOLDEN refresh** (`:2051-2058`, old): `frames_since_golden_refresh`
   counter (reset on KF + on refresh), incremented-then-checked
   `>= A14_GOLDEN_REFRESH_PERIOD (8)` → refresh `0x03`, else `0x01`.
3. **ARF cadence** (`:1247`, old): `inter_frames_since_arf >=
   max(gop/2, 2)` (+ lookahead peek) → non-show ARF (`0x04`),
   superframe-prepended. Only when `enable_alt_ref`.

These were TWO independent cadences (GOLDEN period = const 8; ARF =
gop/2) that libvpx's 2-pass `define_gf_group_structure` merges. The
1-pass RT path the encoder runs does not merge them.

## What landed

`crates/rvp9-encoder/src/gop.rs` (375 LOC incl. 8 unit tests):

- `FrameUpdateType` enum — discriminants match libvpx exactly
  (`vp9_firstpass.h:62-71`: KF=0, LF=1, GF=2, ARF=3, OVERLAY=4).
- `GfGroup { gop_length, gf_interval, enable_alt_ref }` modelled on
  libvpx `GF_GROUP` (`vp9_firstpass.h:80-100`). Constructor
  `GfGroup::new(gop_length, enable_alt_ref)` is the
  `define_gf_group_structure`-equivalent for 1-pass
  (`vp9_firstpass.c:2257-2302`).
- `schedule(frame_idx) -> FrameSchedule { update_type,
  refresh_frame_flags, frame_gop_index, arf_before, arf_src_offset }`
  resolves the disposition from the GOP-relative offset (a deterministic
  function — no materialised array needed for unbounded GOPs).
- Accessors for the TPL/2-pass consumers: `update_type()`,
  `arf_src_offset()`, `gf_group_size()`, `gf_interval()`.

Faithful schedule (reproduces current decisions EXACTLY):
- offset 0 → KfUpdate / 0xFF.
- inter offset `% 8 == 0` → GfUpdate / 0x03.
- ARF at offset `gf_interval + 1` (matches the old `>=` counter: the
  trigger checks BEFORE counting the current frame, so the ARF lands one
  frame after `gf_interval` inter frames have been coded).
- else → LfUpdate / 0x01.

Wiring in `frame_loop.rs`: added `gf_group` field (built in `new()`),
replaced all three decision sites with `gf_group.schedule(frame_idx)`
reads. Removed the dead `A14_GOLDEN_REFRESH_PERIOD` const (moved to
`gop::GOLDEN_REFRESH_PERIOD`). The `frames_since_golden_refresh` /
`inter_frames_since_arf` counters are KEPT in lock-step (ARF picker path
+ diagnostics read them) but the SCHEDULE is now the flag authority.

## 2-pass fields deferred (documented follow-up)

libvpx `GF_GROUP` 2-pass-only fields NOT modelled (need first-pass
stats): `rf_level[]`, `layer_depth[]`, `bit_allocation[]`, `gfu_boost[]`,
`arf_index_stack[]`, `top_arf_idx`, `group_noise_energy`. These slot in
when 2-pass VBR lands. The 1-pass subset stayed at 375 LOC (under the
~300 LOC implementation budget once tests are excluded: ~210 LOC of
struct + schedule).

## PROOF (`crates/rvp9-encoder/tests/w_gop_topology.rs`, 300 LOC)

1. **Anti-G3 schedule fidelity** (`gop_topology_schedule_matches_emitted_frames`):
   encode 40 frames (gop=16), decode each packet's uncompressed header,
   assert the ACTUAL emitted `(frame_type, refresh_frame_flags)` EXACTLY
   matches `GfGroup.schedule(idx)` for every frame. Hard counts: 3 KFs
   (idx 0/16/32), 2 GF_UPDATEs (idx 8/24), rest LF. A stub or divergence
   fails. PASS.
2. **Byte-identity** (`gop_topology_byte_identity`): FNV-1a golden over
   the concatenated bytes. **len = 26015, fnv1a = 0xc077248934d1d266.**
   Confirmed byte-identical to the PRE-refactor encoder by stashing the
   GfGroup wiring + re-running the identical encode (a throwaway
   `gop`-free capture harness): pre-refactor produced the SAME
   len/hash. Pins `RVP9_A4_RD_PARTITION_DISABLE` (mirrors
   `tests/w_buffer_pool.rs`).

## Risks / honest scope-downs

- The ARF trigger condition changed from `inter_frames_since_arf >=
  arf_interval` (`>=`) to the schedule's `offset == gf_interval + 1`
  (`==`). These differ ONLY if the ARF is skipped at its boundary
  (lookahead peek unavailable) and the old code then fired it late. That
  edge case is in the ALTREF feature (OFF on the gate, `enable_alt_ref =
  false`) and represents the PLANNED cadence, which the struct should
  model. Byte-identity holds for the gate + the test config. When ALTREF
  is wired for real, re-verify the late-fire path or fold the peek-gate
  into the schedule.

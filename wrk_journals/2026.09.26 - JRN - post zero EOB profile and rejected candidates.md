# Post-zero-EOB profile and two rejected exact candidates

The exact integrated x86 profile at code commit `48cab42d` is in `wrk_docs/evidence/2026-09-26-after-zero-eob-integrated-three-clip-ip/`. All three 60-frame IVF hashes matched; the PE/PDB pair was verified and each trace had zero lost events/buffers. It is a hotspot map, not a new parity measurement. The latest paired pinned-libvpx result remains **1.134647×** equal-clip process CPU (Ducks 1.249014, Tree 1.128710, Town 1.036176); reaching ≤1.05× needs about 7.5% less CPU from the current integrated code.

Exact-PE Ducks disassembly corrected an apparent TLS lead: `inter.rs:2428` has 128 self samples but actual `gs:0x58` TLS accesses have **zero**. The hottest nearby post-candidate path is denoiser minimum tracking at `inter.rs:2950–2971`, 33/2,072 Ducks self samples. The full-pixel diamond search and SAD4D adapter have 105 and 57 Ducks self samples, but the isolated bounds/slice checks in the adapter are only 17 samples. No single exact full-pixel instruction cluster yet justifies a large rewrite. FDCT8/FDCT16 dispatch source lines are not operation-level estimates; prior transform prototypes were neutral or slower.

Two bounded changes were prototyped and rejected with complete evidence:

- `wrk_docs/evidence/2026-09-26-vertical-row-carry-rejected/`: 16-wide AVX2 vertical-only sub-pixel row carry was byte-exact, with deliberate wrong-row red, six x86 AVX2 tests green, and AArch64 checks green. Its 15-pair screen was slower on Ducks/Tree/Town: **1.019256/1.013603/1.027028×**, **1.019947× overall**. The patch and raw data are archived; no code landed.
- `wrk_docs/evidence/2026-09-26-denoiser-off-minima-neutral/`: the output-backed picker skipped denoiser minima only where `job_denoiser.is_none()`. Its focused result/prediction differential went red before the fix, then green; 96 inter-picker tests passed on AArch64 and x86. Three 15-pair screens gave overall **0.994762, 1.008154, 0.991538×**; combined **0.998126×** and signs reversed. The patch and all 288 exact-output rows are archived; no code landed.

Both rejected remote prototype worktrees and branches were removed after their scratch was cleared; their patches and measurement CSVs remain on `origin/main`. The separate Crucible profile worktree remains because it owns the raw ETLs. Local and remote production code are unchanged. The next bounded selection should resolve current-image IPs within the **Town round-trip reconstruction symbol (122/1,160 self samples)** and the **Tree/Town sub-pixel variance/reduction path**, checking prior prototype history before building. Do not infer a gain from those samples; require exact differential/red, AArch64/x86 validation, and repeatable paired process CPU before integration. A retained gain then needs a fresh pinned-libvpx parity screen.

# JRN — TPL (Temporal Dependency Model) integration assessment — A23

**Date:** 2026-05-26
**Author:** Claude (investigation agent, G3 discipline)
**Decision:** **PATH B — DEFER.** Bounded gate-safe integration is NOT
achievable in this scope. The ported TPL module is the leaf-primitive
half of the subsystem; the driver half (`mc_flow_dispenser` + its
ME / GOP-topology / quant-roundtrip dependency chain) is entirely
absent, and one of its prerequisites (a GF-group/ARF-GOP structure)
does not exist anywhere in the encoder.
**Code change:** NONE.

---

## 1. What the ported TPL module contains (verified, file:line)

`crates/rvp9-encoder/src/tpl/` — **1682 LOC** (matches the re-audit's
~1683), declared at `crates/rvp9-encoder/src/lib.rs:92` (`pub mod tpl;`)
and otherwise **0 production callers** (grep for `tpl::` outside
`src/tpl/` returns nothing; the only consumers are the in-module
`#[cfg(test)]` PROOF tests). A23's "whole dead zone" finding is
accurate.

The four sub-modules are faithful, well-cited ports of the libvpx
**leaf primitives** (v1.14.1 commit `12f3a2ac6`):

| rvp9 file | What it ports | libvpx source | Status |
|---|---|---|---|
| `tpl/stats.rs:1-449` | `TplDepStats`/`TplDepFrame`/`TplGopState` data layout + `init_gop_frames` topology skeleton | `vp9_encoder.h:292-326`, `vp9_tpl_model.c:25-166` | data layout complete; `init_gop_frames` is a **linear-LF-chain skeleton** (`stats.rs:368-381` documents: no lookahead pull, no buffer_pool, no ARF stack) |
| `tpl/mode_est.rs:1-329` | per-block intra/inter SATD `mode_estimation` | `vp9_tpl_model.c:571-727` | **takes MVs + predictor patches as caller inputs** (`mode_est.rs:79-90`); no motion search, no sub-pel MC, no quant roundtrip, 4 of 10 intra modes |
| `tpl/update.rs:1-258` | `tpl_model_store` + `tpl_model_update(_b)` backward propagation | `vp9_tpl_model.c:333-489` | **complete and exact** (round_floor, get_overlap_area, 4-quadrant flow projection) |
| `tpl/rdmult.rs:1-217` | `get_rdmult_delta` + `vp9_get_adaptive_rdmult` + RDO `cb_rdmult` hook | `vp9_encodeframe.c:3719-3768`, `vp9_rd.c:304-310`, `vp9_encodeframe.c:2235-2242` | **complete and exact**, including the `[orig/2, orig*3/2]` cap and the `is_valid`/`layer_depth<=1`/`gf_group_index<MAX_ARF_GOP_SIZE` gates |

So the *consumption* side (`get_rdmult_delta` → `cb_rdmult` → RDO
lambda) and the *propagation* side (`tpl_model_update`) are
production-quality. The **production** side that fills the stats
(`mode_estimation` with real ME + the `mc_flow_dispenser` driver that
sequences it) is the missing half.

## 2. The integration point exists and is clean (1 line)

The RDO lambda is computed at `crates/rvp9-encoder/src/lib.rs:3818-3821`:

```rust
let rdmult = i64::from(rvp9_core::cost::compute_rd_mult(
    i32::from(leaf_qindex),
    rvp9_core::cost::FrameTypeForRd::Inter,
));
```

and threaded into the dispatch leaf at `lib.rs:3894` (`rdmult,`), which
feeds `InterDispatchLeaf::rdmult` (`rdo/inter_dispatch.rs:212`). This is
exactly libvpx's `x->rdmult` consumer site. Substituting a TPL
`cb_rdmult` here behind an opt-in flag would be a ~3-line hook — IF a
populated, `is_valid` `TplDepFrame` were available. **It is not, and
producing one is the whole problem.**

## 3. What is missing for integration (the driver + its prereqs)

Integration requires `vp9_setup_tpl_stats` (`vp9_tpl_model.c:1492-1540`)
and its core `mc_flow_dispenser` (`vp9_tpl_model.c:1138-1255`). Reading
those reveals a dependency chain that is mostly absent from rvp9:

1. **A real per-block, per-ref motion search inside TPL — MISSING.**
   `mc_flow_dispenser` → `mode_estimation` (`vp9_tpl_model.c:666`) calls
   `motion_compensated_prediction` (`vp9_tpl_model.c:280-330`), which
   runs `vp9_full_pixel_search` (NSTEP diamond) + `find_fractional_mv_step`
   (sub-pel) **per reference frame per 32×32 block**, then
   `vp9_build_inter_predictor` (sub-pel 8-tap EIGHTTAP MC) to form the
   predictor. The rvp9 `mode_estimation` (`mode_est.rs:232`)
   deliberately accepts MVs + integer-pel predictor patches from the
   caller (`mode_est.rs:21-32`, `:79-90`) and does NO search. A
   `single_mv_search` driver exists (`rdo/single_mv_search.rs`) and
   could in principle be repurposed, but it is built for the RDO
   per-leaf path (NEAREST/NEAR seeds, mv-cost arrays), not the TPL
   "best_ref_mv1 = {0,0}, ignore mv cost" search at `vp9_tpl_model.c:297,326`.
   A new TPL-specific ME loop over the whole frame at 32×32 granularity
   (the `mc_flow_dispenser` row/col loop, `vp9_tpl_model.c:1231-1253`)
   plus sub-pel 8-tap inter prediction wiring is **net-new** work
   (~250-400 LOC), not "wire the existing scaffold".

2. **A GF-group / ARF-GOP topology — MISSING ENTIRELY.**
   `vp9_setup_tpl_stats` (`vp9_tpl_model.c:1494`) reads
   `cpi->twopass.gf_group`; `init_gop_frames` (`vp9_tpl_model.c:25-155`)
   walks that group + `cm->buffer_pool` frame_bufs to build the
   `gf_picture[].ref_frame[3]` topology and claim recon buffers. rvp9
   has **no GF-group structure** — only an `inter_frames_since_arf: u32`
   counter (`frame_loop.rs:614`) and a `baseline_gf_interval` comment
   (`frame_loop.rs:611,1232`). The rvp9 `init_gop_frames` (`stats.rs:384-422`)
   is explicitly a skeleton that models only a linear LF chain and pulls
   no buffers. The `buffer_pool` (A10) it would need is itself dead (0
   callers per the re-audit). So TPL has no way to learn the GOP's
   forward reference structure, which is the input that makes the
   backward propagation meaningful.

3. **Forward recon buffers for the lookahead window — MISSING.** TPL
   propagates over *coded* recon of future GOP frames. The lookahead
   ring (`lookahead.rs`, wired at `frame_loop.rs:477,787,2593`) buffers
   **raw source** frames only (used for ALTREF ARNR peek). TPL's ME runs
   source-vs-source for the leaf frames but the propagation chain in
   libvpx threads recon buffers via `gf_picture[].frame` from the buffer
   pool. No such per-GOP recon staging exists.

4. **Quant roundtrip — MISSING.** `mode_estimation` in libvpx writes
   `recon_error`/`rate_cost` via `get_quantize_error` +
   `rate_estimator` (`vp9_tpl_model.c:491-570, 713-715`); the rvp9
   scaffold leaves these unimplemented (`mode_est.rs:27-32`). The
   backward propagator (`update.rs`) does not read them, so this is the
   least-critical gap — but `tpl_store_before_propagation` and the
   Qmode sidecar are also absent.

## 4. Realistic LOC estimate

The re-audit's "~400 wire + mode_est" understates it. Honest breakdown
of NEW code (on top of the 1682 LOC ported):

| Piece | LOC | Note |
|---|---|---|
| GF-group/ARF-GOP topology struct + per-GOP build from the ALTREF schedule | ~250 | net-new; A2/A10 territory |
| Per-GOP recon-buffer staging (or a source-only approximation + its correctness argument) | ~150 | net-new |
| TPL-specific full-frame ME loop (32×32, per-ref, zero-ref-mv, no mv-cost) + sub-pel 8-tap inter predictor wiring | ~300 | repurpose `single_mv_search` + `mv_search` kernels, but the harness is new |
| `mc_flow_dispenser` driver (sequence mode_estimation → store → update over the reversed GOP) | ~120 | the `vp9_tpl_model.c:1138-1255` loop |
| `vp9_setup_tpl_stats` orchestration + `TplGopState` on `StreamEncoder` + per-frame `gf_group_index`/`layer_depth` plumbing | ~120 | |
| `cb_rdmult` hook at `lib.rs:3818` behind `enable_tpl` flag + EncoderConfig/CLI plumb | ~40 | the only genuinely small piece |
| quant roundtrip (`get_quantize_error`/`rate_estimator`) | ~120 | optional for a first cut |
| PROOF tests (gate-off byte-identical, TPL-on byte-exact-through-vpxdec, TPL-on-differs) | ~150 | |

**Total: ~1250-1350 LOC of net-new wiring/driver code**, dominated by
infrastructure that does not exist yet (GF-group topology, per-GOP recon
staging, the TPL ME harness). This is **~3x the audit's 400-LOC
estimate** and well over the ~400-LOC bounded-scope ceiling. It is not a
"wire the scaffold" job; it is "build the driver half of the
subsystem + a prerequisite GOP-topology structure".

## 5. Prerequisite chain

```
TPL cb_rdmult (1-line hook, ready)
  └─ populated is_valid TplDepFrame
       └─ mc_flow_dispenser driver (MISSING)
            ├─ TPL full-frame ME + sub-pel MC (MISSING; single_mv_search is RDO-shaped)
            ├─ GF-group / ARF-GOP topology (MISSING ENTIRELY — no struct exists)
            │    └─ buffer_pool / per-GOP recon staging (A10 — also dead)
            └─ quant roundtrip (MISSING; non-blocking)
```

The GOP-topology prerequisite is the structural blocker: A2 (frame-loop)
has no GF-group array, and A10 (buffer_pool) is itself a dead zone. TPL
cannot be cleanly bounded ahead of those.

## 6. Is A23 an acceptable vpxenc-parity deferral?

**YES — acceptable, with a caveat.**

- **Correctness:** TPL is a pure quality/rate-distortion *optimization*.
  It adjusts per-superblock `rdmult` (RDO lambda); it changes WHICH
  modes/MVs the picker prefers, not the bitstream syntax. A VP9 stream
  encoded with TPL off is fully valid and decodable — which is exactly
  why the sacred `cross_decoder_gate` (byte-exact through vpxdec +
  ffmpeg) passes today without it. Deferring TPL costs **BD-rate
  efficiency**, not standards conformance. For a "match vpxenc bitstream
  / decode correctly" goal, this is a legitimate quality-lever deferral
  in the same class as A20 HBD and A21 ML-partition.

- **Caveat (honesty, not a blocker):** if the exit-gate criterion is the
  stricter "byte-identical to vpxenc's *default* output", then vpxenc
  enables `enable_tpl_model` by default at good-quality speeds, so a
  bit-for-bit match to vpxenc's default would eventually require TPL.
  But the project's gate is **decodes byte-exact through vpxdec/ffmpeg**
  (valid-stream parity), not encoder-output-identity — under that gate
  TPL is correctly out of the critical path.

**Conclusion:** A23 is an acceptable deferral for the stated
vpxdec/ffmpeg byte-exact gate. It should be filed alongside A18 (SVC)
and A10 (buffer_pool) as a coupled cluster — TPL's structural
prerequisite (a real GF-group/ARF-GOP topology + recon buffer pool) is
shared with those zones, so they are most cheaply done together in a
dedicated "GOP infrastructure" wave, not piecemeal. Forcing a
half-integration now would either (a) break the gate (TPL not opt-in
clean), or (b) ship a fake TPL fed by a degenerate linear-chain topology
that produces wrong propagation and a worthless `cb_rdmult` — the exact
adversarial-cheat the project's discipline forbids.

## 7. Gate status (unchanged — no code touched)

No code change made. The sacred `cross_decoder_gate` is unaffected
(4/4 byte-exact as of the re-audit). The TPL module remains compiled +
PROOF-tested but inert, exactly as found.

## 8. Recommendation

Defer A23 to a "GOP infrastructure" wave bundling A10 (buffer_pool
wiring) + a real GF-group/ARF-GOP topology struct. Once those land, the
TPL driver (`mc_flow_dispenser` + TPL ME harness, ~600-700 LOC) becomes
a bounded follow-up, and the `cb_rdmult` hook at `lib.rs:3818` behind an
`enable_tpl` flag is then genuinely a few lines. Until then, the
1682-LOC ported leaf-primitive module is correct, tested, and waiting —
not wasted, but not bounded-integrable on its own.

# Serialize throughput CSV writers — KIL-00115

The queue selected KIL-00115 after the earlier build-script fix was recorded. KIL-00108 fixed CSV escaping and metric validation; KIL-00114 fixed baseline identity. Neither serialized concurrent appenders. The current writer opens the destination and checks its length before writing the header, record separator, and batch through multiple writes.

The repair uses the standard library's exclusive file lock immediately after opening the destination and before inspecting its contents. The existing read-plus-append open mode supports this lock on Windows as well as Unix. The file stays open for the entire batch, and dropping it releases the lock on every return path. Validation still precedes directory or file creation. This introduces no dependency or CSV schema change. The guarantee concerns cooperating appenders using the same file; it does not add crash recovery or serialize readers.

The installed Rust 1.95 documentation identifies `File::lock` as stable since 1.89, implemented with Unix `flock` and Windows `LockFileEx`, with release when the file handle closes. The repository pins Rust 1.95.

The focused subprocess target has two parent regressions and one ignored helper that the parents explicitly launch. Each child closes stdin, uses a private temporary directory, signals immediately before append, and is bounded and reaped by its parent. The first regression starts a writer behind an existing-file lock. The second releases eight writers from a barrier against an empty, locked CSV; after releasing the lock it checks one header, all 32 unique rows with exact identities and metrics, quoted and multiline fields, and contiguous four-row batches. While the lock is held, both tests inspect length through the holder's handle, avoiding a second-handle read under Windows locking.

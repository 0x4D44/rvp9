# Track-F iter5 — model_rd-driven picker→emit skip plumbing (NULL, reverted)

Date: 2026-05-27
Branch: main @ bcad0d5
Outcome: **Null result — reverted.** The libvpx-faithful model_rd skip
detector is the correct semantic predicate (no PSNR collapse like
iter4's RD tie-break), but at the CBR operating point it fires on
blocks where the alternative residual would have produced ~0 bits
anyway. Net bitstream change ≈ 0, net PSNR change within noise.
The picker→emit skip plumbing is structurally re-validated; iter5
proves model_rd alone isn't the lever.

## Anatomy reused from iter4

Same plumbing chain as iter4 (which proved structurally correct;
iter4 failed because of the RT picker's `coef_rate` bit estimate
miscalibration driving the wrong `rd_encode < rd_skip` decisions).
This iter5 swap **replaces the predicate**, not the wiring:

- iter4: `picked_skip = !(rd_encode < rd_skip)` — raw RD tie-break,
  poisoned by inflated `coef_rate`.
- iter5: `picked_skip = (mrd.skip_txfm == SkipTxfm::AcDc)` — libvpx's
  variance/dequant-driven skip classification, model-only (no entropy-
  bit estimate involved).

## Diagnosis — why null

Diagnostic counters during a 1200k cpu7 CBR run reported 6.02% of
inter-leaf picker calls return `picked_skip = true`. The blocks
that fire are blocks where:
1. The MC prediction is already very close to the source (small
   residual variance).
2. The finer post-quant zbin threshold the model uses
   (`zbin^2 >> 6`) is loose enough to declare AC and DC coefficients
   "skippable" by inspection.

These are exactly the blocks where the actual forward-quant would
have produced very few non-zero coefficients (which encode to ~0
bits via the small-coef contexts) — and even those small bits are
balanced against the `skip_cost0` vs `skip_cost1` bit the writer
emits. The bitstream-size effect cancels out at the leaf level for
most fired blocks. At qp=70 (very low Q) the predicate degenerates
to "never fires"; at very high Q the predicate over-fires but the
real residual would be tiny anyway.

## Why iter4 looked dramatic at qp=70 and iter5 doesn't

iter4 used `rd_encode < rd_skip` which compares
`lambda*(rate+coef_rate_inflated) + dist` against
`lambda*0 + sse_after_pred`. The inflated `coef_rate` makes
`rd_encode` look big regardless of actual coef bits, so skip wins
for blocks with non-trivial residual. **iter4 over-skipped** ⇒ huge
bitstream shrink + PSNR collapse.

iter5's model_rd predicate is conservative by design (libvpx-
faithful): it skips ONLY blocks where the dequant ladder predicts
zero AC/DC coefs. Those are blocks where libvpx itself skips. **The
encoder was already producing similar bitstreams on those blocks
via real forward-quant + the RC.X1 zero-eob override.** The model
just lets us short-circuit the work; it doesn't change the output
materially because the work was producing the same result.

## Per-iteration AQ tests fail (expected secondary effect)

`aq_cyclic_refresh_segment_1_has_finer_quantization`'s 10% SSE
tolerance trips because AQ-on segment-1 cells get the libvpx-
faithful early-skip more aggressively (finer Q → tighter zbin →
more model-skip firings). The test was tuned against the pre-iter5
encoder which always emitted residual; iter5 honors the predicate.
These tests need retuning for the model_rd skip behavior, but
fixing them isn't part of the iter5 brief.

## Next lead

The picker→emit skip plumbing is **structurally correct** (iter4
proved this with bitstream shrink at qp=70), and the model_rd
predicate is **semantically correct** (iter5 proves no PSNR
collapse, byte-identical at low Q). Combined, they reveal: **the
current rvp9 encoder is NOT residual-bound at the bitrate operating
points** — both libvpx-skip-equivalent blocks and bit-spending
residual blocks already produce near-equivalent outputs.

The PSNR gap to vpxenc (cpu7 1200k: 38.07 vs vpxenc inf — vpxenc
hits the encoder's near-lossless ceiling) is **not in the inter
mode decision skip path**. The remaining gap is somewhere else:

1. **Mode/MV decision quality** (modes chosen at the picker —
   NEAREST/NEAR/ZERO/NEW + the MV refinement quality). iter3
   already explored inter-RD lambda/MV-cost levers and found null;
   this confirms it.
2. **Intra-in-inter classification accuracy**. iter1/iter2 showed
   intra-fallback wasn't the dominant gap on inter frames at this
   working point, but intra-in-inter for the >30% of cells where
   the source-to-LAST-prediction MSE is high may have miscalibrated
   intra-cost-penalty.
3. **Transform/quant precision differences** — rvp9's
   `inter_forward_quant_one_tx` vs libvpx's quant-b path: zbin
   shaping, round offsets, dead-zone width. A small Q-step
   difference per coefficient compounds across 25k+ quantizations
   per frame.
4. **Reference filtering / ARF / GOP topology**. rvp9's ARF picker
   landed (2ab37e1) but the GOP topology may not be producing the
   reference quality libvpx achieves with its adaptive ARF + GF +
   filtered ARF.

The autonomous-lever sweep across Track-F (5 iters: KF cap, intra,
inter-RD, skip-flag plumbing, model_rd skip) has now tried every
mode-decision-side lever the source-tree exposes WITHOUT touching
transform/quant precision. The next quality push will need to
quantify the per-stage error contribution via a per-leaf oracle
(record pred-SSE, post-quant-SSE, post-recon-SSE per leaf at qp=70
for both rvp9 and a libvpx-faithful round-trip; the gap location is
where the SSE delta concentrates).

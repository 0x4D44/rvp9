# Inter-frame drift RESOLVED — session summary (2026-05-27)

## Context
Re-audit pass 4 + a concurrent quality measurement (Claude+Arthur) found the
encoder was byte-exact-correct but **11-28 dB below libvpx**, with monotonic
PSNR decay across the GOP (inter-frame drift) and the RDO path ~10 dB worse than
the RT picker. The byte-exact cross-decoder gate was BLIND to it — it compares
rvp9-decoder vs vpxdec (decoder-vs-decoder), never the encoder's stored reference
vs the true decode. Arthur directed this session to fix the drift before any more
full-integration feature work.

## The diagnostic oracle (the missing test)
`crates/rvp9-encoder/tests/drift_diag.rs` (+ `diag_prelf_recon`/`diag_last_recon_y`
in frame_loop.rs): encodes N frames, decodes the bitstream with the
conformance-correct rvp9-decoder, and compares the decoded frame to the encoder's
STORED reference per frame. This directly measures encoder-recon-vs-true-decode
divergence — the drift the byte-exact gate cannot see. It is now a permanent
regression oracle.

## Root causes (4 independent encoder bugs; stored reference != true decode)

1. **KF Z-order recon** (58d0592, dominant 3.18M SSE): `leaves_from_decision`
   emitted partition leaves in RASTER order, but the decoder reconstructs in VP9
   quadtree Z-order — intra prediction used zero-init neighbours. Fix: recurse Z-order.
2. **IDCT eob-dispatch** (58d0592): encoder called full IDCT unconditionally; the
   decoder uses eob-bucketed kernels (idct16x16_38 differs ±1/px). Fix:
   `enc_inverse_transform_add` mirrors the decoder.
3. **Per-block interp filter** (58d0592): the writer's MI grid hardcoded EightTap,
   dropping each leaf's `picked_interp_filter` under a Switchable frame. Fix: emit it.
4. **GOLDEN ref-index** (b8d2327): writer emitted `ref_frame_indices=[0,0,0]`, so
   the decoder resolved GOLDEN→ref_frame_map[0] (=frame1 after the LAST-refresh)
   while the encoder predicted GOLDEN from ref_frame_map[1] (=KF). Fix: identity map
   [0,1,2].
5. **prev-MV gate + NEAREST/NEAR** (2067127): encoder gated prev-frame-MV salvage on
   `config.use_prev_frame_mvs` (default false), but the decoder derives
   use_prev_frame_mvs from FRAME STRUCTURE (not a header bit) → NEAREST/NEAR resolved
   different MVs each side. Fix: gate on the decoder's structural predicate
   (`!last_frame_was_key && last_show_frame && size_match`); re-pin NEAREST/NEAR
   best_mv to the causal-grid `find_mv_refs` result (the decoder's z-order view).
   (Sub-pel MC was a red herring — `inter_predictor` was already bit-exact.)

## Verified results
- **drift_diag**: STORED-vs-DECODE SSE = **0 for every frame** (KF + all inter),
  both widths (256, 320), both speeds (cpu4, cpu7). Encoder recon == true decode.
- **PSNR (independent bdrate, cpu7, foreman 320x256 60f)**: 400k 33.05 / 1200k 37.92
  / 2000k 40.09 dB (was ~24-26 with drift). Quality now RISES with bitrate — the
  "worse with more bits" pathology is gone. Gap to vpxenc: 11-28 dB → **2.4-4.5 dB**.
- **Cross-decoder gate 4/4 byte-exact**; `cargo build --workspace` clean.
- Two intentional bitstream goldens updated (streams shrink: w_buffer_pool 6211→6117,
  w_gop_topology 26015→25670 — better compression, gate still 4/4).

## Status
SEVERITY-1 drift RESOLVED. The encoder is now competitive (finite ~2-4.5 dB gap,
no drift). The remaining gap is the normal intra/lambda quality gap (Track F:
SATD/Hadamard + lambda co-tuning), NOT drift. The full-integration feature work
(paused for this fix) was layered on a sound base for the wire-correct features
(byte-exact gate stayed green throughout); now the RD decisions those features make
are also quality-sound.

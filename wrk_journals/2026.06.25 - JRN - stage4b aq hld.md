## Phase 1 - Understand

Launched three read-only workflow readers:

- AQ implementation state: current cyclic-refresh AQ, segmentation, frame-loop, and quantization plumbing.
- Rate-control / frame-loop constraints: base-q ownership, AQ-off invariant, Stage 4a dependency, product config assumptions.
- Harness state: quality, cross-decoder, and realtime gates; missing AQ-on coverage; data and reference-binary prerequisites.

Results:

- AQ is already partially live: `AqMode::Off | CyclicRefresh`, optional CR state, spatial segmentation, segment-1 ALT_Q, per-leaf effective q, keyframe reset, and post-encode age/q feedback.
- Remaining implementation gaps are real, not just gate hardening: BOOST2 is not live, per-frame dynamic q-delta/threshold setup is not wired, per-block rate/dist/MV adjustment is not used in production, and rate control is still cyclic-refresh blind.
- Rate control owns base q. The HLD should keep that boundary: AQ adds segment ALT_Q deltas and maintains CR state, while RC keeps mode and base-q ownership.
- Stage 4b can be designed in parallel with Stage 4a if it treats Stage 4a as an interface contract. Product BD-rate acceptance should wait for Stage 4a stabilization because picker, skip, partition, and RC changes move AQ feedback.
- Current Stage 4b four-curve harness is measurement infrastructure, not an enforceable gate. It prints the 0.3% result but does not assert it. AQ-on cross-decoder and AQ-on realtime gates are missing.
- Missing Foreman/libvpx/ffmpeg inputs may be ordinary local skips, but they cannot count as signed-off Stage 4b evidence.

Decision for Phase 2: ask the draft agents to design Stage 4b as a narrow completion of the existing CR implementation plus hard gates. Non-goals stay explicit: no AQ modes 1/2/4, no feature flags, no broad RC rewrite, no TPL/AQ interaction work outside the pinned realtime product gate.

## Phase 2 - Draft

Launched exactly three HLD drafts:

- Draft A, simplest viable: narrow per-frame AQ setup after RC base-q selection, dynamic BOOST1/BOOST2, optional narrow AQ-aware estimate, hard gates.
- Draft B, risk-first: final segment ID must be fixed before final quantization/coefs/recon; one leaf re-sim if segment changes; reject/avoid TPL+CR for this stage; no broad RC rewrite.
- Draft C, testability-first: oracles first; explicit commands; stronger upfront AQ-weighted RC integration.

Launched exactly three judges. All three selected Draft B as the winning spine. Grafts:

- From Draft A: keep the scope narrow, reuse existing helpers, leave `limit_q` and golden cadence out unless gates prove need.

Tie-break: two judges preferred evidence-gating AQ-aware RC; one judge cited `notes/lld/rate-control.md` as assigning CR weighted `bits_per_mb` / `estimate_bits_at_q` to Stage 4b. I resolved this by including only those two LLD-mandated RC estimate hooks, while explicitly ruling out any new RC mode, target/buffer rewrite, or broad RC behavior change.

# Unit 1384 — x86 unchecked lowbd fdct8x8 screen (rejected)

Date: 2026-09-21  
Base: integrated `b69ae126`  
Decision: reject the candidate; keep the source unchanged.

## Candidate

The fresh Crucible profile attributed 709,961 weighted samples to `fdct8x8`
(3.29% of 21,564,981 user-symbol samples). The x86-64 low-bit-depth dispatch
still used the checked SSE2 kernel, which can discard its first pass and redo
both passes in scalar code. This experiment added an unchecked SSE2 lowbd path
matching the AArch64/libvpx schedule: a lowbd first pass, an unchecked i16
second pass with wrapping semantics, and the existing final reduction. The
generic `fdct8x8` path and all non-x86 dispatches remained unchanged.

This candidate was motivated by `RVP9-BUG-CRU-00004`; the bug remains Open
because the measured gain did not clear the retention bar.

## Correctness

- Local AArch64 `cargo fmt --all --check` and focused `cargo test --locked -p rvp9-core --lib transforms::forward -- --nocapture` passed 46/46.
- Cross-compiling the focused x86 target completed successfully.
- Crucible x86-64 release `cargo test --locked --release -p rvp9-core --lib transforms::forward::sse2 -- --nocapture` passed 4/4, including 512 deterministic random residuals, stride jitter, alternating extremes, impulses, and out-of-range i16 wrapping against a scalar oracle.
- Deliberately changing x86 lowbd dispatch back to the checked `fdct8x8` path made `fdct8x8_sse2_lowbd_dispatches_to_unchecked_kernel` fail with `x86 lowbd dispatch must call the unchecked SSE2 kernel`. Restoring the dispatch made the focused suite pass again.

control IVF hashes matched.

# Post-alpha acceptance widening

## Unit W1 — complete official conformance matrix

Current source no longer has the decoder limitation carried by the published
`v0.2.0-alpha.1` tag. The official spatial-SVC vector now passes, so the
reproducible source-tree gate must cover the complete corpus instead of
continuing to exercise only the alpha-supported subset.

The conformance binary now has a fail-closed `--official` mode. It requires
exactly 307 pinned vectors, rejects `--limit` and `--non-gating`, and requires
exactly 4,816 displayed-frame matches. `--threads N` selects the decoder
worker count explicitly. `scripts/qualify-conformance.sh` fetches and SHA-1
verifies the pinned corpus, then runs the complete 2x2 matrix:

- native dispatch, one decoder thread;
- native dispatch, two decoder threads;
- forced-scalar dispatch, one decoder thread;
- forced-scalar dispatch, two decoder threads.

All four release runs passed 307/307 vectors and 4,816/4,816 displayed frames,
with zero mismatches and zero skips. That is 19,264 successful frame checks in
total. The corpus came from pinned libvpx v1.14.1 commit
`12f3a2ac603e8f10742105519e0cd03c3b8f71dd`; the provisioning script verified
every stream and ledger against that revision's manifest.

Focused tests cover malformed-packet failure, explicit diagnostic skipping,
missing shown-frame accounting, and the new official-scope exclusions. The
README distinguishes the published alpha's 306-vector claim from current
source's complete 307-vector result.

Exact next unit: add a fast in-process encoder interaction matrix over
CPU6--8, CBR/VBR, AQ3, denoising, and temporal T2/T3. Use deterministic
motion/noise inputs and require every component to parse and decode under
`rvp9-decoder`, with frame counts, dimensions, temporal IDs, and retained-layer
reconstruction checked. Keep the existing 32-row real-corpus three-decoder
matrix as the slower external gate.

## Unit W2 — routine encoder feature-interaction matrix

A non-ignored integration test now exercises 36 one-pass realtime rows:
CPU6, CPU7, and CPU8 crossed with CBR and VBR, then baseline, AQ3, denoiser,
T2, T3, and combined AQ3+denoiser+T3 configurations. Each row encodes twelve
deterministic moving/noisy 128x64 frames, for 432 encoded and decoded frames
per test invocation.

Every row requires one keyframe plus eleven inter frames; exact 0/1 and
0/2/1/2 temporal-layer patterns; non-empty packets with consistent bit counts;
one shown component per temporal access unit; successful packet parsing and
decoding through `rvp9-decoder`; unchanged 128x64 output geometry; every
configured temporal layer exercised; and twelve decoded outputs. Each row
uses one deterministic decoder worker so the routine test does not create a
host-sized thread pool 36 times. For T2 and T3, separate decoder instances
also drop every packet above each retained temporal operating point and
require the surviving reconstructions to remain byte-identical to the same
frames decoded from the full stream.

The focused test passed in both Cargo profiles. Its steady test body took
0.36 seconds in release and 0.43 seconds in the workspace's optimized debug
profile on this host. This fast matrix complements rather than replaces the
32-row real-corpus gate through pinned `vpxdec` and FFmpeg.

## Unit W6 — exact encoder-side scaled-reference image

Pinned libvpx does not run motion search directly against a lower-resolution
spatial reference. `vp9_scale_references` first creates a current-layer-sized
image with `vp9_scale_and_extend_frame(..., EIGHTTAP, 0)`, then temporarily
substitutes that image in the picker. Final reconstruction still uses the true
lower-resolution reference through normative scaled motion compensation.

The new private `scale_reference` module reproduces that first operation for
the canonical adjacent 2x spatial-layer relationship. It deliberately remains
separate from `scale_source`: source downscaling uses low-pass or bilinear
filtering at phase 8, while reconstructed-reference upscaling uses regular
eight-tap filtering at phase 0. The implementation matches libvpx's separable
two-pass arithmetic, 8-bit rounding between passes, and visible-edge
replication.

The independent golden output came from pinned libvpx v1.14.1 commit
`12f3a2ac603e8f10742105519e0cd03c3b8f71dd`, linked against
`vp9_scale_and_extend_frame_c`. A tightly packed 160x90 I420 input filled
across Y, U, and V by xorshift32 seed `0x51ca1e5e` produced the same packed
320x180 SHA-256 in both implementations:
`f57c311767cb1fcc4d335f4a5f2e47e30cf924c8d1dd067a4be86f0efefaff4c`.

## Unit W7 — spatial references through inter coding

The inter picker and reconstruction simulator now carry one dimensioned view
per named reference. Each view separates the current-sized analysis image from
the original decoder-visible reconstruction. Equal-size references still alias
the same storage. An adjacent lower spatial reference uses the exact W6 upscale
for motion search, while final residual coding reads the lower-resolution slot
through the decoder-matched scaled predictor from W4.

The output-backed luma shortcut is bypassed only when the selected reference is
scaled. This prevents a picker prediction made from the temporary analysis
image from leaking into decoder-visible reconstruction. Zero-motion fallback
leaves likewise retain the exact old copy for equal dimensions and use scaled
MC only for a lower spatial reference.

The full encoder suite caught an identity bug during this wiring. Denoised LAST
and GOLDEN analysis views can have different allocation addresses even while

the reconstruction slots, not the temporary analysis buffers. The denoiser

## Unit W8 — first stateful two-layer spatial inter stream

`SpatialEncoder` now emits a synchronous two-component access unit while its
per-layer `StreamEncoder`s share one decoder-visible reference map, entropy
context, previous-MV grid, and preceding-frame metadata. Rate control,
pre-analysis, cyclic-refresh AQ, thresholds, and scratch stay layer-local.

The emitted fixed no-temporal-layer topology matches pinned libvpx v1.14.1
commit `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`, specifically
`vp9/encoder/vp9_svc_layercontext.c::set_flags_and_fb_idx_for_temporal_mode_noLayering`:
the base refreshes map entry 0; the first enhancement component reads entry 0
and refreshes entry 1; later enhancement components read their own prior frame
from entry 1 plus the newly reconstructed base from entry 0, then refresh
entry 1 again. Spatial components use frame-parallel decoding without the
error-resilient reset, preserving their shared forward-updated probability
state while suppressing backward adaptation.

The central four-access-unit oracle covers key/inter/inter/key transitions,
parses every component header, decodes components in low-to-high order through
one production rvp9 decoder, and compares each decoded I420 plane byte-for-byte
with the encoder's refreshed reference slot. The header oracle failed when the
first enhancement refresh was deliberately changed from `0x02` to `0x04`.
The reconstruction oracle failed when deliberately pointed at the other
spatial slot. Both mutations were restored before the green run.

The stateful path currently requires exactly two layers, inter-layer
prediction, `lag_in_frames == 0`, no ALTREF, no temporal layering, no denoiser,
and a minimum 64-pixel layer height. The height floor avoids the existing
SB64 pre-analysis assumption on inter frames; the keyframe-only wrapper still
supports its prior 32-pixel-high base layer.

## Unit W10 — exact short spatial-layer reconstruction

The stateful encoder again accepts the original 128x64 top / 64x32 base
geometry. Two independent tight-plane assumptions had blocked it.

First, the realtime average-source-SAD pass called a 64x64 dispatched kernel
on a 32-row luma plane. Libvpx's YV12 source has an edge-extended border;
rvp9 now materialises one 64x64 edge block only when a tight plane is shorter
than the requested SB and repeats its final visible row. The new focused test
failed in the AArch64 SAD precondition before this change and now proves the
expected 409,600 SAD for a uniform 100-level difference over the extended SB.

Second, `build_kf_mi_grid_for_lf` used floor division for SB rows. A 64x32
keyframe therefore supplied a fallback mode grid to the encoder loop filter,
while the decoder filtered the actual coded modes. The stream decoded, but the
encoder's base reference first differed at Y pixel 495. The builder now visits
partial SB rows and clips oversized leaf splats to the visible MI grid. The
four-access-unit reconstruction oracle is byte-exact again at both 64x32 and
128x64, including the base reference reused by following inter frames.

## Unit W11 — three-layer spatial reference topology

`SpatialEncoder` now accepts two or three layers. A four-access-unit 256x128 /
128x64 / 64x32 stream proves the base, middle, and top components through
key/inter/inter/key transitions. Every component decodes sequentially through
rvp9, and its encoder reconstruction agrees byte-for-byte with the decoder.

The new test first failed at construction because the production path still
required exactly two layers. After lifting that gate, it exposed a distinct
reference-preparation bug: the top component of the first access unit refreshes
map entry 2 but does not reference its old pixels. That stale slot is still
quarter-sized, so eagerly scaling every named GOLDEN slot rejected an otherwise
legal access unit. The encoder now applies `allow_golden_ref` before scaling;
an unavailable GOLDEN view aliases LAST and cannot enter the picker.

The emitted reference selectors also now match pinned libvpx
`reset_fb_idx_unused`: an unused and unrefreshed selector aliases the first
referenced slot. The no-temporal spatial schedule is therefore `[0,0,0]` for
normal base components, `[i-1,i,i-1]` for key-access-unit enhancement
components, and `[i,i-1,i]` for normal enhancement components. Refresh masks
remain one map bit per spatial layer.

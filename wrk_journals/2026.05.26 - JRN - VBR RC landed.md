# 2026-05-26 — One-pass VBR rate-control landed

## What

Replaced the `RcMode::Vbr` panic arm in
`crates/rvp9-encoder/src/rate_control/state.rs::pick_q_and_bounds`
with a real port of libvpx's one-pass VBR Q-picker. Two-pass remains
deferred (no first-pass stats writer / reader in rvp9).

## libvpx algorithm — what was ported

Direct ports of these libvpx functions
(`third_party/libvpx/vp9/encoder/vp9_ratectrl.c`):

1. **`rc_pick_q_and_bounds_one_pass_vbr`** (`:1138-1303`) → top-level
   dispatch in `vbr::pick_q_and_bounds`.
2. **`calc_active_worst_quality_one_pass_vbr`** (`:905-928`) → VBR's
   ambient-Q-driven active_worst ceiling (vs CBR's buffer-driven one):
   - First-ever KF: `worst_quality`.
   - Subsequent KF: `last_q[KEY] << 1`.
   - First inter (frames_since_key == 1): `last_q[KEY] << 1` fallback
     (avg_inter EWMA still at worst_quality seed).
   - Steady inter: `avg_frame_qindex[INTER] * fac_active_worst_inter / 100`,
     with `fac_active_worst_inter = 150`.
3. **Active-best computation** (`:1167-1185` KF / `:1234-1247` inter):
   - KF: `get_kf_active_quality(avg_frame_qindex[KEY])` — reuses our
     existing `cbr.rs` LUT port.
   - Inter: `inter_minq(min(avg_inter, active_worst))`. New
     `inter_minq` LUT lookup via the existing `get_minq_index` helper
     with the libvpx VBR coefficients `(0.00000271, -0.00113, 0.70)`.
4. **`vp9_calc_iframe_target_size_one_pass_vbr`** (`:2039-2048`) → KF
   target = `avg_bw * kf_ratio (= 25)`. Massively larger than the
   inter target — the VBR rate model spends the keyframe bit budget
   up front and amortises it over the GOP.
5. **`vp9_calc_pframe_target_size_one_pass_vbr`** (`:2019-2037`) →
   inter target = `avg_bw * baseline_gf_interval / (baseline_gf_interval
   + af_ratio - 1)`. With our hard-coded `baseline_gf_interval = 15`
   and `af_ratio = 10`, this is `avg * 15/24 ≈ 0.625 * avg`. The
   slack accumulates to pay for the large KF.
6. **`vp9_rc_clamp_pframe_target_size`** (`:207-232`) → min / max
   frame-target clamping reused from the CBR floor logic.

## Deliberate divergences (documented in the module comment)

- **No GF/ARF path.** libvpx branches the inter path on
  `cpi->refresh_golden_frame || cpi->refresh_alt_ref_frame` and uses
  `get_gf_active_quality`. Our encoder treats every non-keyframe as
  a normal inter (same simplification as CBR).
- **No forced-KF popping prevention.** `this_key_frame_forced`
  + `last_boosted_qindex` need the 2-pass stats reader.
- **No `LIMIT_QRANGE_FOR_ALTREF_AND_KEY`** qdelta widening — dead
  code in our no-GF model.
- **No `q_adj_factor` for ≤CIF.** Default frame is 1280x720, well
  above CIF; the factor stays at 1.0.
- **`baseline_gf_interval` hard-coded to 15.** libvpx's dynamic
  adjuster is part of the GF/ARF path we don't drive; 15 is the
  steady-state value libvpx settles into for our 30 fps default.
- **`af_ratio_onepass_vbr` hard-coded to 10.** Seeded value, only
  changed by the GF reshuffle code path.

## Two-pass status — DEFERRED

Still `unimplemented!()` in `state.rs::pick_q_and_bounds`. Two-pass
requires:
- A first-pass stats writer (mean-row variance, intra-cost, motion
  prediction error). Not present in rvp9 yet.
- A stats file format compatible with libvpx's `FIRSTPASS_STATS`
  (currently only consumed by `rc_pick_q_and_bounds_two_pass`).
- A multi-pass driver in the encoder front-end that runs pass 1
  (analysis-only) then pass 2 (real encode using pass 1 stats).

None of this infrastructure exists. The two-pass arm now reads:

```rust
RcMode::Vbr => vbr::pick_q_and_bounds(self, frame_kind),
// 2-pass still panics — needs first-pass stats writer (REAUDIT).
```

## PROOF — `tests/w_vbr_rc_proof.rs`

5 assertions, all passing:

1. `vbr_completes_30_frames_without_panic` — primary "the panic arm
   is gone" gate. Runs 30 frames through `pick_q_and_bounds` with
   `RcMode::Vbr` and a target-bits-exact postencode update. Before
   this wave, frame 1 (first inter) panicked.
2. `vbr_q_respects_active_best_and_active_worst_bounds_every_frame`
   — for every emitted frame, `active_best <= q <= active_worst`,
   and both bounds lie in `[best_quality, worst_quality]`. This is
   the libvpx contract at `vp9_ratectrl.c:1287-1295` + 1252-1255.
3. `vbr_kf_q_differs_from_steady_state_inter_q` — KF and steady-
   state inter pick structurally different Q (KF target = 25× avg;
   inter target = 0.625× avg).
4. `vbr_targets_diverge_from_cbr_on_first_frame` — CBR and VBR pick
   different per-frame KF targets at the same starting state,
   proving the dispatcher actually routes VBR through VBR.
5. `vbr_q_stays_in_reasonable_range` — over the 30-frame run, at
   least one frame's Q lands in the working middle band `[20, 230]`
   (regulator is engaging, not just clamping at the edges).

Plus 9 unit tests in `rate_control::vbr::tests` covering each helper
in isolation.

## Cross-decoder gate

`cargo test -p rvp9-encoder --test cross_decoder_gate -- --ignored` →
**4/4 passing, byte-exact**. The VBR work is RC-mode-gated; the
default `EncoderConfig` produces a `RateControlConfig` with
`rc_mode: RcMode::Cbr`, so the CBR encode path runs unmodified and
the bitstream stays byte-identical to libvpx-decoded output.

# Unit 1422 — integrated x86 parity recheck

Built the newly integrated Unit 1421 encoder on Crucible and compared it
directly with the unchanged pinned libvpx binary. The first 14-pair-per-clip
screen was heavily distorted by RVP9 wall-time stalls; a subsequent CPU
sample found near-saturation and high Defender activity. The warmed repeat
under lower observed load gave 1.400× paired RVP9/libvpx across Ducks,
In-to-tree, and Old-town-cross. This is above the 1.05× target; the shift
from Unit 1415's 1.231× is not a measured code regression because host
conditions and reference times also changed. Raw pairs, exact commands,
hashes, and caveats are in
`wrk_docs/evidence/2026-09-25-unit1422-integrated-libvpx/`.

An exact-profile audit found no attractive non-architectural next edit.
TX4 batching remains the plausible larger target, but its draft HLD at
`wrk_docs/2026.09.25 - HLD - TX4 batching diagnostic.md` explicitly calls
for Arthur's discussion before changing per-tile entropy ordering. The
bounded prototype would need exhaustive differential cases, a deliberate
red, byte-identical three-clip output, and two stable paired screens.

## Phase 4 Review Round 1 - verified findings and fixes

Three read-only review agents inspected the implementation against the signed-off HLD. Findings with 2-of-3 or better agreement:

- Candidate pairing could accept an invalid strict baseline.
- Block-stat artifacts were only path-recorded, not parsed or compared against strict/candidate sanity thresholds.
- Diff artifacts accepted non-empty stdout without requiring a successful `diff-bitstream` exit.
- The Stage 4a product runner allowed `testsrc_720p30.y4m`, which belongs only to the legacy realtime gate, not the Foreman product runner.
- The approved libvpx tool manifest is empty.

Additional accepted findings from direct inspection:

- ffmpeg PSNR fallback needed to reject decoded-size mismatch before PSNR.
- `RVP9_*` environment rejection needed ASCII-case-insensitive matching on Windows.
- `Slack1Over8` selector used `speed.unsigned_abs() >= 7`; the HLD says `speed >= 7`.

Fixes applied:

- Candidate pairing now requires the strict baseline report to be `PASS`, validation-clean, `split_override == ForceStrict`, hashable, and matching source/config/tool fingerprints.
- Cross-decoder and realtime product tests assert the baseline report as well as the candidate.
- Product block stats are now wrapped in a product JSON artifact with HLD provenance fields and parsed into the report. Candidate pairing compares `8x8 + 8x16 + 16x8` and `16x16` area movement against the strict baseline thresholds.
- Diff artifacts now require a successful `diff-bitstream` exit and valid newline-delimited JSON with a summary event.
- Product ignored-input allowlist is now Foreman-only.
- ffmpeg size mismatch now fails before PSNR fallback.
- `RVP9_*` env rejection is case-insensitive.
- Encoder policy gate now uses literal `speed >= 7` and has a negative-speed regression assertion.

Parked blocker: the approved libvpx tool manifest cannot be populated on this host. No `vpxenc`, `vpxdec`, or `ffmpeg` binaries exist under `D:\language` or `D:\worktrees`; `third_party/libvpx` is uninitialized; and this host lacks `make`/MSYS2, so `scripts/build-libvpx.sh` cannot build pinned tools here. The manifest remains a hard-fail mechanism until approved binary hashes are available.

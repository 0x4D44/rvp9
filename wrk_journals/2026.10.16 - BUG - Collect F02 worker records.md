# Collect F.0.2 worker records — FLUX-00016

The F.0.2 harness drains the encoder caller's thread-local decision buffer. Inter-tile and compact row workers emitted decisions and partition traces into their own thread-local buffers, so those records never reached the harness. Their frame/spatial labels also remained worker-local defaults. FLUX-00024's earlier diagnostic environment inheritance does not transport these record buffers or labels; its fix is separate.

The bounded repair carries an owned F.0.2 batch with each completed worker result and merges it on the caller in existing deterministic order. Captured context includes frame and spatial labels. A scoped swap of both buffers/tags is required because the worker pool can execute the first submitted job on the caller thread, where a partition backlog may already exist. Restoration must also hold for nested capture and panic; partial failed-job records are not merged. Disabled capture must avoid allocation. Existing diagnostic keyframe serialization and the public drain API remain unchanged.

Scope includes the tile result in `frame_loop.rs`, compact row result in `lib.rs`, and internal capture helpers in `f02_oracle.rs`, with focused regressions. No new dependency or global shared collector is intended. The large old-town recording from the original report is not a prerequisite for a smaller real-encoder regression covering both worker paths.

The internal `CaptureContext::run` keeps its restoration guard private inside the callback boundary. `RecordBatch` owns decisions and partition traces; parent buffers are never moved into a sendable context. Both worker result types carry the completed batch. The disabled path calls the job directly and returns zero-capacity vectors without touching the record TLS.

Full-record comparison found one additional missing compact-worker initialization: core candidate-probe tracing was reset on the parent before compact jobs were dispatched. Workers then emitted decisions with unavailable probes. The compact job now calls the same existing `candidate_trace::reset(f02_oracle_enabled)` before picking. Candidate handles are created and consumed within that job. Core APIs/source and codec policy are unchanged.

## Observed regression evidence

The Sol 6.1 medium worker ran both real-encoder regressions against original production code before implementing capture:

- `f02_tile_workers_preserve_complete_frame_records` failed on worker frame-one coverage after serial coverage passed.
- `f02_compact_workers_preserve_complete_frame_records` failed on the same missing worker coverage boundary.

The regressions encode three 512×128 frames with two tiles, one versus two threads, spatial label two, and forced low-resolution ML tracing. They compare complete sorted decisions, partition traces and packet bytes. Each frame must have exact pixel coverage without overlaps, correct frame/spatial labels, nonempty inter-frame partition traces and empty second drains. These are encoder-generated records, not fabricated sink counts.

The worker observed semantic assertion failures for the new helper tests before trusting them:

- Omit TLS isolation: nested/panicking capture and caller/persistent-worker tests fail their sink-isolation assertions.
- Inject disabled-path allocation: the disabled test fails its zero-capacity batch assertion.
- Remove the disabled early return after strengthening the test: inside-job labels become `(0, 0)` instead of `(42, 2)`, and the assertion fails. Inside-job sentinel lengths in both raw TLS buffers are also checked.

All faults were restored before final validation. The partial capture implementation recovered coverage and packet equality, but the compact complete-record comparison caught missing candidate probes; adding the existing per-job tracing initialization made full equality pass. No encoder decision was changed to satisfy the oracle.

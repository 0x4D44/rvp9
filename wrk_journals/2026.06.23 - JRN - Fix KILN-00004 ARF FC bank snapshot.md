# 2026-06-23 - JRN - Fix KILN-00004 ARF FC bank snapshot

## Pick

Selected `RVP9-BUG-KILN-00004` from the Open ledger queue. It was the highest-severity unattended-fixable item left in the queue: High severity, scoped to `encode_altref_internal`, and already had a clear contrast against the show-frame FC mirror path.

## Diagnosis

The show-frame inter path snapshots `decoder_fc_state` before compressed-header coding mutates it, then backward-adapts from that pre-header bank. The ARF path cloned `decoder_fc_state_arf` into `decoder_fc`, passed it mutably to `build_inter_packet_with_residuals`, and then adapted bank 1 from the mutated value.

That explains the full symptom: the decoder adapts frame context bank 1 from the bank saved before reading the ARF header, while the encoder mirror adapted from a post-header bank. Bank 0 stayed correct because the show-frame path already used a pre-header snapshot.

Adversarial review: the proposed root cause accounts for the ARF-only failure, the absence of a bank-0 failure, and the location of the mutation. The minimal fix is to snapshot the ARF bank before packet assembly and use that snapshot as the base for mode, coefficient, and MV adaptation.

## Regression Proof

Added `arf_decoder_fc_bank_one_stays_synced_after_non_show_frame`, which drives delayed encoding until a non-show ARF using frame context bank 1 is emitted, decodes each frame, and compares `StreamEncoder`'s ARF bank mirror with `Decoder::frame_context(1)` immediately after decode.

## Fix

`encode_altref_internal` now clones `pre_header_decoder_fc_arf` immediately after loading `decoder_fc_state_arf`. The packet builder still mutates `decoder_fc` for compressed-header coding, but the post-encode adaptation calls use the saved pre-header snapshot, matching `encode_inter_internal` and the decoder's frame-context lifecycle.

Version bumped from `0.1.10` to `0.1.11` because this changes shipped encoder behavior.

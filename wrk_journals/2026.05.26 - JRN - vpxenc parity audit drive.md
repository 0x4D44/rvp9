### L1 — A2 pilot failure modes (2026-05-26)

A2 returned thin and scope-confused. Three failure modes to harden against:

**L1a. Scope drift.** Despite the prompt saying "Profile 0/1/2/3 all in scope; CBR + VBR + 2-pass all in scope; cpu-used 0..=8 all in scope", the agent classified the following IN-SCOPE items as out-of-scope:
- Recode loop ("not needed in RT")
- Dynamic resize (`vp9_change_config`)
- Lookahead pipeline ("not needed for single-pass")
- External RC API

**Mitigation:** new prompts must (a) include the goal doc by reference and require the agent to read it FIRST, (b) explicitly forbid any "MVP scope" or "RT-only" framing, (c) require an explicit per-out-of-scope row justification citing libvpx absence.

**L1b. Thin format.** A2 produced 20 rows; picker inventory had 45 for a similar-size subsystem. No libvpx file:line citations on rows. No section narratives. No PARTIAL detail table.

**Mitigation:** prompts must (a) require the picker inventory format LITERALLY, including section-by-section narrative + PARTIAL detail table + cross-cutting gaps + porter's checklist, (b) require `file:line` on EVERY row, (c) include a row-count sanity check ("if your row count is materially lower than the picker's 45 for a comparable-size subsystem, re-audit").

**L1c. Out-of-bounds conclusions.** Agent wrote "Quality parity with libvpx on single-pass CBR is achieved" — audits cannot make parity claims; that's a Phase 4 measurement.

**Mitigation:** prompts must (a) forbid parity / "complete" / "achieved" language in the conclusion, (b) restrict the conclusion section to gap counts + dependencies + recommended sequencing.

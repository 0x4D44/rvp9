# Exact-candidate Miri cfg correlation

Audited the current `fb5c0c917038db6c640b3dbc7c2b84b567233333` transform
source after the decoder `panic_safety` Miri target failed to compile. The six
missing scalar helper definitions use
`cfg(any(not(target_arch = "aarch64"), test))`, while their dispatcher call
blocks use `cfg(any(not(target_arch = "aarch64"), miri))`. Thus the AArch64
dependent-library Miri build includes calls and omits definitions. This
matches the source condition already described by FLU-00037; it is not runtime
safety evidence or a new defect claim.

Recorded the source blob IDs and function line locations in the Miri
qualification JSON and linked that audit from the readiness report. The
ordinary release `panic_safety` target passed 4/4; the Miri run started none of
those tests.

Validation: parsed the qualification JSON, checked both recorded Git blob IDs
against the exact-candidate worktree, and ran `git diff --check`.

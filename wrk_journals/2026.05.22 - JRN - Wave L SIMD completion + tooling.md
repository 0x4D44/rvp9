## L4 outcome (`0a258de`)

256-bit fast path for `convolve8_vert` — 32 columns/group (vs 128-bit's
16) for the 32-/64-wide blocks and pass 2 of the 2-D convolve. Key: the
`unpacklo/unpackhi` lane split aligns with `packus_epi16`'s lane structure,
so the wider reduction reassembles natural column order with NO permute
fixup — same maddubs math, twice as wide. ≤16 remainder keeps the 128-bit
path. Bit-exact (differential 32x*/64x*; conformance 201; clippy 68).
**dsp-microbench: vert 64×64 +28% (777→557 ns), 2-D 32×32 +19%, 2-D 64×64
+15%.** The 2-D's u8 intermediate double-clip is spec-mandated (can't keep
i16), so the single-axis kernels are the only bit-exact lever. avg_vert /
256-bit horiz could get the same treatment as future polish — primary
broadest-impact win (vert) delivered; rest is diminishing returns.

## L5 outcome (`36010e6`)

Replaced D117/D153 `copy_within` diagonal recurrence + strided col-byte
writes with a vectorized shift-and-insert pass (folds both into one loop).
D153 = shift-by-2; D117 = shift-by-1 with r-2 dependency → two interleaved
running vectors. 128-bit `slli_si128` for bs≤16; full-width 256-bit
`alignr(v, permute2x128(v,v,0x08), 14|15)` for bs=32. No dst read-back,
bounded `store_row`. Bit-exact (29 directional tests green; conformance
201; clippy 68). **dsp-microbench: D117 ~1.9–2×, D153 ~1.5–2.9×.** Hypothesis
(copy_within already optimal) was WRONG — the real cost was the per-row
strided single-byte col writes, which the fused vector pass eliminates.

## Honest framing

- L1 is the substantive win but **harder than Waves F–K**: the scaled convolve
  selects a *different* filter row and integer base **per output column**
  (`x_q4 & SUBPEL_MASK`, `x_q4 >> SUBPEL_BITS` advancing by `x_step_q4`). That
  is a gather, not a fixed-tap FIR, so the AVX2 win is bounded. Still: bit-exact
  promotion + dispatch completion has value, and the horizontal-pass round/clip
  + the `_avg` round-average are vectorizable even when the tap fetch is serial.
- L4/L5 are perf-only on *already-fast* code; without L3's bench they'd be
  "predict the future" tuning. L3 gates them.
- L6 may be genuinely unfinishable here (no encoder corpus). Resolution =
  documented closure if so.

Our decoder is bit-exact on the official 201-frame corpus but **mismatches a
default-`vpxenc` foreman encode (1/10 frames pass; keyframe passes, inter
frames diverge)**. Cannot be a Wave L regression — every Wave L kernel is
proven bit-exact vs scalar, and the official corpus (which exercises the

encoder features outside the official starter set. Recommended as a
dedicated decoder-conformance follow-up (bisect which vpxenc feature
diverges: interp filter / segmentation / compound / loopfilter level).

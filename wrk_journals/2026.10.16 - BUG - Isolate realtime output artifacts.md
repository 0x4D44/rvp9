# Isolate realtime output artifacts — KIL-00111

Every default realtime invocation passed the same system-temporary IVF path to its encoder and later counted that path. Concurrent invocations could overwrite or count each other's data; a successful child that wrote nothing could leave a stale artifact looking like fresh work.

Each default output now resolves inside an atomically created, owned temporary directory. Explicit output paths must be fresh and are reserved with `create_new`, without altering existing files or symlinks; the reservation handle closes before launching the encoder. Explicitly requested new files remain available after the run. Argument parsing stays free of output-file creation. Main returns the existing exit codes so the temporary guard drops on ordinary success and error returns. Timing calculations and child-runner behavior remain unchanged. Help explains temporary defaults and the freshness requirement for explicit paths.

Observed assertion-red reversals, all restored manually:

- Returning the legacy shared default path made the concurrent CLI test fail path inequality: both paths were `.../tmp/rvp9_realtime_bench.ivf`. The stale-artifact CLI test returned 0 instead of the expected zero-frame exit 2. Portable output-guard tests also caught lost uniqueness.
- Replacing exclusive creation with create-and-truncate made both existing-file and symlink CLI tests return 0 instead of rejection exit 1. The portable guard test also detected acceptance of an existing file.
- Disabling owned-directory Drop made success and timing-failure cleanup assertions fail.
- Reserving an explicit artifact during parsing failed the parser-purity assertion.
- Erroneously deleting an explicit file in Drop failed the standalone integration assertion `explicit output was removed after success` and the portable unit's `fresh_path.is_file()` assertion.

All 14 realtime unit tests and six CLI integration tests passed after restoration. The lead independently reran all 20. Concurrent default runs used distinct paths and counted their own two- and five-frame fixtures; existing stale data remained unchanged; a child that wrote nothing failed with exit 2; existing explicit files and symlinks were preserved before child startup; fresh explicit output remained available; default directories were removed after success, encoder failure and timing-CSV failure. The existing bounded-child unit check remained green. CLI children use the existing file-backed process runner with ten-second deadlines; concurrency uses scoped threads. An initial harness attempt did not capture subprocess stdout, making `reported_frames` return `None`; that harness issue was corrected before behavioral fault proofs. Small synthetic IVF containers were checked up front for expected packet counts; their payloads are counting fixtures, not decoded codec vectors.

Scoped realtime and integration-test Clippy passed with warnings denied, as did workspace formatting and diff checks. Subprocess roots were isolated under task-local `.scratch`; root test calls set absolute `TMPDIR`. Script and symlink coverage ran natively on macOS under Unix guards. No real encode, Windows runtime, prolonged benchmark or throughput result is claimed. The preselected final smoke after catch-up is `cargo test -p rvp9-bench --test realtime_output`, bounded to 60 seconds.

# Reject unrepresentable loop-filter and quantization fields — CRU-00005

The queue selected CRU-00005. The public loop-filter and quantization writers accept wider Rust field types than their wire representations and silently emit only the low bits. The existing tile-info range fix addresses a separate writer.

The bounded repair validates each complete sub-block before mutating its bit writer. Loop-filter level and sharpness must fit six and three bits; emitted reference/mode signed deltas must have six-bit magnitudes. Inactive delta fields retain their ignored semantics. All three quantization deltas must fit four-bit magnitudes before even the base quantizer is written. The private quantization-delta emitter remains behind that public preflight. The existing non-exhaustive bitstream error enum receives a documented field/range error with contextual display text.

Atomicity is at each named sub-writer call boundary, including a writer that already contains a prefix. This does not add rollback for an entire uncompressed header. Valid wire encodings, parser behavior, and low-level truncating raw-writer APIs remain compatibility constraints.

- Old quantization writer: invalid delta rejection failed at the same expected-error assertion.

- Deliberately validating inactive deltas unconditionally: the new ignored-field control failed because `i8::MIN` was rejected despite its field not being emitted.

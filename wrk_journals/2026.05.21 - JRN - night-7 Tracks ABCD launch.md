### Final definitive diagnosis (multiple-agent convergence)

The foreman 16 dB floor is **the `bits_per_mb` rate model under-predicting per-MB cost by ~10×**:
1. Encoder thinks it fits target bitrate when it actually produces 10× more bits
2. RC raises qindex to limit overshoot → eventually pins at 255
3. At q=255 residuals quant to zero → reconstruction = stale LASTFRAME
4. PSNR locks at LASTFRAME-staleness (~16 dB for moving content)

**Picker changes can't fix this** (verified by A2, A6, A7, A8): even with correct picks, RC clamps to q=255 because the rate model says we're overshooting.
**RC q-cap can't fix this** (verified by A5, A9): lowering qindex floor produces more bits without breaking the underlying rate-model misprediction.

Closing requires **content-aware `bits_per_mb` estimator** (Stage 4c-level work, libvpx ports its from `vp9_rd.c::vp9_rd_init` with empirical tuning). ## Post-loop-reopen breakthrough — A11 reference divergence

The Stop hook held the loop open after A9's "definitive" close-out. Three further experiments:

- **A10.bpm-hack** (`0502f0e`): tested whether bits_per_mb's ~10× under-prediction (A9's claim) was the bottleneck. Measured actual/predicted ratio = **1.05** (not 10×) — RC.1's correction_factor closes the loop within 5 frames. Multiplier swing of 100× moved PSNR by < 0.3 dB. **Hypothesis disproven, but the agent's NEXT-angle hypothesis was the key**:

  > "Encoder-side reference-buffer divergence: encoder's LASTFRAME may store predicted-only (dropping residual) while decoder stores predicted+residual. Cross-decoder byte-exact on BITSTREAM doesn't imply encoder LASTFRAME == decoder LASTFRAME."

- **A11.refdiverge** (`db11f63`): **HYPOTHESIS CONFIRMED — and fixed in one bit.**

  Step 1 measurement: `SSE(encoder_lastframe, decoder_lastframe)` per frame on foreman: `6.2M → 6.2M → 11.9M → ... → 72.0M by frame 11` (12× growth). On testsrc: `0 → 0 → 728K → 2.5M → 5.1M → ... → 8.7M`. **Buffers diverge linearly per frame** — confirms the hypothesis exactly.

  Root cause: encoder emitted `refresh_frame_flags = 0x00` on every inter frame in the uncompressed header. Decoder NEVER updated LASTFRAME. Every inter frame was decoded against the keyframe instead of the previous reconstructed frame. Encoder's internal `last_recon` was correct, but the decoder used a stale (keyframe) reference, causing motion compensation against the wrong baseline. Residuals fixed the wrong MC base → accumulating drift → 16 dB PSNR floor.

  **Fix**: `crates/rvp9-encoder/src/frame_loop.rs:1370` — `refresh_frame_flags: 0x00 → 0x01`. ONE BIT.

  **Result on foreman_cif F12 PSNR sweep**:

### Why this slipped past 10 prior experiments

Every prior experiment (A0-A10) measured downstream symptoms (picker mode distribution, qindex, lambda, residual quant, partition shape, rate-model under-prediction). None measured the upstream invariant: "does the encoder's LASTFRAME match what the decoder would reconstruct from the bitstream the encoder just emitted?" The bitstream produced by the encoder was syntactically correct (vpxdec accepted it byte-exact), so all downstream tests looked sane. But the encoder was making prediction decisions against a reference that diverged from the decoder's reference, so every prediction looked good locally but compounded into drift globally.

The cross-decoder gate was load-bearing for SYNTAX correctness. The new `diag_ref_divergence` test is load-bearing for SEMANTIC correctness.

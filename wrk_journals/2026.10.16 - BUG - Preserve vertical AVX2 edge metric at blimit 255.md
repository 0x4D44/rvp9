# Preserve vertical AVX2 edge metric at blimit 255 — FLU-00034

The queue selected FLU-00034. The vertical-16 AVX2 mask saturates `2*abs(p0-q0) + abs(p1-q1)/2` to an unsigned byte before comparing with `blimit`. Saturation preserves that comparison below 255, but incorrectly accepts larger metrics when the threshold itself is 255. This is the vertical counterpart of the already-landed FLU-00035 horizontal fix.

The bounded correction preserves the byte comparison below 255. At 255 it widens both differences to 16 bits, computes the exact metric (maximum 637), compares against the threshold, and packs the canonical comparison masks before the existing limit-mask combination. It changes no tap loading, filter arithmetic, dispatch, or public interface.

The new full-filter regression mixes eight rows with exact metrics 254, 255, 256, 607, 225, 255, 637, and 256. It includes the recorded `p0=246, q0=3` case, checks scalar acceptance, and compares the entire scalar/AVX2 output at pitches 16 and 29 with prefix, row-padding, and suffix guards.

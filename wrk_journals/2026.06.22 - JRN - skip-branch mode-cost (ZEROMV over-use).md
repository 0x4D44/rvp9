## Diagnosis (parallel workflow: 4 readers + synthesis)

Attacked the dominant, most concrete measured divergence from the
2026-06-21 VBR product-gate analysis: **ZEROMV over-use — rvp9 ~26% vs libvpx
~4% area, consistent across 25/50/100/250 kbps** (with NEARESTMV
correspondingly lower; NEWMV under-use is a secondary divergence that grows
with rate). Four parallel agents (rvp9 picker trace, libvpx `vp9_pickmode.c`,
NEAREST predictor grid, NEWMV under-selection) **converged** on one
high-confidence smoking gun:

**rvp9's RT-picker skip tie-break DROPS the per-mode rate on the skip branch.**
- libvpx (`vp9_pickmode.c:2352-2399`): on a skippable leaf it overwrites
  ONLY the coefficient rate (`this_rdc.rate = vp9_cost_bit(skip_prob,1)`,
  2353/2359/2374) and then **unconditionally** re-adds `rate_mv` (2394) +
  `inter_mode_cost[ctx][mode]` (2395) + `ref_frame_cost` (2398) before
  `RDCOST` (2399). So the per-mode cost differential — ZEROMV ~7.0 bits
  (3584 units, ctx0) vs NEARESTMV ~0.35 bit (181 units) — always survives
  into the RD ranking and disfavours ZEROMV.
- rvp9 (`inter.rs:3197-3206`): on `take_skip` it sets `final_rate =
  skip_true_cost` ONLY, discarding `mode_rate`/`mv_rate`/`ref_frame_rate_cost`
  AND `coef_rate`. Static blocks take the skip branch (~69% skip=1), so the
  ZEROMV-vs-NEARESTMV comparison loses the mode-cost handicap and ranks ONLY
  by pred-SSE — the (0,0) predictor of a static block is lowest, ZEROMV-first
  (`RT_INTER_MODES`, inter.rs:1311) + strict-`<` cements it. This is
  rate-independent (skip dominates static blocks at every operating point),
  matching the measured constant ~21% NEAREST→ZERO flip.

(Secondary, composing: rvp9 builds picker NEAREST/NEAR from the FULL decoder
`dec_find_mv_refs` while libvpx's RT picker uses the truncated `mv_refs_rt`,
leaving NEAREST==(0,0) more often. Tertiary: NEWMV affordability collapse from
the wrong full-pel search family + hardcoded `sad_per_bit=16`.)

## Conclusion — REFUTED, reverted

The skip-branch mode-cost restoration is a **faithful libvpx-parity detail**
(the divergence is real and three-agent-corroborated) but is **RD-NEGATIVE for
rvp9 in isolation**. Mechanism (now precise, fixed-Q-confirmed so NOT a
rate-control artifact):

1. rvp9's NEAREST predictor is **non-zero** on the affected static blocks
   (full-scan `dec_find_mv_refs`, same as libvpx's actual NEAREST), so
   penalizing ZEROMV's mode cost does NOT cleanly relabel ZEROMV→NEARESTMV at
   equal prediction — it forces the block onto a **worse-predicting**
   NEARESTMV (skip, no residual to repair it) or onto a worse non-skip mode.
2. libvpx accepts that tradeoff (cheaper mode label for slightly worse
   prediction) because *its* overall calibration — lambda, reference quality,
   NEWMV affordability — makes the saved mode-bits pay back. rvp9's weaker
   prediction/RC calibration does not, so at matched Q the saved bits are
   worth less than the lost prediction quality.

This is exactly the coupling the 2026-06-21 CR doc predicted ("every isolated
perturbation of the picker RD-domain has regressed"). It RETIRES the sharpest
remaining isolated lever and **confirms the central thesis with a concrete,
RC-independent measurement**: the ZEROMV/NEAREST/skip/NEWMV divergences are one
co-calibrated system (lambda ↔ coef-dist ↔ skip tie-break ↔ mode costs ↔
NEAREST derivation ↔ partition granularity ↔ NEWMV affordability); restoring any
single libvpx term in isolation breaks rvp9's internal balance.

Per the goal keep/discard rule, the source change is **reverted** (worktree
back to clean `681cb29`; `git diff` empty). The full diff is recorded above:
`skip_modecost_enabled()` + the skip-arm `final_rate` restoration. Cross-decoder
NOT run for the variant (reverted tree == known-clean baseline; the change was a
pure RD-ranking perturbation that picks a valid mode either way, so decodability
was never at risk — the regression is RD, not validity).

## Second lever (same session): MV-search cost `sad_per_bit`/`error_per_bit` — INERT

To test a *different* mechanism (motion-search prediction quality, not mode
relabeling), probed the NEWMV-affordability lever (NEWMV agent's #1): rvp9 pins
`sad_per_bit = error_per_bit = 16` (`inter.rs:388/395`, L-43) for all q, while

MV-search cost model is NOT a live RD lever for this gate. Probe reverted
(worktree clean).

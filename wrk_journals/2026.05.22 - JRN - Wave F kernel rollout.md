## Operating principles (autonomous mode)

- **Worktree isolation per gap** — every implementer in a fresh
  `EnterWorktree`; squash-merge onto main only after pre-merge
  validation green.
- **Conformance is the gate** — every merge must preserve
  201/0/0/0/201. Revert if it doesn't.
- **G4-γ pattern is the template** — `srai(slli(_, 16), 16)` for
  exact `wraplow` (NOT `_mm256_packs_epi32` which saturates).
  Hand-derived i32 lanes from the scalar reference; do NOT port
  libvpx SSE2 patterns blindly.
- **Tautology guard mandatory** — every new AVX2 kernel test
  must `assert_ne!(dispatch.fn_ptr(), scalar_fn_ptr)` to prove the
  AVX2 path actually runs.
- **Stay in lane** — encoder team touches `transforms/forward.rs`,
  `rate_control/*`, `encoder/src/*`. If I see build errors in
  those files, I retry — never fix.
- **Skip-and-document for blocked items** — if a derivation
  proves intractable (e.g., F8 idct32x32 full-1D might be too big
  for one round), file Wave G follow-up in this journal and move
  on.
- **Sub-1-hour dispatch budget per agent** — keeps context lean.

## Sub-sequencing rationale

Order: small → medium → large, with dependencies respected.

- **F1 first** — smallest kernel, fastest validation, proves
  G4-γ pattern transfers off idct8x8.
- **F2 before F3/F4/F5** — the 16×16 full-1D machinery (i32-lane
  butterflies + transpose-16) becomes a building block for the
  three EOB/iht slots that follow.
- **F8 second-to-last** — biggest derivation, risky. Failure
  fallback: ship F1-F7 and document F8 for Wave G.
- **F10-F12 deferrable** — independent surfaces, can be picked up
  if F1-F9 complete with time remaining.

### F11 + F12 closure rationale

Both turned out to be already-analysed problems whose verdicts were
captured verbatim in `dispatch.rs` slot docstrings:

- **F11**: `extend_frame_borders` is `slice::fill` + `slice::copy_within`,
  both of which lower to platform `memset` / `memmove`, both already
  vector-dispatched at runtime. Border extension is < 2 μs per 1080p
  frame. **No SIMD work justified.** Notes filed at
  `notes/wave-f-f11-audit.md` for future Wave G if profile data
  changes the calculus.

- **F12**: `plane_dequant_pair` slot exists only as a reserved
  family-name. The actual dequant arithmetic is FUSED INTO the
  bool-coder loop in `entropy/detokenize.rs:415,425,432,435,444`.
  Separating dequant requires a 3-5 day entropy-decoder rewrite
  touching ~10 files. **Wave G architectural refactor.** Notes filed
  at `notes/wave-g-f12-blocker.md` with two-option recommendation
  (split-loop fix vs retire-the-slot).

Skipping the agent-dispatch overhead for both saved ~30 min of
wall-clock time vs spawning two more implementer rounds — supervisor
direct inspection of the dispatch.rs docstrings + source files +
notes write was much faster.

### F10 worktree-base drift story

F10 was dispatched in background while I worked on F11/F12 notes.
When it returned, the worktree had branched from `0b5aa92` (the Wave
F base commit) — BEFORE F1-F9 landed on main. A naive squash-merge
would have reverted F1-F9. Three resolution paths:

1. ❌ `git merge --squash worktree-agent-a40a8fa461f8d3390` — would
   add F10's lpf file AND revert F1-F9.
2. ❌ `git cherry-pick e92b3c7` — contaminated my supervisor shell
   by implicitly switching the main worktree's branch HEAD to the
   worktree branch. Had to `cd` recover.
3. ✅ Manual port: `cp` the new file + 7 targeted `Edit`s to apply
   dispatch.rs and mod.rs deltas verbatim.

The worktree-base drift was caused by my F10 dispatch happening
while encoder team commits were also landing on main — the
worktree-creation hook branched from main's then-tip but main moved
forward before the merge.

**Wave G lesson**: when dispatching agents to long-running
background work, prefer to do the dispatch IMMEDIATELY before
synchronizing main, so the worktree-base is fresh. Or pin a
specific commit explicitly in the dispatch.

### Lessons captured (Wave F)

1. **Template-driven kernels land first-try**. F1, F7, F6, F2, F8
   all derived cleanly from the G4-γ idct8x8 template. The biggest
   risk-reduction in Wave F was Wave E's commit `e14f4dc`
   establishing the pattern — every subsequent kernel was an
   extension exercise.
2. **The transpose decomposition insight scales**. 16x16 = 4× 8x8
   transposes + cross-block swaps; 32x32 = 16× 8x8 transposes +
   cross-block swaps. The "scary big-N transpose" never materialised
   because the implementers correctly applied the decomposition.
3. **Strategic reorder by risk pays off**. Original catalog ordered
   F2/F8 before EOB ports; reordering to small-template-extensions
   first → finisher-only ports → big refactors meant the wave
   shipped 6 deliverables before the first risky one (F2). If F2 or
   F8 had failed, Wave F would still have shipped 6+ deliverables.
4. **F11+F12 supervisor-direct closure was efficient**. Both turned
   out to be already-analysed (verdicts captured in dispatch.rs slot
   docstrings). Spawning agents would have wasted ~30 min wall-clock
   for what amounted to "confirm the doc is still accurate and file
   a notes/ entry". Reading the source FIRST before deciding to
   dispatch saved agent rounds.
5. **Hand-resolved merges scale**. ~30 conflict regions across Wave
   F (3 hand-resolved squashes + the F10 manual port). All
   additive. Median resolution time was < 5 minutes per gap.
6. **F10 worktree-base drift** (see above) — Wave G should pin the
   dispatch commit explicitly when launching background agents.
7. **Background agent dispatch saves wall-clock**. F10 ran in
   background while I closed F11+F12 in parallel — saved 15-20 min.
8. **`cd` into a worktree from cherry-pick contaminates the
   supervisor's branch HEAD**. Wave E lesson #2 confirmed. Always
   use `git -C` for branch-modifying operations.

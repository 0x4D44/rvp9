# Unit 1387 — final-leaf quantizer setup table rejected

## Decision

Reject and do not retain the code change. The final supported-leaf picker
repeatedly rebuilt the effective segment qindex, plane quantizers, UV dequant
pair, and inter RD multiplier. A frame-level eight-entry table removed those
recomputations, but the exact Crucible screen made the encoder slower on every
clip. The task branch is restored to docs-only evidence so the negative result
is auditable without changing shipped behavior.

## Why this candidate

The fresh Crucible x86-64 profile at integrated source `a94c8ce8` attributes
10.604% of 19,597,341 weighted RVP9 user samples to
`rvp9_core::dsp::x86_64::quantize_fp_avx2::vp9_quantize_fp_avx2_inner`.
Earlier arithmetic and packing changes in this kernel regressed, so this unit
tested a narrower setup-only reuse. It cached immutable per-segment values once
per frame and changed only the final supported-leaf loop; A4 descent setup and
calibration remained unchanged.

## Correctness evidence

- `cargo fmt --all -- --check` and `git diff --check` passed.
- The focused table-oracle test passed locally and on Crucible:
  `final_leaf_quantizer_entries_match_direct_segment_setup`.
- The full local encoder library passed: 780 tests passed and one was ignored.
- The x86-64 cross-compile (`x86_64-apple-darwin`) passed.
- Deliberate red run: changing the table builder to select
  `segment_id.saturating_sub(1)` failed the focused test at segment 1 with a
  qindex mismatch. Restoring the selector returned it to green.
- All three candidate/control streams were hash-exact across the 30 measured
  samples per clip, so the regression is speed-only rather than quality drift.

## Crucible screen

The relaxed Crucible screen used CPU-used 6, CBR 1260 kbps, 30 fps, one
thread, zero tile columns, AQ 0, 60 frames, KF interval 60, one warmup, 15
alternating pairs, two reversed clip-order rotations, and no `--max-load1`
cap. Ratios are candidate/control; lower is faster.

| ducks | 1.016219× | 1.017060× | 18.2391 | 17.9480 |

| three-clip corpus geomean | 1.011541× | 1.011930× | — | — |

The screen completed with recorded busy-core load observations below 0.66.
Because the candidate failed the plain retention screen, no pinned-libvpx run
was warranted.

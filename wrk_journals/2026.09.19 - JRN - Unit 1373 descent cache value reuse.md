# Unit 1373 — descent-cache value reuse Tesco

## Scope

The final leaf loop previously queried the bounded A4 descent cache again for
the NEWMV overrides, the Block16 breakout guard, and the optional full-pick
reuse. This unit keeps one cache result per leaf, copies its `Copy` payload
once, and reuses that value. The value copy avoids extending a borrow through
the large picker dispatch; the first reference-only version regressed 7.6–
16.0% and was discarded.

## Correctness

- Local AArch64 release encoder tests passed:
  `descent_pick_cache_covers_complete_superblock_key_space` and
  `realtime_cached_full_pick_requires_context_and_non_newmv_winner`.
- Crucible x86-64 release ran the same two tests; both passed. The build still
  reports the repository's two existing dead-code warnings in `frame_loop.rs`
  and `pre_analysis.rs`.
- A forced-A4 red mutation replaced the copied LAST causal context with the
  GOLDEN context. The baseline stream hash was
  `3f5f9d4367db14c7af82457a490dd9d6e6c230e8c5b3d140c3f641c64af826de`; the
  mutated stream was `a259a42848c3e018fcb3a6cd181b900b330935bf0cc02a5a01bc56be677f3008`.
  The mutation was restored before the candidate build.
- Every default-path candidate/control pair across four 20-pair screens had
  one stable hash per clip, with no candidate/control mismatch. The forced-A4
  five-pair screen was also hash-exact.

## Timing

The plain-release control and candidate were built with the same native
Windows toolchain and measured on Crucible under the relaxed load policy.
Each screen used one warmup and twenty alternating pairs for ducks, in-tree,
and old-town. Ratios are candidate/control; values below 1.0 are faster. The
screen statistic is the mean of the two middle paired ratios after sorting.

| Screen | Ducks | In-tree | Old-town | Geomean |
| --- | ---: | ---: | ---: | ---: |
| A | 0.982666 | 1.005859 | 0.984936 | 0.991099 |
| B | 0.998873 | 0.989124 | 0.995298 | 0.994423 |
| C | 0.983613 | 0.986712 | 0.985817 | 0.985380 |
| D | 1.001618 | 0.958016 | 1.016503 | 0.991732 |

The median of the four screen geomeans is `0.991415`, an approximately 0.86%
whole-encode improvement. This is below the former 1% single-unit retention
bar, but it is consistently positive across independent screens and fits the
explicit cumulative-Tesco policy. The forced-A4 screen was effectively neutral
(geomean `0.999712` from per-clip medians), so the change does not claim a
quality or speed win for the diagnostic path it touches.

A completed direct screen of the same semantic candidate before the final
`.as_ref()` spelling cleanup measured `1.4761x` against pinned libvpx (ducks
`1.4483x`, in-tree `1.5393x`, old-town `1.4426x`). A fresh direct rerun for the
final binary was stopped after Crucible stopped accepting SSH banners; its
partial files are not acceptance evidence. The parity target remains `<=1.05x`.

## Decision

Keep the value-copy change as a cumulative Tesco-sized, output-exact
optimization. It is not a parity milestone and should not be described as a
production-PGO qualification; the next integration gate can recheck it under
the normal host-trained PGO build.

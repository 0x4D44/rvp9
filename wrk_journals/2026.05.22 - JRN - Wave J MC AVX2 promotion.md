### Convolve8 AVX2 strategy notes (for agent briefs)

The dominant pattern for 8-tap MC is **multiply-add of u8 × i8 → i16** then
shift+clip. AVX2 helpers:

- `_mm256_maddubs_epi16(u8x32, i8x32) → i16x16`: signed `a*b + c*d` pairs.
  Two taps fuse into one madd; the 8-tap filter sums four madds.
- `_mm256_unpacklo_epi8` / `unpackhi_epi8` to interleave two source rows
  for the madd input.
- Final accumulator: add `(1 << (FILTER_BITS - 1))` rounding bias, arithmetic
  right-shift by `FILTER_BITS = 7`, then `_mm256_packus_epi16` for [0,255]
  clip + pack back to u8. **Remember the lane-unscramble** after packus
  (`_mm256_permute4x64_epi64(_, _MM_SHUFFLE(3,1,2,0))`) — same gotcha as
  Wave I TM_PRED.
- Filter taps come in as `&[i16; 8]` but libvpx ports cast them to `i8`
  (taps fit in i8 — max magnitude is 127). Confirm tap range before assuming
  i8 fits.

### Phase 2 design note — convolve8 source over-read

The scalar convolve8_horiz contract gives `src` exactly `(h-1)*src_stride +
w + 7` bytes (tight footprint). A 16-byte AVX2 load at the right edge of the
last row over-reads ~1 byte past that — the over-read bytes only feed
*invalid* output lanes (≥ w), so they never corrupt valid output, but the
OOB access itself is UB. **Decision:** the horizontal kernel copies each
row's `w+7` source span into a zeroed `[u8; 80]` stack scratch, then
SIMD-filters from the scratch. This honors the *exact* scalar contract (safe
drop-in, no hidden slack precondition) at the cost of one ≤71-byte memcpy
per row. The vertical kernel has no horizontal over-read (column loads are
exactly w-wide) so it filters `src` directly.

Filter math mirrors libvpx `convolve8_16` verbatim for bit-exactness:
4× `maddubs_epi16` of pixel(u8)×tap(i8) pairs, regrouped `(x0+x2)+(x1+x3)`
with early `+64` rounding and saturating final add, `srai 7`, then
`packus_epi16` for the [0,255] clip.

#### Design decisions (kept in head)

- **Two core kernels + compositions.** J3 (horiz) and J4 (vert) are the
  only kernels with real filter math. J5 = horiz-pass → u8 intermediate
  → vert-pass (reuses J3+J4 wrappers). J6/J7/J8 = prediction kernel →
  scratch → `convolve_avg_avx2` (reuses J2). Minimal new SIMD surface,
  maximal reuse, all bit-exact by construction.
- **Sub-pel-only contract.** The `maddubs` signed operand needs taps in
  i8 (|tap| ≤ 127). The sole offender is the full-pel centre tap 128
  (filter row 0), which `inter_predictor` always routes to
  `convolve_copy` — so it never reaches the 8-tap kernels. A
  `debug_assert` documents this; the differential tests skip row 0.
  (This surfaced as a J3 test failure on the identity filter — caught
  immediately, fixed by aligning the test to the production contract.)
- **Horiz over-read → per-row scratch.** See Phase 2 note above. Vert
  has no over-read (exact-width column loads), so it reads `src`
  directly.

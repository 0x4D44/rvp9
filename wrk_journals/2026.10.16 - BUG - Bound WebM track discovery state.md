# Bound WebM track-discovery state — KIL-00098

The in-memory track finder scanned an entire container while pushing every recognized child onto a pending vector. Wide sibling lists amplified allocation even when discovery ultimately returned “VP9 video track not found.” The packet walk's later nesting limit did not protect this earlier scan.

Replace pending siblings with active scan levels containing position, end and Tracks context. Advance the parent before entering each child; pop finished levels immediately. The existing recognized-container depth limit bounds retained levels to root plus 32 ancestors (Vec capacity may be larger). Discovery now returns the first VP9 track in document order, matching streaming discovery. Previously multiple VP9 track sets could select the last pending set because of stack order; this observable correction is covered by parity tests. Streaming discovery, packet walking, size validation and payload bounds remain unchanged.

## Observed regression evidence

The Sol 6.1 medium worker ran three new tests against original production code before the fix:

- A Segment containing 65,536 empty Tracks siblings returned the expected not-found error, but discovery requested **6,291,384 cumulative allocation/reallocation bytes**, exceeding the 16 KiB test budget. Streaming returned the same not-found error without the pending-width growth.
- Excessive recognized nesting before a later usable track was accepted by the old memory path, while streaming returned its depth-limit error. The new parity assertion failed on old memory success.
- Multiple VP9 track sets selected payload `[0x22]` in memory instead of the first document-order payload `[0x11]`; the streaming reader selected the first track.

The new allocation test uses a separate integration binary's System-delegating global allocator. Constant-initialized thread-local Cell counters measure only requested alloc/zeroed/realloc sizes on the calling test thread. Fixture construction, file I/O, assertions and formatting occur outside the measured interval. Allocation hooks do no allocating work and forward their arguments unchanged; measurement scope restores its flag on unwind. This measures cumulative requested bytes, **not peak live memory or RSS**.

The corrected finder requested **120 cumulative bytes** on the same wide fixture. The worker exposed that count with a temporary zero-budget assertion, restored the normal 16 KiB budget, and observed green. A separate wide positive control preserves exact packet bytes in both APIs. Deliberately changing its expected payload to `[0x99]` failed at actual `[0x11]`; restoring the expectation passed. These calibrations are separate from the original-defect red proofs.

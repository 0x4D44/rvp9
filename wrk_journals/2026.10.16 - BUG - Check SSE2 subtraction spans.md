# RVP9-BUG-FLU-00032 — Check SSE2 subtraction spans

The safe square-subtraction wrappers computed the last-row input span with
unchecked `(side - 1) * stride + side`. With wrapping arithmetic, an extreme
stride could produce a small span, pass the slice-length assertion, and enter
the raw-pointer SIMD loop with an invalid row offset.

The fix checks both multiplication and addition before validating each input
slice. The plain and nonzero-reporting wrappers share the same checked-span
helper and retain their existing guard order. Supported sizes constrain the
destination multiplication; the input stride remains caller-controlled and
requires checked arithmetic. Valid subtraction and nonzero behavior remain.

Regression calibration must stop before unsafe memory access. Its temporary
sentinel is installed at the inner-loop entry while the old unchecked span
arithmetic is restored. The regression expects the checked overflow panic and
therefore fails on the sentinel panic. The sentinel and unchecked mutation are
both removed before final checks.

Validation uses the installed x86_64-apple-darwin target under Rosetta with
`RUSTFLAGS='-C target-cpu=x86-64 -C overflow-checks=no'`. Explicitly disabling
overflow checks reproduces release-style wrapping without requiring a deployable
build.

The regression covers 32 combinations: plain/nonzero wrappers, source/prediction
stride, sides 8/16/32/64, and multiplication/addition overflow. Buffers cover
ordinary blocks, so a different bounds failure cannot satisfy its exact
`square input span overflow` panic check. It aggregates outcomes so every case
runs before the final assertion.

The unchecked-span reversal selected one regression and exited 101 at that
final assertion. All 32 combinations reached the pre-unsafe sentinel instead
of the expected overflow rejection. No malicious-stride pointer operation or
load executed. Final diff review confirmed that the sentinel is absent and the
checked helper is restored.

The final focused module filter passed all three tests under explicit wrapping
arithmetic: the new matrix and the unchanged random/extreme differential tests.
`cargo fmt --all --check`, `git diff --check`, and x86 core Clippy
(`--lib --tests`) passed; Clippy emitted no warnings.

The selected final smoke is the same x86 module filter
`dsp::x86_64::subtract_sse2`, with explicit CPU/overflow flags, bounded to
60 seconds after final fetch/catch-up.

Independent read-only safety review found no issues in source SHA-256
`7ad83632c2f93c9320680b3b04f5e9a75d55fa28e3b6458687775ae9ed00309c`.
It confirmed input span and destination arithmetic proofs, both wrappers,
absence of temporary instrumentation, and the observed red/green evidence.
Execution was under Rosetta rather than native x86 hardware.

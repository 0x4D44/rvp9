# RVP9-BUG-FLU-00043 — Arm decoder scalar routing

Manual Open-queue fixing pass. Claimed with run `fix-20261018T155935Z-dd09e04f`; fresh worktree after FLU-00045 landed. Related Fixed CRU-00001 concerns x86 direct encoder bypasses, not this decoder issue; Open FLU-00037 concerns missing scalar forward helpers in non-test Miri builds and remains separate.

## Root cause and scope

AArch64 capability detection ignored `RVP9_FORCE_SCALAR`. All decoder SIMD table families are conditional on those flags, but three inverse-DCT16 wrappers are additionally unconditional NEON calls; their scalar aliases in the dispatch table point back to these wrappers. Thus merely clearing capabilities would leave the direct inverse-transform bypass. The decoder crate has no direct Arm/NEON calls outside these core routing paths.

Fix scope: exact-value environment mask for Arm table capabilities; frozen table capability routing in the three public inverse-DCT16 entry points; compile their existing scalar helper in ordinary Arm library builds. Preserve native dispatch and existing explicit ISA entry points. Arm encoder direct forward-transform/quantization/Hadamard paths remain outside this decoder fix. Document the extended decoder hook scope in the capability API docs. The repository instruction file is not expanded by this task.

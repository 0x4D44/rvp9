## What was found (headline)

- Two real bdrate defects: `--limit` desyncs PSNR against the un-truncated
  reference (tool can't produce a number for its own documented invocation);
  `polyfit3` returns `[0;4]` on a singular fit and the caller fabricates a
  finite wrong BD-rate (the harness sibling handles the same case correctly).
- `RVP9_*` env scrubbing exists only in `encode-headtohead.rs` — the BD-rate
  gate tools inherit ambient debug vars, asymmetrically (rvp9 honours them,
  the libvpx anchor doesn't).
- The checked-in ratchet baseline CSV is mislabeled (`--pinned` rows from a
  Windows dev box) and its fixtures (`testsrc_*`) can never match the ratchet's
  `DEFAULT_FIXTURES` (`vp90-2-*`) — plus ~26% run-to-run noise vs a 10% budget.
- Fixed shared temp paths in the crate's unit tests (cross-worktree flake);
  soak's `--vpxdec` default is a `D:\language\libvpx-stock` out-of-tree path
  (the KILN-00039 class, contradicting that bug's closure sweep statement).
- Design drafts: mandatory tail-latency budget for the realtime gate;
  noise-aware ratchet before any host is pinned; soak RSS-growth assertion +
  in-process watchdog.
- Clean bills: `mwu.rs` verified correct end-to-end by the lead;
  `encode-headtohead.rs` is the methodological high-water mark of the crate.

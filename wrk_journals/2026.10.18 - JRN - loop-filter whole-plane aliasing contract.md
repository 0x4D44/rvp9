# Loop-filter whole-plane aliasing contract

RVP9-BUG-FLU-00052 is fixed by documenting the full-plane exclusivity required whenever `SharedFrame` reconstructs its Y, U, or V `&mut [u8]`. The slice helpers, `loop_filter_sb_row`, and `apply_one_sb` now state that disjoint SB/row ownership does not authorize overlapping full-plane slices. The same requirement is recorded for `run_split_edge_lf_worker`, which reconstructs the slices directly. Its current implementation asserts a single LF worker.

The unsafe-block comments and `SharedFrame` `Send`/`Sync` rationale now distinguish raw-pointer sharing and pixel-ordering from the exclusive full-plane access required by mutable slices. The decoder call-site rationale now records its one-worker and joined-decode conditions. The cited HLD's contradictory claim that byte-level exclusion justifies full-plane mutable slices is corrected. This is a safety-contract correction, so no runtime regression test was added.

`cargo fmt --all --check`, `cargo check -p rvp9-decoder --lib --locked`, `cargo doc -p rvp9-core --no-deps --locked`, and `git diff --check` passed. Rustdoc completed with 79 warnings, including existing private-item links in `apply.rs`.

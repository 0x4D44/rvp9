## Bug

KILN-00010 (Open, Medium): `idct16x16_sse2_eq_avx2_{uniform_12,eob_dense}` are RED —
the SSE2 256-point inverse DCT (`idct16x16_add_sse2_256`) is not bit-identical to the
AVX2 oracle (`idct16x16_add_avx2`). SSE2 saturates (`_mm_packs_epi32` / saturating
add?); AVX2 + scalar use modular wraplow (libvpx-C-faithful). Prior pass REFUTED the
"out-of-domain full-density" hypothesis (2/2) and left root cause UNCONFIRMED with an
explicit warning: do not "fix" by narrowing the test until instrumented.

## Decision tree (must resolve with DATA, not assumption)

For the failing seed:
- If the full-precision (no-wrap) IDCT intermediates EXCEED i16 anywhere → the input
  is out-of-domain (modular wrap vs saturate legitimately differ; libvpx's own SSE2
  diverges from its C there too) → tighten the proptest domain + record in
  divergence-ledger. NOT a kernel fix.
- If NO intermediate exceeds i16 → saturate==wrap, so the SSE2 divergence has a
  DIFFERENT cause = a real rvp9 SSE2 porting bug → fix the kernel to match
  libvpx SSE2 / the modular spec.

Cross-check: compare rvp9 SSE2 ops (which add/sub saturate) against libvpx
`vpx_idct16x16_256_add_sse2` — is rvp9 SSE2 libvpx-faithful?

## Investigation & root cause (CONFIRMED out-of-domain)

Reproduced RED (`uniform_12`, `eob_dense` fail; `sparse_12`, `eob_38` pass).

Code: rvp9 SSE2 butterfly uses modular `_mm_add/sub_epi16`; the suspect
saturating op is `write_buffer_8x1` line 342 `_mm_adds_epi16` (final +32
rounding). **libvpx `inv_txfm_sse2.h:232` uses `_mm_adds_epi16` there too** — so
rvp9 SSE2 is libvpx-faithful (saturating), and rvp9 AVX2/scalar are libvpx-C-
faithful (modular wraplow). libvpx's own SSE2 vs C diverge identically on
i16-overflowing inputs.

Instrumented the actual seed (the step the prior pass deferred):
- seed = 190/256 dense, max|coef|=2046 (prior pass's "sparse seed" claim was
  factually wrong).
- full seed → 1 px mismatch; **seed/2 → 0** (/3,/4,/8,/16 → 0): pure
  magnitude/overflow, not algorithmic (a structural bug wouldn't vanish under
  scaling).
- in-domain sweep (2000× `fdct16x16` of `[-255,255]` residuals, coefs up to
  ±5310): **0/2000** mismatches.
- low-energy passes / high-energy fails = saturation-on-overflow signature.

=> The kernel is correct & libvpx-faithful. The full-density arbitrary-i12 test
strategies are OUT OF DOMAIN (their collective energy overflows the i16 SSE2
transform, where saturate legitimately differs from modular wrap). Prior pass's
refutation rested on the wrong "sparse seed" premise + an unverified overflow
condition.

Adversarial panel (Workflow, 3 skeptics): **accepted 2-of-1**. #1/#2 confirm
(kernel faithful, encoder/dequant path itself i16-bounded so valid bitstreams
can't produce these inputs). #3 (dissent) didn't dispute the diagnosis but asked
for completeness — ledger entry, a pinned regression, instrumented evidence —
all now addressed.

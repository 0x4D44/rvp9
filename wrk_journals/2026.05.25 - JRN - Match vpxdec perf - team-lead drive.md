## Operating model

- **Worktrees**: each implementation wave runs in its own `.claude/worktrees/<name>` so we can scrap without contamination.
- **Bench oracle**: `scripts/bench-headtohead.ps1`. Headline fixture = `testsrc_1080p30 t=4`. Single-threaded torture test = `testsrc_720p30 t=1`. The 2× gate is the goal — anything under 2× ratio (rvp9/vpxdec) on each fixture is "matched".
- **Promotion rule**: a wave merges to main only when (a) cumulative bench shows a real win (>2% on at least one fixture, no regression >2% elsewhere) AND (b) `cargo test --workspace` plus conformance suite stay green. Otherwise the worktree is scrapped.
- **Conformance**: 201/201 vectors must remain green at every merge.
- **Journal cadence**: update after each wave's decision point (merge or scrap), plus a daily wrap-up.

**Hypothesis (compelling):** The faster kernel exposes a secondary bottleneck. **This is a real architectural finding worth remembering:** in this decoder at this frame size, "make a kernel faster in microbench" is not sufficient evidence to ship. The 128-bit "AVX2" path is *correctly tuned* for the decoder's working set even though microbench says it's leaving 40% on the floor.

### 2026-05-25 evening — Wave 6 designed and DEFERRED

Plan agent dispatched in parallel with W5b for Wave 6 (tile load imbalance fix). Returned with a thorough analysis and a **defer recommendation**:

**Key finding:** tile-internal CABAC parse is strictly serial (one `BoolReader`, no checkpoint). Work-stealing at SB-row granularity (option A) and worst-tile split (option B) are both **infeasible** — they would require resuming bitstream parse at an arbitrary cursor, which the format doesn't support. The only viable approach is parse/reconstruct pipelining (option B′): a second worker runs reconstruct-half for SB row R while the primary parses R+1.

**B′ costs 600-1200 LOC for 200-700 µs gain** on a 3 256 µs frame. With the W2-trap (scope overhead vs gain at small frames) sitting at ~30% odds of net regression, the Plan agent put confidence at **low**.

**Decision: defer.** Plan saved to `wrk_docs/2026.05.25 - HLD - Wave 6 tile load balance plan.md` with revisit triggers (larger frame sizes, parse fraction measurement >40%, HBD/4:4:4 support).

This means after W5b, the immediate Tier-3 levers are exhausted:
- W5b inflight (LF prereq decoupling)
- W3 retry (convolve8_horiz 256-bit) — no win, held
- W6 (tile load balance) — deferred

If W5b lands a big win, that's the closing move on the planned roadmap. If not, the remaining options are smaller (BoolReader peek-bit table cache, intra-pred kernel tweaks, PGO promotion) and we'd be honest about not hitting 2× this session.

To reach 2×, the LF stage itself must shrink by ~45%, which is impossible to do via overlap alone (the kernels are already AVX2; W2 row-MT showed dispatching them doesn't win). The only remaining ways to reduce LF µs:
- Make the LF kernels themselves faster (W3 showed wider kernels can regress; needs careful study)
- Reduce LF *work* (skip more edges per frame — semantic change, conformance-critical)

# Reject forbidden unknown-size WebM elements — KIL-00094

The WebM readers interpreted unknown-size binary blocks as extending to their parent's end. A malformed block could absorb a following sibling into one packet, and the streaming reader could allocate the whole remainder. Memory track discovery also accepted an unknown-size TrackEntry, which the streaming finder already rejected.

[RFC 8794 section 6.2](https://www.rfc-editor.org/rfc/rfc8794.html#section-6.2) restricts unknown sizes to schema-enabled Master elements. The [official Matroska schema](https://raw.githubusercontent.com/ietf-wg-cellar/matroska-specification/master/ebml_matroska.xml) enables this only for Segment and Cluster. Block and SimpleBlock are binary elements; TrackEntry and BlockGroup do not enable unknown size. The intended correction validates each encountered size header before using parent-end semantics, dispatching, skipping or reading payloads. Known-sized skipped masters remain skipped; this is not a complete Matroska schema validator.

Scope: container size-header handling and focused container tests. Preserve the valid unknown-size Segment/Cluster sibling termination from KIL-00093. Neighboring KIL-00098 pending-container growth and KIL-00099 relative I/O positions are separate, Open and unowned when checked; neither is part of this fix. No dependency or public interface change is intended.

The shared validator returns the original unknown-size marker after checking the element ID. All six element-header dispatch sites call it before payload calculations or traversal. Streaming payload-end calculation now receives that validated marker. The separate Block track-number vints remain untouched, and TrackEntry child diagnostics retain their existing stricter context rule. This rejects malformed inputs without allocating a whole parent remainder as a binary block.

## Observed regression evidence

The Luna 6 max worker ran the new rejection tests before changing production code. The three new assertions failed; the existing unknown-size Segment control passed. Each negative fixture computes memory and streaming results before the aggregate assertion, so both paths were exercised even when one failed. Widths one and eight were covered.

- `webm_unknown_size_block_leaves_are_rejected_by_both_readers`: old SimpleBlock and Block results included the following sibling bytes instead of rejecting the size marker.
- `webm_unknown_size_track_entry_is_rejected_by_both_readers`: memory returned the fixture packet (`Ok([[7]])`); streaming already returned its existing unknown-size TrackEntry error.
- `webm_unknown_size_forbidden_element_ids_are_rejected_by_both_readers`: the aggregate assertion caught missing unknown-size rejection for EBML, Tracks, BlockGroup/child, Info, Void and an unrecognized element ID. The test was renamed from its initial inaccurate “non-master” label; several of these are masters whose schema does not permit unknown sizes.

The new known-size positive control verifies exact SimpleBlock/Block packet bytes and skipped known-size elements in both APIs. Its initial fixture mistakenly encoded an eight-byte track-number vint as nine bytes; the first full post-fix run failed on empty packets versus two expected frames. Correcting the fixture to eight bytes made the control pass. This is fixture calibration evidence, not a production-defect reversal.

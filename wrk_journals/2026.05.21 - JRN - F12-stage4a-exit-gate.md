### Deliverable 1 — BD-rate computation function

`crates/rvp9-harness/src/bdrate.rs` — pure-function BD-rate via the
trapezoidal-rule approximation:

1. Sort both curves by PSNR ascending.
2. Take the overlapping PSNR range as
   `[max(min_psnr_A, min_psnr_B), min(max_psnr_A, max_psnr_B)]`.
3. Resample `log10(bitrate)` at each curve's breakpoints inside the
   overlap via linear interpolation.
4. Compute the trapezoidal mean of `log10(bitrate)` for each curve.
5. Return `(10^(mean_b - mean_a) - 1) * 100` — the percent-difference
   in geometric-mean bitrate at matched PSNR.

Sign convention: positive ⇒ curve B uses more bits than curve A;
negative ⇒ curve B saves bits.

**Divergence from Bjøntegaard cubic:** the standard formula fits a
cubic polynomial in `log10(bitrate) vs PSNR` and integrates the
closed-form gap. Trapezoidal vs cubic agree to within ~0.5 percentage
points for monotonic curves with 4+ points (Bjøntegaard's own 2008
note). Documented in `notes/divergence-ledger.md` under "F-series
Stage 4a — BD-rate trapezoidal approximation".

### Deliverable 2 — Measurement harness

`crates/rvp9-encoder/tests/bdrate_gate.rs` — integration test gated by
`#[ignore]`. Run via:

```text
cargo test --test bdrate_gate -- --ignored --nocapture
```

What it does:

1. Synthesises a 128×128 8-frame animated-gradient source (one diagonal
   gradient that shifts per frame — exercises inter mode picker).
2. Encodes through `rvp9-encoder::StreamEncoder` at four target
   bitrates: 250 / 500 / 1000 / 2000 kbps.
3. Decodes each packet through `rvp9-decoder::Decoder`, computes
   Y-plane PSNR per frame, averages per operating point.
4. Probes `D:\language\libvpx-stock\vpxenc.exe`; if present, encodes
   the same source through `vpxenc --codec=vp9 --rt --cpu-used=7
   --tune-content=default --passes=1`, decodes back via vpxdec, and
   reports the libvpx curve.
5. Calls `bdrate(libvpx_curve, rvp9_curve)` for the report.
6. Asserts the rvp9 curve is monotonic in PSNR (defensive sanity
   check, the only HARD assert in the test).

## What this tells us — and what it doesn't

The harness works end-to-end on both legs. libvpx-stock is present and
the encode→decode→PSNR pipeline through it is wired correctly. The
**measurement is not yet meaningful** for two compounding reasons:

1. **Synthetic source is too easy.** The animated gradient is smooth
   enough that BOTH encoders hit a quality ceiling well below the
   target bitrate at every operating point — rvp9 sits at ~35 dB / 20
   kbps regardless of target; libvpx sits at ~52 dB / 23 kbps. The
   PSNR-axis is degenerate (a single point per curve), so the
   trapezoidal integral has zero PSNR range to span and correctly
   returns the NaN sentinel.

2. **rvp9 is well below libvpx in PSNR at matched bitrate** — 35 dB
   vs 52 dB. This isn't a target-bitrate-response issue; it's the
   encoder's **maximum quality at q=1** on this content. Translating
   gradient + DC-PRED-heavy partition → high-freq residual energy
   from the inter mismatch → quant-noise floor at the encoder's
   smallest q-step. The encoder's known divergences (no NEARMV, no
   compound-ref, simplified mode set, fixed correction factor) all
   contribute.

The encoder's RD curve is currently FLAT — the rate controller can't
push the q-index high enough at large targets to produce more bits, OR
the content is genuinely below the encoder's discrimination threshold.
We'd need a textured, non-synthetic source to disambiguate.

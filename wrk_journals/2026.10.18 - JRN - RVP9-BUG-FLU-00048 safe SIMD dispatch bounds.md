# RVP9-BUG-FLU-00048 — Safe SIMD dispatch bounds

Manual Open-queue fixing pass. Claimed with `deltic start-task --bug RVP9-BUG-FLU-00048`; run `fix-20261018T153528Z-cff45905`.

## Change

Safe x86 dispatch wrappers now validate slice geometry with checked arithmetic before entering target-feature kernels. Covers IDCT/IHT, intra prediction, single/dual loop filters, copy/average and filtered/scaled convolution, SAD/SAD4d, variance/subpixel variance, and dequant scratch/scatter bounds. Existing specialized variance kernels and explicit scalar predictor fallbacks remain in use. Horizontal convolution falls back to scalar when overlapping source rows cannot supply SIMD's extra nonfinal-row load footprint.

The DC4 public getter is exercised with forced AVX2 caps and invalid above, left, destination and stride inputs: all reject before the ISA boundary. No dependency, public signature or dispatch tier changed. No version pre-bump.

## Regression evidence

- Root-cause reversal: removed the new `idct8x8_add_sse2_64` layout guard only. With debug assertions and overflow checks disabled, `safety_bounds_sse2_transform_overlapping_stride` selected one test and failed on `safe transform must reject a stride shorter than its block width`. The zero-stride fixture has ample backing storage, so the pre-fix call stays within allocation. Restoring the guard made all four `safety_bounds` tests pass.
- Root-cause reversal: block footprint helper used `debug_assert!` instead of `assert!`. Release-semantics run selected four helper tests: three failed with `did not panic as expected` for short storage, overflowing stride and zero height; exact-tail fixture passed. Restoring the release assertion made the checks pass.
- Root-cause reversal: omitted LPF helper's upper slice-length check. Exact-footprint rejection test failed; restored check passed in optimized standalone execution. No invalid raw-pointer call was made during this reversal.
- Predictor source predicate was red before guard insertion (13 missing wrapper guards) and green after. This proves guard placement only; executed invalid-input tests separately verify rejection before AVX2 entry. Pre-fix AVX2 invalid-memory reproduction was deliberately not run: Rosetta reports AVX2 unavailable, and invoking unchecked malformed inputs would be undefined behavior.

## Validation environment

Guard checks use release semantics with `CARGO_PROFILE_RELEASE_LTO=false CARGO_PROFILE_RELEASE_OPT_LEVEL=0 CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16`, or dev with `CARGO_PROFILE_DEV_DEBUG_ASSERTIONS=false CARGO_PROFILE_DEV_OVERFLOW_CHECKS=false CARGO_PROFILE_DEV_OPT_LEVEL=0`. These are unoptimized checks, not production-speed evidence. An initial opt3 release guard build exceeded its 180-second bound; it is not a passing check.

Test filters: `safety_bounds`, `lpf_bounds`, `before_avx2_inner`, `guard`, `scalar_fallback_accepts_valid_64x64_layout`; valid SSE2 smoke: `dsp::x86_64::idct8x8_sse2_64::tests`. Formatting: `cargo fmt --all -- --check`. Lint: `cargo clippy -p rvp9-core --lib --tests --target x86_64-apple-darwin --locked` with baseline x86 rustflags.

## Limits

Valid AVX2 differential tests cannot execute on this host; they retain their existing ISA gates. No full workspace suite or timing comparison was run. Dequantization validates raster indices in an added upfront pass; its performance cost is unmeasured. The separate already-Open RVP9-BUG-FLU-00050 concerns final-row pointer advancement in IDCT32 helpers and remains outside this fix. Do not interpret these bounds checks as resolving that record.

Runtime isolation: these are pure codec unit tests using process-local buffers and this worktree's Cargo output; no running rvp9 application appeared in the process inspection, and no shared application state was used.

### Risk #1 verification (HLD §8 #1) — H-filter tap span

Per HLD §8 Risk #1, must confirm max pixel-read offset above the H-edge is
within libvpx-equivalent reach (≤ 7 rows for nsync=4 to be valid).

**Findings (file: `crates/rvp9-core/src/dsp/x86_64/lpf_horizontal_16_avx2.rs:728-743`)**:
```
let p7 = load_row(base, s_index - 8 * pitch);
let p6 = load_row(base, s_index - 7 * pitch);
...
let q7 = load_row(base, s_index + 7 * pitch);
```

Maximum read = **8 luma rows above** edge (p7 at `-8*pitch`). HLD §8 mitigation
says nsync=4 is a *latency* choice, not correctness — and 8 rows above the SB
top edge is well within row r-1's 64-row body (SB height). Horizontal headroom
(nsync=4 = 256 px) guarantees row r-1 has finished V+H at column c before row r
reads its top-edge pixels at column c. Identical to libvpx (16-tap variant).
**Risk #1 cleared. Proceeding.**

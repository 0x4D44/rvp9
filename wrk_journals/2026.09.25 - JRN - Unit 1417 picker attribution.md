# Unit 1417 — picker attribution

This docs-only unit rechecked the retained Unit 1416 x86 profile and wrote a
fresh source-attribution record. No repository source, remote profile artifact,
or scratch file was changed.

## Evidence

Unit 1416 profiled integrated `5b6822c05c8d7ff3005902715d618f0ecbfbfd2c`
with twenty serial 1920×1080 Ducks encodes at CPU-used 6, CBR 1260 kb/s,
one thread, tile 0, AQ0, noise 0, lag 0, and KF60. The native release/debug=2
input, executable, PDB, ETL, and xperf-report hashes are recorded in the
adjacent evidence README. A fresh remote SHA-256 read produced the same five
artifact hashes.

The remote report parser summed only rows whose process was `rvp9enc.exe` and
whose symbol began `rvp9enc.exe!`. It reproduced 40,988,965 weighted samples
and this top symbol: the picker closure 5,273,714 (12.8662%), AVX2 quantizer
2,806,832 (6.8478%), SAD4D 2,080,005 (5.0745%), inter-mode picker 1,865,459
(4.5511%), diamond search 1,756,889 (4.2862%), `fdct16x16` 1,753,713
(4.2785%), 16×16 variance 1,719,943 (4.1961%), 16×16 sub-pel variance
1,527,768 (3.7273%), `fdct8x8` 1,509,356 (3.6823%), and slot evaluation
1,449,906 (3.5373%).

For the picker closure, a read-only Python/DbgHelp pass used
`SymFromName` and `SymGetLineFromAddr64` against the exact remote PDB and
filtered `rvp9-cpu6-sampled-rvp9enc.txt` by the sampled-IP field. The symbol
range was RVA `0x12def0..0x1451dd` (94,957 bytes). It found 5,274 direct rows,
1,189 unique IPs, 5,274 mapped rows, and 4,943 nonzero source lines. The top
mapping was `crates/rvp9-encoder/src/lib.rs:11471` with 1,525 rows (28.915% of
picker rows; about 3.72% of 40,989 direct encoder rows). The next four were
lines 11588 (345), 12115 (254), 10126 (231), and 11563 (223).

This is a sampled ceiling, not runtime attribution. Unit 1412 previously
reported the same callsite at 1,224/4,797 picker rows and 3.09% of direct
encoder rows on older source. The current count supports a persistent target,
not a speed claim.

## Decision

The defensible next target is an exact-output, algorithmic call-count study of
the `choose_inter_luma_tx_size` region at `lib.rs:11471`. The line mapping does
not establish selected-emission duplicate work. Units 585 and 586 in
`wrk_journals/2026.07.30 - JRN - production parity drive.md` already rejected
copied and zero-copy selected-TX coefficient caches after neutral paired
results, so cache work is a design fork requiring new duplicate-work evidence,
not a recommendation here.

The latest direct pinned-libvpx result remains Unit 1415's `1.230937x` paired
equal-clip corpus ratio; no Unit 1417 timing or code result exists. No code
change was made.

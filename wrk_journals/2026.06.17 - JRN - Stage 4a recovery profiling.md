# 2026-06-17 - JRN - Stage 4a recovery profiling

Goal file: `wrk_docs/2026.06.17 - PLN - compressor Stage 4a recovery goal.md`.

## Baseline

- Default encoder lib tests pass serially: `cargo test -p rvp9-encoder --lib -- --test-threads=1` => 456 passed, 1 ignored.
- Default cross-decoder gate remains byte-exact against rvp9-decoder, vpxdec, and ffmpeg on the exercised 8-frame stream.
- Default quality gate is still not Stage 4a recovered: mean matched-bitrate PSNR gap `+2.36 dB`, BD-rate `+22.88%`.
- Default 720p30 realtime remains far over budget. Env-gated profiling shows steady-state inter frames dominated by A4 partition descent: roughly `85-115 ms` descent, `16-21 ms` final pick, `22-24 ms` emit.

## Speed A/Bs

- `RVP9_A4_RD_PARTITION_DISABLE=1` removes descent but still misses realtime: median about `59 ms`.
- Adding `RVP9_RT_SKIP_PICKER_SKIP_EMIT=1` cuts emit to about `1 ms`, but with A4 on it changes reconstruction enough to make descent worse.
- Full speed hammer (`A4_RD_PARTITION_DISABLE`, skip emit, disable GOLDEN, EightTap-only, disable all NEWMV) passes realtime at about `27 ms`, but quality collapses to mean gap `+5.34 dB`.
- Replacing all-NEWMV-off with `RVP9_RT_DISABLE_NEWMV_MAX_EDGE=16` also passes realtime (`26.56 ms`) but gives the same poor quality signal (`+5.34 dB` mean gap).
- `RVP9_RT_DISABLE_NEWMV_MAX_EDGE=8` passes realtime at `29.74 ms` with EightTap-only / GOLDEN disabled, but quality remains poor (`+5.32 dB` mean gap).
- Restoring GOLDEN with the `<=8` NEWMV mask still passes realtime (`31.62 ms`) but worsens quality to `+5.48 dB`.
- Restoring two-filter search with the `<=8` NEWMV mask misses by a small amount (`34.30 ms`). Adding `RVP9_RT_NEWMV_MAX_ITERS=0` and `RVP9_RT_NEWMV_SUBPEL_ITERS=0` brings it to `32.73 ms`, but quality is still poor (`+5.37 dB`).

## Quality isolation

- Disabling A4 partition descent alone regresses quality to mean gap `+4.09 dB`.
- Adding skip-emission on top of A4-off is similar (`+4.13 dB`), so the main quality loss is the partition path, not the emit shortcut.
- Keeping A4 on while masking NEWMV on `<=8` blocks still leaves realtime dominated by descent (`75-115 ms` descent per inter frame; median `140.84 ms`). The mask creates some Phase-2 NEWMV reuse but not enough to move the gate.

## Current conclusion

The current high-confidence map is:

- Speed gate can be met only by bypassing or heavily weakening the A4 partition path.
- The A4 partition path is also the largest measured contributor to current quality.
- NEWMV search-depth caps help once A4 is disabled, but they do not recover Stage 4a quality.
- The next useful work is a real A4 descent speedup or a cheaper partition oracle that preserves A4-like partition choices, not more all-or-nothing mode masking.

## Emit and descent reuse follow-up

- Added `RVP9_EMIT_PROFILE` to split inter emit into MC prediction, TX-size selection, residual build, quant, inverse, and coefficient insertion. In the best A4-on/C2 candidate before emit changes, emit was ~24-26 ms/frame, dominated by `choose_inter_luma_tx_size` (~13 ms) and inter forward quant (~7 ms); prediction and inverse were tiny.
- Exact scratch-buffer cleanup in the inter emit/TX-select paths reduced allocation churn but did not change the architecture: `RVP9_C2B_THRESH=-100 RVP9_RT_EIGHTTAP_ONLY=1 RVP9_RT_DISABLE_NEWMV_MAX_EDGE=8` still measured about 60 ms median, far above the 33 ms gate.
- `RVP9_RT_EMIT_MAX_TX=1` removes final emit TX-size search. With C2 aggressive + EightTap-only + NEWMV masked on <=8 blocks + `RVP9_RDO_TXSEARCH=0`, realtime improved to ~45-48 ms but still failed.
- `RVP9_RT_REUSE_DESCENT_PICK=1` reuses the full cached A4 descent picker result for the committed leaf and drives final-picker time to 0. In the `<=8` stack it still measured ~39 ms because A4 descent rose to ~16-18 ms and emit stayed ~8-9 ms.
- Masking NEWMV on <=16 blocks makes the stack pass realtime: `RVP9_C2B_THRESH=-100 RVP9_RT_EIGHTTAP_ONLY=1 RVP9_RT_DISABLE_NEWMV_MAX_EDGE=16 RVP9_RT_EMIT_MAX_TX=1 RVP9_RDO_TXSEARCH=0 RVP9_RT_REUSE_DESCENT_PICK=1` measured 29.85-32.10 ms median and remained cross-decoder byte-exact on the vpxdec/ffmpeg gate. Quality is not viable: BD-rate was +180.31% with full reuse, mean matched-bitrate gap +5.27 dB.
- The less destructive `<=8` NEWMV mask with max-TX emit and `RVP9_RDO_TXSEARCH=0` keeps quality closer but misses realtime: BD-rate +54.60%, mean gap +2.27 dB without full descent-pick reuse; with reuse, BD-rate +32.13%, mean gap +2.84 dB. Both are still well outside the Stage 4a +2% BD-rate target.
- Imported two small track2 quality ideas (block-size-aware diamond start and coefficient sign-bit costing) as an A/B, then backed them out after they regressed current-tree quality. Default quality returned to the known baseline when disabled: BD-rate +22.88%, mean gap +2.36 dB. Do not assume track2's June 4 quality wins transfer to this tree.

## High-precision MV probe

- Added an opt-in `RVP9_HIGHMV=1` path that threads the frame-level high-precision MV gate through MV costs, search, final MV precision lowering, uncompressed/compressed headers, and decoder-frame-context adaptation.
- The first HP run exposed a real writer-side adaptation bug: `write_mv_component` only bumped `class0_hp` / `hp` counts when an HP bit was coded. libvpx increments those counts unconditionally, using the fallback `hp=1` when block-level HP is disabled. Fixing the writer counts made `RVP9_HIGHMV=1` cross-decoder byte-exact again for both fixed-q 150 and normal cross-decoder gates.
- HP MVs are not a Stage 4a recovery lever on the current tree. With `RVP9_HIGHMV=1`, the real-content quality gate measured BD-rate `+25.20%`, mean matched-bitrate gap `+2.38 dB` (slightly worse than the default `+22.88%` / `+2.36 dB`). The 720p30 realtime gate still failed at median `140.63 ms`.

## P8 / reuse / emit frontier

- Full committed-pick reuse on the default path removes final-pick time but still fails realtime: median `111.18 ms`, with descent still about `77-98 ms` and emit about `17-19 ms`.
- `RVP9_P8=0` is a large descent-speed lever: median `81.02 ms`; descent drops to roughly `32-43 ms` and final pick remains `13-17 ms`. Quality is mixed but not recovered: BD-rate `+36.66%`, mean matched-bitrate gap `+2.27 dB`.
- `RVP9_P8=0 RVP9_RT_REUSE_DESCENT_PICK=1` cuts the median to `63.25 ms` by eliminating final-pick time, but descent remains roughly `31-38 ms` and emit about `17-18 ms`.
- Adding `RVP9_RT_EMIT_MAX_TX=1 RVP9_RDO_TXSEARCH=0` reduces emit to about `6.5-6.9 ms`, but median still fails at `52.77 ms`.
- Aggressive large-frame ML breakout (`RVP9_C2B_THRESH=-100`) on top of P8-off/full-reuse/max-TX gets close but still fails: median `38.16 ms`, descent around `19-25 ms`, emit around `6.4-7.1 ms`.
- Adding EightTap-only to that stack passes the realtime gate: `RVP9_P8=0 RVP9_RT_REUSE_DESCENT_PICK=1 RVP9_RT_EMIT_MAX_TX=1 RVP9_RDO_TXSEARCH=0 RVP9_C2B_THRESH=-100 RVP9_RT_EIGHTTAP_ONLY=1` measured median `30.69 ms`. It is a speed-only frontier, not recovery: the real-content quality gate worsened to mean matched-bitrate gap `+2.95 dB` (BD-rate readout `-58.92%` is not useful because the rvp9 curve is poorly shaped at low-rate points).

## Descent filter shortcut and S2/3D check

- Added opt-in `RVP9_A4_DESCENT_CB_FILTER=1`, which enables the cheap `cb_pred_filter_search` shortcut only in the A4 partition-descent proxy. The final emitted picker keeps the normal speed-feature setting, so the knob tests whether descent can be cheaper without globally forcing a single interpolation filter.
- On the default path, the knob alone improves realtime from the current default median `144.31 ms` to a measured `120.45 ms`, but A4 descent still dominates and the gate still fails by a wide margin.
- In the closest non-EightTap stack, `RVP9_A4_DESCENT_CB_FILTER=1 RVP9_P8=0 RVP9_RT_REUSE_DESCENT_PICK=1 RVP9_RT_EMIT_MAX_TX=1 RVP9_RDO_TXSEARCH=0 RVP9_C2B_THRESH=-100`, realtime measured median `34.82 ms` (fails by `1.82 ms`). The matching quality measurement is not viable for Stage 4a recovery: BD-rate `-97.87%` is misleading due curve shape, but mean matched-bitrate gap is `+2.98 dB` and max gap is `+3.47 dB`, worse than default.
- That same opt-in stack remains cross-decoder byte-exact against both `vpxdec` and `ffmpeg` on the 8-frame gate, so the shortcut is a performance/quality tradeoff problem rather than a bitstream validity problem.
- Disabling the existing S2/3D path with `RVP9_3D=0` worsens the real-content quality gate to mean gap `+4.25 dB` (default is `+2.36 dB`). S2/3D is already carrying default quality and is not an unused recovery lever.

## Quality residual decomposition closure

- Components accounted for by prior measurement: entropy adaptation/update is faithful, motion search is ahead of libvpx cpu7, rect partitions are a favorable divergence, dead-zone quantization is ahead/faithful, loop-filter and RC calibration fixes are already in the baseline. The remaining `+2.36 dB` Foreman gap is the emergent high-Q RT picker/motion-field micro-decision trunk, not a bounded single knob.

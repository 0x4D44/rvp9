### 16:30 — Phase 4 Verdict: ALREADY OPTIMAL

Disassembly audit confirms:
- Bit-decision is **fully branchless** (CMOV): `cmp; setae; cmovbl; cmovaeq; sub`
- Renormalization uses `lzcntl` (1-cycle, LZCNT) + `shlxl`/`shlxq` (BMI2)
- Fill fast-path inlined into `read()` with `movbeq` + shifts
- `read()` itself is NOT inlined into callers (93 call sites — LLVM chose not to inline)

**Strategy A: 0% headroom.** Already branchless.
**Strategy B: Marginal.** Tree specialization helps <2% whole-frame.
**Strategy C: Risky.** R.15 precedent (23% regression from over-inlining).

**DECISION: Phase 4 de-prioritized.** Path to 2x is entirely structural:
- Phase 1: eliminate merge (-12.8%) — implementation in progress
- Phase 2: eliminate grid stitch (-6.8%)
- Phase 3: row-parallel loop filter (-35.5%)

Combined savings: ~55% of frame time → projected 2.7x ratio. May need
additional micro-optimizations after Phase 3 to reach exactly 2x, but
the structural work is the dominant lever.

### 18:45 — Phase 3 FAILED: Design Flaw

**Result:** The per-SB-row wavefront approach REGRESSED performance.

| Fixture | Phase 2 p50 | Phase 3 p50 | Change |
|---------|-------------|-------------|--------|
| tile_1x4 t=4 | 8,172 µs | 11,085 µs | +35.6% REGRESSION |
| testsrc_1080p60 t=4 | 4,411 µs | 5,090 µs | +15.4% REGRESSION |
| testsrc_1080p30 t=4 | 5,126 µs | 5,027 µs | -1.9% (noise) |

**Root cause:** The per-SB-row dependency chain (row R+1 waits for row R)
makes the LF inherently sequential. Each row depends on the immediately
preceding row, creating a strict serial chain regardless of worker count.
The HLD's timing diagram was incorrect — it assumed rows could overlap,
but the dependency prevents it. Net: serial execution + atomic/spin/scope
overhead = regression.

**Design error:** The fundamental issue is that horizontal LF reads 8
pixels into the previous SB row's already-filtered pixels. This creates
a strict ordering constraint that prevents row-level parallelism.

**Correct approaches (for future work):**
1. Two-pass LF: separate vertical (parallelizable) from horizontal (serial)
2. Pipeline LF with next-frame decode (libvpx approach)
3. Column-parallel within each row

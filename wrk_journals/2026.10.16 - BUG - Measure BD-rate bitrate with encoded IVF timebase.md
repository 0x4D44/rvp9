# Measure BD-rate bitrate with encoded IVF timebase — KIL-00116

The queue selected KIL-00116. The benchmark passes `--fps` to both encoders but computes both measured bitrates from the source Y4M header, falling back to 30 fps if that source-header lookup fails. A source declaring 50 fps and an encode at 30 fps therefore uses the wrong clip duration for its reported RD points.

The correction takes the timebase from each encoded IVF file through the existing container reader. This measures the actual output rate and also respects role-specific encoder arguments that override the common FPS option. It removes the source-header FPS lookup. Invalid or absent IVF timing cannot supply a meaningful duration and must produce a measurement error rather than an invented fallback. The existing file-size numerator, frame-count semantics, command construction, BD-rate math, and CSV schema stay in scope as compatibility constraints.

The actual-CLI fixture uses an input declaring 50 fps and synthetic encoder/decoder tools that produce known IVF sizes, one valid container packet per output, and four distinct PSNR levels so the BD-rate sweep completes. The reporting regression checks stdout and every CSV RD point for common 30/1 and fractional 30000/1001 rates, then separate role overrides at 24/1 and 60/1. Expected bitrates come from explicit scenario rates and file lengths, independently of the production helper. A second regression requires failure, a contextual error, and no CSV for zero IVF timebase components.

# Require real tile-profiling evidence — KIL-00110

The tile profiler could exit successfully with zero runs or no timed samples, and its CPU calibration checked the bench feature even when users enabled the documented decoder feature directly. It counted decoded frames as CSV evidence although only parallel tile decoding emits profiling rows. Sink failures were ignored.

The driver rejects zero or malformed numeric arguments and unsupported instrumentation before creating output. Decoder-owned capability queries resolve the effective dependency feature and architecture. A process-wide status counts only fully written rows after a successful header and latches open/header/row/mutex failure. The driver measures row deltas around each decode, excludes warmup from timed counts, and requires progress across a full post-warmup fixture pass. Empty fixtures, serial-only decoding and CSV failures cannot claim success. The summary explicitly counts timed rows; the CSV continues to retain warmup rows. No new dependency, schema change or codec behavior change is intended.

A read-only Sol review found that the first partly timed fixture pass must not be treated as a full no-progress pass. The corrected guard permits replay when warmup consumed that pass's only profiling row. A tiled-keyframe plus show-existing fixture exercises exactly that case. The reviewer confirmed the correction and found no remaining concrete issue in scope.

## Observed regression evidence

The worker ran new tests against the original driver before production edits: the empty-fixture unit assertion failed on `Ok((0, 0.0))`; the initial four process tests failed on zero runs, zero minimum, invalid numeric fallback and the unsupported diagnostic. These were assertion failures, not compilation failures.

Root then observed each semantic reversal fail its focused assertion, restoring the source after each:

- Restore rejection of a partially timed pass: mixed tiled/show-existing warmup replay test fails on the process-success assertion.
- Count every decoded frame as one row: serial-only fixture incorrectly succeeds; the process test catches it.
- Ignore the latched output failure: the CSV-open test catches the missing output-failure diagnostic.
- Return success for an empty fixture: the process test catches successful exit with no evidence.
- Allow writes after a partial header/row failure: the injected short-writer test catches bytes written after the failure latch.

Positive-control calibration was separate: requesting three timed rows instead of two while retaining the expected four-row summary failed on the summary assertion. Restoring the input returned it to green. This calibration is not claimed as a production-defect reversal.

## Focused validation

Using task-local TMPDIR and closed stdin, the bin's two unit tests and nine process tests pass in five configurations: native ARM default, native ARM decoder feature, x86_64 default, x86_64 decoder feature, and x86_64 bench feature. x86 builds use `RUSTFLAGS='-C target-cpu=x86-64'` and run under Rosetta. Supported-only process tests return early in unsupported configurations; the unsupported-instrumentation test executes there. The two supported x86 configurations execute the actual positive, serial, open-failure and mixed-replay oracles.

The positive two-tile fixture replays across two runs with three warmup and two timed rows per run: ten emitted CSV rows plus one header, four timed rows in the summary, positive finite MHz and two tiles in every row. The mixed fixture emits one warmup and one timed row, plus header. The decoder's short-writer test passes for no capacity, partial header, partial row and complete writes, including sticky failure and successful subsequent rows.

Scoped native and supported-x86 Clippy pass with `-D warnings`; rustfmt and `git diff --check` pass. Initial x86 Clippy found a collapsible condition in the new sink handling; the final condition is flattened without suppressing a lint. Final feature runtime checks were repeated after that change.

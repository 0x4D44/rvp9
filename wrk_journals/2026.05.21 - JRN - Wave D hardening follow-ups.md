# Wave D — Hardening Follow-ups

Sequential drive through the three highest-leverage unblocked
follow-ups filed at Wave C close-out. Externally-gated work (G7.1,
G8.1, G6.1 — all need `vpxenc`) is deferred until a binary is
available. G9.1/G9.2 are blocked on Stage 4a landing.

## Sub-sequencing

1. **G4.3.1** — `intra_predict` dispatch threading. Smallest piece;
   validates the SimdDispatch pattern survived Wave B/C merges and
   wires the already-written `dc_predictor_4x4` AVX2 kernel into
   production.
2. **G5.1** — real parallel tile dispatch. Converts the tautological
   N=1==N=2 oracle into a real correctness check. Three
   sub-deliverables: disjoint plane views, `scope.submit`,
   per-worker FrameCounts merge.
3. **G4.2-full + G4.3a** — bulk AVX2 kernel rollout. Inverse
   transforms + ADST hybrids. Reviewer pipeline carries this on
   bit-exact oracles.

Concurrent encoder activity is hot on `crates/rvp9-core/src/transforms/`
(forward.rs, mod.rs) — none of the three Wave D tracks overlap
that surface (decoder intra_predict, decoder tile_threading,
decoder-side inverse-transform AVX2 dispatch). Drive in parallel.

## Acceptance criteria (per gap)

- G4.3.1: 201/0/0/0/201 preserved; dispatch-aware test exercises
  the AVX2 dc_predictor_4x4 path; per-fn sentinel script clean.

### G5.1 — DONE (`73f4668`)

Squash-merged onto current main (which gained 5 RC commits + my own
G4.3.1 during this session — merge was clean, no conflicts).
7 files / +1138 / -89.

Architectural decision: **per-tile fresh Yv12Buffer**, NOT
column-slicing. Each worker decodes into its own scratch buffer,
then post-scope `merge_tile_columns_from()` copies each tile's
region back into the main yv12. ZERO new unsafe — sidesteps the
lifetime/aliasing problem that column-slicing would face.

Memory cost: ~3MB/tile/frame at 1080p. At 1080p60 × 8 tiles ≈
1.44 GB/s alloc + 1.44 GB/s memcpy (~3-6% of DRAM bandwidth).
Reviewer call: **ship-with-note, not ship-blocking**. G5.2
follow-up (arena pool) tracked.

Activation gate: `log2_tile_rows == 0 && buffers.len() > 1 &&
num_threads > 1`. tile_rows > 1 still falls back to inline (G5.3
followup). All conformance vectors are tile_rows=1.

Proof of non-tautology: `RVP9_G5_1_PARALLEL_JOBS` atomic counter
shows 52-54 parallel jobs across 10 frames of tile_1x2 at N=2;
test `multi_tile_dispatch_uses_worker_pool` asserts
`delta >= 2 * n_frames`. determinism_n1_eq_n2 asserts byte-identical
across ALL 201 vectors.

FrameCounts merge: additive `add()` on 5 structs + 4 new tests
(identity / associativity / bit-exact-vs-explicit-sum).

Pipeline: 1 implementer + 1 reviewer. APPROVE-WITH-NITS, all NITs
addressed pre-merge (rebase onto fresh main was clean).

Lessons captured:

1. **Scope reduction is honest engineering** (continued lesson from
   Wave B/C). G5.1 shipped tile_rows=1-only with explicit G5.2/G5.3
   followups. G4.2/G4.3a shipped 1 AVX2 kernel + 2 scalar-only
   slots vs the "full rollout" framing — and that's the right call
   for one agent-round.

2. **Per-tile fresh buffer** (G5.1) — choosing the high-allocation
   path over column-slicing was the right call: zero unsafe, fully
   reviewable disjointness, ~3-6% DRAM bandwidth cost. Arena pool
   is a clean follow-up.

3. **AVX2 finisher-only convention** is acceptable as a project-
   wide pattern AS LONG AS it's documented as a stepping-stone.
   Wave E owes a libvpx-parity full-1D vectorisation.

4. **Worktree isolation worked beautifully**. Three concurrent
   encoder agents committed 6 RC.* commits during Wave D and the
   isolation pattern absorbed them without a single conflict on
   any of my three squash-merges.

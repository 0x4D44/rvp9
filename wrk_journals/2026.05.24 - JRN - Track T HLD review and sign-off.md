## Lead review and sign-off

**T-1 (HBD Profile-2): SIGN OFF.**
Honest multi-week scope. First-slice deliverable is 440 LOC of scaffolding
that *deliberately does not enable HBD decode* — it builds: (a) HBD quant
tables (`dc_qlookup_10`, `ac_qlookup_10`, plus 12-bit siblings), (b)
`dc_quant`/`ac_quant` taking `BitDepth`, (c) `highbd_wraplow` +
`highbd_clip_pixel_add` helpers, (d) ONE scalar `highbd_idct4x4_16_add`
kernel + differential test against the 8-bit oracle via input-downshift,
(e) `SimdDispatch::highbd_idct4x4_add` slot stub, (f) explicit bit-depth
gate at `decode_frame`. Conformance count unchanged (201/201). The slice's
value is making phase 1 (intra path) and phase 2 (full inverse-transform)
mechanically bisectable — exactly the right framing for a 4500-LOC project.

**T-2 (Profile-1 corpus): SIGN OFF.**
Headline finding: the official upstream Profile-1 corpus is only 3 vectors
(`vp91-2-04-yuv{422,440,444}.webm`), and they are all already in the tree.
Real plan is 12 (stretch 16) self-encoded vectors via
`vpxenc --profile=1 {--i444|--i422|--i440}` across the multi-tile,
frame-parallel, and intra-only feature axes. Wave-O triangulated `vpxdec ∧
ffmpeg` oracle is already wired and is the structural defense against a
bug-encoded vector being adopted. Budget: 1-2 Wave-P-class real rvp9 bugs
may surface (foreman_c440 precedent); each one fixed and journaled.
Per-format triples committed to avoid cascade failure.

**T-3 (Bitreader Phase 2): SIGN OFF — with the agent's revised scope.**
The agent's analysis honestly contradicts the brief's "30-50% expected"
headline. Concrete findings:
- BLSR clears the lowest set bit — VP9's renorm has no "lowest set bit"
  semantic; wrong tool.
- PEXT is microcoded ~18 cycles on Zen 1-3 — using it is a portability
  regression.
- SHLX (BMI2 variable-shift) is already used implicitly via
  `target-cpu=native`.
- Inline asm is genuinely 2-3 weeks and the brief acknowledged that.

Agent's recommended first slice: **measurement, not behavior change**.
Add `caps.bmi2` (additive, no behavior change), add a `bool_reader`
microbench to `dsp-microbench`, baseline ns/call. The slice's value is
the data, not a perf number. The lead agrees: shipping a measurement
slice and explicitly declaring "the brief's headline was speculative,
here is the calibrated number" is more honest than shipping a likely-
noise BMI2 path.

**T-4 (i16-lane IDCT): SIGN OFF.**
Concrete and tractable. First-slice port: `vpx_idct16x16_256_add_sse2`
(libvpx `inv_txfm_sse2.c:403-431`). ~480 LOC kernel + ~250 LOC tests =
~730 LOC. Reuses 5 helpers from Track-S Task A's `idct8x8_12_sse2.rs`
(`pair_set_epi16`, `idct_madd_round_shift_sse2`,
`idct_calc_wraplow_sse2`, `butterfly`, `load_input_data{4,8}`); new
helpers are `transpose_16bit_8x8`, `idct16_8col`, `recon_and_store_16`.
Per-helper proptest (i12 envelope per Task A precedent) + outer
differential vs `idct16x16_add_avx2` + 201/201 conformance.

Wired as the non-AVX2-but-SSE2 arm initially (conservative); Slice 1.5
flips the AVX2 arm to the new SSE2 i16 kernel and retires the i32-lane
`idct16x16_avx2.rs` if bench is positive.

Honest bench expectation: kernel-local 15-25% (i16 vs i32 lanes); fixture
level 2-3% which is below the 13-21% noise floor at n=5. Microbench is
the secondary gate; conformance is primary.

**T-5 (Tile dispatch profiling): SIGN OFF.**
Instrumentation-only slice, no fix scoped. `profile-tiles` cargo feature
(default off, zero cost when off — proven by `#[cfg(feature)]` at parse
time). `core::arch::x86_64::_rdtsc()` wrapper (~10 ns/call vs ms-scale
phases = <0.1% perturbation). 10 phases timed: setup, submit, wait,
tile_lock_in, tile_decode, tile_lock_out, join, merge, grid_stitch,
loopfilter, border. Per-frame CSV emission gated on env var.

Ranked hypothesis tree (the analytical contribution that justifies this
work):

- **H1 HIGH:** serial work outside the parallel region dominates
  (single-threaded loopfilter, merge memcpy, grid stitch, border extend).
  Amdahl math at 35% serial = 1.97× theoretical 4-thread speedup —
  matches observed 1.79× uncannily well.
- **H3 MEDIUM-HIGH:** per-frame allocator churn on un-pooled per-tile
  counts/seg/mv slabs (~6 MiB/frame).
- **H7/H8 MEDIUM:** `build_frame_mi_grid` and `extend_frame_borders`
  contribute to the serial fraction (H1).
- **H2/H5/H6 LOW:** mutex overhead, imbalance, dispatch latency.

Action plan from findings is a decision tree (§7); each branch points
at a libvpx-known fix (pipelined LF for H1, scoped UnsafeCell for H2,
pooled allocs for H3, etc.) but the fix is its own follow-up HLD.

## Decision: dispatch implementation agents in parallel via worktrees

Five agents, five worktrees. Each agent:
1. Reads its HLD.
2. Implements the first-slice deliverable.
3. Runs `/code-reviewer` on the diff (or performs a structured self-review
   covering: bit-exact safety, conformance impact, unsafe correctness,
   feature-flag hygiene, test coverage, comment quality).
4. Applies feedback via `/code-review-apply-feedback`.
5. Runs the bit-exact gates: conformance 201/201, profile1_decode,
   frame_parallel_regression, tile_threading, rvp9-core --lib.
6. Reports back with the worktree branch + commit SHA + summary.

The lead then merges each worktree's branch into main sequentially,
running the bit-exact gates after each merge. Conflicts resolved
manually with the agent's commit as the source of truth.

Bench gates (T-2, T-4) run on the merged main, not the worktree.

# Fail requested E1 libvpx legs — KIL-00089

E1 represented libvpx execution and I/O failures as `None`, the same representation used when the user deliberately omitted `--vpxenc`. The renderer then emitted `n/a` and the executable wrote a successful partial comparison report.

The correction uses `Result<Aggregate, String>` for the libvpx leg and `Result<Option<Aggregate>, String>` for requested-or-omitted execution. Only omission returns `Ok(None)`. Temporary setup, raw-plane writes, stderr setup/read, child execution and output-IVF reads attach stage/path/rate context to errors. Explicit missing paths now fail at spawn. Main propagates a requested-leg error to exit 1 before writing the report. The extracted E1 run boundary retains the original four production target rates. Existing child timeout, kill/reap, stdin closure and temporary-directory isolation remain in force. Codec/statistics behavior and the separate IVF-input mode are outside this change.

Observed assertion-red evidence:

- With the original failure-to-absence behavior, the nonzero-exit, timeout, missing-explicit-path and missing-output-IVF tests each observed an absent leg; the one-target report test returned success after child failure.
- On the final Result API, mutating `Some(path)` to `Ok(run_libvpx(...).ok())` made the report sentinel equality assertion fail: the generated report replaced `existing report sentinel`. The mutation was manually restored.
- Returning a fake aggregate for omission failed `result.is_none()`, then was restored.
- Rejecting the valid empty-IVF positive fixture failed `result.is_ok()`, then was restored. This is fixture calibration, not proof of the original defect.

All 21 E1 bin tests passed, including the existing bounded runner test, after restoring the final implementation. The lead independently reran all 21. Fake executable tests ran natively on macOS under Unix guards; the omission contract remains portable. A built-bin smoke with one synthetic 256×256 Y4M frame and a failing fake encoder exited 1 with path, target rate and child stderr, preserving the report sentinel. Scoped `cargo clippy -p rvp9-harness --bin e1_block_stats -- -D warnings`, file rustfmt and diff checks passed. A first green attempt exposed an over-specific IVF error assertion that expected the executable path instead of the actual failed IVF path; correcting the assertion retained stage, path and rate checks. No real libvpx, Windows runtime or external corpus was used. The positive child fixture contains a valid empty IVF and tests transport/result handling, not codec parity. Tests used the task's absolute `.scratch` as `TMPDIR`. A hook refused removal of the empty scratch directory; it was left for normal integration cleanup.

The preselected final smoke after catch-up is `cargo test -p rvp9-harness --bin e1_block_stats tests::explicit_leg_failure_does_not_publish_a_successful_report -- --exact`, bounded to 60 seconds.

### S4.13 — recursive partition writer (`2fdf76c`)

Dispatched to agent. The writer's v1 had pinned every 64×64 SB to
`PARTITION_NONE`; this commit replaces the inner SB loop with a fully
recursive `write_partition_tree` mirroring the decoder's
`decode_partition` 1:1.

New module pieces:
- `infer_partition(grid, ..., bsize) -> Result<PartitionType, _>` —
  inspects the leaf at the parent's top-left cell, matches against
  `bsize`, `subsize(bsize, HORZ)`, `subsize(bsize, VERT)`; falls
  through to `SPLIT` if the parent supports it. BLOCK_8x8 parents are
  scope-pinned to `NONE` (sub-8 partitioning still out of scope).
- `write_partition(bw, ctx, partition)` — emits the canonical 4-way
  tree-walk bit-sequence (`0` / `1,0` / `1,1,0` / `1,1,1`) against
  `VP9_KF_PARTITION_PROBS[ctx]`, exactly the inverse of
  `read_partition`.
- Recursive `write_partition_tree` — bsl/ctx/num_8x8/hbs match the
  decoder; switch on partition into one (NONE) / two (HORZ/VERT)
  `write_block_intra_keyframe` calls or four recursive calls (SPLIT);
  applies the libvpx partition-context-update gate.
- `write_block_intra_keyframe` widened to take a `leaf_bsize`
  parameter; neighbour-grid splat uses `leaf_bsize.n_8x8_wide()` /
  `.n_8x8_high()`.
- New `ModesWriterError::InconsistentPartitionTree {parent_bsize,
  leaf_bsize}` for malformed input grids.

11 new tests + 1 new whole-loop integration test
(`s4_13_round_trip_partition_split_64x64_through_decoder` —
encodes a 64×64 keyframe with SPLIT into 4× 32×32 leaves, decodes it
back through `Decoder::decode_frame`, asserts recovered mi_grid).
**Critical:** the all-NONE path produces byte-identical output, so
the two existing regression-guard tests
(`write_tile_intra_keyframe_round_trip_2x2_sb_via_per_symbol_readers`
and `s4_10_round_trip_synthetic_64x64_keyframe_through_decoder`)
stayed green.

### S4.14 — write_tx_size (`76be094`)

Direct supervisor write. Adds `pub fn write_tx_size` next to
`read_tx_size` in `mode_info.rs`. Selected path emits 1..3 bits via
the tree walk against `tx_probs[max_tx_size][ctx]`:

| tx_size  | max=Tx8x8 | max=Tx16x16 | max=Tx32x32 |
|----------|-----------|-------------|-------------|
| Tx4x4    | 0         | 0           | 0           |
| Tx8x8    | 1         | 1, 0        | 1, 0        |
| Tx16x16  | —         | 1, 1        | 1, 1, 0     |
| Tx32x32  | —         | —           | 1, 1, 1     |

sentinel cases.

### S4.15 — encode_coefs (token writer) (`0a080f5`)

The big one. Dispatched to agent with the existing `decode_coefs`
test patterns as the bit-sequence ground truth (those tests at
`detokenize.rs:691-1110` literally show what the writer needs to
emit per token).

New `pub fn encode_coefs` in `entropy/detokenize.rs` (+618 ll). The
agent flagged the load-bearing detail: the outer-NOT-EOB +
inner-ZERO-run loop structure is the only one the decoder parses
correctly. First-cut mis-emitted one NOT-EOB per zero; restructured
to one NOT-EOB per outer iteration + inner ZERO run (until non-zero)
+ value tree + sign + terminal EOB. Three tests caught this on first
run.

Coverage: 16 round-trip tests across every token category
(ZERO/ONE/TWO/THREE/FOUR/CAT1..CAT6), boundary values (5,6 / 7..10 /
11,18 / 19,34 / 35,66 / 67,16450), zero-runs, block-full-to-seg-eob
(no terminal EOB bit), 100-iter random fuzz, all 4 TxSize values.
For Tx32x32 the test helper uses `dequant=(2,2)` so `(val*2)>>1`
cancels the `dq_shift=1` right-shift cleanly.

**Encoder is now wire-complete for non-skip residual.** The remaining
gap is integration into the encoder API (the writers exist; the
mode-decision driver doesn't yet feed them).

### S4.16a — write_mv_component + write_mv (`e3ccdf0`)

MV-difference encoder primitives. Dispatched to agent. New module
pieces in `inter/mv.rs` (+530 ll):
- `pub fn write_mv_component(bw, diff, comp_probs, use_hp)` — mirror
  of `read_mv_component`.
- `pub fn write_mv(bw, cur_mv, ref_mv, allow_hp, nmv_context)` —
  computes `diff = cur_mv - ref_mv`, emits MV_JOINT_TREE then one
  component per non-zero axis.
- Private `mv_class_and_base(mag)` and `write_tree(bw, tree, probs,
  target)` helpers.

The agent caught a real bug in my brief: class 0 covers magnitudes
0..=15 (not 0..=7 as my prose table claimed), and the
`CLASS0_SIZE<<(class+2)` formula only applies for class>=1. Without
the explicit class-0-base=0 guard, `mag in 8..=15` mis-routes to
base=8 (wrong). The agent's `mv_class_and_base_spot_checks` test
locks in the fix.

10 new tests including exhaustive class-0 round-trip (every value in
-7..=-1, 1..=8), one representative per MvClass (Class1..Class10),
±8191 extreme values, all 4 MvJoint variants, 200-iter XorShift64
fuzz.

`use_hp == false` contract: encoder must only be called with
`abs(diff)` even (so composed magnitude has LSB=1). Debug-asserted.

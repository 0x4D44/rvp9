### Key analytical steer handed to the agents
The notes conclude **the bool-coder cursor stays synced** (error does not extend
rightward to the frame edge; the rest of frame 0 is bit-exact). That is decisive:

- If the **token-reading set** differed between rvp9 and libvpx (e.g. rvp9 read
  phantom tokens for invisible bottom cells), the cursor would desync and the
  remainder of the frame would be garbage. It is **not**.
- ⇒ The bug is **not** the iteration/clamp count. It is in the **predictor
  inputs** for bottom-edge intra TX cells (`build_intra_predictors`: neighbour
  availability `have_top/have_left/have_right`, above-right extension, or edge
  pixel fill), and/or the inverse-transform-add for those cells.
- ⇒ A naïve "mirror the inter `max_blocks_{wide,high}` clamp into the intra path"
  is **likely the wrong fix** (it would change the token-set, which already
  matches). Agents must PROVE the root cause with a trace, not assume the clamp.

### Code under suspicion
- `crates/rvp9-decoder/src/tile.rs::reconstruct_intra_planes` (per-cell skip
  `tx_px_{x,y} >= plane_{width,height}_px`, full-extent `plane_bw/bh_4x4`,
  `have_right = (aoff+tx_step) < bw_in_4x4`).
- `crates/rvp9-decoder/src/reconstruct_inter.rs:505–552` (the D.25 per-block
  clamp the inter path uses — reference for "what libvpx does", NOT a template
  to copy blindly).
- `rvp9_core::intra_pred::build_intra_predictors` + `intra_predict` (predictor
  edge sourcing — the most likely true locus).

### Findings (full detail in the HLD)
HLD written: `wrk_docs/2026.06.01 - HLD - SIG2 partial-bottom intra
reconstruction (entropy-context edge clamp).md`.

**ROOT CAUSE (high confidence, libvpx-cited):** rvp9's entropy-context
writeback `set_coef_flags` (`detokenize.rs:323`) lacks libvpx's **frame-edge
clamp** (`vp9_set_contexts`, `vp9_blockd.c:87-122`). For a TX with `eob>0`
crossing the frame's right/bottom edge, libvpx zeroes the beyond-edge
above/left context cells; rvp9 sets them to `1`. An adjacent large TX folds
those corrupted cells into its entropy context → wrong token probs → **per-tile
desync** in the partial-bottom SB row. Entropy-context analog of the D.25 inter
*iteration*-clamp fix.

**Evidence:** worst cell (352,1056) has bit-exact prediction inputs but garbage
residual (oracle≈[113,105,101,103] vs rvp9 [42,0,86,253]) ⇒ wrong tokens, not
wrong reconstruction. Divergence cuts off **exactly** at tile boundaries (0/448/
960/1408) — VP9 tiles have independent bool-coders, so a desync is tile-local.

**Corrected the prior steer:** Entry 0 said "predictor bug, not desync (cursor
stays synced)." That was confounded by per-tile coders — it IS a token desync,
but tile-local. The *conclusion* (not the naive iteration clamp) still holds.

**Ruled out:** (a) per-cell skip / iteration clamp — `y_plane().height()=1080`
(8-aligned, `frame.rs:219`), so the token-cell set already matches libvpx;
(b) partition-tree edge inference + context update — `decode_partition` is
libvpx-faithful.

### Files changed (all decoder-side; no encoder/`mv.rs` touched)
- `crates/rvp9-core/src/coef_ctx.rs` — new `TileCoefCtx::set_coef_flags_clamped`
  (the `vp9_set_contexts` clamp: in-frame cells = `nonzero`, beyond-edge cells
  = 0). `set_coef_flags` now delegates with `above_cells=w4, left_cells=h4`
  (byte-identical for all existing callers, incl. the encoder).

  `above_cells, left_cells` params; writeback `:323` switched to

  `above_cells, left_cells`, threads them into `decode_block_tokens`. 9 in-file

- `crates/rvp9-decoder/src/reconstruct_inter.rs` — inter caller computes
  `above_cells/left_cells` from its existing `max_blocks_{wide,high}` + `aoff/
  loff` (`= (max_blocks_* - off).clamp(0, n)`), passes them in.
- `crates/rvp9-decoder/src/tile.rs` — `reconstruct_intra_planes` gains
  `mi_rows, mi_cols`; computes `max_blocks_{wide,high}` per plane mirroring

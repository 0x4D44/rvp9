## Hypothesis for the regression

The mask-build worker steals one of the 4 worker threads (`num_threads.get() = 4`). For testsrc_1080p30 t=4 the tile decode is fast (~3 ms p50 baseline) and bound by the slowest of 4 tile workers; stealing a thread for ~300-500 µs of mask-build work directly extends the critical path of the slowest tile. Net: mask-build saves the serial 300 µs post-scope but adds more contention than that.

Whereas tile_1x4 t=4 baseline is 6 ms — tile decode is the bottleneck. The mask-build worker finds slack at the tail of slower tiles, so net win.

This is the W2 trap variant: the parallelism isn't always free. The HLD's "one submit per frame avoids the per-row dispatch overhead" is true but doesn't address the thread-stealing cost.

## Suggested next step (for the lead)

If the W7 design is to be revived: explore a **gated-by-fixture-cost** dispatch (e.g. submit the worker only when sb_rows × per-row-mask-build-cost > a threshold that scales with average tile-decode duration). Or, simpler: ship with the kill switch **default-ON-disabled** (Wave 2's pattern after the row-MT regression). The validated code stays landed, opt-in via `RVP9_INTRA_SCOPE_LFM=1` for benchmarking.

No code change for option 2 is mine to make without lead approval — flagging it as a possibility, not a recommendation.

# Correct Parkrun source mapping

Xiph's [Derf collection index](https://media.xiph.org/video/derf/) links the
Parkrun clip to `video/derf/y4m/720p50_parkrun_ter.y4m`. The fetch scripts
requested the obsolete reversed-name path `parkrun_ter_720p50.y4m`, so the
documented corpus setup failed on a 404. Both scripts now map the current
remote filename to the existing local name `parkrun_ter_720p50.y4m`, and the
HLD source note records that distinction.

Validation used registered Deltic scratch directories and stubbed downloads,
so no multi-hundred-megabyte corpus files were fetched. With the original
script, the mock rejected the stale Parkrun URL and the script exited 1 after
the other three mocked clips succeeded. With the fix, the POSIX script
reported four successes and the expected remote/local path pair for each
clip. `pwsh -NoProfile -File scripts/fetch-corpus.ps1 -WhatIf` printed the
updated Parkrun URL. `bash -n scripts/fetch-corpus.sh` and `git diff --check`
passed.

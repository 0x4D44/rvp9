# Validate raw input geometry — KIL-00123

The raw reader checked plane-size arithmetic and file length before the encoder checked its supported dimension and luma-pixel envelope. A geometry representable by `usize` could therefore allocate and read a large frame before eventual `InvalidConfig` rejection.

The correction exposes the existing shared `coded_dimensions_supported` predicate and calls it at the start of `RawFrameReader::open`, ahead of plane-size arithmetic, opening the raw file and reading metadata or frame data. Its nonzero, maximum-dimension and maximum-luma-area rules remain the same rules used by both encoder entry paths. Individual encoding-mode alignment and chroma requirements remain validated by those entry paths.

Both new regressions failed on the original reader: the unit test received a file-opening error, and the CLI test received a partial-frame-length error instead of the geometry diagnostic. Removing only the guard reproduced both assertion failures after final wording changes. With the guard restored, missing-path cases cover both dimension limits, excessive luma area, zero dimensions and arithmetic extremes. Empty files exercise supported envelope boundaries without allocating frame planes. The CLI test also verifies existing IVF and timing CSV outputs survive rejection.

Validation passed: 23 encoder-config tests, 15 encoder CLI unit tests, six raw-input CLI tests, and one ordinary plus one rectangular raw round trip. The lead independently reran the new reader test, all six raw CLI tests and the rectangular round trip. Scoped encoder-library and encoder-CLI Clippy passed with warnings denied; formatting and diff checks passed. Tests used the task's absolute `.scratch` directory as `TMPDIR`. No large-allocation fixture or measured memory-pressure claim is made. The preselected final smoke is `cargo test -p rvp9-cli --test cli_arg_coverage enc_raw_invalid_geometry_precedes_frame_errors_and_preserves_outputs -- --exact` after final catch-up, bounded to 60 seconds.

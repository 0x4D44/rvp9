# RVP9-BUG-KIL-00101 — Reject unsupported lossless configurations

The streaming encoder accepted configurations whose rate controller could
select qindex zero, then silently changed the selected value to one. The codec
path does not implement lossless transforms/quantization, so successful lossy
output did not honor the requested quantizer.

The fix rejects unsupported configurations in the common StreamEncoder
constructor after rate-control validation and before its state allocations:

- CBR, VBR and two-pass VBR require a positive minimum qindex.
- Constrained-quality mode requires either a positive minimum or a positive
  quality floor, since its floor is applied after every rate-control pick.
- Constant-Q mode requires `cq_level >= 9`: its keyframe boost subtracts eight
  and otherwise selects zero even for positive values 1 through 8.

Standalone rate-control qindex-zero behavior remains available as a model. The
streaming configuration documentation describes the codec restriction. The
frame loop reports an unsupported-qindex error if zero still reaches encoding,
rather than silently clamping it. The diagnostic fixed-Q override already
accepts only 1 through 255; zero remains a no-op.

The top-level two-pass driver can perform first-pass work before constructing
the second-pass encoder. This fix does not change that driver's scheduling or
claim earlier rejection there; it validates each StreamEncoder construction.

The new public integration target covers all Q requests 0 through 8 and all
four regulated zero-bound modes. Before the guard, both rejection tests failed
their aggregate assertions, listing every unsupported configuration as accepted.
Its positive-boundary test already passed on the baseline.

The positive test keeps default CBR usable, constructs positive-minimum CBR/VBR/
two-pass VBR, and encodes key plus inter frames for Q9, CQ with a positive floor,
CQ with a positive minimum, and fixed-bound CBR. It checks reported and parsed
wire quantizers and consumes each frame in the decoder. Q9 emits keyframe Q1
and inter Q9; the constrained boundary cases emit Q1 for both. A separate oracle
calibration changed the expected wire Q from one to two and observed the named
wire assertion fail, then restored it. That calibration is distinct from the
constructor regression's fails-before proof.

The rejection helper evaluates both public constructors unconditionally.
Removing the constructor guard with that final helper made both rejection tests
fail again, exercising all 26 constructor calls across the unsupported cases.
The guard was restored and all three integration tests passed.

Existing focused checks passed: 20 rate-control state tests, 13 constructor
rejection tests, and the two-pass completion regression. Formatting, diff check,
and scoped encoder Clippy (`--lib --test w_lossless_config`) passed without
warnings. The selected final smoke is `cargo test -p rvp9-encoder --test
w_lossless_config`, bounded to 60 seconds after final fetch/catch-up.
Independent read-only review found no issues in the final source and test,
combined SHA-256
`6f1bd405e06d6934736f82a1c16d0a65d83df31ba517aaf966aa3fe9cba9022e`.
It verified mode coverage, keyframe subtraction/CQ-floor semantics, default
compatibility, both constructors, wire/decode checks, and observed red/green
evidence. The two-pass driver's first-pass timing remains the stated limitation.

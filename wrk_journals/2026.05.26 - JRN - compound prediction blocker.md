## Step 1 — decoder compound support: **YES (fully implemented)**

The rvp9-decoder can decode a compound-predicted VP9 frame today. The
machinery is complete and byte-exact end-to-end:

1. **Frame-header `reference_mode`** — `read_frame_reference_mode`
   (`crates/rvp9-core/src/bitstream/compressed_header.rs:318`) parses the
   0/1/2-bit field into `ReferenceMode::{Single,Compound,Select}`; the
   matching prob diff-updates land in `read_frame_reference_mode_probs`
   (`compressed_header.rs:342`). Wired into the decoder's compressed-header
   read at `crates/rvp9-decoder/src/lib.rs:2488-2494` (derives
   `comp_fixed_ref`/`comp_var_ref` via `setup_compound_reference_mode`).
2. **Per-block compound ref bits** — `read_ref_frames`
   (`crates/rvp9-core/src/inter/mode_info.rs:591`) handles all three
   reference modes. The compound branch (`mode_info.rs:616-636`) reads the
   `comp_inter` selector (Select mode), then the `comp_ref` bit, and sets
   `ref_frames[idx] = comp_fixed_ref; ref_frames[1-idx] = var`.
3. **Two-MV resolution** — `resolve_parent_mvs`
   (`crates/rvp9-core/src/inter/mode_info.rs:1401`) iterates
   `num_refs = 1 + is_compound`; NEWMV reads two MV residuals, NEAREST/NEAR
   copy two ref-MVs, ZEROMV leaves both zero. Sub-8 path mirrors it
   (`resolve_sub8_bmi`, `mode_info.rs:1469`).
4. **Compound averaging reconstruction** —
   `crates/rvp9-decoder/src/tile.rs:303-474` iterates `1 + is_compound`
   refs; the first writes `dst`, the second runs with
   `is_compound_avg = r > 0` (`tile.rs:409`) so `inter_predictor` averages
   the two predictions. Direct unit test at `tile.rs:1608`
   (`compound_zero_mvs_avg_const_refs_block8x8`): two const refs (0x40,
   0xC0) average to 0x80, asserted byte-exact.

There is even a matching **entropy writer** for compound mode info
(`write_inter_block_mode_info`, `mode_info.rs:932`+, compound branch at
`:1028-1052`) and a frame-header writer (`write_frame_reference_mode`,
`compressed_header.rs:786`). So the *bitstream layer* on both sides is
ready. The blocker is entirely in the encoder's frame-management /
reference-pool layer.

## Step 2 — why the encoder cannot emit compound

### Blocker A — LAST+GOLDEN compound is structurally impossible in VP9

The prompt asks for LAST+GOLDEN compound candidates. VP9 does not encode a
free pair of references for a compound block. It encodes one `comp_ref`
bit that selects between two *variable* references; the *fixed* reference
is implicit. `setup_compound_reference_mode`
(`crates/rvp9-core/src/inter/mode_info.rs:738-760`, libvpx
`vp9_pred_common.c:24-40`) derives the fixed/var split purely from the
per-ref sign-bias table:

- `last == golden` → `comp_fixed = ALTREF`, `comp_var = [LAST, GOLDEN]`
- `last == altref` → `comp_fixed = GOLDEN`, `comp_var = [LAST, ALTREF]`
- else            → `comp_fixed = LAST`,   `comp_var = [GOLDEN, ALTREF]`

Every compound block **must** contain `comp_fixed_ref`
(`read_ref_frames`, `mode_info.rs:633`:
`ref_frames[idx] = params.comp_fixed_ref`). A compound block whose two refs
are exactly {LAST, GOLDEN} only arises in the first branch — where the
fixed ref is ALTREF, i.e. the pair is {ALTREF, LAST} or {ALTREF, GOLDEN},
never {LAST, GOLDEN}. **There is no sign-bias configuration that yields a
LAST+GOLDEN-only compound block.** Compound in VP9 is fundamentally a
"bracket the current frame with a past and a future reference" tool, and
the future reference is ALTREF.

So any real compound requires a distinct **ALTREF** reference with a sign
bias opposite to LAST/GOLDEN.

### Blocker B — the encoder has no usable ALTREF, and never sets sign bias

1. **Sign bias is hardcoded all-false.** Every frame-header / inter-params
   construction site sets `ref_frame_sign_biases: [false; MAX_INTER_REFS]`
   and `sign_bias_from_header(&[false, false, false])`:
   `crates/rvp9-encoder/src/frame_loop.rs:2959`, `:3091`, `:4281`;
   `crates/rvp9-encoder/src/lib.rs:799`, and the per-frame
   `compound_allowed: false` at `frame_loop.rs:2738`, `:2935` and
   `lib.rs:453,605,771`. With all biases equal,
   `vp9_compound_reference_allowed`
   (`crates/rvp9-encoder/src/compound.rs:121`, libvpx
   `vp9_pred_common.c:16-22`) returns **false** → compound is illegal for
   the frame. Nothing in the encoder ever flips a sign bias.

2. **ALTREF is a stub, not a real reference.** Even with
   `enable_alt_ref` (default `false` in every config including all 4
   cross-decoder-gate tests, `tests/cross_decoder_gate.rs:282`),
   `encode_altref_internal` (`frame_loop.rs:2143`) emits an all-skip
   ZEROMV-against-LAST frame whose slot-2 reconstruction merely *mirrors
   LAST* (`frame_loop.rs:2154-2160`). There is no temporal filter applied,
   so the ALTREF content is byte-identical to LAST — a compound average of
   LAST and an ALTREF-that-equals-LAST is just LAST, providing zero coding
   benefit and no test signal.

3. **The picker is explicitly LAST/GOLDEN-only by design.** The W8 ALTREF
   comment states it outright (`frame_loop.rs:2137-2142`):
   *"No picker iterates against slot 2 today (the per-leaf
   `picked_ref_frame` ∈ {LAST, GOLDEN})... The cross-decoder gate stays
   byte-exact because every inter packet's `ref_frame_indices[i]` still
   resolves to slot 0 (LAST)."*

4. **The emit path carries only one ref + one MV.** `InterPartitionLeafDesc`
   (`crates/rvp9-encoder/src/lib.rs:2249`) and
   `splat_inter_leaf_into_mi_grid` (`lib.rs:2191`) hardcode
   `ref_frames: [picked_ref_frame, RefFrame::NoRefFrame]` and
   `mvs: [picked_mv, Mv::ZERO]` (`lib.rs:2223-2224`). There is no field for
   a second ref or second MV; the simulator's predictor
   (`build_inter_pred_plane_unscaled`, `lib.rs:4913`) passes
   `is_compound_avg = false` (`lib.rs:4972`) and convolves a single ref.

### What the unconsumed `compound.rs` module actually is

`crates/rvp9-encoder/src/compound.rs` (declared `pub mod compound` at
`lib.rs:76`) is the per-frame compound *decision* layer, not a predictor:
the sign-bias gate (`vp9_compound_reference_allowed`,
`allow_comp_inter_inter`), the `ReferenceMode` enum + adaptive
`PredictionTypeThreshes` picker (`pick_reference_mode`,
`update_prediction_type_threshes`), the `SingleNewmvCache`, and the ALTREF
sign-bias gate (`sign_bias_opposite_altref`). It is fully unit-tested
(W3.6-W3.8) but unconsumed precisely because the producer it would feed —
a frame that emits compound blocks — cannot exist until ALTREF lands. It
contains **no** compound averaging predictor and **no** RDO compound-mode
evaluation; those would be net-new.

~740-LOC ALTREF prerequisite — before a single compound bit is legal. The
joint-MV-search deferral the prompt anticipated (~250 LOC) is *not* the
binding constraint; the ALTREF reference is.

# 2026.05.27 — JRN — ML partition pruning landed (A21)

## Path: LANDED (scoped to the highest-value pruner)

Wired libvpx's ML **partition-search breakout** pruner
(`ml_predict_breakout`) into the A4 recursive RD partition descent,
behind the speed feature `sf.rd_ml_partition.search_breakout`. The
pruner activates at the libvpx-faithful speed(s) (Good preset, speed
0/1, below 1080p) and uses real features + the real `nn_predict`-backed
linear model. No synthetic shortcut.

## What was wired

The A21 `ml_partition` module exposes three pruners:

| pruner | what it gates | fit to the A4 descent |
|--------|---------------|------------------------|
| `ml_predict_breakout` | skip SPLIT after a winning NONE (`do_split = 0`) | **WIRED** — clean fit |
| `ml_pruning_partition` (search_early_termination) | skip SPLIT+rect, speed-0-only ≥480p | follow-up |
| `ml_prune_rect_partition` | mask HORZ/VERT arms | N/A — descent is square-only |

The A4 descent is **square NONE/SPLIT only** (rect HORZ/VERT is a
documented A4 follow-up), so `ml_prune_rect_partition` has nothing to
gate today. `ml_pruning_partition` (the early-termination model) is
gated only at speed 0 ≥480p in libvpx and is deferred as a follow-up.

`ml_predict_breakout` was the highest-value, cleanest fit: it gates
exactly the square `do_split` decision the descent already makes, its
features are all available at the descent's NONE-evaluation point, and
its decision is a clean boolean — mirroring libvpx
`vp9_encodeframe.c:4161-4168` (`if (ml_predict_breakout(...)) {
do_split = 0; do_rect = 0; }`).

## The descent hook

- `crates/rvp9-core/src/mode_decision/nonrd_partition.rs` — added a
  `BreakoutPruner` trait + `NoBreakout` default + closure adapter, and
  `nonrd_pick_partition_with_breakout(...)`. In `descend()`, after a
  NONE pick wins the running best, the pruner is consulted; a `true`
  vote sets `do_split = false`, suppressing that block's SPLIT
  recursion (libvpx `vp9_encodeframe.c:4140-4168`, gate at `:4004`).
  The old `nonrd_pick_partition` delegates with `NoBreakout` (pre-A21
  behaviour byte-for-byte).
- `crates/rvp9-encoder/src/lib.rs:3310-3409` — builds the breakout
  pruner closure when `sf.rd_ml_partition.search_breakout &&
  base_qindex >= 100` (libvpx `:4163`). Real features:
  - source-block Y variance vs. zeros `>> num_pels_log2`
    (libvpx `:3301-3304`),
  - the NONE pick's rate (incl. `partition_cost[NONE]`) and dist
    (libvpx `:4136`, `:4165`, `:3308-3309`),
  - `x->rdmult` = `f3_rd_mult`, `vp9_ac_quant(base_qindex)` (`:3285`),
  - q-context-indexed `search_breakout_thresh` (`:3259`, `:3328`).
  Then calls the real `crate::ml_partition::ml_predict_breakout`.
- `crates/rvp9-core/src/mode_decision/speed_features.rs` — added the
  `RdMlPartition { search_breakout, search_breakout_thresh[3] }` SF
  struct, populated in `apply_good` per libvpx
  `vp9_speed_features.c:81-180` (on at speed 0/1 below 1080p, off at
  speed 3+ and in the RT preset / best-quality defaults).
- `crates/rvp9-encoder/src/rdo/inter_dispatch.rs` — added the
  `ML_PARTITION_BREAKOUT_FIRED` anti-G3 diagnostic counter.

## Gate-speed note (read carefully)

The sacred cross_decoder_gate runs at **speed 7 / Realtime**, where
libvpx leaves `sf.rd_ml_partition.search_breakout = 0` — so the ML
pruner does NOT fire on the gate's default stream. This is libvpx-
faithful, not a bug. The A21 PROOF therefore runs at **speed 1 / Good**
(below 1080p) to exercise the pruner, and re-uses the gate's vpxdec
byte-exact oracle on that stream.

# JRN — Wave 4 RDO mode-decision integration assessment

**Date:** 2026-05-26
**Author:** Arthur (paired)
**Decision:** **DEFERRED.** The Wave 4 RDO driver cannot be wired into
`StreamEncoder::encode_frame`'s hot path as a real, non-regressing
speed≤4 mode-decision path in ≤400 LOC of glue. The blocker is *not* the
dispatch plumbing or the coef-source bridge — it is that the RDO
driver's core RD evaluator is a **synthetic model estimate**, not a
real-pixel RD. Wiring it as-is would replace the fully-plumbed RT picker
with a *worse* decision driven by fake RD numbers — a regression
dressed as an integration, and exactly the kind of cheat the audit
brief forbids.

No code changes were made. Baseline preserved: `cargo test -p
rvp9-encoder --lib -- --test-threads=1` = **411 passed** (confirmed
2026-05-26).

## The architecture (what would actually have to happen)

The encoder's inter path is two decoupled stages:

1. **Pick** — `pick_inter_mode` (the RT picker, in
   `crates/rvp9-core/src/mode_decision/inter.rs:1005`) chooses per leaf
   only `(best_mode, best_mv, picked_ref_frame, picked_interp_filter,
   picked_intra_mode, skip-hint)`. These are written into
   `sb_partitions[sb_idx][leaf_idx]` (`lib.rs:4038-4050`).

2. **Emit** — a shared ~370-LOC per-plane TX walk (`lib.rs:4082-4450`)
   reads those picked fields and does the real MC + residual + fdct +
   forward-quant + IT-add, writing into `coef_source` (the
   `VecBackedInterCoefSource` the packet builder consumes) and
   `recon_yuv_out`. **This stage produces the decodable bitstream and is
   independent of which picker chose the fields.**

So the *coef-source bridge is free*: an RDO picker that emits the same
`(mode, mv, ref, filter)` tuple feeds the existing emission stage with
zero new coef machinery. That part really is ~50 LOC of dispatch. The
problem is upstream.

## Why the RDO driver's RD is fake

`handle_inter_mode_single_ref` (`handle_inter.rs:306-460`) is the inner
cost function `pick_inter_mode_sb` calls (via the `HandleInterRunner`
closure) for every `(mode, ref)` candidate. Its documented standalone
deviations (`handle_inter.rs:30-41`, `:336-345`, `:480-483`) are
load-bearing:

- **It does not apply the interp filter.** The per-filter inner loop
  uses `filter_quality_bias(filter, mode)` — a synthetic constant — in
  place of re-running the 8-tap kernel and re-measuring SSE
  (`handle_inter.rs:345`, `:363`). The three filters are scored against
  a fabricated bias, not real pixels.
- **Its RD is a SAD model, not a transform RD.**
  `build_inter_pred_model_rd_earlyterm` (`handle_inter.rs:119`) is a
  `vp9_model_rd_from_var_lapndz`-style integer approximation, *not* a
  forward transform + quant + coef-cost. `block_yrd.rs::super_block_yrd`
  (the real walker) exists but is **never called** from `handle_inter`.
- **Y-only.** Chroma RD (libvpx `vp9_rdopt.c:3193-3204`) is stubbed
  `rate_uv = 0` (`handle_inter.rs:30-33`).
- **The mode-rate cost is a placeholder.**
  `pick_inter_sb.rs:340-347` (`libvpx_mode_rate_placeholder`) hard-codes
  `{NEAREST:400, NEAR:500, ZERO:300, NEW:1200}` instead of the real
  `inter_mode_costs(frame_context)` table the RT path already builds
  (`lib.rs:2465`).

Net: feeding `pick_inter_mode_sb` real plane views would still yield
mode decisions ranked by `filter_quality_bias` + a SAD model + a
hard-coded rate table. The RT `pick_inter_mode` it would replace already
does real subpel SSE, real chroma RD, real adapted cost tables, and the
P13/P15/P18/P20 content gates. Swapping in the RDO driver as-built is a
strict downgrade of decision quality.

## What is actually reusable

- `single_motion_search` (`single_mv_search.rs:230`) is **real** — a
  genuine diamond + subpel search returning a real MV + `rate_mv`. Usable.
- `super_block_yrd` (`block_yrd.rs`), `cost_coeffs`, `trellis`,
  `block_error`, `ref_costs` are **real** RDO primitives. They take a
  pre-computed residual (`src_diff`) and produce real transform-domain
  RD. They are the right building blocks — they're just not composed
  into `handle_inter`.

## Missing glue — the specific functions + LOC estimate

To make a speed≤4 RDO path that is *real* (and therefore worth wiring),
the following must be built. These are the deferrals the standalone
modules pushed onto "the caller":

| # | Glue function | What it does | Est. LOC |
|---|---------------|--------------|----------|
| 1 | `rdo_handle_inter_real` (replace `handle_inter`'s model RD) | For each of 3 filters: run `build_inter_pred_plane_unscaled` to produce the real prediction, compute `src_diff`, call `super_block_yrd`, add chroma RD, pick min-RD filter. This is libvpx `vp9_rdopt.c:2812-3219` for real. | ~450 |
| 2 | `build_handle_inter_runner` closure factory | Lift the per-leaf plane views (`src_y`, `ref_y`/`ref_y_golden`, UV planes), quantizer, cost tables, switchable-interp ctx into the `HandleInterRunner` boxed closure `pick_inter_mode_sb` requires; replace the placeholder mode-rate table with the real `inter_mode_costs`. | ~120 |
| 3 | `build_ref_mv_candidates_rdo` | Pre-run `single_motion_search` per ref-frame (LAST/GOLDEN), assemble `RefMvCandidates {nearest, near, newmv, newmv_rate}`, derive `pred_mv_sad`/`mv_step_param`/`error_per_bit` inputs. | ~110 |
| 4 | `rdo_intra_fallback` | Compute the real `IntraFallback {rate, dist, rd}` (the driver returns intra when all inter is worse). libvpx threads `vp9_rd_pick_intra_mode_sb`; minimally reuse the RT intra-in-inter cost. | ~90 |
| 5 | `leaf_rd_fn` adapter for `rd_pick_partition` | Wrap (2)+(3)+(4)+`pick_inter_mode_sb` into the `LeafRdFn` closure; map the winning `PickResult` back into `InterPartitionLeafDesc` and re-emit the SB's leaf list (mirrors the existing F.3 descent adapter at `lib.rs:3155-3197`). | ~110 |
| 6 | `encode_frame` speed≤4 dispatch | Gate the new RDO partition+pick path vs. the RT path on `config.speed <= 4`; thread the new producer into the residual-emission stage. | ~60 |
| 7 | Partition-cost bits + HORZ/VERT | `rd_pick_partition` is NONE+SPLIT only and omits `partition_cost[pl][PARTITION_*]` (`pick_partition.rs:19-30`). A real partition decision needs the rect arms and the per-symbol partition cost, else SPLIT vs NONE is mis-ranked. | ~250 |
| 8 | PROOF + cross-decoder gate test | A test asserting speed=3 routes to RDO and decodes (output differs from speed=7, both decode through rvp9-decoder). | ~80 |

**Total: ~1270 LOC**, of which items 1 and 7 (the real per-mode RD and
the missing partition arms) are the irreducible core. Even a "minimal
real" cut (skip GOLDEN, skip HORZ/VERT, Y-only-but-real transform RD)
lands at **~700-800 LOC** — comfortably past the 400-LOC threshold, and
still a partial port whose decision quality would need a
testsrc/foreman BD-rate gate to prove it isn't a regression against the
RT picker.

## Recommendation

Treat Wave 4 as what `mod.rs` says it is: **standalone primitives.** The
highest-value *next* step is item 1 — composing `super_block_yrd` +
real per-filter prediction into `handle_inter_mode_single_ref` so the
RDO driver produces real RD. That is a self-contained ~450-LOC unit
with a clean differential oracle (its RD should track the RT picker's
SSE-derived RD within a model-vs-exact tolerance), and it unblocks
everything downstream. It should be its own wave/PR, not smuggled into
an "integration" commit.

Wiring the dispatch (items 5/6) is cheap and correct to do *after* item
1 lands — doing it before would only let a fake-RD picker drive the
byte stream.

## Risks / open questions

- Even with real RD, the RDO partition driver's early-exit
  (`pick_partition.rs:234-239`) compares `sum_rd >= best.rd.rd` without
  the partition-cost bits, so SPLIT is currently under-penalised.
  Item 7 must land with item 1 or the partition decision is unsound.
- The cross-decoder gate is preserved by construction here (no code
  changed). Any future wiring MUST re-run it; the RDO picker changing
  `(mode, mv, ref, filter)` is fine as long as the shared emission
  stage re-derives `best_ref_mv` from the mi_grid identically to the
  decoder (the invariant the RT path already maintains at
  `lib.rs:3442-3458`).

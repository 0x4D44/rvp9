# Reject dynamic Y4M output formats — KIL-00119

The decoder CLI emitted a single Y4M header followed by frames with unchecked dimensions and chroma. A later displayed frame with a different format could therefore disagree with the declared frame layout while the process reported success.

The correction latches the first emitted pixel frame's width, height and chroma after its header write succeeds, and rejects a changed tuple before packing or writing that frame. The diagnostic identifies its one-based output frame number and both formats. Skip and limit continue to apply before output selection; raw output, hashing and no-blit paths keep their existing behavior. Initial unsupported 4:4:0 still fails before opening the destination; a later change to 4:4:0 reaches the tuple diagnostic. Successfully written earlier frames may remain in the destination; this is not a transactional whole-file change.

Observed assertion-red evidence, with every reversal restored:

- Before the fix, each selected width, height and chroma-change writer test failed `Y4M format change ... must be rejected`.
- Before the fix, the selected real-CLI changing-resolution test failed `Y4M output with changing geometry must fail`.
- Removing only tuple equality made the same-format control reject its second frame and fail. This proves permissiveness of the unchanged-format boundary separately from the original defect.
- Moving the format latch before the header write made the injected writer-failure test fail `failed header must not latch a format`, observing `Some((64, 64, Yuv420))`.

All five decoder writer unit tests passed, including changed width, height and chroma (4:2:2, 4:4:4 and later 4:4:0), same-format frames and header-write failure. The hermetic CLI regression passed: two independently encoded keyframes at 64×64 and 128×64 are muxed into one IVF; Y4M fails with exactly the valid first-frame prefix; limit-one and skip-one controls succeed; raw I420/YV12, MD5 and no-blit still accept the stream. Existing rectangular and spatial-SVC CLI round trips passed. The lead independently reran all five unit tests and the dynamic CLI regression. Decoder-scoped Clippy with warnings denied, CLI formatting and diff checks passed. Tests used the task's absolute `.scratch` directory as `TMPDIR`; no external vectors, libvpx or chroma-changing encoded fixture was used. Chroma-change coverage exercises the writer directly with allocated frame buffers. The preselected final smoke after catch-up is `cargo test -p rvp9-cli --test cli_roundtrip y4m_rejects_dynamic_geometry_and_skip_selects_the_output_format -- --exact`, bounded to 60 seconds.

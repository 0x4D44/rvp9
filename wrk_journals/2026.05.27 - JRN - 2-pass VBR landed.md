Path: **LANDED (bounded)**.

## Architecture chosen — per-SEQUENCE two-pass

libvpx's two-pass runs the whole sequence once gathering per-frame
`FIRSTPASS_STATS`, then re-encodes consuming the stats. The rvp9 encoder
API is single-pass (`StreamEncoder::encode_frame`), so I added a
sequence-level driver `rvp9_encoder::encode_two_pass(config, &[frames])`
that owns two independent `StreamEncoder` runs over the same input:

1. **First pass (stats-only).** Encode every frame at a FIXED quantizer
   (`RcMode::Q`, q-index 128) so coded error reflects content
   complexity, not a rate-driven Q. Per frame gather three genuine,
   content-driven stats from the actual encode:
   - `coded_error` = SSE(source Y, post-LF reconstruction Y) — read from
     the encoder's `diag_last_recon_y()`.
   - `intra_error` = SSE(source Y, frame-DC-mean prediction) — a cheap
     intra-cost proxy.
   - `pcnt_inter` = `clamp(1 - coded_error/intra_error, 0, 1)` for inter
     frames, `0` for KFs.
   The first-pass bitstream is discarded (mirrors libvpx writing stats
   to a file and throwing pass-1 output away). Kept in-memory (single
   process).
2. **Second pass (emit).** Build a `TwoPassState` that distributes the
   sequence bit budget (`avg_frame_bandwidth * n_frames`) across frames
   **proportional to each frame's `coded_error` score** (keyframes get an
   8x score boost — the intra anchor earns more, mirroring libvpx
   `kf_bits`). Attach it to a fresh encoder running `RcMode::VbrTwoPass`
   and re-encode. The 2-pass `pick_q_and_bounds` arm reads each frame's
   precomputed target (NOT the flat 1-pass target) and runs `regulate_q`
   to hit it.

## What stats drive pass 2

The per-frame **bit allocation** is `seq_budget * (frame_score /
total_score)` where `frame_score = max(coded_error, 1)` (KF boosted).
Busy/high-residual frames earn more bits → lower Q; flat frames earn
fewer → higher Q. The target — hence the picked Q — is a pure function of
the first-pass coded-error distribution.

## PROOF (tests/w_2pass_vbr.rs)

- `two_pass_q_sequence_differs_from_one_pass_cbr` — anti-G3: 2-pass Q
  sequence ≠ 1-pass CBR Q sequence on the same input.
- `two_pass_allocates_lower_q_to_busier_frames` — **strong anti-G3**:
  busy (high coded-error) inter frames get a lower mean Q than flat
  inter frames. MUTATION-VERIFIED: I temporarily made the 2-pass arm
  ignore the allocation (use avg bandwidth) → this test FAILED
  (`busy_mean_q=191 == flat_mean_q=191`), confirming it is a genuine
  oracle that catches "pass 2 ignores the stats". Restored → passes.
- `two_pass_stream_byte_exact_through_vpxdec` (`#[ignore]`) — oracle:
  2-pass stream BYTE-EXACT through rvp9-decoder AND libvpx vpxdec
  (221184 bytes, verified).
- `two_pass_completes_and_emits_one_packet_per_frame` — sanity / no panic.
- 5 lib unit tests in `two_pass.rs` (allocation proportionality, KF
  boost, cursor, stats-driven Q divergence).

## Scope-downs (documented follow-ups)

- **ARF placement / GF-group bit-allocation reshuffle** (`define_gf_group`
  + `define_gf_group_structure`, `vp9_firstpass.c:2257-2302, 2692`). We
  allocate per-frame, not per-GF-group with ARF boost. ~300-400 LOC.
- **Stats-driven adaptive KF placement** (`find_next_key_frame`,
  `:3247`). We honour the configured `gop_length` cadence. ~150 LOC.
- **Full first-pass motion search** (`MVr`/`MVc`/`pcnt_motion`,
  `MVrv`/`mv_in_out_count`). Our first pass uses the real coded error +
  DC-intra/motion-effectiveness proxies; the full motion-stats set is
  deferred. ~200 LOC.
- **`bpm_factor` / noise / inactive-zone Q adjustments**
  (`get_twopass_worst_quality`). ~100 LOC.
- **Two-pass + lag/ALTREF interaction** — the driver forces
  `lag_in_frames = 0`. ~100 LOC.

Full libvpx two-pass is ~800-1200 LOC; this bounded landing is the core
"first-pass stats drive pass-2 bit allocation" loop with the family-
completing dispatch arm.

# Exact sub-pixel pass profile

The Unit1434 EXE/PDB had disappeared from Crucible scratch, so its archived
sampled RVAs could not safely be disassembled. I recaptured Tree and Town from
clean integrated `07edb682`, retained the hash-matched EXE/PDB and zero-loss
ETLs in a new Crucible task worktree, and recorded the exact-address analysis
in `wrk_docs/evidence/2026-09-26-exact-subpel-pass-profile/README.md`.

The reusable full two-pass horizontal loop accounts for 45/1,611 Tree and
40/1,457 Town process samples (~2.8% each). A one-entry cache has an immediate
matching key on only ~13% of eligible two-dimensional calls. This narrows the
likely value of the proposed cache but is not a measured speedup; the candidate
still needs Arthur's architecture go-ahead, exact differentials, and paired
CPU evidence before any production integration. The retained parity ratio is
1.182520×.

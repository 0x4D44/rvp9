# Unit 1385 — AVX2 16×16 variance four-way accumulator

## Decision

Retain and integrate. The x86 AVX2 16×16 variance reduction now keeps four
independent `(sum, sse)` accumulator pairs live. Every other block shape keeps
the existing generic kernel, and the integer reduction order remains exact.

## Why this candidate

The fresh Crucible CPU profile at integrated source `2595e969` mapped
20,048,075 weighted user samples. The active
`rvp9_core::dsp::x86_64::variance_avx2::var_sum_sse_16x16_avx2` path accounted
for 841,048 samples (4.195%), making its serialized accumulator chain a
bounded instruction-level-parallelism target. The candidate only changes that
hot 16×16 path; it does not change dispatch policy, search decisions, or
quality settings.

## Correctness evidence

- `cargo fmt --all --check` passed.
- AArch64 `cargo test --locked -p rvp9-core --lib dsp::x86_64::variance_avx2 -- --nocapture`
  compiled and passed with zero filtered tests because the x86 module is
  cfg-gated there.
- `RUSTFLAGS='-C target-cpu=x86-64' cargo test --locked --target
  x86_64-apple-darwin -p rvp9-core --lib dsp::x86_64::variance_avx2 --no-run`
  passed.
- Crucible x86-64 release focused tests passed 4/4: random all-size and
  edge-content scalar differentials, dispatch round-trip, and the 8×8 cell
  differential.
- Deliberate red run: changing the four-way `row2` offset from `r + 8` to
  `r + 9` failed the random differential at `w=16, h=16` with a `(sum, sse)`
  mismatch. Restoring the offset returned the focused suite to 4/4 green.
- Candidate and integrated-control release encodes were byte-identical for
  all three 1280×720@30 clips. The hashes are retained in the screen manifests.

## Performance evidence

Both RVP9 screens used CPU-used 6, CBR 1260 kbps, 30 fps, one thread, zero
tile columns, AQ 0, 60 frames, one warmup, 15 alternating pairs, two
rotations, and no `--max-load1` cap. Ratios below are candidate/control;
lower is faster.

| clip | screen A paired | screen B paired |
| --- | ---: | ---: |
| ducks | 0.973586× | 0.971128× |
| in-to-tree | 0.988769× | 0.988022× |
| old-town-cross | 0.984149× | 0.984420× |
| three-clip corpus geomean | 0.982148× | 0.981163× |

The repeated corpus gain is 1.8–1.9%, with matching output hashes. The
relaxed screens stayed below load1 0.75 and 0.55 at completion. Against the
pinned libvpx encoder under the same protocol, the candidate was 1.454355×
paired for the corpus, so this is a measurable RVP9 improvement but not yet
the 1.05× parity bar.

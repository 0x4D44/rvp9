1 agent round). Then G2 (iadst16 derivation, mostly low risk because
F7/F6 already derived iadst8/iadst4). Then loopfilter family in

G7 last (highest risk).

deliverables since some can be combined).

### Notable design points

1. **G1 skip-and-zero-fill** for EOB-bucket row groups was bit-exact
   because the parent kernel's intermediate scratch is zero-init and
   idct of all-zero is all-zero. No partial-group execution needed.

2. **G2 iadst16 derivation** picked up the iadst pattern from F7
   (iadst8) and F6 (iadst4) — 4-stage butterfly with cospi
   {1,3,5,...,31}, heavy negation rewrites via `sub(zero, sum)`,
   output permutation with sign flips. First-try bit-exact.

3. **G3 no-transpose loopfilter** was the simplest of the loopfilter
   AVX2 ports — about 35 fewer SIMD ops than F10 because horizontal
   filtering reads contiguous rows.

4. **G4+G5 shared helpers** (filter8 + flat_mask4 derived once,
   used in both vertical and horizontal). Combined-deliverable
   approach saved agent dispatch overhead.

5. **G6 three-tier cascade** (filter4 / filter8 / filter16 based on
   flat_mask4 + flat_mask5) was the most complex loopfilter port,
   but implementer hand-derived filter16's 15-tap weighted sum
   cleanly into u16 lanes with bit-exact ROUND_POWER_OF_TWO.

6. **G7 architectural prototype** proved the F12 two-pass decode
   split is feasible without bit-exactness loss. Risk now
   downgraded from "3-5 calendar days unknown architectural risk"
   to "40-50 dev-hours mechanical extension".

### Lessons captured (Wave G)

1. **Read the scalar before writing the brief**. G6's brief had a
   wrong count parameter — implementer caught it by reading source.
   Briefs that quote scalar implementation details without the
   supervisor having read them first risk propagating errors.

2. **Worktree-base drift is the dominant merge pain**. When an
   agent's worktree branches from main BEFORE intermediate Wave
   commits land, the squash will conflict on every file that
   intermediate work touched. The reset-to-HEAD + hand-port pattern
   handles this in O(n_changed_files) but is tedious.

3. **The "combined deliverable" pattern works well for paired
   variants**. G4+G5 (vertical+horizontal of the same filter
   family) shipped in one agent round because they share the inner
   helper functions. F3+F4 (16x16 EOB ports) followed the same
   pattern in Wave F.

4. **Architectural deliverables benefit from explicit Option A/B
   framing**. G7's brief offered "prototype (preferred) OR scoping
   document (fallback)". Implementer chose Option A and shipped a
   working ONE_TOKEN proof-of-concept. Compare to F12 in Wave F
   which I deferred entirely as a Wave G blocker — G7 retired more
   risk than F12's deferral did, in roughly the same time budget.

5. **Implementer agents are competent at catching supervisor
   errors**. G6's implementer caught my brief's mistake about
   count=1 vs count=8. Trust their source-reading; don't over-spec
   in briefs.

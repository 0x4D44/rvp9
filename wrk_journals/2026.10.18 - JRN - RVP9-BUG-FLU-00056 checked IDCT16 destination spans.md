# RVP9-BUG-FLU-00056 — checked IDCT16 destination spans

The AArch64 IDCT16 wrapper checked `dest.len() >= stride * 15 + 16` before calling its raw-pointer kernel. With release overflow checks disabled, a large stride could wrap the required-length expression and let a short slice pass before out-of-bounds pointer arithmetic.

The required length now uses `checked_mul(15)` followed by `checked_add(16)`. A shared unconditional guard also enforces a minimum stride of 16 and checks the slice length. The scalar 16×16 IDCT paths use the guard before writing, and the NEON wrapper invokes it before the unsafe inner kernel. The regression exercises multiplication overflow, addition overflow, a normal 16×16 span, and the guard panic using only safe code; it never calls a kernel with invalid geometry.

The regression failed before the fix with overflow checks disabled: the overflowing spans were accepted as lengths 30 and 15. It passed afterward with `CARGO_PROFILE_DEV_DEBUG_ASSERTIONS=false CARGO_PROFILE_DEV_OVERFLOW_CHECKS=false`. On the native `aarch64-apple-darwin` host, the focused `cargo test -p rvp9-core idct16x16` group passed (16 tests), including NEON/scalar parity coverage. Scoped `cargo clippy -p rvp9-core --lib --tests -- -D warnings`, `cargo fmt --all -- --check`, and `git diff --check` passed. The final exact regression smoke with debug assertions and overflow checks disabled passed in under 60 seconds.

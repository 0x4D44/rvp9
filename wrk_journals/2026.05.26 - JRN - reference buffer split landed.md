# 2026.05.26 — JRN — Reference-buffer split (me_ref vs last_recon) landed

**Verdict: LANDED.** The structural split between the ME-side reference
buffer and the residual-coding reference buffer is in place across the
`StreamEncoder` storage, the `pick_and_simulate_inter_encode_partitions`
signature, and every interior call site. Cross-decoder gate stays GREEN
(byte-exact vs vpxdec). PROOF test added and passing.

This unblocks the three downstream features the prior assessment journal
(`wrk_journals/2026.05.26 - JRN - denoiser integration assessment.md`)
identified: temporal denoiser, filtered-ALTREF, and the compound ME-vs-
prediction-ref separation. All three need a writable ME-side reference
that is not the bitstream-committed reconstruction.

## What changed

### `StreamEncoder` storage (`frame_loop.rs`)

Three new `Vec<u8>` fields parallel `last_recon_{y,u,v}`:
`me_ref_{y,u,v}`. Allocated with the same dimensions as the
residual-coding buffers in `StreamEncoder::new`. Three new test-only
read accessors (`me_ref_y/u/v`).

### Buffer commit lifecycle

- **Keyframe**: after `apply_loop_filter_to_tight_recon` writes the
  post-LF KF reconstruction into `last_recon_*`, the encoder mirrors
  those bytes into `me_ref_*` (alongside the existing GOLDEN mirror).
- **Inter frame**: after the new recon is committed into `last_recon_*`
  (post-LF, the existing line), the encoder mirrors those bytes into
  `me_ref_*`.

Until the denoiser / filtered-ALTREF wave fills `me_ref_*` with
filtered pixels, the two buffers stay byte-identical after every
commit — which is the structural-split invariant the PROOF test
verifies.

### Picker signature (`lib.rs::pick_and_simulate_inter_encode_partitions`)

New parameter `me_ref_yuv: (&[u8], &[u8], &[u8])` inserted between
`input_yuv` and the existing `last_recon_yuv`. The doc above the
function explains the split.

Call-site routing:
- **ME-side (now reads `me_ref_yuv`)**: `ref_y` (motion search, ME root
  PlaneRef), `last_ref_u`/`last_ref_v` in the two `PickInterModeParams`
  literals (chroma SSE/RD), `ref_u`/`ref_v` in the RDO `RefInputs`
  (chroma RDO), plus the e12 + e3 diagnostic candidate-sweep params.
- **Residual-coding (still reads `last_recon_yuv`)**: the up-front
  `recon_yuv_out.copy_from_slice(last_recon_yuv.*)` seed and the
  per-leaf plane selector inside `build_inter_pred_plane_unscaled`
  (the MC the decoder bit-exactly reproduces).
- **Partition picker (`choose_partitions_for_frame` in
  `frame_loop.rs`)**: now reads `me_ref_y` rather than `last_recon_y`
  for the variance-based partition decision. Partitioning is an
  ME-side analysis.

### PROOF test

`frame_loop::tests::reference_split_me_and_pred_identical_initially`
(in `crates/rvp9-encoder/src/frame_loop.rs`):

- Encodes a KF + 3 inter frames against a small 64×64 gradient.
- After every commit, asserts `me_ref_*` equals `last_recon_*`
  byte-for-byte across all three planes.
- Anti-cheat assertion: `me_ref_y/u/v` and `last_recon_y/u/v` must
  have **distinct backing allocations** (`as_ptr()` comparison). A
  shared `Vec` / `Arc` view would not be a real split — the denoiser
  needs separate writable storage to write filtered pixels into.

When the denoiser wave later wires a real per-block filter, the
byte-equality assertions fail until the test is updated to compare
against the filtered expectation. That failure is the intended
anti-G3 signal: it means the ME-side buffer actually diverged, which
is the entire point of the split.

### Known preexisting parallel flakiness (unrelated)

When the lib tests run in parallel (the default), the test
`encode_frame_q_index_responds_to_bitrate` is ~50% flaky on this
branch. Diagnosis: other lib tests (`encode_frame_respects_fixed_q_env_override`
and friends) set `RVP9_FIXED_Q` as a **process-wide env var**,
serialized with `env_test_mutex()` among themselves. The bitrate test
does not take that mutex, so when it runs concurrently the encoder's
`std::env::var("RVP9_FIXED_Q")` read inside `pick_q_and_bounds`
sometimes catches `100` and pins the test's Q value (observed:
`low_q=100, high_q=168`, where 100 is exactly the override value).

This race predates the refactor — the `set_var` paths and the
bitrate test have both been on `main` for many commits. The refactor
changed test scheduling slightly (a few extra mirror copies per
frame), making the race window measurably wider but not introducing
the bug. The task spec explicitly required
`--test-threads=1` verification; under that flag we are stable across
5/5 runs.

A proper fix is a follow-up: add `env_test_mutex()` to the bitrate
test (and any other env-reading test). Not in scope for this refactor.

## Next steps (out of scope here)

Now that `me_ref_*` is a separately-allocated, writable buffer the
denoiser, filtered-ALTREF, and ME-vs-pred-ref features can each
write filtered pixels into without touching the cross-decoder gate.
Each of those waves will replace the post-commit `copy_from_slice`
in `encode_frame` with its own filter pass (mirroring libvpx's
`vp9_denoiser.c:336-437` `vp9_denoiser_denoise` or the equivalent
ALTREF temporal filter), and will update the PROOF test to compare
against the filtered expectation.

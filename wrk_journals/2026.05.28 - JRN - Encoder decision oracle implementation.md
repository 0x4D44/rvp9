### Stage 2 — KF-rate ablation — CONCLUDED. Hypothesis REFUTED: KF is an independent lever, not the root cause.

**Method:** temporary one-line change in `cbr.rs` first-KF arm (`best = get_kf_active_quality(122)`, re-instating the removed `KF_ACTIVE_QUALITY_BASIS_CAP=122`), rebuilt, re-ran `e1_block_stats` @100k/250k, reverted (tree clean). Landed KF **exactly** on libvpx: q57, 75,432 bits (libvpx 74,536).

| metric @100k | BEFORE | AFTER (KF fixed) | libvpx |
|---|---:|---:|---:|
| KF bits / q | 152k / 20 | **75k / 57** | 74k / 57 |
| inter avg-q | 237.3 | **233.7** | 203.9 |
| achieved kbps | 148.8 | **119.9** | 140.1 |
| area% 16×16 | 96.5 | **96.7** | 64.5 |
| area% 64×64 | 0.0 | **0.0** | 4.8 |
| ZEROMV % | 97.4 | **95.7** | 3.4 |

**Verdict: KF-rate is ONE INDEPENDENT LEVER, not the upstream cause.** Landing the KF perfectly on libvpx moved the 16×16 partition by <0.2pp (utterly insensitive to rate), inter-q by only ~3.6 (still 30 above libvpx), ZEROMV by ~1.7. Striking: at 100k the freed ~77k KF bits *drained out* (achieved rate fell 148.8→119.9) instead of lowering inter-q → **the inter path cannot use the headroom.** Three confirmed independent levers:
1. **KF cap** — `cbr.rs` (lands KF at libvpx point; halves KF size; improves rate compliance, esp. 250k 345→257 kbps).
2. **Partition 16×16 cap** — `nonrd_partition.rs:511-556` `variance_hint_bounds` (rate-independent; descent literally cannot emit 8×8/64×64).
3. **Inter-q/mode reinvestment** — freed bits not spent; inter-q stays high, ZEROMV dominates (HLD-R2 cost-model/operating-point, still live for the inter path).

**CRITICAL CAVEAT:** all metrics so far are *distributions*. `partition.rs:480` A7 experiment warns distributions can shift with **no PSNR gain** at saturated q. **Must validate each lever against PSNR/BD-rate (the real oracle) before implementing.**

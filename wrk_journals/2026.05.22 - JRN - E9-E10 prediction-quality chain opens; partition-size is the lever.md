## E9 — decomposition (committed 119cf93)

Matched-Q oracle (foreman, q∈{80,120,160}) decisively attributes the
~9 dB matched-bitrate gap to **prediction quality (bucket 1)**:
- libvpx +8–10 dB PSNR AND ~half the bits at every Q (textbook
  prediction-quality signature).
- rvp9 prediction PSNR ~26 dB and **Q-independent** (26.3→25.9) → it's
  mode/MV/partition, not transform/quant (which would scale with Q).
- Entropy healthy (~1.7 bits/nonzero-coef); bit excess is coefficient
  VOLUME from weak prediction.
- Root cluster: degenerate `find_mv_refs` (circular — neighbours all
  (0,0) because no block introduces motion), over-fine 8×8 descent,
  NEWMV unaffordable at 8×8.

## E10 — int_pro edge-SB seed fix (committed 5a61f8b)

Genuine bug fixed: `int_pro_motion_estimation` bailed (`u32::MAX`) on
12/16 SBs (every edge SB of 256²) because rvp9's `PlaneRef` is the bare
visible plane and the projection window/SAD halo ran off the border.
libvpx reads an edge-replicated extended-border frame. Fix: edge-clamped
reference accessors. New test `all_sbs_seeded_no_edge_bail` (16/16).
Byte-exact; 94 encoder tests pass.

**Necessary-but-NOT-sufficient.** The cascade did NOT fire: prediction
PSNR still ~26 dB, NEWMV RD-win **0% even at 2 Mbps** (low Q, low
lambda), partition still 8×8-dominated. The decisive signal: NEWMV loses
even with good seeds at low lambda → the binding constraint is NOT seed
quality or MV-rate affordability per se — it's that **NEWMV is only ever
evaluated at 8×8**, where (a) foreman's slow pan barely changes a small
block so (0,0) is nearly as good, and (b) MV-rate isn't amortized. The
picker evaluates modes at the wrong granularity.

## The lever: larger inter partitions (next — E11)

The over-fine partitioning is the binding constraint. libvpx's nonrd
evaluates modes (incl. NEWMV) at 64/32/16 FIRST and only splits if
needed; rvp9's variance partitioner decides 8×8 from the ZEROMV-residual
variance BEFORE any mode search, so NEWMV never gets a fair evaluation at
an affordable, motion-significant block size.

E11 = decisive experiment: cap inter partition at 16×16 (reuse the
`allow_split_to_8x8` gate) and re-measure at matched Q. If NEWMV now wins
and prediction PSNR rises above 26 dB → the lever is confirmed
(motion-aware/larger partitioning) → iterate toward faithful nonrd. If
not → the issue is NEWMV distortion/search at larger blocks, a different
fix. (Note: A7.inter-cap tried this pre-E8 and saw PSNR locked at 16 dB
— but that was under RC q-saturation, since fixed by E8; the matched-Q
oracle is a clean re-test.)

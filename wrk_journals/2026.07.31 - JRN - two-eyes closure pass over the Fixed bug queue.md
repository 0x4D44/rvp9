## The find that mattered: KILN-00020 regressed a live encoder path

The accepted fix `ce657a77` hardened the public AVX2 V_PRED wrapper by validating block
geometry. The validation is stricter than the real callers: it rejects any `bs` outside
`{4,8,16,32}` and panics, but `evaluate_intra_fallback` drives V_PRED with `bw = 64` on
`BLOCK_64X64`, and the inner AVX2 kernel has a deliberate scalar arm for exactly those
sizes. On any AVX2 host `cargo test --workspace` panics in `w_tpl` with
`v_predictor_avx2: unsupported block size`.

Proven, not inferred: neutralising the new panic (scratch edit, reverted, never committed)
makes both tests pass, and `crates/rvp9-encoder/tests/w_tpl.rs` has not been touched since
`1e22d91`, well before the fix. Reopened, raised to `Priority: Must`, landed as `3a7aba2`.

This is the failure mode every later group was told to hunt for. None of the other 51
repeats it — every new guard in the batch was traced to its real callers, and several of
those traces (KILN-00023's `parse_tile_buffers`, KILN-00024's `num_workers == 1` assert,
KILN-00026's tightly-packed-stream risk) were genuinely close calls that came out clean.

## Two process mistakes I made, both worth remembering

1. **The first gate run was truncated and I nearly believed it.** `cargo test --workspace`
   is fail-fast: the `w_tpl` failure aborted the run before `rvp9-harness` and `rvp9-io`
   ever executed, so two whole crates' worth of regression evidence was silently missing
   from a log that looked complete. Caught only by cross-checking each analyst's named test
   against my own index and finding six `NOT FOUND`. Every verification run from here should
   use `--no-fail-fast`.
2. **I started the vector fetch while a test run was in flight.** The harness raced a
   half-downloaded corpus and `conformance_runner_walks_all_vectors` failed on a missing
   `.md5`. Contaminated run, discarded, re-run clean. Fetch first, then test.

## Fetching the conformance vectors changed the verdicts

The worktree starts with no `tests/conformance/vectors`, no `tests/corpus` and no
`build/libvpx` — all gitignored, and KILN-00039's fix correctly stops the harness reaching
into the main clone for them. That left 61 tests `ignored` and three bugs unverifiable:

- KILN-00044's new WebM track filter (`CodecID == "V_VP9"` + `TrackType == 1`) would cause a
  MASS conformance failure if any shipped vector lacked that metadata.
- KILN-00040's new 1-based `.md5` frame-index rule would hard-fail every conformance vector
  if any upstream ledger were 0-based.
- KILN-00027's only regression test is vector-gated and does not run at all without them.

`scripts/fetch-vectors.sh` (30 files, ~50 MB) settled all three empirically. It also
un-ignored 14 more tests and surfaced a defect that had been invisible on every vectorless
box — see below. Fetching the vectors should be routine for a verification pass, not
optional.

## Second real defect: a test-isolation race that reds the workspace gate

With vectors present, `parallel_tile_decode_reuses_isolated_scratch_buffers` fails:
`left: 12, right: 8`. It samples the process-global `RVP9_G5_2_SCRATCH_ALLOCS` across a
`decode_frame` window while its six sibling tests decode concurrently in the same binary.

- default (parallel): FAILED, reproduced twice, deterministic
- `--test-threads=1`: 7 passed
- the test alone: ok

So `cargo test --workspace --locked` — the documented full gate AND the
`.deltic-integrate.toml` fallback gate — is red on any machine that has fetched vectors.
Split to KILN-00062 at `Must`/`High`. Same defect class as FLUX-00004, which was fixed with
a serializing mutex; the same remedy applies.

## Method

Six analyst agents read the 52 fix diffs against their original recorded observations,
read-only and with cargo forbidden (I owned the single test run; concurrent cargo would have
fought the target lock). Each returned per-bug: root-cause fix site at HEAD, exact regression
test names, an adversarial judgement of whether the test would fail without the fix, and any
residual.

I then cross-checked every named test against my own `cargo test --workspace` index rather
than taking the reports on trust — which is what caught the truncated run. Two claims I
verified by hand because they could not be settled from a log:

- FLUX-00001 (aarch64-only, unreproducible on this host) — settled with
  `cargo check -p rvp9-core --all-targets --target aarch64-unknown-linux-gnu`. With the fix's
  `#[cfg(target_arch = "x86_64")]` removed it fails with exactly the recorded
  `error[E0609]: no field 'avx2' on type 'caps::AArch64Caps'` at `dispatch.rs:3714`; with it,
  clean. A true fails-before/passes-after on the reported target.
- KILN-00015 — its only regression test is behind `--features highbitdepth`, so no default
  workspace run has ever executed it. Ran it explicitly; passes.

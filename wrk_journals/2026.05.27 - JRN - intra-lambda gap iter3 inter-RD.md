## The three iter3 levers tried (reverted)

### 1. `compute_sad_per_bit` / `compute_error_per_bit` (qindex-derived, libvpx-faithful)
libvpx `vp9_rd.c:165-176` `init_me_luts_bd` and `vp9_rd.h:198-201`
`set_error_per_bit`. rvp9 had `DEFAULT_SAD_PER_BIT = 16` /
`DEFAULT_ERROR_PER_BIT = 16` as stand-in constants marked
*"Tuning lives later"*; the libvpx values at qindex 100-128 are
`sad_per_bit ≈ 3-5` (4x too high in rvp9) and `error_per_bit ≈ 1000-1300`
(80x too low). I plumbed the libvpx formulas into both the RT picker
(`mode_decision/inter.rs:2076,2143`) and the RDO dispatch leaf
(`rdo/inter_dispatch.rs:382-384` via `InterDispatchLeaf` literal in
`lib.rs:4133-4134`).

PSNR delta: **0.00 dB** at cpu7/1200k. The MV-cost weight inside the
diamond/sub-pel search isn't load-bearing for this corpus's MV magnitudes
(SAD on a 16x16 block is 1000-5000; `sad_per_bit` swings of 4 vs 16 move
the augmented-SAD by ~30-50 units, dwarfed by the underlying SAD).

### 2. `encode_breakout_thresh` = 300 (libvpx speed=7 default)
libvpx `vp9_speed_features.c:446-449` sets `encode_breakout_thresh =
(min(w,h) >= 720) ? 800 : 300` at speed ≥ 7, then
`vp9_speed_features.c:893-896` bumps `cpi->encode_breakout` up to that
floor. rvp9 hard-coded `encode_breakout: 20` in **both**
`pick_and_simulate_inter_encode_partitions` call sites (the RT picker at
`lib.rs:3222` and the RT-fallback after RDO at `lib.rs:4242`). That
collapses `encode_breakout_test`'s `min_thresh = encode_breakout << 4` to
320 instead of libvpx's 4800; at high q (q_index ~100, dequant_ac ~50)
the threshold clamps to ~320 vs ~1300, so the gate rarely fires.

PSNR delta: **+0.02 dB** at cpu7/1200k mean. Why: in rvp9 the
`encode_breakout_test` only BREAKS the mode loop — the winning mode is
still encoded with its full residual. libvpx's gate ALSO sets
`x->skip = 1` so the emit-side suppresses residual coding entirely (rate
collapses to a single skip bit). rvp9's emit decides skip data-driven
post-quant (`leaf_total_eob == 0`), which only fires when every coef
quantizes to zero. The encode_breakout signal never reaches the emit
gate.

### 3. (combined) — both 1 and 2 together
Same result: +0.02 dB. Not significant.

## Real cause: **structural coding inefficiency**, not RD lambda / MV cost

At fixed qp=70 rvp9 emits 1.5x the bytes vpxenc does. Possible loci, in
suspected impact order:

1. **Picker→emit skip-flag plumbing.** rvp9's emit ignores the picker's
   skip decision and re-decides post-quant. libvpx wires `x->skip = 1`
   from `encode_breakout_test` directly into the emit walk. This is
   structural — needs the `InterPartitionLeafDesc::skip` flag to honor
   the picker's tie-break (`evaluate_candidate_for_filter`'s
   `rd_encode < rd_skip` branch) rather than only `leaf_total_eob == 0`.

2. **Coefficient coding cost vs. real entropy-coded bits.** The picker
   adds `coef_rate` from Hadamard-SATD as the rate estimate. The actual
   emit uses full DCT + arithmetic coding. If picker over-estimates,
   it under-picks NEWMV (which has more residual reduction → fewer
   real bits). The K1 calibration history at
   `inter.rs::reconstruct_via_round_trip` shows previous calibration
   work was inconclusive.

3. **MV cost weight `MV_COST_WEIGHT = 108`.** The final emitted MV cost
   uses `(mv_cost * 108 + 64) >> 7`. If this is mis-calibrated against
   `compute_rd_mult`'s lambda, NEWMV looks expensive in RD but emits
   cheap bits.

4. **Switchable interp filter rate.** `filter_rate` from
   `switchable_interp_costs[ctx][filter]` is added unconditionally; if
   the per-context costs don't match libvpx's table, picker picks
   suboptimal filter.

## Next localization for iter4

Compare actual emitted bits per (mode, ref) class vs the picker's
estimated rate. The cleanest probe: run rvp9enc at fixed qp=70 on
foreman with a per-leaf rate dump (sum of skip + mode + mv + coef
rate, vs the actual emitted byte count for that leaf), and the same
in libvpx (with `--debug-output` or a patched `block_yrd`). If the
picker systematically under-estimates by N%, that's the calibration
target. If it over-estimates, expect the picker is picking ZEROMV when
NEWMV would be cheaper in reality.

The picker→emit skip plumbing (lever 1 above) is the highest-impact
single fix; it requires:
1. Add `picked_skip: bool` to `InterPartitionLeafDesc`.
2. Wire `evaluate_candidate_for_filter`'s skip decision (the
   `rd_encode < rd_skip` branch) into the result.
3. At the emit site (`lib.rs:4900-4913`), honor `picked_skip` to
   override the residual emission: no coef coding, just the skip bit.
4. Verify cross-decoder gate still 4/4 — the skip-flag context is the
   sensitive part.

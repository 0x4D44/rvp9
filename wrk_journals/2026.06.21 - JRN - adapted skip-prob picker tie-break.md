## Hypothesis (novel — not in the refuted list)

rvp9's realtime skip-flag RD tie-break
(`crates/rvp9-core/src/mode_decision/inter.rs` `evaluate_candidate_for_filter`,
~line 3144) prices the skip bit with `DEFAULT_SKIP_PROBS[skip_ctx]`
(the **un-adapted** default `{192,128,64}`), while libvpx uses
`cm->fc->skip_probs[skip_ctx]` — the **frame-adapted** values. The code
comment itself flags "Threading the real per-block skip context is a
follow-up."

On inter frames where skipping dominates, adapted skip_probs fall *below*
the defaults, which (a) makes signalling skip=1 cheaper and (b) makes
coding residual more expensive — biasing the RD tie-break toward skip,
matching libvpx's higher skip rate and reducing the token over-emission.

Distinction from refuted probes:
- The "live frame-context **partition** cost" probe (collapsed Q80 +12 dB)
  changed `partition_costs`, NOT the skip tie-break. Different lever.
- `RVP9_RT_SKIP_PICKER_SKIP_EMIT=1` (honor picker-skip in emit) was tested
  with the **default** probs: on VBR it gave +0.93 dB on comparable points
  (better than +1.16) but shifted the curve left (BD-rate +23%, range
  artifact). Nobody combined honor-picker-skip with **adapted** probs.

`picker_skip = take_skip` (inter.rs:3226) so adapted probs flow to the
emit honor-skip path consistently.

## Conclusion — REFUTED, reverting

The adapted skip prob is a faithful libvpx-parity detail, but wired through
rvp9's *current* skip RD tie-break it **regresses both oracles**:

- Fixed-Q: V1/V2 degrade the mode field (skip-friendly, poorly-predicting
  modes win) and V2 discards needed residual (Q120 −2.6 dB prediction).
- VBR product gate: the apparent mean-Δ improvement is the same curve-shift
  artifact the prior pass already refuted — more skip → curve shifts to
  lower bitrate where rvp9 is relatively closer to libvpx, but coverage
  drops (4→3→2 in-range) and the real product metric (BD-rate) worsens
  (+6.43% → +12.69% for V1; range collapse for V2). This is the "loose
  diagnostic threshold ≠ product pass" trap the goal warns against.

Root-cause insight (the actionable part): rvp9's skip tie-break
`rd_encode >= rd_skip` **over-triggers skip** once the skip bit is cheap.
The skip-side dist `dist_skip = sse_after_pred << s3_skip_shift()` is not
calibrated against `dist_encode = coef_dist` and `lambda` the way libvpx's
is, so a cheaper skip prob makes too many blocks pick the skip path
(mode-ranking) and, when honoured, discards residual that mattered. Matching
libvpx's higher skip rate therefore requires first fixing the skip
tie-break's dist-domain calibration — adapted probs alone are net-negative.

Per the goal keep/discard rule (keep only RD wins), the source change is
**reverted**. The implementation is fully recorded here; the diff is:
`adapted_skip_prob_enabled()` + `resolve_skip_prob()` + `skip_prob:
Option<u8>` on `InterModeSearchParams`/`PickInterModeParams`, threaded from
`frame_context.skip_probs[skip_ctx]`, consumed in
`evaluate_candidate_for_filter`. Follow-up parked in `scratchpad.md`.

Cross-decoder gate NOT run for the variants: the reverted tree == baseline
(known cross-decoder-clean), so no validity risk is introduced.

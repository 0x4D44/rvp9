# Shorten optional Windows load samples — FLU-00033

Windows `encode-headtohead` used its minute-long CPU sample even without a `--max-load1` ceiling, at preflight, every clip rotation and completion. The no-ceiling branch recorded metadata but could not reject a run, so sampling dominated relaxed screens.

The correction selects a short Windows metadata window when the ceiling is absent, while preserving the existing guarded minute window, retry, threshold and fail-closed behavior when the ceiling is present. The manifest names the short metric `windows_1s_busy_logical_cores`; guarded readings retain `windows_60s_mean_busy_logical_cores`. Unix continues to read its existing one-minute system load average. The short probe has a ten-second process deadline; the guarded probe retains ninety seconds.

The [PowerShell 5.1 Get-Counter documentation](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.diagnostics/get-counter?view=powershell-5.1) defines SampleInterval in seconds between observations and MaxSamples as the number collected. The short policy uses two samples one second apart and retains the post-baseline value; guarded sampling retains the existing thirteen samples five seconds apart. These are configured sample windows, not measured Windows wall-clock durations; startup and command overhead are additional.

Regression evidence: after adding the injected-probe seam around the existing policy, `load_enforcement_uses_metadata_without_weakening_the_guard` failed on the original dispatch: four guarded selections instead of four metadata selections. Reversing metadata settings to the guarded minute-long settings also failed the new settings coverage. The final tests check four metadata checkpoints, optional probe failure without retry, strict unavailable-load retry and rejection, acceptance exactly at the ceiling, rejection above it, generated counter scripts, deadlines and metric names.

The worker observed 22/22 focused binary tests passing with absolute task-local `TMPDIR`, formatting, scoped Clippy and diff hygiene. An initial run with a relative `TMPDIR` failed the existing child-process timeout fixture because its path resolved from a different working directory; correcting the invocation passed without changing that fixture. Lead validation independently passed all 22 tests and cross-compiled the production binary with Windows GNU Clippy and `-D warnings`. The preselected final smoke is the exact injected-policy regression test. No live Windows duration or runtime result is claimed.

# Reject out-of-range CLI denoiser settings — KIL-00124

The CLI's noise-sensitivity handler parses an unrestricted `u32`, while the config builder defensively clamps it to six. Consequently, a misspelled or unsupported setting silently becomes a different setting. The bug's prescribed correction is to validate the documented `0..=6` range at parsing time while retaining the defensive builder clamp.

This pass addresses CLI validation only. KILN-00073 remains Blocked for Arthur's temporal-denoiser strength contract decision; range rejection neither answers that question nor proves adaptive denoising behavior. Valid settings must retain their exact config value, and the omitted flag must keep its default.

Observed reversal 2: the actual CLI regression selected one test against the unrestricted handler and failed its required range-diagnostic assertion. Stderr instead reported opening the deliberately missing input, proving that parsing accepted 7 and reached I/O. The existing output sentinel is checked by the same regression.

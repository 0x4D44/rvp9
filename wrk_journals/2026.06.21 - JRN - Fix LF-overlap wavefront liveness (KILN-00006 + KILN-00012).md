## Diagnosis (both bugs, one root cause)

Confirmed against e678386 (KILN-00006 still Open; code matches the 06.20 review):
- `spin_then_yield_wavefront` (`apply.rs:313`) is an unbounded spin with **no abort**.
- The L1 gate (`apply.rs:458-465`) spins until
  `decode_progress[gate_row] >= num_tile_cols`. Tiles publish a row's counter only at
  the *end* of a fully-decoded SB row (`tile.rs`), so a tile that exits early (`?` Err
  **or** panic-unwind) before a row's publish leaves that row's counter short forever.
- The driver dispatches the single LF worker (`LfWorkerPool`, N_LF=1) BEFORE the decode
  scope and joins it after via `handle.wait()` (`lib.rs:2216/3600`) — or, on a panic that
  unwinds out of `WorkerPool::scope`, via `LfBatchHandle::Drop` (`lf_pool.rs:350`), both
  no-timeout `rx.recv()`. With the worker spinning, both block forever.

Root cause (single): **the LF wavefront worker has no abort path, and the driver never
signals abort on an abnormal exit** — so any incomplete decode (Err or panic) strands
the worker and hangs the join. KILN-00006 = the Err manifestation; KILN-00012 = the
panic/`Drop` manifestation. One fix closes both.

## Fix (minimal, at the root)

1. `ColumnWavefrontLfState` gains `abort: Option<&'a AtomicBool>`.
2. `run_split_edge_lf_worker`'s L1 gate predicate also returns on `abort`; after the
   spin, if aborting, the worker `return`s immediately (decode failed → frame discarded
   → no filtering needed). Soundness preserved: abort only makes the worker FINISH
   SOONER; the join (`wait`/`Drop`) still happens, so the temporal-exclusion edge for the
   unsafe `'frame` raw-pointer access is intact, and abort is only ever set when output
   is being thrown away.
3. Driver: per overlap dispatch, a `lf_abort: AtomicBool`. On the error path
   (`merge_err.is_some()`), store `true` before `handle.wait()` (closes KILN-00006). An
   RAII guard `LfAbortOnPanic(&lf_abort)` whose `Drop` sets the flag iff
   `std::thread::panicking()` — declared *after* the handle so on unwind it drops first,
   setting abort before the handle's `Drop` recv (closes KILN-00012).

## Implementation

`crates/rvp9-core/src/loopfilter/apply.rs`:
- `ColumnWavefrontLfState` gains `abort: Option<&'a AtomicBool>` (documented).
- `run_split_edge_lf_worker`: a hoisted `aborted` closure; BOTH wavefront spins
  (the L1 `decode_progress` gate and the inner `cur_sb_col` sync-read) now release
  on abort and `return` before touching frame planes.

`crates/rvp9-decoder/src/lib.rs`:
- Module-level `LfAbortOnPanic<'a>` RAII guard (Drop sets the flag iff
  `std::thread::panicking()`).
- Both overlap drivers (keyframe + inter): a per-dispatch `lf_abort: AtomicBool`,
  passed as `abort: Some(&lf_abort)`; error-path `if merge_err.is_some() {
  lf_abort.store(true, Release) }` before `handle.wait()`; `let _lf_abort_guard =
  LfAbortOnPanic(&lf_abort)` declared AFTER the handle (drops first on unwind).
- Two-scope (row-MT) construction: `abort: None`.

Both ~300-line driver blocks are pre-existing near-duplicates (flagged in the 06.20
CR as a refuted/maintainability item); I mirrored the existing structure rather than
expand scope into a risky extract-shared-fn refactor.

# Fail incomplete decode throughput sweeps — KILN-00066

The decode-throughput CLI failed empty runs and CSV errors, but a default sweep with at least one successful fixture and another failed fixture still appended its partial rows and exited successfully. Automation could therefore mistake an incomplete measurement for a completed sweep.

The bounded correction preserves successfully measured rows and the existing error diagnostic, then returns failure when any requested fixture failed. Success now requires measurements for the complete requested set and a successful CSV append. This does not change the throughput metric, fixture selection, baseline identity, or CSV schema.

The mixed default-sweep regression ran against the original CLI and failed its intended exit-status assertion: it exited zero after recording 1,000 timed samples from one valid fixture, while stderr reported one malformed and two missing fixtures. The corrected test also requires exactly the retained successful CSV row with a positive frame count, so an empty/all-failed result cannot stand in for the defect.

The all-success control uses all four default names and requires four positive measurement rows. Temporarily changing the final successful exit to failure made this test fail its status assertion while still showing four 1,000-frame rows. The mutation was restored before implementing the intended failure exit inside the existing `had_error` branch.

Fixture data comes from a generated 64x64 flat VP9 keyframe wrapped in a small WebM container. Per-child vector-directory and CSV overrides isolate writes from the tracked ratchet data. CLI subprocesses use the existing bounded capture runner and closed stdin. Both existing missing-fixture and CSV-write-failure tests and their assertions remain.

The worker's four CLI integration tests, workspace formatting check, and focused Clippy passed. The lead independently ran all four CLI integration tests successfully and checked the diff. The preselected final smoke is `TMPDIR="$PWD/.scratch" deltic timeout 60 cargo test -p rvp9-bench --test decode_throughput_cli default_sweep </dev/null`, selecting both new regressions after final catch-up. No performance or official conformance result is claimed.

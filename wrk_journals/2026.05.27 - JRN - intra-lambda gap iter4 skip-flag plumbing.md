Date: 2026-05-27
Branch: main @ a3c92fe
Outcome: **Negative result — reverted.** The structural fix is
correct and the bitstream did shrink, but the rate calibration in the
RT picker over-favours skip and PSNR collapses. Honest negative;
encoder source unchanged.

## Anatomy of the bug (carried over from iter3)

Two encoder paths exist:

- **RT picker** (cpu>=5, used at cpu7):
  `core::mode_decision::inter::pick_inter_mode` iterates
  `RT_INTER_MODES`; each candidate goes through
  `evaluate_candidate_for_filter`. That function computes
  `let rd_skip = rd_cost(lambda, 0, sse_after_pred_u32); ... if rd_encode
  < rd_skip ...` (`inter.rs:2640-2650`) — picking skip when cheaper.
  The skip decision affected `final_rate` / `final_dist` (so RD-ordering
  was libvpx-faithful), but the **identity** of which branch won was
  dropped — neither `InterModeSearchResult` nor `PickInterModeResult`
  carried it.

- **RDO dispatch path** (cpu<=4):
  `rdo::handle_inter::handle_inter_mode_single_ref` has the same
  tie-break (`handle_inter.rs:441-470`) and surfaces it via
  `HandleInterModeResult::disable_skip`. The `InterDispatchResult`
  produced by `pick_inter_sb_leaf` (`inter_dispatch.rs:648-655`)
  discarded it.

Downstream the `lib.rs` emit walk reads only
`sb_partitions[..].picked_*` fields; `skip` is initialised `false`
(at the picker-resolved call site `lib.rs:4615`) and only set to `true`
post-hoc when forward-quant produces all-zero coefs across the
entire leaf (the "RC.X1" override at `lib.rs:5108`). Result: any leaf
where the picker would have picked skip but produced any non-zero coef
emits the residual, fattening the stream.

## Diagnosis — RT picker rate calibration

The cpu7 catastrophe is the iter3 lever 2 ("coef_rate over-estimates
real bits") cashing out for the first time. With residual emission
forced ON (pre-iter4), the rate inflation didn't matter — the actual
bitstream paid real coef costs regardless. Wiring the picker's choice
through to the emit walk made the inflation MATTER: `rd_encode = lambda
* (rate + coef_rate_inflated) + dist` looks much bigger than
`rd_skip = lambda * 0 + sse_after_pred`, so skip wins for blocks that
actually had useful residual.

The cpu4 RDO path also regressed (-0.14 dB at 1200k) — milder, because
its `super_block_yrd` rate is real transform-domain (not SATD-from-
qcoeff). But even with real rate the `disable_skip` flag in libvpx
flows through ranking, not directly into `x->skip = 1` emit. The
libvpx-faithful "emit skip" signal is the SEPARATE `encode_breakout_
test` + `skip_txfm == AC_DC` machinery.

## Next lead

The picker-honors-skip plumbing is **structurally correct** but
exposes a **picker rate-estimate calibration** bug. The two distinct
fix surfaces:

1. **Real-bits-aware skip gate.** Replace the SATD-based `coef_rate`
   bit estimate inside the RT picker's `rate` sum with a per-context
   approximation that matches the entropy coder's actual output. The
   F.1 note in `evaluate_candidate_for_filter` already documents the
   K1=4 scale exponent as "winning"; calibration is the open work
   item (DV-F1-1 Hadamard port, beyond F.4-2 scope).

2. **`skip_txfm == AC_DC` propagation.** The libvpx `x->skip = 1`
   path that ACTUALLY fires libvpx-side is the `model_rd_for_sb_y`
   `skip_txfm[0] == SKIP_TXFM_AC_DC` classification (full-skip
   detection via variance/quant model). rvp9 has `mrd.skip_txfm` in
   the picker — propagating that as `picked_skip` (instead of the
   raw tie-break) might capture the same blocks libvpx does without
   over-shooting.

3. **Decode the actual libvpx behavior** at `vp9_encodeframe.c` /
   `vp9_pickmode.c` skip-emit sites. The tie-break's `*disable_skip =
   1` write at libvpx `vp9_pickmode.c:2362` clearly tracks something
   different from "emit skip=1": iter4's reading of the brief was
   that `*disable_skip = 1` ⇒ `x->skip = 1`, which is plausibly
   wrong. Mapping the libvpx flag flow before the next encode-walk
   patch attempt is prerequisite.

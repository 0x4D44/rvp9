# RVP9-BUG-KIL-00112 — Benchmark child process deadlines

External encoders and decoders in realtime, BD-rate, SVC BD-rate and encoder
head-to-head benchmarks used blocking `status` or `output` waits. A stalled
tool could therefore hold the benchmark indefinitely.

All benchmark child waits now use `rvp9_bench::process`: closed stdin, bounded
`try_wait` polling, kill and bounded reap on timeout, and errors identifying the
tool role and program with retained stdout/stderr. File-backed captures avoid
pipe-capacity deadlocks and inherited-pipe waits. Each retained tail is capped
at 64 KiB and marked when truncated. Capture handles and files are cleaned up
on normal completion and error paths. A failed termination reports its PID
and reap result rather than falling back to a blocking wait.

Encoder/decoder invocations use a 300-second default. Soak retains its existing
30-second deadline and quiet successful cross-decode behavior. Metadata probes
use 10 seconds; the Windows load sampler gets 90 seconds for its existing
60-second sampling window. No dependency or command-line interface was added.

## Regression evidence

Six tests exercise the actual encoder/decoder call paths with fake executable
tools, without needing external codecs. Their one-second deadline expires
before the fake tool's eventual successful completion after two seconds.
Replacing the runner with the old unbounded `stdin(null).output()` behavior
made all six named tests fail at assertions: both BD-rate paths, both SVC paths,
realtime, and head-to-head. The BD-rate decoder incorrectly produced PSNR 100;
the other paths accepted completion or reported the fake output shape instead
of the required timeout. The shared helper timeout test also failed on an
unexpected successful Output. These were assertion failures, not build errors
or outer command timeouts.

Supporting test calibration separately observed the bounded-tail assertion
fail with uncapped output and the nonzero-status assertion fail when the child
input was changed from exit 7 to exit 0. These calibrations verify the supporting
oracles; they are not additional proof of the original hang. Fake-child test
entrypoints are fixtures, not regression oracles. The real helper and exit-7
input were restored before final validation.

The helper tests also check closed stdin, retained stdout and stderr, timeout
PID/reap diagnostics, large output beyond pipe capacity, and preserved nonzero
exit status. Existing soak timeout and isolated temporary-directory tests remain.

## Validation and limits

`cargo test -p rvp9-bench` passed 97 tests before the final internal deadline
field cleanup. After that cleanup, the library and all five affected binary
test targets passed 88 tests. The final six actual-path tests were also observed
failing again with the unbounded runner, then restored and passing.
`cargo fmt --all --check` and `cargo clippy -p rvp9-bench --all-targets`
passed; the final clippy run emitted no warnings. `git diff --check` passed.
The selected final smoke is `cargo test -p rvp9-bench --no-fail-fast external_
-- --nocapture`, bounded to 60 seconds after the final fetch/catch-up check.

Independent read-only review found no blocking issues in the final eight Rust
files, combined SHA-256
`e570a400d3950c0f768f2fc4007c3ba97d76f36811be9add18d6ac17d80df2c4`.
The reviewer checked child lifecycle, handle cleanup, call coverage, errors and
the mutant evidence. Validation runs on macOS; Windows paths receive source review only.
The deadline controls the direct child. Descendant process-tree termination is
outside this fix; file captures prevent descendants from extending pipe waits.
Capture files may grow while the child runs, although retained memory is capped.

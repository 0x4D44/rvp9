## Step 1 — count plumbing investigation (the decisive finding)

**Counts ARE gathered today, but only the 4-token MODEL histogram, and only
AFTER the header is written.**

- The G3 count-accumulation HLD
  (`wrk_docs/2026.05.24 - HLD - G3 coef count accumulation.md`) was IMPLEMENTED:
  `encode_coefs` (`detokenize.rs:948`) and `write_block_tokens`
  (`detokenize.rs:1224`) accumulate counts into `DecodeCoefCounts`
  (`detokenize.rs:218`), threaded through `write_tile_inter` →
  `write_inter_partition_tree` → `write_inter_block_leaf` →
  `write_inter_block_residual` → `write_block_tokens` → `encode_coefs`
  (`modes_writer.rs:1487/1579/1796/2178`). Consumed by `adapt_coef_probs`
  (`frame_loop.rs:2140/2156/2534`).

- BUT the shape is the **4-token model** histogram:
  `CoefCountsBlock = [..][UNCONSTRAINED_NODES + 1]` = ZERO/ONE/TWO/EOB_MODEL
  (`detokenize.rs:206`). It COLLAPSES TWO..CAT6 into one TWO_TOKEN bucket.
  libvpx's encoder accumulates the **full 12-token** `vp9_coeff_count`
  (`vp9_encoder.h:379`, accumulated in `vp9_tokenize.c`).

- libvpx's TWO_LOOP PIVOT_NODE branch (`vp9_bitstream.c:569-575`) calls
  `vp9_prob_diff_update_savings_search_model` (`vp9_subexp.c:141-180`), which
  scores the PIVOT branch PLUS the 8 downstream Pareto-8 model nodes — branch
  counts that `build_tree_distribution` (`vp9_bitstream.c:518-543`) derives
  from the FULL 12-token histogram. **rvp9 does not have those counts.**

- ORDERING obstacle: rvp9 writes the compressed header (`frame_loop.rs:3393`)
  BEFORE the tile encode that gathers counts (`frame_loop.rs:3460-3474`).
  libvpx writes the header after tokenizing (counts ready). A faithful port
  needs a count pass before the header → a two-pass tile encode (token VALUES
  are prob-independent, so a pre-header count pass is sound, but it doubles the
  tile-encode cost and restructures the byte-exact path in BOTH
  `build_inter_packet_with_residuals` and `build_keyframe_packet`).

- SHARED-TYPE obstacle: `CoefCountsBank` lives in `rvp9-core` and is read by
  the decoder's backward-adapt path in ~10 sites; widening its token dimension
  to 12 ripples into the decoder.

**Count-plumbing estimate (full-12-token bank + thread + two-pass reorder):
~200-300 LOC, at/over the task's STOP threshold, on the only
byte-exact-through-vpxdec path.** Per the task's decision rule and the "no
half-TWO_LOOP that breaks the gate" discipline, full integration is deferred.

## Step 2 — what landed (gate-safe, no production caller, gate untouched)

`crates/rvp9-encoder/src/bitstream_gates.rs` — added the two omitted libvpx
helpers (the original module's PIVOT_NODE deviation note, `:201-208`, is now
resolved at the helper level):

1. **`build_coef_branch_cts`** (= `build_tree_distribution`'s per-slot body,
   `vp9_bitstream.c:518-543`): ports `vp9_tree_probs_from_distribution`
   (`vp9_treewriter.c:34-58`) over `vp9_coef_tree` (`vp9_tokenize.c:75-87`),
   applies the node-0 EOB fixup (`:533-534`), and emits the 3 ideal
   UNCONSTRAINED_NODES probs via `get_binary_prob` (`:535-538`). The `-0`/`-11`
   leaf ambiguity in libvpx's `i16` tree is resolved with a positional
   `LEAF_TOKEN` + `COEF_TREE_CHILD` split.
2. **`prob_diff_update_savings_search_model`** (PIVOT, `vp9_subexp.c:141-180`):
   scores PIVOT branch + 8 model nodes under `VP9_PARETO8_FULL`, with libvpx's
   `(newp-oldp)*step_sign < 0` walk and `stepsize` (coeff_prob_appx_step).

`crates/rvp9-encoder/tests/w_coef_prob_parity.rs` (NEW, integration) + 2 PROOF
tests in `bitstream_gates.rs::tests`:

- **DIFFERENTIAL ORACLE** — `build_coef_branch_cts`'s 3 unconstrained branch
  counts are checked against the INDEPENDENT model-token folding already in
  `adapt_coef_probs` (`adapt.rs:614-618`). Two paths written from opposite
  directions must agree (they do). Also asserts the 8 model nodes carry the
  within-TWO+ mass — exactly what the 4-token shape discards.
- **PIVOT exercised + differential** — the model search moves a skewed pivot
  prob with positive savings, AND differs (savings or best_newp) from the plain
  single-branch search → proves the 8 Pareto-8 nodes are actually scored (the
  original deviation could not).

  `loop_filter_frame` before refactoring; thread `&SimdDispatch` down.
  Check rvp9-decoder; rvp9-encoder (for the loop-filter-in-encode

  arm to stay within sub-1-hour dispatch budget.

- **Worktree isolation per gap** with `git -C` discipline.

Refactored apply.rs to thread `&SimdDispatch` through 6 inner helpers
and replace all 12 direct `lpf_*` callsites with dispatch slot
lookups. Public API of `loop_filter_frame` unchanged (encoder-side
caller in `crates/rvp9-encoder/src/loopfilter.rs` not modified) —
the entry point looks up `dsp::get()` once per frame and threads
`&SimdDispatch` to inner helpers.

Added 6 dual-variant scalar slots to `SimdDispatch`:
`lpf_vertical_4_dual`, `lpf_horizontal_4_dual`,
`lpf_vertical_8_dual`, `lpf_horizontal_8_dual`,
`lpf_vertical_16_dual`, `lpf_horizontal_16_dual`. The 4/8-tap duals
are 9-arg (independent threshold sets); the 16-tap duals are 6-arg
(shared threshold set per libvpx convention). All scalar at H1
close, awaiting H2/H3/H4 AVX2 fills.

**Surprise**: when the H1 wiring went live, **58/201 conformance
regressions appeared**. The F10 + G3-G6 AVX2 single-variant
loopfilter kernels passed unit tests in Wave F/G but diverge from
scalar on real corpus inputs. Wave F/G's "first-try bit-exactness"
claim was based on per-kernel unit tests; conformance exercises
edge cases the unit tests missed.

**Mitigation**: added `RVP9_DSP_LOOPFILTER_AVX2` env-var gate
in `SimdDispatch::build` — AVX2 paths active ONLY when the var is
set to `1`. Default behaviour reverts to scalar. Conformance back
to 201/0/0/0/201.

**Wave H follow-up**: created task H7 — bisect & fix the buggy AVX2
kernels, then remove the gate. See `notes/wave-h-loopfilter-avx2-gate.md`.

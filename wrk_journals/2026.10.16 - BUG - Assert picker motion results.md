# Assert picker motion results — KIL-00104

The active `picker_finds_motion_on_shifted_block` test printed both picker entry points without asserting a result. Its reference varied only by column, making the documented two-row displacement unobservable; the comment also placed the step at column 16 although the code used column 32. With the source sampled from reference coordinates two rows and three columns earlier, the expected reference-sampling motion has negative sign.

The original selected test passed natively. NEWMV won at `(0, -24)` Q3 with zero distortion and RD cost 36,758; the zero-motion candidates had distortion 320. That output confirms the missing vertical discrimination, not a production picker defect.

The reference now has independent row and column steps at coordinate 32, with quadrant levels 20, 100, 140 and 220. Both boundaries remain inside the centered 32×32 block. The source origin `(16,16)` samples reference origin `(14,13)`, so the exact matching motion is `(-2,-3)` pixels, or `(-16,-24)` Q3. The test confirms zero raw SAD at that offset, asserts the NEWMV candidate's exact vector and zero distortion, requires its RD cost to beat every zero-motion competitor, and checks that both picker entry points agree. It remains active and no production codec code changed.

The repaired fixture selected NEWMV `(-16,-24)` with zero distortion and RD cost 36,758. Zero-motion candidates had distortion 954 and RD costs 85,841,768, 85,605,641 and 85,751,668. The assertions use relative cost ordering rather than hardcoded cost values.

Changing the expected vector to the old comment's wrong sign produced an observed assertion-red run: the selected test failed at the motion equality assertion with left `(-16,-24)` and right `(16,24)`. Restoring the expected vector passed. This proves the motion-result assertion separately from fixture calibration; it is a coverage repair, not an observed codec defect.

The focused test passed natively on ARM and under Rosetta for `x86_64-apple-darwin` with `RUSTFLAGS='-C target-cpu=x86-64'`, one selected test each. The lead independently reran both. Scoped integration-test Clippy passed with warnings denied, as did workspace formatting and diff checks. Tests used the task's absolute `.scratch` as `TMPDIR`. No physical x86, AVX2, Windows, external corpus or performance claim is made. Hooks refused removal of the empty scratch directory, so it was left for normal integration cleanup.

# Anchor relative I/O seeks to caller position — KIL-00099

`parse_header` consumes a Y4M header at the caller's current `File` position, then seeks to the header byte count as an absolute file offset. `IvfStreamWriter` likewise writes its header at the current cursor but patches the packet count at absolute byte 24. Prefixes therefore expose two independent position errors: the Y4M reader resumes inside earlier bytes, and IVF finalization overwrites earlier data instead of its actual count field.

The correction captures each initial position and uses checked relative offsets. The IVF constructor must validate its future count-field offset before writing the provisional header. Existing IVF finish behavior still seeks to the underlying stream's end and flushes. This pass leaves reader allocation policy, packet format and valid zero-position callers unchanged.

Observed reversal 1: the prefixed Y4M regression selected one test and failed the post-header cursor assertion: byte 31 instead of byte 50.

Observed reversal 2: the prefixed IVF regression selected one test and failed prefix equality: absolute bytes 24 through 27 were overwritten by packet count two. The corrected regression also checks the actual embedded count field, packet timestamps and payloads, and final cursor at EOF. Checking the count field directly matters because the packet-range reader does not enforce that field.

Observed reversal 3: the overflow regression selected one test and failed its constructor error-kind assertion, observing `Other` from the synthetic header write instead of `InvalidInput` from a checked offset. After correction, the same test also requires zero write calls. The synthetic writer reports a near-maximum position and errors on any write, so no huge file or allocation is required. The lead inspected all three failure logs.

The worker's three regressions passed after the corrections; formatting, scoped `cargo clippy -p rvp9-io --all-targets` and diff checks passed. The lead independently reviewed the offset calculations and ran `TMPDIR="$PWD/.scratch" deltic timeout 180 cargo test -p rvp9-io </dev/null`: all 139 runtime tests passed (60 unit, 75 error-path, four track-discovery), with one existing ignored doctest. The lead also removed stale zero-position wording from the API docs.

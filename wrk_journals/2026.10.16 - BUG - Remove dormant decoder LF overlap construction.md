# Remove dormant decoder LF overlap construction — KILN-00067

The decoder disabled output-frame loop-filter overlap with a false constant after discovering that its whole-grid immutable MI slices could overlap tile workers' mutable MI views. Both unsafe pre-decode constructions remained compiled in the source and could be rearmed by changing that constant. The bug explicitly allows removing the dormant construction instead of redesigning and enabling overlap.

The selected correction removes both dormant intra/inter state-construction, dispatch, and join paths, their flags, and overlap-only metadata snapshot. It preserves decode-progress publication and the active post-decode loop-filter dispatch, where workers have completed and their scratch output has been merged. The obsolete private panic guard and its two tests, plus the duplicate-overlap snapshot equality assertion, are retired as part of removing their sole production use; this is not suppression of a failing check. The active core loop-filter worker abort test remains unchanged.

The public counter and constructor behavior remain for compatibility. The private retained LF pool is named as reserved storage; its resource cost is outside this removal. Inspection established that the cached overlap flag was private (`TraceFlags` is `pub(crate)` in a private module) and had no remaining consumer. Its field and environment-snapshot entry are removed with the dormant feature; the old disable environment variable had no effect under the false constant and is now documented as obsolete. No dummy read or lint suppression hides dead code.

Observed regression proofs:

- Before removal, both source-integrity tests selected their own intra/inter method bodies and failed on the retained `SharedFrame` construction. After removal both pass and also reject the old rearming constant. These checks establish content coverage, not a general runtime alias-soundness proof.
- Temporarily suppressing LF on the generated parallel keyframe failed `frame 0: parallel LF differs`.
- With the keyframe still filtered, temporarily suppressing LF on only the parallel inter frame failed `frame 1: parallel LF differs`.
- Both behavioral mutations were restored manually before final validation.

The generated fixture uses fixed quantizer 100, 512x128 textured I420 input, and two tile columns. It checks actual parsed tile geometry, positive LF levels, key/inter frame kinds, serial/parallel visible Y/U/V equality, and four tile job submissions across two frames. An independent filter-level-zero header baseline changes visible pixels for each frame; the inter baseline rebuilds the same filtered reference history first. Thus the comparison cannot pass merely because LF is inactive or the encoder clamped to one tile.

Worker checks passed: generated/source integration tests 3, decoder `merge_lf_params` tests 4, scratch-boundedness test 1, and core `loopfilter::apply::tests` 39 (including the unchanged abort regression, also run separately once). Decoder Clippy across all targets produced no warnings; rustfmt and diff checks passed. The lead independently passed all three new integration tests and compiled `rvp9-decoder` with `profile-tiles` for `x86_64-apple-darwin`, using `RUSTFLAGS='-C target-cpu=x86-64'`. That is a cross-target compilation check, not a physical x86 runtime result.

The lead reviewed all removal hunks: tile decode scope-joins, scratch merge/error handling, progress publication and active post-decode LF arguments remain. The active post-decode shared-frame constructor is outside the guarded decode methods and unchanged. The named external conformance vectors are absent on this host, so their existing test and assertions remain intact but provide no evidence here. No Miri, compression-quality, performance, or full conformance result is claimed. Scratch is retained for authorized integration teardown.

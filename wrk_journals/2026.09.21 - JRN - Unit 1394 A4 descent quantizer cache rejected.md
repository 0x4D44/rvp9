# Unit 1394 — A4 descent quantizer cache (rejected)

## Hypothesis

The A4 partition-descent callback visits several block sizes at the same 8×8
cell. Its effective qindex, segment calibration, forward quantizer pack, and
UV dequant pair are cell-dependent, so caching those values once per cell
could reduce repeated setup in the profiled A4 closure.

## Correctness evidence

- The candidate was committed as `fb57f526` and reverted as `cd8c5d66`; the
  final branch has no shipped code difference from integrated `38623762`.
- `cargo fmt --all` and `git diff --check` passed.
- Focused AArch64 tests passed:
  `descent_cell_picker_context_matches_direct_neighbours` and
  `descent_pick_cache_covers_complete_superblock_key_space`.
- The full AArch64 encoder library passed 780 tests; one test was ignored.
- Crucible candidate and control release builds completed. The short screens
  produced one stable, byte-identical stream hash per clip and arm.

## Crucible screen

Both runs used the relaxed Crucible policy: CPU-used 6, CBR 1260 kbps, 30 fps,
one thread, zero tile columns, AQ 0, zero noise sensitivity, 60 frames, a
60-frame keyframe interval, one warmup, three alternating pairs, two reversed
clip-order rotations, and no `--max-load1` cap. Raw manifests and summaries
are retained under
`wrk_docs/evidence/2026-09-21-unit1394-screen-quick/run1/` and `run2/`.

Ratios are candidate/control; lower is faster:

| run | ducks | in-to-tree | old-town-cross | corpus |
| --- | ---: | ---: | ---: | ---: |
| 1 paired | 1.002584× | 1.003523× | 1.001142× | 1.002416× |
| 2 paired | 1.007935× | 0.993900× | 0.998359× | 1.000047× |

The first run regressed on every clip. The repeat improved only in-to-tree
and old-town-cross, with a neutral corpus result. Across both runs the cache
has no reproducible positive signal, so it fails the Tesco retention bar and
was rejected without a full 15-pair or pinned-libvpx screen.

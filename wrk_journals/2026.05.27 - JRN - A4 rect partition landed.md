# 2026.05.27 — JRN — A4 rect partition (HORZ/VERT) landed

## Outcome

**LANDED.** The recursive RD partition descent now evaluates
**PARTITION_HORZ and PARTITION_VERT** alongside NONE and SPLIT at every
square parent (64/32/16), coding each rect as two sub-blocks at the rect
size and ranking the summed RD against NONE/SPLIT — closing the
documented square-only scope-down of A4 (commit 71d8625). The sacred
cross-decoder gate is **4/4 GREEN** (rvp9-decoder, vpxdec, ffmpeg all
byte-exact on the rect-containing stream). `cargo build --workspace`
clean.

## What was already there (the leverage)

The bitstream emit path for inter frames was ALREADY rect-aware:
`write_inter_partition_tree` (`crates/rvp9-core/src/bitstream/modes_writer.rs:1562`)
infers the partition type from the mi-grid block sizes via
`infer_inter_partition` (`:698`) — a rect leaf size (e.g. Block32x16)
maps to PARTITION_HORZ, and the writer emits the two stacked /
side-by-side halves in the layout the decoder's `decode_inter_partition`
reader expects. Existing round-trip tests (e.g.
`s5_tile_inter_block8x16_vert_round_trip`) already proved rect emit +
decode. The post-pick recon TX walk, the UV-plane helpers
(`f5_uv_plane_block_size` / `f5_uv_plane_tx_size`) and
`splat_inter_leaf_into_mi_grid` were all `(w,h)`-generic. So the work was
in the DESCENT (decide rect) + a handful of square-only assumptions in
the picker path.

## What this commit did

1. **Rect HORZ/VERT in the descent**
   (`crates/rvp9-core/src/mode_decision/nonrd_partition.rs`). After NONE
   and SPLIT, `descend` now evaluates HORZ (two `w×h/2` halves stacked)
   and VERT (two `w/2×h` halves side by side) via the same
   `ModePickerFn` callback at the rect subsize, sums the two halves' RD +
   the rect `partition_cost`, and keeps the result if it beats the best.
   New helpers `subsize_for_horz`/`subsize_for_vert`/`rect_half_step_8x8`
   and `commit_rect_leaves` (rolls back speculative SPLIT children, same
   invariant as `commit_leaf`). Mirrors libvpx `rd_pick_partition`
   PARTITION_HORZ/VERT (`vp9/encoder/vp9_encodeframe.c:4342-4436`); the
   `partition_{horz,vert}_allowed` size gate
   (`:4018-4021`, `bsize >= BLOCK_8X8`) is honoured via `!bsize_at_floor`;
   rect is additionally bounded by `bsize <= max_partition_size` (the
   variance hint already excluded larger parents — preserves the
   `none_disallowed_when_bsize_exceeds_max` contract). Frame-edge
   `force_{horz,vert}_split` overrides are NOT modelled (the descent runs
   only on 64-aligned SBs; the picker callback's SB-edge guard makes any
   off-frame rect half infeasible).

2. **Rect sub-pixel-variance kernels**
   (`crates/rvp9-core/src/dsp/distortion.rs` +
   `crates/rvp9-core/src/mv_search/sub_pixel.rs`). The NEWMV sub-pel
   refinement panicked: `sub_pixel_variance` was ported for 5 square
   sizes only. The core is `(w,h)`-generic, so added the 6 rect macro
   expansions the descent emits (16x8, 8x16, 32x16, 16x32, 64x32, 32x64)
   and wired them into `svf_for`. Mirrors libvpx `SUBPIX_VAR(W,H)`.

3. **Square-only intra-in-inter guard**
   (`crates/rvp9-core/src/mode_decision/inter.rs`). `evaluate_intra_fallback`
   does a single whole-block square `intra_predict` (one `bs` side,
   square edge buffers) — on a rect block it over-read the left/above
   buffers and crashed in `dc_predict_left_avx2`. libvpx tiles
   intra-in-inter per-TX (`vp9_pickmode.c:2517-2646`), which rvp9 has not
   ported, so the fallback now returns `None` for `width != height`.
   Honest measurement gap (no intra signal on rect leaves), NOT a
   correctness gap: the chosen inter candidate reconstructs and decodes
   byte-exact. Square leaves unaffected.

4. **Widened the picker-supported gate** (`crates/rvp9-encoder/src/lib.rs`).
   The post-descent per-leaf loop's `picker_supported` and the descent
   picker callback's defensive size guard now allow all square + the six
   rect sizes (only the three sub-8 sizes, which rvp9 never emits, fall
   back to ZEROMV/skip).

5. **Anti-G3 counter `RD_PARTITION_RECT_LEAVES`**
   (`crates/rvp9-encoder/src/rdo/inter_dispatch.rs`), bumped once per
   rectangular leaf (`width != height`) the descent commits.

## PROOF (`crates/rvp9-encoder/tests/w_rd_partition_rect.rs`)

Synthetic clip (128×128, 8 frames): top band scrolls left fast, bottom
band scrolls left slow — diverging motion across the horizontal mid-line,
so a single 64×64 MV (NONE) fits one band but not the other, and a HORZ
split lets each band take its own MV.

- **Assertion #1 (anti-G3):** `RD_PARTITION_RECT_LEAVES > 0` — the
  descent emitted rect leaves (observed: 2, i.e. one HORZ decision =
  two halves). FAILS if rect is never evaluated or never wins.
- **Assertion #2 (oracle):** the rect-containing stream decodes to 8
  frames and is byte-exact across rvp9-decoder AND vpxdec.

The descent's own unit tests add `horz_wins_on_horizontal_edge`,
`vert_wins_on_vertical_edge`, `horz_at_32x32_under_split` (rect nested
under SPLIT + speculative-child rollback). All 20 nonrd_partition unit
tests pass.

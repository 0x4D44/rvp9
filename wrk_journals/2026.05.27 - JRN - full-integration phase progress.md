### A10 buffer_pool — LANDED (commit 1574ead, task #25)

Full VP9 8-slot `RefFramePool` + `ref_frame_map[8]` + `new_fb_idx` on
`StreamEncoder` (`crates/rvp9-encoder/src/buffer_pool.rs`), replacing the ad-hoc
`last_recon_*` / `golden_recon_*` / `altref_recon_*` field-triples. `keyframe_reset`
broadcasts one slot across all 8 map entries; `commit_new_frame` +
`update_reference_frames(refresh_flags)` rotate the map (libvpx `swap_frame_buffers`
/ `update_reference_frames`, `vp9_encoder.c`). KF/inter/ARF paths read refs via
`named_ref_planes(LAST/GOLDEN/ALTREF)`.

**Gate-safe refactor (byte-identical).** Obstacle resolved: first cut resolved
GOLDEN through `ref_frame_map[0]` and changed the stream (6073 vs 6211 bytes)
because GOLDEN candidates are picked at the gate's speed; fix = direct

any wrong slot mapping/stubbed rotation) + clean round-trip; 5 unit tests for

### A4 RDO partition descent — LANDED (commit 71d8625, task #26)

The pre-A4 partition SHAPE was always the variance heuristic
(`choose_partitioning`, libvpx `vp9_encodeframe.c:1261`); the RDO leaf machinery
only re-priced MODES inside fixed leaves. A real recursive NONE/SPLIT RD descent
(`nonrd_pick_partition`, `vp9_encodeframe.c:4922-5210`) existed but was
infrastructure-only (default-OFF, env-gated) and didn't drive the bitstream. A4
**promoted that descent to the default** (`lib.rs:2603`), opt-out
`RVP9_A4_RD_PARTITION_DISABLE`, anti-G3 counter `RD_PARTITION_RESHAPED_SBS`.

Scope (honest): square NONE/SPLIT, 64→32→16, inter-only. Rect HORZ/VERT deferred
(libvpx also defers at speed≥5); KF descent a follow-up. NO synthetic model — real
recursive RD through the real `pick_inter_mode`.

PROOF (`tests/w_rd_partition.rs`): descent ON re-shapes 22 SBs, OFF 0 (anti-G3);
ON/OFF streams differ (3525 vs 2992 bytes); ON stream byte-exact across
rvp9-decoder + vpxdec. **Sacred gate 4/4** (both decoders agree on the new
RD-partitioned default stream). Lib 429.

Collateral test reconciliation verified clean (no assertion weakened): the A10
byte-identity golden in `w_buffer_pool.rs` was kept intact by pinning the pre-A4
partition path (`RVP9_A4_RD_PARTITION_DISABLE=1`) in that test — the A10
pool-refactor oracle and the A4 partition oracle stay independent. `rdo_dispatch_proof`
+ `a18_prev_frame_mvs_fires` similarly pinned the pre-A4 path for the claims they own.

Risk noted: the descent now runs at realtime speed too and may pressure the 720p
perf gate (`realtime_gate_720p30`, #[ignore], release-only) — perf, not correctness;
env opt-out exists. Unblocks ML (A21).

## Phase II — zone integration

### ML partition pruning (A21) — LANDED (commit a1ea238, task #29)

Wired libvpx's ML partition-search **breakout** (`ml_predict_breakout`, `vp9_encodeframe.c:3250-3329` model, `:4161-4168` gate) into the A4 descent: after a winning PARTITION_NONE pick, the real NN/linear model votes; a positive vote forces `do_split = 0`, skipping that block's SPLIT recursion. Real features only (source-block Y variance, the NONE pick's rate/dist, `x->rdmult`, `vp9_ac_quant`) — no synthetic shortcut.

Cross-crate architecture (correct): a new `BreakoutPruner` trait + `nonrd_pick_partition_with_breakout()` in `rvp9-core::mode_decision::nonrd_partition` (the `do_split` gate after the NONE pick, mirroring libvpx `:4004`/`:4140-4168`); the encoder implements the trait and plugs the real `ml_partition::ml_predict_breakout` (`lib.rs:3310-3409`) — NO core→encoder dependency. Speed feature `sf.rd_ml_partition.search_breakout` added (`speed_features.rs`, libvpx `vp9_speed_features.c:81-180`).

**Gate-speed finding:** the sacred gate runs at speed 7 / Realtime, where libvpx leaves `search_breakout = 0` — the pruner is libvpx-faithfully OFF at the gate's speed (gate unaffected). The PROOF runs at speed 1 / Good to exercise it.

PROOF (`tests/w_ml_partition.rs`, `a21_ml_partition_breakout_fires_and_decodes`): anti-G3 — pruner fired 265× at speed 1, 0× at speed 7 (gate doesn't leak); oracle — the speed-1 pruned stream byte-exact across rvp9-decoder + vpxdec. Sacred gate 4/4. Lib 429.

Scope-downs (honest, documented follow-ups): `ml_prune_rect_partition` (nothing to gate — A4 is square-only), `ml_pruning_partition` (speed-0 early-term), `ml_predict_var_rd_partitioning` (needs a `simple_motion_search` pre-pass).

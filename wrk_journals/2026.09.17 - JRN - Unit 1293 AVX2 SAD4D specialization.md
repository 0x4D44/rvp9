# Unit 1293 — retain compile-time AVX2 SAD4D dimensions

This unit tested candidate commit `1b6ff302362e0f9118e1ce6cacfc7cc726062849`
from the integrated `ffb19b50` tree. The candidate makes the x86-64 AVX2
`sad4d_avx2_inner` kernel const-generic over width and height. Its 13 wrappers
therefore compile fixed block dimensions into the reduction loops; the scalar
fallback, dispatch table, lane order, tie handling and all output values are
unchanged.

## Correctness

The candidate passed the focused AVX2 differential suite on native Crucible
x86-64: four tests covering edge content, dispatch round trips, shared-plane
offsets and randomized all-size cases. The full-pixel release suite passed all
19 tests. Local native AArch64 release checks passed the 19 full-pixel tests;
the AArch64 build does not compile the x86 AVX2 test module. Rustfmt and
`git diff --check` passed.

A deliberate mutation changed the W=32 lane-0 comparison to compare the source
against itself. Native Crucible x86 then failed
`differential_random_all_sizes` at `sad4d_avx2.rs:344` with `w=32,h=16` and
left/right values `0`/`43198`. The mutation was reverted, the four AVX2 tests
were rerun, and all passed.

## Disposition

Retain and integrate the candidate. It clears the one-percent plain and
production-PGO retention bars, reproduces on two independent PGO rotations,
and preserves exact output. The current direct parity is still far from the
`<=1.05×` target, so the next selection must refresh the integrated x86
profile rather than infer a hotspot from this unit.

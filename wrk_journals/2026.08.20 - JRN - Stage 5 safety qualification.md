# Stage 5 safety qualification

## Unit 1255 — release worker-scope borrows before completion

- The post-quality Miri sweep found a genuine Stacked Borrows violation in
  `WorkerPool::scope`, tracked as `RVP9-BUG-FLU-00028`. Each lifetime-erased
  worker wrapper retained the scope-local panic-list reference, sent its done
  message, and was only then destroyed by the worker loop. The caller could
  receive every done message and deallocate the panic list while the last
  wrapper still strongly protected that shared reference.
- `WorkerJob` now owns the erased closure and completion sender separately.
  `WorkerJob::execute` consumes and drops the closure under `catch_unwind`
  before sending completion. Caller-participating and queued jobs use the same
  ordering, preserving panic propagation and the unconditional join contract.
- Controlled-red evidence: a new 256-scope reuse regression deterministically
  aborted under Miri before the fix. It is green afterward. The complete
  tile-threading Miri suite passes 23/23, and the native tile-threading suite
  passes 23/23. Focused warnings-denied Clippy, rustfmt, and diff hygiene are
  green.
- Exact next work: commit this safety unit, finish the already-green
  motion-search scalar-Miri dispatch unit, then run the remaining
  mode-decision Miri surface before starting bounded fuzz and soak evidence.

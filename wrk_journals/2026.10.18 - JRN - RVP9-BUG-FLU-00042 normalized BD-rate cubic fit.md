# RVP9-BUG-FLU-00042 — normalized BD-rate cubic fit

The BD-rate solver lost accuracy when realistic PSNR values occupied a narrow range around 25–26 dB. The harness's raw-PSNR normal equations produced `-0.714401618768%` for the six-point rounded reproducer, while the Decimal80 reference over the same overlap is `-1.788791640314064%`. The benchmark had a second copy of the same solver and returned `-0.714401695614%`.

Each curve now fits its cubic in centered PSNR coordinates scaled to `[-1, 1]`. The fit retains that basis, and the overlap mean is evaluated directly using the normalized interval moments, avoiding both the raw-basis conditioning problem and cancellation between large antiderivative values. The solver rejects curves with fewer than four distinct PSNR values, invalid scales, non-finite matrix values, or pivots below the relative tolerance. BD-rate uses `exp_m1` for the final percentage and returns the existing NaN sentinel for non-finite results. The standalone benchmark now converts its points and calls the shared harness implementation, removing the duplicate solver.

Both new regression tests failed before the fix on their assertion: the harness returned `-0.714401618768%`, and the benchmark returned `-0.714401695614%`, against the expected `-1.788791640314064%`. After the fix, the harness BD-rate test group passed (24 tests), the benchmark binary test suite passed (21 tests), and scoped Clippy passed for `rvp9-harness --lib` and `rvp9-bench --bin bdrate`. `cargo fmt --all -- --check` and `git diff --check` passed.

The evidence covers the rounded six-point reproducer and local solver behavior. It does not re-run the full spatial quality campaign or replace its recorded unrounded observations.

# Dual-filter luma-prediction equality no-go

The prior filter-evaluator stage census showed 89,085 Ducks two-filter pairs and 390.8M measured luma-model cycles, leaving a small but countable question: do the two filters ever make the same active prediction, allowing reuse of the model result while retaining each filter's rate cost? The isolated diagnostic answered it on canonical 60-frame CPU6/CBR1260 encodes: Ducks 4/89,085, Tree 173/50,860, Town 436/47,431. Every IVF stayed exact. This rejects model reuse before a production-PGO build. Full evidence, identities and the patch are in [the census](../wrk_docs/evidence/2026-09-28-dual-filter-luma-equality-no-go/README.md); shipped code is unchanged.

The cross-family consultation also suggested an early partial-transform abort. Its premise was a repeated `block_yrd` on Ducks picker candidates, but the existing exact stage census says 99.700% of Ducks filter-evaluator candidates are model-only and only 0.060% call the round-trip. The consultation did not inspect this source, so that proposed bound is not accepted as a Ducks optimization candidate. Its duplicate-MV forwarding idea overlaps the prior strict-repeat evaluator census (0.414% Ducks calls). Follow-up needs a source-verified, operation-level target rather than another broad picker hotspot reading.

# Unit 1376 — AVX2 full-width subpel loads (rejected)

## Hypothesis

The AVX2 subpel variance kernels used bounded byte-copy loads for every
16-byte chunk. For full chunks in widths above 16, replacing those copies with
unaligned `_mm_loadu_si128` loads should reduce setup overhead while retaining
the bounded path for 16-wide and tail chunks.

## Correctness

The candidate passed all five `subpel_variance_avx2::tests` release tests on
Crucible x86:

- `production_wrapper_reuses_thread_local_scratch`
- `dispatch_round_trip`
- `differential_edge_content`
- `differential_temp_byte_identical`
- `differential_var_sse`

A deliberate `+1` source-offset mutation made
`differential_temp_byte_identical` fail at `w=16,h=16,xoff=0,yoff=0`; the
correct source was restored afterward. The AArch64 host remains cfg-excluded
from this x86-only module, and the candidate source was removed before this
journal commit.

## Kernel microbench

The candidate was faster on the larger full-width cases while leaving 16×16
neutral. Values are dispatch nanoseconds per call on Crucible:

| shape / offset | control | candidate |
| --- | ---: | ---: |
| 16×16 (0,0) | 23.3 | 23.4 |
| 16×16 (4,4) | 32.5 | 30.9 |
| 32×32 (0,0) | 61.7 | 61.6 |
| 32×32 (4,4) | 241.2 | 175.3 |
| 64×64 (0,0) | 202.2 | 206.6 |
| 64×64 (4,4) | 847.3 | 588.0 |

## Decision

Reject and do not integrate the source experiment. The kernel benchmark is
promising, but the whole-encode results change direction between identical
paired runs: one is 0.025% faster and the repeat is 0.609% slower. That is not
a reproducible Tesco-sized gain. The worktree now contains only this negative
evidence journal.

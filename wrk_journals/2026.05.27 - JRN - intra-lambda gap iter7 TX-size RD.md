# 2026.05.27 — JRN — Track-F iter7: per-block transform-size RD selection

## Goal

iter6 (commit 7b5d8e0) localized the remaining matched-Q PSNR gap to
**transform size**: rvp9 always coded `max_txsize(leaf_bsize)` and never
emitted 4x4/8x8 transforms (inter Y TX hist `[4x4,8x8,16x16,32x32] =
[0,0,15484,161]`), giving ~2.1x the SSE of vpxenc at the same bit budget.
libvpx runs a per-block TX-size RD loop (`super_block_yrd` /
`choose_tx_size_from_rd`). iter7 implements that loop on the encoder side.

## What shipped

**The TX-size RD loop** — `choose_inter_luma_tx_size`
(`crates/rvp9-encoder/src/lib.rs:5741`). libvpx ref
`vp9/encoder/vp9_rdopt.c` `super_block_yrd` / `choose_tx_size_from_rd` /
`txfm_rd_in_plane`. For an inter leaf the MC prediction is
TX-size-independent, so the residual is identical for every candidate
size. The loop walks `Tx4x4 .. max_txsize(leaf_bsize)`, and for each size
sums over the leaf's tiles: transform-domain quant distortion
(`vp9_block_error(coeff, dqcoeff) >> shift`, libvpx `dist_block`) + coef
rate (`cost_coeffs` with a leaf-local propagating above/left entropy
context). Picks the min-RD size via libvpx `RDCOST`. Runs on BOTH the RDO
(cpu≤4) and RT (cpu≥5) paths since both share the residual-coding
simulator — the gate at cpu7 gets the win directly.

**Integration** (all in `pick_and_simulate_inter_encode_partitions`,
`lib.rs`): the search runs once per leaf for plane 0 right after the Y MC
prediction is built (`lib.rs:5085`); `chosen_luma_tx` then drives the Y
coding walk + the UV cap and is stored on the leaf
(`InterPartitionLeafDesc::picked_tx_size`, `lib.rs:2261`).

**Signalling** (`frame_loop.rs`): inter frames now code
`tx_mode = TxModeSelect` (was `AllowTx32x32`). The modes writer already
had full `write_tx_size` select-tree support; the changes were (a) the
compressed-header `target.tx_mode` + the real tile pass + the TWO_LOOP
count pass all set to `TxModeSelect`, (b) `tx_mode_select=true` in the
show + ARF backward-adaptation calls, (c) the two mi-grid builders
(`build_inter_mi_grid_from_picker`, `build_inter_mi_grid_for_lf`) read
`leaf.picked_tx_size` for non-skip leaves and `max_txsize` for skip
leaves (the decoder derives `max_tx` for skip inter blocks where
`allow_select` is false — keeps the LF transform-edge mask in sync).

**The drift fix** (`crates/rvp9-core/src/bitstream/modes_writer.rs:1906`):
the writer accumulated per-context tx p-counts UNCONDITIONALLY, but the
decoder's `read_tx_size` only counts them in the selected branch
(`allow_select && TxModeSelect`). Harmless under `AllowTx32x32`
(adaptation ignored tx counts), but under `TxModeSelect` the over-count
on skip-inter leaves desynced the adapted `tx_probs` across the GOP —
frame 1 decoded clean, frame 2+ diverged 100M+ SSE. Gated the p-count
accumulation on the decoder's exact condition. `tx_totals` (encoder
bookkeeping, not consumed by adaptation) stays unconditional.

## Residual gap / honest scope

- **+0.5 dB at cpu7 1200k, below the +1 dB target.** The CBR rate
  controller reclaims some of the SSE win as bits (smaller transforms
  cost more coef header bits), so the PSNR-at-fixed-bitrate gain is
  smaller than the matched-Q SSE reduction. The cpu4 RDO path sees a
  larger gain (+0.88 dB) because its mode/partition decisions compound
  with the better TX sizes.
- **KF / intra path untouched.** The intra-in-inter and keyframe intra TX
  walks still pin `max_txsize` (KF Y TX hist still `[0,0,244,3]`). Intra
  prediction is causal and TX-size-dependent, so a faithful per-size RD
  search needs per-candidate recon simulation — deferred. The KF is a
  large slice of the remaining matched-Q gap (KF pred_PSNR ~19 dB).
- **Perf.** The full 4-way search adds ~70ms/frame at 720p speed7
  (135→205ms median, release). The realtime_gate (33ms budget) was
  already failing 4x pre-iter7 (a known open perf gap, not an iter7
  deliverable, and not in the iter7 gate list). A bounded RT-path search
  (e.g. max + max-1 candidates) is the obvious follow-up if perf becomes
  the binding constraint.

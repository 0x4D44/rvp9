# Unit 1374 — cache A4 hint segment IDs

## Change

The A4 inter-partition descent callback used `segment_id_for_hint_cell` for
each candidate leaf. That helper scans the superblock hint leaves linearly.
The callback now materialises the 8×8 segment-ID grid once per source
superblock and indexes it for each callback visit. The later grid is still
rebuilt from the selected tree, so this change does not reuse stale hint data.

## Correctness

- `cargo fmt --all --check` passed.
- Release tests passed on the AArch64 development host:
  `fixed_tree_hint_segment_grid_matches_point_lookup`,
  `realtime_cached_full_pick_requires_context_and_non_newmv_winner`, and
  `descent_pick_cache_covers_complete_superblock_key_space`.
- The segment-grid oracle was deliberately mutated to add one to every
  segment ID. The focused test went red (`left: 4`, `right: 3`), then the
  mutation was reverted and the worktree returned to the candidate.
- Crucible x86 built clean release control and candidate binaries. The paired
  screen produced identical IVF hashes for every clip and arm.

## Decision

Keep the cache as a bounded Tesco improvement and integrate it. It removes a
repeated linear scan from a ranked hot callback without changing the hint
mapping or selected-tree semantics.

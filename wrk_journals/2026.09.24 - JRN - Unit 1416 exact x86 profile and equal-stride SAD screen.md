# Unit 1416 — exact x86 profile and rejected equal-stride SAD screen

The Unit 1415 ETL, PDB, and executable were no longer present in Crucible's
documented scratch directory. I corrected that stale availability claim in
the earlier evidence README and ran a fresh exact profile from integrated
`5b6822c0`. Twenty serial 1080p Ducks encodes were output-identical. This
time the matching PDB and ETL yielded bounded raw-IP source attribution;
the hashes, direct-IP rows, line aggregates, and protocol are in
`wrk_docs/evidence/2026-09-24-unit1416-profile/README.md`.

The 16×16 AVX2 SAD4D symbol held 5.07% of weighted encoder samples.
DbgHelp maps 95.7% of that symbol's selected direct rows to the generated
wrapper call, so the profile does not isolate an arithmetic instruction.
The diamond caller's largest source line is MV-cost augmentation
(`full_pixel.rs:665`); the SAD helper's leading lines are reference
`block_at` and result packing. This profile is enough to bound a kernel
experiment, not to promise its speedup.

The experiment specialized equal source/reference stride for 16×16 SAD4D.
A new distinct-lane differential failed deliberately with lane 0 off by one
and passed when restored. Crucible passed five SAD4D and 20 full-pixel
tests; the AArch64 core suite passed 1,719 tests with two ignored. Both
release binaries used native target CPU and debug=2, and all three clip
hashes matched control in both paired screens.

Screen A gave a 0.998938 candidate/control paired corpus ratio. The
larger, quieter Screen B gave 1.002625, with Ducks 1.007265. The variant
is not a reproducible gain. Its generated code shares an offset but turns
the old fully unrolled kernel into a loop and adds a wrapper branch. The
exact patch and raw screens are archived in the evidence directory; the
source was restored to its integrated blob. No codec code from this unit
belongs on trunk.

The unchanged integrated encoder's last direct pinned-libvpx comparison
remains Unit 1415's 1.230937 paired corpus ratio. It is still above the
1.05 target. Next investigate `mvsad_err_cost_in_range` at the measured
`full_pixel.rs:665` call site, or another bounded hot kernel, with a
separate oracle and paired screen. Do not re-run the rejected SAD union
bounds or equal-stride variants without a different cost hypothesis.

# RVP9-BUG-FLU-00046 — complete AArch64 checked span validation

Arthur authorized a manual fixing drain with one fresh claimed worktree and one integration per Open bug. Deltic selected the sole Open record, RVP9-BUG-FLU-00046. Its first fix covered horizontal convolution; independent verification reopened it because the same record explicitly included unchecked sibling span guards.

The cause is unchecked multiplication/addition in slice-length preconditions: release arithmetic can wrap before the assertion establishes the footprint required by a raw-pointer kernel. This pass changes the validation layer, preserving representable footprints and kernel calculations. Regression inputs exercise arithmetic validators only; no invalid-pointer counterexample is executed.

`dsp/bounds.rs::strided_len` checks the zero-based last-row offset and final row width in slice elements. The existing checked x86 loop-filter footprint validator moves into the same module, with the original x86 module retaining its alias and tests. AArch64 filter entrypoints use that common checker for prefixes, end offsets and dual-strip starts. Vertical convolution also checks halo-height addition before forming its source footprint.

The complete recorded sibling checklist is covered:

| Unscaled convolution | Vertical source `(h+6)*stride+w`; full 2-D source `(h+6)*stride+w+7`; destinations `(h-1)*stride+w`. Horizontal and scaled convolution were already checked. |
| Copy | `h.saturating_sub(1)*stride+w`; existing supported-width zero-height behavior and scalar fallback retained. |

Fails-before evidence (release overflow checks disabled):

- The new shared strided-span regression executed one test with unchecked multiplication/addition and failed `accepted overflowing row offset: last_row=3 width=4`. Checked arithmetic passes the same regression, including the recorded minmax shape, final-width addition and exact tails.
- A scratch copy of the shared loop-filter validator with only checked arithmetic replaced by the original unchecked calculations executed its new test and failed `accepted overflowing filter window`. The real checked validator passes the same test. This isolated arithmetic proof never invokes a filter kernel.
- The three new private vertical-validator tests executed against the original guards and failed their own assertions: `accepted a wrapped source extent`, `accepted a wrapped destination extent`, and `accepted a wrapped halo height`. The final guards pass all three. The source test includes an accepted exact-tail control.

# RVP9-BUG-KIL-00103 — StreamEncoder speed validation

`EncoderConfig::speed` documents the range `-9..=9`, but the common streaming
encoder constructor did not validate it before constructing rate-control and
encoding state. Unsupported values therefore reached speed-feature dispatch.

This fix adds range validation in the common constructor and returns
`EncodeError::InvalidConfig` for an unsupported speed. Valid speed behavior and
the public configuration interface remain unchanged. The adjacent ledger bug
RVP9-BUG-KIL-00101 concerns lossless quantizers and is a separate defect.

Before the fix, `cargo test -p rvp9-encoder --lib stream_encoder_speed_`
selected two tests. Boundary acceptance passed. The rejection regression failed
its aggregate assertion: all four values `-10`, `10`, `i32::MIN` and `i32::MAX`
were accepted instead of returning `InvalidConfig`. All four constructor calls
ran before the assertion, so both signs and integer extremes are covered by the
observed failure.

After the guard was added, both speed tests and all 13 existing
`stream_encoder_rejects` constructor tests passed. The supporting acceptance
oracle was separately calibrated by substituting `[-10, 10]` for its boundary
inputs: it failed with `documented speed -10 was rejected`. Restoring `[-9, 9]`
made both speed tests pass again. This input calibration is separate from the
original rejection regression's fails-before evidence.

`cargo fmt --all --check` and `git diff --check` passed. Lead source review
confirmed the guard precedes rate-control/state construction and uses a direct
range comparison, including at integer extremes. No dependencies or codec
behavior within the supported speed range changed.

The selected final smoke is `cargo test -p rvp9-encoder --lib
stream_encoder_speed_`, bounded to 60 seconds after final fetch/catch-up.

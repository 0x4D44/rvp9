# Unit 1377 — A4 RD calibration cache

## Scope

The A4 partition-descent callback rebuilt `inter_rd_calibration_for_segment`
and its SVC model policy for every leaf. That function's only segment
dependency is baseline segment 0 versus any nonzero cyclic-refresh segment.
This unit computes the two completed values once per frame and selects the
appropriate cached value for each leaf.

## Correctness

- Local AArch64 release validation passed the A4 descent, descent-cache, and
  cyclic-refresh calibration tests before the Crucible screen.
- Crucible x86 release validation passed `descent` (6 tests),
  `cyclic_refresh_calibrates_baseline_and_boosted_segments_independently`, and
  `a4_rd_calibration_cache_selects_baseline_only_for_segment_zero`.
- The new selector test was deliberately mutated to swap the zero/nonzero
  branches. It failed on the baseline assertion, then passed after restoration.
- The existing build warnings for unused `frame_hf_energy` and
  `frame_hf_laplacian_sum_scalar` remain unchanged.

The canonical 1280×720@30/1 clips were regenerated from the Xiph prefixes and
matched the recorded manifests:

The A4-active runs used a temporary wrapper because `encode-headtohead`

otherwise identical.

## Crucible timing

The control and candidate were native release builds on Crucible. Runs used
one warmup, two reverse rotations, one thread, CPU-used 6, CBR 1260 kbps,
60 frames, and no strict host-load ceiling. Ratios are candidate/control;
values below 1.0 are faster. Every arm produced one stable IVF hash per clip,
and control/candidate hashes matched exactly:

| Screen | Ducks | In-tree | Old-town | Corpus paired geomean |
| --- | ---: | ---: | ---: | ---: |
| A4 canonical 1 | 0.641093× | 0.974650× | 1.485769× | 0.975530× |
| A4 canonical 2 | 0.584144× | 0.958083× | 0.663051× | 0.718605× |

The per-frame candidate times were 56–61 ms across the screens. Control times
varied much more under the relaxed host load, so the two screens are evidence
of a bounded cumulative gain, not a stable percentage claim for every clip.

The candidate IVF hashes were stable in both screens:

- ducks: `3f5f9d4367db14c7af82457a490dd9d6e6c230e8c5b3d140c3f641c64af826de`

- old-town: `ffc0ec57aae80ad54ef4102acdda770785386c1778b87aee06392fad8ea19bff`

For context, a relaxed-load comparison against the pinned libvpx `vpxenc`
measured `5.889104×` candidate/libvpx across the same A4-active setup. This
unit improves one hot callback path; it does not claim production parity.

## Decision

Keep the frame-level cache as a cumulative Tesco-sized, output-exact
optimization. It is ready to integrate, but the parity target remains open.

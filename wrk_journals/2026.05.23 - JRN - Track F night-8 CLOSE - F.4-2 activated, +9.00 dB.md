## Why the goal isn't met (and why it isn't reachable autonomously)

The night-8 F.4-1 calibration sweep (`notes/F4-calibration-sweep.md`)
established empirically that **parametric K1-K4 tuning of the
current picker bounds at ~0.1 dB**. The libvpx-default `<< 2` SATD
scale is wrong for rvp9 (DV-F1-1: rvp9 uses DCT qcoeffs where libvpx
uses Hadamard, magnitudes differ ~4×); K1=4 corrects this, gaining
0.07 dB.

The remaining ~8 dB is **structural**:

1. **DV-F1-1 (Hadamard port, F.1.2 in HLD terminology)**: would
   require porting `vpx_hadamard_{8x8,16x16}` (~150 lines scalar
   Rust) AND refactoring `reconstruct_via_round_trip` to expose
   `src_diff` so the Hadamard pass can run on the raw residual. The
   `crates/rvp9-core/src/transforms/` module is hands-off per
   CLAUDE.md (other team's WiP) — so the Hadamard kernel would land
   in `mode_decision/` instead. Expected gain: ~1-3 dB.

2. **Lambda recalibration in `compute_rd_mult`**: rvp9's
   `compute_rd_mult` is line-for-line a port of libvpx's, but
   libvpx's lambda is co-tuned with libvpx's `dist` choice
   (coef-domain, `block_error_fp >> 2`) and `block_yrd`'s Hadamard
   SATD. rvp9 keeps pixel-SSE-of-recon for `dist` (DV-F1-3) —
   different units, different operating point. The lambda formula
   in `rd_mult.rs` would need to be re-derived for rvp9's choices.
   Expected gain: ~1-2 dB.

3. **Motion-aware partition activation (F.3 default flip)**:
   `RVP9_F3_NONRD_PARTITION_ENABLE` would activate the motion-aware
   descent. Today the variance partitioner over-splits to 8×8 where
   `block_yrd` doesn't run, neutralising F.1's leverage on ~85% of
   foreman blocks. Expected gain: ~2-4 dB once F.1 actually fires.

4. **A18 default flip (F.2 default flip)**: `use_prev_frame_mvs:
   true` would close the chicken-and-egg degeneracy on NEAREST
   anchors. Currently regresses testsrc -240pp until F.1 makes
   NEWMV competitive — but the night-8 sweep proves F.1 alone
   doesn't make NEWMV competitive enough. Expected gain: ~1-2 dB.

5. **F.4-3 (skip-flag tie-break activation)**: blocked by the same
   `dist` saturation that blocked F.4-1 Phase B. Needs widening
   `rd_cost`'s API from `u32` to `u64` — touches the public
   `rate/dist` contract used across the codebase. Expected gain:
   ~0.5 dB.

**Each item is multi-hour or multi-day. Each one has architectural
implications that need Arthur's design review before implementation.
None is appropriate for unsupervised overnight execution.**

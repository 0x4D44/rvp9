## TL;DR

**Classification: ACCEPTABLE DEFERRAL.**

SVC is a distinct, optional ENCODE MODE that produces a layered (multi spatial/temporal) bitstream. It is NOT on the default single-layer encode path, and a single-layer VP9 stream is fully valid (decodable by vpxdec + ffmpeg) without any SVC code. The valid-stream gate is therefore unaffected. A18 is the same class of deferral as TPL (A23), HBD (A20), and coef-prob rate-parity (A6): it changes what *modes* the encoder can offer, not whether the default-path output is a VALID VP9 stream.

## 3. What SVC IS (framing)

SVC in VP9 is a distinct encode mode (libvpx `vp9_svc_layercontext.c`, driven by `vpxenc --spatial-layers`/`--temporal-layers` or the `vpx_svc` API / `vp9_spatial_svc_encoder` example) that packs multiple spatial/temporal layers into one superframe-structured bitstream. It is orthogonal to a normal single-layer encode: a single-layer VP9 stream never invokes the layer-context machinery. libvpx itself gates the whole subsystem behind `is_one_pass_svc(cpi) := use_svc && pass==0` (mirrored at `svc.rs:684`); with `use_svc=false` (the default), none of it runs.

## 4. Decision

- (a) Reachable/intended from CLI? **No.** `--svc` is parse-and-store dead in the bin, and an explicit `[not yet]`/error stub in `args.rs`.
- (b) Default single-layer path depends on SVC? **No.** `frame_loop.rs` has zero references; the one `use_svc` gate field is hardwired false.
- (c) Full-integration cost? Re-audit pass 3 estimates **~600 LOC of wiring** on top of the already-ported 1341 LOC (`REAUDIT pass 3` row 95). Prereqs it lists: A2/A3/A6/A10 — notably **buffer_pool wired into StreamEncoder** (A10, ~300 LOC, "Multi-ARF / SVC structural prereq", row 101), because the temporal setters assign `lst/gld/alt_fb_idx` into an 8-slot reference pool the StreamEncoder does not yet own. Realistic end-to-end (Svc on StreamEncoder + per-layer save/restore + superframe assembly + CLI `--spatial-layers`/`--temporal-layers` parsing + cross-decoder validation of a layered stream) is meaningfully more than 600 once buffer_pool, superframe index emission, and per-layer rate control are included.

## 5. Classification + rationale

**ACCEPTABLE DEFERRAL.**

The project's gate is a valid-stream gate, not an encoder-output-identity gate: `cargo test -p rvp9-encoder --test cross_decoder_gate -- --ignored` requires rvp9's output to be byte-exact DECODABLE by vpxdec + ffmpeg, not byte-identical to vpxenc. SVC is an optional encode MODE: enabling it would let rvp9 emit a *different kind* of (layered) stream, but its absence does not make the default single-layer output invalid or undecodable. The default encode path provably touches no SVC code (frame_loop.rs clean; the lone gate field is hardwired false). Therefore SVC's dead-zone status cannot fail the valid-stream gate — it sits in exactly the same deferral class as TPL/HBD/coef-prob-parity: a quality/feature-surface gap, not a stream-validity gap. The 1341 LOC are an honest, well-cited, test-backed scaffold parked ahead of an integration wave (and a buffer_pool prereq), not a correctness liability on the shipping path.

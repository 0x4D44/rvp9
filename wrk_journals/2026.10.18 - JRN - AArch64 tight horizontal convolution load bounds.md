# AArch64 tight horizontal convolution load bounds

RVP9-BUG-FLU-00039 is fixed in the horizontal AArch64 convolution wrapper. A checked footprint guard keeps the width-four I8MM loader on the scalar path unless 12 bytes are available, and routes I8MM/dotprod vector blocks to generic NEON when their 16-byte loads would exceed the accepted source slice. The public `w + 7` source extent remains accepted.

The new footprint regression failed before the guard was corrected: the initial `vector_w + 7` calculation incorrectly accepted the width-four 11-byte slice. After correction, the regression passed (1 test). The existing `single_axis_matches_scalar_all_filters_and_shapes` test passed on native AArch64 both in the release-style focused run and under the recorded nightly AddressSanitizer command (1 test; 5m35s build and run). Scoped `cargo clippy -p rvp9-core --lib --tests -- -D warnings`, `cargo fmt --all --check`, and `git diff --check` passed.

The separate unchecked arithmetic in `validate_horiz` remains outside this fix; it is tracked by RVP9-BUG-FLU-00046.

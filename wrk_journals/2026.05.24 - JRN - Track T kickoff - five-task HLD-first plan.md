## Operating model

- **Phase 1 (now):** Dispatch 5 HLD agents in parallel. Each gets a
  self-contained brief, must produce a `wrk_docs/Track_T/T<N>_HLD.md`,
  and must NOT write any production code.
- **Phase 2:** Lead reviews each HLD. Iterate with the agent (one
  round of revision is normal; two rounds means scope is wrong).
  Sign-off recorded in this journal with a one-line verdict per HLD.
- **Phase 3:** For HLDs whose scope is achievable overnight, dispatch
  implementation agents. Each must invoke `/code-reviewer` after the
  first draft and `/code-review-apply-feedback` to address findings.
  Bit-exact gates non-negotiable.
- **Phase 4:** Code-review-applied diffs come back to the lead. Lead
  validates bit-exact gates, runs bench gate where applicable, and
  commits if green.
- **Phase 5:** Close-out journal documents what shipped, what was
  HLD-only, and why.

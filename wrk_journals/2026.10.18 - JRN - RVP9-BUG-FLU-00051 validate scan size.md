# RVP9-BUG-FLU-00051 — validate scan size before coefficient decode

`decode_coefs` accepted a valid `ScanOrder` independently from `TxSize`. Its scan-length check was debug-only and after the EOB fast path, while the coefficient loop and context helper use unchecked scan and neighbor-table indexing. A 4×4 scan paired with `Tx32x32` could therefore pass the public API checks and reach an out-of-bounds static-table read when the token stream continued beyond scan position 15.

The public function now checks at entry that the scan and inverse-scan lengths match `tx_size.n_coeffs()` and the neighbor table length matches `(n_coeffs + 1) * MAX_NEIGHBORS`. These unconditional assertions run before the first EOB read, including for empty blocks. The API panic docs and the proof comment beside the unchecked accesses record the table-size contract.

The regression test was run first against the old implementation with overflow checks disabled. It failed because the safe EOB-at-zero stream returned without panicking; that input never reached an unchecked scan access. After the guard, the exact regression passed under the same release-style profile and reported scan length 16 versus transform size 1024. The focused detokenizer test module passed (55 tests). Scoped `cargo clippy -p rvp9-core --lib --tests -- -D warnings` and `cargo fmt --all -- --check` passed. The final exact regression smoke with debug assertions and overflow checks disabled passed in 10.41 seconds.

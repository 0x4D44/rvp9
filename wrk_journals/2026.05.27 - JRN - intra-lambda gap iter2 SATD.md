# 2026.05.27 — JRN — Intra/lambda PSNR gap iter2: SATD rate-proxy hypothesis (NEGATIVE)

## Context

Track-F iteration 2 — Arthur's directive. Previous agent (iter1, commit
`f971c4e`) removed the KF active-quality cap. Per the iter1 numbers,
`foreman_320x256_60f.y4m` at cpu7 + 1200k still showed a ~3.13 dB mean
PSNR gap to vpxenc (rvp9 38.07 vs libvpx ~41.20). Iter1 agent's
working hypothesis for iter2: the intra mode-RD path uses `block_yrd`
SSE distortion but libvpx uses SATD/Hadamard — switching distortion to
SATD should close the gap further.

## Investigation — actual libvpx intra picker

`vp9/encoder/vp9_pickmode.c:1156-1214` (`vp9_pick_intra_mode` — realtime
path, cpu ≥ 5) calls `estimate_block_intra` → `block_yrd`. Reading
`block_yrd` at `vp9_pickmode.c:719-845`:

- **Forward transform**: Hadamard (cheap proxy for DCT in the RD search).
- **Distortion**: `vp9_block_error_fp(coeff, dqcoeff, ...) >> 2` =
  `sum((coef[i] - dqcoeff[i])^2) >> 2`. Pure SSE in transform-coef
  domain — the iter1 agent's premise that libvpx uses SATD as
  distortion is INCORRECT.
- **Rate (token-side proxy)**: `vpx_satd(qcoeff, n)` scaled by
  `<< (2 + VP9_PROB_COST_SHIFT)` (line 843) plus `eob_cost <<
  VP9_PROB_COST_SHIFT`. THIS is where the SATD lives — it's a rate
  proxy on the *quantized* coefficients, not a distortion metric.

So the real libvpx-vs-rvp9 picker divergences are:
1. rvp9 uses real DCT (`fht*`) for the forward transform; libvpx uses
   Hadamard. (Net effect: rvp9's distortion estimate is strictly more
   accurate. This is NOT a gap source.)
2. rvp9's picker rate = `mode_cost_row[mode]` only — the mode-coding
   probability cost. libvpx's rate = `mode_cost + (vpx_satd(qcoeff)
   << 11) + (eob_cost << 9)`. **rvp9 was missing the coefficient-rate
   proxy entirely.**

## Implementation — SATD-on-qcoeff rate proxy

Added `block_yrd_satd_rate_qcoeff(qcoeff, n)` helper next to the
existing `block_yrd_distortion` in
`crates/rvp9-core/src/mode_decision/intra.rs`. Implements `sum(|qcoeff[i]|)`
exactly per `vpx_dsp/avg.c:334-341` (`vpx_satd_c`).

Wired into both `pick_intra_mode_luma` and `pick_intra_mode_uv`:
```rust
let satd_qcoeff = block_yrd_satd_rate_qcoeff(&qcoeff[..n], n);
let satd_rate_term = satd_qcoeff.saturating_mul(1u32 << 11);  // <<11 per libvpx
let rate = mode_cost.saturating_add(satd_rate_term);
let this_rd = rd_cost(lambda, rate, dist);
```

Three unit tests added (all-zero, known-value, max-dynamic-range).
The 15-test intra-module suite passes.

## Why the change had no effect — per-frame breakdown

Per-frame PSNR on cpu7/400k (frames 0..29):

```
frame    rvp9     vpx     gap
  0 (KF) 53.71   57.08   -3.37
  1      34.57   37.65   -3.08
  2      33.94   35.64   -1.70
  3      33.78   34.98   -1.20
  ...
 10      32.74   36.07   -3.33
 ...
 28      32.41   37.77   -5.36
```

**The 4-5 dB mean gap is overwhelmingly an INTER-frame gap.** The KF
contributes one frame in 30 (the GOP length); the other 29 frames are
inter. rvp9's inter frames sit at 32-34 dB; libvpx's at 35-38 dB. Even
a 3 dB gain on the KF would only lift the mean by ~0.1 dB; the inter
gap dwarfs everything.

The intra picker was already producing reasonable mode choices via
`block_yrd_distortion` (transform-coef SSE) alone. Adding the
SATD-on-qcoeff rate proxy is a *correct* libvpx-faithfulness fix —
the picker is now more rate-aware — but the picker's mode choices
matter only for the keyframe leaves, and KF leaves were not the
dominant gap source. **Hypothesis falsified.**

## Localization for iter3

The inter picker (`mode_decision/inter.rs`) already uses
Hadamard + `satd_i16` for the rate proxy (lines 2952-3000) — the full
libvpx-faithful `block_yrd` pattern is wired through. So the inter
gap is NOT a missing-SATD issue.

Hypotheses to investigate next, ordered by suspect:

1. **Motion search depth / sub-pel refinement.** libvpx's `--rt
   --cpu-used=7` runs a specific NSTEP / sub-pel cascade. If rvp9's
   motion search converges to suboptimal MVs, residual is large,
   PSNR drops uniformly across inter frames — matches the observation.
2. **Lambda scaling for inter frames.** `compute_rd_mult(qindex,
   FrameTypeForRd::Inter)` may be calibrated wrong for `--rt --cbr`.
   Symptom would be the same: too-low lambda → too-coarse quant on
   the residual.
3. **Inter mode candidate set.** libvpx-realtime evaluates a specific
   12-entry `ref_mode_set` (vp9_pickmode.c:1239). rvp9 may evaluate a
   different set or skip candidates.
4. **NEWMV vs NEARESTMV rate weighting.** The `compound_newmv`
   discount path (commit b8d2327) interacts with the rate proxy here.

The aggregate gap of 3-4 dB on inter frames at 400k cpu7 is too large
for any single fine-tuning fix — likely needs a structural audit of
the inter mode-search pipeline.

## Take-away

iter1 closed the KF-cap gap (real win). iter2's hypothesis was based
on a misreading of libvpx's `block_yrd` — SATD is a rate proxy on
qcoeff, not a distortion metric. Even after wiring the correct rate
proxy faithfully, the change moved aggregate mean PSNR by ≤0.1 dB
because the picker only governs KF mode choice and the gap lives in
inter frames. Iter3 should audit the inter pipeline (motion search,
lambda scaling, mode candidate set) — that's where the 3-4 dB lives.

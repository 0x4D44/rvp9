# Enforce advertised F02 strict fields — KIL-00084

The F02 block oracle advertised `q_index`, `tx_size`, and `luma_eob_nonzero` as strict fields, but its pairwise comparison omitted all three. A divergence isolated to any one of them therefore remained a match. The paired decision serializer also omitted their values, limiting diagnosis.

The bounded correction adds these three comparisons and emits both legs' quantizer, canonical transform-size tag, and boolean luma-EOB status in paired JSONL. The existing `require_match` policy continues to reject divergence in strict mode and allow it in report-only mode. Record alignment, count validation, diagnostic-only costs, and codec behavior remain unchanged. Separately tracked duplicate-key parsing and child-process isolation work is outside this fix.

Regression proofs observed by the worker:

- On the original comparator, isolated `q_index`, `tx_size`, and `luma_eob_nonzero` changes each failed their mismatch-count assertion: expected one, observed zero. Each test also requires exactly the changed field name, strict failure, and report-only success.
- After adding only the comparator checks, those three tests passed and the paired-JSON test failed its typed-value assertion: rvp9 quantizer was JSON null instead of 143. Adding the serializer fields fixed that independent gap.
- Deliberately adding `ref_bits_est` to strict comparison failed the diagnostic-only acceptance control: expected zero mismatches, observed one. The mutation was restored manually.

Identical-record and diagnostic-only controls preserve their non-failing policy. Paired JSON is parsed with the existing serde_json dependency and checks both legs' actual values and all three mismatch names. The worker and lead each passed the 22-test `cargo test -p rvp9-harness --lib f02_schema::` module and 19-test `cargo test -p rvp9-harness --bin f02-block-oracle` binary unit suite. The worker also passed scoped library Clippy with warnings denied, rustfmt and diff checks. Tests ran with task-local `TMPDIR`, closed stdin, and a Deltic timeout. No real patched-libvpx run or codec-parity result is claimed.

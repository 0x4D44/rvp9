# Production timing batches resume across quiet leases

RVP9-BUG-FLU-00047 showed that the production timing matrix could exceed a single Deltic quiet lease while the runner refused any restart after timing evidence appeared. The runner now resumes speed at complete speed-group boundaries and latency at complete feature/mode/target/CPU groups. Each complete batch has a receipt bound to the run fingerprint and a stable SHA-256 of its retained artifacts. Resume reuses only valid receipts; an interrupted group stays on disk and is rerun whole in a new numbered attempt. The output tree publishes through one final directory rename after canonical summary files are present.

The regression assertion failed before the implementation with `resume self-test: sealed timing batch could not resume` (exit 1). After the change, `bash -n scripts/qualify-production-encoder.sh`, `--self-test`, `--self-test-resume`, and `--self-test-timing` passed. The timing self-test used stubs and verified one completed group is reused, the interrupted group is preserved and retried, and resumed speed and latency summaries contain no duplicate rows. An initial 120-second timeout expired before the latency-resume fixture finished; the same timing test passed with a 240-second bound.

No real encoder timing or performance result was produced. The full production matrix remains subject to its normal host-load guards. The code commit left the ledger Open; after integration, `deltic bugs land` recorded Fixed provenance for `056ddb1839c3caa22bffcc048f06305e4cfb3974` and cleared the owner. This docs follow-up fills the ledger's fix summary without changing its state history.

# 2026.05.26 — JRN — CLI reachability landed

## Goal

Make ~3000 LOC of already-implemented, byte-exact-verified VP9 encoder
features reachable from the `rvp9enc` CLI. Re-audit pass 3
(`wrk_docs/2026.05.26 - REAUDIT pass 3 - inventory refresh.md`, commit
511ee0e) found VBR/CQ/Q rate control and ALTREF/compound prediction all
work and pass byte-exact PROOF tests, but a CLI user could not trigger
them because ~65 LOC of plumbing was missing. This session was that
plumbing — no kernel/algorithm work, pure wiring + an anti-G3 oracle.

## The two gaps (both confirmed by the re-audit, file:line)

1. **Rate-control mode CLI-unreachable.** `EncoderConfig` had no
   `rc_mode`/`cq_level` field; `to_rate_control_config` fell straight
   through `..defaults` so the controller always saw Cbr/0. `--end-usage`
   only accepted the literal `cbr` (`validate_eq(v, "cbr", ...)`). The
   controller itself was fully ready: `RateControl::pick_q_and_bounds`
   (`rate_control/state.rs:279`) already dispatches all four one-pass
   arms (Cbr/Vbr/Cq/Q) — only the 2-pass driver is deferred.
2. **ALTREF CLI-unreachable.** `enable_alt_ref: false` was hardcoded at
   the CLI construction site; `--auto-alt-ref` was parsed into
   `opts.auto_alt_ref` (0..=6) but never consumed.

## What landed

### Encoder (`crates/rvp9-encoder/src/frame_loop.rs`)
- Added two public fields to `EncoderConfig` after `enable_alt_ref`:
  `rc_mode: RcMode` and `cq_level: u8`, with doc comments citing
  `vpxenc.c --end-usage` / `--cq-level` (`vpxenc.c:385`) and
  `vpx_encoder.h enum vpx_rc_mode`.
- Imported `RcMode` into `frame_loop.rs` and re-exported it at the
  encoder crate root (`lib.rs`) since it is now part of the public
  `EncoderConfig` surface.
- `to_rate_control_config` now carries `rc_mode: self.rc_mode` and
  `cq_level: self.cq_level` (keeping `..defaults` for the rest).
- `EncoderConfig::new(...)` sets `rc_mode: RcMode::Cbr, cq_level: 0`.
- Refreshed two stale doc comments (`rate_control/mod.rs`,
  `rate_control/state.rs`) that still claimed "only CBR is ported / the
  other arms panic" — now reflects that all four one-pass arms are live.

### CLI (`crates/rvp9-cli/src/bin/rvp9enc.rs`)
- Added `rc_mode: RcMode` to `EncOpts` (+ default `RcMode::Cbr`).
- `--end-usage` now accepts `cbr|vbr|cq|q` via a new `parse_end_usage`
  helper (modeled on `parse_aq_mode`); unknown modes reject (not silent
  fallback to Cbr).
- **Refactored** the production builder and the test helper into one
  shared `build_encoder_config(opts, w, h, fps, bitrate)` — the SINGLE
  CLI→encoder source of truth. This removed a duplicated literal AND
  makes the PROOF test exercise the exact production mapping.
  - `rc_mode: opts.rc_mode`
  - `cq_level: opts.cq_level.map(|v| v.min(255) as u8).unwrap_or(0)`
  - `enable_alt_ref: opts.auto_alt_ref.map(|v| v > 0).unwrap_or(false)`

### CLI struct-literal sweep
Every compiled `EncoderConfig { ... }` literal gained
`rc_mode: RcMode::Cbr,` + `cq_level: 0,` (preserving Cbr behaviour),
anchored strictly on each literal's `enable_alt_ref` field line (value
form `: false,`/`: true,` and the 2 shorthand `enable_alt_ref,` cases).
**73 literals** in total were swept (71 via script across 26 files + 2
in `rvp9enc.rs` handled by hand as part of the shared-builder refactor).
Each swept file also got `RcMode` added to its `use rvp9_encoder::{...}`
group import (RcMode is re-exported at the crate root).

The re-audit estimated ~28 literals; the true count is 73 — `frame_loop.rs`'s
own `#[cfg(test)]` module alone holds 39 full literals (its spread
literals `EncoderConfig { field, ..base }` correctly need nothing and
were left untouched, since the anchor only matches full literals).

## PROOF (anti-G3, end-to-end CLI reachability)

Two new tests in `rvp9enc.rs`'s `#[cfg(test)] mod tests` (the existing
W5.1/W7.8 PROOFs live here; `build_encoder_config`/`EncOpts`/`flag_table`
are binary-private so an external `tests/` file can't reach them):

- `reaudit3_end_usage_plumbs_into_rate_control` — parses
  `--end-usage=vbr|cq|q` (+ bitrate/dims), asserts `EncoderConfig.rc_mode`
  AND, critically, `StreamEncoder::new(cfg).rate_control().config().rc_mode`
  (proves the mapping reached the controller, not just the parser).
  Asserts `cq_level` for cq/q, clamp to 255, and unknown-mode rejection.
- `reaudit3_auto_alt_ref_plumbs_into_encoder_config` — `=0`/absent →
  false; `=1`/`=6` → true.

Both FAIL if the plumbing is stripped (reverting to hardcoded Cbr/false
would flip the controller-side assertion). Also repurposed the now-stale
integration test `enc_end_usage_vbr_rejected` →
`enc_end_usage_unknown_rejected` in `tests/cli_arg_coverage.rs` (vbr is
now accepted; bogus rejects).

## Surprises / notes

- The literal count (73 vs estimated ~28) was the main surprise. The
  strict `enable_alt_ref`-anchored sweep handled it cleanly; a dry-run
  match-set listing + sample reads confirmed every match was a genuine
  full literal before applying.
- One self-inflicted snag: the sweep matched the `new()` constructor's
  `enable_alt_ref` line, which I'd already hand-edited — produced a
  "field specified more than once" compile error, fixed by deleting the
  duplicate bare pair. Caught immediately by `cargo build`.

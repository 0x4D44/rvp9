# Wave E — Hardening Extension

Wide rollout of the AVX2 dispatch surface + parallel-decode
maturation. Six unblocked deliverables, dispatched sequentially.

## Sub-sequencing rationale

Order: most self-contained first, riskiest last. This lets a late
failure on a risky piece cleanly fall back to a "5/6 shipped"
state rather than blocking the whole wave.

1. **G5.2** — arena pool. Self-contained refactor (frame.rs +
   lib.rs). Eliminates 1.44 GB/s alloc churn from G5.1.
2. **G4-α** — idct32x32 AVX2. Biggest single kernel addition; new
   slot, no refactor of existing code.
3. **G4-β** — AVX2 ADST 4x4 + 8x8 kernels. Drops into the
   scalar-only slots created in Wave D G4.3a.
4. **G4-δ** — iht16x16_add slot + idct16x16 EOB fast paths
   (10/38 EOB-bucket sparse-block optimisations).
5. **G4-γ** — full-1D AVX2 vectorisation refactor. Touches
   established working kernels (idct4x4, idct8x8, idct16x16) —
   highest regression risk, last in order.
6. **G5.3** — tile_rows > 1 parallelism. Generalises G5.1.

The risky piece — refactored existing idct8x8 AVX2 from
finisher-only to FULL-1D vectorisation. **Bit-exact**.

libvpx SSE2 (Option A). Reason: libvpx's `_mm_packs_epi32` is

on pathological i16::MAX inputs. The proptest's
`pathological_strategy` would catch this. Hand-derive in i32
lanes with explicit `srai(slli(_, 16), 16)` — exact `as i16 as
i32` truncation. 360 lines added, 98 removed. Single-kernel scope
(remaining 3 AVX2 kernels + iht hybrids stay finisher-only as
Wave F).

## Lessons captured

1. **Agent session limits are real**. The G4-α implementer ran
   ~24 min and ended with "test is still building" mid-validation.
   Supervisor took over directly. Pattern: if agent stalls mid-
   validation, inspect worktree directly, run tests as supervisor,
   commit if clean. Don't dispatch a new agent for completion work.

2. **`cd` into worktree contaminates the supervisor's bash session**.
   When I ran `cargo build` inside the worktree directory, my
   subsequent bash commands kept inheriting that working directory.
   Workaround: always pass `-C <path>` to git, use absolute paths
   for cargo, or explicitly `cd /d/language/rvp9-2` before mainline
   commits.

3. **Squash conflicts are mostly additive merges**. Out of ~30 total
   conflict regions resolved during Wave E, ~28 were trivial
   "include both halves" + light text-shifting. Only the G4-γ
   bit-exactness decision involved nontrivial supervisor judgment.
   This argues for keeping the per-deliverable squash pattern (vs
   monolithic Wave E merge).

4. **Single-kernel scope for G4-γ paid off**. The implementer
   picked idct8x8, hand-derived bit-exactly, and shipped. Trying
   the full-1D refactor for all 4 kernels in one round would have
   exhausted the implementer's context window + introduced
   bit-exactness risk on each kernel. The remaining 3 kernels +
   iht hybrids are Wave F follow-ups.

5. **Hand-resolved merges work when conflicts are additive**.
   For G4-δ's 8-region dispatch.rs conflict, supervisor-resolution
   took ~10 minutes vs dispatching a separate merge-resolution
   agent. Faster for additive cases; agent dispatch is right when
   conflicts require semantic understanding of the diverged code.

# Repeated exact Tree IP profile

Nine same-image Crucible captures of the post-zero-EOB integrated encoder
(`48cab42d` code image) yielded 94,152 direct EXE samples with exact Tree IVF
output and zero trace loss. The checks, exact PE/PDB identity, run records and
aggregate IP/RVA tables are in
`wrk_docs/evidence/2026-09-26-repeated-tree-profile/`. `xperf -ProfInt` read
0.1221 ms after the campaign, consistent with the unusually dense samples;
it was not recorded per run. These counts cannot be compared directly with
older ~1 ms profiles; none is a CPU speed measurement.

The generic AVX2 sub-pixel variance body accounts for 15.46% of Tree samples,
but the complete first horizontal pass is 3.43%. The previous census says an
immediately reusable horizontal key occurs in only 13.25% of Tree two-axis
calls. That bounds a free one-entry cache at about 0.45% whole-process sampled
work before lookup/copy cost, so the earlier cache idea is not a justified
production trial. The leading exact RVAs are mostly necessary dot products,
filter shuffles, and loop backs. Other apparent source-line hotspots likewise
resolve to necessary arithmetic or trivial instructions following a call.

No code was changed or retained. The latest uninstrumented three-clip
RVP9/pinned-libvpx ratio remains 1.134647×, above the ≤1.05× goal. The next
selection needs a changed mechanism with a larger realistic ceiling: isolate
32×32/64×64 sub-pixel shape cost with exact kernel microbenching or caller
attribution, then run a bounded differential and paired CPU screen. The old
16×16 fused candidate was already exact and neutral, so do not repeat it.

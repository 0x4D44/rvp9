# v0.2.0-alpha.1 release qualification

## Identity and scope

- Candidate source at session start: `61facabad271578da525b575ea4f6e2be326b8a2`.
- Reference encoder and decoder: pinned libvpx v1.14.1 commit
  `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`.
- Intended label: `v0.2.0-alpha.1`.
- Intended claim: an 8-bit, one-pass realtime VP9 encoder and decoder preview
  for CPU6--8, including VBR, CBR, cyclic-refresh AQ, denoising, and two- and
  three-layer temporal SVC. It is not production parity and does not include
  spatial SVC.
- `TESTING-GUIDE.md` is absent. This session therefore uses `CLAUDE.md`, the
  checked-in harnesses, and the generic testing-session diagnostic discipline.

## Qualification plan

1. Expand the official-vector fetch surface from its Stage 0 subset to the
   complete pinned VP9 conformance manifest, with content-hash verification.
2. Run every official vector in strict mode on the ordinary decoder, then
   repeat across scalar and serialized decoder paths where the harness supports
   them.
3. Run the full workspace gate, the checked-in real-world/profile/tile decoder
   suites, and a bounded parser-fuzz pass.
4. Exercise a representative encoder matrix across CPU6--8, VBR/CBR, AQ3,
   denoising, temporal T2/T3, thread/tile variants, and cross-decode every
   generated stream through rvp9-decoder, pinned vpxdec, and ffmpeg.
5. Qualify portable release binaries, their licence and patent notices, CLI
   version/help behavior, archive contents, and checksums.
6. Integrate the exact candidate, tag it, and publish a prerelease only after
   all release-blocking evidence is green. Preserve every limitation in the
   release notes.

## Decision trail

- 2026-08-12: Arthur approved a deliberately scoped alpha before spatial SVC
  and asked for wider testing first. The release can proceed without claiming
  the unresolved quiet-host CPU8/T3 relative-speed gate, but the provisional
  speed status must be explicit.
- 2026-08-12: The repository currently has no tags, release runbook, or hosted
  workflow. The alpha therefore needs an explicit local qualification and
  packaging path rather than relying on an existing release automation lane.
- 2026-08-12: The existing `scripts/fetch-vectors.sh` names only fifteen Stage
  0 vectors, while `PLAN.md` records a prior 191-pass conformance run. A pinned,
  hash-verified full-vector fetch is the first test-infrastructure unit; testing
  only the surviving subset would not satisfy the requested wide pass.

## Findings

No release-qualification defect has been observed yet.

## Unit A1 — complete pinned vector provisioning

- Initial candidate `61facaba` was confirmed to carry the exact libvpx pin but
  no initialized submodule or fetched vector set. Initializing the submodule
  exposed 307 valid 8-bit Profile 0/1 VP9 streams with sibling decoded-output
  MD5 ledgers in pinned `test/test-data.sha1`. This is wider than both the
  fifteen-name Stage 0 fetch script and the older 201-vector PLAN result.
- Replaced the static Stage 0 list with manifest-derived selection. The script
  now refuses a wrong or missing libvpx revision, excludes malformed-input,
  VP8, high-bit-depth Profile 2/3, and encoder-only media, downloads the 307
  paired stream/ledger files concurrently, and verifies every file against its
  pinned SHA-1 before publication. Existing files are also verified and a
  mismatch fails without overwriting them.
- Added `--list` as a network-free structural oracle. `bash -n` passes; the
  list contains 307 unique entries, no Profile 2/3 entry, and includes the
  profile-1 and SVC tails. The next step is an actual full fetch followed by
  strict conformance on every resulting vector.
- Release-readiness testing also reproduced a public setup-document defect:
  `README.md` names nonexistent `scripts/fetch-vectors.ps1`. It is tracked as
  `RVP9-BUG-FLUX-00018` and remains Open for an independent fix.

## Unit A2 — official ledger compatibility

- The first strict run over all 307 fetched vectors reached 4,654 displayed
  frames: 4,624 passed, 30 mismatched, and six vectors failed structurally.
  The failures were independently reproduced with an isolated seven-vector
  directory and recorded as `RVP9-BUG-FLUX-00019` through `00022`.
- Two structural failures were a harness defect, not decoder failures. The
  pinned `vp90-2-19-skip.webm` and `vp90-2-19-skip-01.webm` ledgers use
  ordinal-only names such as `01.yuv`; the parser previously required every
  name to contain dimensions. It now accepts the exact ordinal form, retains
  sequential-index validation, and uses the decoded buffer dimensions only
  for verbose output.
- Focused parser and conformance tests pass, clippy is warning-free, and both
  affected official streams pass all 120 displayed-frame MD5 checks in strict
  release mode. The remaining release blockers are three tile/skip decode
  errors and the 20-frame subpixel mismatch. The spatial-SVC vector remains a
  separately tracked post-alpha limitation.

## Unit A3 — vertically adjacent tile state

- The subpixel vector and the two multi-row tile vectors had one root cause:
  rvp9 treated a tile-row boundary as a complete decoder-state boundary.
  Pinned libvpx permits above-neighbour mode reads across tile rows and keeps
  coefficient and partition above-contexts for the whole frame, resetting only
  the left contexts at each superblock row.
- Production frame-grid views now preserve those asymmetric bounds: tile
  columns remain isolated, but a lower tile row can read the completed row
  above. Multi-row tiles run in raster order because the current worker-owned
  reconstruction surfaces cannot provide the required row barrier. One
  coefficient/partition above-context is retained per tile column across rows.
  The public single-tile decode API remains unchanged.
- Focused context tests, all 216 decoder unit tests, the 14 conformance-coverage
  tests, four panic-safety tests, decoder clippy with warnings denied, rustfmt,
  and diff checks pass. Exact strict runs pass `vp90-2-09-subpixel-00.ivf`
  20/20, `vp90-2-08-tile-4x1.webm` 5/5, and
  `vp90-2-08-tile-4x4.webm` 5/5. The subpixel vector also passes forced-scalar,
  loop-filter-disabled, and combined variants.
- A fresh strict run over all 307 vectors improves the result to 4,774 passed,
  10 mismatched, zero skipped, and two structural failures across 4,784
  decoded frames. The remaining supported-path blockers are the ten luma-edge
  mismatches in `vp90-2-03-size-226x210.webm` and the packet-six residual
  entropy failure in `vp90-2-19-skip-02.webm`. The spatial-SVC selection error
  remains the declared post-alpha limitation.
- Five of seven tile-threading integration tests pass. The two conformance
  aggregators stop only on the already tracked `skip-02` decoder failure, so
  that suite cannot become wholly green until the next correctness unit.

## Unit A4 — public AVX2 predictor safety

- The release-blocker audit confirmed `RVP9-BUG-KILN-00020` still had a
  defective prior fix: the public AVX2 V_PRED wrapper checked its CPU and slice
  preconditions in release builds, but rejected the encoder's supported 64x64
  scalar-fallback case.
- Split the storage arithmetic from the fixed-width SIMD-size check. The public
  AVX2 V_PRED boundary now accepts exactly the four SIMD sizes plus the
  intentional checked 64x64 scalar fallback, while invalid sizes, short edges,
  short destinations, bad strides, overflow, and non-AVX2 hosts still fail
  before any raw pointer access.
- Focused storage, 64x64 picker, and `w_tpl` encoder tests pass on AArch64.
  The complete x86_64 all-target source surface cross-compiles on macOS, and
  the x86-only AVX2/scalar dispatch differential now includes 64x64. Native
  x86 execution remains part of the release matrix rather than being inferred
  from this cross-compile.

## Unit A5 — external-data tests cannot false-green

- `RVP9-BUG-KILN-00063` identified four tests that could report success after
  comparing no external inputs. The harness and core crates now detect their
  conformance data at build time and mark the dependent tests visibly ignored
  when it is absent. If data disappears after compilation, the tests fail
  instead of returning early.
- The real-world decoder fixtures are committed repository inputs, so an empty
  fixture set is now a hard failure rather than a printed skip.
- With no conformance data, both captured core oracles and the harness walker
  report explicit `requires scripts/fetch-vectors.sh` ignores. With the pinned
  resize vector present, both core oracles execute and pass; the harness walker
  executes and enforces its 201-frame corpus floor. The two committed
  real-world streams execute 43 decoded frames, including one hidden frame,
  with 42/42 visible MD5 matches. Focused clippy with warnings denied, rustfmt,
  and diff checks pass.

## Unit A6 — isolated tile scratch-allocation evidence

- `RVP9-BUG-KILN-00062` made the tile scratch reuse test sample a
  process-global allocation counter while sibling tests allocated concurrently.
  The test now reads a monotonic allocation count owned by its decoder's own
  `Yv12ScratchPool`; unrelated decoders cannot enter that measurement window.
- The instance counter increments only beside a successful fresh scratch-frame
  allocation. Existing process-wide instrumentation remains available, and
  the hot reuse path gains no atomic or allocation work.
- Core pool growth and warm-reuse tests pass. Four multi-tile tests ran in
  parallel ten consecutive times with fetched official vectors: 40/40 test
  executions passed, including an exact first-frame count of eight isolated
  scratch frames and zero later-frame allocations. Focused clippy with warnings
  denied, rustfmt, and diff checks pass. The full seven-test binary still awaits
  the separately tracked `skip-02` decoder fix.

## Unit A7 — release-valid core test semantics

- `RVP9-BUG-FLUX-00008` expected a panic from `debug_assert!` in both Cargo
  profiles. The unsupported-block-size regression remains active and passing in
  debug builds, while release builds now report it as explicitly ignored with
  `requires debug assertions` instead of failing after the assertion is
  compiled out.

## Unit A8 — parent-block-aware intra edge extension

- `RVP9-BUG-FLUX-00023` was a silent luma mismatch on the official
  `vp90-2-03-size-226x210.webm` vector. The first pre-filter divergence was a
  hidden padded-edge pixel read by a 4x4 D63 transform inside a partial
  16x32 coding block.
- Pinned libvpx selects its slow right/bottom reference-extension paths from
  the parent coding block's signed frame-edge distances. rvp9 instead derived
  clipping only from the current transform, so it read padded samples beyond
  x=231 rather than replicating the last in-frame reference.
- The decoder now passes the existing parent-block clipping flags to the core
  intra edge builder. The original public helper keeps its coordinate-derived
  behavior for encoder and test callers. A focused D63 oracle covers a
  transform that fits the padded plane while its parent crosses the edge.
- Strict native and forced-scalar conformance pass all 30 frames across the
  adjacent 226x208, 226x210, and 226x224 vectors. The formerly failing
  226x210 output is byte-identical to pinned vpxdec for all ten frames
  (SHA-256 `475f82ab66469cd569fdfb2fe9bd140af099007ce398381ab28156bbe283eee4`).
  All 58 intra-prediction tests, all 216 decoder unit tests, all 14 decoder
  conformance-coverage tests, all four decoder panic-safety tests, focused
  clippy with warnings denied, and rustfmt pass.

## Unit A9 — preserve the last enabled segmentation map

- `RVP9-BUG-FLUX-00020` remained on official vector
  `vp90-2-19-skip-02.webm`. A disabled frame replaced rvp9's previous
  segmentation map with zeros. The next frame re-enabled segmentation with
  `update_map == false`, inherited segment zero instead of segment one in its
  first block, and immediately desynchronised the entropy reader.
- Pinned libvpx revision `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`
  swaps current and previous segment maps only when segmentation is enabled.
  Rvp9 now follows that lifetime rule on inter frames. Keyframe and intra-only
  reset behavior remains unchanged.
- Two in-memory state regressions cover disabled-map preservation and enabled-
  map replacement. The official skip-02 vector is also a named differential
  regression in the decoder conformance-coverage suite.
- The repaired vector passes all 12 displayed frames natively and with
  `RVP9_FORCE_SCALAR=1`. Its raw 539,136-byte I420 output is byte-identical to
  pinned vpxdec (SHA-256
  `b20c0cd323aa000969e799025cee6b0db94512415f7589f028c32ddfee55c85a`).
- The complete alpha-supported official corpus passes 4,796/4,796 displayed
  frames with zero mismatches or skips in both native and forced-scalar runs.
  The unfiltered 307-vector suite has exactly one remaining vector-level
  failure: `vp90-2-22-svc_1280x720_3.ivf`, the already-scoped spatial-SVC
  stream outside this alpha.
- All 218 decoder unit tests, all 15 focused conformance-coverage tests, all
  four panic-safety tests, focused clippy with warnings denied, and rustfmt
  pass.

## Unit A10 — release-only workspace versioning

- The first guarded integration attempt rebased the decoder fix cleanly, then
  failed before validation because the default per-integration version bump
  expects a root Cargo package. This repository is an intentional virtual
  workspace with its shared version under `[workspace.package]`.
- `.deltic-integrate.toml` now declares `version_bump = "release-only"`.
  Ordinary integrations no longer try to stamp every crate, while a deliberate
  release remains the single authority for the shared version. This also avoids
  invalidating the whole workspace build cache for every landed optimization.
- `deltic integrate-config validate --json` accepts the candidate. Explicit
  path explanation keeps source under the workspace gate and keeps Cargo or
  policy changes on the full fallback gate.

## Unit A11 — executable alpha conformance boundary

- The harness now owns one named, fail-closed `--alpha-supported` scope. It
  requires the complete 307-vector manifest-derived corpus, requires exactly
  one `vp90-2-22-svc_1280x720_3.ivf`, visibly excludes that tracked spatial-
  SVC stream, selects exactly 306 vectors, and requires exactly 4,796 decoded
  displayed frames. It cannot be combined with `--limit` or diagnostic
  `--non-gating` mode.
- The Cargo integration test uses the same selector and now asserts 4,796
  passes, 4,796 expected frames, and zero mismatches, skips, gated profiles,
  or unexpected decode errors. Selector unit tests fail on an incomplete
  corpus or a missing spatial-SVC boundary.
- `scripts/qualify-alpha-conformance.sh` fetches and SHA-1-verifies all 307
  official vectors, builds the release harness, then runs the named gate with
  native and forced-scalar dispatch. Both observed 4,796/4,796 passes with zero
  mismatches or skips.
- The default unfiltered strict command remains intact. It exits nonzero with
  exactly one vector-level error, the tracked spatial-SVC vector, while the
  other 306 vectors still produce 4,796/4,796 passing frames. This keeps the
  post-alpha decoder work visible rather than deleting or weakening its oracle.

## Unit A12 — thread-count gates use the same alpha scope

- The first complete harness run exposed two thread-count tests that still
  walked all 307 files directly. Both correctly failed on the unsupported
  spatial-SVC vector. They now call the same fail-closed alpha selector as the
  primary conformance gate rather than carrying a second exclusion rule.
- The two-worker conformance test passes all 4,796 supported frames. The N=1
  versus N=2 determinism test reports all 4,796 displayed frames byte-identical.
  The complete seven-test tile-threading binary passes.

## Unit A13 — broad workspace and external-decoder qualification

- `cargo test --workspace --locked` and
  `cargo test --workspace --release --locked` pass with the complete official
  vector corpus present. This covers every workspace unit, integration, CLI,
  conformance, threading, and doctest target in both debug and release modes.
- `cargo clippy --workspace --all-targets --locked -- -D warnings` and
  `cargo fmt --all --check` pass.
- The Stage 4a product stream decodes byte-exactly through rvp9-decoder,
  pinned vpxdec, and ffmpeg. The two-layer temporal stream is byte-exact
  through rvp9-decoder and vpxdec. Every extracted layer of the three-layer
  temporal stream is byte-exact through all three decoders.
- The host lacks `cargo-fuzz` and the nightly Miri component. A direct nightly
  `fuzz_parse_packet` smoke run completed 2,388,017 iterations in 31 seconds
  without a crash, but it did not have libFuzzer coverage or ASan hooks. Treat
  this as panic smoke only, not a substitute for the unavailable sanitizer and
  Miri gates.

## Unit A14 — fail-closed alpha encoder matrix

- `scripts/qualify-alpha-encoder.sh` defines 32 orthogonal 60-frame streams.
  The matrix covers CPU-used 6, 7, and 8; VBR and CBR; AQ3; denoising; two- and
  three-layer temporal SVC; 720p30, 1080p30, and 1080p60; and the canonical
  `in_to_tree`, `ducks_take_off`, and `old_town_cross` motion/texture classes.
- The driver requires an initialized libvpx checkout at exact revision
  `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`. It fails on missing tools,
  sources, binaries, frames, or byte differences. It records the host, tool
  versions, source hashes, vpxdec hash, stream hashes, and decoded hashes.
- The four-frame structural pass succeeded on 32/32 streams. The full
  60-frame pass then succeeded on 32/32 streams. Every stream produced the
  exact expected decoded byte count, and rvp9dec, pinned vpxdec, and ffmpeg
  agreed byte-for-byte. The full evidence manifest SHA-256 is
  `f33fca98de66444c862aec1e3f02d27a69612de35172d4b14bb45a18f8984725`.

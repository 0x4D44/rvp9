# v0.2.0-alpha.1 release qualification

## Identity and scope

- Candidate source at session start: `61facabad271578da525b575ea4f6e2be326b8a2`.
- Reference encoder and decoder: pinned libvpx v1.14.1 commit
  `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`.
- Intended label: `v0.2.0-alpha.1`.
- Intended claim: an 8-bit, one-pass realtime VP9 encoder and decoder preview
  for CPU6--8, including VBR, CBR, cyclic-refresh AQ, denoising, and two- and
  three-layer temporal SVC. It is not production parity and does not include
  spatial SVC.
- `TESTING-GUIDE.md` is absent. This session therefore uses `CLAUDE.md`, the
  checked-in harnesses, and the generic testing-session diagnostic discipline.

## Qualification plan

1. Expand the official-vector fetch surface from its Stage 0 subset to the
   complete pinned VP9 conformance manifest, with content-hash verification.
2. Run every official vector in strict mode on the ordinary decoder, then
   repeat across scalar and serialized decoder paths where the harness supports
   them.
3. Run the full workspace gate, the checked-in real-world/profile/tile decoder
   suites, and a bounded parser-fuzz pass.
4. Exercise a representative encoder matrix across CPU6--8, VBR/CBR, AQ3,
   denoising, temporal T2/T3, thread/tile variants, and cross-decode every
   generated stream through rvp9-decoder, pinned vpxdec, and ffmpeg.
5. Qualify portable release binaries, their licence and patent notices, CLI
   version/help behavior, archive contents, and checksums.
6. Integrate the exact candidate, tag it, and publish a prerelease only after
   all release-blocking evidence is green. Preserve every limitation in the
   release notes.

## Decision trail

- 2026-08-12: Arthur approved a deliberately scoped alpha before spatial SVC
  and asked for wider testing first. The release can proceed without claiming
  the unresolved quiet-host CPU8/T3 relative-speed gate, but the provisional
  speed status must be explicit.
- 2026-08-12: The repository currently has no tags, release runbook, or hosted
  workflow. The alpha therefore needs an explicit local qualification and
  packaging path rather than relying on an existing release automation lane.
- 2026-08-12: The existing `scripts/fetch-vectors.sh` names only fifteen Stage
  0 vectors, while `PLAN.md` records a prior 191-pass conformance run. A pinned,
  hash-verified full-vector fetch is the first test-infrastructure unit; testing
  only the surviving subset would not satisfy the requested wide pass.

## Findings

No release-qualification defect has been observed yet.

## Unit A1 — complete pinned vector provisioning

- Initial candidate `61facaba` was confirmed to carry the exact libvpx pin but
  no initialized submodule or fetched vector set. Initializing the submodule
  exposed 307 valid 8-bit Profile 0/1 VP9 streams with sibling decoded-output
  MD5 ledgers in pinned `test/test-data.sha1`. This is wider than both the
  fifteen-name Stage 0 fetch script and the older 201-vector PLAN result.
- Replaced the static Stage 0 list with manifest-derived selection. The script
  now refuses a wrong or missing libvpx revision, excludes malformed-input,
  VP8, high-bit-depth Profile 2/3, and encoder-only media, downloads the 307
  paired stream/ledger files concurrently, and verifies every file against its
  pinned SHA-1 before publication. Existing files are also verified and a
  mismatch fails without overwriting them.
- Added `--list` as a network-free structural oracle. `bash -n` passes; the
  list contains 307 unique entries, no Profile 2/3 entry, and includes the
  profile-1 and SVC tails. The next step is an actual full fetch followed by
  strict conformance on every resulting vector.
- Release-readiness testing also reproduced a public setup-document defect:
  `README.md` names nonexistent `scripts/fetch-vectors.ps1`. It is tracked as
  `RVP9-BUG-FLUX-00018` and remains Open for an independent fix.

## Unit A2 — official ledger compatibility

- The first strict run over all 307 fetched vectors reached 4,654 displayed
  frames: 4,624 passed, 30 mismatched, and six vectors failed structurally.
  The failures were independently reproduced with an isolated seven-vector
  directory and recorded as `RVP9-BUG-FLUX-00019` through `00022`.
- Two structural failures were a harness defect, not decoder failures. The
  pinned `vp90-2-19-skip.webm` and `vp90-2-19-skip-01.webm` ledgers use
  ordinal-only names such as `01.yuv`; the parser previously required every
  name to contain dimensions. It now accepts the exact ordinal form, retains
  sequential-index validation, and uses the decoded buffer dimensions only
  for verbose output.
- Focused parser and conformance tests pass, clippy is warning-free, and both
  affected official streams pass all 120 displayed-frame MD5 checks in strict
  release mode. The remaining release blockers are three tile/skip decode
  errors and the 20-frame subpixel mismatch. The spatial-SVC vector remains a
  separately tracked post-alpha limitation.

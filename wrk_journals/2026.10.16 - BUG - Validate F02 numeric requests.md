# RVP9-BUG-KIL-00086 — Validate F02 numeric requests

The F02 block oracle parsed several supplied numbers with `parse().ok()` and
then selected defaults. Its bitrate list discarded malformed tokens. A typo
could therefore change an experiment's parameters silently, or an empty list
could run no encodes/comparisons and still report success.

The fix separates omission from malformed supplied input for frames, width,
height, FPS, threads, tile columns and bitrates. It keeps existing defaults and
both option syntaxes, requires positive work/rate values, permits tile-column
zero, and rejects incomplete or mixed-validity bitrate lists. Validation occurs
before corpus access or oracle work. Bitrates must also fit the existing
kilobit-to-bit conversion used by the encoder configuration.

The separate strict-field comparison and external-process/temp-file defects
remain separate ledger records. This fix changes numeric parsing only.

The aggregate malformed-input regression was observed failing, exit 101, with
the extracted helper retaining the old parsing semantics. It listed accepted
missing, empty, malformed, negative, zero and overflowing values across every
target option. `--kbps nope` and empty lists produced an empty vector; mixed
lists silently dropped bad/empty tokens. The final parser instead returns an
error naming the offending option. This is a focused reversal of the original
numeric parsing behavior, without running the oracle or external encoders.

Positive tests pin documented defaults, both option forms, first-occurrence
behavior, tile-column zero, trimmed bitrate order and duplicates, and the largest
kilobit value whose conversion fits u32 (4,294,967). The next value is rejected.
Supporting calibrations separately changed the expected default frame count
from 64 to 63 and valid-form width from 320 to 321. Each named test failed at
its comparison assertion, exit 101; both expected values were restored. These
calibrations check the positive-contract oracles and are separate from the
malformed-input regression proof.

After restoration, all 19 F02 bin tests passed, including the three new parser
tests. Lead ran that full focused target again against the frozen source and
confirmed 19 passes. `cargo fmt --all --check`, scoped harness Clippy
(`--bin f02-block-oracle`), and `git diff --check` passed without new warnings.
Lead source review confirmed `main` consumes the validated values before any
corpus access and no external process or strict-comparison logic changed.

The selected final smoke is `cargo test -p rvp9-harness --bin
f02-block-oracle`, bounded to 60 seconds after final fetch/catch-up.

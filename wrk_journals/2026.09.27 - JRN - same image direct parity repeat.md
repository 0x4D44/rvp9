New 30-pair-per-clip process CPU was 1.061219× equal-clip; the earlier independent 30-pair group was 1.054068×. Pooling all 60 pairs per clip gives 1.057638×, still above the ≤1.05× target. All 186 new encodes, including warmups, exited zero and matched canonical arm-specific IVF hashes. [Raw and identity evidence](../wrk_docs/evidence/2026-09-27-integrated-pgo-direct-repeat/README.md) is retained.

No code or profile changed between the two direct groups. Ducks stayed near 1.17× while Tree moved from 1.021× to 1.048×; the available host-load observations do not explain that shift. Do not claim parity from one favourable screen, and do not infer a code regression from same-image variation.

The exact-image IP triage found no new bounded operation with a defensible >0.4 percentage-point equal-clip saving. In particular, the large Ducks picker stack load, tight-plane vector load, and Tree/Town filter metric arithmetic are not independently removable just because they are sampled. AVX2 subpel checked-load hoisting, NSTEP prepared seed, TX-selector forwarding, large-model TX-cell early exit, and duplicate inter-evaluator reuse have already been measured and rejected. The parity goal remains active. The next code experiment needs a new invariant with an operation-level count or a changed profile that identifies actual redundant work; a broad function share alone is insufficient.

# RVP9-BUG-KIL-00122 — Reject two-pass temporal SVC

The two-pass driver attaches first-pass allocations to the stream controller.
Temporal SVC replaces that controller with per-layer state before selecting Q;
those layer controllers do not contain the first-pass allocation. A CLI request
for two-pass temporal SVC therefore succeeded while falling back to average
bandwidth instead of the requested first-pass model.

`encode_two_pass` now rejects `temporal_layers > 1` with `InvalidConfig` before
gathering first-pass statistics. The public error documentation explains the
restriction and diagnostic directs callers to one temporal layer. The existing
CLI propagates the shared error before opening its IVF output, so the check
also protects direct library callers without duplicate CLI validation.

The CLI still reads/buffers its input before entering the driver. Thread/tile
option handling and delayed two-pass scheduling belong to separate Open bugs
RVP9-BUG-KIL-00120 and RVP9-BUG-KIL-00121 and were not changed. The deliberate
support restriction is recorded in `notes/divergence-ledger.md`.

## Evidence

Before adding the guard, the new API regression selected one test and failed its
aggregate assertion: both two and three layers were accepted with empty input
and with three valid frames, for four observed accepts. The new actual-CLI
regression also selected one test and failed: both layer counts exited
successfully, created an output and omitted the required unsupported-combination
diagnostic. Logs were `api-red.log` and `cli-red.log` in task scratch.

After the guard, both regression tests passed. The API requires the specific
`InvalidConfig` diagnostic; the CLI checks its error, absent output and preserved
input bytes. Three existing positive controls also passed separately:

- `two_pass_completes_and_emits_one_packet_per_frame`
- `enc_passes_two_still_writes_complete_ivf`
- `enc_frame_time_csv_writes_one_row_per_temporal_svc_frame`

All five selections ran one test and passed it. `cargo fmt --all --check`,
`cargo clippy -p rvp9-encoder --test w_2pass_vbr`, and
`cargo clippy -p rvp9-cli --test cli_arg_coverage` passed with no warnings.

Test commands used stdin at EOF, bounded harness commands and a task-local
`.scratch` TMPDIR. The preselected final smoke after fetch/catch-up is:

```text
deltic timeout 60 cargo test -p rvp9-cli --test cli_arg_coverage enc_two_pass_temporal_svc_rejected_before_output_creation -- --exact
```

The lead reviewed the guard placement, caller propagation and red/green logs.
No external decoder or full workspace test suite was required. This pass leaves
the bug Fixed for a different verifier and does not close it.

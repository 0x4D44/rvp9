# Record existing decoder metadata bound — KIL-00082

The accepted resolution permits either tile-local rectangles or full-frame metadata bounded by active workers. The latter already landed in `dc19bcea3f41952f6d0a2a53b027c852a79a5aed` (`fix(dec): bound tile scratch by worker count`, 2026-08-22). `git log -S 'num_tiles <= num_threads'` found this commit; `git show` confirms it introduced the shared eligibility gate into both intra and inter decode paths. `git merge-base --is-ancestor` confirms it is on `origin/main`. This is the actual code provenance, rather than the unrelated current trunk tip or this journal commit.

Both paths call `parallel_tile_decode_enabled` before allocating any per-tile segment or MV slab. The gate requires one tile row and at most the configured worker count. Thread count is private, initialized only by the constructor and has no setter; the worker pool uses that same count. A 64-column frame with two workers therefore stays inline and does not allocate tile metadata.

For either pool, let retained slab count be P, eligible tiles N, successful returns K and configured workers W. Starting with empty pools, N ≤ W and K ≤ N. Pop N slabs (allocating shortfalls), then return successful slabs: the retained count is `max(P−N,0)+K ≤ max(P,N) ≤ W`. Pool plus checked-out slabs is also at most `max(P,N)`. Errors drop metadata and cannot increase the count. Intra and inter share the same segment pool; MV metadata has its own independently bounded pool. An independent source review confirmed the acquisition and return sites and this bound.

Vectors still retain full-frame capacity and historical maximum geometry. The conclusion is O(workers × historical frame area), not tile-local storage or a strict current-frame byte bound. Compact rectangles would be a further optimization outside this already satisfied resolution. The separate disabled loop-filter aliasing construction (KILN-00067) is unchanged.

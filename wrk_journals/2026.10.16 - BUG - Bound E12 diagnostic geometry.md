# Bound E12 diagnostic geometry — KIL-00105

The queue selected KIL-00105 and the task claimed it before inspecting the source. The public diagnostic `record_leaf` accepts caller-controlled planes, strides, offsets and block geometry. Enabled sampled calls reach `pred_sse`, which currently validates only the declared reference window before constructing a fixed 64×64 prediction buffer and indexing both planes. Invalid source coverage, dimensions or arithmetic can therefore panic.

The bounded correction preserves the public signature and makes invalid samples a documented no-op. Validation belongs in `pred_sse` so every zero, shipped, searched and exhaustive candidate is checked before prediction. It must bound the block, prove source rows and the actual fractional reference halo fit their slices and strides, and use checked conversions and coordinate arithmetic. Valid prediction, sampling, motion-vector interpretation and aggregate behavior stay intact.

The source review also found that identity `ScaleFactors::new` calls a fixed-point constructor whose shifted numerator assumes VP9-sized dimensions. Reference dimensions must remain within the documented 65,536 maximum before that call; accepting merely representable `u32` dimensions would not prove an identity scale.

The tests-only pre-fix run selected 26 module tests: 24 passed and both new regressions failed on their own assertions. The invalid-geometry table caught both panics and incorrectly accumulated samples. The separate fractional-halo case caught a predictor slice-coverage panic even though the zero-motion block fitted. The strengthened 64×64 strided, exact-last-source-byte case passed before the fix. The lead inspected the raw pre-fix log and the post-fix logs showing all 26 tests passing.

- Changing the maximum block check to reject 64 selected one positive-control test and failed its sample-count assertion (`0` versus `2`).
- Rejecting all fractional candidates selected one positive-control test and failed its assertion that the valid fractional SSE differs from zero-motion fallback.

Both mutants were manually restored. The lead verified final source SHA-256 `6b20a50c18c9d9bb3c9a3d9f074caf47c0badd17bd567e5376ac240e943bd92e`, independently observed 26 module tests and formatting pass, read the clean restored scoped Clippy log, and observed `git diff --check` pass. No new warnings were reported.

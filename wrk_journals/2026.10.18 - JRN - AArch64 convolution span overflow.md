# AArch64 convolution span overflow

RVP9-BUG-FLU-00046 is fixed by checking the horizontal source and destination extent arithmetic before comparing each span with its slice length. Overflow now panics in validation before the convolution wrapper can enter its raw-pointer loop.

The two direct `validate_horiz` regression tests failed before the fix in a release build with overflow checks disabled. Each failed at its named assertion (`validate_horiz accepted a wrapped source extent` and `validate_horiz accepted a wrapped destination extent`); neither test called the unsafe wrapper. After the fix, both passed by catching the checked-arithmetic panic. The existing single-axis AArch64 NEON scalar-parity test passed, as did `cargo fmt --all --check` and `git diff --check`.

The workspace's default fat-LTO release compile exceeded an initial 180-second bound before reaching tests. Re-running with release LTO disabled and 16 codegen units completed; overflow checks remained disabled for the red-before and fixed release runs.

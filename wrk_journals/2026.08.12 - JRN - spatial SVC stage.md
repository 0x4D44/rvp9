# Spatial SVC stage

## Unit S1 — full official decoder conformance

Baseline `7c47aabf2d79bcd4986d7e88a421b234d66093e0` passed the alpha-supported 306-vector gate but failed `vp90-2-22-svc_1280x720_3.ivf`. The stream has 20 IVF packets. Every packet contains three shown spatial components in low-to-high order: 320×180, 640×360, and 1280×720. The official ledger contains the 20 final 1280×720 outputs.

Two independent mismatches caused the failure:

- `Decoder::decode_inter_frame` rejected a frame when any declared reference had invalid scale factors. Pinned libvpx ORs validity across the three declared references, then rejects only a block that actually selects an invalid reference. The lower spatial layer legally retains an unused 1280×720 ALTREF while predicting from its valid 320×180 LAST reference.
- The conformance harness and `rvp9dec` emitted every shown component. Pinned libvpx decodes all components for state but exposes only the final shown component from one packet decode call.

Accepted changes:

- Mirror libvpx's frame-level any-valid reference gate and add a release-build block-level selected-reference guard.
- Centralize packet output selection in `PacketFrames::output_frame_index` without changing the low-level all-component decode API.
- Route the conformance runner, permanent conformance test, tile-threading gates, and `rvp9dec` through that packet-output policy.
- Expand permanent decoder gates from the alpha subset to all 307 official vectors and 4,816 displayed frames.
- Correct the documented scale envelope to `current/16 <= reference <= 2*current` per axis. The implementation already matched pinned libvpx.

Evidence on the exact dirty tree before commit:

- Packet-output policy test: passed.
- Synthetic two-component `rvp9dec` test: one final output, `2 decoded frames/1 showed frames`.
- Official SVC vector: 20/20 top-layer MD5s matched.
- Full strict official corpus: 307/307 vectors, 4,816/4,816 displayed frames, zero mismatches/skips/gated frames.
- Threaded conformance at N=2: 4,816/4,816 passed.
- N=1 versus N=2 determinism: 4,816/4,816 byte-identical.
- `rvp9dec` output for the official SVC vector matched pinned `vpxdec` top-layer I420 byte-for-byte: whole-file MD5 `fbdd9f9bb30c27434d50c1258fe80491`; summary `60 decoded frames/20 showed frames`.

Pinned reference remains libvpx v1.14.1 commit `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`.

FFmpeg does not decode the mid and top layers of this particular official vector correctly: it warns about the retained 1280×720 reference and only matches the base layer. Keep libvpx plus the official ledger as the spatial-layer oracle; do not falsely claim three-decoder agreement for this vector.

uses the same separable 8-tap arithmetic, 8-bit rounding between passes, and

## Unit S3 — canonical spatial layer plan

Spatial-SVC configuration now has a separate public planning API rather than
adding fields to `EncoderConfig`. `SpatialSvcConfig::default()` is one spatial
layer, so this unit cannot alter the mature single-layer or temporal-only
encoder paths. A later access-unit encoder will consume the validated plan.

`SpatialLayerPlan::canonical` reproduces the pinned libvpx real-time defaults:

- one layer: `1/1`, all target bitrate;
- two layers: `1/2, 1/1`, with area-weighted targets `1:4`;
- three layers: `1/4, 1/2, 1/1`, with targets `1:4:16`;
- each target calculation truncates independently, as libvpx does;
- downscaled layers at or below 320×240 use eight-tap-smooth, larger
  downscaled layers use bilinear, and both use Q4 phase 8;
- coded dimensions use libvpx's multiply/truncate/round-up-to-even rule.

The v1 API rejects zero or more than three layers, source geometry that cannot
form an exact even-sized I420 pyramid, and rates too small to assign every
layer a positive integer bitrate. The 720p three-layer test locks 320×180,
640×360, and 1280×720 with targets 71,428, 285,714, and 1,142,857 bit/s for a
1.5 Mbit/s aggregate. The 1080p two-layer test locks 960×540 and 1920×1080 at
200,000 and 800,000 bit/s for a 1 Mbit/s aggregate.

Evidence on the exact dirty tree before commit:

- focused spatial-plan tests: 3/3 passed;
- libvpx dimension-rounding test: 1/1 passed;
- complete `svc::tests` release set: 16/16 passed;
- release `cargo check -p rvp9-encoder`, encoder-lib clippy with `-D warnings`,
  rustfmt, and `git diff --check`: green.

Exact next unit: build a packet-level spatial access-unit API that owns the
per-layer encoder state and emits low-to-high VP9 superframe components. Keep
the first live slice spatial-only (`temporal_layers=1`, lag 0, no alt-ref,
8-bit profile 0) and require cross-decoder extraction of every layer before
rate-control or compression tuning.

## Unit S4 — keyframe-only spatial access units

`SpatialKeyframeEncoder` now proves the packet boundary without overstating
the implementation. It owns one ordinary encoder per spatial layer, forces a
one-frame GOP, builds the exact source pyramid, encodes components low to high,
and appends a VP9 superframe index. It rejects lag, ALTREF, temporal layering,
and canonical layer dimensions the current encoder geometry cannot represent.
The wrapper poisons itself after a partial component failure so its layer
states cannot silently diverge.

This is deliberately not persistent spatial SVC. Independent inter streams
all reference and refresh decoder slot 0; once the low component replaces that
slot, the upper component would see a reference at the wrong resolution.
Production inter pictures need explicit shared reference-map scheduling and
cross-layer reconstruction injection before this API can grow an ordinary
`encode_frame` operation.

Evidence on the exact dirty tree before commit:

- release unit tests: two 128x64 two-layer access units both parsed as
  64x32 then 128x64 keyframes and decoded through `rvp9-decoder`; packet sizes
  matched the superframe index;
- release unit tests also covered padded source strides, short-plane rejection,
  stateful-mode rejection, and explicit deferral of 720p's 320x180 base layer;
- FFmpeg decoded both packed access units successfully, and all four extracted
  native-resolution components matched `rvp9-decoder` byte-for-byte by
  SHA-256;
- a durable ignored pinned-`vpxdec` top-layer byte-exact gate is present, but
  this host has no pinned `vpxdec` executable available, so that external gate
  was not rerun for this unit.

The first failed FFmpeg oracle expected one raw output stream to preserve
alternating 64x32 and 128x64 component geometry. FFmpeg decoded all four
frames, but its raw-video output fixed the first 64x32 geometry and rescaled
the upper layers. The corrected gate checks packed decode success, then extracts
each component into its own native-resolution IVF before byte comparison.

Exact next unit: widen the stable non-spatial release evidence before resuming
SVC. Exercise official conformance beyond the existing decoder matrix, then
run representative encoder streams through `rvp9-decoder`, pinned `vpxdec`,
and FFmpeg. After that base is recorded, add shared spatial reference-map
controls and the first valid enhancement-layer inter picture.

## Unit S5 — CPU7 720p three-layer transform model

The committed `4ac5dcb75bae0ef31c6a2812bef4f883056938c9` quality baseline
passed all 120 required spatial-layer BD-rate gates, but its production-PGO
720p30 three-layer speed was still `1.11618x` vpxenc at CPU7 and `1.06088x`
at CPU8. Ducks Take Off was the limiting CPU7 clip at `1.20428x`.

Matched 300-frame profiles and decoder-side block counts ruled out excess
partition leaves and candidate counts. CPU7's exact emit-side TX8/TX16
selector instead repeated two transform/quantization evaluations on every
eligible leaf. Runtime instrumentation measured about 0.30 ms per middle
component and 1.1 ms per top component on ordinary Ducks frames. The exact
selector chose TX16 increasingly often once residual SSE exceeded variance.

The accepted policy keeps exact transform redecision for the spatial base,
two-layer SVC, 1080p, single-layer, temporal SVC, CPU6, and explicit diagnostic
overrides. Only CPU7 720p three-layer enhancement components use the picker's
existing TX8 choice plus a measured TX16 rule: choose TX16 for a max-TX16 leaf
when `SSE * 8 >= variance * 9`. This removes both repeated transform/quant
walks from the failing resolution class without broadening the shortcut.

Two nearby hypotheses were rejected before this change. Narrowing the spatial
simple-model skip policy was production-PGO neutral. A libvpx-inspired
enhancement large-block model-only Q shortcut improved CPU7 by about 0.24% and
was neutral at CPU8, below the retention threshold.

`9d4f3aa8687cc14fec9fdaf1947a58fce2777e20d00a8bec3b4d044476f03029`

The accepted AArch64 kernel ports pinned libvpx's two-pass scaled NEON shape.

widths 4/8/16/32/64, uses scalar tails instead of reading rounded-up source
rows, and retains the scalar compound-average sibling because pinned libvpx
does not expose a matching scaled-average NEON entry point. Forced-scalar
dispatch remains available. The implementation is output-exact, so it changes
neither coding decisions nor decoded quality.

# Spatial SVC stage

## Unit S1 — full official decoder conformance

Baseline `7c47aabf2d79bcd4986d7e88a421b234d66093e0` passed the alpha-supported 306-vector gate but failed `vp90-2-22-svc_1280x720_3.ivf`. The stream has 20 IVF packets. Every packet contains three shown spatial components in low-to-high order: 320×180, 640×360, and 1280×720. The official ledger contains the 20 final 1280×720 outputs.

Two independent mismatches caused the failure:

- `Decoder::decode_inter_frame` rejected a frame when any declared reference had invalid scale factors. Pinned libvpx ORs validity across the three declared references, then rejects only a block that actually selects an invalid reference. The lower spatial layer legally retains an unused 1280×720 ALTREF while predicting from its valid 320×180 LAST reference.
- The conformance harness and `rvp9dec` emitted every shown component. Pinned libvpx decodes all components for state but exposes only the final shown component from one packet decode call.

Accepted changes:

- Mirror libvpx's frame-level any-valid reference gate and add a release-build block-level selected-reference guard.
- Centralize packet output selection in `PacketFrames::output_frame_index` without changing the low-level all-component decode API.
- Route the conformance runner, permanent conformance test, tile-threading gates, and `rvp9dec` through that packet-output policy.
- Expand permanent decoder gates from the alpha subset to all 307 official vectors and 4,816 displayed frames.
- Correct the documented scale envelope to `current/16 <= reference <= 2*current` per axis. The implementation already matched pinned libvpx.

Evidence on the exact dirty tree before commit:

- Focused mixed-reference tests: 3/3 passed.
- Packet-output policy test: passed.
- Synthetic two-component `rvp9dec` test: one final output, `2 decoded frames/1 showed frames`.

Pinned reference remains libvpx v1.14.1 commit `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`.

FFmpeg does not decode the mid and top layers of this particular official vector correctly: it warns about the retained 1280×720 reference and only matches the base layer. Keep libvpx plus the official ledger as the spatial-layer oracle; do not falsely claim three-decoder agreement for this vector.

Exact next stage: implement spatial-SVC encoder packet topology and per-layer reference scheduling first, prove rvp9-decoder plus pinned vpxdec extraction for every layer, then establish the per-layer quality/speed baseline before tuning.

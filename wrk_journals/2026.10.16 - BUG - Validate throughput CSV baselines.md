# RVP9-BUG-KIL-00108 — Validate throughput CSV baselines

The throughput writer interpolated caller-controlled names into CSV, while the
reader split physical lines on commas and accepted extra columns and nonfinite
metrics. A NaN operand could also make the ratchet's greater-than comparison
silently succeed.

The private record codec now handles quoted commas, doubled quotes and embedded
CR/LF, with UTF-8 text, LF/CRLF endings and optional final separators. Its quoting
rules follow [RFC 4180 section 2](https://www.rfc-editor.org/rfc/rfc4180).
It decodes one logical record at a time from the existing loaded input string.
The decoded header must exactly match twelve schema-v1 column names. Malformed
quoting or record endings fail the entire read with `InvalidData`; well-formed
future, wrong-width or invalid typed rows are skipped. Counts and dimensions
must be positive, and all three serialized latency metrics finite and positive.

The writer validates its whole result batch before creating directories or
opening the CSV. It escapes text fields, supplies the header for an existing
empty file, and preserves tiny positive metrics that three-decimal formatting
would round to zero. Public `CsvRow` values with invalid metrics are excluded
from baseline selection. Ratchet operands and their computed budget must also
be finite and positive, including the multiplication overflow/underflow cases.

Review found an additional record-framing requirement within this codec fix:
appending to a valid file without its last separator joined two records. Append
now inspects the last byte and inserts LF when a nonempty batch needs it. This
requires read permission on existing CSV files, as documented in the API. It
does not validate or repair the entire existing file.

## Evidence

Eight new regression tests ran before the production change: all eight failed
on their assertions. They cover an independently authored quoted multiline
reader sample, exact independently authored writer bytes, invalid typed rows,
ambiguous quoting/bad headers, invalid append batches, tiny positive values,
invalid ratchet operands/products and invalid public baseline rows.

The first implementation passed all eighteen throughput tests. A separate
append-EOF regression then aggregated both missing-separator failures: a
header-only file became invalid, while a populated file lost the appended
record. After the separator correction, all nineteen throughput tests passed.
Independent literal reader and writer oracles avoid relying solely on a
mutually consistent roundtrip.

Focused validation used a task-local `.scratch` TMPDIR and stdin at EOF:

```text
deltic timeout 60 cargo test -p rvp9-bench --lib throughput::
cargo fmt --all --check
cargo clippy -p rvp9-bench --lib
```

Formatting, scoped Clippy and diff checks passed with no warnings. The final
smoke is the exact nineteen-test throughput command above after fetch/catch-up.
No performance measurement or workspace test suite was needed.

## Review and limits

An independent GPT-6.1 Sol medium reviewer checked the parser states, numeric
validation, independent oracles and final separator correction. The required
separator finding was addressed; its final reread found no remaining issue.

RVP9-BUG-KIL-00114 still tracks build-profile baseline selection and
RVP9-BUG-KIL-00115 still tracks concurrent appender serialization. No profile
selection or locking changes are included here. This fixing pass leaves the
bug Fixed for another verifier and does not close it.

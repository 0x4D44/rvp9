# 2026.05.26 — JRN — A10: full 8-slot reference-frame buffer pool landed

## Outcome: LANDED (gate-safe, byte-identical)

Implemented the full VP9 8-slot reference-frame buffer pool
(`RefFramePool` + `ref_frame_map[8]` indirection) on `StreamEncoder`,
replacing the ad-hoc `last_recon_* / golden_recon_* / altref_recon_*`
field-triples. This is the shared-infrastructure prereq for SVC (A18)
and TPL (A23) integration.

The refactor is **byte-identical** on the default path: a captured
golden (FNV-1a of the concatenated packet bytes for a fixed synthetic
clip) matches pre- and post-refactor exactly (len 6211, fnv1a
0x959781b702249817). The sacred cross-decoder gate stays **4/4
byte-exact**.

## What migrated

- **New types in `crates/rvp9-encoder/src/buffer_pool.rs`:**
  - `RefSlotPlanes { y, u, v: Vec<u8> }` — one physical slot's
    tight-stride Y/U/V pixel storage (libvpx `RefCntBuffer::buf`,
    `vp9_onyxc_int.h:64-91`).
  - `RefFramePool` — 8 physical `slots[REF_FRAMES]`, `ref_frame_map[8]`
    (libvpx `cm->ref_frame_map`, `vp9_onyxc_int.h:126`), `new_fb_idx`
    (libvpx `cm->new_fb_idx`, `:138`). Methods: `keyframe_reset`
    (broadcast one slot across all 8 map entries, libvpx
    `vp9_setup_past_independence`), `commit_new_frame` (acquire a free
    slot + copy recon in, libvpx `get_free_fb`,
    `vp9_onyxc_int.h:332-347`), `update_reference_frames(refresh_flags)`
    (rotate map per the 8-bit mask, libvpx `vp9_update_reference_frames`
    `vp9_encoder.c:3382` / rotation body `:3312-3367`),
    `named_ref_planes(which)` / `frame_refs()` resolution.
  - Named-ref index constants `LAST_REF=0 / GOLDEN_REF=1 / ALTREF_REF=2`
    (libvpx `MV_REF - LAST_FRAME`, `vp9_blockd.h:48-52`).

- **`StreamEncoder` (`frame_loop.rs`):** the 3 residual-coding
  reference field-triples replaced by one `ref_pool: RefFramePool`.
  - KF path: `keyframe_reset()` then the simulator reconstructs directly
    into the new slot via `new_frame_planes_mut()`; the broadcast
    `ref_frame_map=[kf;8]` subsumes the old per-buffer KF copies.
  - Inter path: picker reads LAST/GOLDEN/ALTREF via
    `named_ref_planes(which)`; commit via `commit_new_frame()` +
    `update_reference_frames(refresh_flags)` (0x01 / 0x03). The old
    `golden_recon.copy_from_slice(&last_recon)` GOLDEN-refresh mirror is
    subsumed by the 0x03 map rotation.
  - ARF path: `commit_new_frame()` + `update_reference_frames(0x04)`
    rotates only the ALTREF map entry.
  - `me_ref_*` **kept as a distinct field** (NOT in the pool) — it is
    the ME-side filtered/denoiser running-average view (libvpx
    `VP9_DENOISER::running_avg_y[]`, `vp9_denoiser.c:294-304`), which is
    deliberately separate from `cm->frame_refs[]`. The
    `reference_split_me_and_pred_identical_initially` anti-G3 test
    (separate-allocation assertion) still passes.

## Key design decision — named-ref → map-slot **identity** mapping

The first cut resolved all named refs through `ref_frame_map[0]`
(matching the wire `ref_frame_indices=[0,0,0]`). This made GOLDEN read
the LAST slot, which **changed the bitstream** (len 6073 vs 6211) —
GOLDEN candidates ARE picked at the gate's speed (`!disable_golden_ref`).

Fix: the encoder's INTERNAL named-ref model reads `ref_frame_map[which]`
directly (LAST→map[0], GOLDEN→map[1], ALTREF→map[2]). Each named ref
rotates on its own refresh bit (LAST bit 0 every frame, GOLDEN bit 1,
ALTREF bit 2), reproducing the prior separate-buffer pixels exactly.
This is distinct from the wire `ref_frame_indices` header field (emitted
unchanged by the writer); libvpx's `frame_refs[i].idx =
ref_frame_map[ref_frame_idx[i]]` (`vp9_decodeframe.c:1206`) collapses to
the identity here. Byte-identity restored and confirmed.

NOTE: the rvp9 encoder emits `ref_frame_indices=[0,0,0]` while reading
GOLDEN from a non-rotating slot — a latent encoder-internal vs wire
mismatch that predates this work. It does not manifest because the gate
config never desyncs on it (proven 4/4 byte-exact both pre- and
post-refactor). Faithfully reproduced rather than "fixed", per the
gate-safe-refactor remit.

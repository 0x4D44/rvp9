# RVP9-BUG-CRU-00002 — SSE2 forward DCT guard coverage

The existing high-energy 8x8 residual fixtures called the checked transform
wrapper. Their first-pass output exceeded its safe range, so scalar fallback
produced the value compared with the scalar oracle. Those cases tested fallback
wiring but did not cover SSE2 arithmetic near the guard boundary.

The fix adds engineered inputs inside the guard and explicitly checks that the
inner SIMD kernel returns true before comparing its output to scalar results.
Matching outside cases check rejection and fallback output. Existing tests and
assertions remain. The related RVP9-BUG-CRU-00004 concerns the lowbd realtime
dispatch/performance contract and is separate from this coverage defect.

This Apple Silicon host has the x86_64-apple-darwin target installed and Rosetta
execution available. Validation cross-compiles with
`RUSTFLAGS='-C target-cpu=x86-64'` to override host-native Cargo CPU flags, then
executes the x86 test binary. A native ARM run would not select the SSE2 tests.

The coverage-gap probe added an explicit `fdct8x8_inner`-returned-true assertion
to the existing constant-extreme group. The x86 test selected the intended SSE2
test and failed at residual `-255`, exit 101. Its existing wrapper/scalar
comparison had passed. The probe confirms that this extreme fixture was taking
fallback rather than exercising SIMD arithmetic; it is replaced by explicit
inside/fallback path checks in the final tests.

The new inside cases use constants `±181` and alternating-column `±181` at
stride 13, with large sentinel padding outside visible samples. They check the
inner return value and compare its actual coefficient array with scalar output.
The outside cases use `±182`, assert kernel rejection and compare wrapper
fallback coefficients with scalar. A direct guard test pins inclusive signed
lane bounds `-4096` and `4095` and rejects `-4097` and `4096`.

Supporting oracle calibration corrupted the SIMD output by adding one to its
stored coefficients. The new inside test failed its coefficient assertion at
`-181`. Omitting the wrapper's scalar redo made the new outside test fail its
coefficient assertion at `-182`. Both selected the intended named test and
exited 101. These are test-oracle calibrations, not additional codec defects.
The original production code was restored after each probe.

Narrowing the upper guard to 4094 and the lower guard to -4095 separately made
the exact-boundary test fail at its corresponding inclusive-bound assertion,
exit 101 in both runs. Both correct bounds were restored. Every new test was
observed failing at its intended assertion before final validation.

The final x86 filter `fdct8x8_sse2` passed all four selected tests under Rosetta,
including the original test with its name preserved. Focused x86 core Clippy
(`--all-targets -- -D warnings`) passed without warnings after placing the safety comments
directly beside their unsafe expressions. Lead diff review confirmed all
changes are inside the test module and the existing coefficient assertions
remain. Production SIMD arithmetic, guard bounds, and fallback are unchanged.
`cargo fmt --all --check` and `git diff --check` passed.

The selected final smoke is the same x86 `fdct8x8_sse2` filter with the explicit
baseline CPU flags, bounded to 60 seconds after final fetch/catch-up.

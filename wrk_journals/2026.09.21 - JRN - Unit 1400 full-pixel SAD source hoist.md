# Unit 1400 — full-pixel SAD source hoist

## Change

The full-pel motion-search paths now bounds-check the source block once and
reuse that slice for each candidate SAD. The scalar and four-lane helpers keep
the reference-side bounds checks unchanged. This removes repeated source-side
`block_at` work from `diamond_search_sad_from_step`, `refining_search_sad`,
and `fast_diamond_search_sad_impl`.

The focused regression covers all four batched lanes, including an out-of-
bounds reference lane, and verifies that an invalid source still returns four
`None` results. I mutated the hoisted source binding to `None` before the final
run; the test failed with lane 0 `None` instead of `Some(0)`, then passed after
restoring the implementation.

## Validation

- AArch64 local workspace: `cargo test -p rvp9-core --lib` — 1,719 passed,
  2 ignored.
- x86-64 Crucible focused suite: `cargo test -p rvp9-core --lib
  mv_search::full_pixel -- --nocapture` — 20 passed.
- Candidate/control encoder binaries produced identical IVF hashes for all
  three canonical clips in every screen.

## Crucible timing

All runs used the canonical 1280x720@30 clips, 60 frames, CPU-used 6, CBR
1260 kbps, one thread, no tile columns, AQ0, noise0, and no `--max-load1`
ceiling. The raw data and manifests are under `wrk_docs/evidence/`.

| screen | pairs × rotations | paired corpus ratio | result |
| --- | ---: | ---: | --- |
| short | 3 × 2 | 0.993080807× | pass |
| independent repeat | 3 × 2 | 0.994531081× | pass |
| full | 15 × 2 | 0.997568885× | pass |

The full run was positive on every clip: ducks 0.996496235×, intree
0.997675191×, and oldtown 0.998536282×. This is a small, reproducible
0.24% median paired gain, below the former 1% retention bar but consistent
with the agreed Tesco rule for low-risk wins.

Against pinned libvpx `12f3a2ac603e8f10742105519e0cd03c3b8f71dd`, the candidate
was 1.466127177× the reference time under the same relaxed policy. The parity
gap remains; this change only improves the RVP9 baseline and does not claim
parity.

The candidate is committed as `917c4950` (`perf(core): hoist full-pixel SAD
source slice`) and is ready for integration.

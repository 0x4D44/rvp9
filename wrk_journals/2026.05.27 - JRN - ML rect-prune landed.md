# 2026.05.27 — JRN — ML rect-partition pruner landed (A21 scope-down tail)

## Outcome: LANDED (rect pruner) + var pruner DEFERRED (honest scope-down)

Wired libvpx's `ml_prune_rect_partition` (the ML model that, after
NONE+SPLIT, decides whether PARTITION_HORZ / PARTITION_VERT are worth
evaluating) into rvp9's A4 recursive RD partition descent. This was the
higher-value, now-unblocked piece: A4-rect (commit 9ac5c1a) added the
rect HORZ/VERT evaluation, so the rect pruner finally has something to
gate. The var-based pruner (`ml_predict_var_rd_partitioning`) is deferred
— it needs a `simple_motion_search` per-SB pre-pass that does not exist
(see deferral below).

## Implementation (rect pruner)

- **`RectPruner` trait + `RectPruneRdContext`** in `nonrd_partition.rs`
  (mirrors `BreakoutPruner`): the encoder plugs the real kernel without
  pulling `ml_partition` into rvp9-core. `NoRectPrune` is the inert
  default; `nonrd_pick_partition_with_breakout` delegates to the new
  `nonrd_pick_partition_with_pruners(..., rect_prune)`.
- **`descend()` hook**: right where the A4-rect eval begins, after NONE +
  SPLIT, the pruner is consulted with the running `best_rd_cost`
  (`ref_rd`), the NONE arm's RD (`none_rd_cost`, captured separately so
  it survives SPLIT/rect lowering the running best), each SPLIT child's
  own NONE-arm RD (new `DescendResult.none_rd_cost` field), and
  `partitioning_is_none` (NONE feasible AND SPLIT didn't beat it). The
  `(allow_horz, allow_vert)` verdict gates each rect arm — a pruned arm
  skips ALL its picker invocations (libvpx `:4343` / `:4393`
  short-circuit).
- **Speed feature**: `RdMlPartition.prune_rect_thresh: [i32; 4]` added,
  populated in `apply_good` per the libvpx framesize-independent table.
- **Encoder closure** in `lib.rs`: real features — `vp9_dc_quant`,
  `partitioning_is_none`, `ref_rd`, NONE/SPLIT-child RDs — fed to the
  real `ml_prune_rect_partition`. Both pruner closures now always built;
  internal `ml_*_active` guards make them no-ops when their speed feature
  is off, so all 4 on/off combinations route through one
  `nonrd_pick_partition_with_pruners` call.
- **Anti-G3 counter**: `ML_PARTITION_RECT_PRUNED` bumps once per arm the
  model removes.

LOC: ~330 lines net (rvp9-core trait + descent ~200, lib.rs closure ~90,
speed_features ~25, inter_dispatch counter ~18), plus ~280 lines of PROOF
+ unit tests.

## Var-pruner deferral (honest)

`ml_predict_var_rd_partitioning` (`vp9_encodeframe.c:3489-3618`) is a
var-based NONE-vs-SPLIT early decision. Its features are the variance of
the residue against a motion-compensated prediction, which requires
`simple_motion_search` (`:3429-3483`) to run a per-SB diamond search and
fill a 64×64 prediction buffer BEFORE the descent. rvp9 has no such
pre-pass: `simple_motion_search` is ported (`var_partition.rs`) but takes
a `MotionSearchOps` trait that nothing in the encoder implements, and
wiring it needs a new per-SB MC pre-pass (full-pixel search +
`build_inter_predictors_sby` into a scratch buffer) threaded into the
descent params. That is well over the ~150 LOC deferral threshold and is
a deeper architectural addition (a motion-search pre-pass), not a
gate-and-call like the rect pruner. Deferred with this note.

Remaining A21 follow-ups: var pruner (needs the motion-search pre-pass
above); `ml_pruning_partition` / `search_early_termination` (speed-0
only, lower value). The breakout + rect pruners — the two now-unblocked,
higher-value models — are both live.

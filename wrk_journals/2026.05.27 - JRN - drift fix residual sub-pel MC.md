# 2026.05.27 — JRN — drift fix: residual inter-frame divergence (prev-frame-MV gate + NEAREST/NEAR causal MV)

## TL;DR
The last localized SEVERITY-1 inter-frame drift was **NOT** a sub-pixel-MC /
edge-rounding bug. It was a **motion-vector-derivation disagreement** between
the encoder and the decoder for NEAREST/NEAR blocks:

1. **`use_prev_frame_mvs` gate** — the decoder computes this PURELY from frame
   structure (`!error_resilient && size_match && !last_intra_only &&
   last_show_frame && last_frame_type != KEY`). It is NOT a header bit. The
   encoder gated prev-frame-MV salvage on `config.use_prev_frame_mvs` (default
   `false`), so the picker/recon/writer passed `prev_mv_grid = None` while the
   decoder pulled the collocated prev-frame MV into `find_mv_refs`'s salvage
   pass — changing the NEAREST/NEAR ref-MV the decoder derives. Encoder recon
   then predicted a NEAREST block from a different MV than the decode → drift.

2. **cpu≤4 RDO descent NEAREST/NEAR MV** — the RDO partition descent picks the
   NEAREST/NEAR mode during the search with a neighbour grid that lacks the
   within-SB neighbours present at decode time. Its `best_mv` could disagree
   with the decoder's causal `find_mv_refs` (observed at frame edges).

Both fixed → **all frames byte-exact (drift_diag STORED SSE = 0), both 256 and
320 widths, cpu4 + cpu7.** Gate 4/4. Build clean.

## Diagnosis chain
- drift_diag (HEAD): cpu7-320 f2 STORED SSE_Y 162k, 256-wide byte-exact through
  f2 → width-dependent. cpu4-320 diverged from f1.
- `drift_diag_localize_frame2`: first diverging f2 block `mi=(12,12)` decoded as
  `NearestMv mv=(0,0) ref=LAST EightTapSmooth sk=0`, whole-interior divergence.
- Recon-time dump: encoder reconstructed `mi=(12,12)` with `NearestMv
  mv=(6,-12)` — disagreeing with the decode's `(0,0)`.
- All 8 of `(12,12)`'s 16x16 mv-ref neighbours were GOLDEN; `find_mv_refs(LAST)`
  with no prev-MV → different-ref GOLDEN salvage `(6,-12)`; WITH the prev-MV →
  the LAST(0,0) collocated candidate is added in the FIRST salvage pass
  (early-break) → `(0,0)`.
- `RVP9_TRACE_INTER_MV` confirmed the decoder decoded f2 `(12,12)` with
  `prev_mv=Some(LAST,(0,0))` while the encoder config had
  `use_prev_frame_mvs=false`. Root cause: the encoder ignored prev-frame MVs;
  the decoder applied them (structural gate).
- cpu4 f1 (gate closed, prev_mv=None): bottom/right-edge NEAREST blocks
  reconstructed at `(0,0)` while the decoder derived a real spatial MV. Root:
  the RDO descent's pick-time grid lacked within-SB neighbours; the recon
  trusted `rdo.best_mv`.

## Fix (encoder-only, `crates/rvp9-encoder/`)
- `frame_loop.rs`:
  - Added `last_show_frame` state mirroring the decoder.
  - `encode_inter_internal` gate now `!last_frame_was_key && last_show_frame &&
    size_match` — the decoder's structural predicate, dropping the
    `config.use_prev_frame_mvs` AND. Threads `prev_grid_slice` to picker +
    writer whenever the decoder would.
  - `last_show_frame` set true after KF + show inter frames, **false** after a
    non-show ALTREF (so the post-ARF show frame's gate is closed, matching the
    decoder).
  - Updated `prev_grid_gate_open_for_test` + its unit tests to the structural
    gate.
- `lib.rs` (`pick_and_simulate_inter_encode_partitions` recon loop): for
  NEAREST/NEAR winners, re-pin `pick.best_mv` to the recon loop's causal-grid
  `mvc`/`mvc_golden`/`mvc_altref` `.nearest`/`.near` (built from the in-progress
  z-order `mi_grid` = the decoder's view). No-op for the RT picker (its mvc
  drove the pick); corrects the RDO descent. NEWMV (explicit delta) / ZEROMV
  untouched. This also keeps the splatted grid + next-frame `cur_mv_grid` MV =
  the decoder's, so downstream neighbour lookups stay in lock-step.
- Added `diag_golden_recon_y` accessor (verified enc GOLDEN == dec frame0,
  SSE 0).

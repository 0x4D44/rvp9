## Real bugs surfaced (2)

### Bug 1: kfonly decode divergence (Profile-1)

- **Trigger:** `--kf-max-dist=1 --lag-in-frames=0` forces all frames to keyframes.
- **Symptom:** Frames 0-2 decode correctly but frames 3+ diverge from oracle.
- **Scope:** All three chroma formats (444, 422, 440). 11/12 mismatches each.
- **Oracle:** vpxdec and ffmpeg agree on all 12 frames (triangulated).
- **Hypothesis:** The inter-to-intra transition state reset in rvp9 doesn't
  fully reinitialise some accumulated state (possibly ref-frame slots,
  above/left entropy context, or loop-filter state) when consecutive
  keyframes arrive in Profile-1 mode. The first few keyframes work because
  the stale state hasn't accumulated enough error yet.
- **Status:** `#[ignore]`d follow-up tests committed. Vectors committed with
  full oracle ledgers for future fix verification.

### Bug 2: aq-mode=2 segmentation decode (Profile-1)

- **Trigger:** `--aq-mode=2` (cyclic refresh) activates VP9 segmentation
  with per-segment quantisation deltas.
- **Symptom:** First frames pass (before segmentation activates), then
  divergence starts when segment map becomes non-trivial.
  - foreman 444: 9/12 mismatch (frames 3-11)
  - testsrc 720p 444: 8/12 mismatch (frames 2, 5-11)
- **Oracle:** vpxdec and ffmpeg agree.
- **Hypothesis:** The non-420 (Profile-1) segmentation decode path has a
  bug in segment_id-based quantisation or loop-filter delta application.
  The Profile-0 path likely works (201/201 conformance includes aq-mode
  vectors), so this is specific to the ss-aware branch.
- **Status:** `#[ignore]`d follow-up tests committed.

## Rejected/infeasible vectors

### Multi-tile foreman (HLD vectors 1-3)

The HLD specified `foreman_c{444,422,440}_tile2.ivf` with `--tile-columns=1`.
Investigation revealed that vpxenc clamps tile_columns based on resolution:
for 352px-wide foreman, `max_log2_tile_cols = 0` (MIN_TILE_WIDTH_B64 = 4
sb64 cols, foreman has 6 sb64 cols, only 1 tile is possible). All
`--tile-columns` values produce byte-identical output at this resolution.

Multi-tile coverage is instead exercised via `testsrc_c422_720p_tile2.ivf`
at 1280px width (2 tiles via --tile-columns=1, vs 4 tiles default).

### Frame-parallel foreman (HLD vectors 4-6)

`--frame-parallel=1` also produces byte-identical output to default for
foreman at 352px width. The encoder silently downgrades the flag. At 720p
the flag is also not honoured (tested). These vectors were not generated.

    vpxdec's per-frame `-o` only works with `--i420`)

## Diagnosis

The root cause was missing upper-bound validation at the config boundary. Existing checks rejected zero and non-finite values, but valid-looking huge values then flowed into narrower assumptions:

- `RateControlConfig::mbs()` multiplied rounded-up `u32` macroblock counts directly.
- `ms_to_bits()` used an `i64` multiplication of buffer milliseconds by target bitrate.
- `StreamEncoder::new` allocated frame/TPL buffers from accepted dimensions and GOP lengths.
- SVC setup converted `target_bitrate_bps` to `i32` before splitting.
- The CBR keyframe target formula could magnify absurd finite framerates or keyframe boosts.

Parallel read-only review agreed the right layer was explicit config-domain validation before derived arithmetic/allocation, plus checked SVC splitting. The second reviewer also pointed out same-cluster gaps for bounded framerate, bounded GOP length, bounded keyframe boost, and non-divisible SVC bitrate preservation.

## Fix

Added explicit supported bounds in `RateControlConfig::validate`:

- `MAX_CODED_DIMENSION = 16_384`
- `MAX_CODED_LUMA_PIXELS = 8_192 * 8_192`
- `MAX_FRAMERATE = 1_000.0`
- `MAX_KF_BOOST = 4_096`
- `MAX_GOP_LENGTH = 10_000`
- buffer-ms by target-bitrate product must fit the downstream `i64` domain

`RateControlConfig::mbs()` now rounds up in `u64` and saturates to `u32::MAX` for unvalidated callers. `StreamEncoder::new` gets the validation before frame/TPL allocation. SVC setup now splits bitrate in `u32`, rejects too-small or unrepresentable per-layer targets, and preserves the total across remainders.

The code-reviewer pass found no correctness blocker. I applied one small robustness cleanup: `macroblock_count_fits_u32` now guards zero dimensions locally, even though current validation calls it only after zero-dimension rejection. A clippy check then caught a warning in the new helper, so I changed it to use `is_multiple_of(16)`.
